Topic and objective

TOPIC: Runtime environments as their own object. What an activation record contains and why; the stack discipline of calls; the control link and the access link and the different questions they answer; how a non-local name is resolved by following access links or by indexing a display; where the parameter modes diverge; and how a frame size becomes a depth limit. This is the phrase Runtime environments in Section 7 of the GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Given a small program with nested procedures, state the frame layout and its size, count the frames alive at a chosen moment, name the frame that a non-local reference resolves to and the number of links followed to reach it, and predict the printed value under a stated scoping rule and a stated parameter-passing mode — without confusing the two links.

I read the topic as one record, two pointers, and the arithmetic on top of them. Everything else in the clause — displays, parameter modes, depth limits — is that record and those pointers used in a particular way. Every number on this page is computed by the page and printed on the canvas.

Prerequisites

  • Recursion — the call-return discipline this lesson counts frames on.

Approximate learning time: 50 to 70 minutes including the practice set. That figure is an estimate, not a measurement.

The five ideas

  1. A frame belongs to one call, not to one procedure, and it dies when that call returns.
  2. The control link points at the caller; the access link points at the enclosing definition. They are different pointers answering different questions.
  3. The number of access links to follow is the difference between two nesting levels — never the depth of the stack.
  4. A display trades a walk for an index, and pays for it with a save and restore on every call.
  5. Frame size is computed from fields and alignment; depth is the stack divided by that size, rounded down.

Intuition first: the stack of trays

A canteen keeps its trays in one pile. You take the top tray, use it, and put it back on top. Nobody ever pulls a tray from the middle, because the trays above it are still in use. A running program's calls work the same way: the newest call is always the one that finishes first, so its storage sits on top and is released first.

Educational interpretation The tray pile is mine and it is deliberately thin: it explains why a stack is the right shape but says nothing about the two pointers, which are the actual subject. The pointers come next, and the page tests them rather than assuming them.

Formal statements

Activation. One execution of a procedure, from the call to the return. A procedure may have many activations alive at once.

Activation record (frame). The block of storage created for one activation. It holds space for the returned value, the actual parameters, the control link, the access link, saved machine state including the return address, the local variables, and the temporaries used in evaluating expressions.

Control link (dynamic link). A pointer in the frame to the frame of the caller — the saved frame pointer of the caller. Following control links from any frame walks the chain of calls.

Access link (static link). A pointer in the frame to the most recent activation of the procedure that lexically encloses this one. Following access links walks the nesting of the source text.

Nesting level. The number of procedures a procedure is textually inside. The outermost block is level 0; a procedure declared directly inside it is level 1; and so on. The compiler knows every level before the program runs.

Display. An array indexed by nesting level, whose entry i points to the most recent activation at level i. A non-local access becomes one index plus an offset.

Symbols, in words

  • frame pointer — a register holding the base address of the frame that is running, so that any field is frame pointer plus offset.
  • stack pointer — a register holding the address of the next free slot, so that the top of the stack is known at all times.
  • offset — a distance in bytes from the frame pointer to a field, fixed by the compiler for each procedure.
  • level difference — the nesting level of the reading code minus the nesting level of the declaration. It is the number of access links to follow, and it is never negative for a legal program.
  • padding — bytes inserted so that a frame size is a multiple of the alignment. They belong to no variable but they occupy the stack.
  • value-result — copy the argument in, work on the copy, copy the final value back at return. Distinct from reference whenever the body also touches the actual variable.

The program this lesson uses, and its assumptions

A Pascal-like language that allows procedures to be nested, with static (lexical) scoping unless a question says otherwise:

program Main;                    level 0
  var g : integer;               g = 1
  procedure P;                   level 1
    var a : integer;             a = 2
    procedure Q;                 level 2
      var b : integer;           b = 3
      begin b := a + g end;      reads level 1 and level 0
    end Q;
    procedure R(n : integer);    level 2
      begin Q end;               Q called from R
    end R;
    begin a := 2; R(5) end;
  begin g := 1; P end.

The call chain is Main, then P, then R, then Q. Q is written inside P and called from R, which is the whole point: its enclosing definition and its caller are different frames. Words are four bytes and frames are aligned to eight, so every size on the page is arithmetic you can redo by hand.

The calling sequence, split between caller and callee

Before the call, the caller evaluates the actual parameters and stores them where the callee expects them, stores the return address, and passes the access link. Then it jumps.

On entry, the callee saves the state it will clobber, stores the caller's frame pointer as its own control link, sets the frame pointer to its new frame, and makes room for its locals and temporaries.

On return, the callee places the returned value where the caller can find it, restores the frame pointer from the control link, restores saved registers, and jumps to the return address. The caller then continues with its own frame intact.

Mathematical derivation The division of labour is forced by who knows what: only the caller knows the arguments, and only the callee knows its own local layout. That is why the frame is built from both ends and why the control link must be saved before the frame pointer moves.

Where each kind of storage lives

Static area — globals, string literals, and static locals. Addresses fixed at link time, lifetime the whole run, no frame involved.

Stack — one frame per live activation. Lifetime is the call, freed strictly in reverse order.

Heap — objects whose lifetime is not nested inside a call, such as anything from malloc. Freed in any order, which is why it cannot be a stack.

Mathematical derivation The stack can only support lifetimes that nest, because a frame can only be freed when it is on top. A pointer to a local that has been returned is therefore a dangling pointer: the storage is gone the moment the frame is popped.

Example 1 — the layout of one frame

Question. Give the offset and size of every field of Q's frame, and its total size.

Step 1, the bookkeeping. Returned value at 0, return address at 4, control link at 8, access link at 12. Sixteen bytes, the same in every frame of every procedure.

Step 2, the data. Q has no parameters, one local b at 16, and one temporary at 20.

Step 3, the total. Twenty-four bytes used, which is already a multiple of eight, so no padding and the frame is 24 bytes.

Compare Main. Twenty bytes used, so four bytes of padding at offset 20 and a 24-byte frame. The padding is part of the frame and part of the stack usage.

Example 2 — peak stack occupancy

Question. How many bytes of stack does the call Main, P, R, Q use at its deepest?

Step 1. At the moment Q runs, four frames are alive: Main, P, R and Q.

Step 2. Each of the four is 24 bytes, so the peak is 4 times 24, which is 96 bytes.

The trap. If the program called Q a hundred times, the peak would still be 96 bytes. Peak occupancy is a property of one moment, not a running total.

Example 3 — counting recursive frames

Question. With fact(n) returning 1 when n is at most 1, how many frames are alive during fact(4)?

Step 1. The calls are fact(4), fact(3), fact(2), fact(1): four fact frames, holding n = 4, 3, 2, 1.

Step 2. The base case fires at n = 1 and returns 1 without another call, so nothing deeper is pushed.

Step 3. Add the frame of whoever called fact: five frames alive at the deepest point.

The products. On the way back up the values are 1, then 1 times 2, then 2 times 3, then 6 times 4, which is 24. The multiplication happens in reverse order of the calls.

Example 4 — six references, seven hops

Question. For each reference in the program, how many access links does the code follow?

The rule. Hops equal the level of the reading code minus the level of the declaration. From Q at level 2: b is level 2, so 0; a is level 1, so 1; g is level 0, so 2. From R at level 2: a gives 1 and g gives 2. From P at level 1: g gives 1.

The total. 0 + 1 + 2 + 1 + 2 + 1 = 7 hops over six references, an average of 1.166667.

The check. Each walk must arrive in the frame that the declaration says: a in P, g in Main, b in Q. The page performs that check on all six.

Example 5 — the display during Q

Question. What does the display hold while Q is running?

Step 1. Main sets d[0], P sets d[1], R sets d[2]. When R calls Q, Q is also at level 2, so Q overwrites d[2].

Step 2. During Q the display reads Main, P, Q. R's frame is still on the stack but no longer reachable through the display.

Step 3. The old value R was saved inside Q's frame and is written back when Q returns, so d[2] is R again. That save and restore is what the display costs on each call.

Example 6 — four modes, one program

The program. a is 5. Procedure p(x) does x := x + 1 and then a := a + x. The call is p(a) and then a is printed.

By value. The copy becomes 6, then a becomes 5 + 6 = 11. The copy is discarded.

By reference. x is another name for a, so the first statement makes a 6, and then a becomes 6 + 6 = 12.

By value-result. The copy becomes 6 and a becomes 11; then the copy-back overwrites 11 with 6.

By name. x is the expression a, re-evaluated each time, so the two statements read as a := a + 1 and a := a + a, giving 12. Name and reference agree here; the next example separates them.

Example 7 — name against reference

The program. i is 1 and A holds 0, 0, 0. Procedure p(x) does i := 2 and then x := 10. The call is p(A[i]).

By reference. The address of A[1] is taken at the call, while i is still 1. The write goes to A[1] whatever happens to i afterwards, so A becomes 10, 0, 0.

By name. The formal is the expression A[i], evaluated at the point of the write, when i is 2. A becomes 0, 10, 0.

By value-result. Address taken at the call and value copied back into A[1], so it agrees with reference here — and disagrees with it on the scalar program above, where it printed 6 rather than 12. A mode pair can agree on one program and disagree on the next.

Example 8 — from frame size to depth

Question. An 8 MiB stack and 96 bytes per frame: how deep can the recursion go?

Step 1. 8 MiB is 8 388 608 bytes.

Step 2. 8 388 608 divided by 96 is 87381.33, so 87381 whole frames fit.

Step 3. 87381 times 96 is 8 388 576, leaving 32 bytes unused. One more frame would need 8 388 672, which is 64 bytes beyond the stack.

Why the check matters. Rounding up instead of down gives 87382, an answer that cannot be allocated. The multiplication is the cheap way to catch it.

Where the rules stop being obvious

Nine boundary cases that decide whether an answer is right. Each one is stated with the reason it holds, not as a rule to memorise.

A local costs zero links, not one

When the declaration level equals the reading level, the frame pointer already points at the right frame, so the access is frame pointer plus offset with no link followed at all. Writing "1" for a local is a common slip and it changes every total in a hop-count question.

Mathematical derivation Hops equal the level difference. For a local that difference is exactly 0, and following zero links is the identity.

Siblings cannot read each other's locals

Q and R are both declared inside P, so both are at level 2, and neither encloses the other. Q cannot name n, R's parameter, at all: it is not in Q's scope. A program that appears to do it is either illegal or is reading a different declaration with the same name.

This is why the access-link chain of Q is P then Main and never R. The chain follows the text, and the text puts R beside Q, not around it.

Under recursion the access link does not point at the previous activation

For a procedure declared at the top level, its static parent is the outermost block, so its access link points there — not at the previous frame of itself. Two activations of the same procedure at the same level are not linked by access links, because neither encloses the other.

Mathematical derivation The access link is defined by the enclosing definition. Recursion creates frames at the same level, so no nesting relation exists between them to point at.

Calling outward: the access link is not the caller's frame

If code at level 2 calls a procedure at level 1, the access link for the new frame is the frame at level 1 — which may or may not be the caller. When the call goes to an enclosing procedure the two can coincide; when it does not, they differ. The rule that decides it is the level, not the call.

The general recipe: take the callee's level minus one, walk that far from the caller's frame, and use the frame you reach.

Same-level calls overwrite the display entry

R and Q are both level 2, so calling Q from R overwrites d[2]. The displaced frame is still live, but a display alone can no longer reach it. That is exactly why the old entry is saved in the new frame and restored on return.

A display with one slot per level is not a display with one slot per call, and questions that confuse the two produce a display that cannot be restored.

Static locals and globals are in no frame

A static local has static storage duration: it lives in the static data area for the whole run, so it survives between calls and is not part of any activation record. A recursive function that keeps state in a static local does not keep one copy per frame — it keeps one copy, shared.

This is the difference between "each call has its own" and "each call sees the same", and it is why the frame count and the value count can disagree.

C frames carry no access link

Standard C does not allow a function to be defined inside another function, so every function is at level 0 and no non-local reference ever needs a link. A C frame still has a control link, because returning still needs the caller's frame pointer.

Verified fact Nested function definitions are a GNU C extension, not standard C, and code relying on them is not portable. GATE questions in the Compiler Design section use a hypothetical nested language for exactly this reason.

Variable-length data on the stack

When a local array's size is only known at run time, the frame cannot have a fixed size. The usual arrangement keeps the fixed part of the frame at a known offset from the frame pointer and grows the variable part below it, so offsets to parameters and locals stay fixed even though the frame does not.

That is why the frame pointer exists separately from the stack pointer: the stack pointer moves with the variable part, the frame pointer does not.

Objects that outlive the call cannot live in the frame

Return the address of a local and the storage is freed the moment the frame is popped: the pointer dangles, and reading it is undefined behaviour in C. The same applies to a pointer stored somewhere that outlives the call.

This is the boundary of the whole stack model: nested lifetimes go on the stack, non-nested lifetimes go on the heap, and a lifetime that is neither is a bug in the program rather than a gap in the model.

Seven wrong beliefs, each with the smallest example that refutes it

Each entry gives the belief, the counterexample, and what to say instead. The counterexamples are the ones this page computes and draws, so you can watch each one fail.

1. "The access link is the caller."

The belief. One pointer does both jobs, so a frame points at whoever called it.

The counterexample. Q is written inside P and called from R. If the access link pointed at R, then b := a + g would look for a in R, and R has no a. The read either fails or takes the wrong declaration.

Instead. Two pointers, two questions: control link answers "who called me", access link answers "where was I written".

2. "Under recursion the static link points at the previous activation."

The belief. The second call of fact links back to the first, like a chain of calls.

The counterexample. All the fact frames are at the same nesting level, and a static link points at a strictly outer level. There is no level between them to point at.

Instead. The chain of calls is the control links; the access link of a top-level recursive procedure points at the outermost block.

3. "Value-result is just another name for reference."

The belief. Both let the callee change the caller's variable, so they behave the same.

The counterexample. With a equal to 5 and a body of x := x + 1 then a := a + x, reference prints 12 and value-result prints 6: the body stores 11 into a, and then the delayed copy-back overwrites it.

Instead. Reference writes immediately; value-result writes once, at return. They differ exactly when the body touches the actual variable directly.

4. "Name is the same as reference."

The belief. Both give the callee access to the caller's variable, so the outputs match.

The counterexample. On the scalar program both print 12, which is where the belief comes from. On p(A[i]) with i set to 2 inside, reference writes A[1] and name writes A[2].

Instead. Reference binds an address once; name re-evaluates an expression at every use. Agreeing on one program is not evidence of equality.

5. "The frame size is the sum of the variables."

The belief. Count the parameters and locals, multiply by four, done.

The counterexample. Main holds one four-byte local and sixteen bytes of bookkeeping, which is twenty, yet its frame is twenty-four. The extra four bytes are padding so the frame starts on an eight-byte boundary.

Instead. Bookkeeping plus data, then rounded up to the alignment. Padding occupies the stack even though no variable lives in it.

6. "Count every call to get the frame count."

The belief. A loop that calls a function a hundred times creates a hundred frames that all count.

The counterexample. Each call's frame is popped when it returns, so at any moment only the calls that have started and not returned are alive. Calling Q a hundred times still peaks at four frames.

Instead. Take the deepest point of the call chain. Peak occupancy is a property of one moment.

7. "A display has one entry per call."

The belief. Every frame gets a slot, so a display is a copy of the stack.

The counterexample. R and Q are both level 2, so they share one slot and Q overwrites R. The display has exactly as many slots as the program has nesting levels, which the compiler knows.

Instead. One slot per level, holding the most recent activation at that level, with the displaced value saved in the frame and restored on return.

The one-sentence separator

The control link answers who called me and is used to return. The access link answers where was I written and is used to read a non-local name.

Every other fact in this topic — scoping rules, displays, hop counts, depth limits — is arithmetic layered on that sentence. If an answer contradicts it, the answer is wrong, whatever the arithmetic looked like.

How this clause is examined

Section 7 names Runtime environments as one item in a list of six. Within that item, questions come in three shapes, and all three reduce to the same five steps. Nothing on this page claims a marks distribution, and nothing claims that a particular shape appeared in a particular paper unless a year and paper are named.

Verified fact The clause is quoted from the official GATE 2027 CS syllabus PDF at gate2027.iitm.ac.in, read during this run. That is the entire syllabus justification for this lesson.

Shape 1 — output under a stated rule

A small program with a global and a shadowing local, run under static scoping and then under dynamic scoping, asking for the two printed values. Or the same program under two parameter modes.

Procedure. Fix the rule first. Under static scoping, resolve every free name in the text where the procedure is written; under dynamic scoping, resolve it in the most recent live frame on the call chain. Then execute the statements in order, one column per variable.

The check. If your static trace ever consulted the caller, the trace is a dynamic trace and the answer is wrong.

Shape 2 — which frame, which link

Name the frame that a given reference resolves to, the link that is followed, or the number of dereferences. Sometimes the question shows a stack of frames and asks which one a name reaches.

Procedure. Find the declaration and its level, subtract the reading level, follow that many access links, then add the offset. For the link itself: caller for the control link, enclosing definition for the access link.

The check. The frame you reach must be the one whose procedure declares the name. If it is not, the level or the parent map is wrong.

Shape 3 — counts and bytes

How many frames are alive, how many bytes the stack uses, how deep a recursion of a given frame size can go, or how many fields a record holds.

Procedure. Find the deepest point of the call chain, count the frames alive there, and multiply by the padded frame size. For a depth limit, divide the stack by the frame size and round down.

The check. Multiply back: the product must not exceed the stack, and one more frame must exceed it.

Traps that cost marks here

  • Using the caller as the access link, which silently converts a static-scoping question into a dynamic one.
  • Counting one hop for a local, which is zero.
  • Counting every call rather than the frames alive at one moment.
  • Forgetting the padding when the question asks for bytes.
  • Treating value-result as reference when the body touches the actual variable.
  • Treating name as reference when the argument contains a side-effecting expression such as an array index.
  • Rounding a depth limit up rather than down.
  • Assuming a display has one slot per call instead of one per level.

The five-step procedure, written once

  1. Find the declaration the name denotes, under the rule the question states.
  2. Read its nesting level, and the level of the code doing the reading.
  3. Subtract: that difference is the number of access links.
  4. Follow that many links, then add the offset inside the frame you reached.
  5. Name the frame — or, for a count, take the deepest point and multiply by the frame size.

Mathematical derivation Steps 2 and 3 are the definition of the access-link walk, and step 4 is the definition of an offset. The procedure is not a shortcut; it is the definition written as instructions.

NATOriginal practice question

In the program of this lesson, the statement b := a + g runs in Q. How many access links does the code follow to read g? Give the count.

Answer: 2

g is declared in Main at level 0, and the reading code is in Q at level 2. The number of links is the difference, 2 − 0 = 2: one link from Q's frame to P's, then one from P's to Main's.

Why 1 appears. That is the count for a, which is declared in P at level 1. Why 0 appears. That is the count for b, a local of Q. Why 3 appears. That is the number of frames below Q on the stack, which is a different quantity: hop count follows levels, not frames.

The page walks this chain and checks that it arrives in Main.

MCQOriginal practice question

While Q is executing, which frame does Q's control link point to, and which does Q's access link point to?

  1. Control link to R, access link to P
  2. Control link to P, access link to R
  3. Both point to R
  4. Both point to P

Answer: A

Q was called from R, so its control link is R's frame. Q was written inside P, so its access link is the most recent activation of P.

Why B is wrong. It swaps the two jobs, which is the single most common error in this topic. Why C is wrong. It is the answer you get if one pointer is made to do both jobs, which is exactly dynamic scoping. Why D is wrong. P is not the caller, so no control link can point at it here.

The page checks that the two parents of Q are different frames, and draws both arrows.

NATOriginal practice question

Frames are 24 bytes each. What is the maximum number of stack bytes in use during the call Main, then P, then R, then Q? Give the number of bytes.

Answer: 96

At the deepest point four frames are alive, and 4 × 24 = 96.

Why 72 appears. That is three frames, as if Main's frame did not count. Why 24 appears. That is one frame, which is the answer to a different question. Why 120 appears. That is five frames, one more than the chain has.

The page sums the four frame sizes and checks the total against the peak.

NATOriginal practice question

A function f(n) returns 1 when n is at most 1, and otherwise calls f(n-1). Including the frame of the caller of f, how many frames are alive at the deepest point of the call f(6)?

Answer: 7

The base case fires at n = 1, so the calls are f(6), f(5), f(4), f(3), f(2), f(1): six frames of f. Adding the caller's frame gives 7.

Why 6 appears. That counts only the frames of f, which is right for a question that excludes the caller and wrong for this one. Why 8 appears. That is the answer for a base case of n equal to 0, where one more call happens. Read the base case before you count.

The page checks both formulas: n frames for base case n ≤ 1, n + 1 frames for base case n = 0.

MCQOriginal practice question

A global a is 5. A procedure p(x) executes x := x + 1 and then a := a + x, and is called as p(a). What does a equal afterwards if the parameter is passed by value-result?

  1. 5
  2. 6
  3. 11
  4. 12

Answer: B

The copy becomes 6 and a becomes 5 + 6 = 11 inside the body. At return the copy value 6 is written back into a, overwriting the 11.

Why 11 is wrong. That is call by value, where nothing is copied back. Why 12 is wrong. That is call by reference, where x and a are the same cell, so the second statement reads 6 twice. Why 5 is wrong. That is the value before the call, which nothing here preserves.

The page runs all four modes as separate simulators and prints the four results.

MCQOriginal practice question

i is 1 and A holds 0, 0, 0. Procedure p(x) executes i := 2 and then x := 10, and is called as p(A[i]). Under call by name, which cell of A holds 10 afterwards?

  1. A[1]
  2. A[2]
  3. Both A[1] and A[2]
  4. Neither, because the assignment is invalid

Answer: B

Under call by name the formal is the expression A[i], evaluated at the point of use. By then i is 2, so the write lands in A[2].

Why A[1] is wrong. That is call by reference, and also value-result, where the address is captured while i is still 1. Why both is wrong. The statement is executed once, so exactly one cell is written. Why neither is wrong. Nothing about the assignment is invalid; only its target depends on when the expression is evaluated.

The page simulates all four modes on this program and checks that reference and name write different cells while value-result and reference agree.

MSQOriginal practice question

Which of the following statements about a display are true?

  1. It has one entry per nesting level of the program
  2. It has one entry per live activation record
  3. Its entry for a level holds the most recent activation at that level
  4. An entry overwritten by a same-level call must be saved and restored

Answer: A, C, D

The number of slots equals the number of nesting levels, which the compiler knows from the program text. Each slot holds the most recent activation at its level, and a same-level call overwrites a slot, so the displaced value is saved in the new frame and restored at return.

Why B is wrong. A display is not a copy of the stack: R and Q are both level 2 and share one slot. A display with one slot per live frame would not be a display, and could not be indexed by level.

The page simulates the display over the call sequence and checks that Q overwrites R at level 2 and that R's entry is restored.

NATOriginal practice question

An 8 MiB stack, frames of 96 bytes, no other stack usage. What is the greatest number of frames that can be allocated? Give the count.

Answer: 87381

8 388 608 divided by 96 is 87381.33, and a partial frame cannot be allocated, so the answer is 87381. Multiplying back: 87381 × 96 = 8 388 576, which fits, and 87382 × 96 = 8 388 672, which does not.

Why 87382 appears. That is rounding up, which allocates a frame that does not fit. Why 87381.33 appears. A count is an integer. Why 8192 appears. That is 8 MiB divided by 1024, which counts kilobytes rather than frames.

The page computes the floor, the product and the next product, and checks that the first fits and the second does not.

MCQOriginal practice question

x is a global equal to 1. show prints x and is declared at the top level. g declares a local x equal to 2 and calls show. The program calls g from the main block. What is printed under static scoping and under dynamic scoping?

  1. Static 1, dynamic 2
  2. Static 2, dynamic 1
  3. Static 1, dynamic 1
  4. Static 2, dynamic 2

Answer: A

show is written at the top level, so under static scoping its free x is the global, whatever called it: 1. Under dynamic scoping the lookup follows the control links to the caller g, whose local x is the most recent live binding: 2.

Why B is wrong. It reverses the two rules. Why C is wrong. It is the static answer twice, which is what a trace that never consults the call chain produces. Why D is wrong. It is the dynamic answer twice, which is what a trace that always consults the caller produces.

The page resolves the same name through the two different parent maps and checks that the two answers differ.

Revision sheet

The definitions, the arithmetic, the decision procedure and the traps, on one screen. Every number is the one this lesson computed.

Definitions in one line each

  • Activation record — the storage of one call: returned value, parameters, control link, access link, saved state and return address, locals, temporaries.
  • Control link — to the caller frame; saved frame pointer; used to return.
  • Access link — to the most recent frame of the enclosing definition; used for non-local reads.
  • Nesting level — how many procedures enclose the declaration textually; outermost is 0.
  • Display — array indexed by level; one slot per level; save and restore on same-level calls.
  • Static scoping — resolve along access links. Dynamic scoping — resolve along control links.

The arithmetic

  • Hops = level of the reading code − level of the declaration. Zero for a local.
  • Frame size = bookkeeping + parameters + locals + temporaries, rounded up to the alignment.
  • Peak stack = frames alive at the deepest point × padded frame size.
  • Depth limit = floor(stack bytes ÷ frame size), then check the product and the next product.
  • Recursive frame count = n for base case n ≤ 1, n + 1 for base case n = 0, plus the caller's frame.
  • Display cost = one index, always; chain cost = the level difference.

The four parameter modes

  • Value — a copy in the callee frame; changes lost. On this lesson's program: 11.
  • Reference — the caller's address; every write immediate. 12.
  • Value-result — copy in, copy out at return. 6, because the copy-back overwrites the body's own change.
  • Name — the argument expression, re-evaluated at each use. 12 here, but it writes A[2] rather than A[1] on the array program, where reference writes A[1].

Only value is C's ordinary parameter passing. The other three appear in hypothetical languages, which is where GATE puts them.

Eight traps, in the order they bite

  1. Access link set to the caller instead of the enclosing definition.
  2. A local given one hop instead of zero.
  3. Hop count taken from the stack depth instead of the level difference.
  4. Frames counted over the run instead of at the deepest point.
  5. Padding omitted from the frame size.
  6. Value-result assumed equal to reference.
  7. Name assumed equal to reference.
  8. Depth limit rounded up.

Quick self-test, answers in one word

  • Which link does a return use? control.
  • Which link does a non-local read use? access.
  • How many hops for a global from level 2? two.
  • How many bytes of bookkeeping in this lesson's frames? sixteen.
  • How many slots does a display have for a program with three levels? three.
  • Does value-result differ from reference when the body never touches the actual? no.
  • Is a static local inside the frame? no.
  • What happens to a pointer to a returned local? dangles.
