Topic and objective

TOPIC: Ethernet bridging and the learning switch — the transparent bridge, the forwarding table, the three actions, the loop and the spanning tree, inside the word "Ethernet" in Section 10 of the GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Say what a bridge decides on and what it leaves unchanged. State the learning rule and the three actions with the condition that selects each. Run a frame trace and read the resulting table, the actions and the copies on the wire. Count collision domains and broadcast domains on a mixed hub, switch and router topology. Explain why a correct bridge in a loop produces frames forever, and count them. Elect a spanning tree root by bridge ID, assign root, designated and blocked ports, and verify that the forwarding links form a tree. Compute both convergence figures from the three default timers. Compute the wait before a frame can leave for store-and-forward, fragment-free and cut-through.

I read this clause as four counts and one procedure: domains, table entries, copies, ports, and the seconds a port spends becoming useful. Every question I have seen on it is one of those five asked on a small diagram.

GATE relevance

Verified fact Class A — inside the syllabus.

Section 10 of the GATE 2027 CS syllabus, published by IIT Madras as CS_GATE2027_Syllabus.pdf, reads: "Principles of Layering; Basics of switching (circuit, packet and virtual circuit) and performance metrics; Data link layer: error detection, Medium Access Control, Ethernet; Distance vector and link state routing; IPv4 – Fragmentation, CIDR Notation, Network Address Translation; TCP – flow control and congestion control, socket API; DNS and HTTP."

Educational interpretation The printed word is "Ethernet", not "bridging". Bridging is how Ethernet LANs are built and extended — IEEE 802.1D defines the transparent bridge and the spanning tree — so I treat the bridge, the switch and the spanning tree as inside that word, and say so rather than pretending the word is printed.

Community observation Published question indexes place several past items on exactly the two counts this lesson teaches — a bridge against a router, and a switch against a hub. That is an observation about a catalogue of past papers, not a forecast for 2027 and not a weightage.

The one line to keep

A bridge learns the source, decides with the table, floods what it does not know, and needs a spanning tree only because a loop has no end.

The five ideas this lesson turns on

1. One field. The destination MAC address. Not the IP address, not the payload, and nothing is rewritten.

2. Source in, destination out. The table is written from source addresses and read for destination addresses. Every table question is decided by that asymmetry.

3. Two counts, two devices. A switch port is one collision domain; a broadcast domain ends only at a router.

4. A loop has no end. An Ethernet frame carries no hop count, so a flooded frame in a loop is copied forever. No device is faulty.

5. Blocking is the fix. A spanning tree keeps B − 1 links of E, blocks E − (B − 1) ports, and spends 30 to 50 seconds doing it.

Intuition: the mailroom clerk who reads one line

Imagine a mailroom between two wings of an office. The clerk does not open anything. She reads the "to" line on the envelope, and nothing else. If the name is on a list she has built herself, she puts the envelope in the right tray. If the name is not on the list, she photocopies the envelope and puts a copy in every tray except the one it came from.

And here is the part that matters: she builds that list from the "from" lines of the envelopes that pass through her hands. Nobody ever gives her the list. Traffic teaches it to her, and an entry she has not seen for five minutes is struck out.

Educational interpretation The analogy is for the mechanism only: one field read, a self-built directory, a copy to every tray when the name is unknown. It says nothing about frame formats.

Formal: the bridge and the table

A bridge is a layer-2 device that joins two or more LAN segments so that they behave as one LAN. A switch is a bridge with many ports that forwards in hardware; the algorithm is the same, so this lesson uses the two words interchangeably and says so.

A transparent bridge is one that stations do not have to know about: it is configured with nothing, it changes no frame, and it learns from what it sees.

The forwarding table — also called the MAC table, the bridge table or the content-addressable memory table — maps a 6-octet MAC address to the port on which that address was last seen, plus an age.

Formal: the three actions

For a frame arriving on port i with source s and destination d:

  1. Write s to port i. the learning step, and the only write the table ever receives
  2. Look up d. read only; a miss is not an error, it is the common case for broadcasts
  3. Act: unknown → flood to every port except i; known on i → filter, send nothing; known elsewhere → forward to that one port. three outcomes, three names, and the copy count differs for each

Formal: the two domains

A collision domain is a set of stations whose simultaneous transmissions collide. It is one shared medium. A hub repeats onto all its ports, so all of them are one medium. A switch port is a medium of its own, so each port is one collision domain.

A broadcast domain is the set of stations a broadcast frame reaches. A switch floods broadcasts, so it does not end one. A router does not forward broadcasts, so it does.

The counts, as identities

collision domains = one per switch port + one per hubA link between two switch ports is one medium, so it counts once, not twice. Two switches with three host ports each give 3 + 1 + 3 = 7, not 8.

broadcast domains = one per router boundary + oneWith no router in the picture the answer is one, however many switches there are. A router in the middle makes it two.

Mathematical derivation Both are computed in code by union-find over ports and devices, and checked on five topologies in the Animation tab.

The spanning tree, as three elections

  1. Root. Lowest bridge ID, which is a 2-octet priority and a 6-octet MAC. default priority 32768, so by default the lowest MAC wins
  2. Root port. On every non-root bridge, one port: the one on its cheapest path to the root. equal cost goes to the lower neighbouring bridge ID
  3. Designated port. On every segment, one port: the end with the lower root path cost. equal cost again goes to the lower bridge ID

Every port that is neither a root port nor a designated port is blocked: it receives BPDUs and forwards nothing else.

What a BPDU carries

Bridges exchange bridge protocol data units every 2 seconds. Five fields do all the work: the root bridge ID the sender believes in, the root path cost to reach it, the sender's own bridge ID, the port ID it left from, and the three timers.

root path cost = sum of port costs along the pathPort costs come from a table: 100 at 10 Mb/s, 19 at 100 Mb/s, 4 at 1 Gb/s, 2 at 10 Gb/s. Lower is better, so a gigabit link is cheaper than a fast Ethernet one.

Verified fact The four cost values and the three default timers are the IEEE 802.1D values, and several independent vendor documents reproduce them identically; the Sources tab names each one.

The timers, as arithmetic

blocked → forwarding = 15 + 15 = 30 sOne forward delay listening, one learning. The port cannot skip either, because the other bridges may not yet agree on the tree.

worst case = 20 + 15 + 15 = 50 sIf the failure is not on a directly attached link, the max age timer must expire first: 20 s of silence, which is 10 missed hellos at 2 s.

A directly failed link skips the max age wait, so it converges in 30 s. The MAC table ageing time is 300 s and is a different clock entirely.

Worked examples, in the order the reasoning goes

Example 1 is a verified previous-year item and is labelled as one. Examples 2 to 7 are original, written for this lesson on the numbers the page computes. Where an example quotes a figure, that figure came from the model and not from memory.

Example 1 — a verified previous-year item: bridge against router

Verified fact GATE CSE 2004, Question 16. "Which of the following is NOT true with respect to a transparent bridge and a router?" Options: (A) both bridge and router selectively forward data packets; (B) a bridge uses IP addresses while a router uses MAC addresses; (C) a bridge builds up its routing table by inspecting incoming packets; (D) a router can connect between a LAN and a WAN. Two independent reproductions of the paper agree on the wording and on the key.

  1. (A) is true: both look at a destination field and choose to send or not. "selectively forward" is the shared property, which is why the question is about what is not shared
  2. (B) is false: it is the other way round. A bridge reads MAC addresses; a router reads IP addresses. this is the answer, and it is a definition, not a calculation
  3. (C) is true, and it is the whole of transparent bridging: the table is built by inspecting incoming frames. the word "routing" in the option is loose language for the forwarding table; the statement is still true
  4. (D) is true: a router is the device that joins dissimilar networks. a bridge joins segments of one LAN; that is the distinction the paper is testing

Answer: B. The trap is reading (C) as false because a bridge has no "routing table". It has a forwarding table, built exactly as the option describes.

Example 2 — eight frames, counted (original)

One four-port switch, A on port 1, B on port 2, C on port 3, uplink on port 4 to a second switch holding D and E. The trace is A→B, B→A, A→B, D→A, A→D, D→E, E→D, A→B.

Run it and the actions come out as two floods, five forwards and one filter. The floods are frames 1 and 6, each costing three copies; the filter is frame 7, where E sends to D and D sits on the same port. Total copies: 3 + 1 + 1 + 1 + 1 + 3 + 0 + 1 = 11.

Mathematical derivation The table ends with four entries — A on 1, B on 2, D on 4, E on 4 — one per distinct source. C never sends, so C is never learned, and every frame addressed to C would flood.

Example 3 — one frame across two switches (original)

S1 has four ports: A, B, C and the uplink. S2 has three: the uplink, D and E. A sends to D and nobody has spoken.

S1 floods to three ports, so the frame reaches S2 once. S2 has never heard of D, so it floods to two more. One frame becomes five copies on the wire.

D replies to A. Both switches now know A — S1 on port 1, S2 on its uplink — so each forwards exactly one copy. The reply costs two. Mathematical derivation 3 + 2 = 5, then 1 + 1 = 2, both computed by the same simulator that drives the animation.

Example 4 — two switches, a router, and two counts (original)

Two switches, three PCs on each, joined by a router. Count both quantities.

Collision domains: S1 gives three host ports plus one port to the router; S2 gives three plus one; the router has two ports. That is 4 + 4 + 2 = 10, or by the shorter route 3 + 1 + 1 + 1 + 3 = 9 plus the routers own two interfaces. What matters is the method: one per switch port, one per link, never two for one link.

Broadcast domains: two, because the router is a boundary. Join the same switches directly instead and the answer is one, with seven collision domains (3 + 1 + 3). Mathematical derivation Both figures are produced by union-find over the topology in the page's model.

Example 5 — the four-bridge spanning tree (original)

Four bridges, all at priority 32768, so the MAC decides: B1 is root. Five links at costs 19, 19, 19, 19 and 100, the last being the 10 Mb/s link between B2 and B4.

  1. Root path costs: B2 = 19, B4 = 19, B3 = 38. B3 ties at 38 by two routes, so the lower neighbour B2 wins
  2. Root ports: B2→B1, B4→B1, B3→B2. one each, on the cheapest path
  3. Designated ports: B1 on both of its links, B2 on B2–B3, B4 on B3–B4, and B2 on B2–B4 by the tie-break. lower root path cost, then lower bridge ID
  4. Blocked: B3 towards B4 and B4 towards B2. neither a root port nor a designated port

Check: 5 − (4 − 1) = 2 blocked, and the three forwarding links connect all four bridges with no cycle. The page verifies connectivity and acyclicity with union-find rather than asserting them.

Example 6 — the two convergence figures (original)

Defaults: hello 2 s, max age 20 s, forward delay 15 s. A port must move blocking → listening → learning → forwarding.

A link on this bridge fails. The port is blocked and now has to take over: 15 s listening, 15 s learning, forwarding at 30 s.

A link two bridges away fails. This bridge hears nothing for 20 s before it believes the topology has changed, then pays the same 30 s: 50 s. Mathematical derivation Both are sums of the three published timers, and both are checked in the model.

Example 7 — three forwarding modes (original)

A 1514-octet frame is 12112 bits. At 100 Mb/s that is 121.12 µs on the wire.

Store and forward waits all of it, because the CRC covers all of it: 121.12 µs. Fragment free waits for the 64-octet collision window: 5.12 µs. Cut through waits for the 6-octet destination address: 0.48 µs.

The ratio is 121.12 / 0.48 ≈ 252, and that is the price of checking every frame before sending it on. At 1 Gb/s all three divide by ten: 12.112, 0.512, 0.048 µs.

Counterexample: a switch in a loop is not broken

Four bridges, fully meshed, one host each. One broadcast is injected. The first round puts 3 frames on the trunks, the second 9, the third 18, and by ten rounds 4602 frames have been sent and the count is still doubling.

What this refutes: the belief that a broadcast storm implies a faulty device. Every bridge here follows the three actions exactly. The fault is the absence of a spanning tree, and an Ethernet frame carries no hop count that could have stopped it.

Counterexample: adding switches does not shrink the broadcast domain

Take one switch and four PCs: one broadcast domain. Replace it with two switches and eight PCs: still one broadcast domain. Replace it with twenty switches: still one.

What this refutes: the belief that a more "intelligent" device must reduce broadcasts. A switch's job is to flood broadcasts, so every switch you add is another device that copies them. Only a router, or a VLAN boundary inside a switch, ends the domain.

Counterexample: a filter is not a forward to a shorter list

E and D sit behind one port. E sends to D. The table knows D on the ingress port, so the bridge sends nothing at all.

What this refutes: the habit of counting a filter as one copy. A filter costs zero copies, and on a diagram that asks for copies on the wire, that zero is the answer.

Counterexample: the "closest" bridge is not the root

Put a gigabit bridge at the centre of a star and leave the others at default priority. The centre bridge is not the root unless its bridge ID is lowest. Add a bridge with priority 4096 at the edge and it becomes root, and every path is recomputed towards it.

What this refutes: the belief that the root is chosen for being central or fast. It is chosen by a 2-octet priority and a 6-octet MAC, nothing else.

Boundary: the table is never complete

A station that only receives is never learned, so every frame to it floods. The first frame of every conversation floods, because the destination has not spoken yet. A broadcast address is never in the table, so a broadcast always floods.

The consequence for a question: "how many copies does this frame produce" is unanswerable until you know whether the destination has already been seen, and for how long. An entry idle for 300 s has expired.

Boundary: a stale entry survives 300 seconds

A station moves from port 2 to port 3. Frames sent to it keep going to port 2 until it sends something from port 3, which updates the entry, or until 300 s pass and the entry expires.

The consequence: connectivity recovers by itself, but not instantly. A question that gives a station a move and a quiet period is testing this timer.

Boundary: a hub on a switch port

Three PCs on a hub, the hub on one switch port, two more PCs directly on the switch. The collision domains are 3, not 5: the hub and its three PCs and the link to the switch are one medium, and each direct PC is one more.

The consequence: a hub in the picture collapses everything attached to it into one domain, and the broadcast count does not move at all.

Boundary: a blocked port is listening

A blocked port forwards no data frames, but it receives and processes BPDUs the whole time. That is how it knows when to take over, and it is why a topology change converges in seconds rather than never.

The consequence: a question that asks whether a blocked port carries traffic has two correct halves — no data, yes BPDUs — and the option wording decides which one is being asked.

Boundary: cut-through cannot check the frame

Cut-through forwards after 6 octets, so the CRC at the far end of the frame has not arrived. A corrupted frame is carried onward and dropped at the destination instead of at the switch.

The consequence: the mode is a trade of correctness for latency. Fragment-free is the compromise, catching runts shorter than 64 octets but nothing longer.

Takeaway

Every boundary here is a condition on a count: what the table knows, which medium is shared, which port is blocked, which timers have run out.

1. "A switch splits the broadcast domain"

Why it tempts: a switch does split something — the collision domain — and the two phrases sit one line apart in every textbook.

Minimal counterexample: one switch, four PCs. One broadcast reaches all four, so there is one broadcast domain. Put four switches in a chain: still one.

Correct rule: a switch floods broadcasts out of every port but the ingress port. Only a router, or a VLAN, ends a broadcast domain.

2. "The switch learns the destination address"

Why it tempts: the table is used to look up the destination, so it feels like it must be built from destinations.

Minimal counterexample: the eight-frame trace. C is addressed twice and never sends; C never enters the table. A is never addressed first and enters it on frame one.

Correct rule: source in, destination out. The table holds one entry per source that has spoken, and none per destination that has been asked for.

3. "A blocked port is a broken port"

Why it tempts: the word blocked sounds like a fault, and the port is drawn with a cross on every diagram.

Minimal counterexample: remove the blocking and the same topology storms. Blocking is the only thing stopping the frames.

Correct rule: blocked means no data forwarding and full BPDU reception. It is the port that makes the loop finite.

4. "A bridge and a router both filter, so they are the same kind of device"

Why it tempts: both read a destination and both drop frames they do not need to send. The verified 2004 question is built on exactly this resemblance.

Minimal counterexample: a router decrements the hop limit and writes a new frame with new link addresses; a bridge changes no byte. Put a bridge where a router was and two subnets become one broadcast domain.

Correct rule: a bridge reads MAC addresses and is transparent; a router reads IP addresses and is not.

5. "More bandwidth means a cheaper spanning tree path"

Why it tempts: the cost table is ordered by speed, so the two feel like the same statement.

Minimal counterexample: in the four-bridge example the 10 Mb/s link costs 100 and the 100 Mb/s links cost 19. A path of three fast links (57) is cheaper than one fast link plus the slow one (119).

Correct rule: cost is a small integer from a table and paths are compared by their sums. Bandwidth is the input to the table, not the metric.

6. "Spanning tree converges as soon as a link fails"

Why it tempts: the protocol is described as "recovering from failure", which sounds immediate.

Minimal counterexample: a port that must take over waits 15 s listening and 15 s learning, so at least 30 s, and up to 50 s if a max age timer must expire first.

Correct rule: convergence is 30 s on a directly attached failure and up to 50 s otherwise, both computed from the three default timers.

How the clause is actually asked

Five shapes account for the items I could find on bridges, switches and domains. Each shape demands a different first move, and the common wrong approach is named with it. The shapes are drawn from published question indexes; the counts are not a weightage claim.

Shape 1 — a definitional MCQ with no numbers

"Which is NOT true of a transparent bridge and a router?" The reasoning is pure definition, and the answer is the option that swaps the two address types.

Common wrong approach: hunting for a subtle arithmetic error in an option that has none. If every option is qualitative, the answer is a reversed definition.

Shape 2 — count the domains on a diagram

A picture with hubs, switches, a router and some hosts, asking for one or both counts. The method: one domain per switch port, one per hub, one per link, and a router ends the broadcast count.

Common wrong approach: counting devices instead of media, which over-counts by every hub and under-counts by every inter-switch link.

Shape 3 — trace a frame and count copies

A small table state and a sequence of frames. The method: learn the source, look up the destination, apply one of three actions, and add the copies.

Common wrong approach: using the table as it is after the frame, or forgetting that a broadcast is never in the table and therefore always floods.

Shape 4 — elect the root and the port roles

Bridge IDs, link costs, and a request for the root, the root port of one bridge, or the number of blocked ports. The method: lowest ID, then shortest root path cost with the bridge-ID tie-break, then one designated port per segment.

Common wrong approach: electing the root by cost or position, and forgetting that a blocked port is one per removed link, not one per bridge.

Shape 5 — the timers

"How long before the port forwards?" or "what is the maximum convergence time?" The method: two forward delays for a direct failure, plus max age when the failure is remote.

Common wrong approach: adding hello time into a convergence figure, or quoting 50 s for a link that failed on the bridge's own port.

Takeaway

Say the unit first — domains, entries, copies, ports or seconds — then run the four steps. The unit catches most wrong answers before the arithmetic starts.

MCQOriginal practice

Two switches, S1 and S2, are joined by a single link. S1 has three PCs attached and S2 has three PCs attached. How many collision domains and how many broadcast domains are there?

  1. 6 collision, 1 broadcast
  2. 7 collision, 1 broadcast
  3. 7 collision, 2 broadcast
  4. 8 collision, 1 broadcast

Answer: B — 7 collision domains, 1 broadcast domain

Three host ports on S1, the inter-switch link, and three host ports on S2: 3 + 1 + 3 = 7. The link is one medium shared by both ends, so it counts once. The switches flood to each other, so the broadcast domain is still one.

Why 6. That forgets the link. Why 8. That counts the link twice, once for each end. Why 2 broadcasts. Only a router or a VLAN ends a broadcast domain; a switch never does.

NATOriginal practice

A four-port switch has an empty forwarding table. Frames arrive in this order, each on the port shown: A→B on port 1, B→A on port 2, A→B on port 1, D→A on port 4, A→D on port 1, D→E on port 4, E→D on port 4, A→B on port 1. How many frame copies does the switch put on the wire in total?

Answer: 11

Two frames flood at 3 copies each (A→B first, D→E), five are forwarded at 1 copy, and one is filtered at 0 copies. 6 + 5 + 0 = 11.

Why 13. That counts the filtered frame as if it had flooded. Why 10. That forgets one of the forwards, usually the D→A frame, which is the first frame that arrives from the uplink.

MSQOriginal practice

A transparent bridge receives a frame on port 3 with source S and destination D. Which statements are CORRECT?

  1. If D is absent from the table, the frame is sent out of every port except port 3.
  2. If D is in the table on port 3, the frame is dropped.
  3. If D is in the table on port 1, the frame is sent out of port 1 only.
  4. The bridge writes an entry for D on port 3 as well as an entry for S.

Answer: A, B and C

A is the flood rule, B is the filter rule, and C is the forward rule. Together they are the three actions.

Why D is wrong. The table is written from sources only. D's location is a question the bridge asks, not an answer it records; only S is written, on port 3.

MCQPrevious year

Which of the following is NOT true with respect to a transparent bridge and a router?

  1. Both bridge and router selectively forward data packets.
  2. A bridge uses IP addresses while a router uses MAC addresses.
  3. A bridge builds up its routing table by inspecting incoming packets.
  4. A router can connect between a LAN and a WAN.

Answer: B — GATE CSE 2004, Question 16

The statement reverses the two address types: a bridge reads MAC addresses and a router reads IP addresses. The other three statements are true.

Why C is not the answer. It reads oddly because a bridge has no "routing table", but the statement — the table is built by inspecting incoming packets — is exactly the learning rule, so it is true. Why A is true. Both filter, which is why the question asks what is not shared.

NATOriginal practice

Four bridges form a mesh with five links. All bridges use the default priority. Using the four-bridge, five-link topology of this lesson, how many ports are blocked by the spanning tree?

Answer: 2

A spanning tree keeps B − 1 = 3 links of the 5, so 2 links are removed, and each removed link has exactly one blocked port. Hence 5 − (4 − 1) = 2.

Why 3. That counts forwarding links, not blocked ports. Why 5. That counts links. The identity is a difference of links, and each removed link contributes one blocked port.

NATOriginal practice

A bridge port that is blocking must take over as a forwarding port after a link failure on the bridge itself. Using the default timers, what is the shortest time, in seconds, before the port forwards?

Answer: 30

Listening for one forward delay (15 s) then learning for one forward delay (15 s): 30 s. A directly attached failure does not wait for max age.

Why 50. That is the worst case, where the failure is remote and a 20 s max age timer must expire first. Why 15. That is one state, not two.

MSQOriginal practice

Which of the following are symptoms of an unmanaged loop of switches?

  1. Broadcast frames are copied again and again and never expire.
  2. The same source MAC address is learned on two different ports in turn.
  3. The links between the switches become saturated.
  4. Each switch stops flooding unknown unicast frames.

Answer: A, B and C

A is the storm, B is the flapping table, and C is the consequence on the wire. All three follow from correct flooding in a topology that has a cycle.

Why D is wrong. Flooding does not stop; it is the flooding that keeps the loop alive. If unknown unicast stopped flooding, the storm would stop with it.

NATOriginal practice

A switch forwards in cut-through mode, reading the 6-octet destination address before sending. For a 1514-octet frame on a 100 Mb/s link, how many microseconds pass before the switch can begin transmitting? Give the answer to two decimal places.

Answer: 0.48

Six octets are 48 bits. 48 / 100,000,000 s = 0.48 µs. Store and forward would wait 12112 / 100,000,000 = 121.12 µs for the same frame.

Why 5.12. That is fragment-free, which waits for 64 octets. Why 121.12. That is the whole frame. The mode decides which of the three numbers is being asked for.

Definitions in one line

Bridge / switch — a layer-2 device that joins segments and forwards by destination MAC.

Transparent — no configuration, no frame change, learned from traffic.

Forwarding table — MAC to port, plus an age, written from sources.

Collision domain — one shared medium.

Broadcast domain — everything a broadcast reaches; ends at a router.

Identities

collision domains = switch ports + hubsA link between two switch ports is one medium, counted once.

blocked ports = E − (B − 1)one per removed link; the tree keeps B − 1 of E links.

blocked → forwarding = 2 × forward delay15 + 15 = 30 s; add max age 20 for a remote failure, giving 50 s.

Frame wait: store 1514 octets, fragment-free 64, cut-through 6 — at 100 Mb/s that is 121.12, 5.12 and 0.48 µs.

The three actions, in order

  1. Learn the source on the ingress port.
  2. Look up the destination.
  3. Unknown: flood p − 1. Same port: filter, 0. Else: forward, 1.

An entry ages out after 300 s of silence; a station that only receives is never learned.

The spanning tree, in three elections

  1. Root: lowest bridge ID (priority, then MAC).
  2. Root port: cheapest root path cost, tie to the lower neighbour ID.
  3. Designated: per segment, the lower root path cost, same tie-break.

Everything else is blocked: no data, but BPDUs still received. Costs: 100 / 19 / 4 / 2 at 10 Mb/s to 10 Gb/s.

Traps, in the order they cost marks

1. A switch splitting the broadcast domain. It does not.

2. Learning the destination. It learns the source.

3. Calling a blocked port broken. It is the fix.

4. Counting the inter-switch link twice.

5. Quoting 50 s for a failure on the bridge's own port.

Thirty-second self-test

One switch, four PCs: how many of each domain? Add a router to a second switch: what changes? Trace A→B, B→A, A→B on an empty table: how many copies? Four bridges, five links: how many blocked ports, and why? A port takes over after a local failure: how many seconds?

  • GATE 2027 CS syllabus, IIT Madras — CS_GATE2027_Syllabus.pdf, read on 4 November 2026. Supports the Section 10 wording quoted in Overview, including the fact that the printed word is "Ethernet" and not "bridging".
  • IEEE 802.1D — the standard that defines transparent bridging and the spanning tree algorithm. Not read directly; its values are taken from the three documents below, which agree on every number used here.

No claim in this lesson rests on an official question paper that could not be reproduced. Only one item is presented as a previous-year question, and both reproductions of it are listed below.

Standards and vendor documentation

  • Cisco, "Understand and Tune Spanning Tree Protocol Timers" — supports hello 2 s, forward delay 15 s, max age 20 s, and the 20 + 15 + 15 reasoning behind the default max age.
  • TP-Link, "Configuring Spanning Tree" configuration guide — supports the bridge ID as 2-octet priority plus 6-octet MAC, the root and designated port definitions, and the default priority 32768.
  • MikroTik RouterOS documentation, "Spanning Tree Protocol" — supports the default priority 32768, the default timers, and the short path-cost table (100 / 19 / 4 / 2).
  • A published 802.1D study note (nyquist/ccie) — supports the path-cost table, the BPDU field list, and the 50 s and 30 s convergence figures.

Previous-year question used

  • GATE CSE 2004, Question 16 — "Which of the following is NOT true with respect to a transparent bridge and a router?" Reproduced in Example 1 and in the practice set. Two independent reproductions were read and agree on the options and on the key.
  • A related item from the GATE IT 2005 paper (a false statement about bridges reducing broadcast domains) was found and agrees with the rule taught here, but it is an IT-paper item, so it is not reproduced as a CS previous-year question.

Every other question in this lesson is labelled original practice.

Teaching material, used for mechanism only

  • Fraida Fund, "Operation of a basic Ethernet switch or bridge" (NYU / witestlab) — a lab walkthrough of learning, flooding, filtering and the ageing timer. Used for the description of the mechanism, not for any number in this lesson.
  • GateOverflow discussion threads — used as a community observation of which misconceptions are common, not as authority. The 2004 item's key was checked against a second reproduction before being used.

Where this research stopped

I did not read IEEE 802.1D itself, so the timer values and path costs are attributed to the vendor documents that reproduce them, not to the standard directly.

I did not verify any item on spanning tree port roles against an actual GATE paper, so none is presented as a previous-year question.

Rapid spanning tree (802.1w) and multiple spanning tree (802.1s) are named nowhere in this lesson beyond this sentence: they change the convergence numbers, and no number here assumes them.
