Topic and objective

TOPIC: IPv4 fragmentation, CIDR notation and network address translation — one clause of GATE 2027 Section 10, Computer Networks.

LEARNING OBJECTIVE: Read a prefix as a cut position in a 32-bit number, compute the five numbers of the block that contains a given address, and pick the winning entry in a routing table by longest prefix match rather than by first match. Decide when two adjacent blocks may be merged into one, and check that the merged block steals no address. Fragment a datagram for a given MTU by computing the payload budget, rounding it down to a multiple of eight, and writing the offset, the more-fragments bit and the identification field for each piece; then do it again at a second link, keeping every offset relative to the original data. Finally, follow one packet out through a NAT table and back, and name exactly which header fields change in each direction.

I read this clause as one arithmetic question asked in three costumes: how many bits belong to whom, where a byte sits inside a bigger byte string, and who is allowed to rewrite an address. The block arithmetic of CIDR, the offset arithmetic of fragmentation and the table arithmetic of NAT are the same three operations — cut, index, substitute — applied to an address, to a payload and to a connection.

Prerequisites

  • Binary, and bitwise AND. Every number here is produced by ANDing an address with a mask, or by dividing a byte count by eight. Built in Number Representation and Arithmetic.
  • Encapsulation, and what a per-hop header is. An IP datagram is a header plus data, and the data may itself be a transport segment. Built in Layering, Switching and Performance Metrics.
  • Store-and-forward, and link capacity. An MTU is a property of one link, which is why the same datagram may be too large on the next hop. Same lesson as above.
  • Routing tables and next hops. Longest prefix match is what a routing table is read with; the table itself is built by the routing protocols. Built in Distance Vector and Link State Routing.
  • Transport headers and ports. The UDP header sits inside the IP data, which is why fragment 1 carries the ports and the others do not. Built in Layering, Switching and Performance Metrics.
  • Sets and union. Aggregation is a union of address blocks, and a correct merge covers exactly that union. Built in Sets and Set Operations.

Nothing about TCP congestion control, DNS or HTTP is assumed; those are the next two lessons in this section.

The five ideas to leave with

  1. A prefix is a cut, not a mask value. Turn it into a block size first, and every other number follows by counting from the two ends.
  2. Longest prefix match, never first match. A default route is a prefix of length zero and wins nothing.
  3. Two blocks merge exactly when they are the same size, adjacent, and aligned as a pair — and the merged block must capture no foreign address.
  4. The fragment budget is MTU minus header, and it is rounded down to a multiple of eight. Only the last fragment may carry a remainder.
  5. Offsets are absolute positions in the original data. A second fragmentation continues the numbering; it never restarts it.

Intuition: a street, a parcel, and a receptionist

An IPv4 address is a 32-bit number, and a prefix is a pair of scissors. Where you cut decides which part names the street and which part names the house. Move the cut one bit left and the street doubles in length while each street loses half its houses. Nothing about the number changed; only the cut moved.

That single picture covers the whole addressing half of this clause: block size, network address, broadcast address and usable hosts are all consequences of where the cut sits. Fragmentation is a different costume for the same arithmetic — a parcel too big for a van is cut into boxes, and each box is labelled with the byte range it carries, measured from the start of the original parcel, not from the previous box. NAT is the third costume: a receptionist who signs for parcels on behalf of everybody inside, and who has to remember which insider each returning parcel belongs to.

Level 1 — Intuition, in one sentence each

  • Prefix. How many of the leftmost bits are the street name.
  • Block. All the addresses with the same street name, which is a run of consecutive numbers starting at a multiple of its own length.
  • Longest prefix match. When several rules apply, obey the most specific one.
  • Aggregation. Two neighbouring streets with the same destination can be announced as one bigger street, provided the bigger street contains nobody else.
  • MTU. The biggest parcel the next van will take, box and label included.
  • Fragment. One box, labelled with the byte range it carries and whether more boxes follow.
  • NAT. One public return address for many private senders, with a ledger that says which sender each reply belongs to.

Level 2 — Formal definitions

Verified fact A CIDR block is written a.b.c.d/p, where p is the prefix length. Its mask has p one-bits followed by 32 − p zero-bits. Its network address is the bitwise AND of the address and the mask, and its block contains exactly $$2^{32-p}$$ consecutive addresses beginning at that network address.

Usable hosts. With h = 32 − p host bits, $$2^h - 2$$ addresses may be assigned: the all-zero host value names the network and the all-one host value is the directed broadcast. Two exceptions are stated in Edge cases.

Longest prefix match. Among the entries whose network address equals the destination AND that entry's mask, forward to the one with the largest prefix length. If none matches, use the default route, which is the entry with prefix length zero.

MTU and fragmentation. For a link of MTU M and header length H, the payload budget is M − H and the usable payload per fragment is $$8\left\lfloor \frac{M-H}{8} \right\rfloor$$. A datagram of L bytes of data becomes $$\left\lceil \frac{L}{\text{usable}} \right\rceil$$ fragments, the last of which may carry any remainder.

Level 5 — the boundary conditions, stated up front

The formula $$2^h - 2$$ assumes a subnet with a network address and a broadcast address. It fails for a /31 point-to-point link and for a /32 single host, where a later standard reuses those two values. The fragmentation formula assumes the datagram is larger than the budget and that the don't-fragment bit is clear; if DF is set, the datagram is not fragmented at all, and it is discarded with an error back to the source. The offset field is 13 bits, so the largest expressible position is $$8191 \times 8 = 65528$$ bytes, which is why the maximum datagram of 65535 bytes can still be described. And the aggregation rule assumes both halves are reachable through the same next hop; without that assumption, a merge can send foreign traffic to the wrong place.

Level 3 and 4 — why each mechanism is built this way

The three mechanisms look unrelated and are not. Each one answers the question "where does this byte, or this address, sit inside a longer string, and who is allowed to change it". CIDR asks where the network part ends inside a 32-bit address. Fragmentation asks where a fragment's first byte sits inside the original payload. NAT asks which private address sits behind one public address-and-port pair. All three are answered by an index plus a substitution, and all three are examined by making you compute the index.

That is why the arithmetic in this clause is short and the mistakes are frequent: the operations are trivial, and the errors are all about units and bases — bits against bytes, block size against mask value, offset units against offset bytes, total length against data length.

Why the fragment offset is counted in eights

Mathematical derivation The offset field is 13 bits. Counting in bytes, 13 bits reach only 8191 bytes, which is far below the 65535-byte maximum datagram. Counting in 8-byte units multiplies the reach by eight, to 65528 bytes, which is just short of the maximum data a 20-byte header can precede. The unit was chosen so that the field could address the whole datagram.

Mathematical derivation The cost of that choice is the alignment rule. A fragment's start must be a multiple of 8, so every fragment except the last must carry a multiple of 8 bytes. This is why the usable payload is the budget rounded down: rounding up would produce a start position that is not a whole number of units, which the field cannot express.

Why reassembly is at the destination only

Verified fact IPv4 places reassembly at the destination host. A router that reassembled would spend buffer memory on every passing datagram, and would then have to fragment the result again if the next link were smaller. GATE CSE 2024 Set 2 Question 28 tests exactly this as a statement set, and the two true statements are "fragmentation may happen at any router whose outgoing link is too small" and "reassembly happens only at the destination".

Mathematical derivation A consequence worth knowing: if one fragment is lost, the destination cannot reassemble, so the transport layer must resend the whole segment, because the sender never learned that fragmentation happened at all. That is the reasoning behind the second correct option of GATE CSE 2021 Set 1 Question 45.

Why NAT needs a port

Verified fact Plain NAT maps one private address to one public address. When many hosts must share a single public address, the device also rewrites the source port, so the pair (public address, public port) becomes the key of the table. This is port address translation, and it is what a home router does.

Mathematical derivation The pair must be unique, or two flows collide: two internal hosts using the same source port would receive each other's replies. The page checks uniqueness on its own table rather than assuming it. And because the source address changed, the header checksum — which covers the header — must be recomputed; the total length does not change, because no byte was added or removed.

Level 6 and 7 — where the exam actually bites

Two shapes account for nearly every question in this clause. The first gives you an address, a prefix and a question about one of the five numbers, or a table and a destination. The second gives you a datagram, one or two MTUs and asks for a count, an offset, a size, or which statement is true. Both are mechanical once the units are fixed, and both are decided by a single line of arithmetic that the paper expects you to write down.

The GATE patterns tab lists every previous-year item this page recomputed, with its year and set. Nothing there is a claim about 2027; it is a list of what has been asked, so that the shape of the question is familiar before it arrives.

Level 5 again — what breaks each formula

  • Block size assumes the address is inside the block you computed. Round down, then check the answer is between the network and the broadcast address.
  • Longest match assumes at least one entry matches. If none does and there is no default, the packet is discarded, and "interface 0" is not a fallback.
  • Aggregation assumes the same next hop. Two blocks that merge arithmetically but leave through different interfaces must stay as two entries.
  • Fragment count assumes the datagram exceeds the budget. If it fits, there is one fragment, no fragmentation, and MF stays zero.
  • Offset arithmetic assumes the same header length in every fragment. If options are present and not copied, the header length changes and the budget changes with it.

Level 9 — consolidation before the animation

  1. Prefix → block size → block start → five numbers. Never skip the second step.
  2. Match by ANDing, choose by prefix length. Write the candidate list down; it is two lines and it prevents the first-match error.
  3. Merge only equal, adjacent, aligned pairs, then count the union to prove nothing extra was captured.
  4. Budget, floor to eight, count, then offsets as running sums over eight.
  5. Write the unit next to every number: bytes, units of eight, or addresses. Most lost marks are unit errors.

Worked examples, page 1 of 2 — five fragmentations, every number recomputed

Each list below was produced by the model on this page and then checked against five invariants: the data sums to the original, every non-last fragment carries a multiple of 8, the offsets are the running sums over 8, every fragment fits the MTU, and the more-fragments bit is zero only on the last. The counts are printed under the canvas in the Animation tab.

Example 1 — GATE CSE 2016 Set 1 Q53 (NAT, 2 marks)

Datagram 1000 bytes including a 20-byte header; link MTU 100 bytes. Data is 980. Budget is 100 − 20 = 80, already a multiple of 8. 980 = 12 × 80 + 20, so there are 13 fragments; the twelfth ends at byte 959 and the thirteenth carries 20 bytes with total length 40, offset 120, MF = 0.

Verified fact The accepted answer to this paper item is 13. The popular wrong answer, 12, is the number of full fragments.

Example 2 — GATE CSE 2025 Set 2 Q23 (MCQ, 1 mark)

UDP payload 7488, UDP header 8, so the IP data is 7496. Ethernet data field 1500 with no IP options gives a budget of 1480. 7496 = 5 × 1480 + 96, so 6 fragments, and the last is 96 + 20 = 116 bytes.

The options offered were 5/1488, 6/88, 6/108 and 6/116. Each wrong option corresponds to one unit error: ignoring the UDP header, or reporting the last fragment's data without its IP header.

Example 3 — GATE CSE 2015 Set 2 Q52 (MCQ, 2 marks)

UDP user data 8880 with an 8-byte UDP header, so 8888 bytes of IP data, MTU 1500, IP header 20. Budget 1480. 8888 = 6 × 1480 + 8, so 7 fragments, and the last fragment's offset is 6 × 1480 / 8 = 1110 units.

The eighth byte of data in the last fragment is the entire remainder; it is not an error in the arithmetic. A remainder of exactly zero would have produced six fragments instead.

Example 4 — GATE CSE 2021 Set 1 Q45 (MSQ, 2 marks)

TCP segment 1400 bytes, MTU 1500 then 820, IP header 20, DF clear. The first link carries the datagram whole. At the router the budget is 800, so the datagram becomes 800 + 600 of data: fragment sizes 820 and 620 bytes.

The two correct statements are that two fragments are created with the second 620 bytes, and that a lost second fragment forces the source to resend the whole TCP segment. The statement that the destination port can be read from the second fragment alone is false: the transport header lives in fragment 1.

Example 5 — GATE CSE 2024 Set 1 Q65 (NAT, 2 marks)

Datagram 1420 bytes including a 20-byte header, so 1400 bytes of data. First link MTU 542: budget 522, usable 520. 1400 = 520 + 520 + 360, so three fragments leave the sender. Second link MTU 360: budget 340, usable 336. Each 520 becomes 336 + 184; the 360 becomes 336 + 24. So 6 fragments reach the receiver, carrying 336 + 184 + 336 + 184 + 336 + 24 = 1400 bytes.

Mathematical derivation The offsets of the six pieces are 0, 42, 65, 107, 130 and 172 units. They are positions in the original data: the pieces of the second fragment start at byte 520, which is 65 units, and never restart at zero. That is what lets the receiver reassemble without knowing the path.

Example 6 — GATE CSE 2015 Set 3 Q38 (NAT, 1 mark)

In 200.10.11.144/27, the fourth octet of the last assignable host. A /27 leaves five host bits, so the block size is 32 and the mask octet is 224. 144 AND 224 = 128, so the block is .128 to .159; .159 is the broadcast, so the last host is 158.

Accepted answer 158. The tempting 159 is the broadcast address, and it is usually one of the options.

Example 7 — GATE CSE 2019 Q28 (MCQ, 1 mark)

Mask 255.255.255.252 is a /30 with block size 4. Of 100.10.5.2, .5 and .6, the block starts are .0, .4 and .4, so only N and P share a subnet — option C.

Two addresses three apart can be in different blocks, and two addresses one apart can be in the same one. The boundary decides.

Example 8 — GATE CSE 2023 Q55 (NAT, 1 mark)

Destination 200.150.68.118 against a table of /16, /19, /24 and /27. The first three match; the /27 entry 200.150.68.64/27 ends at .95 and does not. The longest match is the /24, so the packet leaves on interface 3.

Checking the /27 range first is the fast route: one range check eliminates it and the answer is the next longest.

Example 9 — GATE CSE 2024 Set 1 (longest match, NAT, 2 marks)

Table 10.1.1.0/24 → R1, 10.1.1.128/25 → R2, 10.1.1.64/26 → R3, 10.1.1.192/26 → R4. Hosts .16 → R1, .72 → R3, .132 → R2, .191 → R2, .205 → R4. Two hosts take R2, twenty packets each, so 40 packets.

Host .191 is the interesting one: it is inside 10.1.1.128/25 and also inside the /24, and it is not inside 10.1.1.192/26 because 191 is below 192. That single comparison is the whole question.

Example 10 — GATE CSE 2022 Q45 (MSQ, 2 marks)

Four subnets: 12.20.164.0/22, 12.20.166.0/23, 12.20.168.0/23, 12.20.170.0/23. The /22 runs from 164 to 167 and already contains the /23 at 166. The blocks at 168 and 170 are the two halves of 168.0/22. So 164.0/22 and 168.0/22 cover everything, and cover 2048 addresses, exactly the union of the four.

Community observation The official key was B and D. Community discussion of this item notes that merging 168.0/23 with 170.0/23 is only valid if both are reached through the same next hop; that assumption is not stated in the question. State it whenever you aggregate.

Example 11 — GATE CSE 2014 Set 3 Q26 (NAT, 1 mark)

Destination 131.23.151.76 against 131.16.0.0/12, 131.28.0.0/14, 131.19.0.0/16 and 131.22.0.0/15. ANDing gives 131.16.0.0 (match, /12) and 131.22.0.0 (match, /15); the /14 and /16 entries do not match. The /15 is longer, so the packet leaves on interface 1.

Note the direction of the answer: the shorter of the two matching prefixes is not chosen. Longest wins even when the shorter one appears earlier in the table.

The boundary cases that change the answer

Each item below is a case where the standard formula gives the wrong answer, or where the formula's assumption fails. They are here because a well-written paper can reach any of them, and because two of them are the reason a formula that always works is worth stating with its assumptions.

1. /31 and /32 break the minus-two rule

Verified fact A /31 has two addresses, and a later standard allows both to be used on a point-to-point link, so the usable count is 2 rather than 0. A /32 is a single host route, where the one address is the host itself, so the usable count is 1 rather than −1.

The page computes usable as $$2^h - 2$$ for prefixes up to /30 and as $$2^h$$ for /31 and /32, and says so in the code. If a question uses the older convention, both addresses of a /31 are still unusable; read the question's convention before answering.

2. A datagram that already fits is not fragmented

If the total length is at most the MTU, there is one fragment, MF is zero, the offset is zero, and no new header is created. A question that gives a datagram of exactly the MTU is testing whether you notice.

Similarly, a datagram of MTU + 1 byte becomes two fragments, the second carrying one byte. The count is a ceiling, and it never rounds down to zero.

3. DF set means no fragmentation at all

Verified fact If the don't-fragment bit is one and the datagram exceeds the MTU, the router does not fragment it: it discards the datagram and reports the problem to the source, which is how path-MTU discovery works.

The reporting protocol is ICMP, which the 2027 wording no longer names. Treat the DF behaviour as the syllabus item and the ICMP message as context.

4. An MTU smaller than the header

If the MTU is 20 bytes or less, the budget is zero or negative, and no fragment can be formed. The page's fragmentation routine returns an empty list in that case rather than dividing by zero, and the checks would fail loudly if a question implied it.

Real links do not have MTUs that small, but a malformed question can. Saying "no valid fragmentation exists" is a legitimate answer.

5. The 13-bit offset is a hard ceiling

Mathematical derivation The offset field holds 0 to 8191 in units of 8, so it can name a position up to byte 65528. The maximum IPv4 datagram is 65535 bytes, of which at most 65515 is data, so the field is exactly large enough — and a fragment starting beyond 65528 bytes cannot be described at all.

This is the derivation behind the 8-byte unit, and it is also the reason no valid fragmentation question produces a larger offset.

6. Two prefixes of the same length can both match

Longest prefix match does not order equal-length matches. In a well-formed table, two distinct prefixes of the same length cannot both contain the same address, because they would have to agree on all p fixed bits and still differ. So a tie is a symptom of a malformed table, not a case the rule resolves.

If you meet one, say the table is inconsistent rather than inventing a tie-break.

7. A prefix of length zero

The default route is 0.0.0.0/0: it matches every address and is the longest match only when nothing else matches. It is not "interface 0" and it is not a rule about the address.

A table with no default and no match discards the packet. That is a legitimate question outcome.

8. NAT with no free port

Port address translation is limited by the port space: with one public address, roughly 64K flows at a time. When the table is full, new connections fail rather than queue.

This is a consequence of the design, not a syllabus item, but it explains why a NAT table has to be aged out and why the pair must be unique.

Six beliefs that produce wrong answers, each with the smallest case that refutes it

Each entry states the belief in the form a learner would hold it, gives the counterexample, and then states the correction as a rule that can be applied. The counterexamples are computed by the model, not quoted.

1. "A /27 means the mask is .27"

Counterexample. A /27 mask is 255.255.255.224. The 224 is not the prefix and the prefix is not 224; one is a count of bits and the other is the value of the last non-zero octet.

Correction. Turn the prefix into a block size, $$2^{32-p}$$, before doing anything else. A /27 gives 32, and 32 divides the octet into eight blocks of 32: 0, 32, 64, 96, 128, 160, 192, 224.

2. "The network address is the first usable host"

Counterexample. In 200.10.11.128/27 the network address is .128 and the first usable host is .129. Assigning .128 to a host gives an address that duplicates the network name.

Correction. Network and broadcast are names, not hosts. First host = network + 1, last host = broadcast − 1, and usable = 2h − 2.

3. "The first matching row is the route"

Counterexample. GATE CSE 2014 Set 3 Q26: 131.23.151.76 matches both 131.16.0.0/12 and 131.22.0.0/15. The /12 row comes first in the table and is the wrong answer; interface 1 is correct.

Correction. Collect every match, then take the largest prefix length. Order in the table is not part of the rule.

4. "Divide the data by the MTU"

Counterexample. 980 bytes of data on a 100-byte MTU: 980/100 gives 9.8, so 10, but the answer is 13, because only 80 bytes of each fragment can be data.

Correction. Budget first: MTU − header. Then round the budget down to a multiple of 8. Divide by that. Three operations, in that order.

5. "The offset is the number of bytes before this fragment"

Counterexample. In GATE CSE 2016 Set 1, the second fragment starts at byte 80 and its offset field holds 10, not 80. Writing 80 gives a value that names byte 640.

Correction. Offset = bytes before this fragment ÷ 8. To read a fragment's start, multiply the offset by 8. The unit is part of the field's definition.

6. "NAT changes the destination on the way out"

Counterexample. GATE CSE 2024 Set 1 Q21 offers destination IP and total length among the fields; neither changes on an outbound packet. Only the source address (and, with port translation, the source port) changes, plus the header checksum.

Correction. Outbound: rewrite the source. Inbound: rewrite the destination. In both directions the checksum is recomputed, and the total length never changes.

Closely confused pairs, side by side

Block size against number of usable hosts. A /27 has 32 addresses and 30 usable hosts. A question about "how many hosts" wants 30; a question about "how many addresses" wants 32. GATE 2015 Set 3 asks neither directly, and instead asks for the last assignable address, which is the block end minus one.

Total length against data length. Fragment total length includes its own 20-byte header; the offset counts data only. GATE 2025 Set 2 mixes the two deliberately: 88 bytes of remainder is data, 108 is data plus header, and 116 is the same thing computed after including the UDP header.

Fragmentation against segmentation. Fragmentation is an IP-layer operation on a datagram, invisible to the transport layer. Segmentation is a transport-layer operation on a byte stream, visible to the receiver. A lost fragment costs a whole segment; a lost segment costs a retransmission sized by the transport layer, not the MTU.

The four question shapes, and what each demands

  1. One number out of a block. Prefix → block size → block start → count from an end. Almost always one mark, almost always lost to an off-by-one.
  2. A table and a destination. AND each entry, list the matches, take the longest. Two marks when five hosts are involved, because the count multiplies.
  3. A datagram and one or two MTUs. Budget, floor to eight, ceiling, offsets. The two-hop version is the current favourite because it tests whether offsets stay absolute.
  4. A statement set. Fragmentation and NAT both generate true/false items, and the false items are usually the plausible design choices a learner would have made — reassembling at a router, changing the destination outbound.

NATGATE CSE 2016 Set 1 Q53

An IP datagram of size 1000 bytes arrives at a router. The router must forward it on a link whose MTU is 100 bytes. The IP header is 20 bytes. The number of fragments is ______.

Answer: 13

Data is 980. Budget is 80, already a multiple of 8. 980 = 12 × 80 + 20, so twelve full fragments and one of 20 bytes.

Why the others fail. 10 comes from dividing 980 by 100 and ignoring the header. 12 is the count of full fragments. 15 comes from dividing the total 1000 by the budget 80 and rounding up, which counts header bytes as data.

NATGATE CSE 2024 Set 1 Q65

An IP datagram of size 1420 bytes (including a 20-byte header) crosses two links with a router between them. The first link has MTU 542 bytes and the second 360 bytes. The number of fragments delivered at the receiver is ______.

Answer: 6

Data is 1400. First hop: usable 520, so 520 + 520 + 360, three fragments. Second hop: usable 336, so each 520 becomes 336 + 184 and the 360 becomes 336 + 24, giving six.

Trap. Answering 3 reports the count after the first hop, not at the receiver. Answering 7 comes from using 340 (the raw budget) instead of 336.

MSQGATE CSE 2024 Set 2 Q28

Which of the following statements about IPv4 fragmentation is/are TRUE?

  1. Fragmentation is performed only at the source of the datagram.
  2. Fragmentation is performed at any IP router which finds that the datagram exceeds the MTU of the outgoing link.
  3. Reassembly is performed only at the destination.
  4. Reassembly is performed at all intermediate routers along the path.

Answer: B and C

A router on a smaller link must fragment, and only the destination reassembles. Reassembling at a router would waste memory and would still need re-fragmenting on the next link.

Why A and D fail. A source cannot know the MTU of every later link, and D is exactly the design IPv4 rejected.

NATGATE CSE 2015 Set 3 Q38

In the network 200.10.11.144/27, the fourth octet, in decimal, of the last IP address of the network which can be assigned to a host is ______.

Answer: 158

Block size 32, block start .128, block end .159. The end is the broadcast, so the last assignable address ends in .158.

Why the others fail. 159 is the broadcast address. 128 is the network address. 144 is the given address, which is neither end.

MCQGATE CSE 2023 Q55

A packet with destination 200.150.68.118 arrives at a router whose table is 200.150.0.0/16 → 1, 200.150.64.0/19 → 2, 200.150.68.0/24 → 3, 200.150.68.64/27 → 4, default → 0. The interface chosen is ______.

Answer: 3

Entries /16, /19 and /24 all match; the /27 block ends at .95 so it does not. The longest match is /24, which is interface 3.

Why the others fail. 4 is the trap for anyone who matches on the first three octets and stops. 1 and 2 match but are less specific.

MSQGATE CSE 2021 Set 1 Q45

Hosts P and Q are joined by router R. The P–R link has MTU 1500 and the R–Q link has MTU 820. A TCP segment of 1400 bytes is sent from P to Q with IP identification 0x1234; the IP header is 20 bytes and DF is clear. Which statements are correct?

  1. Two fragments are created at R and the datagram carrying the second is 620 bytes.
  2. If the second fragment is lost, R resends it with identification 0x1234.
  3. If the second fragment is lost, P must resend the whole TCP segment.
  4. The TCP destination port can be determined from the second fragment alone.

Answer: A and C

Budget on the second link is 800, so the 1400 bytes become 800 + 600 and the second datagram is 600 + 20 = 620 bytes. A lost fragment is invisible to P, so the whole segment is resent.

Why B and D fail. R keeps no copy of the datagram and does not retransmit. The transport header sits at the start of the data, so it travels in fragment 1 only.

OriginalNAT

An organisation is given 172.16.40.0/22. It wants four equal subnets of the largest possible size. What is the prefix of each subnet, how many usable hosts does each hold, and what is the last assignable address of the fourth subnet?

Answer: /24, 254 usable hosts, last assignable address 172.16.43.254

A /22 holds 1024 addresses; four equal subnets need 256 each, which is a /24. They are 40.0, 41.0, 42.0 and 43.0. Each /24 has 8 host bits, so 254 usable. The fourth block is 172.16.43.0/24, whose broadcast is .255, so the last host is .254.

Shortcut and its assumption. Splitting a /p into 2k equal subnets gives prefix p + k, and it requires the original block to be a single CIDR block, which it is. The shortcut does not apply if the four subnets are not required to be equal.

OriginalNAT

A datagram of 3000 bytes total, with a 20-byte header and no options, must cross a link of MTU 600 bytes. Give the number of fragments, the offset and total length of the last fragment, and the total number of IP bytes actually put on the link.

Answer: 6 fragments; last offset 360 units, last total length 120 bytes; 3120 IP bytes on the link

Data 2980. Budget 580, usable 576 (72 units). 2980 = 5 × 576 + 100, so six fragments. The last starts at byte 2880, so its offset is 2880 ÷ 8 = 360 units, and its total length is 100 + 20 = 120 bytes. The link carries 5 × 600 + 120 = 3120 bytes.

The lesson in this question. The extra 120 bytes are five extra 20-byte headers: the link carries more bytes than the datagram contained, which is a real cost of fragmentation and a legitimate thing to be asked.

OriginalMSQ

Which of these statements are TRUE?

  1. A /30 block has 2 usable host addresses.
  2. The fragment offset field counts bytes, not units of 8.
  3. Two adjacent /23 blocks always merge into one /22.
  4. Longest prefix match can select a route listed after a shorter matching route.

Answer: A and D

A /30 has four addresses, two of which are reserved, so two usable. Longest match ignores table order entirely, so a later, longer entry wins.

Why B and C fail. The offset counts 8-byte units — that is the whole reason for the alignment rule. Two adjacent /23 blocks merge only if they are aligned as a pair, meaning their start addresses differ by exactly 512 and the pair begins at a multiple of 1024; otherwise the merged /22 would not start on its own boundary.

OriginalMCQ

Ten internal hosts behind one NAT device each open a connection to the same web server on port 80, and all ten happen to pick source port 4000. Which statement is correct?

  1. The device must have at least ten public addresses.
  2. The device rewrites the source port so that each (public address, public port) pair is unique.
  3. The device leaves the port unchanged and uses the destination port to tell the flows apart.
  4. The connections fail, because two flows cannot share a source port.

Answer: B

Port address translation rewrites the source port so the table key stays unique. This is exactly why the pair, not the address alone, is the key.

Why the others fail. A is not required, which is the point of PAT. C fails because the destination port is identical for all ten flows and so distinguishes nothing. D is false once the port is rewritten.

Revision sheet — everything on this page, compressed

Use this after the practice set. If a line here is not obvious, the tab that explains it is named beside it.

Addressing

  • Block size = $$2^{32-p}$$. Mask has p ones then zeros.
  • Network = address AND mask. Broadcast = network + block size − 1.
  • First host = network + 1. Last host = broadcast − 1. Usable = $$2^{h} - 2$$, except /31 and /32.
  • Round the address down to the block start; never to the nearest boundary.
  • Forwarding: AND every entry, list the matches, take the longest prefix. Default is prefix 0.

Aggregation

  • Two equal blocks merge iff they are adjacent and aligned as a pair; the prefix shortens by one.
  • The merged block must cover exactly the union, or the extra addresses must share the same next hop.
  • Check by counting addresses: union of the parts must equal the size of the merge.
  • A single shorter prefix usually captures foreign addresses; that is why the GATE 2022 answer is a pair of /22s and not one /20.

Fragmentation

  • Budget = MTU − header. Usable = budget rounded down to a multiple of 8.
  • Count = ceil(data / usable). Last fragment may carry a remainder of any size.
  • Offset = bytes before this fragment ÷ 8. Total length = this fragment's data + header.
  • Identification is copied. MF is 1 everywhere except the last. Checksum recomputed per fragment.
  • Second fragmentation keeps offsets absolute. Reassembly at the destination only.
  • Transport header sits in fragment 1. A lost fragment costs a whole segment.

NAT

  • Outbound: rewrite source address (and port with PAT), recompute the header checksum.
  • Inbound: match (public address, public port), rewrite destination address and port.
  • Destination IP and total length do not change outbound; source IP does not change inbound.
  • The (public address, public port) pair must be unique. No entry means the packet is dropped.

Decision procedure in one line each

Address question. Prefix → block size → block start → five numbers → re-read which one is wanted.

Table question. AND each entry → list matches → largest prefix length → count hosts and multiply.

Fragmentation question. Budget → floor to eight → ceiling → offsets as running sums over eight → check the data adds up.

Statement question. Ask what the design would cost if the statement were true. Reassembling at routers costs memory and does not remove the next fragmentation; rewriting the destination outbound breaks delivery.

The four slips, one last time

Total addresses against usable hosts · block size against mask value · offset in bytes against offset in units of eight · first match against longest match. Write the unit next to every number and none of the four survives.

What was consulted, and what each source supports

Official documents are separated from community catalogues. A community catalogue is evidence that a question exists and was asked in a given year; it is not evidence about the 2027 paper. Every numeric answer on this page was recomputed from the question text, so the catalogues were used to find questions, not to settle answers.

Official

  • GATE 2027 CS syllabus, IIT Madras, CS_GATE2027_Syllabus.pdf, read on 28 October 2026. Supports the Section 10 wording quoted in Overview, including the fact that "IP addressing" is not named separately in 2027 while fragmentation, CIDR notation and NAT are.
  • RFC 791 (Internet Protocol) — the header fields, the 8-byte offset unit, the 13-bit offset field, and the statement that reassembly happens at the destination.
  • RFC 3021 — the /31 point-to-point convention used in Edge cases.
  • RFC 950 / RFC 1519 — subnetting and classless addressing, the basis of the block arithmetic.

Question catalogues, used to locate items

  • GATE Overflow threads for 2014 Set 3 Q26, 2015 Set 2 Q52, 2015 Set 3 Q38, 2016 Set 1 Q53, 2021 Set 1 Q45, 2022 Q45, 2023 Q55, 2024 Set 1 Q21 and Q65, 2024 Set 2 Q28. Used for question text and for the community's reasoning about the 2022 aggregation assumption.
  • ExamSide and GateAI topic indexes, used to confirm which papers contain fragmentation items and to see the option lists.
  • Analyst compilations of subject-wise marks, quoted in Overview only as an observation about past papers, with the caveat that they are somebody's tagging of somebody's collection.
