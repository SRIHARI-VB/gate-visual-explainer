Topic and objective

TOPIC: The optimal binary search tree — the cheapest tree for a fixed sorted key set whose keys are searched with different frequencies. This sits inside Section 5, Algorithms, of the GATE 2027 CS syllabus, under the clause "Algorithm design techniques: greedy, dynamic programming and divide-and-conquer".

LEARNING OBJECTIVE: Define the cost of a search tree as a weighted sum of levels, with the root at level 1. Derive from that definition why the cost of a tree equals the cost of its two subtrees plus the total weight of the keys in it, and turn that into the recurrence $$C(i,j) = W(i,j) + \min_{i \le r \le j}\{C(i,r-1) + C(r+1,j)\}$$. Fill the triangular table by increasing length, read the winning root out of a second table, and rebuild the tree. Then defeat the greedy rule — "put the most searched key at the root" — with an instance where it costs one comparison too many, and explain why a root choice is a decision about a whole range rather than about one key.

I am treating this as one topic, not two: the recurrence, the table and the reconstruction are one procedure, and the greedy failure is the reason the procedure exists. Nothing here needs the unsuccessful-search weights; that general case is named in the Build-up and then set aside, because it changes the arithmetic without changing the reasoning.

GATE relevance

Verified fact Class A for the technique. Section 5 of the GATE 2027 CS syllabus, published by IIT Madras as CS_GATE2027_Syllabus.pdf, reads in full: "Searching, sorting, hashing. Asymptotic worst case time and space complexity. Algorithm design techniques: greedy, dynamic programming and divide-and-conquer. Graph traversals, minimum spanning trees, shortest paths."

The phrase "dynamic programming" is named outright. The optimal search tree is the standard dynamic-programming problem in which the greedy rule visibly fails, which is why it is the usual companion to the greedy-versus-DP comparison the same clause sets up. Prerequisites

  • Trees, binary search trees and heaps — the search-tree ordering, and what the level of a node means. This lesson assumes a successful search compares once per node on the path, including the target.
  • Dynamic programming: formulation, tables and classic problems — optimal substructure, overlapping subproblems, filling a table by increasing size, and reconstructing a solution from a stored choice. The matrix-chain problem there is the closest relative of this one.
  • Greedy algorithms and exchange arguments — what it means for a greedy rule to fail, and why an exchange argument is the right tool when it succeeds.
  • Summation notation, and the idea of a weighted average. Nothing else.

No software is needed. Every number on the canvas is computed on the page and re-checked against the rule it should satisfy.

The five ideas, in one line each

  • The cost is weighted depth. A tree costs the sum over keys of weight times level, with the root at level 1.
  • A root is paid for by everyone. Pushing a subtree down one level adds its total weight once, which is why the range weight appears in the recurrence.
  • The table is a triangle. $$n(n+1)/2$$ cells, filled by increasing length, cubic time and quadratic space.
  • Greedy fails. On weights 4, 2, 1, 3 the heaviest key as root costs 20, and the optimum is 19.
  • A second table gives the tree. The cost table says how much; the root table says which.

Intuition first: a library where some books are asked for far more often

A librarian shelves four books in alphabetical order. She can arrange them so the most requested book is easiest to reach — but the alphabetical order must survive, so the shelf is not free. Put the popular book first and the rest stretch away down the shelf; put it in the middle and the far ends are shorter. Something must be paid either way.

That is the whole problem. The order is fixed, the shape is not, and the price of a shape is how far each book has to be reached for, weighted by how often it is asked for. Educational interpretation The analogy carries the trade-off and the fixed order. It does not carry the arithmetic, which is the next three cards.

Formal vocabulary, every term in words

Search tree — a binary tree holding keys $$k_1 < k_2 < \dots < k_n$$ such that every key in a left subtree is smaller than its parent and every key in a right subtree is larger.

Level of a key — the number of comparisons a successful search for that key performs, counting the comparison against the key itself. The root is at level 1.

Weight — how often a key is searched for. A count such as 4 out of 10, or a probability such as 0.4; both work, because only ratios matter.

Cost of a tree — the sum over keys of weight times level. It is the total number of comparisons over all searches.

Optimal tree — a tree of minimum cost among all search trees on the same keys. It need not be unique.

The cost, written out

cost(T) = Σ pi · levelT(ki)Each key contributes its weight once for every comparison needed to reach it. The root contributes its weight once, its children twice, and so on.

The expected number of comparisons per search is the cost divided by the total weight.

average = cost(T) / Σ piWith weights 4, 2, 1, 3 the total is 10, so a cost of 19 is 1.9 comparisons per search.

Mathematical derivation Both formulas are checked on the page: every tree on four keys is enumerated and its cost recomputed from its levels, and the minimum is confirmed to be at least the total weight, because no key can sit above level 1.

The key lemma: a subtree pays its own weight to move down

Fix a key r as the root of the range i to j. Every key below it moves one level deeper than it was in its own subtree. So each key in a subtree contributes one extra copy of its weight.

cost(T) = cost(TL) + cost(TR) + Σt=i..j ptThe left and right subtrees pay their internal costs. Then everything in the range pays once more, because the root is above it. The last term is the total weight of the range, which does not depend on the shape.

That is the whole derivation. It is short, and every step of it matters: the extra term is a weight, not a count of keys, and it is the same number for every candidate root.

Mathematical derivation Verified by computing both sides independently on every one of the 14 trees on four keys, and on the 42 trees on five keys.

Optimal substructure, and why it is not assumed

If the left subtree of an optimal tree were not optimal for its range, swapping in a better one would lower the total, because the range-weight term is unchanged by that swap. So an optimal tree is built from optimal subtrees.

The assumption being used. The term $$W(i,j)$$ depends only on which keys are in the range, never on the shape. That is exactly what makes the swap argument work. In a problem where moving a subtree changed the shared term, this argument would fail — and there are such problems, so the check is worth stating rather than skipping.

The recurrence

C(i,j) = W(i,j) + mini≤r≤j [ C(i,r−1) + C(r+1,j) ]C of a range is the cheapest cost for that range, counting levels from the range's own root. For each candidate root r, pay the two side ranges and the range weight once. Keep the smallest total.

C(i,i) = pi  ·  C(i,i−1) = 0One key costs its weight, because it is compared once. An empty range costs nothing, which is what lets the two ends of the range be handled by the same expression.

The answer for the whole problem is the single cell $$C(1,n)$$. Mathematical derivation The page evaluates this recurrence and, separately, enumerates every tree and takes the minimum; the two agree on all 256 four-key weight vectors with weights 1 to 4, and on all 243 five-key vectors with weights 1 to 3.

The table, its shape and its price

Only ranges with $$i \le j$$ are meaningful, so the table is a triangle. For n keys it holds $$n(n+1)/2$$ cells: 10 for four keys, 21 for six.

A cell of length L tries L roots, so the total work is about $$n^3/6$$ root evaluations. Time is cubic; space is quadratic.

Knuth's bound. If the weights are monotone in the sense that makes the quadrangle inequality hold, the winning root of a cell always lies between the winning roots of the two cells beside it: $$R(i,j-1) \le R(i,j) \le R(i+1,j)$$. Restricting the search to that window makes the fill quadratic. The condition matters — without it the bound is not a theorem — and the syllabus does not name it, so treat it as an extension rather than a default.

Reconstruction: the second table

Store $$R(i,j)$$, the root that achieved the minimum. Then starting from $$R(1,n)$$, split the range at that root and recurse on both sides.

For the worked instance, $$R(1,4) = 2$$ gives key 20 at the root; $$R(1,1) = 1$$ gives key 10 on the left; $$R(3,4) = 4$$ gives key 40, with $$R(3,3) = 3$$ putting key 30 beneath it. Levels 1, 2, 2, 3, and the re-add gives 19. Mathematical derivation The page rebuilds the tree from the root table and confirms that its weighted level sum equals the table entry.

The general case, named once and then set aside

When searches may also fail, each gap between consecutive keys is an external node with its own weight $$q_j$$, and the range weight becomes the internal weights plus the external weights from $$i-1$$ to $$j$$. The recurrence itself is unchanged — only $$W$$ grows a term. GATE-style questions on this topic that appear in public archives give successful-search weights only, so this lesson works the simpler version throughout; if a question gives both sets of weights, add them into $$W$$ and nothing else changes. Educational interpretation Choosing the simpler version as the main line is a teaching decision, not a claim about what any particular paper will ask.

Five worked examples, each with the reason for every step

Weights are search counts, not probabilities, so every cost below is a whole number of comparisons over ten searches. Each result was recomputed by the page's model.

Example 1 — three shapes, three costs

Keys 10, 20, 30, 40 with weights 4, 2, 1, 3. Three legal trees.

  • The chain, 10 on top. Levels 1, 2, 3, 4. Cost 4·1 + 2·2 + 1·3 + 3·4 = 4 + 4 + 3 + 12 = 23.
  • 40 on top, with 10 → 20 → 30 down the left. Levels 2, 3, 4, 1. Cost 4·2 + 2·3 + 1·4 + 3·1 = 8 + 6 + 4 + 3 = 21.
  • 20 on top. Levels 2, 1, 3, 2. Cost 4·2 + 2·1 + 1·3 + 3·2 = 8 + 2 + 3 + 6 = 19.

    • Read the reason off the numbers. The chain puts the heaviest key (weight 4) at the top and still costs most, because it also puts the second-heaviest key at the bottom. A root choice trades one key's level against every other key's.

    Example 2 — the table for the worked instance

    Fill length by length. Each entry is the cost; the root that achieved it is in brackets.

  • Length 1. C(1,1)=4, C(2,2)=2, C(3,3)=1, C(4,4)=3. These are the weights themselves.
  • Length 2. Range 1–2: weight 6, roots give 2+6=8 and 4+6=10, so 8 with root 1. Range 2–3: weight 3, roots give 4 and 5, so 4 with root 2. Range 3–4: weight 4, roots give 7 and 5, so 5 with root 4.
  • Length 3. Range 1–3: weight 7, roots give 4+7=11, 4+1+7=12, 8+7=15, so 11 with root 1. Range 2–4: weight 6, roots give 5+6=11, 2+3+6=11, 4+6=10, so 10 with root 4.
  • Length 4. Weight 10, roots give 10+10=20, 4+5+10=19, 8+3+10=21, 11+10=21. So 19 with root 2.

    • Check. Ten cells were filled, one for each range, and the last cell reads 19 — the same 19 the tree in Example 1 costs. That agreement is the point of the exercise, not a coincidence.

    Example 3 — greedy against optimal on two instances

    The greedy rule takes the largest weight in the range as the root, then repeats on each side.

  • Weights 4, 2, 1, 3. Greedy picks key 10 (weight 4), then 40 (weight 3), then 20. Levels 1, 3, 4, 2. Cost 4·1 + 2·3 + 1·4 + 3·2 = 4 + 6 + 4 + 6 = 20. The optimum is 19.
  • Weights 3, 3, 1, 1. Greedy picks key 10, then 20, then 30, producing a chain. Levels 1, 2, 3, 4. Cost 3 + 6 + 3 + 4 = 16. Rooting at key 20 gives levels 2, 1, 2, 3 and cost 6 + 3 + 2 + 3 = 14.

    • The reason. Making a key the root saves that key one comparison and charges every other key in the range one comparison. So a root choice is only correct if it is judged against the whole range, which is exactly what the table does and exactly what greedy refuses to do.

    Example 4 — a tie, and two optimal trees

    Keys 10, 20, 30, 40 with weights 5, 45, 45, 5.

  • Length 2. C(1,2) = 55 with root 2; C(2,3) = 135 with root 2; C(3,4) = 55 with root 3.
  • Length 3. C(1,3) = 145 with root 2; C(2,4) = 145 with root 3.
  • Length 4. Weight 100. Root 1 gives 145+100=245. Root 2 gives 5 + 55 + 100 = 160. Root 3 gives 55 + 5 + 100 = 160. Root 4 gives 145+100=245.

    • Answer. The optimum is 160 and there are two optimal trees, one rooted at key 20 and one at key 30. Both have the same two heavy keys at level 2 and the two light keys at level 3. So "the" optimal tree is not unique, and a question that asks for the minimum cost has one answer while a question that asks for the tree may have two.

    Example 5 — three equal weights, and the 1991 item

    Weights 1, 1, 1 on keys 10, 20, 30.

  • Length 1. 1, 1, 1.
  • Length 2. Range 1–2: weight 2, roots give 1+2=3 and 1+2=3, so 3. Range 2–3: also 3.
  • Length 3. Weight 3, roots give 3+3=6, 1+1+3=5, 3+3=6. So 5, with the middle key at the root.

    • Cost 5 over weight 3 is $$5/3 \approx 1.67$$ comparisons. The best tree is the balanced one: middle key on top, the other two beneath it.

    Previous-year item, GATE CSE 1991, Question 23 (2 marks). "Obtain the optimal binary search tree with equal probabilities for the identifier set (a1, a2, a3) = (if, stop, while)."

    Answer: a2 = "stop" at the root, with "if" as its left child and "while" as its right child. The expected number of comparisons is $$5/3$$.

    Why that is the answer, and not "if". With equal weights the tree that minimises weighted depth is the one that minimises depth, which is the balanced tree. Putting "if" on top gives levels 1, 2, 3 and cost 6, not 5. The identifiers are already in alphabetical order, which is the key order the search tree must respect.

    The boundaries, each with the condition it breaks

    Every case below is a place where the rule still applies but a shortcut does not. Each is stated with the property that fails, and each is computed on the page.

    1. One key: the base case is not zero

    A single key of weight 7.

    What happens: the only tree has that key at level 1, so the cost is 7. The empty range beside it costs 0, which is a different statement about a different range.

    What breaks: initialising the whole table to zero and then reading a one-key cell without filling the diagonal. Every cost downstream is then one key's weight too small.

    2. Equal weights: the answer is the balanced tree

    Three keys, weights 1, 1, 1.

    What happens: every tree with the middle key at the root costs 5; every tree with an end key at the root costs 6. The optimum is the balanced shape.

    Why it matters: this is the one case where "balance the tree" is the correct rule, and it is exactly the case the greedy rule also gets right. It is a bad test of either rule, which is why the counterexamples below use unequal weights.

    3. A weight of zero is legal and changes the shape

    Weights 4, 0, 0, 6.

    What happens: a key with weight zero is never searched for, so it can be pushed arbitrarily deep at no cost. The optimal tree is free to bury it.

    What breaks: assuming every key sits at a sensible level. Zero-weight keys can sit as deep as the ordering allows, and a question that asks for the tree may have many optimal answers for that reason alone.

    4. Ties: two roots, one cost

    Weights 5, 45, 45, 5.

    What happens: both middle keys give 160. The tree is not unique, and no tie-breaking rule is needed to state the cost.

    What breaks: asserting "the optimal tree has key 20 at the root" as though it were a theorem. It is true on weights 4, 2, 1, 3 and false in general.

    5. All the weight on one key: the optimum is a chain

    Weights 0, 0, 0, 10.

    What happens: put key 40 at the root and let the rest hang to the left in any order. Every such tree costs 10, the minimum possible, because the only searched key is at level 1.

    What breaks: the habit of preferring shallow trees. Depth is free when the deep keys are never searched for; the cost is what matters, and here the chain and the balanced tree tie.

    6. Weights that are probabilities

    Weights 0.4, 0.2, 0.1, 0.3.

    What happens: the same table, scaled by 0.1. The optimal root is the same, and the cost is 1.9 rather than 19.

    The rule: the recurrence is linear in the weights, so scaling all of them scales the cost and changes nothing else. Do not normalise before filling the table; divide once at the end, if the question asks for an expected value.

    7. A range weight that is not the sum of the range's own keys

    With unsuccessful-search weights the range term becomes the internal weights plus the external weights between the range's ends, and the external weights at the two boundaries belong to the neighbouring ranges, not to this one. That is the one place in this topic where the term is easy to get wrong: adding a boundary external weight to both ranges it borders double-counts it. The lesson keeps the successful-search version as its main line and states this so that a question which does give both sets of weights is not a surprise — but the arithmetic of that case is not worked on this page, and the Sources tab says so.

    Seven beliefs that cost marks, and what replaces them

    Each entry gives the belief, why it tempts, the smallest case that defeats it, and the rule to hold instead.

    Misconception 1 — "the most probable key goes at the root"

    Why it tempts. It is true for Huffman, it is true for a priority queue, and it is true on symmetric weight vectors.

    Defeated by. Weights 4, 2, 1, 3. The heaviest key as root costs 20; rooting at the second key costs 19.

    The rule. A root is chosen for the whole range, not for one key. The candidate that wins is the one whose two sides are cheap, and the heaviest key often leaves one side expensive.

    Misconception 2 — "the root is at level 0"

    Why it tempts. Depth in a tree is conventionally counted in edges, so the root is at depth 0.

    Defeated by. A one-key tree. A successful search compares against that key once, so its cost is its weight, not zero. With levels counted from 0 the entire table is wrong by the total weight.

    The rule. Count comparisons, not edges. Level 1 is the root, and no tree costs less than the total weight — which is a one-line sanity check on any answer.

    Misconception 3 — "the range weight is added once per side"

    Why it tempts. Each side genuinely pays its own weight, so adding it per side looks like the same thing.

    Defeated by. The two-key case with weights 1 and 1. The correct cost is 3. Adding the range weight twice gives 5, which exceeds even the chain's cost and is impossible for two keys.

    The rule. The range weight appears once per cell, and the root's own weight is inside it. The left side's weight and the right side's weight are parts of that one number, not additions to it.

    Misconception 4 — "the optimal tree is unique"

    Why it tempts. Most worked examples happen to have one winner, so uniqueness looks like part of the theorem.

    Defeated by. Weights 5, 45, 45, 5: roots 2 and 3 both give 160, and both trees are optimal.

    The rule. The minimum cost is unique; the tree achieving it need not be. If a question asks for the tree and two answers exist, both are correct.

    Misconception 5 — "the Huffman number can be compared with the search-tree number"

    Why it tempts. Both numbers are computed as weight times depth, so they look like the same quantity measured two ways.

    Defeated by. Weights 5, 45, 45, 5. Huffman gives 165 and the optimal search tree gives 160 — but the two count different things. Huffman charges each symbol at its leaf; the search tree charges each key at the node where it is compared. Reading 165 against 160 as "Huffman is worse" is not a comparison at all, and reading it the other way is not one either.

    The rule. A number is only comparable between objects of the same kind. Huffman's tree stores symbols at leaves and obeys no order, so it is not a candidate for this problem however small its number is.

    Misconception 6 — "this is Huffman coding with keys instead of letters"

    Why it tempts. Both minimise weight times depth, both are trees, both are built from weights.

    Defeated by. The ordering. Huffman may put the two lightest symbols anywhere; a search tree must keep every smaller key left of every larger one. Huffman's greedy is optimal for its own problem and wrong for this one.

    The rule. Huffman: symbols are leaves, no order, greedy works. Search tree: keys are internal nodes, order fixed, DP needed. Alphabetic coding is a third object that keeps the order but still puts symbols at the leaves.

    Misconception 7 — "filling the table by row is the same as by length"

    Why it tempts. On a four-key table a row-major pass happens to read only cells that are already filled, so the numbers come out right and the procedure looks correct.

    Defeated by. A five-key table. Cell (1,5) needs (2,5), which sits below and to the right of it; a row-major pass reaches (1,5) long before (2,5). The cell then reads a zero that was never computed.

    The rule. The dependency is on length, not on position. Fill all length-1 cells, then all length-2, and so on; within a length the order is free because those cells never read each other.

    How this topic is actually asked

    Five shapes cover the family. Each is given with the reasoning it demands and the approach that loses the mark. No claim is made about how often any of them appears; that would need evidence this page does not have.

    Pattern 1 — the numeric cost of one instance

    Shape. "Given keys and search probabilities, the minimum expected number of comparisons is ___." A numeric-answer item.

    Reasoning. Fill the triangle, read the top cell, divide by the total weight only if the question asks for an expected value.

    The losing approach. Building the tree by eye and summing. On four keys it works often enough to be dangerous; on six it does not, and there is no check on it.

    Pattern 2 — which key is at the root

    Shape. "The root of the optimal tree is ___", or a question that names four candidate trees and asks which is optimal.

    Reasoning. Only the top row of the table matters: compute the four candidates and take the smallest. Then read the tree out of the root table.

    The losing approach. Choosing the heaviest key, which is the greedy rule and is wrong on weights 4, 2, 1, 3 and on 3, 3, 1, 1.

    Pattern 3 — a statement question about the method

    Shape. "Which of the following statements is false?" with one option about the search tree and the others about neighbouring topics. This is the shape of GATE CSE 1994 Question 1.22, quoted in the Practice tab.

    Reasoning. Decide each option independently. For the search-tree option the statement is that the construction can be done efficiently by dynamic programming, which is true: cubic time, quadratic space.

    The losing approach. Hunting for a false statement among options you have not read, instead of eliminating the ones you can settle in seconds.

    Pattern 4 — a count of cells or of trees

    Shape. "How many distinct binary search trees are there on n keys?", "How many subproblems does the table hold?", "What is the time complexity?"

    Reasoning. Trees: the Catalan number, which is $$C(2n,n)/(n+1)$$ — 1, 2, 5, 14, 42, 132 for n from 1 to 6. Subproblems: $$n(n+1)/2$$. Time: cubic, or quadratic under Knuth's monotonicity condition.

    The losing approach. Confusing the number of trees with the number of table cells. Both are counts about this problem and they are not the same count.

    Pattern 5 — the greedy-versus-DP discrimination

    Shape. "Which technique solves this problem?" or "Why does the greedy strategy fail here?" — often paired with a problem where greedy does work, such as Huffman or interval scheduling.

    Reasoning. Name the constraint that makes the greedy choice unsafe. Here it is that the root choice is paid for by every other key in the range, so a locally cheap root can be globally expensive. Then show one instance where the greedy tree costs more.

    The losing approach. Answering "greedy fails because the weights are not sorted" or another vague reason. The examiner wants the mechanism: what does the greedy choice change for the keys it did not choose?

    The habit that covers all five

    Before computing, name what the question wants: a cost, a root, a truth value, a count, or a technique. Each has its own sanity check. A cost must be at least the total weight and at most the chain's cost. A root must be a key in the range. A count of cells must be a triangular number. A count of trees must be a Catalan number. A technique claim must come with the instance that separates it from its rival. Most wrong options fail one of those checks before any arithmetic is done.

    MCQGATE CSE 1991 Q23, adapted

    The 1991 item asked, for 2 marks, to obtain the optimal binary search tree with equal probabilities for the identifier set (a1, a2, a3) = (if, stop, while). Presented here as a multiple-choice item on the root: which identifier sits at the root of that tree?

    1. if
    2. stop
    3. while
    4. Any of the three; all three trees have the same cost.

    Answer: B

    With equal weights the cost is proportional to the sum of levels, so the tree that minimises it is the balanced one. "stop" is the middle identifier in alphabetical order, so it sits at the root with "if" on its left and "while" on its right. Levels 2, 1, 2, so the cost is 5 out of a total weight of 3, that is $$5/3 \approx 1.67$$ comparisons.

    Why A fails. Rooting at "if" forces levels 1, 2, 3 and a cost of 6, which is worse. It is the greedy choice, and here the greedy choice loses. Why D fails. The three rooted-at-an-end trees cost 6 and the rooted-at-the-middle tree costs 5, so the costs are not equal.

    Note on the adaptation. The original was a construction question, not a multiple-choice one. Only the question's data and its answer are taken from it; the option list is this page's.

    MCQGATE CSE 1994 Q1.22

    Which one of the following statements is false?

    1. Optimal binary search tree construction can be performed efficiently using dynamic programming.
    2. Breadth-first search cannot be used to find connected components of a graph.
    3. Given the prefix and postfix walks over a binary tree, the binary tree cannot be uniquely constructed.
    4. Depth-first search can be used to find connected components of a graph.

    Answer: B

    Breadth-first search finds connected components perfectly well: run it from an unvisited vertex, and the set it reaches is exactly that vertex's component. So the claim that it cannot is false.

    Why A is true. The construction is a dynamic program with $$n(n+1)/2$$ subproblems and cubic time, which is efficient for exam-sized inputs — the point this whole lesson is built on. Why C is true. Two walks are not enough in general; a full binary tree is the special case where prefix and postfix do determine the tree. Why D is true. Depth-first search reaches the same set as breadth-first search, just in a different order.

    The trap. Reading option A as the odd one out because it is the only one about this topic. The question is a mixed-topic statement question, and the option that belongs to the page you are reading is the true one.

    NATOriginal practice question

    Keys 10, 20, 30, 40 have search weights 4, 2, 1, 3. What is the minimum total cost over all binary search trees on these keys, with the root counted at level 1?

    Answer: 19

    At the top level the range weight is 10 and the four candidate roots give 10+10=20, 4+5+10=19, 8+3+10=21 and 11+10=21. The smallest is 19, at root 20. The tree is 20 at the root, 10 on the left, 40 on the right with 30 beneath it, and 4·2 + 2·1 + 1·3 + 3·2 = 19.

    Why 20 appears. It is the greedy answer: put weight 4 at the root, then weight 3, then weight 2. Why 21 appears. It is the tree with 40 at the root, and also the tree with 30 at the root. Why 23 appears. It is the chain with 10 at the top.

    NATOriginal practice question

    Keys 10, 20, 30, 40 have search weights 3, 3, 1, 1. What is the minimum total cost over all binary search trees on these keys, with the root counted at level 1?

    Answer: 14

    The range weight is 8. The four candidate roots give: root 10, C(2,4) + 8 = 8 + 8 = 16; root 20, C(1,1) + C(3,4) + 8 = 3 + 3 + 8 = 14; root 30, C(1,2) + C(4,4) + 8 = 9 + 1 + 8 = 18; root 40, C(1,3) + 8 = 11 + 8 = 19. The minimum is 14, at root key 20.

    The tree is 20 at the root, 10 on its left, and 30 with 40 beneath it on the right. Levels 2, 1, 2, 3, so 3·2 + 3·1 + 1·2 + 1·3 = 6 + 3 + 2 + 3 = 14.

    Why 16 appears. It is the greedy tree: the largest weight is 3, the tie is broken towards the leftmost key, and greedy then produces a chain 10 → 20 → 30 → 40 with levels 1, 2, 3, 4 and cost 3 + 6 + 3 + 4 = 16. Here the greedy error is at the very first step, which is the usual case.

    MSQOriginal practice question

    For a search tree on n keys with positive weights, where the root is counted at level 1 and the total weight is S, which statements are correct?

    1. The cost of every search tree on these keys is at least S.
    2. The minimum cost is at most the cost of the tree built by making the heaviest key the root at every step.
    3. If all weights are equal, the minimum-cost tree is balanced.
    4. If two different trees both achieve the minimum cost, then every key has the same level in both.

    Answer: A, B and C

    A holds because every key is at level 1 or deeper, so each contributes at least its own weight. B holds because the greedy tree is one of the trees being minimised over, so the minimum cannot exceed it. C holds because with equal weights minimising the weighted level sum is minimising the level sum, and the balanced tree does that.

    Why D is false. On weights 5, 45, 45, 5 both optimal trees have the same multiset of levels — 1, 2, 2, 3 — but the keys at each level differ: one tree puts key 20 at level 1 and key 30 at level 2, the other reverses them. Equal costs, different level assignments.

    NATOriginal practice question

    The dynamic-programming table for the optimal binary search tree stores one entry per contiguous key range. How many entries are needed for 6 keys?

    Answer: 21

    A range is named by its two ends with the left end not beyond the right, so the count is 6 + 5 + 4 + 3 + 2 + 1 = 21, which is n(n+1)/2.

    Why 36 appears. It is n squared, the full square table, most of which is never used. Why 15 appears. It is n(n−1)/2, which leaves out the six single-key ranges — the base cases, which are most of the useful table.

    MCQOriginal practice question

    Which one of the following best explains why Huffman's greedy merging strategy does not solve the optimal binary search tree problem?

    1. Huffman minimises the sum of weights, while the search tree minimises a weighted sum of depths.
    2. Huffman places symbols at leaves with no ordering constraint, while a search tree must keep every smaller key to the left of every larger one.
    3. Huffman's algorithm is only correct for probabilities that sum to one.
    4. Huffman produces a tree of minimum depth, while the search tree must minimise total cost.

    Answer: B

    The objective is the same shape in both problems — weight times depth, minimised. What differs is the constraint. Huffman may put any symbol anywhere, so its greedy merging is safe; a search tree must respect the key order, and that is what makes a locally cheap root globally expensive.

    Why A fails. Both minimise a weighted depth. Why C fails. Scaling all weights by a constant changes neither algorithm's choices. Why D fails. Huffman does not minimise depth; a complete tree of equal depths is not what it produces in general, and depth is not its objective.

    NATOriginal practice question

    Keys 10, 20, 30, 40 have search weights 5, 45, 45, 5. What is the minimum total cost over all binary search trees on these keys, with the root counted at level 1?

    Answer: 160

    The range weight is 100. Root 10 gives 145 + 100 = 245. Root 20 gives C(1,1) + C(3,4) + 100 = 5 + 55 + 100 = 160. Root 30 gives C(1,2) + C(4,4) + 100 = 55 + 5 + 100 = 160. Root 40 gives 145 + 100 = 245. Both middle roots win, so the optimum is 160 and there are two optimal trees.

    Take the tree rooted at key 20: its left subtree is key 10 alone, and its right subtree is keys 30 and 40, whose cheapest root is 30 (cost 55). Levels are 10 at 2, 20 at 1, 30 at 2, 40 at 3. The cost is 5·2 + 45·1 + 45·2 + 5·3 = 10 + 45 + 90 + 15 = 160.

    Why 245 appears. It is what an end key at the root costs: one heavy key is then pushed to level 2 while the other stays high. Why 165 appears. It is Huffman's cost on the same weights, and Huffman's tree stores the keys at leaves, so it is not a search tree and not a candidate.

    The one-screen revision sheet

    Definitions, formulas, decision procedures and traps. If you remember only this tab, remember that the root is level 1 and that the range weight appears once.

    The cost and the lemma

    cost(T) = Σ pi · levelT(ki)Level 1 is the root. Average comparisons = cost divided by the total weight.

    cost(T) = cost(TL) + cost(TR) + W(i,j)Moving a subtree down one level adds its total weight once, so the whole range pays its weight once for having a root.

    Sanity checks. Cost ≥ total weight. Cost ≤ the chain's cost. The rebuilt tree must re-add to the table entry.

    The recurrence and its price

    C(i,j) = W(i,j) + mini≤r≤j[C(i,r−1) + C(r+1,j)]Base: C(i,i) = p_i and C(i,i−1) = 0. The answer is C(1,n).

    Cells: $$n(n+1)/2$$ — 10 for four keys, 21 for six. Time: cubic. Space: quadratic. Knuth: quadratic time if $$R(i,j-1) \le R(i,j) \le R(i+1,j)$$ holds.

    Fill order: by increasing length. Within one length the order is free.

    Counts to know

    Search trees on n keys — the Catalan number $$C(2n,n)/(n+1)$$: 1, 2, 5, 14, 42, 132 for n from 1 to 6.

    Table cells — $$n(n+1)/2$$.

    Root evaluations — about $$n^3/6$$ in the naive fill.

    Optimal trees — the minimum cost is unique; the tree need not be. Weights 5, 45, 45, 5 have two.

    Decision procedure, five lines

    1. Check the keys are sorted and each has a weight.
    2. Draw the triangle; put the weights on the diagonal.
    3. Fill by increasing length, trying every root in each range.
    4. Record the winning root in a second table.
    5. Rebuild the tree, re-add weight times level, compare with the top cell.

    The traps, in one list

    Making the heaviest key the root. Counting levels from zero. Adding the range weight once per side. Asserting the optimal tree is unique. Treating an unordered tree's cost as comparable with an ordered one's. Confusing this problem with Huffman. Filling the table by row. Reporting the total cost when the question asked for expected comparisons, or the reverse.
