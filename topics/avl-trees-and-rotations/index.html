Topic and objective

TOPIC: AVL trees — the height-balanced binary search tree. The invariant, the four rotation cases, what a rotation does to the tree, why insertion needs one repair and deletion may need many, and the height bound that the whole structure exists to guarantee.

LEARNING OBJECTIVE: Given an insertion order, build the AVL tree correctly, name each rotation as LL, RR, LR or RL, and state the final root, the height and the number of rotations. Given n, state the maximum height of an AVL tree on n nodes; given h, state the minimum number of nodes. And reject the three answers that look right: "balanced means complete", "checking the root is enough", and "2h+1 − 1 is the minimum".

I read this topic as one invariant and four repairs. Everything else — the height bound, the rotation counts, the complexity claims — follows from the invariant, so the lesson spends its time on the invariant and on making the four repairs mechanical.

Prerequisites

  • Binary search trees and the search property. Left subtree smaller, right subtree larger, and the in-order walk is sorted. Built in Trees, Binary Search Trees and Heaps.
  • Height, depth and the level of a node. The same lesson fixes the vocabulary; this lesson adds the empty-tree convention.
  • Insertion into a BST as a failing search. Every new key becomes a leaf, which is why a single insertion can only disturb one root-to-leaf path.
  • Asymptotic notation and logarithms. O(log n) against O(n), and log base 2. Built in Asymptotic Complexity and Recurrences.
  • Recurrences and induction. The height bound is a recurrence solved by comparison with Fibonacci, and the identity N(h) = F(h+3) − 1 is an induction. Built in Recurrence Relations and Mathematical Induction and Well-Ordering.
  • Fibonacci numbers. F(1) = F(2) = 1, and growth at the golden ratio 1.618. Built in Recurrence Relations.

No red-black tree, no B-tree and no splay tree is assumed. Each is a different balance rule over the same rotation machinery, and none is needed here.

Conventions used throughout

height(empty) = −1, height(leaf) = 0Height counts edges on the longest downward path. Every number in this lesson — every bound, every minimum, every factor — uses this convention. If a question says "the height of a single node is 1", add one everywhere.

bf(n) = height(n.right) − height(n.left)Positive leans right, negative leans left, zero is level. The opposite sign convention exists in some textbooks; it changes no rotation, only the labels.

AVL: |bf(n)| ≤ 1 for every node nA universal statement over nodes. The counterexample in scene 9 is a tree with bf = 0 at the root and bf = ±2 two levels down.

N(h) = N(h−1) + N(h−2) + 1, N(−1) = 0, N(0) = 1The fewest nodes an AVL tree of height h can have: 1, 2, 4, 7, 12, 20, 33, 54, 88. Identical to F(h+3) − 1.

Mathematical derivation A rotation is called "single" or "double" by how many rotations it performs, not by how many pointer writes it takes. A double rotation is two single rotations: three assignments each, six in total, at two different nodes.

Intuition first: the bookshelf that keeps its shelves level

A binary search tree is a filing system with one rule: everything smaller goes left, everything larger goes right. That rule is enough to find any file in time proportional to the depth of the shelf you have to walk down. It says nothing about how deep the shelves go.

Feed it sorted input and it builds a single stack: every new file goes to the right, and finding the last one means walking past all of them. The filing rule is intact; the shape has collapsed. An AVL tree adds one more rule, about shape, and the rule is about a single number at each shelf: the difference in depth between the left pile and the right pile may never exceed one. A shelf that breaks the rule is rebuilt by lifting one file up and letting two others fall into place.

Educational interpretation The shelf image explains why the rule is local — it compares two piles at one shelf — and why the repair is local — it rearranges three piles and leaves everything above and below alone. It is not a proof that the rule bounds the height; that proof is scene 8.

Formal definitions, in the order they build on each other

Height of a tree. The number of edges on the longest path from the root down to a leaf. By convention the empty tree has height −1 and a leaf has height 0. The height of a node means the height of the subtree rooted at it.

Balance factor. For a node n, the number bf(n) = height(n.right) − height(n.left). It is always an integer, and it is defined even when one or both children are empty, because the empty height is −1.

AVL tree. A binary search tree in which |bf(n)| ≤ 1 for every node n. Both halves of that sentence do work: a heap-shaped thing with balanced heights is not an AVL tree, and a perfectly ordered search tree that leans is not one either.

Rotation. A local rearrangement of three nodes and their subtrees that preserves the in-order sequence. A right rotation at y makes y's left child the new root of the subtree, gives y that child's right subtree, and hangs y beneath it.

AVL insertion. Ordinary BST insertion, then a walk back up the path recomputing heights and repairing the first node whose |bf| exceeds 1.

Why the height convention is minus one, and not zero

The convention exists so that the balance factor of a node with exactly one child is 1 and not 0. A leaf has two empty children, so with empty = −1 its two subtree heights are both −1 and its factor is 0 — correct, it is level. A node with one leaf child has heights −1 and 0, so its factor is ±1 — correct, it leans by one. A node with one child that itself has a child has heights −1 and 1, so its factor is ±2 — correct, it is broken.

Mathematical derivation With empty = 0 instead, a leaf would have height 1, a node with one leaf child would have heights 0 and 1 and factor ±1, and a node with a two-level child would have factor ±2 as well. The factors are the same; only the reported heights shift by one. That is exactly why a question must state its convention and why the answers to "maximum height on 7 nodes" are 3 or 4 depending on it.

The four cases, named by two comparisons

Take the lowest node whose factor has reached ±2 and call it y. Ask two questions: which side of y is taller, and which side of that taller child is taller?

LL: y leans left, child leans left → one right rotation at y
RR: y leans right, child leans right → one left rotation at y
LR: y leans left, child leans right → left at the child, then right at y
RL: y leans right, child leans left → right at the child, then left at y

Mathematical derivation Same side twice is a straight path, and one rotation about y turns a straight path into a balanced three-node tree. Opposite sides is a zig-zag, and rotating about y alone would move the zig-zag rather than remove it: the middle key of the three is not y and is not y's child, so it has to be rotated up twice. That is the whole distinction between a single and a double case.

What a rotation does, in three assignments

A right rotation at y, where x is y's left child:

x = y.left  ·  y.left = x.right  ·  x.right = y  ·  recompute height(y), then height(x)The order matters twice. y.left must be overwritten before x.right points at y, or the subtree x.right used to hold is lost. And y's height must be recomputed before x's, because x's height depends on y's.

The in-order walk of the subtree is unchanged: whatever was between x and y in sorted order is still between them, because x.right moved from being x's right subtree to being y's left subtree, and both positions are "between x and y".

Mathematical derivation A rotation preserves the in-order sequence, so it preserves the search property. That is the reason a rotation is safe at all: it changes shape, and shape only. Every claim in this lesson about correctness reduces to this one invariant.

Why insertion needs at most one repair

Before the insertion, every subtree had a legal height. The insertion adds one node at a leaf, so it changes the height of exactly one subtree at each level of one root-to-leaf path — by at most one, and only along that path.

Let y be the lowest node that has become illegal. Its two subtree heights now differ by 2. A rotation about y, with or without the preliminary rotation at its child, restores y's subtree to exactly the height it had before the insertion. Every ancestor of y therefore sees the same subtree height it saw before, so no ancestor can have become illegal.

Mathematical derivation That is the whole proof, and it is why the answer to "how many rotations does one insertion need" is "at most one repair, which is one or two single rotations". It is verified in this lesson's model over 200 insertions: the largest number of single rotations any of them needed was 1, and the check asserts the bound of 2 in general.

Why deletion may need many

A deletion removes a node, so the subtree it lived in may end up shorter — not merely restored. If the repaired subtree is one level shorter than before, its parent's balance factor can now be ±2 even though it was legal a moment ago. So the repair repeats one level up, and can repeat all the way to the root.

Verified fact This asymmetry is standard: an AVL insertion needs O(1) rotations and an AVL deletion needs O(log n) in the worst case, while both remain O(log n) overall because of the descent. The lesson's model exhibits a concrete case — deleting 15 from a 16-key AVL tree needs a repair at 20 and then another at 25 — so the claim is not merely quoted.

The height bound, derived in four lines

Let N(h) be the fewest nodes an AVL tree of height h can have. One subtree must have height h−1, since that is what makes the whole tree height h. The other must have height at least h−2, by the balance rule. Both must themselves be AVL trees with as few nodes as possible. Hence

N(h) = N(h−1) + N(h−2) + 1, with N(−1) = 0, N(0) = 1The +1 is the root. The sequence is 1, 2, 4, 7, 12, 20, 33, 54, 88 for h = 0 to 8.

This is the Fibonacci recurrence with a root added each time, so N(h) = F(h+3) − 1, and N(h) grows like φh with φ = 1.618. Since a tree on n nodes has n ≥ N(h), solving gives

h ≤ 1.44 log2(n + 2) − 0.328For n = 7 this evaluates to 4.24, and the tallest legal 7-key tree has height 3 — the bound is loose for tiny trees and never violated.

Mathematical derivation Read in the other direction the same table answers the other question: the maximum height on n nodes is the largest h with N(h) ≤ n. For 7 nodes that is 3, for 12 nodes 4, for 20 nodes 5, for 33 nodes 6, for 100 nodes 8.

The one table, read in two directions

Almost every counting question in this topic is one row of numbers used one way or the other.

h : 0  1  2  3  4  5  6  7  8
N(h): 1  2  4  7 12 20 33 54 88

"Minimum nodes in an AVL tree of height h" is the entry at h. "Maximum height of an AVL tree on n nodes" is the largest h whose entry does not exceed n. "Is a 10-node tree of height 4 possible?" is the comparison 12 > 10, so no.

Mathematical derivation The perfect-tree count 2h+1 − 1 belongs to the same question at its other extreme: it is the most nodes a tree of height h can have. At h = 0 and h = 1 the two agree (1 and 2 nodes); from h = 2 they diverge (4 against 7). Confusing the two turns the answer 7 into 15.

Where this leads

The same three-assignment rotation is the whole machinery of every balanced tree: a red-black tree adds a colour and relaxes the height rule to "no path has twice the black nodes of another"; an AVL deletion is the operation that motivates the relaxation, because it is the one that keeps propagating; and a B-tree applies the same idea to a node with many keys, which is why File Organisation and Indexing can use B+ trees for disk pages. None of those is taught here.

Six worked examples, every tree computed by the page

Each example is a full trace: the tree after each insertion, the balance factors, the rotation if one fired, and the in-order walk as a check. The model behind the animation produces all of these, and the checks beside the canvas assert the invariant after every single operation.

Example 1 — insert 9, 6, 5, 8, 7, 10

The sequence used in the animation. Read it as a table:

insert 9  → no rotation  · h 0 · [9]
insert 6  → no rotation  · h 1 · [6 9]
insert 5  → LL at 9    · h 1 · [5 6 9]
insert 8  → no rotation  · h 2 · [5 6 8 9]
insert 7  → LL at 9    · h 2 · [5 6 7 8 9]
insert 10 → RR at 6   · h 2 · [5 6 7 8 9 10]

Final tree: root 8, left child 6 with children 5 and 7, right child 9 with right child 10. Six insertions, three single rotations, height 2, and the in-order walk is still sorted.

Example 2 — the LR case in slow motion

Insert 30, 10, 20 into an empty AVL tree.

After 30 and 10: 30 has a left child 10, so bf(30) = −1. Legal. After 20: 20 is the right child of 10, so 30 has a left subtree of height 1 and an empty right side, bf(30) = −2. Illegal. The left child 10 has bf = +1, which is the opposite sign: LR.

First rotation: left at 10. Now 30 has left child 20, whose left child is 10 — a straight LL path, still illegal at 30 but now repairable in one step. Second rotation: right at 30, lifting 20 to the root.

Final tree: 20 with children 10 and 30, height 1, bf = 0 everywhere. Two single rotations, and the same tree the LL and RR examples reach — a useful check, because all four cases on the same three keys must converge.

Example 3 — a rotation that moves a middle subtree

Rotate right at 30, where 30 has left child 20 and 20 has right child 25. This is the case where the middle subtree is not empty, and it is the one people draw wrongly.

The three assignments: x is 20; 30's left becomes 25; 20's right becomes 30. So 25 moves from being the right child of 20 to being the left child of 30, and it must — otherwise 30 would have two children and 20 would have lost a subtree.

Check: in-order before is 20, 25, 30 and in-order after is 20, 25, 30. The rotation changed the shape and nothing else. If your drawing of a rotation changes the in-order walk, the drawing is wrong.

Example 4 — insert 10, 20, 30, 40, 50, 25

A longer run, and the one most likely to be asked, because it mixes a double case into a sequence of single ones.

10 → —  · 20 → —  · 30 → RR at 10  · 40 → —
50 → RR at 30  · 25 → RL at 20 (two rotations)

After 40 the tree is 20 with left child 10 and right child 30, which has right child 40. Inserting 50 makes 40's right child, so bf(30) = +2 with bf(40) = +1: RR, one left rotation at 30, which makes 40 the root of that subtree with 30 and 50 beneath it. The overall root is still 20.

Then 25 goes left of 30. Now 40's left subtree is one taller than its right, while its parent 20 has bf = +2 — opposite signs, so RL: rotate right at 40, then left at 20. Final root 30, with left child 20 (children 10 and 25) and right child 40 (right child 50); height 2, four single rotations in total, three repairs.

Example 5 — minimum nodes at each height

Build the sparsest legal tree of each height by hand and check it against N(h):

h = 0: one node               → 1
h = 1: root + one child      → 2
h = 2: + a grandchild on one side → 4
h = 3: one side 2 tall, other 1 tall → 7
h = 4: one side 3 tall, other 2 tall → 12

Each step adds a whole subtree rather than a node, which is why the count jumps 1, 2, 4, 7, 12 and not 1, 2, 3, 4. At height 3 the two subtrees must have heights 2 and 1, and the sparsest such subtrees have 4 and 2 nodes, so 4 + 2 + 1 = 7.

Example 6 — the two counting questions on one row

Q: maximum height of an AVL tree with 15 nodes? Find the largest h with N(h) ≤ 15. N(4) = 12 ≤ 15 and N(5) = 20 > 15, so the answer is 4.

Q: minimum nodes in an AVL tree of height 5? Read the entry at 5: 20.

Q: is a 10-node AVL tree of height 4 possible? Height 4 needs at least 12 nodes, and 10 < 12, so no.

Q: maximum height with 7 nodes? N(3) = 7 ≤ 7 and N(4) = 12 > 7, so 3 — and a 7-node tree of height 3 exists, so the bound is attained, not merely an upper bound.

Example 7 — deletion needs two repairs

Insert 50, 25, 75, 10, 30, 60, 90, 5, 15, 20, 27, 35, 55, 65, 80, 95 into an empty AVL tree. Sixteen keys, height 4, every factor legal. Now delete 15.

The tree is 25 at the root, with left child 15 (left child 10, which has left child 5; right child 20) and right child 50 (left 30 with children 27 and 35; right 75 with children 60 and 90). Node 15 has two children, so the deletion is not a leaf removal: 15 is replaced by its in-order successor 20, and 20 is then removed from the right subtree.

That removal shortens the subtree, and the node now holding 20 — with left child 10 and no right child — breaks at bf = −2. That is the first repair. Because the repaired subtree comes back shorter, its parent 25 breaks at bf = +2, and a second rotation is needed at 25.

The exact log this model produces is LL@20 then RR@25: two single rotations at two different nodes for one deletion. Fifteen keys remain, the final root is 50, the height is 3, and the tree is still AVL with a sorted in-order walk.

Example 8 — the same keys, three shapes

Insert 50, 30, 70, 20, 60, 80, 10, 40, 65 into an AVL tree: nine keys, height 3, root 50, one rotation during the build (LL at 30). It is AVL and it is not complete, because node 30 has a right child 40 and no left child.

Insert 5, 3, 8, 1, 4, 7, 9, 2 into an AVL tree: eight keys, height 3, root 5, and no rotation at all — the input order happened to be legal. A tree needing zero rotations is not a tree that is not AVL.

Insert 1, 2, 3, 4, 5, 6, 7: seven keys, height 2, root 4, four single rotations, every one of them an RR case. Sorted input is the worst case for a plain BST and the most rotation-heavy case for an AVL tree — and it is also the case where the height bound is attained exactly.

The boundary cases that decide answers

Every one of these is a place where a formula or a rule that is right in general produces a wrong answer at the edge, or where two conventions disagree.

The empty tree

Height −1, and it is a legal AVL tree. N(−1) = 0 is a base case of the recurrence, not an oddity: it is what makes N(1) = 2 rather than 1 + N(0) + N(−1) failing. A question that asks for the height of an empty tree is asking whether you know the convention.

The empty tree is also the only tree with no node at which to check a balance factor — which is why "every node satisfies |bf| ≤ 1" is vacuously true for it.

One node, and two nodes

A single node has height 0 and bf 0: legal, and N(0) = 1 confirms it is the sparsest tree of height 0. Two nodes: a root with one child has bf ±1, legal, and N(1) = 2. Three nodes on a straight path: the root has bf ±2, illegal — the smallest illegal tree.

So the smallest tree that can need a rotation has three nodes, and the smallest tree that needs a double rotation also has three nodes (the zig-zag order).

Height conventions disagree

With "empty = −1, leaf = 0" a 7-key AVL tree reaches height 3. With "leaf = 1" — counting levels rather than edges — the same tree has height 4, and every N(h) shifts by one index. Both conventions are in use, and a question that does not state one is ambiguous.

The safe habit: read the question's own sentence. "Assume the height of a tree with a single node is 0" pins the convention; "number of levels" pins the other.

Duplicate keys

An AVL tree over a set of keys has no duplicates, and the model here treats a repeated key as a no-op rather than inserting it on one side. Some implementations allow duplicates by keeping a count in the node; others place equal keys consistently right.

Consequence for counting questions: if an insertion order repeats a key, the number of distinct keys and the number of insertions differ, and the tree size after the run is not the length of the list.

The height bound is loose for small n

For n = 7 the bound 1.44 log2(n+2) − 0.328 evaluates to 4.24 while the true maximum is 3. The bound is asymptotic: it is tight in the limit and generous below about thirty nodes.

So a question that asks for the maximum height on small n wants the table, not the formula. The formula is for proving O(log n), and for large-n estimates.

Balanced but not legal, and legal but not balanced-looking

The tree 50 with left child 20 (which has left 10, which has left 5) and right child 80 (which has right 90, which has right 95) has bf(50) = 0 and is not AVL. Conversely, a tree that looks lopsided on paper can be perfectly legal: a chain of three nodes on the left with a full subtree of two levels on the right can still have every factor inside ±1.

Only the numbers decide. That is the reason the routine computes factors instead of judging by eye.

Counterexample: complete does not follow from AVL

Insert 50, 30, 70, 20, 60, 80, 10, 40, 65. The result is AVL with 9 keys and height 3, but node 30 has a right child and no left child, and the last level is not filled from the left. Complete requires the last level to fill left to right; AVL requires only that heights differ by at most one at every node.

The implication runs the other way: a complete binary tree's levels differ by at most one, so every complete tree is AVL. The converse is false, and this is the smallest kind of witness for it.

Counterexample: one rotation is not always enough

Insert 30, 10, 20. A single right rotation at 30 gives 20 as the left child of 30 with 10 beneath it — still a zig-zag, and bf(30) is still −2. A single left rotation at 10 alone gives a mirror zig-zag. Only the pair works.

So "one rotation per insertion" means one repair, which may be two rotations. The count of rotations and the count of repairs are different questions, and the exam may ask either.

Seven beliefs that cost marks, each with the smallest case that kills it

Each entry states the belief in the form people actually hold it, then the counterexample or the definition that refutes it. Read the belief first and decide whether you hold it.

1. "Balanced means complete"

They are different rules. Complete is about the shape: every level full except the last, which fills from the left. AVL is about heights: at every node the two subtree heights differ by at most one.

Smallest witness: insert 50, 30, 70, 20, 60, 80, 10, 40, 65. Nine keys, height 3, every factor legal, and not complete — node 30 has a right child and no left child. Complete implies AVL; AVL does not imply complete.

2. "If the root is balanced, the tree is AVL"

The rule is a universal statement over nodes, so one legal node proves nothing. The root is one node out of n.

Smallest witness: insert 50, 20, 80, 10, 90, 5, 95 into a plain BST. bf(50) = 0, while bf(20) = −2 and bf(80) = +2. A root-only check passes a tree that is not AVL, and this is the most common way a wrong option gets chosen.

3. "A double rotation is one rotation"

The mechanism is two single rotations at two different nodes: first at the child, then at the grandparent. Textbooks and answer keys differ on how to count them, which is a convention, not a fact.

Practical rule: if the question asks for the case, answer LR or RL. If it asks for a count, state the convention — two single rotations per double case — and, if the options force a choice, check whether the key is counting repairs (one) or rotations (two). The number of insertions that needed a repair and the number of rotations performed differ whenever a double case occurs.

4. "An AVL tree is perfectly balanced"

Perfect is a much stronger condition: every internal node has two children and all leaves are on one level, so the size must be 2h+1 − 1.

A 7-node AVL tree of height 3 is not perfect — a perfect tree of height 3 has 15 nodes. AVL allows the two sides of every node to differ by one, and those ones accumulate along a path, which is exactly why the height can be 1.44 log n rather than log n.

5. "A rotation can change the sorted order"

It cannot, and that is the point of a rotation. The middle subtree changes parent — from the right child of the lower node to the left child of the upper node — and both positions sit between the same two keys in sorted order.

Test any drawing by writing the in-order walk before and after. Rotate right at 30 with left child 20 and 20's right child 25: before 20, 25, 30; after 20, 25, 30. If your version differs, a subtree has been dropped or duplicated.

6. "2h+1 − 1 is the minimum number of nodes at height h"

That formula is the maximum: it is the perfect tree. The minimum is N(h) = N(h−1) + N(h−2) + 1, which is 1, 2, 4, 7, 12, 20, 33.

At h = 3 the two answers are 15 and 7. A question that says "minimum" and expects 15 has been misread, and a question that says "maximum" and gets 7 has been answered with the wrong row.

7. "Deleting never needs more than one rotation"

Insertion restores the height of the repaired subtree, so nothing above it can break. Deletion can shorten it, so the imbalance can travel upward and need a repair at each level.

Witness computed in this lesson: build a 16-key AVL tree from 50, 25, 75, 10, 30, 60, 90, 5, 15, 20, 27, 35, 55, 65, 80, 95 and delete 15. The log is a rotation at 20 and then another at 25 — two repairs for one deletion.

The pairs that get confused with each other

Four distinctions, each one sentence apart, each one decisive on a multiple-choice option.

Balance factor against height

Height is a property of one subtree, measured downward. The balance factor is a comparison of two heights at one node. A tree can have a large height and every balance factor legal — that is the normal case for a deep AVL tree.

So "the tree is unbalanced" never means "the tree is tall". It means some node has a factor of ±2.

LL against LR

Both have bf(y) = −2, so the sign at y does not distinguish them. The child's sign does: bf(child) ≤ 0 is LL, bf(child) = +1 is LR. Equivalently, the taller grandchild is on the outside (LL) or the inside (LR) of the path.

The cheap test without computing factors: write the three keys in sorted order. The one that should become the root is the middle key. If it is already the child of y, the case is single; if it is the grandchild, it is double.

Minimum nodes against maximum nodes

At height h: the minimum is N(h) (the Fibonacci-like row) and the maximum is 2h+1 − 1 (the perfect tree). Both are about the same height and both are routinely asked.

The habit that prevents the error: when the question says "minimum", immediately write the recurrence; when it says "maximum", immediately write the power of two.

One repair against one rotation

A repair is a rebalancing action at one node; a rotation is one three-pointer rearrangement. A single case is one repair and one rotation; a double case is one repair and two rotations.

Insertion needs at most one repair. Deletion may need many repairs, hence up to O(log n) rotations. Any question about counts has to say which of the two it is counting.

What none of this says

Nothing here promises that an AVL tree has a unique shape for a given set of keys — two different insertion orders of the same keys give different AVL trees, both legal. Nothing promises that the AVL tree is the one with minimum height; a perfect tree has smaller height and is not reachable by rotations alone. And nothing promises that a rotation is the cheapest possible repair — it is the cheapest repair that preserves the in-order sequence with three pointer writes.

How this material is actually asked

Community observation Balanced-tree items in practice archives come in five recognisable shapes. The list below describes the patterns, which are stable, and claims nothing about how often any of them appears in GATE CSE 2027. No previous-year question is reproduced in this lesson, because none could be verified against an official paper.

Every pattern below is answerable with the four-step routine: draw the insertions, mark heights and factors, repair at the lowest broken node, then read what the question asked for.

Pattern A — insert a sequence, name the final root

The commonest form, and the most error-prone, because one wrong rotation propagates. Example: insert 10, 20, 30, 40, 50, 25; the root is 30.

Procedure. Insert in order, redraw after every insertion, and repair immediately. Do not defer repairs to the end: an AVL tree repairs as it goes, and the shape depends on that.

Pattern B — count the rotations

Example: insert 50, 40, 30, 20, 10; the answer is 2 single rotations (LL at 50, then LL at 30). Sorted input of 1 to 7 needs 4.

Procedure. Count as you repair, not afterwards. For a double case write 2 and note the convention. Descending input of n keys needs about n − 3 single rotations, which is a useful sanity bound — never n and never log n.

Pattern C — minimum nodes or maximum height

Example: minimum nodes at height 5 is 20; maximum height on 15 nodes is 4; maximum height on 7 nodes is 3.

Procedure. Write the row 1, 2, 4, 7, 12, 20, 33, 54, 88. For "minimum nodes at h" read across. For "maximum height on n" read back: the largest h whose entry is ≤ n. Check the stated height convention before answering.

Pattern D — which rotation repairs this tree

A tree is drawn with one node marked. The options are "left rotation at X", "right rotation at X", "left then right", "right then left".

Procedure. Compute the factor at the marked node and at its taller child. Same sign twice: single, rotating in the direction opposite to the lean. Opposite signs: double, starting at the child. The middle key of the three sorted keys tells you which node must end up on top, and that alone usually eliminates two options.

Pattern E — is this tree AVL, and what is its height

A drawing with several levels, and a question that asks whether it is AVL, complete, perfect, or what its height is.

Procedure. Walk bottom-up computing every height, then every factor in one pass. Then answer each adjective separately: complete is a shape test on the last level, perfect is a count test against 2h+1 − 1, AVL is a factor test at every node. One tree can be one and not the others.

Pattern F — cost of a run of operations

Example: the cost of inserting n² keys into an AVL tree that already holds n. Each insertion is O(log n) because the tree stays logarithmic, so the total is Θ(n² log n) — the trap being Θ(n⁴) from multiplying n² by n².

Procedure. Bound the height first, then multiply by the number of operations. The repair is O(1) and never changes the bound; that is the whole reason the invariant is worth maintaining.

No marks weight for balanced trees in GATE CSE 2027 is asserted here, and no previous-year item is attributed to a year or a question number. The five patterns describe the shape of the questions that appear in practice archives; they are not a frequency count and not a prediction.

Q1 MCQ Original

Insert 10, 20, 30, 40, 50, 25 in that order into an initially empty AVL tree. Which key is at the root of the final tree?

(A) 20   (B) 25   (C) 30   (D) 40

Answer: C. The run is: 10, then 20, legal; inserting 30 gives RR at 10, so 20 becomes the root; 40 legal; inserting 50 gives RR at 30, so that subtree becomes 40 with 30 and 50 beneath it; inserting 25 goes left of 30, after which 20 has bf = +2 while its right child 40 has bf = −1 — opposite signs, so RL: rotate right at 40, then left at 20, which lifts 30 to the root.

A is the root after the first rotation, kept by anyone who stops repairing early. D is the root of the subtree that the last RL case repairs, not the root of the tree. B is the key that caused the last repair, not the root.

Check: the final tree is 30 with left child 20 (children 10 and 25) and right child 40 (right child 50). Every factor is inside ±1 and the in-order walk is 10 20 25 30 40 50.

Q2 NAT Original

Insert 50, 40, 30, 20, 10 in that order into an initially empty AVL tree. How many single rotations are performed in total? (Count each rotation of a double case separately; here every repair is a single case.)

Answer: 2. Inserting 30 gives LL at 50, one right rotation, and 40 becomes the root with 30 and 50 beneath. Inserting 20 is legal. Inserting 10 gives LL at 30, one right rotation, leaving 40 with left child 20 (children 10 and 30) and right child 50.

The trap is assuming one rotation per insertion: five keys would then suggest four. A rotation only fires when a factor reaches ±2, and here two of the five insertions were legal. Check: height 2 on five keys, and 5 is between N(2) = 4 and the perfect 7.

Q3 MCQ Original

What is the minimum number of nodes in an AVL tree of height 5, with the height of a single node equal to 0?

(A) 12   (B) 20   (C) 32   (D) 63

Answer: B. N(5) = N(4) + N(3) + 1 = 12 + 7 + 1 = 20.

A is N(4), the answer one height too low. C is 25, a power of two with no recurrence behind it. D is 26 − 1, the maximum number of nodes at height 5 — the perfect tree.

The row: 1, 2, 4, 7, 12, 20, 33, 54, 88 for h = 0 to 8.

Q4 NAT Original

What is the maximum possible height of an AVL tree with 15 nodes, with the height of a single node equal to 0?

Answer: 4. Height 4 needs at least N(4) = 12 nodes, and 12 ≤ 15, so height 4 is achievable. Height 5 needs N(5) = 20 nodes, and 15 < 20, so height 5 is impossible.

The formula 1.44 log2(n+2) − 0.328 gives 5.56 for n = 15, which is an upper bound and not the answer; for small n the table is exact and the formula is not.

Q5 MSQ Original

The keys 5, 3, 8, 1, 4, 7, 9, 2 are inserted in that order into an initially empty AVL tree. Which of the following statements are true of the resulting tree?

(A) No rotation is performed during the build.
(B) The tree is complete.
(C) The tree is AVL.
(D) The tree has height 3.

Answer: A, C and D.

The result is root 5, left child 3 (children 1 and 4), right child 8 (children 7 and 9), and 2 as the right child of 1. Every insertion happened to keep all factors inside ±1, so no rotation fired — which is why A is true: needing no rotation is not the same as being un-balanced.

B is false. Level 3 holds one node, 2, and it is the right child of 1 — the last level does not fill from the left, so the tree is not complete. D is true: the path 5, 3, 1, 2 has three edges.

This is the pair of distinctions worth carrying: "no rotation needed" against "not balanced", and "AVL" against "complete".

Q6 MCQ Original

Which insertion order makes the first rotation that ever fires an LR case?

(A) 30, 10, 20   (B) 30, 20, 10   (C) 10, 20, 30   (D) 20, 30, 10

Answer: A. After 30 and 10, bf(30) = −1. Inserting 20 makes it the right child of 10, so bf(30) = −2 while bf(10) = +1: opposite signs, LR, repaired by a left rotation at 10 and then a right rotation at 30.

B is LL — the same side twice, one right rotation at 30. C is RR, one left rotation at 10. D needs no rotation at all: 20 is the root, 30 its right child, 10 its left child, all factors 0.

The decision is the sign of the child, not the sign of the unbalanced node: all four sequences have bf = ±2 somewhere or nowhere, and only the child's sign separates LL from LR.

Q7 MCQ Original

In the worst case, how many single rotations can a single deletion from an AVL tree of n nodes require?

(A) 0   (B) exactly 1   (C) at most 2   (D) Θ(log n)

Answer: D. A deletion can shorten the repaired subtree, so the imbalance can propagate to the next level up, and the repair can repeat at every level of the path — Θ(log n) rotations in the worst case, one per level.

B and C are the insertion answers: an insertion restores the old subtree height, so at most one repair (one or two rotations) is ever needed. A is the answer for a deletion that happens not to disturb any factor, which is possible but not the worst case.

This lesson's model shows a concrete two-repair deletion: from a 16-key tree built by inserting 50, 25, 75, 10, 30, 60, 90, 5, 15, 20, 27, 35, 55, 65, 80, 95, deleting 15 needs a rotation at 20 and then another at 25.

Q8 NAT Original

Rotate right at the node holding 30, in a subtree where 30 has left child 20 and 20 has right child 25 (and no other nodes). List the in-order walk of the subtree after the rotation, as three space-separated keys.

Answer: 20 25 30. The rotation makes 20 the subtree root, gives 30 the former right child of 20 — that is 25 — as its left child, and hangs 30 on the right of 20. The in-order walk is unchanged, which is the point: a rotation moves shape, never order.

The common wrong answer is "20 30" with 25 dropped, or "20 25 30" with 25 still drawn as 20's right child while 30 also keeps it. If a subtree appears twice or not at all, three pointer writes were written as two.

The revision sheet

Everything on one screen: the definitions, the four cases, the two directions of the counting table, the routine and the traps. If you remember one thing, remember that the rule is local and the repair is local.

Definitions

Height — edges on the longest downward path; empty = −1, leaf = 0.

Balance factor — bf(n) = height(right) − height(left), an integer in [−h, +h].

AVL tree — a BST with |bf(n)| ≤ 1 at every node.

Rotation — a three-pointer rearrangement of three nodes that preserves the in-order walk.

N(h) — the fewest nodes an AVL tree of height h can have.

Formulas

N(h) = N(h−1) + N(h−2) + 1, N(−1) = 0, N(0) = 1
N(h) = F(h+3) − 1
h ≤ 1.44 log2(n+2) − 0.328
max nodes at height h = 2h+1 − 1 (perfect)
insert: O(log n) time, O(1) rotations
delete: O(log n) time, O(log n) rotations
search: O(log n) always

The row to memorise: 1, 2, 4, 7, 12, 20, 33, 54, 88 for h = 0 to 8.

The four cases

LL: bf(y) = −2, bf(child) ≤ 0 → rotate right at y
RR: bf(y) = +2, bf(child) ≥ 0 → rotate left at y
LR: bf(y) = −2, bf(child) = +1 → left at child, right at y
RL: bf(y) = +2, bf(child) = −1 → right at child, left at y

Shorter test: the middle of the three sorted keys must become the root. If it is already y's child, the case is single; if it is y's grandchild, it is double.

The decision procedure

  1. Insert in the given order, one key at a time, going left on smaller and right on larger.
  2. After each insertion, recompute heights from the new leaf up the path.
  3. Find the lowest node whose |bf| = 2. If none, continue.
  4. Name the case from the child's and grandchild's sides; apply one or two rotations.
  5. Continue the sequence. At the end, read what was asked: root, height, rotation count, or AVL/complete/perfect.

Traps in one line each

Repairing at the root instead of the lowest break.

One rotation on LR or RL, which mirrors the zig-zag instead of removing it.

Counting a double case as one rotation when the question counts rotations.

Reading "balanced" as "complete", or checking only the root's factor.

Using 2h+1 − 1 for the minimum nodes at height h.

Ignoring the stated height convention (leaf 0 or leaf 1).

Assuming a deletion needs one repair, as an insertion does.

Three questions to ask yourself before answering

Does the question ask for a count of rotations or of repairs? Does it say minimum or maximum nodes? Does it state the height convention?

Those three sentences decide more answers in this topic than the arithmetic does.

What is computed here rather than cited

Every tree, every balance factor, every rotation, every rotation count and every height in this lesson is produced by the AVL implementation in lesson.js, which re-checks its own invariant after every operation and reports the result under "Model checks" beside the canvas. The checks include: every intermediate tree is a BST and AVL, heights stay consistent with shapes, rotations preserve the in-order walk, the four cases converge to the same tree, N(h) matches F(h+3) − 1, the minimum-node trees really are AVL, and the two counterexamples fail the properties they are meant to fail.

Mathematical derivation The rotation-count facts (three rotations for the six-key run; two for the descending five-key run; four for 1 to 7; two repairs for the stated deletion) are computed, not quoted.

What this lesson does not cover

  • Splay trees, treaps, weight-balanced trees and other balance rules.
  • Threaded trees, and the persistence or concurrency questions that follow from rotation-heavy updates.
  • Full AVL deletion code — the lesson states the rule, exhibits a two-repair case, and leaves the implementation to the reader.
