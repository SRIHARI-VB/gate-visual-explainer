Topic and objective

TOPIC: The three protocols that sit beside IPv4 and make the first packet possible — ARP (an IPv4 address to a hardware address), DHCP (no address at all to a leased one), and ICMP (a packet that failed to a report saying why).

LEARNING OBJECTIVE: Given a network scenario, name which of the three protocols answers it, then justify the answer with the numbers: the 28 octets of an ARP header and the padding that reaches 64, the next-hop decision made by a prefix, the four DHCP messages with their ports and broadcasts, the T1 and T2 timers computed from a lease, and the ICMP type-and-code pair that a router or a host actually sends — including the five cases where nothing is sent at all.

I read this topic as three gaps and three fillers, not as three unrelated protocols. Every claim on the page is either a rule quoted from a standard, an arithmetic sum you can check, or a classification the page computes at load. Where the standards leave a value to the implementation — an ARP cache timeout, for instance — the lesson says so instead of inventing a number.

The five ideas to leave with

  1. A frame names an interface; a packet names a host. ARP is the conversion, and it never crosses a router.
  2. The prefix, not the destination address, decides whose MAC you ask for.
  3. DHCP has to shout because the client has no legal source address yet. Two of its four messages are client broadcasts.
  4. T1 is when renewal starts, at half the lease; T2 is when rebinding starts, at seven eighths. Neither is the expiry.
  5. ICMP reports and never repairs, and five rules mean the correct number of messages is sometimes zero.

Intuition: three gaps at the front door

A parcel has two kinds of label. One names the person it is for and travels with it all the way. The other names the van that carries it on the next leg, and it is rewritten at every depot. That is the difference between an IP address and a MAC address, and it is the reason the first of the three protocols exists.

ARP is the address book at the depot. The van driver knows the person's name — the IPv4 address — but the loading bay needs the bay number, which is the hardware address. If the book has no entry, the driver shouts the name across the yard. Exactly one person answers, quietly, and the book is updated.

DHCP is the desk that issues addresses. A new arrival has no address at all, so they cannot even post a letter. They stand at the gate and shout "is there a desk that hands out addresses?", every desk in earshot answers with an offer, the arrival picks one and says so out loud — again so that the other desks hear the choice — and the chosen desk confirms it with a time limit.

ICMP is the note that comes back when a parcel fails. It is written by whoever gave up on the parcel — a depot that could not find the road, or the destination itself — and it quotes the original label so the sender knows which parcel is meant. It never resends the parcel, and sometimes no note is written at all.

Formal definition: ARP

Verified fact ARP is defined by RFC 826 for IPv4 over any link layer that has broadcast addresses. It carries one question — "which hardware address has this protocol address?" — and one answer to it.

The message has a fixed shape for Ethernet and IPv4: hardware type (2 octets), protocol type (2), hardware length (1), protocol length (1), operation (2), sender hardware address (6), sender protocol address (4), target hardware address (6), target protocol address (4). That is 8 + 20 = 28 octets.

Operation 1 is a request; operation 2 is a reply. A request is sent to the link-layer broadcast address with the target hardware field zeroed, because that field is the thing being asked for. A reply is sent to the hardware address the request carried.

The ARP frame is identified by EtherType 0x0806, which is a link-layer field, not an IP field. This is the single fact that separates ARP from the other two protocols in a "which layer" question.

Formal definition: DHCP

Verified fact DHCP (RFC 2131) is a UDP application. Client messages go to the server port 67; server messages go to the client port 68. It reuses the BOOTP message format: a fixed header of 236 octets, a four-octet magic cookie (99.130.83.99), then tagged options.

The fixed header's fields are op, htype, hlen, hops, xid, secs, flags, ciaddr, yiaddr, siaddr, giaddr, chaddr, sname, file, which add to 236 octets. The reply address goes in yiaddr, the client's hardware address in chaddr, and a relay agent's address in giaddr.

A client before it has an address sends from source 0.0.0.0 to 255.255.255.255. RFC 2131 permits exactly this one case, because a source address must otherwise be one of the host's own.

Formal definition: ICMP

Verified fact ICMP (RFC 792) is carried as the payload of an IP datagram with IP protocol number 1. The standards describe it as an integral part of IP, which must be implemented by every IP module — not as a transport protocol above it.

Every message begins with type (1 octet), code (1), checksum (2) and four further octets whose meaning depends on the type. An error message then quotes the IPv4 header of the datagram that caused it and at least the first 8 octets of that datagram's data.

Verified fact RFC 792 states that no ICMP messages are sent about ICMP messages, and that messages are sent only about errors in handling fragment zero. RFC 1122 §3.2.2 generalises this into the five suppression rules of scene 8.

The arithmetic that questions actually ask for

Five sums cover most of the numeric content of this topic. Each one is computed on this page at load, and each appears in the model checks beside the animation.

ARP header. 2 + 2 + 1 + 1 + 2 + 6 + 4 + 6 + 4 = 28 octets.

Minimum Ethernet frame. 14 header + 28 ARP = 42 octets of payload, against a 46-octet minimum, so 18 octets of padding; 42 + 18 + 4 of frame check sequence = 64 octets.

DHCP sizes. 236 fixed + 4 cookie = 240; the BOOTP minimum frame is 300, leaving 60 octets for options and padding; the DHCP message must be able to reach 236 + 312 = 548 octets, and 548 + 20 of IP + 8 of UDP = 576, which is the datagram size every host must be able to receive.

Lease timers. For a 3600-second lease, T1 = 0.5 × 3600 = 1800 and T2 = 0.875 × 3600 = 3150, with T1 < T2 < expiry.

ICMP quotes. 20 octets of IPv4 header plus 8 octets of data = 28 octets quoted inside every error message.

This table is the fastest way to answer "at which layer does this operate". ARP's identifier lives in the frame header, so ARP is spoken of as sitting between the link layer and the network layer. ICMP's lives in the IP header, so ICMP is part of the network layer. DHCP's lives in a UDP header, so DHCP is an application protocol.

What each one is allowed to answer

  • ARP: which interface holds this IPv4 address, on this link. Nothing else — it has no field for a route, a lease or an error.
  • DHCP: what address, mask, gateway, DNS server and lease duration a client should use. It can also refuse, decline or release, but it never resolves a hardware address.
  • ICMP: what went wrong with a datagram — unreachable, expired, too big, redirected, malformed. It carries no configuration and resolves nothing.

The one distinction that decides most questions

A question versus an announcement. ARP's request expects an answer and is broadcast; its reply answers one asker and is unicast; a gratuitous ARP is a reply nobody asked for, broadcast to everyone. DHCP's discover expects offers; its request announces a choice; its acknowledgement confirms it.

In both protocols the broadcast carries the question and the unicast carries the answer — except where the answer has to be heard by everyone, which is exactly the case the DHCP request creates. Reading who must hear this answers the addressing question without memorising a table.

How the three fit together

They are not parallel topics. They hand over to each other, and one handover is written into a standard.

DHCP → ARP. RFC 2131 tells a client that has just accepted a lease to broadcast an ARP reply announcing its new address, precisely so that stale cache entries elsewhere on the link are corrected. A DHCP exchange therefore ends with an ARP message.

ARP → ICMP. If ARP gets no reply, the datagram cannot be framed at all, and the host reports a destination unreachable to itself — no ICMP message goes on the wire, because there is no frame in which to send one.

DHCP → ICMP. Nothing direct. But a client that cannot reach a DHCP server usually learns it through silence, not through an error message, because its request was a broadcast and the suppression rules forbid an error in reply to a broadcast.

A counterexample that fixes the layer question

"ARP is an application protocol because it has its own message format, like DHCP." The conclusion is false and the reasoning is the interesting part.

DHCP's format sits inside a UDP header, so an application chose to send it. ARP's format sits directly inside the frame, identified by an EtherType, with no IP header at all — so there is no transport layer and no application to speak of. A protocol is placed by what carries it, not by whether it has fields of its own.

Why "ping failed, so the host is down" is not an inference

An echo request is a datagram like any other. It can be dropped by a congested link, blocked by a filter, answered but with the reply lost, or suppressed by a rule if it was addressed to a broadcast.

ICMP promises nothing. RFC 792 says plainly that there are no guarantees a datagram will be delivered or that a control message will be returned. A missing reply is evidence about the path, not a verdict about the host.

Worked example 1: size one ARP exchange, end to end

Host A (192.168.10.5/24, MAC AA:00:00:00:00:0A) wants to send one datagram to 192.168.10.20. Its ARP cache is empty.

Step 1, the prefix test. A's network is 192.168.10.0/24. The destination's network, under the same mask, is also 192.168.10.0. Equal, so the destination is on this link and the next hop is the destination itself.

Step 2, the request. One ARP request frame: destination MAC FF:FF:FF:FF:FF:FF, operation 1, sender hardware AA:…:0A, sender protocol 192.168.10.5, target hardware all zeros, target protocol 192.168.10.20. Every station on the link reads it; only the owner of .20 answers.

Step 3, the reply. One ARP reply, unicast to AA:…:0A, operation 2, carrying the answer in the sender fields. A caches the pair.

Step 4, the sizes. The ARP message is 28 octets. The frame is 14 + 28 = 42 octets before padding, which is under the 46-octet minimum, so 18 octets of padding follow; with the 4-octet frame check sequence the frame is 64 octets. Two frames were sent, one broadcast and one unicast, and the datagram itself is sent afterwards in a third frame.

Worked example 2: five destinations, one mask

From 192.168.10.5/24, the ARP target for each destination is the next hop:

DestinationPrefix testARP asks for
192.168.10.20inside192.168.10.20
192.168.10.77inside192.168.10.77
192.168.10.254inside192.168.10.254
192.168.10.9inside192.168.10.9

Four requests name a host and one names the gateway. In all five cases the IP destination stays 192.168.20.9 or its own value; only the frame's destination MAC differs. A page that says "the router's IP address goes in the packet" has the two facts confused.

Worked example 3: the same question with a different mask

Change A to 192.168.10.5/28. Its network is now 192.168.10.0 with a block of 16 addresses, 192.168.10.0 to 192.168.10.15, so .20, .77 and .254 are outside, while .9 is still inside.

Three of the five destinations now resolve to the gateway instead of one, and .9 keeps resolving to itself because 9 is inside the 0–15 block. Nothing about the addresses changed; the mask did. That is why a question that supplies a mask is really asking you to apply it, and a question that omits one is usually assuming the classful or the stated default.

Worked example 4: a lease of 3600 seconds, traced on the clock

t = 0. The client broadcasts DHCPDISCOVER from 0.0.0.0:68 to 255.255.255.255:67. One or more servers answer with DHCPOFFER. The client broadcasts DHCPREQUEST naming one server and one address. That server answers DHCPACK with a lease of 3600 seconds.

t = 1800. T1, half the lease. The client is still configured, so it unicasts a DHCPREQUEST to the server that granted the lease, with its own address in ciaddr and no server identifier. A DHCPACK here returns the client to the bound state and resets both timers.

t = 3150. T2, seven eighths of the lease, reached only if the renewal at T1 got no answer. The client broadcasts a DHCPREQUEST to any server, because the original one may be the thing that is broken.

t = 3600. The lease expires. If no acknowledgement arrived, the client stops using the address and returns to the initial state. Counting the client's broadcasts over one clean cycle gives two at the start and none at renewal — the renewal is unicast, and the rebinding broadcast only happens if renewal failed.

Worked example 5: count the messages on a five-hop path

Traceroute sends a probe with TTL 1. Router 1 decrements to zero, discards the datagram and returns time exceeded, type 11 code 0. The source address of that message is router 1.

TTL 2 reaches router 2 before expiring, so router 2 reports. TTL 3 and TTL 4 give routers 3 and 4. That is four type 11 messages.

TTL 5 reaches the destination. Classic traceroute sends UDP to a port nothing listens on, so the host itself returns destination unreachable, type 3 code 3. One message, from the target.

Total: five messages for five hops. Two things to keep straight: the last message is a different type, and it comes from a different kind of device. A variant that probes with ICMP echo instead ends with type 0, an echo reply.

Worked example 6: six cases, and two silences

Apply the five RFC 1122 rules to each case and say whether an error message is sent.

A unicast UDP datagram to a closed port, first fragment, valid source: sent, type 3 code 3. A datagram whose TTL reaches zero at a router: sent, type 11 code 0. A datagram larger than the next link with the don't-fragment bit set: sent, type 3 code 4. A destination network the router cannot reach: sent, type 3 code 0.

A datagram addressed to 255.255.255.255: not sent, because the destination is a broadcast address. A datagram that is itself an ICMP error and then fails: not sent, because no error is sent about an error.

Four problems, four reports, two silences. A question that says "how many ICMP messages are generated by these six events" has the answer 4, and the two silences are the whole difficulty.

The boundaries where the rules bite

Each of these is a place where a confident sentence becomes false if the boundary is ignored. They are the cases a well-written question is built on.

An empty cache is normal, and the timeout is not standard

ARP entries are cached for a while and then dropped, so the first packet after a quiet period repeats the exchange. The standards do not fix the lifetime: it is implementation-defined, and different systems choose different values.

So a question that asks "how many ARP requests are sent in five minutes" without stating a timeout has no single answer. Say what the assumption is, or say the question is under-specified — both are better than inventing a number.

No ARP reply means no ICMP message either

If ARP resolves nothing, the datagram cannot be put into a frame, so nothing is transmitted. The host may report the failure to the local application, but no ICMP message crosses the wire.

This is the cleanest example of the difference between "an error happened" and "an error message was sent". The event is real; the message does not exist because there was no frame to carry it.

Fragment zero, not "the first fragment you see"

RFC 792 allows ICMP messages only about errors in handling fragment zero — the fragment whose offset field is zero. A non-initial fragment carries no transport header, so a port unreachable about it could not name a socket.

RFC 1122 turns this into a suppression rule: no error about a non-initial fragment. But a reassembly timeout is a different condition and does produce type 11 code 1, sent about the fragment-zero information the receiver still holds.

A link-layer broadcast that looks unicast

A frame can be sent to the hardware broadcast address while its IP destination is an ordinary unicast address. The suppression rule counts that as a broadcast too, which is why RFC 1122 requires the link layer to tell IP when a frame arrived as a broadcast.

Checking only the IP destination misses the case. This is the one rule where the information needed lives in the layer below.

0.0.0.0 is legal once, and only as a source

A DHCP client sends from 0.0.0.0 because it has no address. RFC 1122 forbids 0.0.0.0 as a source in general, and permits it during initialisation — the same permission DHCP depends on.

It is never a valid destination, and it is never a host you can send an error to. That is why a datagram from 0.0.0.0 is on the suppression list: there is no single host at the other end.

T1 and T2 are defaults, not constants

RFC 2131 gives T1 = 0.5 × lease and T2 = 0.875 × lease as defaults, and lets the server send other values in options 58 and 59. It also recommends some random variation, so that clients do not all renew at the same instant.

A question that supplies T1 and T2 explicitly is testing whether you use the given values. A question that gives only the lease is testing whether you know the defaults. They are different questions.

Six beliefs that cost marks, each with the smallest thing that refutes it

Each entry is the wrong belief, then the correction, then the smallest fact that settles it. Where the refutation is a standard, the standard is named.

1. "ICMP uses port 1"

Wrong. 1 is the IP protocol number in the IPv4 header. ICMP has no ports, because no transport header sits above it, and no application can bind to it.

Fix. Ask which header holds the identifier. ARP's is in the frame, ICMP's in the IP header, DHCP's in a UDP header. Only the last one has ports.

2. "ARP requests cross routers to find remote hosts"

Wrong. An ARP request is a link-layer broadcast, and a router does not forward broadcasts. ARP resolves only addresses on the same link.

Fix. For a remote destination, ARP resolves the router. The packet's IP destination is unchanged, and the far host's MAC is never known to the sender.

3. "DHCP works across subnets by broadcast"

Wrong. The broadcast is exactly what stops at the router. What carries the message across is a relay agent, which forwards it and records its own address in giaddr so the server knows which pool to use.

Fix. Broadcast is the reason a relay is needed, not a substitute for one.

4. "The lease expires at T1"

Wrong. T1 is when renewal starts, at half the lease. T2 is when rebinding starts, at seven eighths. The address is still usable until the lease itself runs out.

Fix. Three times, in order: T1 < T2 < expiry. A configuration with T2 before T1 is invalid, which is a standard way to build a wrong option.

5. "Every failed datagram produces an ICMP error"

Wrong. Five suppression rules can silence it: an error about an error, a broadcast or multicast destination, a link-layer broadcast, a non-initial fragment, or a source that is not one single host.

Fix. Run the rules before counting. "None" is a legitimate answer, and it is the one the rules exist to produce.

6. "ICMP makes IP reliable"

Wrong. ICMP reports; it never retransmits, acknowledges or repairs. RFC 792 states that there is no guarantee a datagram is delivered or that a report is returned.

Fix. Reliability, where it exists, is built above IP — by TCP, which uses acknowledgements and retransmissions of its own and treats an ICMP report as information, not as a repair.

How this material is asked, and the reasoning each shape demands

Educational interpretation The four shapes below are the ones these protocols make natural: a statement pair about addressing, a count of messages, a size sum, and a "which protocol" placement. One official question is quoted, with its paper and year. No frequency claim is made.

Official question: GATE CS 2021, Set 1, Question 18

Verified fact The question is a 1-mark MCQ and reads: "Consider the following two statements. S1: Destination MAC address of an ARP reply is a broadcast address. S2: Destination MAC address of an ARP request is a broadcast address. Which one of the following choices is correct?"

The official key is that S1 is false and S2 is true. I checked this against several independent reproductions of the paper, including a scanned-and-retyped copy of the CS 2021 Paper I. The option letter differs between reproductions — one lists this answer as (A), another as (C) — so the answer is given here by content, not by letter.

What it demands. One fact: the request must reach every station, so it is broadcast; the reply goes to exactly one station, whose hardware address the request supplied, so it is unicast. The framing of the question is a pair of statements, so both halves must be judged separately.

Shape 1: statement pairs and MSQs

"Which of the following are true of ARP / DHCP / ICMP?" with options drawn from the addressing, the layer and the suppression rules.

What it demands. One fact per option, and no reasoning across protocols. The commonest wrong option is a true statement about the wrong protocol, for instance a DHCP broadcast offered as an ARP fact.

Procedure. For each option, name the protocol, then the header that identifies it, then whether the statement is about addressing or about timing.

Shape 2: count the messages or the broadcasts

"How many ARP requests are sent?", "how many DHCP messages are broadcast?", "how many ICMP messages are generated?"

What it demands. A model of who must hear each message, plus the suppression rules for ICMP. Cache timeouts, retransmissions and failures are usually excluded by the wording, and the wording must be read.

Trap. One ARP request per unresolved next hop, not per packet. Two client broadcasts per clean DHCP exchange, not four.

Shape 3: the size sum

"What is the size of the ARP message?", "what is the minimum frame size?", "how many octets does the DHCP fixed header have?"

What it demands. Adding the fields, then applying the link-layer minimum. The two conventions for the Ethernet minimum — 64 including the 4-octet frame check sequence, 60 excluding it — must be kept apart.

Trap. Quoting the ARP header as 8 octets, which is only the fixed part, and forgetting the two address pairs that make it 28.

Shape 4: which protocol, and at which layer

"A host needs the hardware address of its gateway. Which protocol is used?" or "which of these operates at the network layer?"

What it demands. The gap being filled, then the identifier that proves the layer. ARP: EtherType, between link and network. ICMP: protocol number 1, part of the network layer. DHCP: UDP ports 67 and 68, application layer.

Trap. "ARP is an application protocol because it has a message format" is the wrong inference, and it is offered as an option more often than it should be.

Practice set — answers withheld until you reveal them

Q1 MCQ GATE CS 2021, Set 1, Q18

S1: Destination MAC address of an ARP reply is a broadcast address. S2: Destination MAC address of an ARP request is a broadcast address. Which is correct?

(A) Both are true
(B) S1 true, S2 false
(C) S1 false, S2 true
(D) Both are false

Answer: S1 is false and S2 is true — option (C) as printed in this reproduction. The official key states the answer by content; reproductions differ in lettering.

The request has to reach every station on the link, because the sender does not know which one holds the target address, so its destination MAC is FF:FF:FF:FF:FF:FF. The reply goes to exactly one station, and that station's hardware address was carried in the request's sender field, so the reply is unicast.

Why the others fail. A says both are broadcast, which would mean every station processes every answer. B inverts the pair. D says the request is unicast, which is impossible when the sender does not yet know the address.

Q2 NAT Original

An ARP message for Ethernet over IPv4 is carried in an Ethernet frame with no VLAN tag. How many octets of padding are added to reach the minimum payload?

Answer: 18. The ARP message is 8 + 6 + 4 + 6 + 4 = 28 octets. The minimum payload is 46 octets, so 46 − 28 = 18 octets of padding.

The trap. Padding is measured against the payload minimum, not against the 64-octet frame. The frame is 14 + 46 + 4 = 64; the padding inside the payload is 18.

Q3 MSQ Original

Host A is 10.1.2.3/22. Which destinations does A resolve by ARP to its default gateway rather than to the destination itself?

(A) 10.1.2.200
(B) 10.1.3.1
(C) 10.1.4.5
(D) 10.1.7.255

Answer: C and D. A /22 block is four /24s: 10.1.0.0 through 10.1.3.255. So 10.1.0.x, 10.1.1.x, 10.1.2.x and 10.1.3.x are inside; 10.1.4.0 onwards is outside.

A is inside (10.1.2.x). B is inside (10.1.3.x). C is outside. D, 10.1.7.255, is the directed broadcast of a network A cannot reach directly, so it is outside too.

The trap. Reading /22 as three octets plus two bits of the fourth is the whole question. And a broadcast address of a remote network is still a remote address, not a local one.

Q4 NAT Original

A DHCP server grants a lease of 7200 seconds and sends no T1 or T2 options. At what time, in seconds from the start of the lease, does the client first try to rebind by broadcast?

Answer: 6300. T2 defaults to 0.875 × 7200 = 6300 seconds. T1 would be 3600.

The trap. Three candidate answers are all plausible: 3600 (T1), 6300 (T2) and 7200 (expiry). Rebinding is the T2 event and it is broadcast; renewal at T1 is unicast.

Q5 MSQ Original

A client with no address completes a clean DHCP exchange on a segment with two servers. Which statements are true?

(A) The client sends two broadcasts.
(B) The client's source address is 0.0.0.0 in all four messages.
(C) The client sends to UDP port 67.
(D) The DHCPREQUEST is broadcast so the servers it did not choose learn the decision.

Answer: A, C and D.

A: DHCPDISCOVER and DHCPREQUEST are both broadcast, so two of the client's two messages are broadcasts. C: client messages go to the server port 67 from port 68. D: the broadcast is the withdrawal signal to the losing server.

B is false. Only the client's messages come from 0.0.0.0; the two server messages come from the server's own address, 192.168.10.2 in this lesson's network. Reading "all four messages" as "both directions" is the error.

Q6 MCQ Original

A router receives a datagram addressed to 224.0.0.9 whose UDP port is closed on every host that receives it. How many ICMP destination-unreachable messages are sent?

(A) One per host that receives it
(B) One, from the router
(C) One per interface
(D) None

Answer: D, none. 224.0.0.9 is a multicast address, and an ICMP error must not be sent about a datagram whose destination is a broadcast or multicast address.

Why the others fail. A describes exactly the message storm the rule prevents. B invents a router responsibility that the rule removes. C is a real Ethernet fact about hubs and switches, irrelevant to ICMP.

Q7 NAT Original

A traceroute reaches its target in 7 hops. Counting only the ICMP messages the tool depends on, and assuming the UDP variant, how many ICMP messages are received by the source?

Answer: 7. Six routers each return time exceeded, type 11 code 0, and the destination returns destination unreachable, type 3 code 3. Six plus one is seven.

The trap. The count equals the hop count only because the last message is also an ICMP message. A tool that printed nothing for a hop — because the report was filtered — would still have sent seven probes.

Q8 MCQ Original

Which statement about the identifiers is correct?

(A) ARP is identified by IP protocol number 1.
(B) DHCP is identified by EtherType 0x0806.
(C) ICMP is identified by IP protocol number 1.
(D) ICMP is identified by UDP port 1.

Answer: C. ICMP datagrams carry protocol number 1 in the IPv4 header.

A swaps ARP with ICMP: ARP has no IP header at all, so it cannot have a protocol number. B swaps ARP's EtherType onto DHCP, which is a UDP application with ports 67 and 68. D is the classic port confusion: ICMP has no ports.

The distinction being tested: three protocols, three different headers, three different places to look.

Revision sheet

Everything needed to answer a question on this topic, in the order it would be needed. The numbers are the ones this page computes at load.

The three gaps and their fillers

  • No hardware address for a known IPv4 address: ARP, EtherType 0x0806, 28 octets, request broadcast, reply unicast.
  • No IPv4 address at all: DHCP, UDP 68 → 67, 236 fixed octets, four messages, two client broadcasts.
  • A datagram failed: ICMP, IP protocol 1, 8-octet header, five suppression rules.

Numbers to carry in

ARP 8 + 20 = 28; 14 + 28 = 42; pad 18; 42 + 18 + 4 = 64

DHCP 236 + 4 = 240; 300 minimum; 236 + 312 = 548; + 28 = 576

T1 = 0.5 × lease; T2 = 0.875 × lease; T1 < T2 < expiry

ICMP 20 + 8 = 28 octets quoted; 5 error types; 6 query types

Types and codes worth knowing

0 echo reply · 3 destination unreachable · 4 source quench · 5 redirect · 8 echo request · 11 time exceeded · 12 parameter problem · 13/14 timestamp.

Codes that decide questions: type 3 code 0 network unreachable, code 3 port unreachable, code 4 fragmentation needed with don't-fragment set. Type 11 code 0 TTL expired in transit, code 1 reassembly timed out.

These code assignments are the standard ones from RFC 792 and RFC 1122. The type numbers were re-read in RFC 792 during this run; the individual codes were not re-read in full, so treat them as standard knowledge rather than as a quoted passage.

The five suppression rules, one line each

1. No error about an ICMP error.

2. No error about a broadcast or multicast IP destination.

3. No error about a link-layer broadcast.

4. No error about a fragment other than the first.

5. No error when the source is not one single host.

Decision procedure for an unfamiliar scenario

  1. What is missing: a hardware address, an IPv4 address, or a report? That names the protocol.
  2. If ARP: apply the prefix. Inside, the target is the destination; outside, it is the gateway.
  3. If DHCP: is the client on the server's link? If not, a relay is required and giaddr is set.
  4. If ICMP: run the five rules before counting, and read the code as well as the type.
  5. Name the identifier: EtherType, protocol number or port pair. Never the wrong one.

Four traps, one line each

1. ICMP has no ports; 1 is a protocol number.

2. ARP never crosses a router, so remote destinations resolve to the gateway.

3. Routers drop broadcasts, so DHCP across subnets needs a relay.

4. T1 starts renewal, T2 starts rebinding, and neither is the expiry.

Supports: protocol number 1; the summary of message types 0, 3, 4, 5, 8, 11, 12, 13, 14, 15 and 16; that no ICMP messages are sent about ICMP messages and that they concern fragment zero; that an error quotes the internet header and 64 bits of the original data; and the statement that delivery and report are not guaranteed.

RFC 1122, Requirements for Internet Hosts, §3.2.2. Supports: the split of ICMP messages into error and query classes; the five conditions under which an error message must not be sent; and the precedence of those restrictions over other requirements.
