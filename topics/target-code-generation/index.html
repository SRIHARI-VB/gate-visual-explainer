Topic and objective

TOPIC: Target code generation — the three decisions between intermediate code and machine code. Choosing an instruction for each part of a DAG and pricing the choice; deciding how many registers a computation needs, by the Sethi-Ullman numbering and by exact search; building an interference graph from liveness, colouring it, proving the colour count optimal with a clique, assigning registers and spilling when there are too few; and cleaning up locally with peephole rules. The two previous-year questions that sit here are GATE CSE 2013 Q49 (minimum registers for a code segment, keyed 4) and GATE CSE 2017 Set 1 Q52 (minimum registers for an expression tree, keyed 2).

LEARNING OBJECTIVE: Given a basic block, build its DAG and say how many instructions two different machines need. Given an expression, compute the Sethi-Ullman label and then decide whether it is the answer or an over-count. Given a block with control flow, compute live-in and live-out at every statement, build the interference graph, colour it, name its largest clique, and say whether the colour count is proved minimal. Given a k smaller than that count, choose a spill set and justify it. Given a few instructions, decide whether a peephole rewrite preserves behaviour, and say which condition it needs.

I read the topic as three decisions, three counts. Instruction selection is counted in instructions, register allocation in registers, and peephole optimisation in instructions removed — and the three counts are independent, which is why one question can have two defensible-looking answers. Every number on this page is computed at load time and printed on the canvas.

Prerequisites

  • Intermediate code generation — three-address code, temporaries, quadruples. Every instruction list here is in that form.
  • Data-flow analysis — the fixed-point idea and the liveness equations used in scene 5.
  • Local optimisation and basic blocks — the DAG of a basic block and the local rewrites.
  • Runtime environments — where a variable lives when it is not in a register.
  • Comfort with sets and with the idea of a graph colouring, both from Discrete Mathematics.

What you should be able to do afterwards

Count instructions from a DAG for a named machine; count registers from a tree, and say when the formula is exact; compute liveness on a block with a branch; draw the interference graph and defend every edge; colour it, and prove the number with a clique; pick a spill set and say what it costs; and reject a peephole rewrite whose condition is missing.

Level 1 — intuition: three questions, in order

Think of a builder who has a drawing and must produce a real wall. The drawing says what shape the wall is; the builder decides which bricks to use (instruction selection), which hands hold what while the mortar sets (register allocation), and which offcuts to throw away at the end (peephole optimisation). The drawing never changes. Only the three decisions do.

Educational interpretation The analogy stops here: bricks have no liveness, and a register holding a dead value can be reused, which is the whole subject.

Level 2 — the DAG of a basic block

A basic block is a straight-line sequence with one entry and one exit. Its DAG has a leaf for each variable read, an internal node for each distinct operator applied to two values, and an edge from an operand to the operator that uses it. Two statements with the same operator and the same two operands land on the same node.

For the block used in this lesson — t1 = a*b; t2 = c*d; t3 = t1+t2; t4 = a*b; t5 = t4-t2 — counting the statements gives 5 operators and 6 variable reads. Counting the DAG gives 4 operators and 4 leaves, because the second a*b is the first one.

Mathematical derivation The merge is sound only inside one block: outside it, a branch may have changed a or b.

Level 2 — instruction selection and its price list

Selection is a covering problem: each machine instruction covers one node of the DAG plus some of the loads its operands need. On a load-store machine every operand must sit in a register, so a load covers one leaf. On an accumulator machine an operand may be read from memory, so one instruction covers a node and an operand.

The two coverings of this lesson's DAG: 8 instructions (4 loads, 4 arithmetic) peaking at 3 registers, or 12 instructions (3 per operator node) at 1 register.

Mathematical derivation 4 loads + 4 operations = 8; 4 operator nodes × 3 instructions = 12. Both lists are executed by the page.

Level 2 — liveness and interference

A variable is live at a point if some path from that point reads it before writing it. Liveness is computed backwards: live-in(s) = use(s) ∪ (live-out(s) − def(s)), iterated over the control-flow graph until nothing changes. Two variables interfere when some point has both live; then they cannot share a register.

The interference graph has one node per variable and one edge per interfering pair. Colouring it with k colours assigns k registers, and the largest clique is a lower bound on the colours needed.

Mathematical derivation A clique of size k forces k distinct registers, because every pair in it is live together at some point.

Level 2 — Sethi-Ullman numbering

Label each leaf 1. For an internal node with child labels l and r, the label is max(l, r) when they differ, and l + 1 when they are equal. The label of the root is the number of registers the tree needs when every leaf must occupy a register and the instruction cannot write into a register that already holds an operand.

For (a-1)*(((b+c)/3)+d) the labels run 1, 1, 2 on the left, 1, 1, 2, 1, 2, 1, 2 on the right, and 3 at the root — because the two children of the root both carry 2.

Mathematical derivation Equal labels mean one result must be held while the other subtree is computed, which is what costs the extra register.

Level 4 — the worked example, and the number that differs

Run the formula on that expression and you get 3. Run an exhaustive search over every order in which the tree can be evaluated, on a machine that allows immediates and lets an instruction write into a register holding an operand, and you get 2. The search is not disagreeing with the formula: the formula charges the constants 1 and 3 a register each, and this machine does not need to.

Label the constant leaves 0 instead of 1 and the formula returns 2 as well. The paper — GATE CSE 2017 Set 1 Q52 — keys 2.

Mathematical derivation The eight-instruction sequence in the Examples tab uses two registers at every point, and one register is impossible because the division needs both an operand and the immediate.

Level 5 — spilling

When the machine has fewer registers than the graph needs colours, some variable must be spilled: stored after each definition and reloaded before each use. Spilling removes that node from the graph, which is an approximation — the real live range breaks into small pieces — and it is the standard one.

The page tries all 63 non-empty spill sets on the 2013 block and keeps the cheapest that leaves a 3-colourable graph: spill d, at 1 reload plus 2 stores.

Mathematical derivation Dropping b and x instead leaves the clique {a, c, d, e} intact, so the graph still needs 4 colours and the spill bought nothing.

Level 6 — peephole rules carry conditions

A peephole pass slides a small window over the generated code and rewrites short patterns. Five rules are used here, each with a condition: a load of the location just stored to (nothing writes the register in between); adding zero or multiplying by one; a jump to the very next label; and a store overwritten by another store to the same location (no read of that location in between).

Applied to an eleven-instruction list, each rule fires once and six instructions remain. Both lists are executed for all 25 input pairs from 0 to 4, and they agree on memory and on both registers.

Educational interpretation Twenty-five input pairs are evidence, not proof; the argument that the rewrites are sound in general is the condition attached to each rule.

Worked examples, with every number computed

Each example below is executed by the page: the two instruction selections are run on a small machine, the register counts come from an exhaustive search over evaluation orders, and the liveness, interference and colouring come from the block itself rather than from a worked solution.

1. A block, its DAG, and two coverings

Block: t1 = a*b; t2 = c*d; t3 = t1+t2; t4 = a*b; t5 = t4-t2. As a tree it needs 5 operators and 6 variable reads — 11 instructions on a load-store machine. As a DAG it needs 4 operators and 4 leaves — 8.

Load-store selection (8 instructions, 3 registers at the peak):

LOAD R1, a · LOAD R2, b · MUL R1, R1, R2 · LOAD R2, c · LOAD R3, d · MUL R2, R2, R3 · ADD R3, R1, R2 · SUB R1, R1, R2

With a, b, c, d = 3, 5, 7, 2 the machine ends with R3 = 29 (t3) and R1 = 1 (t5). With 1, 0, −2, 6 it ends with R1 = 12.

The accumulator covering of the same DAG takes 3 instructions per operator node — 12 — and one register. Both were executed; both agree.

2. The 2017 expression, two ways

For (a-1)*(((b+c)/3)+d) the Sethi-Ullman label is 3; the exact search with immediates returns 2; the label with constants counted as 0 is also 2. The two constants are the entire difference.

Two registers, no spill:

LOAD R1, b · LOAD R2, c · ADD R1, R1, R2 · DIV R1, R1, #3 · LOAD R2, d · ADD R1, R1, R2 · LOAD R2, a · SUB R2, R2, #1 · MUL R1, R2, R1

One register is impossible: the division needs the value of (b+c) and the immediate 3 in play at the same moment, and arithmetic cannot take a memory operand.

On trees with no constants the search returns the label exactly: 4 for ((a+b)*(c+d))+((e+f)*(g+h)), 3 for (a-b)-(c*d).

3. Liveness on the 2013 block

Live-in sets, computed backwards to a fixed point:

S1 c=a+b {a,b} · S2 d=c*a {a,c} · S3 e=c+a {a,c,d} · S4 x=c*c {a,c,d,e} · S5 if(x>a) {a,d,e,x} · S6 y=a*a {a} · S7 goto {—} · S8 d=d*d {d,e} · S9 e=e*e {e} · S10 {—}

The largest set is 4, at the if: the else branch reads d and e, the then branch reads a, and the test reads x and a. y appears nowhere, because it is written and never read.

Four live variables is a lower bound on registers, and here it is met — which the colouring has to show, not assume.

4. The interference graph and its colouring

Ten edges: a-b, a-c, a-d, a-e, a-x, c-d, c-e, d-e, d-x, e-x. Degrees: a 5, d 4, e 4, c 3, x 3, b 1.

Greedy colouring by decreasing degree gives 4 colours: R1 = {a}, R2 = {d, b}, R3 = {e}, R4 = {c, x}. No edge joins two nodes of one colour, so the assignment is valid.

The clique {a, c, d, e} has 4 nodes all joined, so 3 colours is impossible, and the exhaustive search over all 729 three-colourings finds none. Colour count and clique size meet at 4, so 4 registers is optimal.

That meeting is a fact about this graph, not a theorem. Greedy colouring can exceed the chromatic number on other graphs.

5. Three registers instead of four

The graph is not 3-colourable, so one variable must spill. Of the 63 non-empty spill sets, the cheapest that leaves a 3-colourable graph is {d}, at cost 3: one reload (its single use, in d = d*d) and two stores (its two definitions, in d = c*a and in d = d*d).

Dropping b and x instead leaves {a, c, d, e} intact, so the graph still needs 4 colours. A spill only helps if it breaks a clique.

Spill cost here is uses plus definitions — a simple model. Real allocators weight by loop depth, which this block does not have.

6. Peephole: eleven instructions to six

Before: LOAD R1,a · STORE R1,t · LOAD R1,t · ADD R1,R1,#0 · MUL R1,R1,#1 · STORE R1,b · JMP L1 · L1: · LOAD R2,c · STORE R2,b · STORE R1,b.

After: LOAD R1,a · STORE R1,t · STORE R1,b · L1: · LOAD R2,c · STORE R1,b — five rules, one instruction each, six left.

The two programs were executed for every pair of inputs from 0 to 4: 25 pairs, identical memory, identical registers. A second pass over the result removes nothing more, so the list is a fixed point.

Note what survives: the load of c into R2 is now dead, but no rule here removes a dead load whose register is never read. A later dead-code pass would.

Where the rules stop applying

Every claim on this page has a condition attached, and the conditions are what the exam tests. These are the boundary cases worth carrying into the paper.

Maximum live is not the minimum number of registers

Take the 2017 expression as three-address code: t1=b+c; t2=t1/3; t3=t2+d; t4=a-1; t5=t3*t4. On entry to the first statement, a, b, c, d are all live — four variables — and yet the computation needs only 2 registers.

The reason: a, b, c, d are source variables that live in memory. A register is only needed for values that must be held across instructions, and the only such values here are temporaries. Maximum live counts variables; the allocation counts values that must be in registers.

Mathematical derivation In the 2013 question every variable is assumed to be compiled into a register, which is exactly why maximum live is the answer there. Read that assumption before using the shortcut.

A colouring is an upper bound; a clique is a lower bound

Greedy colouring always produces a valid colouring, so its colour count is always achievable — an upper bound on the chromatic number. It is never, by itself, a proof that fewer colours are impossible.

A clique of size k proves k colours are necessary. When the two numbers meet, the answer is proved optimal. When they do not, you know only that the truth lies between them.

In this lesson's graph they meet at 4, and the page states that as a fact about this graph, not as a general rule.

The formula is exact only under its assumptions

Sethi-Ullman assumes (i) every leaf occupies a register and (ii) an instruction's result cannot overwrite one of its operands. On a machine with immediates, condition (i) fails for constant leaves and the label over-counts — 3 instead of 2 on the 2017 tree.

On a machine where results may overwrite operands, the label can also over-count. The exhaustive search in this page allows both, and it is what the 2017 answer follows.

Where the tree has no constants and instructions write into operands, the search and the label agree — checked on two trees here.

A peephole rule without its condition is wrong

Delete a LOAD R1, x after STORE R1, x and you are right only if nothing writes R1 in between. Delete a STORE R2, y that a later STORE R1, y overwrites and you are right only if nothing reads y in between. Delete a jump to the next label and you are right only if that label really is the next instruction.

Each of those conditions is a place where a question can plant the failure: one intervening instruction and the rewrite changes the program.

The five rules in this lesson are written with their conditions in the same sentence, on purpose.

What spilling does not model

Spilling a variable here removes its node from the graph. That is the textbook approximation: the real live range breaks into one small range per use, which often interferes with less than the original did.

The page reports the cheapest set under that approximation and says so. It does not claim the spilled program's register count, and it does not model loop-depth weighting, coalescing, or rematerialisation.

For a GATE question that fixes the code and asks for a count, the approximation is enough; for a compiler you would iterate spill, recolour, and repeat.

One block, not a program

The DAG is valid inside a single basic block. Across a branch, a variable may have been reassigned, so two syntactically identical computations are not the same value.

Liveness, by contrast, is a whole-program property: the live sets here are computed over the block's control-flow graph including the branch, which is why d and e interfere even though they never appear in the same statement.

A DAG of a whole program would need SSA form or value numbering with reaching definitions, which is a different lesson.

Seven beliefs that produce the wrong option

Each is stated as a learner might hold it, then corrected with a computed counterexample from this lesson.

“Minimum registers equals the maximum number of live variables.”

Sometimes. On the 2013 block the largest live set is 4 and the answer is 4, so the shortcut works. On the 2017 expression as three-address code, four variables are live at one point and two registers suffice, because those four live in memory.

Correction: maximum live is a lower bound on registers, and it is tight only when every live value must be in a register.

“The Sethi-Ullman number is the answer to any register question.”

It is the answer under its two assumptions. On (a-1)*(((b+c)/3)+d) it gives 3; the machine with immediates needs 2, and the paper keys 2.

Correction: ask what the question allows before quoting the formula, and label constant leaves 0 when immediates are allowed.

“Greedy colouring is the chromatic number.”

Greedy is a heuristic that always returns a valid colouring and can use more colours than necessary. Here it happens to reach 4, which equals the chromatic number, and the page says that is a coincidence on this graph.

Correction: to claim a minimum, produce a clique of that size, or run the exhaustive search for k−1.

“Two variables interfere if they appear in the same statement.”

Interference is about being live at the same point, not about sharing a line. d and e never appear in one statement and interfere anyway; t1 and t2 in the DAG appear in one statement and do interfere, but for the liveness reason.

Correction: draw an edge only when a program point has both live, and name that point.

“A DAG is an optimisation you apply after code generation.”

The DAG is the block with repeated computations merged, built before any instruction is chosen. In this lesson the DAG is built by operator lookup from the statements, so the merge is a fact about the block rather than a decision about the drawing.

Correction: build the DAG first, then select instructions from it; the instruction count is a property of the DAG plus the machine.

“Fewer instructions is always the better code.”

The load-store covering is 8 instructions at 3 registers; the accumulator covering is 12 at 1. Neither dominates. A machine with one register cannot run the first, and a machine with registers to spare runs it faster.

Correction: instruction count and register count pull in opposite directions; the machine's price list decides.

“Any peephole rewrite that shortens the code is safe.”

Each of the five rules needs a condition. Drop the condition — one intervening write to the register, one intervening read of the location — and the rewrite changes behaviour while still shortening the code.

Correction: state the condition with the rule; a rewrite without a condition is a guess.

Four question shapes, and the procedure for each

These shapes are described from the two verified questions below and from the general form of the area. No frequency is claimed and no paper is predicted.

Shape 1 — minimum registers for a code segment

The question gives a straight-line block with a branch and asks for the fewest registers that compile it without spilling, sometimes adding "do not apply any optimisation other than register allocation".

Procedure. (1) Write the control-flow graph. (2) Compute live-in and live-out for every statement, backwards, to a fixed point. (3) Take the largest live set — a lower bound. (4) Build the interference graph and colour it. (5) If the colour count equals the largest live set, that is the answer; otherwise the colour count is.

On the 2013 block: largest live set 4, chromatic number 4, answer 4.

Shape 2 — minimum registers for an expression

The question gives an expression, states the machine (load-store, operands from registers only), and asks for the fewest registers with no spill.

Procedure. (1) Draw the tree. (2) Label it by Sethi-Ullman, charging each constant a register only if the machine has no immediates. (3) Check whether an instruction may write into an operand register; if not, the label is the answer. (4) If the question allows immediates, the label with constants at 0 is the answer — and it is what an exhaustive search returns.

On the 2017 expression: label 3, machine with immediates 2, answer 2.

Shape 3 — what liveness is used for

A one-line MCQ asking which optimisation uses live variable analysis. The answer is register assignment, because liveness gives the live ranges and the interference graph.

Procedure. Eliminate the options that do not depend on which values are needed later: constant folding, strength reduction, and runtime call management do not.

GATE CSE 2025 Set 1 Q3 is in this shape; the keyed option is register assignment to variables.

Shape 4 — is this rewrite behaviour-preserving?

The question shows a short instruction sequence and a proposed local rewrite, and asks whether the result computes the same thing.

Procedure. Find the condition the rewrite depends on, then look for the instruction that breaks it: an intervening write to the register, an intervening read of the location, or a label that is not the next instruction. If the breaking instruction is present, the rewrite is not safe.

The page applies five rules to an eleven-instruction list and executes both versions; question 6 in the Practice tab is in this shape.

The two checks that come before any arithmetic

Check 1 — which count? Registers are physical; variables are names, some of which live in memory; instructions are lines of machine code. A question asking for "minimum registers" wants the chromatic number of the interference graph, or the largest live set when that is also the answer. A question asking for "minimum variables" or "minimum temporaries" wants a count of names, not of registers.

Check 2 — what is allowed? Spills allowed or not; code motion allowed or not; immediates allowed or not. Each one changes the answer: the 2013 block needs 4 with allocation alone and 3 with code motion as well, and the 2017 expression needs 3 without immediates and 2 with them.

Both numbers in each pair are defensible answers to different questions, which is why the wrong one is offered as an option.

NATGATE 2017 Set 1, Q52

Consider the expression (a−1) * (((b+c)/3) + d). Let X be the minimum number of registers required by an optimal code generation (without any register spill) algorithm for a load/store architecture, in which (i) only load and store instructions can have memory operands and (ii) arithmetic instructions can have only register or immediate operands. The value of X is ______.

Answer: 2

Load b and c, add, divide by the immediate 3, load d, add, load a, subtract the immediate 1, multiply. Two registers hold everything at every point, and no value spills.

Why 3 appears. That is the Sethi-Ullman label of the tree when the constants 1 and 3 are charged a register each. The architecture described allows immediates, so they are not.

Why 1 appears. One register cannot work: the division needs (b+c) and the immediate in play at once, and arithmetic cannot read a memory operand.

The page computes both numbers — label 3, exhaustive search 2 — and executes the two-register sequence.

MCQGATE 2013, Q49

The following code segment is executed on a processor which allows only register operands in its instructions. Each instruction can have at most two source operands and one destination operand. Assume that all variables are dead after this code segment.

c = a + b; d = c * a; e = c + a; x = c * c; if (x > a) { y = a * a; } else { d = d * d; e = e * e; }

What is the minimum number of registers needed in the instruction set architecture of the processor to compile this code segment without any spill to memory? Do not apply any optimization other than optimizing register allocation.

  1. 3
  2. 4
  3. 5
  4. 6

Answer: B — 4

The live sets peak at 4 on entry to the if, where a, d, e and x are all live. The interference graph has 10 edges, its largest clique is {a, c, d, e}, and the exhaustive search over all 729 three-colourings finds none — so 4 is both necessary and sufficient.

Why 3 appears. With code motion allowed as well, the block needs only 3. The question's last sentence forbids that, so 3 is the answer to a different question.

The page computes the live sets, the graph, the clique and the colouring, and reports the same 4.

MCQGATE 2025 Set 1, Q3

Which ONE of the following techniques used in compiler code optimization uses live variable analysis?

  1. Run-time function call management
  2. Register assignment to variables
  3. Strength reduction
  4. Constant folding

Answer: B — register assignment to variables

Liveness gives the live range of every variable, and two ranges that overlap become an edge in the interference graph. Colouring that graph is the assignment step.

Why the others fail. Call management is about frames and calling conventions; strength reduction replaces an expensive operation with a cheaper equivalent; constant folding evaluates constant expressions. None of them needs to know which values are still going to be read.

Question number follows the archive consulted; the year, set and keyed option are what this page relies on.

NATOriginal practice question

For the 2013 code segment above, the interference graph has one node per variable. How many edges does it have? (Six variables appear; fifteen pairs are possible.)

Answer: 10

The edges are a-b, a-c, a-d, a-e, a-x, c-d, c-e, d-e, d-x, e-x. y never appears, because it is written in the then branch and never read.

Why 15 appears. That is every pair of the six variables, which would be right only if all six were ever live together. Why 9 appears. That usually drops d-e, because the two never share a statement — but they are both live across the else branch, so the edge is real.

The page builds the graph from the live sets and checks every edge against a witness point, in both directions.

NATOriginal practice question

On a load-store machine with immediates, where an instruction may write its result into a register that already holds an operand, what is the minimum number of registers needed to evaluate a*b + (c − 1) with no spill?

Answer: 2

Load a and b, multiply into one of them; load c into the other and subtract the immediate 1; add. Two registers, four instructions plus two loads.

Why 3 appears. The Sethi-Ullman label of this tree is 3: the left child carries 2, the right child carries 2 (because c−1 is labelled 2 when the constant is charged a register), and equal labels add one. Labelling the constant 0 gives 2, which is what the machine needs.

The page's search returns 2 here and returns the label exactly on trees with no constants.

MSQOriginal practice question

Which of the following local rewrites are guaranteed to preserve the behaviour of the surrounding code? Assume no labels are involved unless stated.

  1. Deleting LOAD R1, x immediately after STORE R1, x.
  2. Deleting ADD R1, R1, #0.
  3. Deleting STORE R2, y when a later instruction STORE R1, y exists, with a LOAD R3, y between them.
  4. Deleting JMP L1 when L1: labels the instruction immediately after it.

Answer: A, B, D

A is safe because the register already holds exactly what was stored and nothing writes it in between. B is safe because adding zero changes nothing. D is safe because the jump goes where execution would fall through anyway.

Why C is not safe. The LOAD R3, y between the two stores reads the value the first store wrote. Delete the store and that load reads the old value of y. The condition the rule needs — no read of the location in between — is exactly what fails here.

This is the same condition the page's fifth rule carries, and the reason the rule is stated with it.

MCQOriginal practice question

A basic block has five statements and six variable reads. Its DAG has four operator nodes and four leaves. On a load-store machine, how many instructions does the DAG need, and how many would the block need without merging repeated computations?

  1. 8 with the DAG, 11 without
  2. 8 with the DAG, 12 without
  3. 9 with the DAG, 11 without
  4. 4 with the DAG, 5 without

Answer: A — 8 and 11

The DAG needs 4 loads (one per distinct leaf) plus 4 arithmetic instructions. Without merging, the block has 6 leaf occurrences and 5 operators: 6 loads plus 5 arithmetic, which is 11.

Why 12 appears. That counts 6 loads and 6 operators, which is one operator too many for five statements. Why 4 and 5 appear. Those are the DAG's operator count and the block's statement count, not instruction counts.

The page builds the DAG from the block and counts both coverings, then executes them.

Revision sheet

Definitions, procedures and traps, in the order you would use them in the exam.

Definitions in one line each

  • Basic block DAG — one node per distinct value in the block; repeated computations share a node.
  • Instruction selection — covering the DAG's nodes with machine instructions, priced by the machine.
  • Live at a point — some path from there reads the variable before writing it.
  • Interference — two variables live at one point, so they cannot share a register.
  • Colouring — assigning registers so that interfering variables differ.
  • Chromatic number — the fewest colours a valid colouring can use.
  • Clique — a set of nodes all pairwise adjacent; its size bounds the colours from below.
  • Spill — keeping a variable in memory, storing after each definition and reloading before each use.
  • Peephole rule — a short pattern replacement over a small window, valid only under its condition.

The four procedures

Liveness. live-in(s) = use(s) ∪ (live-out(s) − def(s)); live-out(s) = ∪ live-in(t) over successors. Iterate backwards until nothing changes.

Interference. For every program point, join every pair in its live set. An edge without a witness point is a bug.

Colouring. Greedy by decreasing degree gives a valid upper bound; exhaustive search or a clique gives the truth or a lower bound.

Sethi-Ullman. Leaves 1 (0 for constants if immediates are allowed); internal node max(l, r), plus one if l = r.

Numbers from this lesson to remember

  • Block of 5 statements: 11 instructions as a tree, 8 as a DAG.
  • Same DAG: 8 instructions at 3 registers, or 12 at 1.
  • 2017 expression: label 3, machine 2, keyed answer 2.
  • 2013 block: largest live set 4, chromatic number 4, keyed answer 4.
  • 2013 interference graph: 6 nodes, 10 edges, clique {a, c, d, e}.
  • Three registers: spill d at cost 3.
  • Peephole: 11 instructions to 6, five rules, 25 input pairs checked.

Five traps

  • Using maximum live as the answer when some variables live in memory.
  • Quoting the Sethi-Ullman label on a machine with immediates.
  • Reporting a greedy colour count as a proved minimum.
  • Drawing an interference edge from a shared statement rather than from a shared live point.
  • Applying a peephole rule whose condition has been broken by an intervening instruction.

Sixty-second self-test

1. Why does the DAG of five statements have four operator nodes? 2. Why is y absent from the interference graph? 3. What proves that 3 registers is impossible for the 2013 block? 4. Why does the 2017 expression need 2 rather than 3? 5. Which condition does the "delete the overwritten store" rule need?

Answers: the fourth statement repeats the first; it is written and never read; the clique {a, c, d, e}; the constants are immediates; that nothing reads the location between the two stores.

Limits of this lesson

The machine models are simplified: one memory model, no addressing modes beyond a scale of one, no loop-depth weighting in the spill cost, and no coalescing. The execution checks are finite: 25 input pairs for the peephole rules and one or two inputs for the selections. A finite grid is evidence, not proof.

The lesson does not claim that code generation is named in the syllabus, does not claim any marks weight, and does not claim that the greedy colouring is optimal in general — only that it is optimal on this graph, where the clique proves it.
