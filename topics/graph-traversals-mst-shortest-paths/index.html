Topic and objective

TOPIC: Graph algorithms — the two traversals (BFS and DFS), the two minimum-spanning-tree algorithms (Kruskal and Prim), and the shortest-path family (Dijkstra, Bellman-Ford, the DAG pass and Floyd-Warshall), with the properties that make each one correct and the one condition that breaks Dijkstra.

LEARNING OBJECTIVE: Given a graph question, decide in four steps which algorithm applies, execute it by hand without losing the state, and state the guarantee and the cost together. Trace BFS levels and DFS timestamps on a small graph; run Kruskal and Prim to the same total weight from different edge sets; count minimum spanning trees by collapsing forced edges into components; and say exactly why a negative edge makes Dijkstra report a wrong number rather than a slow one.

I read this topic as one lesson on the three graph-algorithm families together, because GATE's own syllabus line names them in one breath — "Graph traversals, minimum spanning trees, shortest paths" — and because the three are constantly confused with each other. The distinctions (a BFS tree is not a shortest-path tree, an MST is not a shortest-path tree, Dijkstra is not Bellman-Ford) are the exam content, so they belong on one page.

Prerequisites

Four published lessons carry the machinery this one uses:

  • Graphs: Connectivity and Structure — vertices, edges, degree, paths, cycles, connectedness, trees and spanning trees. Every definition here assumes that lesson.
  • Arrays, Stacks and Queues — BFS is a queue and DFS is a stack. The two traversals differ only in which one they use.
  • Trees, Binary Search Trees and Heaps — the heap that makes Prim and Dijkstra cost E log V instead of V².
  • Greedy Algorithms and Exchange Arguments — Kruskal, Prim and Dijkstra are all greedy, and the cut property is an exchange argument.

No new mathematics is needed beyond elementary arithmetic and one idea from the greedy lesson: an exchange, a single swap inside a solution that does not make it worse.

What you should be able to do afterwards

Answer any graph-algorithm question in this order: which question is being asked?, which condition does the graph satisfy?, which algorithm is legal, and what does it cost?

The most expensive mistake in this topic is treating the three families as interchangeable. A minimum spanning tree minimises a total, a shortest-path tree minimises each route, and a traversal minimises the number of edges — three objectives, three algorithms, and using one to answer another's question is wrong even when the number looks reasonable.

Level 1 — Intuition: three questions about one map

You already answer all three questions on a map. "Can I get from here to there?" is reachability — you trace roads and see whether a route exists at all. "Can I connect every town with the least total road length?" is the minimum spanning tree — you are not travelling, you are building. "What is the cheapest drive from my house to each town?" is the shortest path — now you are travelling, and the answer is different for each destination.

The building question and the travelling question look similar and are not. A road network that connects everything with the least total length can still force a long detour between two particular towns, because it was never optimising that.

Educational interpretation The road network is exact for both weighted questions and only an analogy for the traversals, where "distance" counts roads rather than kilometres. The shared shape — vertices, edges, a cost, a choice — is the part that transfers.

Level 2 — The formal definitions

A graph is a set of vertices V and a set of edges E, each edge joining two vertices. It is connected when a path exists between every pair, and acyclic when it contains no cycle.

A spanning tree of a connected graph on n vertices is a set of exactly n − 1 edges that is connected and acyclic. A minimum spanning tree (MST) is a spanning tree of smallest total edge weight.

For a source s, d(v) is the length of a shortest path from s to v, where length means the sum of edge weights (or the number of edges, when the graph is unweighted). A shortest-path tree is a spanning tree in which the tree path from s to every v is a shortest path.

Verified fact These are the standard definitions; they are developed in CLRS Chapters 22 (traversals), 23 (MST) and 24 (shortest paths), and in the NPTEL and university notes listed in the Sources tab. The two tree definitions are different, and the difference is the point of scene 11.

Level 3 — The picture that carries the mechanism

Draw the graph once, and let each algorithm draw a different tree on top of it. BFS draws a tree whose levels are distances in edges. DFS draws a tree that follows one branch to the end. Kruskal draws a forest that merges, Prim draws one tree that grows, and Dijkstra draws a tree whose root-paths are cheapest.

All five trees span the same graph, and four of them are different trees. Seeing them on the same vertex set is what stops the confusion: the algorithms are not competing answers to one question, they are answers to different questions.

The picture also shows what to check. A BFS tree's edges all go between adjacent levels; a DFS tree's non-tree edges all go to ancestors; an MST's edges are all light across some cut; a shortest-path tree's edges all satisfy d(v) = d(u) + w(u,v).

Level 4 — Worked example: BFS on eight vertices

Vertices A to H, ten edges: A-B, A-C, B-D, C-D, C-E, D-E, E-F, F-G, G-H, C-F. Start at A.

Queue A. Dequeue A: neighbours B and C are new, so both get distance 1, parent A. Dequeue B: neighbour D is new, distance 2, parent B. Dequeue C: neighbours D (already known), E (new, distance 2, parent C), F (new, distance 2, parent C). Dequeue D: C and E already known. Dequeue E: F known. Dequeue F: G new, distance 3. Dequeue G: H new, distance 4.

Order A B C D E F G H; distances A 0, B 1, C 1, D 2, E 2, F 2, G 3, H 4. Mathematical derivation The page runs BFS and, separately, a brute-force relaxation over all edges in every round; both produce the same eight numbers. That second computation is the check, because it never looks at a queue.

Level 5 — Boundaries: when each algorithm applies

Four conditions decide which algorithm is legal, and each one is a real boundary rather than a formality:

  • Weights or no weights. No weights: a traversal answers distance in edges. Weights: a traversal answers a question nobody asked.
  • Negative weights. Dijkstra requires all weights to be non-negative. One negative edge breaks the argument, not the running time.
  • One source or all pairs. Dijkstra, Bellman-Ford and the DAG pass are single-source. Floyd-Warshall is all-pairs, at cubic cost.
  • Acyclic or not. On a DAG one pass in topological order is enough and costs V + E; on a general graph it is not.

Drop a condition and the algorithm still runs, still prints numbers, and is simply no longer guaranteed to be right. That silent failure is the normal failure mode here, which is why every trace in this lesson is checked by a second, independent computation.

Level 6 — Edge cases that change the answer

Disconnected graph. BFS from one source reaches one component. Kruskal then produces a minimum spanning forest with fewer than n − 1 edges. A question that says "spanning tree" is telling you the graph is connected.

One vertex. A spanning tree has zero edges and weight zero. BFS finishes immediately; Dijkstra settles one vertex. Every formula with n − 1 in it still holds.

Ties in weights. Ties are what make several minimum trees exist. Kruskal and Prim then depend on their tie-break rule, and different rules give different edge sets with the same total.

Ties in Dijkstra. When two unsettled vertices have equal tentative distance, the extraction order is arbitrary and the parent array can differ, but the final distances cannot. GATE sometimes fixes the rule ("updated only when strictly shorter") to make one answer correct.

Self-loops and parallel edges. A self-loop is never in a spanning tree and never helps a shortest path with non-negative weights. A parallel edge keeps only the cheaper copy for both problems.

Level 7 — Two counterexamples you should be able to write from memory

A negative edge defeats Dijkstra. Vertices s, A, B, T. Edges s→A cost 1, s→B cost 2, B→A cost −2, A→T cost 1. Dijkstra settles A at 1, then B at 2, and never revisits A, so it reports T at 2. The true distance to A is 0 and to T is 1.

An MST is not a shortest-path tree. On the six-vertex graph of this lesson the minimum tree is A-B, B-C, B-D, D-F, E-F with total 24. Its route from A to E is A-B-D-F-E, costing 4 + 5 + 6 + 7 = 22, while the cheapest route in the graph is A-C-E at 13.

Mathematical derivation Both are computed on the page rather than quoted: the page runs Dijkstra on the negative instance and reports both arrays, and it runs Dijkstra on the six-vertex graph to find the 13 that the tree path misses. Both instances are small enough to check by hand in an exam, which is why they are the standard ones.

Level 8 — GATE application

Five question shapes appear, and they are answered by five different moves:

  • Trace it. "Give the order in which vertices are settled." The move is a table of rounds, and the answer is the extraction order, not the final array.
  • Count it. "How many distinct minimum spanning trees?" The move is to force the lightest edges, collapse into components, and multiply independent choices.
  • Bound it. "What is the tightest upper bound on the running time?" The move is to name the representation and the data structure, because both change the answer.
  • Classify it. "Which of these statements is true of every such graph?" The move is a small counterexample per false option.
  • Constrain it. "For which largest x is this edge on a shortest path?" The move is to compute the best route that avoids the edge and compare.

A sixth shape exists and is rarer: give a property and ask which algorithm it proves. There the answer is a name — cut property, cycle property, parenthesis property — and the words must be exact.

Level 9 — Consolidation

Four sentences carry the lesson. A traversal answers reachability and, when unweighted, distance in edges. An MST minimises one total for the whole graph and is proved by the cut property. A shortest-path tree minimises one route at a time and needs non-negative weights if it is computed by Dijkstra. Every algorithm's cost in this lesson is either V + E, E log V, VE or V³, and which one you get depends on the representation and the data structure, not on the algorithm's name alone.

Keep one comparison in your head: Kruskal and Prim must agree on the weight and may disagree on the edges; BFS and Dijkstra must agree on an unweighted graph and may disagree on a weighted one; an MST and a shortest-path tree may disagree on both.

Example 4 — The MST is not a shortest-path tree

Take Kruskal's tree on the six vertices: A-B, B-C, B-D, D-F, E-F. The only route from A to E inside that tree is A-B-D-F-E, costing 4 + 5 + 6 + 7 = 22.

The cheapest route in the whole graph is A-C-E, costing 4 + 9 = 13.

So the tree that minimises the total weight is 9 worse than optimal for this one pair. Mathematical derivation The page runs Dijkstra on the six-vertex graph to get the 13, and walks the tree to get the 22, so neither number is quoted. The lesson is that "minimum spanning" and "shortest path" are different objectives, not that one of them is wrong.

Example 7 — Counting MSTs: GATE CSE 2024, Set 2, Q49

Seven vertices a to g. Weights: a-b 1, a-f 1, c-d 1, d-e 1, a-g 2, b-g 2, c-g 2, d-g 2, e-g 2, f-g 2, b-c 3, f-e 3. The paper asks for the number of distinct minimum-weight spanning trees.

The four weight-1 edges are forced, and they join nothing to anything else: they form {a,b,f} and {c,d,e}. That leaves three components, so two more edges are needed, both at weight 2, one from g into each side. Three choices each side, independently: 3 × 3 = 9. Total weight 4 + 2 + 2 = 8.

Verified fact The instance, the question and the answer 9 come from the GATE CSE 2024 Set 2 paper (question 49), whose official key gives 9. Mathematical derivation The page re-derives it: Kruskal gives weight 8, and enumerating all 320 spanning trees of the 7-vertex graph finds exactly 9 at weight 8.

Example 8 — The largest x: GATE CSE 2016, Set 1, Q38

A 4-vertex weighted graph given as a matrix: W12 = 2, W13 = 8, W14 = 5, W23 = 5, W24 = 8, W34 = x. The paper asks for the largest integer x such that at least one shortest path between some pair of vertices contains the edge of weight x.

The edge of weight x joins vertices 3 and 4. It lies on a shortest path exactly when the direct edge is no worse than the best route that avoids it. Routes from 3 to 4 without that edge: 3-1-4 costs 13, 3-2-4 costs 13, 3-2-1-4 costs 5 + 2 + 5 = 12. So x ≤ 12, and at x = 12 the edge ties the alternative and is still on a shortest path.

Verified fact The instance and the answer 12 come from GATE CSE 2016 Set 1, question 38; the official key gives 12. Mathematical derivation The page computes the best avoiding route with Floyd-Warshall and then, for every x from 1 to 20, checks whether the direct edge ties the optimum — finding 12 as the largest.

Disconnected graphs and forests

BFS from one source reaches exactly one connected component; the vertices left at infinity are the ones no path reaches. Kruskal on a disconnected graph accepts fewer than n − 1 edges and produces a minimum spanning forest, one tree per component.

Dijkstra on a disconnected directed graph leaves unreachable vertices at infinity, and a question that asks for "the distance" of such a vertex expects infinity, not zero.

Equal weights, and what they break

Equal weights do not break correctness; they break uniqueness. Both MST algorithms remain correct and both return the minimum weight, but the edge set depends on the tie-break rule. A question that asks for the weight is well posed; one that asks for "the tree" may not be.

In Dijkstra, equal tentative distances make the extraction order arbitrary, so the parent array can differ between two correct runs while every distance agrees.

Negative weights, and the one case that is still fine

A negative edge breaks Dijkstra. A negative cycle breaks everything: shortest paths are not defined, because going round the cycle again is always cheaper. Bellman-Ford distinguishes the two cases by running one extra round — an improvement there means a reachable negative cycle.

Floyd-Warshall tolerates negative edges but not negative cycles, and a negative entry on its diagonal after the run is the signal that a negative cycle exists.

Self-loops, parallel edges, and zero weights

A self-loop is never in a spanning tree, because it closes a cycle of length one. A parallel edge contributes only its cheaper copy to both the MST and the shortest path. A zero-weight edge is legal for Dijkstra, which requires non-negative rather than positive weights, and it can put two vertices in the same BFS level if the graph is being treated as unweighted.

A zero-weight cycle is not a problem: it neither improves nor worsens any distance.

Small and degenerate inputs

With one vertex there are no edges: the spanning tree has weight zero, BFS finishes at once, and Dijkstra settles one vertex. With two vertices the MST is the single edge. Every formula of the form n − 1 or V + E still holds, which is why these cases are the fastest way to catch an off-by-one in a formula you half-remember.

With no edges at all, the number of spanning trees is one when there is a single vertex and zero otherwise.

The counting trap

In the 2024 instance, six edges of weight 2 leave the centre vertex. The naive count is "choose 2 of 6", which gives 15. Nine of those pairs do not span: two edges into the same side leave the other side attached to nothing, and two edges into one side close a cycle through g.

The correct move is to require that the chosen edges touch every component. Here that forces one edge per side, and the count becomes 3 × 3. The same discipline applies to every "how many MSTs" question: multiply only independent choices, and check that the result spans.

1. "A DFS tree is a shortest-path tree."

Wrong. On the eight-vertex graph of this lesson the DFS tree from A is seven levels deep, while the fewest-edges distance to the deepest vertex H is four. The DFS tree path to H uses seven edges where four suffice.

BFS produces a shortest-path tree on an unweighted graph. DFS produces a spanning tree with a nested timestamp structure and nothing more. GATE CSE 2025 Set 2 offered this exact claim as a statement to judge.

2. "Dijkstra works if there is no negative cycle."

Wrong. Dijkstra needs every edge to be non-negative, not merely every cycle. The four-vertex instance in Example 6 has no cycle at all and still defeats it: the answer reported for T is 2 where the truth is 1.

The condition for Bellman-Ford is "no negative cycle reachable from the source". The condition for Dijkstra is "no negative edge". The two conditions are not the same, and this is the most common confusion in the topic.

3. "A minimum spanning tree is unique exactly when the weights are distinct."

Half wrong — the implication runs one way. Distinct weights force a unique minimum tree. A unique minimum tree does not require distinct weights: the 4-vertex matrix instance with x = 12 has repeated weights and still exactly one minimum tree.

The safe statement is "distinct weights are sufficient for uniqueness, not necessary". The page checks the second half by counting minimum trees on that instance.

4. "Kruskal and Prim can give different answers."

Wrong about the weight, right about the edges. Both return a minimum spanning tree, so the total weight is the same number. Their edge sets can differ whenever there are ties, which is exactly what this lesson's six-vertex graph shows: Kruskal takes A-B, Prim takes A-C, both total 24.

So a question asking for the weight has one answer, and a question asking for the edges may have several correct answers.

5. "A BFS tree is a shortest-path tree on a weighted graph."

Wrong. BFS counts edges and ignores weights. On a weighted graph the vertex two edges away can be far cheaper than the vertex one edge away, and BFS will report the one-edge vertex as nearer.

On an unweighted graph — every edge the same cost — BFS and Dijkstra do agree, and that agreement is worth knowing: Dijkstra with a first-in-first-out queue is exactly BFS.

6. "A traversal is linear, so it is O(V)."

Wrong on both counts. On an adjacency list the cost is V + E, which is not linear in V alone when the graph is dense. On an adjacency matrix the cost is V², whatever the number of edges, because every vertex scans a whole row.

GATE CSE 2014 Set 1 asked precisely this for DFS on a matrix, and the answer is V². Name the representation before you name the cost.

Pattern 1 — Execute the algorithm and report a state

"In what order do the vertices get settled?" "Give the BFS order." "How many edges are accepted before the tree is complete?" The mark is for the state at a particular moment, so write the array or the queue at every step rather than only the final answer.

The trap is tie-breaking. When two keys are equal, the paper usually states the rule, or the question is designed so that any tie-break gives the same number. If neither holds, say which rule you used.

Pattern 2 — Count the minimum spanning trees

The standard move has three steps: find the edges that every minimum tree must contain (lightest across a cut, with no equal-weight alternative), collapse them into components, then multiply the number of independent ways to join the remaining components at the next weight up.

GATE CSE 2024 Set 2 used exactly this. The wrong answers are almost always "choose k of m", which ignores the requirement that the chosen edges span.

Pattern 3 — Judge a statement about every such graph

"Which of the following is true for every graph?" Each false option needs one small counterexample, and small means three or four vertices. The eight-vertex graph in this lesson refutes "a DFS tree is a shortest-path tree"; a four-vertex graph with one negative edge refutes "Dijkstra always works".

Keep four counterexamples ready: a negative edge for Dijkstra, a long chain for DFS depth, a tie for uniqueness, and a sparse graph on a matrix for complexity.

Pattern 4 — Cost with a named data structure

"Dijkstra's algorithm can be implemented using a binary heap with time complexity ___." The answer depends on the structure named, not on the algorithm. Binary heap: E log V. Array: V². On an unweighted graph with a queue: V + E.

GATE CSE 2005 and 2006 both asked versions of this for Dijkstra, and 2013 asked for Bellman-Ford on a complete graph, where VE becomes V³.

Pattern 5 — A constraint on one edge

"For which largest x does this edge lie on some shortest path?" The move is to compute the best route that avoids the edge, then compare. The edge is on a shortest path exactly when its weight does not exceed that avoiding route.

The subtlety is "at least one": equality counts, which is why the 2016 answer is 12 and not 11. A version that asked for "guaranteed to contain the edge" would answer 11, and that distinction is the whole question.

Pattern 6 — Structural properties of a traversal

"Which of these is true of every BFS tree / DFS tree?" The four facts worth memorising: BFS non-tree edges join vertices at levels differing by at most one; every DFS non-tree edge in an undirected graph is a back edge; DFS intervals nest or are disjoint; both find connected components of an undirected graph.

For directed graphs, add: DFS classifies edges into tree, back, forward and cross; a DAG has no back edges; a topological order is the reverse of finish-time order.

How to spend the two minutes

Read which family the question is in before computing anything: a total-weight question is an MST question, a per-destination question is a shortest-path question, and a reachability or level question is a traversal. Then check the graph's conditions — weights, signs, acyclicity, connectivity — because they decide which algorithm is legal. Only then start the table.

Most lost marks in this topic are spent executing a legal algorithm on a graph where it is illegal, or answering an MST question with a shortest-path number.

Q1 — Verified PYQ: GATE CSE 2024, Set 2, Q49 (NAT, 2 marks)

A 7-vertex graph has vertices a to g and edges a-b 1, a-f 1, c-d 1, d-e 1, a-g 2, b-g 2, c-g 2, d-g 2, e-g 2, f-g 2, b-c 3, f-e 3. The number of distinct minimum-weight spanning trees is ______.

Answer: 9. The four weight-1 edges are forced: no equal-or-lighter route joins their endpoints, so the cut property puts each in every minimum tree. They form two groups, {a,b,f} and {c,d,e}. Three components remain with g, so two weight-2 edges are needed, one from g into each group. Three choices per group, independently: 3 × 3 = 9. Total weight 4 + 2 + 2 = 8.

Traps. "Choose 2 of the 6 weight-2 edges" gives 15 and is wrong: most pairs fail to span. Choosing both edges from the same group closes a cycle through g. And including any weight-3 edge raises the total to 9, so those trees are not minimum.

Shortcut and its assumption. Multiply independent component-joining choices — valid only when the choices do not interact, which here they do not because each group is joined only to g.

Q2 — Verified PYQ: GATE CSE 2016, Set 1, Q38 (NAT, 2 marks)

A 4-vertex undirected weighted graph has W12 = 2, W13 = 8, W14 = 5, W23 = 5, W24 = 8, W34 = x. The largest possible integer value of x for which at least one shortest path between some pair of vertices contains the edge of weight x is ______.

Answer: 12. The edge of weight x joins vertices 3 and 4, so it is on a shortest path exactly when the direct edge is no longer than the best avoiding route. Avoiding routes from 3 to 4: 3-1-4 = 13, 3-2-4 = 13, 3-2-1-4 = 12. So the edge works for every x ≤ 12, and the largest integer is 12.

Trap. The phrase "at least one" makes equality count. At x = 12 the direct edge ties 3-2-1-4, so it is on a shortest path. Reading it as "the unique shortest path" gives 11, which is the trap answer.

Shortcut and its assumption. Compute the best route that avoids the edge and compare — valid because all weights here are positive, so any shortest path using the edge uses it directly between its endpoints.

Q3 — Verified PYQ: GATE CSE 2015, Set 1, Q45 (MCQ, 2 marks)

Let G be a simple undirected graph with source s, and let d(x) be the shortest distance in G from s to x. A BFS is run from s and T is the resulting BFS tree. If (u,v) is an edge of G not in T, which one of the following CANNOT be the value of d(u) − d(v)?

(A) −1    (B) 0    (C) 1    (D) 2

Answer: (D) 2. A non-tree edge joins vertices whose BFS levels differ by at most one, so the difference can be −1, 0 or 1 and never ±2 or more.

Why. Suppose the difference were 2, with u nearer. When u was dequeued, v was still undiscovered — otherwise v would have been discovered from an even nearer vertex and its distance would not exceed d(u) + 1. So v would have been discovered from u, making (u,v) a tree edge, contradicting that it is not in T.

Why the others are possible. Difference 0: two vertices at the same level joined by an edge, which happens here between D and E. Difference 1: an edge between adjacent levels that the search did not need, such as A-C. Difference −1 is the same case with the labels swapped, which is why the option is not −2.

Q4 — Verified PYQ: GATE CSE 2025, Set 1, Q33 (MCQ, 2 marks)

G is an undirected unweighted graph with 100 vertices. The maximum value of d(u,v) over all distinct pairs is 30. T is any BFS tree of G. Which one of the following is correct for every such G?

(A) height of T is exactly 15
(B) height of T is exactly 30
(C) height of T is at least 15
(D) height of T is at least 30

Answer: (C) at least 15. Let u and v be a pair at distance 30, and root the BFS at any vertex r. The tree distances satisfy d_T(r,u) = d(r,u) and d_T(r,v) = d(r,v), so 30 = d(u,v) ≤ d(u,r) + d(r,v) = d_T(r,u) + d_T(r,v). The larger of the two is at least 15, so the height is at least 15.

Why (A) and (B) fail. Rooting at u gives height exactly 30, so not 15. Rooting at a vertex midway on the longest path gives about 15, so not always 30. Both exact values are refuted by one graph with two different sources.

Why (D) fails. Rooting at a middle vertex of the diameter path gives a height near 15, which is below 30. Note the redundancy — the count of 100 vertices is never used, which is a hint that the answer must follow from the diameter alone.

Q5 — Original practice question (MCQ)

On the six-vertex graph of this lesson (A-B 4, A-C 4, B-C 2, B-D 5, C-D 5, C-E 9, D-E 9, D-F 6, E-F 7), Kruskal and Prim are both run. Which statement is necessarily true?

(A) they return the same edge set
(B) they return the same total weight, and may return different edge sets
(C) they may return different total weights, because Prim depends on the start vertex
(D) both return a shortest-path tree from the start vertex

Answer: (B). Both compute a minimum spanning tree, so the weight is the same number — 24 here. On this graph Kruskal takes A-B and Prim takes A-C, so the edge sets genuinely differ while the totals agree.

Why the others are wrong. (A) is refuted by the very instance in the question. (C) is false: the start vertex changes which minimum tree Prim finds, never its weight, because every minimum tree has the same weight. (D) is false: an MST is not a shortest-path tree, and here the tree path from A to E costs 22 against a shortest 13.

Edge case. If every edge weight were distinct, (A) would become true — the minimum tree would be unique. The question says "necessarily", and this graph has ties.

Q6 — Original practice question (MSQ)

Which of the following statements are TRUE?

(A) Dijkstra returns correct distances when every edge weight is non-negative
(B) Dijkstra can return a wrong distance on a directed acyclic graph
(C) BFS on a weighted graph returns a path with the fewest edges
(D) Floyd-Warshall requires all edge weights to be non-negative

Answer: (A), (B), (C).

(A) is the guarantee, and it is exactly what the non-negativity argument proves. (B) is true and is the point of Example 6: the four-vertex graph with a −2 edge is acyclic and Dijkstra reports 2 for T where the truth is 1. (C) is true: BFS minimises the number of edges, which is a different objective from the sum of weights.

(D) is false. Floyd-Warshall tolerates negative edges; it fails only on a reachable negative cycle, which shows up as a negative value on the diagonal. Trap: the condition "no negative cycle" is the condition for Bellman-Ford and Floyd-Warshall; the condition "no negative edge" is the condition for Dijkstra.

Q7 — Original practice question (NAT)

For the six-vertex graph of this lesson (A-B 4, A-C 4, B-C 2, B-D 5, C-D 5, C-E 9, D-E 9, D-F 6, E-F 7), how many distinct minimum spanning trees does it have?

Answer: 4. Any minimum tree must contain B-C (weight 2), one of A-B or A-C (weight 4), one of B-D or C-D (weight 5), D-F (6) and E-F (7), since those are the only ways to reach F and E cheaply. The two choices are independent, so 2 × 2 = 4, each with total 24.

Trap. The answer is not 1 even though only two weights repeat, and not 8: A-C is only usable together with B-D or C-D in the combinations that keep the tree connected. Enumerating all 55 spanning trees confirms that exactly four have weight 24.

Distinction worth holding. Four minimum trees exist and the minimum weight is unique. "Unique" applies to the weight, not to the tree, unless the weights are distinct.

Q8 — Original practice question (MCQ)

On the same six-vertex graph, T is a minimum spanning tree. Which statement about T is correct?

(A) T contains a shortest path from every vertex to every other
(B) T contains a shortest path from A to every other vertex, for every choice of T
(C) the path from A to E inside T can cost more than the cheapest route in the graph
(D) every edge of T is on some shortest path in the graph

Answer: (C). Kruskal's tree gives A-B-D-F-E at 22 for the A-to-E route, while A-C-E costs 13 in the graph. So a minimum tree can be badly suboptimal for one particular pair, which is exactly what "minimum total" does not promise.

Why the others are wrong. (A) and (B) claim a shortest-path guarantee that an MST does not have. (D) fails on the same edge set: the edge D-F at weight 6 lies on no shortest path from A, since A-C-E reaches E for 13 and A-B-D reaches D for 9 while A-C-D costs 9 too — the tree edge is not needed for either.

Edge case. On a graph that is itself a tree, (A) and (B) become true, because there is only one route between any two vertices. That is why this distinction is easy to miss: the counterexample needs a graph with cycles.

Definitions to be able to write

Spanning tree: n − 1 edges, connected, acyclic. Minimum spanning tree: a spanning tree of least total weight. Shortest-path tree: a spanning tree in which every root-path is a shortest path. Cut: a partition of the vertices into two non-empty parts. Back edge: a non-tree edge joining a vertex to its ancestor.

Discovery and finish time: the clock values when a vertex is first met and when its last neighbour has been dealt with.

The four properties

Cut property. The lightest edge across a cut is in some minimum tree; if its weight is unique, in every one.

Cycle property. The strictly heaviest edge of a cycle is in no minimum tree.

BFS level property. Every non-tree edge joins vertices whose levels differ by at most one.

Parenthesis property. For any two vertices, the DFS intervals either nest or are disjoint — never partly overlap.

Costs, with the condition attached

BFS, DFS V+E list | V² matrix
Kruskal E log E (sort dominates)
Prim E log V heap | V² array
Dijkstra E log V heap | V² array
Bellman-Ford V·E (V³ on a complete graph)
DAG pass V+E (after a topological sort)
Floyd-Warshall V³ (all pairs)

Conditions: Dijkstra needs no negative edge; Bellman-Ford and Floyd-Warshall need no reachable negative cycle; the DAG pass needs acyclicity.

The decision procedure

1. Is the question about reach, about a total, or about a route?
2. Are there weights?
3. Is any weight negative?
4. Is the graph acyclic, and is one source enough?

Reach with no weights → BFS or DFS. Total with weights → Kruskal or Prim. Route with non-negative weights → Dijkstra. Route with a negative edge → Bellman-Ford. Route on a DAG → topological pass. All pairs → Floyd-Warshall.

Four counterexamples to keep ready

Dijkstra fails: s→A 1, s→B 2, B→A −2, A→T 1. Reports 2 for T, truth 1.

DFS is not shortest: a chain of eight vertices where the target is four edges away and seven deep in the DFS tree.

MST is not shortest-path: the six-vertex graph, A to E costs 22 in the tree and 13 in the graph.

Unique without distinct weights: the 4-vertex matrix at x = 12 has repeated weights and one minimum tree.

Quick self-test, no looking

1. Why is a non-tree BFS edge never between levels two apart? 2. Give a graph where Prim and Kruskal differ, and say what stays equal. 3. State the cut property and its uniqueness condition. 4. Why does one negative edge break Dijkstra when a negative cycle does not break Bellman-Ford's detection? 5. What is the cost of DFS on an adjacency matrix, and why?
