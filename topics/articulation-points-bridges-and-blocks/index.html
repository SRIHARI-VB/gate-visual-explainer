Topic and objective

TOPIC: Articulation points, bridges and biconnected components in an undirected graph — the two single-failure questions, the one depth-first search that answers both, the strictness that separates them, the root rule, and the block decomposition with its counting identities.

LEARNING OBJECTIVE: Given an undirected graph, find every vertex whose deletion disconnects it and every edge whose deletion disconnects it, by running one depth-first search and computing the discovery time $$disc$$ and the low-link value $$low$$ of each vertex. State and use the two tests — $$low[v] \ge disc[u]$$ for a vertex, $$low[v] > disc[u]$$ for an edge — and say in words why one is weak and the other strict. Apply the root rule instead of the vertex test at the root of the search. Pop the edge stack at every tree edge that satisfies the weak test to obtain the biconnected components, build the block-cut tree from them, and read the counts off it.

GATE RELEVANCE: Class B — Section 5 of the syllabus names “Graph traversals, minimum spanning trees, shortest paths”. Neither “articulation point” nor “biconnected component” is syllabus wording; they are the standard harder questions asked of the named traversal, and two previous-year papers carry them (2021 Set 1, 2015 Set 2). The page says this rather than implying the words are in the syllabus.

PREREQUISITES: what a connected graph, a path and a simple cycle are (Connectivity); how depth-first search runs on an undirected graph, and what its tree is (Graph traversals). A stack helps for the block algorithm but is not required to read the lesson. No probability, no calculus, no directed graphs.

VISUALIZATION PLAN: twelve scenes on one drawn graph of twelve vertices and fifteen edges, searched from a leaf so that the root rule has to be faced. First the two failure questions, because a vertex cut and an edge cut are different objects. Then the definitions by deletion. I read this topic as the two cuts and the block decomposition that one search computes, not as a general course in connectivity. The neighbouring lessons own connectivity, spanning trees and the directed analogue; this one owns the undirected cuts.

Prerequisites, precisely

Must already be comfortable with:

  • A connected component is a maximal set of vertices joined by paths; the count is what every definition here measures.
  • Depth-first search goes as deep as it can, then backs up; the edges it uses form a tree, and every vertex except the root has exactly one parent.
  • A simple cycle is a closed walk with no repeated vertex; a triangle is the smallest one.
  • A tree on $$n$$ vertices has $$n-1$$ edges and exactly one path between any two vertices.

Helpful, not required: having seen a stack used to unwind a recursion, since the block algorithm is one line of bookkeeping on top of the search.

Approximate learning time: 45–60 minutes with the animation, or 12 minutes for the Revision tab alone. The figure is an estimate, not a measurement.

The five ideas

  1. Two different questions. A cut vertex survives in no form; a cut edge leaves both its endpoints alive. That difference is why the tests differ by one symbol.
  2. One number per vertex decides everything. $$low[v]$$ is the smallest discovery time reachable from $$v$$'s subtree by climbing one back edge.
  3. Weak for vertices, strict for edges. $$low[v] \ge disc[u]$$ makes $$u$$ a cut vertex; $$low[v] > disc[u]$$ makes the edge a bridge. Equality means the escape route returns to $$u$$ itself.
  4. The root is not like the others. It is a cut vertex exactly when it has two or more children, and the vertex test would wrongly flag a root with one child.
  5. Blocks are what the edges fall into. Popping the edge stack at every weak tree edge partitions the edge set; the blocks and the cut vertices form a tree.

Intuition: a network that must survive one failure

A road network, and a planner who has to answer two questions. If one junction closes, does the map still let every town reach every other? If one road closes, same question. Both questions are about a single failure, and both answers are about the same thing: how many pieces is the map in afterwards.

A junction whose closure splits the map is an articulation point, or cut vertex. A road whose closure splits the map is a bridge, or cut edge. The two are not the same object and are not detected by the same test, and the whole lesson turns on that difference.

The pieces that remain are what a repair crew would rebuild separately. Group the roads so that two roads are together exactly when they lie on a common loop; each group is a biconnected component, and a bridge is a group of one road.

Educational interpretation The analogy is exact about failure and silent about cost: nothing here is weighted, and every algorithm in the lesson is linear in vertices plus edges. A question that gives weights is not asking this.

Formal definition

Let $$G = (V, E)$$ be an undirected graph, and write $$c(G)$$ for the number of connected components of $$G$$.

$$u \text{ is an articulation point} \iff c(G - u) > c(G)$$

Read: deleting the vertex $$u$$ and every edge touching it raises the number of pieces the graph falls into. The same definition works for a disconnected graph, because both sides count every piece.

$$e \text{ is a bridge} \iff c(G - e) > c(G)$$

Read: deleting only the edge $$e$$, keeping both of its endpoints, raises the number of pieces.

A biconnected component, or block, is a maximal set of edges such that any two edges in the set lie on a common simple cycle.

Verified fact These are the definitions in the standard textbook treatment (Cormen, Leiserson, Rivest and Stein, chapter 22, problem 22-2) and in the standard competitive-programming reference for the two algorithms. The block definition is the edge version, and the next card shows what follows from it.

Derivation 1 — blocks partition the edges, and every bridge is a block

Take the relation on edges: $$e \sim f$$ when $$e = f$$ or when $$e$$ and $$f$$ lie on a common simple cycle. It is reflexive by the first clause and symmetric by its wording. It is transitive because two cycles sharing an edge can be spliced into one cycle containing all their edges.

So the relation splits the edge set into classes, and each class is exactly one block. Hence:

$$\text{blocks are disjoint, and } \sum_{B} |E_B| = |E|$$

Read: every edge belongs to exactly one block, so the block sizes add up to the number of edges.

An edge on no cycle is a class of its own. Such an edge cannot be avoided when travelling between its ends, which is exactly the definition of a bridge. So every bridge is a block of one edge, and every block of more than one edge is free of bridges.

Derivation Checked on the page: on all 1,024 undirected graphs with five vertices, the blocks computed by the search and the blocks computed from this relation by brute force are the same partition, with zero disagreements.

Derivation 2 — an undirected search has no cross edges

Run a depth-first search and give every vertex a discovery time. Take any edge $$\{u, v\}$$ and suppose $$u$$ was discovered first. When the search examined $$\{u, v\}$$ it either found $$v$$ unvisited — and then $$\{u, v\}$$ is a tree edge — or found $$v$$ already discovered, which can only happen after $$u$$ was entered, so $$v$$ is a descendant of $$u$$ and the edge climbs back up the tree.

The case that cannot happen is the one where $$v$$ sits in a different branch of the tree: had it been so, the search would have crossed that edge while standing at $$u$$, and $$v$$ would have become a child of $$u$$. So:

$$\text{undirected: every edge is a tree edge or a back edge}$$

Read: forward edges and cross edges exist only in directed graphs. In an undirected graph there is no third kind.

Derivation On the drawn graph the search produces 11 tree edges and 4 back edges, and 11 + 4 = 15 is every edge. The page classifies all fifteen and asserts that none is of a third kind.

Derivation 3 — the low-link value, and why one number is enough

Every way out of the subtree rooted at $$v$$ is a tree edge going down, which stays inside the subtree, or a back edge going up. A back edge from any vertex of the subtree to an ancestor of $$v$$ is therefore the only escape. Record the earliest such ancestor:

$$low[v] = \min\Bigl(\, disc[v],\ \min_{v \to w \text{ back}} disc[w],\ \min_{c \text{ child of } v} low[c] \,\Bigr)$$

Read: the smallest discovery time that $$v$$ or anything below it can climb back to, using at most one back edge. Computed bottom-up, in one pass.

Then $$low[v] \ge disc[u]$$ says exactly: nothing in $$v$$'s subtree climbs above $$u$$. And $$low[v] > disc[u]$$ says something stronger: nothing in the subtree climbs as far as $$u$$ itself.

Derivation The two numbers are computed for all twelve vertices of the drawn graph and reported on the Animation and Examples tabs; each is checked against a search of the subtree that climbs every back edge directly.

Derivation 4 — the two tests, and the one symbol between them

Let $$u$$ be a non-root vertex with child $$v$$ in the search tree.

$$low[v] \ge disc[u] \;\Longrightarrow\; u \text{ is an articulation point}$$

Deleting $$u$$ removes $$u$$ and every edge at it, including any back edge that ended at $$u$$. The subtree of $$v$$ then has no way up, so it is sealed off: the graph splits.

$$low[v] > disc[u] \;\Longrightarrow\; \{u, v\} \text{ is a bridge}$$

Deleting the edge keeps $$u$$. If the subtree can climb back to $$u$$ — the equality case — then $$u$$ still connects it, so the edge was not needed.

That is the whole difference: the vertex survives an edge deletion, and does not survive a vertex deletion. Equality is precisely the case where the escape route ends at $$u$$.

Derivation Both tests are compared with brute force on every undirected graph with up to five vertices (1,099 graphs) and on 2,000 seeded random graphs with six to eight vertices, with zero disagreements; the smallest graph on which each wrong variant fails is found by the same search and reported on the Misconceptions tab.

Derivation 5 — the root rule

The vertex test cannot be applied at the root, because the root has no parent and no ancestor to be sealed off from. Ask the question directly instead: removing the root leaves one piece per child subtree, since no edge can join two of them — had one existed, the second subtree would have been reached from the first.

$$\text{root is an articulation point} \iff \text{it has at least two children}$$

Read: one child means everything hangs off the root in a single piece, so deleting the root leaves that piece intact and the graph connected.

A root with one child still satisfies $$low[\text{child}] \ge disc[\text{root}]$$, because the child cannot climb above the root — there is nothing above it. So the vertex test applied at the root answers yes for every root of every graph. The rule is not a refinement of the test; it replaces it.

Derivation Checked over every graph with up to five vertices, searched from every possible start vertex, and over 2,000 seeded random graphs with six to eight vertices: the rule agrees with brute force everywhere, and a leaf of the search tree is never a cut vertex.

Derivation 6 — blocks from an edge stack

Push every edge onto a stack as the search traverses it. When the search finishes a child $$v$$ of $$u$$ and finds $$low[v] \ge disc[u]$$, pop edges until the edge $$\{u, v\}$$ comes off: the popped set is one block.

Why one block and not part of one: the edges of a block are exactly those pushed after the last moment the subtree could climb above $$u$$, so the pop boundary falls exactly between blocks. Why every edge is popped exactly once: every edge is pushed exactly once, and every push is eventually popped, because the root's last child always satisfies the weak test.

$$\#\text{blocks} = \#\{\text{tree edges } (u,v) : low[v] \ge disc[u]\}$$

Read: count the tree edges that satisfy the weak test; that is the number of blocks. Back edges never create a block on their own — they join one.

Derivation The count identity is checked on every graph with up to five vertices and on the 2,000 random graphs, and the partition itself against the common-cycle definition on all 1,024 five-vertex graphs: no disagreement.

A single edge: a bridge, but no cut vertex

Two vertices joined by one edge. The edge is a bridge — delete it and the graph falls from one piece to two. Neither vertex is a cut vertex — delete either and one vertex remains, which is still one piece.

So “every bridge has a cut vertex at one end” is false, and this is the smallest graph that shows it. It is also the smallest graph where the root rule changes the answer, and the smallest graph that is a single block while having no cycle.

Verified fact All three statements are the output of the page’s search on two vertices and one edge, and the first failure found when the search runs over graphs in order of size.

A tree: every edge is a bridge

Between any two vertices of a tree there is exactly one path, so no edge lies on a cycle, so every edge is a bridge. The cut vertices are exactly the vertices of degree at least two: a leaf’s removal takes nothing away from the rest.

$$\text{tree on } n \ge 2: \quad n - 1 \text{ bridges}, \quad \#\{v : \deg v \ge 2\} \text{ cut vertices}$$

Read: a path on ten vertices has nine bridges and eight cut vertices; a star on ten vertices has nine bridges and one cut vertex.

Verified fact Checked on all 1,441 labelled trees with two to six vertices: no tree disagreed with either count.

No bridge, yet a cut vertex

Two triangles sharing a single vertex — five vertices, six edges. Delete any edge and the graph stays connected, so there is no bridge. Delete the shared vertex and the graph falls into two pieces, so it is a cut vertex.

This is the smallest such graph, and it is why the two questions have to be asked separately: a graph can be robust against one kind of failure and fragile against the other.

Verified fact Found by the page’s search over all graphs in order of size: five vertices and six edges is the first with zero bridges and at least one cut vertex.

A disconnected graph

Both definitions compare component counts, so they read correctly on a disconnected graph: a vertex is a cut vertex when deleting it raises the count, which can only happen inside its own component. Run the search from every unvisited vertex in turn and each component is handled on its own; a component’s root obeys the root rule with its own children.

A vertex with no edges at all is not a cut vertex, and under the edge definition it is not a block either, because a block is a set of edges. That is a definitional choice, and the next card is where it bites.

Derivation The exhaustive checks include disconnected graphs: every graph with up to five vertices, most of them disconnected, agrees with brute force.

Two definitions of “biconnected component”

This lesson uses the edge definition: a maximal set of edges any two of which lie on a common simple cycle. Under it, blocks partition the edges, a bridge is a block of one edge, and an isolated vertex is no block at all.

Many textbooks instead say “a maximal 2-vertex-connected subgraph”, meaning a maximal subgraph that stays connected when any single vertex is deleted, and usually requiring at least three vertices. Under that reading a bridge is not a block, and the block count is smaller by exactly the number of bridges.

On the drawn graph the two counts are 7 and 3: seven blocks by the edge definition, and the three cyclic pieces {A,B,C}, {D,E,F,L}, {G,H,I} by the subgraph definition.

Community observation Public discussions of this topic disagree on the count for exactly this reason, so a question that asks for “the number of biconnected components” is only answerable once the paper’s convention is known. Say which definition you are using.

Parallel edges and self-loops

Every graph here is simple. Two parallel edges between the same pair form a cycle of length two, so neither is a bridge, and the algorithm must skip the edge it arrived on rather than the parent vertex to see that. A self-loop lies on a cycle by itself and never changes any component count.

If a question allows multi-edges, the safe move is to number the edges and pass the number, not the endpoint, into the search.

Verified fact The page’s search carries the parent edge index for this reason, which is also what the standard reference implementation recommends.

1. “Use the same test for vertices and edges”

Wrong. The vertex test is $$low[v] \ge disc[u]$$; the edge test is $$low[v] > disc[u]$$. Smallest counterexample, found by search: four vertices with a pendant edge into a triangle — A–B, B–C, B–D, C–D. Searching from A gives $$disc = 0,1,2,3$$ and $$low = 0,1,1,1$$. At B with child C, $$low[C] = 1 = disc[B]$$, so B is a cut vertex; with a strict test B is missed entirely.

Derivation Equality means the subtree climbs back to $$u$$ and no higher. Deleting the edge leaves $$u$$ in place to receive that climb; deleting the vertex removes the receiver.

2. “The root is a cut vertex whenever the test says so”

Wrong. Smallest counterexample: a single edge. The root has one child, and $$low[\text{child}] \ge disc[\text{root}]$$ holds because nothing lies above the root — so the vertex test flags the root of every graph. The root is a cut vertex exactly when it has two or more children.

Derivation Deleting the root leaves one piece per child subtree, and no edge can join two of them without having made them one subtree during the search.

3. “Every bridge has a cut vertex at one end”

Wrong, without a size condition. Smallest counterexample: two vertices and one edge. The edge is a bridge; both endpoints have degree one, so neither is a cut vertex.

The repaired statement is true and worth remembering: in a connected graph with at least three vertices, every bridge has at least one endpoint that is a cut vertex, because one side of the bridge holds at least two vertices and its endpoint is what holds them together.

Verified fact The search finds the first failure at two vertices, and finds none at all once the connected graph has three or more.

4. “No bridge means no cut vertex”

Wrong. Smallest counterexample: the bowtie — two triangles sharing one vertex, five vertices and six edges. Every edge lies on a cycle, so there is no bridge; the shared vertex is a cut vertex.

Derivation An edge cut and a vertex cut are different objects. Two triangles can be immune to the first and not to the second, and the drawn graph shows both failures at once.

5. “Deleting a cut vertex adds exactly one component”

Wrong. Smallest counterexample: a star with three leaves — four vertices, three edges. Delete the centre and the graph goes from one piece to three: an increase of two. A bridge, by contrast, always raises the count by exactly one.

Derivation A cut vertex with $$k$$ children in the search tree splits off $$k$$ subtrees, so the increase is its number of children — which the root rule bounds below by two. The page checks the bridge half of the claim on every graph with up to five vertices, edge by edge.

6. “A block is a cycle, and a search tree has cross edges”

Both wrong. Smallest block that is not a cycle: $$K_4$$ with one edge removed — four vertices, five edges, one block, and it contains a 4-cycle as well as two 3-cycles. The drawn graph’s block {D, E, F, L} is exactly this shape.

Cross edges: an undirected depth-first search produces only tree edges and back edges. On the drawn graph all fifteen edges are classified and none is a cross or forward edge — 11 tree, 4 back.

Derivation The first claim is refuted by the same search that finds the smallest such block; the second by the classification of every edge of the drawn graph.

Pattern A — GATE CSE 2021, Set 1, Question 41 (MSQ, 2 marks)

The paper defines an articulation point as a vertex whose removal disconnects a connected graph into two or more components, lets $$T$$ be a DFS tree of a connected undirected graph $$G$$, and asks which of four statements are correct: (1) if $$u$$ is an articulation point with $$x$$ an ancestor of $$u$$ in $$T$$ and $$y$$ a descendant of $$u$$, then every path from $$x$$ to $$y$$ passes through $$u$$; (2) a leaf of $$T$$ can be an articulation point of $$G$$; (3) the root of $$T$$ is an articulation point of $$G$$ if and only if it has two or more children; (4) the root of $$T$$ can never be an articulation point of $$G$$.

The page recomputes all four rather than quoting a key. Statement 3 survives: it agrees with brute force on every graph with up to five vertices, searched from every possible start vertex. Statement 1 fails on four vertices — A–B, A–C, B–C, B–D searched from A: $$u = B$$ is an articulation point, $$x = A$$ is its ancestor, $$y = C$$ is its descendant, and the edge A–C walks from $$x$$ to $$y$$ without touching $$u$$. Statement 2 fails everywhere: a leaf of the search tree has no child, and everything it touches was discovered before it, so its removal disconnects nothing — no graph the page searched has one, and the argument says none can. Statement 4 fails on three vertices, A–B and A–C: the root has two children and is an articulation point.

Verified fact Wording and key (statement 3 only) agree across three independent archives. Derivation Each of the four verdicts above is the output of this page’s own search, not a copy of that key.

Pattern B — GATE CSE 2015, Set 2, Question 26 (MCQ, 2 marks)

In a connected graph a bridge is an edge whose removal disconnects the graph. Which statement is true: (a) a tree has no bridges; (b) a bridge cannot be part of a simple cycle; (c) every edge of a clique of size at least 3 is a bridge; (d) a graph with bridges cannot have a cycle.

The answer is (b). An edge on a simple cycle has a way round, so deleting it leaves the graph connected. The page checks the contrapositive directly: on every graph with three to five vertices, no bridge ever shared a block with another edge — zero exceptions.

(a) is false because every edge of a tree is a bridge. (c) is false because every edge of a clique lies on a triangle. (d) is false on the same bowtie graph that refutes misconception 4: two triangles joined through one vertex have a bridge and plenty of cycles.

Verified fact The wording and key (b) agree across four independent archives and the paper’s own answer listing.

Pattern C — the counting questions

Questions of the form “how many articulation points / bridges / biconnected components does this graph have” are answered fastest by the structure, not by the algorithm: contract each cyclic piece in your head, mark the vertices where two pieces meet, and count.

cut vertices
vertices lying in two or more blocks
bridges
blocks of exactly one edge
blocks
cyclic pieces plus the bridges, under the edge definition

Educational interpretation On a small drawn graph, deleting candidates and recounting is usually faster than any algorithm — and it is the check the page uses against itself.

The five-step procedure

  1. Ask which cut. A vertex, an edge, or the decomposition? Each is read off a different column of the same search.
  2. Run one DFS from any vertex, recording $$disc$$ on entry and computing $$low$$ on exit.
  3. Apply the weak test $$low[v] \ge disc[u]$$ at every non-root vertex with a child, and the root rule at the root.
  4. Apply the strict test $$low[v] > disc[u]$$ to every tree edge to get the bridges.
  5. Pop the edge stack at every tree edge that satisfies the weak test, then check the pieces against the deletion definition if time allows.

The step candidates skip is the third: applying the vertex test at the root, which flags every root of every graph.

NAT original

Q1 — a path

A path on 10 vertices has 9 edges. The number of articulation points is ______.

Answer: 8

Every internal vertex splits the path into a left piece and a right piece, and there are 10 − 2 = 8 internal vertices. The two ends are leaves and disconnect nothing.

The trap is answering 9 by counting edges, or 9 by counting all but one vertex. The count is $$n - 2$$ for a path on $$n \ge 2$$ vertices, and the 9 bridges are a different number on purpose.

MSQ original

Q2 — which statements hold for every connected graph with at least 3 vertices

(a) every bridge has at least one endpoint that is an articulation point   (b) deleting an articulation point raises the component count by exactly one   (c) a graph with no bridge has no articulation point   (d) two distinct blocks share at most one vertex

Answer: (a), (d)

(a) One side of a bridge holds at least two vertices, and its endpoint is what holds them together. (d) Two shared vertices would put every edge of both blocks on a common cycle, so they would have been one block.

(b) fails on a star with three leaves: 1 becomes 3, an increase of two. (c) fails on the bowtie: two triangles through one vertex, no bridge, one articulation point. Note the size condition in (a): on two vertices and one edge the statement is false, which is why it is written into the question.

NAT original

Q3 — the bowtie

Two triangles share exactly one vertex: five vertices, six edges. Under the edge definition, the number of biconnected components is ______.

Answer: 2

Each triangle is a maximal set of edges any two of which lie on a common cycle, so each is a block. There is no bridge, so there are no one-edge blocks.

The trap is answering 1 by thinking of the whole figure as one 2-connected-looking piece: the shared vertex is a cut vertex, so the two triangles are separate blocks. Under the maximal-2-connected-subgraph convention the answer is also 2 here — the two conventions part company only when bridges are present.

MCQ original

Q4 — the equality case

A depth-first search gives a tree edge from $$u$$ to $$v$$ with $$u$$ not the root, and $$low[v] = disc[u]$$. Which is true?

(a) the edge is a bridge and $$u$$ is an articulation point   (b) the edge is a bridge but $$u$$ is not an articulation point   (c) $$u$$ is an articulation point but the edge is not a bridge   (d) neither

Answer: (c)

Equality satisfies the weak test and fails the strict one. The subtree of $$v$$ climbs back exactly as far as $$u$$ and no further: delete the edge and $$u$$ still receives that climb, so the graph stays connected; delete $$u$$ and the climb has nowhere to land.

This is the single most examinable distinction in the topic, and the drawn graph contains a live example: edge F–E, where $$low[E] = 4 = disc[F]$$, is not a bridge while F is an articulation point.

MCQ original

Q5 — which graph is a single block

(a) two vertices joined by one edge   (b) a triangle with a pendant edge attached   (c) $$K_4$$ with one edge deleted   (d) a path on three vertices

Answer: (c)

$$K_4$$ minus an edge has four vertices and five edges; every two of its edges lie on a common cycle, so it is one block. It is the smallest block that is not itself a cycle.

(a) is a block of one edge — a bridge — which is a block under the edge definition but not a 2-connected subgraph. (b) and (d) both contain a bridge, so each splits into at least two blocks. The question is really asking which definition you are using, which is why the option (a) distractor is there.

MSQ original

Q6 — the search tree

$$G$$ is undirected with $$n$$ vertices, $$m$$ edges and $$c$$ components. Which are true?

(a) every non-tree edge joins a vertex to one of its ancestors   (b) the number of back edges is $$m - n + c$$   (c) a leaf of the search tree can be an articulation point   (d) the root is an articulation point if and only if it has at least two children

Answer: (a), (b), (d)

(a) There are no cross edges in an undirected search. (b) The forest has $$n - c$$ tree edges, so the rest are back edges. (d) is the root rule.

(c) is false: a leaf of the search tree has no child, and every vertex it touches was discovered before it, so removing it leaves those neighbours connected through the rest of the graph. On the drawn graph, J is a leaf of the search tree and is not a cut vertex.

NAT original

Q7 — reading the numbers

In a connected graph, a search from $$u$$ gives $$disc[u] = 5$$ and a child $$v$$ with $$disc[v] = 9$$ and $$low[v] = 5$$. How many of the following are true: the edge $$\{u,v\}$$ is a bridge; $$u$$ is an articulation point; $$v$$ is an articulation point; $$v$$'s subtree contains a back edge to $$u$$.

Answer: 2

True: $$u$$ is an articulation point ($$5 \ge 5$$), and $$v$$'s subtree does contain a back edge to $$u$$ — that is exactly what $$low[v] = disc[u]$$ means. False: $$\{u,v\}$$ is not a bridge ($$5 > 5$$ is false), and nothing here makes $$v$$ an articulation point; that would need one of $$v$$'s own children to satisfy the weak test.

A number-only question like this is common, and the whole answer comes from reading $$=$$ against the two inequalities rather than from any graph.

MCQ original

Q8 — the closely confused pair

A question asks for “the number of biconnected components” of a connected graph that has 3 bridges. Two candidates answer 7 and 4. What separates them?

(a) one counted edges and the other counted vertices   (b) one used the edge definition, the other the maximal-2-connected-subgraph definition   (c) one of them forgot the root rule   (d) one of them counted isolated vertices

Answer: (b)

Under the edge definition every bridge is a block of one edge, so the count includes them: 7. Under the subgraph definition a bridge is not a block, so the count is smaller by the number of bridges: 4.

The difference is exactly 3, the number of bridges, which is the arithmetic tell. (c) and (d) cannot change the count by the bridge count. When a paper does not say, state the definition you used.

The definitions in four lines

Cut vertex
$$c(G - u) > c(G)$$ — deleting the vertex splits the graph
Bridge
$$c(G - e) > c(G)$$ — deleting the edge splits the graph
Block
maximal set of edges, any two on a common simple cycle
Consequence
blocks partition the edges; every bridge is a one-edge block

A vertex is a cut vertex exactly when it lies in two or more blocks.

The three tests, with their symbols

Cut vertex
$$low[v] \ge disc[u]$$ for some child $$v$$, $$u$$ not the root
Root
at least two children in the search tree
Bridge
$$low[v] > disc[u]$$ for the tree edge $$\{u,v\}$$
Block
pop the edge stack when $$low[v] \ge disc[u]$$
Cost
one search: vertices plus edges

Weak for vertices, strict for edges — because the vertex does not survive the deletion and the edge does.

What to say in one sentence

One depth-first search records when each vertex is discovered and the earliest discovery time its subtree can climb back to; comparing that number with the parent’s discovery time by $$\ge$$ finds the vertices whose loss splits the graph, by $$>$$ finds the edges whose loss splits it, and popping the edge stack at every $$\ge$$ splits the edge set into the pieces that survive.

If you remember one thing: the difference between the two tests is whether the vertex survives, and the root has to be asked a different question.
