Topic and objective

TOPIC: Divide and conquer as an algorithm design technique — Section 5 of the GATE CSE 2027 syllabus, whose third named technique it is: "Algorithm design techniques: greedy, dynamic programming and divide-and-conquer". The three steps, the recursion tree, the recurrence T(n) = aT(n/b) + f(n), the three master-theorem cases, and the algorithms the technique is examined through.

LEARNING OBJECTIVE: Take any divide-and-conquer algorithm and read a, b and f(n) off its code. Draw its recursion tree and count the levels and the leaves. Say which of the leaves and the level work dominates, and therefore which case applies. Count the comparisons of a merge, a partition or a binary search exactly, not only asymptotically. Tell divide and conquer (a parts) apart from decrease and conquer (one part). Say why Karatsuba's exponent is 1.585 and where its advantage starts.

I read the syllabus item as the technique plus its instances: the syllabus names the technique, so merge sort, quicksort, binary search, quickselect, Karatsuba and the maximum-subarray recursion are taught here as applications of one idea. The sorting algorithms themselves are counted in the sorting lesson, and the asymptotics in the asymptotic-complexity lesson; this lesson is the one that connects them.

Prerequisites

  • Asymptotic complexity and recurrences — Theta, Omega and O, and how a recurrence is solved. This lesson assumes the notation and adds the tree argument behind it.
  • Recurrence relations — substitution, the characteristic equation and the master theorem as a statement. Here it is derived from the tree rather than applied.
  • Sorting algorithms — merge sort and quicksort as procedures. This lesson counts their comparisons.
  • Binary search and its variants — the decrease-and-conquer case, used on the seventh scene as the contrast.
  • Recursion — a recursive call, a base case and a call tree. Without this the recursion tree means nothing.
  • Dynamic programming and greedy algorithms — the two sibling techniques named in the same syllabus sentence.

Six sentences worth keeping

  • Shape. Divide into a parts of size n/b, solve each, combine at cost f(n). Those three numbers are the whole algorithm.
  • Tree. The levels are logb n and the leaves are nlogb a.
  • Case. Compare f(n) with nlogb a: smaller means leaves win, equal means every level counts, larger means the root wins.
  • Count. n log n counts units of work, not comparisons. Merge sort's worst case at n = 8 is 17, not 24.
  • Decrease. One subproblem is not divide and conquer, and it is the difference between log n and n log n.
  • Balance. A split by value can be unbalanced, and an unbalanced split turns n log n into n2.

1. Intuition — the office that splits the work

A manager has a report to write and three assistants. She does not write it faster by typing harder; she divides the report into sections, gives one section to each assistant, and then assembles the sections into one document. Educational interpretation The division is "divide", each assistant working is "conquer", and the assembly is "combine". The assembly is the part people forget, and it is the part that appears in the recurrence as f(n).

Two things decide whether the plan is any good. How many sections — if she splits into ten sections, she has ten assemblies to pay for. And how much smaller each section is — if a section is almost the whole report, the assistants do not help. Those are exactly a and b. The rest of this lesson is bookkeeping on that idea: count the work at each level of the split, and see which level costs the most.

2. The three steps, formally

Divide one problem of size n into a subproblems, each of size at most n/b. Conquer each subproblem by the same procedure, until the size is small enough that the answer is immediate — the base case. Combine the a answers into one answer for the original problem.

Mathematical derivation The recursion is only well founded if b > 1, so that the sizes strictly decrease and the base case is reached. With b = 1 the recursion never shrinks, which is why T(n) = T(n−1) + n is a different animal: it terminates because the size falls by one, not because it is divided.

3. The recurrence, and what each symbol means

T(n) is the running time on an input of size n. a is the number of recursive calls the body makes. b is the factor by which the input shrinks on each call. f(n) is every step that is not a recursive call — the dividing and the combining together.

T(n) = a·T(n/b) + f(n)a = how many parts; b = how much smaller each part is; f(n) = the work outside the recursive calls. Merge sort: a = 2, b = 2, f(n) = n.

Mathematical derivation Read a and b off the code by counting calls and dividing sizes — not by remembering a formula. For merge sort the body calls itself twice on halves, so a = 2 and b = 2, and the merge is linear, so f(n) = n.

4. The recursion tree

Draw one node per call. The root is the whole problem; its children are the a subproblems; and so on until the pieces reach the base case. The depth of the tree is the number of times you can divide, and the leaves are the base cases.

Mathematical derivation Level k holds ak nodes of size n/bk, so the total length at that level is n·(a/bk)… — more usefully, the work at level k is ak·f(n/bk). The tree exists so that this sum can be seen rather than guessed.

5. The two counts that matter

Levels. Solve n/bk = 1 for k: the answer is logb n. Leaves. The tree has alogb n leaves, and that number equals nlogb a.

alogb n = nlogb aThe left side counts leaves by level; the right side writes the same number as a power of n. Only the right side tells you the exponent in n, which is what a complexity class needs.

Mathematical derivation The page checks the identity as an integer equality at n = 256 with a = 3, b = 2: 38 = 6561 and 2561.585 = 6561. Two routes, one number — which is why the exponent logb a can be read straight off the recurrence.

6. Which level dominates

If f grows more slowly than nlogb a, the level sums grow as you go down and the leaves dominate. If they are comparable, every level costs about the same and the count is the level cost times the number of levels. If f grows faster, the level sums shrink and the root dominates.

Mathematical derivation The three cases are a comparison of exponents, not of functions. That is why "f is bigger" must mean bigger by a polynomial factor; a factor of log n does not move the case, and that is exactly why case 2 gains a factor of log n instead.

7. The three cases of the master theorem

With T(n) = aT(n/b) + f(n), a ≥ 1, b > 1, and nlogb a as the leaf total:

case 1: f(n) = O(nlogb a − ε) → T(n) = Θ(nlogb a)
case 2: f(n) = Θ(nlogb a) → T(n) = Θ(nlogb a log n)
case 3: f(n) = Ω(nlogb a + ε) and a·f(n/b) ≤ c·f(n) → T(n) = Θ(f(n))The condition in case 3 is the regularity condition, with some constant c < 1. It holds for every polynomial and fails for some functions with fast-growing oscillations.

Verified fact The three cases as stated are the standard master theorem of the algorithms texts (Cormen, Leiserson, Rivest and Stein, chapter 4; Kleinberg and Tardos, chapter 5). Mathematical derivation The page evaluates five recurrences by direct recursion at n = 256 and compares each with its closed form, so the cases are checked rather than assumed.

8. Counting comparisons, not just work

"n log n" counts units of work: the elements touched at each level. A comparison count is a different number, and it is the one a numerical-answer question wants. Merging two sorted lists of sizes m and n takes between min(m,n) and m+n−1 comparisons, and neither bound is an approximation.

Mathematical derivation The page enumerates every interleaving for all m, n up to 4 and gets exactly min(m,n) and m+n−1 at the two ends, on all sixteen pairs. Then it sorts all 40,320 orderings of eight elements: worst 17, best 12, average 15.73.

9. Decrease and conquer

If the body makes one recursive call, a = 1, the leaf count is n0 = 1, and the tree is a path. Binary search halves the range and keeps one side: T(n) = T(n/2) + 1, which is Theta(log n). Quickselect partitions and keeps one side: expected Theta(n).

Mathematical derivation With a = 1, case 1 of the master theorem always applies, because f(n) is bigger than n0 = 1 by a polynomial factor. So the answer is f(n) times the height — the cost of one path, not of a whole level.

10. Where the technique is examined

Four question shapes recur: write the recurrence for a given algorithm; solve a given recurrence; give an exact count (comparisons, multiplications, probes); and decide which technique a named algorithm uses. Karatsuba, merge sort, quicksort, binary search and the maximum-subarray recursion cover all four.

Three counts by hand, and one by recursion

Each example below is what the page's model actually computes. Do them with a pen first; the arithmetic is the reasoning.

Example 1 — merge sort on eight elements, counted by level

Divide 8 into 4 and 4, each 4 into 2 and 2, each 2 into 1 and 1. Levels: 3 below the root. Leaves: 8. Merges: 4 + 2 + 1 = 7.

Mathematical derivation At every level the lists being merged have total length 8, so the work per level is 8 and the total is 8 × 3 = 24. The model builds this tree and counts it, rather than quoting 24.

Example 2 — one merge, bounded then counted

Merging [1,4,6,9] with [2,3,7,8]: compare 1 and 2, place 1; 4 and 2, place 2; 4 and 3, place 3; 4 and 7, place 4; 6 and 7, place 6; 9 and 7, place 7; 9 and 8, place 8; then 9 is placed with no comparison. Seven comparisons, which is m+n−1 for m = n = 4.

Mathematical derivation The bound is min(m,n) to m+n−1. The model enumerates every interleaving of the two sorted lists for all m, n up to 4 and finds both ends reached on all sixteen pairs, so the bound is tight.

Example 3 — merge sort at n = 8, over every ordering

Sort all 40,320 orderings of eight elements and count comparisons: worst 17, best 12, average 15.73. The worst case is n·ceil(lg n) − 2ceil(lg n) + 1 = 24 − 8 + 1 = 17, and the model checks that formula at every n from 1 to 8.

Mathematical derivation 17 is less than the 24 units of work because a merge usually finishes before it compares every pair: once one list is exhausted the rest are copied without comparison. Work and comparisons are two different counts of the same algorithm.

Example 4 — quicksort, the same shape and a worse split

Partition eight elements around the first element: 7 comparisons, and the pivot lands in its place. If the pivot is the smallest each time, the sides are 0 and n−1 and the total is 7 + 6 + 5 + 4 + 3 + 2 + 1 = 28 = n(n−1)/2.

Mathematical derivation The model gets 28 on sorted input and 28 on reverse-sorted input, 13 in the best case, and 16.92 on average — the closed form 2(n+1)Hn − 4n matches the enumeration of all 40,320 orderings to four decimals.

Example 5 — Karatsuba, counted in multiplications

Schoolbook multiplication of n digits does four half-size products, so at depth k there are 4k scalar products. Karatsuba computes the middle term as (x1+x0)(y1+y0) − x1y1 − x0y0, reusing two products, so there are 3k.

Mathematical derivation At k = 5 that is 243 against 1024. The exponent is log2 3 = 1.585, and the model checks the identity at n = 256: 38 = 6561 = 2561.585.

Example 6 — maximum subarray, both ways

On the GATE CSE 2019 Q25 array the three-way recursion — best on the left, best on the right, best crossing the middle — returns 29, from indices 2 to 11. A brute force over all 105 contiguous ranges also returns 29.

Mathematical derivation The crossing case is the one that makes the recursion correct: the best range may use a suffix of the left half and a prefix of the right half, and neither half alone contains it. The model compares the two methods on 200 seeded random arrays with no disagreement.

Where each rule stops being safe

A recurrence applied outside its condition is a trap. Each card names the condition and says what breaks when it fails, with the number that shows the size of the break.

The master theorem needs a polynomial gap

Case 1 needs f(n) = O(nlogb a − ε) for some ε > 0, and case 3 needs the mirror condition plus regularity. A gap of a factor of log n fits neither.

Mathematical derivation T(n) = 2T(n/2) + n/log n has f smaller than n but not polynomially smaller, so no case applies; the true answer is Θ(n log log n). Writing Θ(n log n) from case 2 would be wrong.

An unbalanced split changes the recurrence, not just the constant

Quicksort's balanced recurrence T(n) = 2T(n/2) + n holds only when the pivot splits the array in half. With the first element as pivot on sorted input, one side is empty.

Mathematical derivation The two recurrences differ by a factor of n: 24 units of work at n = 8 in the balanced case against 28 comparisons plus deeper recursion in the worst case, and asymptotically n log n against n2.

ceil and floor disagree at powers of two

The merge-sort worst case uses ceil(lg n), not lg n. At n = 8 they agree; at n = 5 they do not, and the formula gives 8 where n·lg n − n + 1 would give 7.61.

Mathematical derivation ceil(lg 5) = 3, so the worst case is 5·3 − 8 + 1 = 8, which is what the enumeration of all 120 orderings of five elements returns. The non-integer 7.61 is a lower bound that no comparison count can attain.

Karatsuba is not faster at every size

Counting one unit per multiplication and per addition, Karatsuba's total at n = 2 is 9 against schoolbook's 8. The asymptotic advantage is certain; the crossover is not.

Mathematical derivation At n = 4 the totals are 39 against 48 and Karatsuba leads. The crossover depends on the relative cost of an addition, which is a machine property, not a mathematical one — so the honest claim is the exponent.

The base case is part of the recurrence

T(1) is not implied by T(n) = 2T(n/2) + n. Change it and the exact solution changes, though the class usually does not.

Mathematical derivation With T(1) = 1 the exact solution is n log2 n + n = 2304 at n = 256; with T(1) = 0 it would be n log2 n = 2048. The class is the same, the number a NAT question wants is not.

A counterexample to "recursive means divide and conquer"

The Towers of Hanoi makes two recursive calls of size n−1. It is recursive, and it is not divide and conquer: the sizes shrink by one, so b = 1 and the tree has n levels, not log n.

Mathematical derivation T(n) = 2T(n−1) + 1 gives 2n − 1, exponential. Reading a = 2 and stopping there — without asking what b is — is how that becomes a wrong n log n.

Five beliefs that cost marks

Each card gives the wrong belief, why it tempts, the smallest counterexample, and the rule that replaces it.

"n log n is the number of comparisons"

Why it tempts. The analysis is written as "n log n", and the analysis is about comparisons. Minimal counterexample. Merge sort on eight elements does at most 17 comparisons, not 24, and at least 12. The rule. n log n counts units of work, one per element per level; a comparison count needs the merge bound and the exact recurrence.

"Quicksort is n log n"

Why it tempts. It is n log n on average, and the average is what a textbook headline says. Minimal counterexample. Sorted input with the first element as pivot gives 28 comparisons at n = 8, which is n(n−1)/2, and Theta(n2) in general. The rule. Say which case you mean. The worst case is quadratic and GATE CSE 2015 Set 1 asks for exactly that recurrence.

"Binary search is divide and conquer"

Why it tempts. It divides the array in half, and it is recursive. Minimal counterexample. It makes one recursive call, not two, so a = 1 and the leaf count is n0 = 1; its recursion tree is a path. The rule. Divide and conquer solves every part because every part contributes; decrease and conquer discards the parts it does not need.

"The leaf count is a to the k, so just add the levels"

Why it tempts. Both quantities are easy to compute and both are "the size of the tree". Minimal counterexample. Merge sort at n = 8 has 3 levels and 8 leaves; adding them gives 11, which is not a cost of anything. The rule. Multiply, do not add: the cost is the level work times the number of levels, or the leaf total, or the root, depending on the case.

"Karatsuba is always faster"

Why it tempts. Its exponent is smaller, so it wins asymptotically. Minimal counterexample. At n = 2, under one unit per operation, Karatsuba costs 9 and schoolbook costs 8. The rule. An asymptotic improvement says "eventually"; the crossover is a constant-factor question and must be computed for the machine.

The one distinction to carry into the exam

Divide and conquer: a ≥ 2, every part is solved, and the cost is the level work times the height or the leaf total. Decrease and conquer: a = 1, one part is solved, and the cost is the work along one path. Everything else — merge sort, quicksort, binary search, Karatsuba — is an instance of one of these two, and the number a tells you which.

Four question shapes, and the reasoning each demands

Every past item this lesson quotes falls into one of these four. The pattern tells you what to write down first.

Shape 1 — write the recurrence

"Which one of the following is the recurrence equation for the worst case time complexity of ..." You are given an algorithm and asked for its recurrence. Write a, b and f from the code, and write the worst split if the question says worst.

Verified fact GATE CSE 2015 Set 1 asks this of quicksort, and the key is T(n) = T(n−1) + O(n). The common wrong approach is to write the balanced recurrence 2T(n/2) + O(n), which is the best case.

Shape 2 — solve a recurrence

"The solution to the recurrence equation T(2k) = 3T(2k−1) + 1, T(1) = 1, is ..." Substitute until the base case, sum the geometric series, then convert back from k to n.

Verified fact GATE CSE 2014 Set 2 asks this item. The sum is 1 + 3 + 9 + ... + 3k = (3k+1 − 1)/2, which is Theta(3k) = Theta(n1.585). The common wrong approach is to answer in k and forget that n = 2k.

Shape 3 — an exact count

"The worst-case number of comparisons is ___." A numerical-answer item wants a number. Count the merges and the comparisons per merge, or the probes per level, and do not stop at the asymptotic class.

Verified fact GATE CSE 2021 Set 2 asks for the worst-case number of arithmetic operations of recursive binary search; the answer is Theta(log n) with ⌊lg n⌋ + 1 levels, which the model confirms for every n up to 64. The common wrong approach is to count comparisons and arithmetic as the same thing.

Shape 4 — apply the technique to a problem

"Divide and conquer approach may be used." The problem is stated, the technique is suggested, and the answer is the numeric optimum. Write the three cases of the recursion — left, right, crossing — and evaluate them.

Verified fact GATE CSE 2019 Q25 is exactly this: the maximum of S(i,j) over fourteen numbers, answer 29. The common wrong approach is to sum the positive values, which reads S(i,j) as a subsequence rather than a contiguous range and gives 42.

How the four shapes relate

Shape 1 produces the recurrence, shape 2 solves it, shape 3 asks for the constant inside the solution, and shape 4 asks you to build the recursion yourself. They are one skill in four costumes: read a, b and f off the algorithm, then count the tree. A question that looks unfamiliar is almost always one of the four with a different algorithm in it.

MCQGATE CSE 2015 Set 1

Which one of the following is the recurrence equation for the worst case time complexity of the Quicksort algorithm for sorting n (n ≥ 2) numbers? In the recurrence equations given below, c is a constant.

  1. T(n) = 2T(n/2) + cn
  2. T(n) = T(n−1) + cn
  3. T(n) = 2T(n−1) + cn
  4. T(n) = T(n/2) + cn

Answer: B — T(n) = T(n−1) + cn

The partition costs cn and leaves one part of size n−1 and one empty part, so there is a single recursive call of size n−1. That solves to Theta(n2), and the model's count of 28 comparisons on sorted eight-element input is n(n−1)/2, consistent with it.

Why A fails. It is the balanced, best-case recurrence — two calls of half size. Why C fails. Quicksort never makes two calls of size n−1; the two parts sum to n−1. Why D fails. The partition does not halve the problem.

The trap. Reading "quicksort" and writing merge sort's recurrence. The word "worst" is the whole question.

NATGATE CSE 2019 Q25

Consider a sequence of 14 elements: A = [−5, −10, 6, 3, −1, −2, 13, 4, −9, −1, 4, 12, −3, 0]. The sequence sum S(i,j) = Σ A[k] for k = i to j. Determine the maximum of S(i,j), where 0 ≤ i ≤ j < 14. (Divide and conquer approach may be used.)

Answer: 29

The maximum is attained at i = 2, j = 11: 6 + 3 − 1 − 2 + 13 + 4 − 9 − 1 + 4 + 12 = 29. The page's divide-and-conquer recursion returns 29, and a brute force over all 105 contiguous ranges returns 29 as well.

Why 42 appears. Summing the positive values reads S(i,j) as a subsequence and ignores the negatives in between; the notation fixes a contiguous range. Why 23 appears. Stopping the range at index 7 gives 23 and misses the later recovery.

The trap. The best range may include a negative dip — here −9 and −1 — because crossing it is cheaper than starting again.

NATOriginal practice question

Written for this lesson. Merge sort is run on the already sorted array [1, 2, 3, 4, 5, 6, 7, 8]. Exactly how many element comparisons does the merge step perform in total?

Answer: 12

Each merge of two sorted halves of length k compares k times and then copies the rest: the four merges of size 2 give 1 each (4), the two merges of size 4 give 2 each (4), and the final merge gives 4, for 12. The model's enumeration over all 40,320 orderings gives 12 as the minimum, attained on sorted input.

Why 17 appears. That is the worst case, and sorted input is the best case for merge sort. Why 24 appears. That is the unit-of-work count n log2 n, not a comparison count.

The trap. Merge sort is n log n in every case, but its comparison count still varies by a factor of 1.4 between the best and the worst.

NATOriginal practice question

Written for this lesson. Binary search is run on a sorted array of 1000 distinct elements. What is the worst-case number of element comparisons?

Answer: 10

The worst case is ⌊lg n⌋ + 1 = ⌊9.97⌋ + 1 = 10. The model runs binary search on every size up to 64 and every target, and the maximum is ⌊lg n⌋ + 1 throughout: 4 for 8 to 15, 5 for 16 to 31, 6 for 32 to 64.

Why 9 appears. lg 1000 rounds down to 9, and the number of halvings is 9 — but each halving ends in a comparison, and the final one is included. Why 11 appears. Using ceil(lg n) + 1 double-counts the last level.

The trap. Count the probes, not the halvings. On n = 2k the two differ, which is why the formula uses a floor.

MSQOriginal practice question

Written for this lesson. Let T(n) = 3T(n/2) + n, with T(1) = 1. Which of the following statements are TRUE?

  1. The recursion tree has log2 n levels
  2. The number of leaves is nlog2 3
  3. Case 1 of the master theorem applies
  4. T(n) = Θ(n log n)

Answer: A, B and C

Levels: log2 n. Leaves: 3log2 n = nlog2 3 = n1.585. Since f(n) = n is polynomially smaller than n1.585, case 1 applies and T(n) = Θ(n1.585). The model checks the leaf identity at n = 256: 38 = 6561 = 2561.585.

Why D fails. n log n is the answer when f(n) equals nlogb a, which needs a = 2 here, not a = 3. The extra subproblem is what changes the class.

The trap. a = 3 with b = 2 looks like merge sort with one more call. That one call raises the exponent from 1 to 1.585, which is Karatsuba's whole point.

MCQOriginal practice question

Written for this lesson. Which one of the following correctly gives the recurrence and its solution for Karatsuba's integer multiplication of n-digit numbers?

  1. T(n) = 3T(n/2) + Θ(n), T(n) = Θ(n1.585)
  2. T(n) = 4T(n/2) + Θ(n), T(n) = Θ(n2)
  3. T(n) = 2T(n/2) + Θ(n), T(n) = Θ(n log n)
  4. T(n) = 3T(n/2) + Θ(n2), T(n) = Θ(n2)

Answer: A

Three half-size products, plus a linear amount of addition and subtraction, gives 3T(n/2) + Θ(n). The leaf count is nlog2 3 = n1.585, and f(n) = n is polynomially smaller, so case 1 applies.

Why B fails. Four half-size products is the schoolbook method written recursively. Why C fails. Two half-size products is not enough to compute the middle term. Why D fails. The combining is linear, not quadratic — Karatsuba adds, it does not multiply n-digit numbers.

The trap. B is the recurrence most people write, because the schoolbook method is what they learned first.

MSQOriginal practice question

Written for this lesson. Quicksort sorts in ascending order using the first element as pivot. Which of the following statements are TRUE?

  1. Already sorted input gives the worst case
  2. The average over all inputs is Θ(n log n)
  3. The worst case is Θ(n log n)
  4. Reverse-sorted input gives the best case

Answer: A and B

On sorted input the pivot is always the smallest, so one side is empty: 28 comparisons at n = 8, which is n(n−1)/2. The average over all 40,320 orderings of eight elements is 16.92, matching 2(n+1)Hn − 4n, which is Θ(n log n).

Why C fails. The worst case is Θ(n2). Why D fails. Reverse-sorted input is equally bad: the model gives 28 there too, because the pivot is then always the largest.

The trap. "Already sorted" feels like the friendly case. For a first-element pivot it is the worst case, and only a randomised or median-of-three pivot fixes it.

NATOriginal practice question

Written for this lesson. Merge sort is run on the array [9, 3, 7, 1, 8, 2, 6, 4]. Exactly how many element comparisons does it perform?

Answer: 17

This array attains the worst case for eight elements: 17 comparisons. The closed form gives n·ceil(lg n) − 2ceil(lg n) + 1 = 24 − 8 + 1 = 17, and the model's enumeration over all 40,320 orderings finds 17 as the maximum.

Why 12 appears. That is the best case, which sorted input attains. Why 24 appears. That is n log2 n, the unit-of-work count.

The trap. An arbitrary array is far more likely to be near the maximum than near the minimum, so the worst case is the number to remember.

The revision sheet

The recurrence, the three cases, the four counts, the procedure and the traps — one screen, to be read the night before.

Notation

T(n): running time on size n. a: recursive calls per level. b: size shrink factor. f(n): work outside the recursive calls. logb n: the number of levels. nlogb a: the number of leaves. Hn: the n-th harmonic number, 1 + 1/2 + ... + 1/n.

Mathematical derivation Two of these are computed and two are read off the code. a and b from the body; levels and leaves from the tree.

The three cases

f(n) < nlogb a → Θ(nlogb a)
f(n) = nlogb a → Θ(nlogb a log n)
f(n) > nlogb a → Θ(f(n))"Less" and "greater" mean by a polynomial factor. Case 3 also needs a·f(n/b) ≤ c·f(n) for some c < 1.

Mathematical derivation Checked at n = 256: 2304 = n log2 n + n, 130816 = 2n2 − n, 511 = 2n − 1, 33488896 just under 2n3.

Mathematical derivation The two counts that are most often confused are 24 (units of work at n = 8) and 17 (comparisons at n = 8). Both are correct answers to different questions.

The decision procedure

  1. Name a, b and f(n); write the recurrence.
  2. Count the levels logb n and the leaves nlogb a.
  3. Compare f(n) with nlogb a; pick the case.
  4. Check whether the split can be unbalanced.
  5. Check the base case, and decide whether the question wants the class or the number.

Three numbers to remember, and where they come from

24 — units of work in merge sort at n = 8: 8 per level, 3 levels.

17 — comparisons in merge sort's worst case at n = 8, from the closed form and from the enumeration of all 40,320 orderings.

28 — comparisons in quicksort's worst case at n = 8, which is n(n−1)/2 and is attained on sorted input.

If you remember only five sentences

Divide into a parts of size n/b and combine at cost f(n); the tree then has logb n levels and nlogb a leaves. Compare f(n) with that leaf total to pick the case, and remember that case 2 is the only one that adds a factor of log n. One recursive call is decrease and conquer, not divide and conquer, and it is the difference between log n and n log n. A split by value can be unbalanced, and an unbalanced split turns n log n into n2. And n log n counts units of work: the comparison count at n = 8 is 17, not 24.

Educational interpretation The five sentences cover every past item quoted in this lesson: the quicksort recurrence, the geometric recurrence, the binary-search count, and the maximum-subarray application.

What is computed rather than cited

The page sorts all 40,320 orderings of eight elements by merge sort and by quicksort, recording min, max and average comparisons for each n from 1 to 8, and compares the extremes with n·ceil(lg n) − 2ceil(lg n) + 1, n(n−1)/2 and 2(n+1)Hn − 4n. It enumerates every interleaving of two sorted lists for all m, n up to 4 and matches both bounds. It builds merge sort's recursion tree at n = 8 and counts 3 levels, 8 leaves, 7 merges and 24 units of work. It evaluates five recurrences by direct recursion at n = 256 and compares each with its closed form, and checks the leaf identity at n = 256 as an integer equality. It runs binary search on every size up to 64 and every target. It counts Karatsuba's and schoolbook's scalar products and additions to k = 6. It solves the maximum-subarray problem by divide and conquer and by brute force on the 2019 array and on 200 seeded random arrays.
