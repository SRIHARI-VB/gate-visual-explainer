Topic and objective

TOPIC: Local optimisation — the rewrites a compiler can justify from a single basic block — built on the basic-block partition itself: the three leader rules, the control-flow graph they induce, the DAG of a block by value numbering, the six local transformations and the condition each one depends on. This is the phrase "Local optimisation" at the start of the final clause of Section 7 of the official GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Cut any three-address program into basic blocks with the three leader rules and count them. Build the control-flow graph and say which conventions change the node and edge counts. Turn a block into a DAG and count its nodes and edges. Name each of the six local rewrites and the condition it needs. Decide whether a given rewrite is sound, and produce a witness when it is not. Say exactly where local optimisation stops and why the rest needs data-flow analysis.

I read this topic as one partition, one graph, one DAG and six rewrites. The partition and the graph are mechanical and appear in every block-counting question; the six rewrites are the conceptual half. The page keeps them apart, because a question that asks for a count never needs a rewrite and a question about a rewrite never needs the edges.

Prerequisites

Needed now: three-address code and what an intermediate representation is (intermediate code and optimisation); what a variable assignment means; integer arithmetic including what a left shift does.

Helpful: the idea of a directed graph and a path (graphs: connectivity and structure); the notion of a partial order if you continue to the global half.

Approximate learning time: 70 to 90 minutes for the whole page, 25 for the animation and the examples.

The five ideas worth carrying away

1. A basic block is a maximal straight-line run with one entry and one exit; the three leader rules produce exactly that partition, so the number of leaders is the number of blocks.

2. The control-flow graph has one node per block; every jump and every fall-through is an edge. Whether the exit counts as a node is a convention, and questions differ.

3. A block's DAG shares a node between two computations of the same operator on the same operand nodes — that sharing is common subexpression elimination, seen rather than performed.

4. Each of the six local rewrites is sound only while its condition holds, and the conditions are about the type and the machine, not only the arithmetic.

5. Everything a block cannot justify is a question about other blocks. That boundary, not difficulty, is what separates local from global.

Intuition first: a paragraph you may rewrite

Think of a basic block as one sentence of a recipe with no "if" in it. Because nothing branches inside it, you can edit it in place: replace "two times eight" by "sixteen", notice that the same quantity was already measured two lines earlier and reuse it, or cross out a line whose result nobody ever picks up. You never have to ask what happened in the previous sentence, and you never have to wonder which of two paths you arrived on.

The moment the recipe says "if the oven is hot, do this, otherwise do that", the editing becomes a question about both branches at once. That is the whole difference between this lesson and the next one.

Formal definition: basic block

A basic block is a maximal sequence of consecutive three-address instructions such that control enters the sequence only at the first instruction and leaves only after the last.

Maximal means you cannot extend it by one instruction at either end and keep the property. Consecutive means in the printed order of the intermediate code, not in the order the machine happens to run.

Verified fact This is the standard definition, stated the same way in the Dragon Book (Aho, Lam, Sethi, Ullman, Compilers: Principles, Techniques and Tools, 2nd edition, §8.4) and in the IIT Madras compiler course notes linked on the Sources tab.

Formal definition: leader

A leader is any instruction that satisfies at least one of:

R1. it is the first instruction of the program;
R2. it is the target of a conditional or unconditional jump;
R3. it is printed immediately after a conditional or unconditional jump.

The blocks are then: for each leader, the run from that leader up to, but not including, the next leader in printed order.

Derivation The three rules produce a partition with one entry and one exit, and it is maximal: any instruction that is not a leader can be entered only from the instruction above it, so it cannot start a block, and any instruction that is a leader cannot sit inside a block because control can reach it without passing the block's first line. So the two definitions agree, and the number of blocks equals the number of leaders.

Formal definition: control-flow graph

A control-flow graph (CFG) has one node per basic block. There is an edge from block P to block Q when control can pass from the end of P to the start of Q, which happens in exactly two ways: the last instruction of P is a jump to the leader of Q, or the last instruction of P is not an unconditional jump and Q is the next block in printed order (a fall-through).

Educational interpretation Whether an extra ENTRY and EXIT node is added is a drawing convention, not part of the definition. It changes node and edge counts by one or two and changes the block count not at all — which is why block-counting questions are safer than node-and-edge questions.

Formal definition: the DAG of a block

Process the block top to bottom. A variable's current node is the node that holds its value. For an instruction x = y op z: take the current node of y and of z, creating a leaf for either if it has none; if a node labelled op with exactly those two children already exists, reuse it; otherwise create one. Then attach the label x to that node and detach x from any other node.

An instruction x = y creates no node: it attaches the label x to the node that currently holds y. For a commutative operator, y + z and z + y are the same node.

The six rewrites and the condition each one needs

Constant folding — x = 2 * 8 becomes x = 16. Needs: both operands constant, and the machine is allowed to perform the operation (no trap, no trap-on-overflow flag).

Constant propagation — x = 3; y = x + 1 becomes y = 4. Needs: x is not reassigned between the two lines.

Copy propagation — x = y; z = x + 1 becomes z = y + 1. Needs: neither x nor y is reassigned in between.

Common subexpression elimination — u = b + c; v = b + c becomes v = u. Needs: no operand was redefined in between.

Algebraic simplification — x + 0, x * 1, x - 0 become x. Needs: the identity holds for the type, which is why x * 0 → 0 fails for floating point.

Strength reduction — x * 4 becomes x << 2. Needs: the cheaper form gives the identical result for every input, which is why x / 2 → x >> 1 fails for signed negatives.

The one principle behind all six

A rewrite is allowed only if, for every input the program can supply, it produces the same observable behaviour — the same values in the variables that are live afterwards, and no lost side effect. Where the mathematics and the target machine disagree, the machine decides: 32-bit addition wraps, a double addition rounds, a signed shift rounds down, and NaN absorbs a multiplication by zero. Every counterexample on the Edge cases tab is a case where that sentence is the whole answer.

Four worked examples, each computed rather than recalled

Every number below is printed by the page's model. The first two are the previous-year programs; the third is a DAG; the fourth is the optimiser run, checked by executing the block before and after on a hundred inputs.

Example 1 — the 2025 program, cut into blocks

The program is seventeen numbered instructions with jumps at 1009 (to 1003), 1011 (to 1002) and 1017 (to 1013).

1. Rule 1 marks 1001. Justification: it is the first instruction.
2. Rule 2 marks 1003, 1002, 1013. Justification: each is a jump target.
3. Rule 3 marks 1010 and 1012. Justification: they follow the jumps at 1009 and 1011. Nothing follows 1017, so rule 3 adds nothing there.
4. Cut at each leader: B1 = 1001, B2 = 1002, B3 = 1003–1009, B4 = 1010–1011, B5 = 1012, B6 = 1013–1017.
5. Sizes 1, 1, 7, 2, 1, 5 sum to 17. Justification: the partition covers the program exactly once, so no leader was missed.

Answer: 6 basic blocks. Edges: B1→B2, B2→B3, B3→B3, B3→B4, B4→B2, B4→B5, B5→B6, B6→B6, and B6→EXIT. The two self-loops exist because each loop-back jump targets its own block's first instruction.

Example 2 — the 2024 program, and the largest block

Fifteen labelled instructions; jumps at L9 (to L11), L12 (to L4) and L14 (to L3).

1. Leaders by the three rules: L1, L3, L4, L10, L11, L13, L15 — seven.
2. Blocks and sizes: B1 = L1–L2 (2), B2 = L3 (1), B3 = L4–L9 (6), B4 = L10 (1), B5 = L11–L12 (2), B6 = L13–L14 (2), B7 = L15 (1).
3. The sizes sum to 15, which is every instruction once.
4. The largest is B3 with six instructions.

Answer: 7 blocks, largest 6 — option D. L3 is a backward jump target, so L1 and L2 form a block of two; missing it gives six blocks and the wrong option.

Example 3 — the DAG of a five-statement block

u = b + c · v = b + c · w = u * 2 · x = u * 2 · y = v + 2

1. Leaves: b, c and the constant 2 — three nodes.
2. u = b + c creates a + node; v = b + c finds it and attaches a second label. One node labelled u, v.
3. w = u * 2 creates a * node; x = u * 2 finds it. One node labelled w, x.
4. y = v + 2 is an addition, not a multiplication, so it needs a new node labelled y.

Count: 6 nodes (3 leaves + 3 operators), 6 edges. Five statements became three computations. If a question does not count leaves, the same structure is 3 nodes — say which convention you used.

Example 4 — nine statements to four

The block t1 = b + c; t2 = b + c; t3 = b * 4; t4 = 2 * 8; t5 = t1 + 0; t6 = t5; x = t4 + t6; y = b * 4; z = 7 with x and y live out.

1. Fold. t4 = 2 * 8 becomes t4 = 16.
2. Simplify. t5 = t1 + 0 becomes t5 = t1.
3. Propagate copies. t5 is t1, so t6 is t1, so x = t4 + t6 becomes x = t4 + t1.
4. Value-number. t2 = b + c is the value already in t1; y = b * 4 is the value already in t3.
5. Delete dead. z is not live out, and t2, t5, t6 have no remaining uses. A second fold round turns t4 into the constant 16 inside the addition and makes t4 dead too.

Result: t1 = b + c; t3 = b * 4; x = 16 + t1; y = t3 — four statements. The page then executes both versions on a hundred inputs and compares x and y: they agree on all hundred.

Boundaries, conventions and the cases that break a shortcut

Each card names the boundary and the condition that fails there. The first four are about the partition, the rest about the rewrites.

A block of one instruction is still a block

In the 2024 program, L3, L10 and L15 are single-instruction blocks, and in the 2025 program B1, B2 and B5 are. Loop code produces them constantly, because a jump target immediately followed by another jump target leaves one instruction between them.

Derivation A leader is a leader by rule, not by size. Since every leader starts a block and the next instruction is also a leader, the block holds exactly that one instruction.

Unreachable code is still partitioned

If an unconditional jump is followed by instructions that nothing jumps to, rule 3 makes the instruction after the jump a leader, so the unreachable run becomes a block — a block with no predecessor in the CFG.

The partition algorithm does not know or care about reachability. A question that asks for the number of blocks counts it; a question that asks for reachable blocks does not. Read which one is asked.

Whether the exit is a node changes the counts

Community observation A well-known archive discussion of GATE CSE 2015 Set 2 Q29 — the same shape of question, asking for nodes and edges of the CFG — records answers of 5 and 7, and 6 and 7, and 7 and 8, differing only in whether explicit START and END nodes are added. Contributors point at an IIT Madras course definition that adds them and at textbooks that do not.

I am not asserting a key for that question. The lesson is the one thing that is certain: the block count is unaffected, and a node-and-edge question must state its convention. This page reports both numbers for the 2025 program — eight edges between blocks, plus one to the exit.

A backward jump target is the leader people miss

L3 in the 2024 program and 1002 in the 2025 program are targets of backward jumps, so they are leaders even though they sit in the middle of what looks like a prologue.

Derivation Rule 2 says "target of a jump". It does not say "forward jump". A loop's header is a leader precisely because the loop's back edge targets it, and a loop with no leader at its header would be a block entered in its middle, which the definition forbids.

Counterexample: reassociating a double

With a = 0.1, b = 0.2, c = 0.3: (a + b) + c gives 0.6000000000000001 and a + (b + c) gives 0.6. The rewrite (a+b)+c → a+(b+c) is therefore unsound for double, although it is sound for int.

The condition violated: floating-point addition is not associative, because each intermediate result is rounded to the nearest representable value. The page finds this witness by searching a grid of candidate values, so it is a demonstration rather than a quotation.

Counterexample: x / 2 is not x >> 1

For x = −3, x / 2 gives −1, because C truncates toward zero, while x >> 1 gives −2, because an arithmetic right shift rounds toward minus infinity.

The condition violated: the two forms agree for every non-negative value and disagree on negatives. The rewrite is valid for unsigned and invalid for signed types — which is exactly the sort of "it works on my test data" reasoning the exam tests.

Counterexample: x * 0 → 0, and folding 1 / 0

If x is NaN, x * 0 is NaN, not 0. If x is −1.0, x * 0 is −0.0, which compares equal to 0 but is distinguishable through 1/x.

And an integer 1 / 0 is a fault at run time: folding it away deletes a fault the program was going to have, which changes observable behaviour. The page's folding guard refuses any division by a zero constant, and the check confirms the refusal.

Counterexample: reusing a[i] across a store

Take t = a[i]; a[j] = 5; u = a[i] with i = j = 1 and the array starting 10, 20, 30. Then t is 20 and u is 5, so reusing t for u gives 20 instead of 5.

The condition violated: common subexpression elimination is sound only when nothing between the two occurrences writes a value the expression reads. A store through a possibly-aliasing index is exactly such a write.

Counterexample: deleting a store because "nobody reads it"

*p = 5, a[i] = 0, volatile flag = 1 and t = f() all define something no later instruction in the block reads.

None of them is dead: the store or the call is the observable effect. The page marks such statements with a side-effect flag and the dead-code pass keeps them; a check confirms that a pointer store survives a sweep that removes its neighbouring arithmetic.

Six beliefs that cost marks, and the smallest fact that refutes each

Each card gives the wrong belief, why it is tempting, the smallest counterexample, and the rule that replaces it.

1. "Local optimisation means optimising small pieces of code"

Why it tempts: the word local suggests size. Refuted by: a block of three hundred straight-line instructions — still one block, still local.

The rule: local means decided from one block, not small. Loop-invariant code motion on a four-line loop is global; constant folding on a three-hundred-line block is local.

2. "Only the target of a jump starts a new block"

Why it tempts: the target is the instruction you think of as the loop header, so it feels like the only interesting one. Refuted by: GATE CSE 2025 Set 1 Q52, where rule 3 alone supplies two of the six leaders (1010 and 1012).

The rule: three rules, and a leader is anything satisfying any of them. Forgetting rule 3 gives five blocks instead of six.

3. "Constant folding and common subexpression elimination are the same"

Why it tempts: both remove work, and both appear in the same list of optimisations. Refuted by: x = 2 * 8 → x = 16 is folding, and no value was computed earlier; v = b + c → v = u is elimination, and nothing is evaluated at compile time.

The rule: folding evaluates arithmetic on constants; elimination reuses a value the program already computed. A rewrite that does both is two rewrites.

4. "Any assignment nobody reads can be deleted"

Why it tempts: the liveness definition — a variable is dead if no later use reads it — is exactly that sentence, applied to variables. Refuted by: *p = 5 with p never read again: the store is the effect.

The rule: delete an assignment only when the target is dead and the statement has no side effect. Stores through pointers, volatile writes and calls always have one.

5. "Strength reduction is always safe because it is cheaper"

Why it tempts: multiplication really is slower than a shift, so the rewrite feels like pure gain. Refuted by: x = −3, where x / 2 is −1 and x >> 1 is −2.

The rule: the cheaper form must give the identical result for every input in the type's range, including negatives and the extremes. Otherwise it is a different program.

6. "A DAG node count is a fixed number for a block"

Why it tempts: the DAG itself is unique up to isomorphism, so the structure feels canonical — and it is. Refuted by: the same five-statement block is 6 nodes if leaves count and 3 if they do not; adding a constant leaf changes the count again.

The rule: the structure is determined; the count depends on the stated convention. Answer the convention in front of you and say which one you used.

Six question shapes, and the reasoning each one demands

The shapes are ordered by how often the leader algorithm alone settles them. Only the last two need an optimisation at all.

Pattern 1 — count the basic blocks (NAT)

You are given a numbered three-address listing and asked for an integer. GATE CSE 2025 Set 1 Q52 is this shape.

Procedure: mark leaders with the three rules, count them, and check that the resulting block sizes sum to the number of instructions.

Common wrong approach: counting jump targets only, or treating the instruction after a jump as part of the previous block. Both lose exactly one block here.

Pattern 2 — blocks plus a second number (MCQ)

GATE CSE 2024 Set 1 Q39 asks for the block count and the size of the largest block. The distractors are the four combinations of getting one right and one wrong.

Procedure: compute both before reading the options, then check that the sizes sum to the instruction count.

Common wrong approach: answering one number and inferring the other from the options. The options are built so that this works half the time.

Pattern 3 — nodes and edges of the CFG

Same partition, then a count of edges: one per jump plus one per fall-through. The EXIT convention changes the answer by one.

Procedure: list the edges explicitly, then count. On the 2025 program that list is B1→B2, B2→B3, B3→B3, B3→B4, B4→B2, B4→B5, B5→B6, B6→B6, plus B6→EXIT. Note the self-loops: two of them, because each loop-back jump targets its own block's first instruction.

Pattern 4 — nodes and edges of a block's DAG

Build the DAG by value numbering and count. The traps are a redefined operand (which prevents sharing) and a swapped commutative pair (which permits it).

Procedure: write each statement's node in a table, note which statements reused an existing node, then count leaves and operators separately and add. State the convention.

Pattern 5 — which optimisation uses which analysis

Verified fact GATE CSE 2025 Set 1 Q13 asks which technique uses live variable analysis, and the answer is register assignment; strength reduction and constant folding do not need it.

Procedure: ask what fact the technique must know. Register allocation needs "is this value still needed"; dead-code elimination needs the same; CSE needs "was this value computed on every path". A technique that only rearranges one statement needs no analysis at all.

Pattern 6 — count the operations after a rewrite

GATE CSE 2021 Set 2 Q30 is this shape: apply CSE and hoisting to a loop, then count additions and dereferences dynamically, over all iterations.

Procedure: compute the iteration count first; count operations per iteration including the loop increment; add the operations before the loop; multiply and add. Here: 100 iterations × 3 + 3 = 303 additions, and 2 dereferences.

Common wrong approach: counting from the source text rather than the transformed code, or forgetting i = i + 2. Both change the answer by exactly 100.

The single most useful habit here

After any count, check it against a property it must satisfy: block sizes sum to the instruction count; the DAG's node count is leaves plus operators; the edges are one per jump plus one per fall-through. Each check takes ten seconds and catches the error that the options are designed to reward.

NATGATE CSE 2025 Set 1 Q52

Refer to the given 3-address code sequence. This code sequence is split into basic blocks. The number of basic blocks is ________. (Answer in integer)

1001: i = 1        1002: j = 1        1003: t1 = 10*i
1004: t2 = t1+j    1005: t3 = 8*t2    1006: t4 = t3-88
1007: a[t4] = 0.0  1008: j = j+1      1009: if j <= 10 goto 1003
1010: i = i+1      1011: if i <= 10 goto 1002
1012: i = 1        1013: t5 = i-1     1014: t6 = 88*t5
1015: a[t6] = 1.0  1016: i = i+1      1017: if i <= 10 goto 1013

Answer: 6

The leaders. Rule 1: 1001. Rule 2, the three jump targets: 1003, 1002, 1013. Rule 3, the lines after the jumps: 1010 follows 1009, and 1012 follows 1011. Nothing follows 1017. That is {1001, 1002, 1003, 1010, 1012, 1013}, six leaders.

The blocks. B1 = 1001, B2 = 1002, B3 = 1003–1009, B4 = 1010–1011, B5 = 1012, B6 = 1013–1017. Sizes 1, 1, 7, 2, 1, 5 sum to 17, so the partition is exact.

Why five is the popular wrong answer. A candidate who marks only jump targets gets {1001, 1002, 1003, 1013} and then merges 1010–1011 into B3 and 1012 into the same run, producing five. Rule 3 is what supplies the other two.

The check. The page runs this program through its own leader algorithm; the six leaders, six blocks, eight inter-block edges and the two self-loops (B3→B3 and B6→B6) are all computed and listed in the Model checks panel.

MCQGATE CSE 2024 Set 1 Q39

Consider the following pseudo-code.

L1:  t1 = -1        L2:  t2 = 0         L3:  t3 = 0
L4:  t4 = 4 * t3    L5:  t5 = 4 * t2     L6:  t6 = t5 * M
L7:  t7 = t4 + t6   L8:  t8 = a[t7]      L9:  if t8 <= max goto L11
L10: t1 = t8        L11: t3 = t3 + 1     L12: if t3 < M goto L4
L13: t2 = t2 + 1    L14: if t2 < N goto L3   L15: max = t1

Which one of the following options correctly specifies the number of basic blocks and the number of instructions in the largest basic block, respectively?

  1. 6 and 6
  2. 6 and 7
  3. 7 and 7
  4. 7 and 6

Answer: option 4 — 7 basic blocks, and the largest holds 6 instructions

The leaders. Rule 1: L1. Rule 2: L11 (from L9), L4 (from L12), L3 (from L14). Rule 3: L10, L13, L15. Seven leaders, so seven blocks.

The blocks. B1 = L1–L2 (2), B2 = L3 (1), B3 = L4–L9 (6), B4 = L10 (1), B5 = L11–L12 (2), B6 = L13–L14 (2), B7 = L15 (1). The sizes sum to 15, the instruction count.

Why option 1 fails. Six blocks means L3 was not counted, which merges L1–L3 into one block of three and leaves the largest at six. The backward target from the outer loop at L14 is the leader that was missed.

Why options 2 and 3 fail. Option 3 keeps the largest at seven, which happens if L10 is merged into the block above it — that is, if the instruction after the conditional jump at L9 is not treated as a leader.

MCQGATE CSE 2021 Set 2 Q30

Consider the following ANSI C code segment:

z = x + 3 + y->f1 + y->f2;
for (i = 0; i < 200; i = i + 2) {
  if (z > i) { p = p + x + 3;  q = q + y->f1; }
  else        { p = p + y->f2; q = q + x + 3; }
}

Assume that y points to a struct on the heap with fields f1 and f2, and that x, y, z, p, q and i are in registers. Common sub-expression elimination is applied. The number of addition and dereference operations in the optimised code, respectively, are:

  1. 300 and 2
  2. 303 and 3
  3. 300 and 3
  4. 303 and 2

Answer: option 4 — 303 additions and 2 dereferences

Additions. The loop runs for i = 0, 2, …, 198: that is 100 iterations. Each iteration performs two additions in its branch, plus one in i = i + 2, so 300. Before the loop, x + 3, then adding y->f1, then adding y->f2 is three more. Total 303.

Dereferences. y->f1 and y->f2 are each computed once, before the loop, because nothing in the loop changes y or either field. Two.

Why option 1 fails. It forgets the three additions before the loop, or forgets the loop increment; either omission is a multiple of 100.

Why options 2 and 3 fail. Three dereferences would mean one of the field loads was not hoisted. Both are loop-invariant, so both are.

Why this is not a local optimisation. The hoisting needs the fact that every block of the loop leaves x, y, y->f1 and y->f2 unchanged. No single block can establish that; a data-flow analysis over the loop can.

MCQGATE CSE 2025 Set 1 Q13

Which ONE of the following techniques used in compiler code optimization uses live variable analysis?

  1. Run-time function call management
  2. Register assignment to variables
  3. Strength reduction
  4. Constant folding

Answer: option 2 — register assignment to variables

Why. Live variable analysis says, at each point, which values will still be needed. Two variables that are live at the same point interfere and cannot share a register, so liveness is exactly the input to register allocation.

Why the others fail. Call management is a calling-convention question. Strength reduction replaces an operation by a cheaper one and needs nothing about liveness. Constant folding evaluates known operands and likewise needs nothing.

The distinction this question tests. A transformation that rearranges one statement is local and analysis-free; a transformation that must know what happens later needs a backward analysis. Dead-code elimination is the other member of the second group, and it uses the same live sets.

MCQOriginal practice question

In the basic block t = a[i]; a[j] = 5; u = a[i]; which one of the following is true?

  1. u may be replaced by t, because the two expressions are identical
  2. u may not be replaced by t, because i and j may be equal
  3. u may be replaced by t only if i is not equal to j at run time, which the compiler cannot know
  4. Neither may be replaced, because a is an array

Answer: option 2 — the replacement is unsound, because the indices may alias

The witness. Take a starting as 10, 20, 30 with i = j = 1. Then t is 20, the store writes 5 over the same location, and u is 5. Reusing t would give 20. The page runs this and reports 20 against 5.

Why option 3 is the same answer wearing a disguise. "Only if i ≠ j" is a condition the compiler cannot establish at compile time, so a compiler must assume they may be equal — which is exactly why the replacement is refused. The two options differ in wording, not in what a compiler may do.

Why option 4 fails. Arrays are not the problem. t = a[3]; a[5] = 5; u = a[3] is perfectly safe, because the two indices are different constants. Aliasing, not array-ness, is what blocks the rewrite.

The condition. Common subexpression elimination requires that nothing between the two occurrences writes a location the expression reads. A store through a possibly-equal index violates it.

MSQOriginal practice question

Which of the following rewrites preserve the value of the result for every input of the stated type?

  1. x * 2 → x << 1, for unsigned int
  2. x / 2 → x >> 1, for int
  3. x + 0 → x, for int
  4. x * 0 → 0, for double
  5. (a + b) + c → a + (b + c), for double

Answer: options 1 and 3 only

1 holds. For an unsigned type, a left shift by one is multiplication by two modulo the width, and the value is well defined even when it wraps.

3 holds. Adding the integer 0 to an integer is exact and has no overflow of its own.

2 fails. x = −3 gives −1 by division and −2 by the shift. C truncates toward zero; an arithmetic shift rounds down.

4 fails. NaN × 0 is NaN, and −1.0 × 0 is −0.0, which is distinguishable from 0 through 1/x.

5 fails. With 0.1, 0.2 and 0.3 the two groupings give 0.6000000000000001 and 0.6. Floating-point addition is not associative.

The habit. For each candidate, ask what the type's extremes do: negatives, zero, the largest value, NaN, and a value whose rounding is visible.

NATOriginal practice question

The basic block below has x and y live at its exit and nothing else. Apply constant folding, algebraic simplification, copy propagation, common subexpression elimination and dead-code elimination, repeating until nothing changes. How many instructions remain?

t1 = b + c
t2 = b + c
t3 = b * 4
t4 = 2 * 8
t5 = t1 + 0
t6 = t5
x  = t4 + t6
y  = b * 4
z  = 7

Answer: 4

What each pass removes. Folding turns t4 = 2 * 8 into 16. Simplification turns t5 = t1 + 0 into a copy of t1. Copy propagation makes t6 a copy of t1 and rewrites x = t4 + t6 to x = t4 + t1. Value numbering sees that t2 = b + c is the value already in t1 and that y = b * 4 is the value already in t3. Dead-code elimination removes z, which is not live out, and the copies t2, t5, t6, which no longer have uses.

The second round. With t4 known to be 16, the fold substitutes it into the addition, giving x = 16 + t1, and then t4 has no uses either.

What remains. t1 = b + c, t3 = b * 4, x = 16 + t1, y = t3 — four instructions.

The check. The page executes the original and the optimised block on all hundred pairs (b, c) with each from −3 to 6 and compares x and y. They agree on all hundred, so the count is four and the rewrite is sound.

MCQOriginal practice question

Which one of the following can not be decided from a single basic block together with its live-out set?

  1. Whether a constant expression can be evaluated at compile time
  2. Whether two computations in the block produce the same value
  3. Whether a variable used in the block was defined on every path reaching the block
  4. Whether an assignment in the block is read by any later instruction in the block

Answer: option 3 — that is a statement about the paths into the block

Why 1, 2 and 4 are decidable. Folding reads the block only. Value numbering reads the block only. Dead-code elimination reads the block plus the live-out set, which is given.

Why 3 is not. "Defined on every path reaching here" is a question about predecessors, and their predecessors, which is the whole control-flow graph. This is the must analysis of the data-flow lesson, not a block-local question.

The distinction. Local means "decided from this block plus the one fact the caller supplies". It does not mean "decided from this block alone", which is why the live-out set is part of the statement of every local pass.

One-screen revision sheet

Definitions, the three rules, the six rewrites, the guards and the traps. Everything on this tab fits on one screen and is worth re-reading the night before.

Definitions to reproduce exactly

Basic block: a maximal run of consecutive instructions with a single entry at the first and a single exit after the last.

Leader: the first instruction; any jump target; the instruction after any jump.

CFG: one node per block; an edge per jump and per fall-through.

Local optimisation: a rewrite justified by one block plus its live-out set.

The numbers that matter

Blocks = leaders. Block sizes sum to the instruction count.

Edges = jumps + fall-throughs. A block ending in a conditional jump has two successors; one ending in an unconditional jump has one; the last block has the exit.

DAG nodes = leaves + operators. DAG edges = one per operand position.

The six rewrites, one line each

Fold: both operands constant, and the machine may perform it.

Propagate a constant: the name is not reassigned in between.

Propagate a copy: neither name is reassigned in between.

Eliminate a common subexpression: no operand redefined in between.

Apply an identity: it holds for the type.

Reduce strength: the cheap form is identical on every input.

The five traps

1. Marking jump targets but not the lines after jumps.

2. Missing a backward jump target, which is every loop header.

3. Deleting a store or a call because "nothing reads it".

4. Reducing strength across a sign or a type where the cheap form rounds differently.

5. Answering a node-count question without stating whether leaves and the exit count.

Two sentences to remember

A block is what one scan can see, and the three leader rules are the scan's first step.

A rewrite is sound only if every input gives the same observable behaviour — and the machine, not the mathematics, decides what "same" means.
