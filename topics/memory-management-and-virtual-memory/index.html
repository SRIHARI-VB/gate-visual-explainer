Topic and objective

TOPIC: Memory management — logical against physical addressing, contiguous allocation and its fragmentation, paging and address translation, page table size and multi-level tables, the translation lookaside buffer and effective access time, demand paging and the page fault, the three replacement policies, Belady's anomaly and the stack property, the alternative table structures, segmentation, thrashing and the working set. This is the clause "Memory management and virtual memory" of Section 8 of the official GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Given a configuration — address width, page size, entry width, frames, hit ratio, fault rate — compute the split of an address into page number and offset, the size of a page table, the effective memory access time, and the number of page faults under a named policy; and say which of two policies can show the anomaly and why.

I read this topic as one arithmetic and one simulation. The arithmetic turns a configuration into bits, bytes and nanoseconds; the simulation turns a reference string into frame contents and fault counts. Almost every question in this topic is one of those two, so the animation does both and prints its work.

Prerequisites

  • Powers of two. The whole topic is exponent arithmetic. If 210 = 1 KB, 220 = 1 MB and 230 = 1 GB are not automatic, revise them first.
  • Processes and threads. A page table is per process, and a context switch changes which table the hardware uses. Built in Processes, Threads and IPC.
  • Memory hierarchy and cache. A TLB is a cache of translations, and the language of hit ratio and effective access time comes from there. Built in Memory Hierarchy and Cache.
  • Binary search trees and heaps, only as a comparison. B and B+ trees are the file-system half of this clause and are a separate lesson; nothing here depends on them.

Nothing from Digital Logic is assumed. Where a claim depends on the hardware — that the page table lives in memory, that a TLB miss costs one extra reference per level — the assumption is stated in the scene.

The five ideas to leave with

  1. An address is a page number and an offset. Only the page number is translated; the offset is copied. Offset bits are the base-two logarithm of the page size.
  2. Page table size is entries times entry width. Multi-level paging exists to keep each table inside one page, and it costs references rather than saving them.
  3. Effective access time is always a weighted average of written-out paths. The weights are the hit ratio or the fault rate, and the paths are where the marks are.
  4. A page fault count is a simulation, not a memory test. Draw one column per reference, evict by the rule the policy names, and mark every fault including the first touch of each page.
  5. Belady's anomaly is a property of first in first out, not of paging. It cannot happen for a policy whose priority order does not depend on the frame count — recency and next-use distance are such orders, arrival time is not.

Intuition: a library that lends by the shelf

A library lends shelf space, not bookshelves of a fixed size. A reader arrives wanting four metres; the librarian finds the first gap of at least four metres and hands over the front of it. Gaps appear and disappear as readers come and go, and eventually a reader wants six metres while the library has nine metres free in three separate gaps of three. Nothing is wrong with the arithmetic; the space is simply the wrong shape.

The fix a paging system makes is to stop lending metres and start lending fixed one-metre slots. Then any request of six metres becomes six slots, and any free slot will do. That is the whole idea of paging, and it is why a page table is needed: the six slots are scattered, so something has to remember which slot holds which metre of the reader's text.

Educational interpretation The analogy fixes two things: fragmentation is about the largest free run rather than the total, and paging trades a lookup for the freedom to place any page anywhere. It says nothing about which page to evict when memory is full, which is the replacement material below.

Formal definitions

  • Logical address — an address as the program sees it, relative to the start of its own space.
  • Physical address — an address on the memory bus, produced by the memory management unit.
  • Page — a fixed-size block of a process's address space. Frame — a block of physical memory of the same size.
  • Page table — one entry per page, holding the frame number and control bits.
  • Internal fragmentation — waste inside the last page or partition of an allocation.
  • External fragmentation — enough total free memory, but no single run large enough.
  • TLB — a small cache of recent page-number to frame-number translations.
  • Page fault — an access to a page whose valid bit is clear, so it is not in memory.
  • Demand paging — loading a page only when it is first touched.
  • Thrashing — a state where the resident working sets do not fit, so faults feed on themselves.
  • Working set — the pages a process has used in the last delta references.

The arithmetic, symbol by symbol

offset bits = log2(page size) "How many bits are needed to name a byte inside one page." A 4 KB page needs 12.

page bits = address bits − offset bits "Everything above the offset names the page." A 32-bit address with 4 KB pages leaves 20.

page table bytes = 2page bits × entry width "One entry per page, each entry a fixed width." 220 × 4 B = 4 MB.

physical = frame × page size + offset "The frame number moves in front of the offset; the offset itself does not change."

Four lines answer the structural half of this topic. Notice that none of them mentions the size of physical memory: the page table is per process and indexes that process's pages.

What every answer depends on

  • Where the page table lives. If it is in memory, a miss costs one reference per level; if a cache or a register holds it, fewer. Questions usually say.
  • What a fault costs. A clean victim costs one disk transfer, a dirty victim two. If the question gives "page transfer time" rather than "page fault service time", say which reading you used.
  • Whether the fault rate applies to accesses or to misses. A page cannot fault on a TLB hit, so the two readings differ by a factor of the miss ratio.
  • Initial frame contents. "All frames initially empty" and "the first k pages are already resident" give different counts.
  • Ties in optimal. When two resident pages are never used again, either may be evicted and the fault count is the same.

From structure to time, and from time to simulation

The build-up so far is about space: where a page sits and how the table records it. The second half is about time: what a translation costs, what a fault costs, and which page should leave when there is no free frame. The bridge is that both halves are the same kind of arithmetic — a weighted average of written-out paths — and the same kind of verification, a number recomputed rather than remembered.

That is why this is one lesson rather than three: the page table makes the TLB necessary, the TLB miss makes the page fault visible, and the page fault is what forces a replacement decision. Cut the chain anywhere and the later parts become formulas to memorise.

The three replacement policies

  • First in first out (FIFO) — evict the page that has been resident longest. A queue; a hit does not change the order.
  • Least recently used (LRU) — evict the page whose most recent use is oldest. A stack ordered by last use; a hit moves the page to the top.
  • Optimal (OPT, MIN) — evict the page whose next use is furthest in the future. Needs the future, so it is a lower bound rather than an implementation.
  • Second chance / clock — FIFO with a reference bit, so a recently used page gets one reprieve. An approximation of LRU.

The two time formulas

EMAT = h(ttlb + tmem) + (1 − h)(ttlb + 2tmem) "A hit pays the buffer plus one memory access; a miss pays the buffer plus two." Weight by the hit ratio h.

EAT = (1 − p)·tmem + p·tservice "With probability 1 − p the access is normal; with probability p it pays the fault service time instead."

Both are weighted averages of two paths. Neither is a law of nature: the first assumes a one-level page table in memory, the second assumes the fault rate is per access and that the service time already includes the transfer. Change either assumption and the formula changes.

The words that decide the question

  • "Initially empty" — every first touch is a fault, and they all count.
  • "In megabytes" — the unit is part of the answer; 4 and 4194304 are the same quantity and only one is marked right.
  • "The page table is in memory" — a miss costs one extra reference per level.
  • "Round to one decimal place" — a rate, not a count. Nine fifteenths is 0.6, not 9.
  • "Dirty pages are written back" — add a second transfer to the miss path.

Worked examples, page 1 of 2 — space

Every number below is produced by the model in this lesson and re-checked on load. Where a step is a definition rather than a calculation, the step says so.

Example 1 — first-fit against best-fit on the same holes

Holes of 100, 500, 200, 300 and 600 K; requests of 212, 417, 112 and 426 K, in that order.

1. First-fit. 212 into the 500 hole (288 left), 417 into the 600 hole (183 left), 112 into the remainder of that first hole (176 left). The scan restarts from the bottom each time.

2. The fourth request needs 426. The holes left are 100, 176, 200, 300 and 183, so the largest is 300 and it waits. Three of four placed, with 959 K free in total.

3. Best-fit. 212 into the 300 hole (88 left), 417 into the 500 hole (83 left), 112 into the 200 hole (88 left), 426 into the 600 hole (174 left).

4. All four placed, leaving 100, 83, 88, 88 and 174. Both runs conserve total memory: the free list plus the placed requests equals 1700 K in each case.

Mathematical derivation The difference is not arithmetic but order: first-fit spends the big hole early and has nothing left for the big request.

Example 2 — one address, translated

32-bit logical address, 4 KB pages, page 3 sits in frame 7, offset 498.

1. 4 KB is 212, so the low 12 bits are the offset and the high 20 bits are the page number.

2. The entry for page 3 holds frame 7. Physical address = 7 × 4096 + 498 = 29170.

3. Check: 29170 mod 4096 = 498. The offset came through unchanged, which is the invariant.

4. The same process of 10,000 bytes needs 3 pages, occupies 12,288 bytes and wastes 2,288.

Mathematical derivation The invariant "offset unchanged" is worth checking on every translation you write down; it catches a whole class of slips.

Example 3 — page table size, one level and two

32-bit addresses, 4 KB pages, 4-byte entries. This is GATE 2015 Set 1.

1. Pages = 232 / 212 = 220 = 1,048,576.

2. Size = 220 × 4 B = 222 B = 4 MB. The paper's key is 4.

3. Two levels: one table page holds 4096 / 4 = 1024 entries, so each level gets 10 bits, and 10 + 10 + 12 = 32.

4. Each level table is 1024 × 4 = 4096 B, which is exactly one page — the reason the split is 10 and 10 rather than 12 and 8.

Verified fact The question text and the key (4 MB) were confirmed against two independent reproductions of the GATE 2015 Set 1 paper.

Example 4 — the TLB, two paths and one average

GATE 2014 Set 3: 10 ms to search the buffer, 80 ms per memory access, hit ratio 0.6.

1. Hit path. 10 + 80 = 90 ms. The frame number comes from the buffer, then the data is read.

2. Miss path. 10 + 80 + 80 = 170 ms. The buffer fails, the page table entry is read, then the data.

3. Weight. 0.6 × 90 + 0.4 × 170 = 54 + 68 = 122 ms.

4. Sanity. 122 lies between 90 and 170, and a hit ratio of 1 would give exactly 90.

Verified fact GATE 2014 Set 3, key 122 ms. One index numbers this question Q33 and another Q43; both quote the same numbers.

Worked examples, page 2 of 2 — time and faults

These four are the shapes the paper actually uses: a fault rate, a simulation, an anomaly, and a page count.

Example 5 — the fault rate in the time formula

GATE 2011: memory access 20 ns, fault service 10 ms, one fault per 106 accesses.

1. Convert: 10 ms = 107 ns. This is the step where the marks are lost.

2. EAT = (1 − 10−6) × 20 + 10−6 × 107 ≈ 20 + 10 = 30 ns.

3. The same formula at 10−3 gives 19.98 + 10,000 ≈ 10,019.98 ns.

4. A thousandfold rise in the fault rate is a 334-fold rise in time, because the second term dominates once p is not tiny.

Verified fact GATE 2011 Q20, key 30 ns.

Example 6 — LRU simulated, cell by cell

GATE 2014 Set 3: string 4, 7, 6, 1, 7, 6, 1, 2, 7, 2 with 3 frames, all empty.

1. 4, 7, 6 fill the frames: three faults.

2. 1 faults and evicts 4, the least recently used: four faults.

3. 7, 6, 1 are hits, in that order, so the recency order becomes 7, 6, 1 → 6, 1, 7 → 1, 7, 6.

4. 2 faults, evicting 7. 7 faults, evicting 6. 2 is a hit. Total six faults, four hits.

Verified fact GATE 2014 Set 3 Q20, key 6. The simulation on the Animation tab reproduces every cell independently.

Example 7 — Belady's anomaly, measured

String 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5, simulated with three frames and with four.

1. FIFO. 9 faults with three frames, 10 with four. More memory, more faults.

2. LRU. 10 with three, 8 with four. Fewer, as expected.

3. Optimal. 7 with three, 6 with four. Also fewer, and the smallest of the three.

4. Inclusion test. The three-frame resident set is a subset of the four-frame set at every step for LRU and optimal, and not for FIFO — the failing step is where the anomaly is created.

Mathematical derivation This is the standard textbook string for the anomaly; the counts here are recomputed, not quoted.

Example 8 — how many pages a two-level table needs

GATE 2024 Set 2: 32-bit system, 4 KB pages, 4-byte entries, 2000 distinct pages touched, outer table allocated at creation.

1. One table page holds 4096 / 4 = 1024 entries, so the 20-bit page number splits 10 and 10.

2. Minimum. Two inner pages hold 2048 entries, enough for 2000, plus one outer page: 3.

3. Maximum. One valid entry in each of as many inner pages as possible; the outer table has 1024 entries, so at most 1024 inner pages: 1025.

4. The paper asks for X + Y = 3 + 1025 = 1028.

Verified fact GATE 2024 Set 2 Q54, key 1028.

Boundaries, counterexamples and the condition each one violates

Each card names the smallest example that breaks a tempting rule, and the exact assumption the rule needed.

Counterexample: optimal can tie with the best real policy

On 4, 7, 6, 1, 7, 6, 1, 2, 7, 2 with three frames, optimal takes 5 faults and LRU takes 6 — a gap of one. On other strings the gap is zero.

Condition violated by the tempting rule: "optimal is much better than LRU" needs a long string with a repeating pattern. On short strings the difference can vanish, so it cannot be used to identify a policy from its count.

Counterexample: one more frame can hurt

FIFO on 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 takes 9 faults with three frames and 10 with four.

Condition violated by the tempting rule: "more frames never hurt" needs the stack property, which FIFO does not have. Adding a frame changes which page is oldest at the next eviction.

Counterexample: a dirty victim costs double

A fault that evicts a page which has been written must write it back before reading the new one: two transfers, not one. A question that says "20% of faults are dirty" is telling you to weight the two.

Condition: the one-transfer fault path assumes a clean victim. Drop that and the miss path has two components.

Counterexample: a small page size is not automatically better

Smaller pages waste less inside the last page and allow finer sharing, but they mean more entries, a bigger page table, more TLB pressure, and more faults per byte of data. The trade is real and the paper sometimes asks for it.

Condition: "less internal fragmentation is better" ignores the table size and the fault rate. All three move together.

Boundary: the last page of a process

A process of exactly 4096 bytes needs one page and wastes nothing. A process of 4097 bytes needs two pages and wastes 4095 bytes — almost an entire page. Internal fragmentation is worst just after a page boundary, and that is where the exam numbers are chosen.

A process of size zero is a special case with no pages at all; a question that gives a process size in bytes and asks for pages wants the ceiling, not the floor.

Boundary: the fault rate that applies to misses

A page cannot fault on a TLB hit, so a stated fault rate is either per access or per miss. GATE 2020 Q53 gives a hit ratio and a fault rate and the two readings give answers that differ by roughly a factor of five; the official key accepts the per-miss reading.

Read the sentence twice. If it says "page fault rate is 10%" with no reference, say which reading you used and why.

Trap: ties in optimal and in LRU

When two resident pages will never be used again, optimal may evict either, and the fault count is unchanged. When two pages have the same last-use time under LRU — possible only if the question defines recency by something coarser than the reference — the choice matters.

Answer the count, not the frame contents, unless the question prints the frame table and asks you to fill it in.

Trap: the page table is not the frame table

An inverted page table has one entry per frame and is indexed by frame, so its size is memory divided by page size, times entry width. A normal page table is indexed by virtual page, so its size is address space divided by page size, times entry width.

The two formulas look alike and give wildly different numbers; the phrase "inverted" or "one entry per frame" is the only signal.

Six beliefs that cost marks

Each one names the belief, why it is tempting, the smallest counterexample, and the rule that replaces it.

1. "The whole address is translated"

Why it tempts: the word "translation" suggests a mapping of the address.

Minimal counterexample: offset 498 in page 3, frame 7: the answer 29170 ends in the same 498.

Correct rule: only the page-number field changes. Check the invariant "physical mod page size = offset" every time.

2. "Paging removes fragmentation"

Why it tempts: any page fits any frame, so nothing ever "does not fit".

Minimal counterexample: 10,000 bytes with 4 KB pages occupies 12,288 bytes and wastes 2,288.

Correct rule: paging removes external fragmentation and keeps internal fragmentation. Say which one the question means.

3. "More levels means faster translation"

Why it tempts: multi-level structures are usually presented as an improvement.

Minimal counterexample: two levels means two table references on a miss instead of one, before the data access.

Correct rule: multi-level paging saves space for sparse address spaces and costs time. The TLB, not the level count, is what makes translation fast.

4. "A page fault is an error"

Why it tempts: the word "fault" sounds like a failure.

Minimal counterexample: the first touch of every page of a program is a fault, and the program is correct.

Correct rule: a fault is the mechanism of demand paging. Only an access outside the process's legal pages is refused.

5. "More frames never hurt"

Why it tempts: more memory is more capacity, and the intuition is about capacity.

Minimal counterexample: FIFO, 1 2 3 4 1 2 5 1 2 3 4 5: 9 faults with three frames, 10 with four.

Correct rule: monotonicity needs the stack property. LRU and optimal have it; FIFO does not.

6. "LRU and FIFO give the same answer because both evict the oldest"

Why it tempts: both are queues, and on the first few references they agree.

Minimal counterexample: on the 2014 string they both give 6, which hides the difference; on 1 2 3 4 1 2 5 1 2 3 4 5 they give 10 and 9 with three frames.

Correct rule: FIFO orders by arrival and a hit does not reorder it; LRU orders by last use and a hit moves the page to the top.

One sentence that replaces all six

Every question here is either a configuration turned into bits and nanoseconds or a reference string turned into a frame table. Write the configuration as exponents, write the paths out, simulate the named policy, and read the answer off your own work.

The six question families, and the reasoning each demands

Families are ordered roughly from the most frequent to the least. Frequency here is a reading of indexed archives, not an official count.

1. Page fault count or rate under a named policy

Shape: a reference string, a frame count, a policy; find the faults, or the faults per access to one decimal place.

Reasoning: draw a table, one column per reference. Mark a fault on every first touch. Evict by the rule the policy names, and keep the policy's own order — arrival for FIFO, last use for LRU, next use for optimal.

Wrong approach: recalling a similar question. The counts are not portable between strings.

2. Address translation and page table size

Shape: address width, page size, entry width; find the bits per field, the number of entries, or the table size in a named unit.

Reasoning: convert everything to powers of two. Offset bits = log2 page size; page bits = the rest; size = 2page bits × entry width.

Wrong approach: using physical memory size instead of the logical address space, or answering in bytes when megabytes were asked for.

3. Effective access time with a TLB

Shape: buffer time, memory time, hit ratio, sometimes the number of levels; find the average access time.

Reasoning: write the hit path and the miss path with their reference counts, then weight by the ratio. Add one reference per level of page table on the miss path if the question gives several levels.

Wrong approach: charging two references on a hit, or ignoring the buffer time on a miss.

4. Effective access time with page faults

Shape: memory time, fault service time, fault rate, sometimes a dirty-page fraction; find the average access time.

Reasoning: (1 − p) × normal + p × service, with the service path including the write-back when the victim is dirty. Check whether the rate applies to accesses or to misses.

Wrong approach: mixing nanoseconds and milliseconds. Convert first, and write the unit beside every number.

5. Multi-level table occupancy

Shape: address width, page size, entry width, a number of distinct pages touched; find the minimum and maximum table pages, or their sum.

Reasoning: entries per table page = page size / entry size. Minimum packs the touched pages into as few inner tables as possible; maximum spreads them, bounded by the number of outer entries.

Wrong approach: using the number of touched pages as the maximum inner count, ignoring the outer table's capacity.

6. Anomaly, and comparisons between policies

Shape: which policy can show Belady's anomaly; or on this string, which relation holds between FIFO, LRU and optimal.

Reasoning: ask whether the policy's priority order depends on the frame count. If it does not — recency, next use — the anomaly is impossible and the count is non-increasing in frames.

Wrong approach: answering from the counts alone. Two policies can tie on one string, so the counts may not distinguish them.

The two sentences to carry into the exam

For structure: convert the configuration to powers of two, then offset bits from the page size and everything else from what remains. For behaviour: write the paths out, or simulate the named policy column by column — never quote a number you did not produce on this question.

NATEasyPYQ — GATE CSE 2015 Set 1

Consider a system with byte-addressable memory, 32-bit logical addresses, 4 kilobyte page size and page table entries of 4 bytes each. The size of the page table in the system in megabytes is ______.

Answer: 4

Pages = 232 / 212 = 220. Size = 220 × 4 B = 222 B = 4 MB.

The question asks for megabytes, so 4194304 is the same quantity in the wrong unit. One index numbers this item Q12 and another Q29; the wording and the key (4) are the same in both.

NATMediumPYQ — GATE CSE 2014 Set 3, Q20

A system uses 3 page frames for storing process pages in main memory. It uses the least recently used page replacement policy. Assume that all the page frames are initially empty. What is the total number of page faults that will occur while processing the page reference string 4, 7, 6, 1, 7, 6, 1, 2, 7, 2?

Answer: 6

4, 7, 6 fill the frames (three faults). 1 faults and evicts 4. Then 7, 6, 1 are hits. 2 faults and evicts 7; 7 faults and evicts 6; 2 is a hit. Six faults, four hits.

The trap is evicting by frame position rather than by last use: after the three hits the recency order is 1, 7, 6, which is not the arrival order.

NATMediumPYQ — GATE CSE 2022, Q64

Consider a demand paging system with four page frames (initially empty) and LRU page replacement policy. For the page reference string 7, 2, 7, 3, 2, 5, 3, 4, 6, 7, 7, 1, 5, 6, 1 the page fault rate, defined as the ratio of number of page faults to the number of memory accesses (rounded off to one decimal place) is ______.

Answer: 0.6

Faults occur on 7, 2, 3, 5, 4, 6, 7, 1 and 5: nine faults in fifteen accesses. 9 / 15 = 0.6.

(a) Dividing by the number of distinct pages (six) instead of the fifteen accesses, and (b) counting only the faults after the frames fill, are the two wrong answers the options are built around.

MCQMediumPYQ — GATE CSE 2011, Q20

Let the page fault service time be 10 ms in a computer with average memory access time being 20 ns. If one page fault is generated for every 106 memory accesses, what is the effective access time for the memory?

(A) 21 ns   (B) 30 ns   (C) 23 ns   (D) 35 ns

Answer: (B) 30 ns

10 ms = 107 ns. EAT = (1 − 10−6) × 20 + 10−6 × 107 ≈ 20 + 10 = 30 ns.

(A) is what you get by taking 10 ms as 106 ns, which is the unit slip the question is testing. The option letters here are reconstructed; the keyed value 30 ns is not.

MCQMediumPYQ — GATE CSE 2010

A system uses FIFO policy for page replacement. It has 4 page frames with no pages loaded to begin with. The system first accesses 100 distinct pages in some order and then accesses the same 100 pages but now in the reverse order. How many page faults will occur?

(A) 196   (B) 192   (C) 197   (D) 195

Answer: (A) 196

The forward pass faults on all 100, and the four frames end holding the last four pages. The reverse pass begins with those four, so four hits, then 96 faults. 100 + 96 = 196.

The closed form is n + (n − k) for k frames. (C) and (D) come from miscounting the overlap; (B) from assuming eight hits. One index numbers this Q34 and another Q24.

NATHardPYQ — GATE CSE 2024 Set 2, Q54

A 32-bit system has 4 KB page size and 4-byte page table entries, and uses a 2-level page table with an outer page directory and an inner page table. The outer directory is allocated as one page at process creation; an inner page is allocated only if it holds at least one valid entry. An active process accesses 2000 unique pages and none is swapped out. Let X be the minimum and Y the maximum number of pages across the two levels. X + Y is ______.

Answer: 1028

One table page holds 1024 entries. Minimum: ceil(2000 / 1024) = 2 inner pages plus 1 outer = 3. Maximum: one valid entry in each of up to 1024 inner pages (the outer table's capacity) plus 1 outer = 1025. 3 + 1025 = 1028.

Answering 2001 for the maximum is the standard error: the outer table can point at no more than 1024 inner pages, so the address space bounds the count, not the 2000 touched pages.

NATHardPYQ — GATE CSE 2025 Set 1, Q54

In the optimal page replacement algorithm all future references are known. A modification predicts only the next 4 page references, including the current one, when a frame is allocated. A process accesses pages 1, 3, 2, 4, 2, 3, 1, 2, 4, 3, 1, 4. With three initially empty frames, the number of page faults is ______.

Answer: 6

Pages 1, 3, 2 fill the frames (three faults). 4 faults; inside the window 4, 2, 3, 1 the resident pages are next used at positions 5, 6 and 7, so the page used furthest away is evicted. 2 and 3 hit. 1 faults and evicts the page whose next use inside 1, 2, 4, 3 is furthest. 2 and 4 hit. 3 faults and evicts the page absent from the window. 1 and 4 hit. Six faults.

Full optimal also gives six here, so the lookahead costs nothing on this string. The error the question is built to catch is using unlimited lookahead, which gives the same count here but not the same table.

MCQHardOriginal GATE-style

A system has 32-bit virtual addresses, 4 KB pages and 4-byte page table entries, and uses a two-level page table in which each level's table occupies exactly one page. Which one of the following is TRUE?

(A) The offset is 12 bits and the two index fields are 10 bits each.
(B) The offset is 12 bits and the two index fields are 11 and 9 bits.
(C) The offset is 12 bits, the two index fields are 10 bits each, and the two levels reduce the number of memory references per access.
(D) The offset is 14 bits because the table has two levels.

Answer: (A)

4 KB is 212, so the offset is 12 bits and 20 bits name the page. One table page holds 4096 / 4 = 1024 = 210 entries, so a level that occupies exactly one page can index at most 210 entries. Splitting 20 into 10 and 10 satisfies that exactly, and 10 + 10 + 12 = 32.

(B) fails the constraint: an 11-bit level needs 211 entries, which is 8192 bytes, two pages, not one. (C) is false for the reason the third misconception names: two levels means more references per access, not fewer. (D) confuses the level count with the page size, which alone fixes the offset. This question is original.

Revision sheet

Definitions, the four arithmetic lines, the two time formulas, the three policies and the traps, in the order a question uses them.

Definitions, one line each

  • Logical address — what the program uses; physical — what the bus uses.
  • Page / frame — equal-sized block of the process / of memory.
  • Page table — one entry per page: frame number plus control bits.
  • Internal fragmentation — waste inside the last page.
  • External fragmentation — enough total free memory, no run large enough.
  • TLB — cache of recent translations.
  • Page fault — access to a page whose valid bit is clear.
  • Demand paging — load on first touch.
  • FIFO / LRU / OPT — evict by arrival, by last use, by next use.
  • Stack property — the resident set with n frames is contained in the set with n + 1.
  • Thrashing — working sets no longer fit, so faults feed on themselves.
  • Working set — pages used in the last delta references.

Formulas and their licences

offset = log2(page size); page bits = address bits − offset Licence: byte-addressable memory, page size a power of two.

table bytes = 2page bits × entry width Licence: a single-level table with one entry per page of the process.

physical = frame × page size + offset Licence: page and frame are the same size, so the offset is unchanged.

EMAT = h(ttlb + tmem) + (1 − h)(ttlb + 2tmem) Licence: one-level page table in memory; add tmem per extra level on the miss path.

EAT = (1 − p)tmem + p·tservice Licence: p is per access; add a second transfer when the victim is dirty.

None of these is universal. The first three are arithmetic facts given the configuration; the last two are models with assumptions written beside them.

Decision procedure

  1. Write the configuration as powers of two: address bits, page size, entry width, frames.
  2. Structure question → offset from the page size, page bits from the remainder, table size from entries × width.
  3. Time question → write the hit path and the miss path in full, then weight.
  4. Fault question → draw one column per reference, mark every first touch, evict by the named rule.
  5. Anomaly question → does the policy's priority order depend on the frame count?
  6. Table-count question → entries per table page, then pack (minimum) or spread (maximum) within the outer table's capacity.

The five traps

  1. Nanoseconds and milliseconds mixed in one expression.
  2. Translating the offset, which is copied through unchanged.
  3. Assuming multi-level paging is faster; it costs references and saves space.
  4. Assuming more frames never hurt; false for FIFO.
  5. Generalising a policy comparison from one reference string.

Two sentences

Structure: convert to powers of two, then offset bits from the page size and everything else from what remains. Behaviour: write the paths out, or simulate the named policy column by column — never quote a number you did not produce on this question.
