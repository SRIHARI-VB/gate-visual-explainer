Topic and objective

TOPIC: C fundamentals — types, operators and control flow, at the depth GATE CSE asks them inside "Programming in C".

LEARNING OBJECTIVE: Given a short C program, predict the value and the type of each expression by reasoning from four rules — the type a literal already has, integer promotion, the usual arithmetic conversions with unsigned beating signed, and short-circuit evaluation — then count a loop's iterations and trace a switch exactly, and recognise the cases where the standard defines no answer at all.

I read "C fundamentals" as the language rules that decide an answer: types, literals, conversions, operators, precedence, control flow. Pointers, arrays, recursion and structures each have their own lesson and are linked from here rather than repeated.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 4 of the official GATE 2027 CS syllabus (IIT Madras) opens with the words "Programming in C." The rest of the section lists data structures.

Class A does not mean "guaranteed to appear". It means the topic is inside the declared boundary, so a question on it is fair game. Historical frequency is an observation about past papers, not a prediction.

Nothing is formally required. Two things make this lesson much easier:

  • Binary and two's complement. The Number Representation and Arithmetic lesson covers bit patterns, the range $$-2^{n-1}$$ to $$2^{n-1}-1$$, and wraparound.
  • Truth tables and connectives. The Propositional Logic lesson covers the meaning of AND, OR and NOT, which C's &&, || and ! inherit — with one important difference, that C's versions can skip work.

Level 1 — Intuition: the measuring cup

A type is a measuring cup. The cup does not decide what you pour in; it decides how much fits, and what happens to the overflow.

An unsigned char is a 256-millilitre cup marked 0 to 255. Pour in 260 and the extra 4 millilitres spill, leaving 4. That spill is not an error — the cup is defined to behave that way.

A signed cup of the same size is marked $$-128$$ to $$127$$. Pour in 200 and the cup cannot report it. The standard says the result is up to the implementation, and every machine you will meet wraps it to $$-56$$. The cup is the same size; the scale printed on it is the declared type.

Level 2 — Formal: what the standard actually fixes

Integer conversion rank orders the integer types: char < short < int < long < long long, with each unsigned type sharing the rank of its signed counterpart.

Minimum ranges are fixed: int must hold at least $$-32767$$ to $$32767$$, and long at least $$-2147483647$$ to $$2147483647$$. Only sizeof(char) is fixed at exactly 1.

Integer promotion: a value of rank below int is converted to int if int can represent every value of its type, otherwise to unsigned int.

Usual arithmetic conversions: after promotion, if one operand is unsigned and its rank is at least the other's, the signed operand becomes unsigned; otherwise the wider type wins. Verified fact — this is the wording of C 6.3.1.8, as reproduced by cppreference.

Level 3 — Visual: why promotion exists at all

Arithmetic on a machine happens in registers of one width. Rather than have a separate add instruction for every narrow type, C converts narrow operands up to int and does the work once.

So char a, b; a + b is int arithmetic. The result is an int, and it can hold a value the operands could not.

That is the whole reason char c = 100; c + c is 200, not $$-56$$: the addition never happens in a char. Assigning 200 back into a char is a separate step, and that is where the wrap happens.

Level 4 — Worked: the same byte, read two ways

One byte, pattern 11001000, is 200 read unsigned and $$-56$$ read signed.

  1. signed char s = 200; 200 is not representable; the conversion wraps to $$-56$$. Implementation-defined, and every GATE machine wraps.
  2. unsigned char u = 200; 200 is representable, so it is stored unchanged. Same byte pattern.
  3. s + 1 s promotes to int $$-56$$ by sign extension; the sum is the int $$-55$$
  4. u + 1 u promotes to int 200 by zero extension; the sum is the int 201
  5. Store each back s+1 in a char is $$-55$$; u+1 in an unsigned char wraps to 201, still in range

Scene 3 draws exactly this, with the two extension arrows.

Level 5 — Boundaries: where the rules stop applying

Each rule has a condition. If the condition fails, the rule does not apply, and the answer is not "the same but different".

  • Promotion applies only to types of rank below int. It does not touch an int operand.
  • Unsigned wraparound applies only when the target type is unsigned. The same wrap on a signed target is undefined in arithmetic and implementation-defined in conversion.
  • Short circuit applies to && and || only. The bitwise & and | evaluate both sides.
  • Truncation towards zero is C99 and later. Before C99 the direction was implementation-defined for negative operands.
  • switch needs an integer controlling expression and constant labels. A double or a string cannot be switched on.

Level 6 — Edge cases that decide marks

Five that GATE has used repeatedly, in the order they bite:

  • -1 < 1u is false. Defined, and counter-intuitive.
  • INT_MIN / -1 is undefined, and so is INT_MIN % -1.
  • -7 / 2 is $$-3$$ and -7 % 2 is $$-1$$.
  • i++ + ++i in one expression is undefined: two unsequenced modifications of the same object.
  • A switch with no matching case and no default does nothing, not even an error.

Each of these is a question where the naive computation gives a number, and the number is wrong.

Level 7 — GATE application: what is actually asked

Almost every question in this topic has one of five shapes:

  1. Print the output of a short program value plus type plus control flow
  2. Count iterations or function calls loop form, short circuit, and side effects
  3. State whether an expression is defined overflow, unsequenced modification, division by zero
  4. Give the value of a comparison mixing signed and unsigned the conversion ladder
  5. Give the output of a switch with a missing break fall-through path

Level 9 — Consolidation: the five rules that do the work

Rule 1 — type of a literal. 42 is int; 42u unsigned; 3.0 double; 3.0f float; 'a' is int in C.

Rule 2 — promote narrow operands. Anything of rank below int becomes int before the operator runs, by sign extension if signed.

Rule 3 — one common type. Wider wins; at equal rank, unsigned beats signed. This is why -1 < 1u is false.

Rule 4 — no answer means no answer. Signed overflow, division by zero, and two unsequenced writes to one object are undefined. Say so instead of computing.

Rule 5 — control flow is a path. &&/|| skip the right operand when the answer is known; switch falls through until break; do-while runs at least once.

Every question in the practice set is one of these five, applied carefully.

Example 1 — the signed/unsigned comparison

Assume 32-bit int. What does this print?

int main(void){
  int a = -1;
  unsigned int b = 1;
  printf("%d\n", a < b);
  return 0;
}
  1. Promote both no promotion needed; both are already int-rank
  2. Common type unsigned has rank equal to int, so the signed operand becomes unsigned
  3. a becomes $$2^{32}-1 = 4294967295$$ unsigned conversion adds $$2^{32}$$ until the value fits
  4. Compare 4294967295 < 1 false
  5. Output: 0 %d prints the int value of the comparison, which is 0 or 1

Example 2 — the loop that counts itself

How many times does the body run?

int i;
for (i = 0; i < 5; i++)
  printf("%d ", i);
  1. Test i < 5 before each body execution for is a while with the bookkeeping moved
  2. Body runs for i = 0,1,2,3,4 five values satisfy the test
  3. At i = 5 the test fails and the loop exits the increment happens after the body, before the next test
  4. Output 0 1 2 3 4 — 5 iterations and 5 is printed nowhere

Change the test to i <= 5 and the answer is six iterations, ending with 5 printed. The comparison symbol is the whole question.

Example 3 — division and remainder with a negative

For int a = -7, b = 2; find a/b and a%b.

  1. True quotient $$-3.5$$ that is ordinary arithmetic, which C does not use for integers
  2. Truncate towards zero C99 fixed this direction; discard the fraction, keep the sign of the result
  3. a/b = $$-3$$ floor would have given $$-4$$
  4. Use the identity: $$(-3)\times 2 + a\%b = -7$$ so $$a\%b = -7 + 6$$
  5. a%b = $$-1$$ the remainder carries the sign of the dividend

Example 4 — one expression, grouped by the table

Evaluate 2 + 3 * 4 % 5 - 1.

  1. * and % share the highest level present multiplicative, left associative
  2. 3 * 4 = 12 leftmost of the pair
  3. 12 % 5 = 2 the result of the first feeds the second
  4. + and - are additive, left associative lower level, so they wait
  5. 2 + 2 - 1 = 3 left to right: (2+2) then −1

Example 5 — counting side effects

How many times is f called?

int calls = 0;
int f(void){ calls++; return 1; }

int main(void){
  int x = 0 && f();
  int y = 1 || f();
  int z = 1 && f();
  printf("%d %d %d %d\n", x, y, z, calls);
}
  1. 0 && f() left is false, so the result is already 0; f is not called
  2. 1 || f() left is true, so the result is already 1; f is not called
  3. 1 && f() left is true, so the right must be evaluated; f is called once
  4. Output 0 1 1 1 three expressions, one call

Replace && with & in the first line and f is called twice: the bitwise operator has no short circuit.

Example 6 — the switch trace

int x = 2, a = 0, b = 0, c = 0;
switch (x) {
  case 1: a++;
  case 2: b++;
  case 3: c++; break;
  default: a = 99;
}
printf("%d %d %d\n", a, b, c);
  1. Jump to case 2 the controlling expression matches it
  2. b++ b becomes 1
  3. Fall through into case 3 nothing stopped execution
  4. c++ then break c becomes 1, and break leaves the switch
  5. Output 0 1 1 a was never touched, and default was never reached

Example 7 — the char that is not a number you expected

Assume plain char is signed, 8 bits. What prints?

char c = 200;
printf("%d %d\n", c, c + 1);
  1. 200 does not fit in a signed 8-bit char range is $$-128$$ to $$127$$
  2. Stored value $$200-256 = -56$$ implementation-defined conversion; every GATE machine wraps
  3. c + 1 promotes c to int first sign extension keeps $$-56$$
  4. So the sum is the int $$-55$$ not a char, and not 201
  5. Output -56 -55 %d reads both as int

INT_MIN / -1 has no answer

With 32-bit int, INT_MIN is $$-2147483648$$. Its negation, $$2147483648$$, is not representable.

So the quotient of INT_MIN / -1 cannot be stored, and the standard makes both / and % undefined there.

Counterexample to "the remainder is always 0 when the division is exact". INT_MIN % -1 is not 0; it is undefined. On many machines it traps, which is why x % -1 is not a safe zero test.

Two writes to one object, no sequencing

int i = 5; i = i++ + ++i; has no defined answer. The two modifications of i are unsequenced with respect to each other.

Different compilers, and different optimisation levels of the same compiler, produce different numbers here. That is the signature of undefined behaviour, not of a hard question.

What is fine: i++; then i + 1 as separate statements, and a[i] = i++; is not fine either — it is the same defect in a quieter form.

The remainder takes the dividend's sign

Four cases, all forced by $$(a/b)\times b + a\%b = a$$:

aba/ba%b
7231
-72-3-1
7-2-31
-7-23-1

The quotient's sign is the mathematical sign; the remainder's sign follows a. Both are computed by the page's model and checked against the identity.

The unsigned countdown that cannot end

for (unsigned i = 3; i >= 0; i--) printf("%u ", i);

The test i >= 0 is always true, because an unsigned value is never negative. After 0 the step wraps to 4294967295 and the loop keeps going.

This is defined behaviour, and that is what makes it dangerous. Nothing is undefined; the program simply never finishes. The fix is i-- > 0, or a signed counter.

Bitwise sits below equality

Because & has lower precedence than ==, the expression a & b == c parses as a & (b == c).

So it computes either a & 0 or a & 1 — almost never what was meant.

Counterexample. With a = 6, b = 3, c = 3: the intended test "is the low bit of a&b equal to c" gives 6&3 = 2, and 2 == 3 is false. The actual parse gives 3 == 3 = 1, then 6 & 1 = 0. Both are falsy, but for entirely different reasons — and with other values the two answers diverge.

sizeof does not evaluate its operand

Except for variable-length arrays, the operand of sizeof is not evaluated. Its type is what gets measured.

int i = 0;
size_t n = sizeof(i++);
/* n is 4; i is still 0 */

So a side effect written inside sizeof never happens. This is the mirror image of short circuit: both are cases where text on the page does not run.

A switch that matches nothing does nothing

With no matching case and no default, control passes to the statement after the switch. There is no diagnostic and no assignment.

switch (x) {           /* x = 9 */
  case 1: y = 1; break;
  case 2: y = 2; break;
}
/* y keeps whatever it had */

Compare this with an if / else if chain, where the same omission is equally silent. Both are legal; both are where marks are lost.

Floating to integer out of range is undefined

Converting a floating value that the integer type cannot represent is undefined behaviour, not a wrap.

int x = 1e20; and int y = -1.0 * 0 + 3e9; are both undefined on a 32-bit int.

Note the asymmetry that trips people up: an integer conversion to unsigned wraps and is defined; a floating conversion to unsigned out of range is undefined. Verified fact — cppreference states both rules explicitly.

Misconception 1 — "minus one is less than one, so -1 < 1u is true"

1. The belief. The comparison is done on the numbers, and $$-1 < 1$$, so the expression is true.

2. Why it seems right. Both operands are integers, the operator is <, and the arithmetic fact is not in dispute. Nothing in the source text mentions a conversion.

3. Why it is wrong. The comparison is not performed on the values you wrote. Both operands are first converted to a common type, and the common type here is unsigned int, so the $$-1$$ becomes 4294967295 before the test.

4. Minimal counterexample.

int a = -1;
unsigned int b = 1;
printf("%d\n", a < b);   /* 0 */
printf("%d\n", a < 1);   /* 1 */

5. Correct rule. Promote both operands, then the wider type wins and unsigned beats signed at equal rank. If the signed value is negative, its unsigned reading is enormous.

6. Question that exposes it. Practice Q2 and Q9.  7. Visual. Animation scene 4 shows the $$-1$$ box being rewritten as 4294967295 before the comparison runs.

Misconception 2 — "char arithmetic happens in a char"

1. The belief. char c = 100; then c + c is 200 stored in a char, so it wraps to $$-56$$ immediately.

2. Why it seems right. The operands are char, the result is stored in a char, so the whole thing feels like char work.

3. Why it is wrong. Integer promotion lifts both operands to int before the +. The sum is the int 200. The wrap only happens if and when you assign that 200 back into a char.

4. Minimal counterexample.

char c = 100;
printf("%d\n", c + c);   /* 200 */
printf("%d\n", (char)(c + c)); /* -56 */

5. Correct rule. Anything of rank below int is promoted first. The result of the operator has the promoted type, so c + c is an int expression.

6. Question that exposes it. Practice Q4 and Q7.  7. Visual. Animation scene 3 lifts the byte into a 32-bit box and shows the sum widening, not wrapping.

Misconception 3 — "signed overflow wraps around, so INT_MAX + 1 is INT_MIN"

1. The belief. Two's complement wraps, so adding one to the largest int gives the most negative int, and that is the answer to write down.

2. Why it seems right. On the hardware it usually does wrap, and the Number Representation lesson shows wraparound as a real, computable rule for bit patterns.

3. Why it is wrong. The wrap is a fact about bit patterns, not a promise about C. The standard says signed overflow is undefined behaviour: the compiler may wrap, may trap, or may assume it never happens and delete the code that would have detected it.

4. Minimal counterexample.

int x = INT_MAX;
if (x + 1 < x) puts("wrapped");
/* the compiler may remove this
   test entirely, since x+1 < x
   is assumed impossible */

5. Correct rule. Unsigned arithmetic is defined modulo $$2^n$$. Signed arithmetic that overflows is undefined. If you want defined wrap, compute in an unsigned type.

6. Question that exposes it. Practice Q6 and Q11.  7. Visual. Animation scene 5 draws the unsigned odometer rolling, then puts a blank card where the signed answer would be.

Misconception 4 — "&& is just a slower &"

1. The belief. Both operands are evaluated either way; the only difference is that && gives 0 or 1 instead of a bit pattern.

2. Why it seems right. On values that are already 0 or 1, the two operators agree on every input. Truth tables confirm it.

3. Why it is wrong. They agree on values, not on evaluation. && is guaranteed to skip its right operand when the left decides the answer; & is guaranteed to evaluate both.

4. Minimal counterexample.

int i = 0;
int a = 0 && ++i;   /* i stays 0 */
int b = 0 &  ++i;   /* i becomes 1 */

5. Correct rule. && and || sequence their operands left to right and stop early. The bitwise operators do neither, and applying them to non-boolean values gives a different numeric result as well.

6. Question that exposes it. Practice Q8 and Q12.  7. Visual. Animation scene 8 shows the right-hand box greyed out and the side-effect counter staying at zero.

Pattern 1 — "what is the output"

A short program with two or three expressions whose types are not what they look like.

Procedure.

  1. Write the declared type of every variable next to it.
  2. For each expression, name the type before computing the value.
  3. Apply promotion, then the common-type rule.
  4. Only then compute. Then check the format specifier matches the type you found.

Step 2 is the one people skip. It is also the only step that catches the trick.

Pattern 2 — "how many times"

A loop or a function call hidden behind short circuit, asking for an iteration or call count.

Procedure.

  1. Identify the test and whether it runs before or after the body.
  2. List the values of the loop variable for which the test is true.
  3. Count them. Do not "count the lines".
  4. For nested loops, multiply only if the ranges are independent.
  5. For short circuit, cross out any operand that cannot be reached.

If a count is infinite, say so. An infinite loop is a valid answer, and often the intended one.

Pattern 3 — "is this defined?"

A question that offers the wrapped value, the mathematical value, and "undefined" as options.

The three sources of undefined behaviour in this topic:

  • signed overflow — INT_MAX + 1
  • division or remainder by zero, including INT_MIN / -1
  • two unsequenced modifications of one object — i++ + ++i

A fourth, quieter one: reading an object whose value was never set. GATE phrases it as "the output is not predictable".

Pattern 4 — "signed meets unsigned"

A comparison, a subtraction, or a loop bound where one side is unsigned.

Procedure.

  1. Find the unsigned operand. Its presence decides everything.
  2. If the ranks are equal, the signed side is converted; a negative value becomes huge.
  3. If the unsigned rank is smaller, and the signed type can hold all its values, the unsigned side converts instead — this is the long against unsigned int case.
  4. Then compare as plain unsigned integers.

Watch for sizeof, whose type is the unsigned size_t. It makes any comparison against it unsigned.

Pattern 5 — the switch trace

A switch with a missing break, or a default in an unexpected place.

Procedure.

  1. Evaluate the controlling expression once, to a value.
  2. Find the matching label. If none, find default. If neither, the switch does nothing.
  3. From there, execute downwards, entering every later case body.
  4. Stop at break or at the closing brace.
  5. Report every variable that changed, not just the first.

The answer is often two counters, not one. That is what makes the question discriminating.

Closely confused pair 1 — = against ==

if (x = 0) assigns 0, and the test is on the value 0, so the branch never runs. if (x == 0) compares.

The assignment is an expression whose value is the value stored, so it is always legal inside a condition. Some compilers warn under -Wall; the standard does not care.

Diagnostic habit: if a condition assigns, the branch taken is decided by the assigned value, not by the old one.

Closely confused pair 2 — i++ against ++i

As a statement they are identical. As a subexpression they differ in which value is used: i++ yields the old value, ++i the new one.

Both modify i exactly once. Using either twice on the same object in one expression without sequencing is undefined behaviour — that is the trap, not the prefix/postfix difference.

In a for header the value is discarded, so i++ and ++i give identical loop behaviour.

Closely confused pair 3 — break against continue

break leaves the innermost loop or switch entirely. continue skips the rest of the body and goes to the next iteration.

In a for loop, continue still runs the increment. In a while loop it does not — so a continue placed before the update produces an infinite loop.

Inside a switch inside a loop, break leaves the switch, not the loop. That nesting is a standard GATE trap.

The 30-second checklist for any C output question

1. Write each declared type. Note which are unsigned.

2. Name the type of each expression before its value.

3. Look for undefined behaviour: overflow, divide by zero, unsequenced writes.

4. Trace control flow as a path, not as lines of text.

5. Match the format specifier to the type.

If step 3 fires, the answer is "undefined" — and saying so is the correct answer.

MCQBasicOriginal GATE-style

What does this print?

int a = 5, b = 2;
printf("%d", a / b);
  1. 2.5
  2. 2
  3. 3
  4. 0

Answer: B — 2

Both operands are int, so the division is integer division: the quotient 2.5 is truncated towards zero, giving 2.

Common wrong answer: C (3). That is rounding to nearest. C never rounds in integer division; it truncates. Wrong answer A requires one operand to be floating: a / 2.0.

MCQModerateOriginal GATE-style

Assume 32-bit int. What is printed?

int a = -1;
unsigned int b = 1;
printf("%d", a < b);
  1. 1
  2. 0
  3. -1
  4. 4294967295

Answer: B — 0

The common type of int and unsigned int is unsigned int, so a becomes 4294967295. Then 4294967295 < 1 is false, and a false comparison yields the int 0.

Common wrong answer: A. That is the mathematical comparison, computed without doing the conversion. D is the converted value of a, not the result of the comparison.

NATBasicOriginal GATE-style

How many times does the body of this loop execute?

int i;
for (i = 0; i < 10; i += 2)
  count++;

Answer as an integer.

Answer: 5

The values satisfying i < 10 are 0, 2, 4, 6, 8 — five values. At i = 10 the test fails.

Common wrong answer: 10. That counts i values as if the step were 1. Read the step expression, not just the bound.

MCQModerateOriginal GATE-style

Assume char is signed, 8 bits, and int is 32 bits. What is printed?

char c = 100;
printf("%d", c + c);
  1. -56
  2. 200
  3. 100
  4. undefined

Answer: B — 200

Integer promotion converts both c operands to int before the addition, so the sum is the int 200. No char can hold it, but no char is involved in the addition.

Common wrong answer: A (-56). That is the answer to (char)(c + c), where the 200 is assigned back into a char. D is wrong: promotion and addition here are fully defined.

MCQModerateOriginal GATE-style

What are the values of a / b and a % b for int a = -7, b = 2;?

  1. -3 and -1
  2. -4 and 1
  3. -3 and 1
  4. -4 and -1

Answer: A — $$-3$$ and $$-1$$

The quotient truncates towards zero, so $$-3.5$$ becomes $$-3$$. The identity $$(a/b)\times b + a\%b = a$$ then forces $$a\%b = -7-(-6) = -1$$.

Common wrong answer: B. That is floor division and a positive remainder — the Python convention, not C's. C mixes the two conventions, and fails the identity: $$(-3)\times 2 + 1 = -5 \neq -7$$.

MSQHardOriginal GATE-style

Assume 32-bit int and two's complement. Which of these expressions have undefined behaviour in standard C?

  1. INT_MAX + 1
  2. INT_MIN / -1
  3. int i = 1; i = i++ + ++i;
  4. unsigned u = UINT_MAX; u = u + 1;

Answer: A, B, C

A — signed overflow is undefined. B — the quotient is not representable, so both / and % are undefined there. C — two unsequenced modifications of i.

D is defined: unsigned arithmetic is modulo $$2^{32}$$, so u becomes 0. That is the option people mark by mistake, because the bit pattern wraps exactly as in A — the difference is the declared type, not the machine.

NATModerateOriginal GATE-style

Assume char is signed, 8 bits. What is printed?

char c = 200;
printf("%d", c);

Answer as an integer.

Answer: -56

200 is outside $$[-128, 127]$$, so the conversion wraps: $$200 - 256 = -56$$. The conversion is implementation-defined, and every machine GATE uses wraps this way.

Common wrong answer: 200. That assumes an unsigned char. The question states signed; that word is the whole question.

NATModerateOriginal GATE-style

How many times is f called?

int calls = 0;
int f(void) { calls++; return 1; }
int main(void) {
  int x = 0 && f();
  int y = 1 || f();
  int z = 1 && f();
  return 0;
}

Answer as an integer.

Answer: 1

Only the third line evaluates f(). In the first, the left operand 0 already decides the result; in the second, the left operand 1 already decides it.

Common wrong answer: 3. That counts the appearances of f() in the source. Short circuit is a guarantee, not an optimisation.

MCQHardOriginal GATE-style

What happens with this loop?

unsigned int i;
for (i = 10; i >= 0; i--)
  printf("%u ", i);
  1. Prints 10 down to 0, then stops
  2. Prints 10 down to 0, then wraps and never stops
  3. Prints nothing
  4. It is undefined behaviour

Answer: B

An unsigned value is never negative, so i >= 0 is always true. After printing 0, i-- wraps to 4294967295 and the loop continues.

Common wrong answer: A. That is the signed version. D is wrong and important: the wrap is defined behaviour. The program does not misbehave; it runs forever.

MCQModerateOriginal GATE-style

What is printed?

int x = 2, a = 0, b = 0, c = 0;
switch (x) {
  case 1: a++;
  case 2: b++;
  case 3: c++; break;
  default: a = 99;
}
printf("%d %d %d", a, b, c);
  1. 0 1 0
  2. 0 1 1
  3. 99 0 0
  4. 1 1 1

Answer: B — 0 1 1

Execution jumps to case 2, increments b, falls into case 3, increments c, then break exits. a is never touched and default is never reached.

Common wrong answer: A. That assumes each case stops at its end. C assumes default always runs.

MCQHardOriginal GATE-style

For 32-bit int, what is the value of INT_MIN % -1?

  1. 0
  2. -1
  3. 1
  4. The behaviour is undefined

Answer: D — undefined

The remainder is defined only when the quotient is representable. Here $$INT\_MIN / -1 = 2^{31}$$ does not fit in a 32-bit int, so both / and % are undefined.

Common wrong answer: A. The identity $$q\times b + r = a$$ with $$q = -2^{31}$$, $$b = -1$$ would give $$r = 0$$, which is why 0 feels forced — but $$q$$ itself is not representable, so the identity never applies. This is the pair that distinguishes "exact division" from "defined division".

NATHardOriginal GATE-style

Evaluate 2 + 3 * 4 % 5 - 1 in C. Answer as an integer.

Answer: 3

* and % share the multiplicative level and group left to right: 3*4 = 12, then 12%5 = 2. Then the additive level, left to right: 2 + 2 - 1 = 3.

Common wrong answer: 1. That comes from grouping as 3*(4%5), which contradicts left associativity at equal precedence. Another wrong answer: 8, from evaluating strictly left to right and ignoring precedence.

Definitions, one line each

Type
A set of values plus the operations allowed on them; for integers, a width and a signedness.
Conversion rank
The order char < short < int < long < long long, unsigned sharing its signed counterpart's rank.
Integer promotion
Converting a type of rank below int to int (or unsigned int) inside an expression.
Usual arithmetic conversions
The rule that gives two operands one common type: wider wins, unsigned beats signed at equal rank.
Undefined behaviour
No requirement at all: the standard permits anything, including a trap or a deleted check.
Implementation-defined
The implementation must choose and document a behaviour; it is not free.
Unspecified behaviour
The implementation may choose any of several behaviours, and need not document which.
Sequence point
A point where all side effects of earlier evaluations are complete; C11 replaces the term with "sequenced before".

Formulas and their conditions

unsigned range: 0 .. 2n − 1 n is the number of value bits. Wrap is modulo 2n.
signed range: −2n−1 .. 2n−1 − 1 Two's complement, which C23 makes mandatory. One extra negative value.
(a / b) × b + a % b = a Only when a/b is representable. This identity fixes both the quotient and the remainder.
quotient truncates towards zero Since C99. Before that, implementation-defined for negative operands.
signed → unsigned: add or subtract 2n until in range So −1 becomes 2n − 1. Defined, and often the answer.
sizeof('a') = sizeof(int), sizeof("a") = 2 In C. Character constant is int; string literal is char[2] with the null.

The precedence ladder, highest first

  1. postfix () [] . -> ++ -- left to right
  2. unary ! ~ + - * & ++ -- sizeof (cast) right to left
  3. multiplicative * / % left to right
  4. additive + - left to right
  5. shift << >> left to right
  6. relational < <= > >= left to right
  7. equality == != left to right
  8. bitwise &, then ^, then | three separate levels, all below equality
  9. logical &&, then || short circuit, left to right
  10. conditional ?: right to left
  11. assignment = += -= *= /= %= right to left
  12. comma , left to right, lowest of all

Traps, one line each

  • -1 < 1u is false. Equal rank, unsigned wins.
  • 1/2 is 0; 1/2.0 is 0.5.
  • -7/2 is $$-3$$; -7%2 is $$-1$$.
  • INT_MAX+1 and INT_MIN/-1 are undefined, not wrapped.
  • Unsigned wrap is defined; signed wrap is not.
  • i++ + ++i is undefined. One modification per sequence point.
  • a & b == c means a & (b == c).
  • sizeof(i++) does not increment i.
  • 0 && f() never calls f; & would.
  • for (unsigned i=n; i>=0; i--) never ends.
  • do-while runs its body at least once.
  • switch falls through; a missing break is silent.
  • break inside a switch inside a loop leaves only the switch.
  • if (x = 0) assigns and is always false.
