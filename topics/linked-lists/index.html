Topic and objective

TOPIC: Linked lists — the singly linked list, the doubly linked list, and the circular list, taught from pointer surgery upward.

LEARNING OBJECTIVE: Given a linked-list question, answer it from the code rather than from a remembered complexity: say which pointer must be updated and in what order, decide whether a given pointer makes an operation constant or linear, state what a splice does to a head pointer, and read a traversal as a sequence of field overwrites.

I read this topic as the mechanics of the links and the cost each representation buys, because every GATE question in it turns on one of three things: the order of two assignments, whether a pointer to the node was supplied, or whether the list terminates at NULL or closes into a ring. Arrays, stacks and queues are a separate lesson here and are linked from this page, not repeated.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 4 of the official GATE 2027 CS syllabus (IIT Madras) reads: "Programming in C. Recursion. Arrays, stacks, queues, linked lists, trees, binary search trees, binary heaps, graphs." The two words linked lists appear as a named item, between queues and trees.

Class A means a question on this is inside the declared boundary. It does not mean one is guaranteed. The previous-year questions quoted in this lesson are observations about old papers, not a forecast.

What you should be able to do afterwards

Take any linked-list question and answer, in this order: is a pointer to the node supplied?, which fields must change, and in what order?, does the head itself change, and can the function report that?

The most expensive mistake here is answering from the name of the structure instead of from its code. "Linked list, so insertion is O(1)" is false the moment the position has to be found.

Level 1 — Intuition: the treasure hunt

The array is a numbered corridor. Every door has a number, and the doors are all the same width, so you walk straight to door 40 without opening anything. The number is the address, and arithmetic gets you there.

The linked list is a treasure hunt. Each clue is written on a scrap of paper and tells you where the next scrap is. The scraps can be anywhere in the house. To reach the fifth clue you must read four of them.

But you can rewrite one clue. If a new scrap has to go between clue 3 and clue 4, you do not move any other scrap: you cross out one address and write another. That is the whole trade — you give up arriving quickly, and you buy cheap rearrangement.

Educational interpretation The treasure hunt is a good picture of following links and a poor one of memory layout: real nodes are allocated and freed, and a scrap nobody points at is a leak, not a lost treasure.

Level 2 — Formal definitions

Node. A record with a data part and one or more link parts. Each link holds the address of another node, or a null pointer.

Singly linked list. Every node holds one link, to its successor. The first node is named by a head pointer. The last node's link is NULL. There is no link back to the predecessor.

Doubly linked list. Every node holds two links: next to the successor and prev to the predecessor. The invariant is that both directions agree about every adjacency.

Circular list. The last node's link names the first node instead of NULL, so the chain closes into a ring. A ring is usually named by a rear or tail pointer, and the front is then one link away.

Length. Not stored. It is either counted by a walk or maintained as a separate field, and the second choice makes every mutation responsible for it.

The four operations, in words

insert x after p: x->next = p->next; p->next = x;

"Copy the old successor into the new node, then make p point at the new node." Two assignments, no search, no shifting.

delete the node after p: p->next = p->next->next;

"Make p skip its successor." Save the successor in a temporary first, or its memory is never freed.

doubly: x->next = b; x->prev = a; a->next = x; b->prev = x;

"Two links on the new node, one on each neighbour." Four writes, against two for the singly linked splice.

reverse: next = c->next; c->next = prev; prev = c; c = next;

"Save the way forward, turn this node round, step both cursors." Repeated n times, with prev starting at NULL.

The assumptions each one needs

The insert-after formula assumes p is not NULL and that p really is in the list. Neither is checked; both are the caller's promise.

The delete-after formula assumes p->next is not NULL — that is, p is not the last node. Otherwise the second ->next dereferences NULL.

The four-assignment doubly splice assumes both neighbours exist, so it is not the code for inserting at the two ends, where one neighbour is NULL and only two or three fields change.

Verified fact Dereferencing a null pointer is undefined behaviour in C (C11 6.5.3.2), so none of these preconditions is enforced by the language — a violation is not guaranteed to crash, which is worse.

Level 3 — Visual understanding: draw the fields, not the arrows

A node is two cells. The left cell holds the value; the right cell holds an address. Draw the address as a number inside the cell, not as an arrow, and every pointer question becomes bookkeeping.

Take three nodes at 1000, 2000, 3000 holding 10, 20, 30. The head holds 1000. Node 1000's link holds 2000; node 2000's link holds 3000; node 3000's link holds 0, which is NULL.

Now p->next = p->next->next with p at 1000 reads the link at 1000, which is 2000, then the link at 2000, which is 3000, and writes 3000 into the link at 1000. Node 2000 is now named by nothing.

Educational interpretation "Named by nothing" is the precise meaning of unreachable. In C the memory is still allocated, which is a leak; in a traced language it would be collected.

The doubly linked invariant

For every node b that has both neighbours, two equations must hold at all times:

b->next->prev == b and b->prev->next == b

"The node after me says I am before it; the node before me says I am after it."

Every doubly linked operation is judged by whether it leaves both equations true. A splice that updates only the forward direction leaves a list that walks forward correctly and backwards into the wrong node — silent corruption rather than a crash.

The page's model asserts this invariant after every operation, on every node, for every list it builds.

The ring, drawn

Five nodes on a circle. No NULL anywhere: node 5's link holds node 1's address. One pointer p names the rear.

Front is p->next. Dequeue removes it: p->next = p->next->next. Enqueue inserts after the rear and then moves the rear: new->next = p->next; p->next = new; p = new;

Both are constant time, and neither needs a second pointer. That is why the answer to GATE 2004 is "the rear node".

The picture that answers every ring question: ask what one link from the pointer reaches, and what needs two.

Where the drawing beats the code

A traversal of a circular list that tests while (p != NULL) never stops. Draw the ring and the missing exit is obvious; read the loop alone and it looks exactly like the traversal you have written a hundred times.

A splice drawn as an arrow from p to the new node hides the fact that the new node's link had to be filled before p's. Draw the two cells and the order becomes a fact about which value is still available.

Rule of thumb: the drawing tells you what the list looks like; the field values tell you when each write is safe. Questions are about the second.

Level 4 — Worked example: GATE 1998, by addresses

Given p at 1000, and the nodes after it at 2000, 3000, 4000. Run the four lines and write down each field after it.

  1. q = p->next → q holds 2000. No field changes; q now names the first of the two nodes to be swapped.
  2. p->next = q->next → the link at 1000 becomes 3000. p now skips 2000. 2000 is still named by q, so nothing is lost.
  3. q->next = (q->next)->next → q->next is 3000, so the link at 2000 becomes 4000. 2000 now skips 3000. 3000 is still named by the link at 1000.
  4. (p->next)->next = q → p->next is 3000, so the link at 3000 becomes 2000. 3000 now points at 2000. The chain reads 1000 → 3000 → 2000 → 4000.

The two nodes after p have swapped places. The page runs this on lists of length 3 to 8 and checks the value sequence at every length.

Level 4 — Worked example: GATE 2010 move_to_front

List 1, 2, 3, 4. The loop leaves p at the last node (4) and q at the one before it (3). Which blank moves 4 to the front?

  1. q->next = NULL → 3 now terminates the list: 1, 2, 3. The tail is detached first, while 4 is still named by p.
  2. p->next = head → 4 points at 1. The old front is still named by head, so it can be attached now.
  3. head = p → head names 4. Last, because until this line the old head was reachable only through head.

Result: 4, 1, 2, 3. The guard at the top returns early for an empty list and for a single node, so the loop always runs at least once and q is never NULL at the end.

The page simulates all four options for list lengths 1 to 6 and reports which ones actually move the last element to the front. Only option D does, at every length.

Level 5 — Boundaries: what breaks, and where

Empty list (head == NULL). Any code that reads head->next before testing head is undefined behaviour. This is the case GATE 2017 Set 1 tests in join.

One node. Its next is NULL, so it is simultaneously the first and the last node. Reversal, deletion and move_to_front all need the single-node case to work.

Last node. Deleting it needs its predecessor, which a singly linked list cannot reach from the node itself. Inserting after it works, but inserting before it does not.

Circular empty list. Represented as a NULL pointer, not as a node pointing at itself. A ring of one node points at itself, and that is a different, non-empty state.

The one sentence to carry

A linked list stores, in each node, exactly the information its operations need — one address for a singly linked list, two for a doubly linked list, and a closed ring for a circular one — and every complexity claim is a claim about which of those addresses you already hold.

If you know which pointer you were given, you know the cost. If you do not, you are guessing.

GATE CSE 1998, Q 19a — four assignments

"Let p be a pointer as shown in the figure in a single linked list. What do the following assignment statements achieve?" The four lines are q := p->next; p->next := q->next; q->next := (q->next)->next; (p->next)->next := q;

Answer: they swap the two nodes immediately after p. Trace with addresses 1000 (p), 2000, 3000, 4000: the links become 1000→3000, 3000→2000, 2000→4000.

Why the obvious reading fails. Line 4 reads (p->next)->next, not p->next. By line 4, p->next is the node that was third, so the field being written is the one after it. A reader who substitutes the original p->next writes into the wrong field and concludes the answer is a deletion.

Verified fact Question text and the "swaps the two nodes next to p" key confirmed on gateoverflow (question 1733, GATE CSE 1998 Q19a).

The check the page performs on it

The model builds lists of length 3 to 8, records the value sequence, runs the four assignments, and compares the result with the sequence that has positions 1 and 2 exchanged (0-based, after the head).

It also checks that the node count is unchanged and that no node became unreachable — a swap that loses a node would show up as a shorter sequence rather than a wrong order.

The animation shows the four field writes in order, so you can see which value is still available at each line.

GATE CSE 2010, Q 36 — move_to_front

"The following C function takes a singly-linked list as input argument. It modifies the list by moving the last element to the front... Some part of the code is left blank." After the loop, p is the last node and q the node before it.

Answer: D — q->next = NULL; p->next = head; head = p;

Why B is wrong: it assigns head = p before p->next = head, so the last node ends up pointing at itself and the rest of the list is lost. Why C is wrong: it makes the head point at the second-to-last node and reverses the tail instead of moving it. Why A is wrong: it never detaches the tail, so the list becomes circular.

Verified fact Question and key D confirmed on gateoverflow (question 2337, GATE CSE 2010 Q36); the paper itself is GATE 2010 CS, available from the IIT Roorkee archive.

GATE CSE 2017, Set 1, Q 08 — join

"Consider the C code fragment given below. ... Assuming that m and n point to valid NULL-terminated linked lists, invocation of join will" — the body walks p = n to the end and then sets p->next = m.

Answer: B — either cause a null pointer dereference or append list m to the end of list n.

A valid NULL-terminated list may be the empty list, in which case n is NULL and the very first test p->next != NULL dereferences NULL. If n is non-empty, the loop stops on the last node and the append is correct.

The trap: "valid" is read as "non-empty". The question's own wording, valid NULL-terminated, admits the empty list, and that is the only reading under which option B is true. Verified fact Key B confirmed on gateoverflow (question 118711).

GATE CSE 2023, Q 03 — SLLdel against DLLdel

"Let SLLdel be a function that deletes a node in a singly-linked list given a pointer to the node and a pointer to the head... Let n denote the number of nodes."

Answer: D — SLLdel is O(n) and DLLdel is O(1).

A singly linked node does not name its predecessor, and the predecessor's link is the field that must change. So SLLdel walks from the head. A doubly linked node names its predecessor, so DLLdel rewrites two fields.

The wrong answer this question is built to catch: "copy the successor's data into the given node, then unlink the successor — O(1)". That trick fails when the given node is the last one, because there is no successor to copy. The question asks for the worst case, so the trick does not rescue the bound. Verified fact Key D confirmed on gateoverflow (question 399309).

GATE CSE 2004, Q 36 — one pointer for a queue

"A circularly linked list is used to represent a Queue. A single variable p is used to access the Queue. To which node should p point such that both the operations enQueue and deQueue can be performed in constant time?"

Answer: A — the rear node. The front is then p->next, one link away, so dequeue is p->next = p->next->next. Enqueue inserts after the rear and moves the pointer, which is also one link.

Why the front fails: a pointer at the front makes dequeue constant, but enqueue needs the rear, and the rear is a full walk away in the direction of the links.

Verified fact Question and key A confirmed on gateoverflow (question 1033, GATE CSE 2004 Q36).

GATE CSE 1997, Q 1.4 — concatenation in O(1)

"The concatenation of two lists is to be performed on O(1) time. Which of the following implementations of a list should be used?" Options: singly linked, doubly linked, circular doubly linked, array.

Answer: C — circular doubly linked list. The tail of the first list is head1->prev, one hop from the head. Four writes join the two rings, whatever their lengths.

A singly or doubly linked list with only a head pointer must walk to the first tail, which is linear. An array must allocate and copy both, which is linear in the sum.

Verified fact Question wording confirmed against the GATE 1997 CS paper; key C confirmed on gateoverflow (question 2220).

GATE CSE 2022, Q 05 — reversal in O(1) space

"Consider the problem of reversing a singly linked list... Which one of the following statements is TRUE about the time complexity of algorithms that solve the above problem in O(1) space?"

Answer: A — the best such algorithm takes Θ(n) time in the worst case.

Every link must be rewritten, so Ω(n) work is unavoidable; the three-cursor loop does exactly n rewrites, so Θ(n) is attained. Option D, "not possible in O(1) space", is refuted by the three variables.

Verified fact Key A confirmed on gateoverflow (question 371931, GATE CSE 2022 Q5).

GATE CSE 2016, Set 2, Q 15 — the sorted doubly linked list

"N items are stored in a sorted doubly linked list... Θ(N) delete, O(log N) insert, O(log N) find, and Θ(N) decrease-key. What is the time complexity of all these operations put together?"

Answer: C — O(N²). Delete given a pointer is O(1), so Θ(N) of them cost O(N). Insert and find each walk the list, so each is O(N), and there are O(log N) of them: O(N log N). Decrease-key must move the record toward the front to restore the order, and that move is a walk: O(N) each, Θ(N) of them, O(N²).

Why B, O(N), is the tempting answer: it treats every operation as constant because "a pointer is provided". Only delete and the pointer arithmetic are constant; restoring the sorted order is not. Verified fact Key C confirmed against the GATE 2016 CS Set 2 answer key.

Two more, worked briefly

GATE IT 2004. "Let P be a singly linked list. Let Q be the pointer to an intermediate node x in the list. What is the worst-case time complexity of the best-known algorithm to delete the node x?" Answer O(n), for the reason in GATE 2023 above: the predecessor must be found. "Intermediate" excludes the last node, which removes the copy trick's failure case but does not remove the need for the predecessor.

GATE CSE 2003. f(p) returns 1 exactly when the list is empty, has one node, or satisfies p->data <= p->next->data and f(p->next). That is the recursive definition of "non-decreasing", so the answer is that the elements are sorted in non-decreasing order. The page checks the equivalence on every list of length up to 5 over the alphabet {1,2,3}.

Both are single-step questions once the representation is understood, and both are unreadable if it is not.

The shape of every one of these

Each question above is decided by one of three facts: which pointer you were given, which field must be rewritten, or whether the list ends. None of them needs a clever idea. All of them punish answering from the name of the structure.

If you can state the three facts for a question before reading the options, you will usually find only one option survives.

Empty list: head == NULL

The case: no nodes at all. The head pointer is NULL and there is nothing else to consult.

What breaks: anything that reads head->next or head->data before testing head. join in GATE 2017 Set 1 is exactly this: a valid NULL-terminated list may be empty.

The rule: the first test in every list function is if (head == NULL), and it comes before any dereference, not after.

One node: first and last at once

The case: a single node whose next is NULL and whose prev is NULL.

What breaks: move_to_front's loop would not execute, so q would stay NULL and q->next would dereference it. Reversal would leave the head correct but a naive implementation can return NULL. Deleting the only node must also clear the head.

The rule: the guard if (head == NULL || head->next == NULL) return head; exists precisely to make the single-node case a no-op.

Last node: no successor to copy

The case: the node you are given a pointer to is the final node.

What breaks: the copy-the-successor trick, which is the only route to O(1) deletion in a singly linked list. There is no successor to copy into the node, so the trick has no move.

The rule: the trick works for every node except the last, so the worst case is the last, so the worst case is O(n). That is the whole of GATE 2023 and GATE IT 2004.

A pointer to the node is not a pointer to its neighbour

The case: you hold a pointer to node x and need to change the link that points at x.

What breaks: a singly linked list cannot find the node that points at x. Inserting before x, or deleting x, both need that node.

The rule: GATE 1999 asked for a constant-time algorithm to insert before a given node in a singly linked list. The standard answer is to insert after x and then swap the two nodes' data — constant time, but it changes which object holds which value.

Circular list: the loop that never ends

The case: a ring, where the last node points at the first and no link is NULL.

What breaks: while (p != NULL) p = p->next; never terminates. So does any "find the last node" loop that tests for NULL, because there is no last node in the NULL sense.

The rule: a ring traversal needs a supplied count or a saved starting node. The empty ring is a NULL pointer; a ring of one node points at itself, which is a different and non-empty state.

Two pointers to the same node

The case: the list is not the only thing naming a node. A cursor, a saved predecessor, an iterator — each is another name.

What breaks: the copy-the-successor trick, and any free that happens while another pointer still names the node. After the copy trick, a saved pointer to the "deleted" node reads the successor's data, silently.

The rule: unlinking is not the same as deleting, and neither is the same as invalidating other names. In C, the caller's contract decides which is intended.

Closely confused pair: insert after p vs insert before p

After p is two assignments and constant time in a singly linked list. Before p needs p's predecessor, which is a walk — unless you insert after p and swap the data, which changes node identity.

Questions are written to swap these two words. Read which one is asked before choosing a complexity.

Closely confused pair: delete the node you were given vs delete the node after it

After it is one assignment in both list kinds: you hold the predecessor. The node itself is O(n) singly and O(1) doubly. The word "given" refers to a different node in the two questions.

GATE 2023 says "given a pointer to the node" and means the node to delete. GATE 2004's queue question means the predecessor. Same words, different pointer.

"Insertion in a linked list is O(1)."

Why it seems reasonable. The splice really is two assignments, and every textbook says a list beats an array for insertion.

Why it is wrong. The splice is constant only once you hold the node after which you insert. Inserting at position k requires arriving at position k, which is a walk. The cost of the operation includes the cost of getting to its starting point.

Minimal counterexample. Insert at the front of a 1000-node list: two assignments, O(1). Insert at position 500: 500 link reads first, O(n). Same operation name, different cost.

The correct rule. Insert or delete given the node is O(1); insert or delete at a position is O(n) in a list and O(n) in an array, for different reasons.

GATE question that exposes it. GATE 2020 asks for the cost of inserting n elements into an empty list kept in sorted order. Each insertion must find its place, so the answer is Θ(n²), not Θ(n).

"A sorted linked list can be binary-searched."

Why it seems reasonable. The elements are in order, and binary search only needs order.

Why it is wrong. Binary search also needs constant-time access to the middle of the current range. In a list the middle is only reachable by walking, so the walk dominates and the halving saves nothing.

Minimal counterexample. Six sorted nodes. To compare against the middle element you walk three links; to reach the middle of the remaining three you walk from the head again. Every comparison costs a walk.

The correct rule. A sorted list searches in Θ(n). Order alone does not give logarithmic search; order plus random access does.

What replaces it. Balanced trees and skip lists — both add structure to the links so that arriving somewhere stops being a full walk.

"Deleting a node from a singly linked list is always O(n)."

Why it seems reasonable. GATE 2023's answer is O(n), and the reasoning about the predecessor is correct.

Why it is wrong as a general statement. If you hold the predecessor, deletion is one assignment. The O(n) comes from not holding it, not from the structure being singly linked.

Minimal counterexample. A two-node list where you hold the head: deleting the second node is head->next = NULL, one assignment, whatever the list length.

The correct rule. The complexity belongs to the pair (operation, what you were given). State both, always.

GATE question that exposes it. GATE 2017 Set 2 asks about a circular queue on a singly linked list with a tail pointer; both operations are constant because the pointers supplied are the right ones.

"Passing the head to a function lets the function change it."

Why it seems reasonable. The parameter has the same type as the head, and inside the function the assignment compiles.

Why it is wrong. C passes by value. The parameter is a copy of the pointer; assigning to it changes the copy. The caller's variable is untouched.

Minimal counterexample. void f(struct node *h) { h = NULL; } called on a three-node list. After the call the caller's head still names the first node; only the local copy was nulled.

The correct rule. Return the new head, take struct node **, or use a dummy header node so the head never changes.

GATE question that exposes it. GATE 2010's move_to_front returns the modified head, which is exactly why the blank ends with head = p and the function has a return type.

"You can delete any node in O(1) by copying its successor."

Why it seems reasonable. The trick is real, it is constant time, and it is widely taught.

Why it is wrong as a general claim. It needs a successor. The last node has none, so the worst case is O(n). It also changes which node object survives, so every other pointer to the deleted node silently reads different data.

Minimal counterexample. A one-node list. The given node is also the last node. There is nothing to copy, and the operation cannot be performed at all.

The correct rule. Constant time for interior nodes, undefined for the last, and never when identity matters. The worst-case bound is O(n).

GATE question that exposes it. GATE 2023 Q3 and GATE IT 2004 both ask for the worst case and both answer O(n). Answering O(1) is the intended trap.

"A circular list is a linked list with a bug."

Why it seems reasonable. Accidental cycles are a classic bug, and a circular list looks like one.

Why it is wrong. A ring is a deliberate representation with its own operations. It is what makes a queue with a single pointer possible, and what makes concatenation constant time.

Minimal counterexample. GATE 2004: a queue as a circular list with one pointer works, and the same queue as a NULL-terminated list with one pointer does not.

The correct rule. A ring is a representation choice; an accidental cycle is a defect. The difference is whether the operations know about it.

What it costs. Every traversal needs an explicit stopping rule. That is the price, and it is paid once per traversal, not per operation.

"A doubly linked list is just a singly linked list with an extra pointer."

Why it seems reasonable. The struct differs by one member.

Why it is wrong. The extra pointer is a second copy of the same information, and two copies can disagree. Every operation now has an invariant to maintain, and every splice costs four writes instead of two.

Minimal counterexample. Update next only in a splice. Forward traversal is perfect; backward traversal lands on the wrong node. No crash, no error — silent corruption.

The correct rule. Buy the backward direction and pay for it with the invariant. What you get is O(1) deletion from a node pointer, which is the reason the structure exists.

Where it is tested. GATE 2016 Set 2's decrease-key arithmetic and GATE 2023's DLLdel are both about that single extra field.

The one habit that fixes all of these

Before answering any linked-list question, write down two things: which pointers do I hold? and which fields must change?

Every misconception on this tab is a shortcut that skipped one of those two questions. Every correct answer in this lesson answers them first.

Which categories apply here

Of the eight question categories, five carry most linked-list questions:

A — Direct definition. Which operation is constant time? What does a circular list store in its last node?

B — Property verification. Does this function produce a sorted list? Does this segment delete the node correctly?

C — Calculation. Count link writes, comparisons, or the total cost of a sequence of operations.

D — Construction. Fill in the blank so that the function does what its comment says.

G — Misconception trap. The copy-the-successor trick, the by-value head, "sorted so binary search". This is the largest category in this topic.

Pattern 1 — "given a pointer to the node"

The reasoning path. Ask what field must change and whether the given pointer reaches it. Deleting x needs the link that points at x: a doubly linked node reaches it through prev, a singly linked node does not.

Expected answer shape. "O(n) singly, O(1) doubly", or a choice between them.

The common wrong approach. Recalling that "linked list deletion is O(1)" and choosing the constant-time option, or recalling the copy trick and ignoring the last-node case.

Pattern 2 — trace the code fragment

The reasoning path. Rewrite the fragment with addresses, not names. Give the nodes numbers, then execute each line and write the new field value. Do not "see" the answer from the arrows.

Expected answer shape. A resulting sequence, or a description such as "swaps the two nodes after p".

The common wrong approach. Following the arrows in the order they appear on the page. GATE 1998's fourth line reads (p->next)->next, whose target has changed by then.

Pattern 3 — fill in the blank

The reasoning path. Establish the state of every variable at the blank from the loop above it, then check each option against the stated goal. Test the smallest inputs: an empty list, one node, two nodes.

Expected answer shape. One of four three-statement options.

The common wrong approach. Choosing the option whose statements are in the order the result is described rather than the order they must execute. In GATE 2010, head = p must come last.

Pattern 4 — the cost of a sequence of operations

The reasoning path. Write the per-operation cost, then multiply by the count, then add. Keep the counts separate: GATE 2016 Set 2 gives N deletes but only log N inserts.

Expected answer shape. A single asymptotic class, usually dominated by one term.

The common wrong approach. Assuming every operation is constant because "a pointer is provided". Only delete is; insert and find walk, and decrease-key walks to restore order.

Pattern 5 — which structure makes this O(1)

The reasoning path. Name the pointer that must be available and ask which representation stores it. Concatenation needs the tail: a circular doubly linked list stores it as head->prev. Deletion needs the predecessor: a doubly linked node stores it.

Expected answer shape. A structure name from four options.

The common wrong approach. Choosing the structure that sounds most elaborate. The answer is the one that stores the missing pointer, and nothing else.

Traps that recur across years

The word "worst case". It removes the copy trick in a singly linked list. Read it before the options.

The word "valid". A valid NULL-terminated list includes the empty one. GATE 2017 Set 1 depends on this.

The word "intermediate". It excludes the last node, which changes what is possible but not what is worst-case.

Three statements in one option. One is usually wrong, and it is usually the last. Check them in execution order.

What is not covered, and why

Skip lists, XOR linked lists and unrolled lists are class C: useful extensions beyond the syllabus wording. They are not named in Section 4 and no verified GATE CSE question in the papers consulted for this lesson turns on them.

Persistent and immutable lists are class D for this exam. If you meet them in an interview, the reasoning transfers, but they are not a GATE topic.

MCQEasyOriginal GATE-style

A singly linked list of n nodes is given only by its head pointer. Which of these is Θ(1)?

  1. Access the k-th node
  2. Append a node at the tail
  3. Insert a node immediately after the head
  4. Delete the last node

Answer: C — insert immediately after the head

The head is held, so its successor is head->next, and the splice is two assignments: x->next = head->next; head->next = x;. No walk.

A is Θ(k) — k link reads. B is Θ(n) — the tail is not held. D is Θ(n) — the last node's predecessor must be found.

This probes the misconception "insertion in a linked list is O(1)": only B and D are insertion or deletion, and both are linear because the position must be reached.

NATEasyOriginal GATE-style

A singly linked list holds 7 nodes. Using the three-cursor loop, how many next fields are written while the list is reversed?

Answer: 7

One write per node: curr->next = prev executes exactly once for each of the 7 nodes. The loop also reads 7 links and moves cursors, but only 7 fields are overwritten.

Common wrong answer: 6. That counts the links between nodes rather than the links from nodes. There are 7 nodes and each has one next field, including the last, whose field changes from a node address to NULL.

The page's model counts the writes and reports n for every list length from 1 to 9.

MSQModerateOriginal GATE-style

Which of the following statements are TRUE? (One or more may be correct.)

  1. A sorted singly linked list supports binary search in O(log n).
  2. Deleting a node given a pointer to it is O(n) in the worst case in a singly linked list.
  3. A circular linked list contains no NULL link.
  4. Merging two sorted singly linked lists requires Θ(n₁ + n₂) new nodes.

Answer: B and C

B is the GATE 2023 result: the predecessor must be found, and the copy trick fails on the last node. C is the definition of the ring: the last node names the first.

A is false: binary search needs the middle in constant time, and a list reaches it only by walking. D is false: a merge relinks existing nodes; no node is allocated.

Partial marking exists in the real exam; this page does not assign marks. The model checks B on lists of length 1 to 40 and C on every ring it builds.

MCQModerateGATE CSE 2023, 1 mark

Let SLLdel delete a node in a singly linked list given a pointer to the node and a pointer to the head. Let DLLdel do the same in a doubly linked list. Which is TRUE about the worst-case time complexity?

  1. SLLdel is O(1) and DLLdel is O(n)
  2. Both are O(log n)
  3. Both are O(1)
  4. SLLdel is O(n) and DLLdel is O(1)

Answer: D

Deletion needs the link that points at the node. A doubly linked node stores it as prev, so two assignments suffice. A singly linked node does not, so the predecessor is found by a walk from the head.

Why C tempts: the copy-the-successor trick is constant time. It fails when the node is the last one, and the question asks for the worst case. A trick with an exception does not set a worst-case bound.

The page simulates both deletions and counts node visits: constant for the doubly linked case at every length, and n − 1 at worst for the singly linked one.

MCQModerateGATE CSE 2022, 1 mark

For reversing a singly linked list using O(1) space, which statement is TRUE about the best algorithm's worst-case time?

  1. Θ(n)
  2. Θ(n log n)
  3. Θ(n²)
  4. Not possible in O(1) space

Answer: A — Θ(n)

Every one of the n links must change, so Ω(n) is forced. The three-cursor loop does exactly n rewrites with three variables, so Θ(n) is achieved.

Why D is wrong: three pointer variables are constant extra space, so the task is possible. Why B and C are wrong: nothing in the loop is nested.

The model reverses lists of length 1 to 12, applies the reversal twice, and checks the original sequence returns — a reversal that loses a node fails the second application.

MCQModerateGATE CSE 2010, 2 marks

In move_to_front, after the loop p is the last node and q the node before it. Which replacement for the blank moves the last element to the front?

  1. q = NULL; p->next = head; head = p;
  2. q->next = NULL; head = p; p->next = head;
  3. head = p; p->next = q; q->next = NULL;
  4. q->next = NULL; p->next = head; head = p;

Answer: D

Detach the tail (q->next = NULL), attach it to the old front (p->next = head), then move the head (head = p).

A never detaches the tail, so the list becomes circular. B sets head = p before p->next = head, so p points at itself and the rest is lost. C moves the second-to-last node to the front and reverses the tail.

The model runs all four options on lists of length 1 to 6 and checks whether the result is the old sequence rotated right by one. Only D passes at every length.

MCQModerateGATE CSE 2017 Set 1, 1 mark

void join(node *m, node *n) sets p = n, walks while (p->next != NULL) p = p->next;, then p->next = m;. Assuming m and n point to valid NULL-terminated lists, invocation of join will

  1. append m to the end of n for all inputs
  2. either cause a null pointer dereference or append m to the end of n
  3. cause a null pointer dereference for all inputs
  4. append n to the end of m for all inputs

Answer: B

A valid NULL-terminated list may be empty. If n is NULL, the very first test p->next != NULL dereferences a null pointer. If n is non-empty, the loop stops on the last node and the append is correct.

Why A tempts: it reads "valid" as "non-empty". Why C is wrong: it claims the failure is unconditional. Why D is wrong: it swaps the two lists.

The model calls join with an empty second list and records the dereference, and with a non-empty one and checks the resulting sequence.

MCQEasyGATE CSE 2004, 2 marks

A circularly linked list represents a queue, accessed by a single variable p. To which node should p point so that both enQueue and deQueue are constant time?

  1. rear node
  2. front node
  3. not possible with a single pointer
  4. node next to front

Answer: A — the rear node

From the rear, the front is p->next, one link away, so dequeue is p->next = p->next->next. Enqueue inserts after the rear and moves the pointer.

Why the front fails: dequeue is constant, but enqueue needs the rear, which is a walk away. Why C is wrong: the ring closes, so one pointer does reach both ends.

The page simulates both conventions for n = 1 to 40 operations and counts pointer writes per operation: constant for the rear pointer, linear for the front pointer.

MCQModerateGATE CSE 1997, 1 mark

Concatenation of two lists is to be performed in O(1) time. Which implementation of a list should be used?

  1. singly linked list
  2. doubly linked list
  3. circular doubly linked list
  4. array implementation of list

Answer: C — circular doubly linked list

The tail of a circular list is head->prev, one hop from the head, so four pointer writes join the two rings whatever their lengths.

A and B need a walk to the first list's tail. D needs a new block and a copy of both, linear in the total size.

The model concatenates rings of sizes 1 to 20 and confirms the pointer-write count is constant, then does the same for a singly linked list and confirms the visit count equals the first list's length.

NATTrickyOriginal GATE-style

A list has a cycle that begins after 5 links, and the cycle repeats every 3 nodes. The tortoise moves one link per step and the hare two. After how many steps do they first stand on the same node? (Answer as an integer.)

Answer: 6

After t steps the tortoise is at node t and the hare at node 2t. Both are inside the cycle once t ≥ 5. The node at index i ≥ 5 is cycle position (i − 5) mod 3, so they coincide when t ≡ 2t (mod 3), that is t ≡ 0 (mod 3). The smallest such t with t ≥ 5 is 6.

Common wrong answer: 8, from adding mu + lambda as if the bound were always attained. The bound is an upper bound, not the answer.

The page's model simulates the two cursors for every (mu, lambda) pair up to 8 and reports the meeting step; for (5, 3) it reports 6.

MCQTrickyOriginal GATE-style

A function is written as void insertFront(struct node *head, int v) { struct node *n = malloc(...); n->data = v; n->next = head; head = n; }. What does the caller observe after insertFront(h, 9)?

  1. The list gains 9 at the front and h names the new node
  2. The list is unchanged and the new node is unreachable
  3. The list is unchanged and the new node is reachable through h->next
  4. Undefined behaviour, because head was reassigned

Answer: B

head is a copy of the caller's pointer. head = n changes only the copy. The new node points at the old first node, but nothing in the caller names it, so it is allocated and unreachable — a leak, not a crash.

Why A tempts: inside the function the assignment looks correct and the code compiles. Why D is wrong: reassigning a parameter is perfectly defined; it is simply invisible to the caller.

This probes the by-value misconception directly. The repairs are: return the new head, take struct node **, or use a dummy header node.

MSQTrickyOriginal GATE-style

About the "copy the successor's data, then unlink the successor" trick for deleting a node x from a singly linked list, which are TRUE?

  1. It removes the node object x from memory
  2. It cannot delete the last node of the list
  3. Any other pointer that named x will afterwards read the successor's data
  4. It requires the list to be doubly linked

Answer: B and C

B: the trick needs a successor to copy, and the last node has none. C: x survives; it is the successor's object that is freed, so other names for x now see different data.

A is false: the freed object is the successor, not x. D is false: the trick is specifically for singly linked lists, where it substitutes for the missing prev pointer.

This is why the worst case stays O(n) and why GATE 2023 answers O(n) for SLLdel. Constant time, wrong object.

Definitions in one line each

Node — a record with a value and one or more links.

Singly linked list — each node names its successor; the last names NULL; the first is named by the head.

Doubly linked list — each node names both neighbours; b->next->prev == b and b->prev->next == b.

Circular list — the last node names the first; no NULL anywhere.

Length — not stored; counted by a walk or kept in a separate field.

The code, with the condition each line needs

x->next = p->next; p->next = x;

needs p ≠ NULL. Order is mandatory: the tail is copied before p is overwritten.

p->next = p->next->next;

needs p ≠ NULL and p->next ≠ NULL. Save the victim to free it.

x->next = b; x->prev = a; a->next = x; b->prev = x;

needs both neighbours to exist; at the ends only two or three fields change.

next = c->next; c->next = prev; prev = c; c = next;

The cost table

Reach element k — array O(1), list O(k).

Search — O(n) in a list, sorted or not; binary search needs random access.

Insert or delete given the node — O(1) in both, except deleting the node itself from a singly linked list, which is O(n).

Insert or delete at position k — O(n) in both, for different reasons: shift versus walk.

Concatenate — O(1) for circular doubly linked; O(n) for the others.

Merge two sorted lists — O(n₁ + n₂) time, at most n₁ + n₂ − 1 comparisons, no new nodes.

Decision procedures

To decide the complexity of an operation: name the field that must change, then ask whether the pointer you were given reaches it. If yes, O(1); if no, the cost of arriving is the answer.

To check a splice is correct: after it, every node except the first is named by exactly one next field, every node except the last by exactly one prev field, and the head names the intended first node.

To find a cycle: two cursors, speeds one and two. Meeting means a cycle; the hare reaching NULL means none. To find the entry, restart one cursor at the head and advance both by one until they meet.

To trace a fragment: replace every node name with a number, then execute line by line, writing each field's new value.

Traps, each with its defusing example

"Linked list insertion is O(1)" — false at position k. One node, insert at the front: O(1). One thousand nodes, insert at position 500: O(n).

"Sorted list, so binary search" — false. Six sorted nodes still need a walk to the middle.

"Delete given the node is O(1)" — only for a doubly linked list, or for an interior node via the copy trick. The last node breaks it.

"Passing head lets the function change it" — false. void f(node *h){ h = NULL; } changes nothing the caller can see.

"A circular list is a bug" — it is a representation. GATE 2004's one-pointer queue depends on it.

Eight quick revision questions

1. How many fields does a splice write in a singly linked list? Two.

2. And in a doubly linked list, in the middle? Four.

3. What is the worst case for deleting a given node in a singly linked list? O(n).

4. What does the last node of a circular list name? The first node.

5. Which pointer makes both queue operations constant in a ring? The rear.

6. How many link writes does reversal need? n.

7. How many comparisons does merging two sorted lists need at most? n₁ + n₂ − 1.

8. What breaks the copy-the-successor trick? The node is last, or another pointer still names it.
