Topic and objective

TOPIC: The two classical synchronisation problems: readers and writers over one shared value, and dining philosophers over a ring of forks. Both solutions, both failures, and the counting questions built on them.

LEARNING OBJECTIVE: Trace the first readers–writers solution step by step and say exactly which statement admits a second reader. State which class starves in each of the three versions of that problem and why. Trace the dining philosophers deadlock, prove by exhaustive search that it is the only stuck state of the naive code, and check three repairs against the same search. Distinguish deadlock from starvation from unbounded waiting, and answer the counting questions without guessing.

I read this as two shapes of contention: one resource with two rules about sharing, and a ring of resources with an ordering problem. Every number on this page is computed here by a semaphore simulator and a state-space search, and 52 model checks re-verify those numbers against their definitions.

Intuition first: a noticeboard and a table of forks

A department noticeboard can be read by any number of people at once. Reading does not spoil the notice, so nobody needs to queue. But if someone is changing the notice, nobody may read it and no second person may change it, because a half-changed notice misleads everyone. That is the readers–writers problem: the resource is the same for both, but the rules about sharing are not.

Now a table with five people and five forks, one between each pair, and each person needing both neighbours' forks to eat. Nobody is competing over a value; they are competing over order. If all five reach left at once, each holds one fork and each waits for a fork the next person is holding, and the table stops. That is the dining philosophers problem. Educational interpretation The two images carry the two failure modes: one problem fails by unfairness, the other by a cycle.

The vocabulary, every term in words

Critical section — the part of a process that touches the shared resource.

readcount — an integer holding how many readers are inside. It is shared, so it needs its own lock.

rmutex — a binary semaphore, initially 1, held only while readcount is changed.

wsem (also called wmutex or db) — the permission to write. Held by a writer while writing, and held by the first reader while any reader is inside.

readTry — the gate added in the second solution; the first waiting writer closes it.

Preference — which class is served first when both are waiting. Reader preference, writer preference, or neither.

The three rules of readers–writers

1. A writer is alone. No reader and no second writer is inside while a writer writes.

2. Readers share. Any number of readers may be inside together.

3. Admission is fair. A process that asks eventually gets in.

Rules 1 and 2 are safety and are easy. Rule 3 is fairness and is where every version differs. A solution can satisfy 1 and 2 perfectly and still starve one class for ever, which is why the exam asks “which process may starve” rather than “is this correct”.

The first solution, and the one line that matters

Reader: wait(rmutex); readcount++; if (readcount == 1) wait(wsem); signal(rmutex); READ wait(rmutex); readcount--; if (readcount == 0) signal(wsem); signal(rmutex); Writer: wait(wsem); WRITE; signal(wsem);

The whole design is the conditional: only the reader that raises the count from 0 to 1 takes wsem, and only the reader that lowers it from 1 to 0 gives it back. Every other reader passes without touching the writer semaphore. That single idea is what buys concurrency, and it is also what starves writers.

The second solution, in one sentence

Add a gate. Every reader takes readTry on the way in and gives it back at once; the first writer to arrive takes readTry and holds it until the last writer leaves. A waiting writer therefore blocks new readers, and the class that can starve flips from writers to readers.

Mathematical derivation The computed trace on this page: reader one leaves wmutex at 0; writer one takes readTry to 0 and blocks on wmutex, which falls to −1; reader two then blocks on readTry, which falls to −1. The gate is shut while the writer waits, and that is the whole mechanism.

Dining philosophers: the setup

fork[5] = {1,1,1,1,1}; philosopher(i): think(); wait(fork[i]); // left wait(fork[(i+1) % 5]); // right eat(); signal(fork[(i+1) % 5]); signal(fork[i]);

Five processes, five locks, and one identical program. The symmetry is the defect: because every philosopher reaches the same way, an interleaving exists in which all five finish their first wait before anyone finishes the second.

Why a finite search settles the questions

A philosopher is, at any moment, in one of four situations: thinking and holding nothing, waiting for his first fork, holding his first fork and waiting for the second, or eating. Which philosopher holds which fork is determined by those four labels, so a state of the whole table is just five labels. That gives at most four to the fifth, which is 1024 states, and most of those are unreachable.

Mathematical derivation Walking every reachable state from “all five thinking” is therefore a complete decision procedure, not a sample: 573 states are reachable in the naive solution, exactly one of them has no legal move, and that one is all five holding the first fork. The same search finds no stuck state at all in the asymmetric and room-of-four repairs. The maximum number eating at once, over every reachable state, is 2.

Example 1 — the first solution, traced with the values kept

The arrivals are R1, R2, W1, R3, R4. Every row below is produced by running the code against a semaphore simulator, with the safety invariant checked after every statement.

arrival readcount rmutex wsem readers in writer R1 1 1 0 1 — R2 2 1 0 2 — W1 2 1 -1 2 queued R3 3 1 -1 3 queued R4 4 1 -1 4 queued

Read the third row carefully. The writer's wait(wsem) takes the value from 0 to −1 and queues it, and nothing else changes: no reader leaves, no reader is affected. The fourth and fifth rows are the starvation mechanism — two more readers enter while the writer's value stays at −1. When all four readers leave, readcount reaches 0 and the last one signals wsem, which wakes the writer.

Example 2 — the subtle detail: who holds rmutex while blocked

Take the other order: the writer arrives first, then twenty readers.

W1 arrives: wsem 1 -> 0, W1 writes R1 arrives: rmutex 1 -> 0, readcount 1, wait(wsem) 0 -> -1, R1 blocks (R1 still holds rmutex) R2..R20: block on rmutex, value -19

Mathematical derivation The computed result: zero readers inside, one reader queued on wsem, nineteen queued on rmutex. The first reader holds rmutex while it waits, so no later reader can even reach the count. This is the detail that makes the solution safe in this order, and it is the detail a question tests when it asks what happens if the writer gets in first.

Example 3 — the second solution, traced

arrival readTry wmutex writecount readcount R1 1 0 0 1 W1 0 -1 1 1 R2 -1 -1 1 1

Reader one passes the gate, takes wmutex (0) and reads. Writer one is the first writer, so it takes readTry (0) and then blocks on wmutex (−1). Reader two now waits at the gate, which falls to −1.

After reader one leaves and the writer finishes, readTry is signalled and the queued reader enters: the computed state at the end is one reader inside and no writer. The gate reopens only when the last writer leaves, which is why a steady stream of writers starves readers.

Example 4 — the search on the naive table

reachable states 573 states with no legal move 1 the stuck state hold, hold, hold, hold, hold most philosophers eating 2 upper bound, 4^5 1024

The one stuck state is the configuration the animation builds: every philosopher holds his left fork and waits for the right one, which his neighbour holds. Its wait-for graph is a cycle of five, which is the independent second check on the same claim.

Two philosophers eating is the ceiling, and the reason is arithmetic: two meals hold four forks, and a third meal needs two more when only one is left. So the answer to “maximum philosophers eating at once” is 2, whatever the scheduling.

Example 5 — the same search on the repairs

model states stuck max eating naive, left first 573 1 2 room semaphore = 4 491 0 2 asymmetric, odd right 492 0 2 room semaphore = 5 573 1 2

Two things are worth reading off this table. The repairs remove the deadlock without raising the number of philosophers who can eat, because the forks — not the code — set that ceiling. And a room semaphore initialised to 5 is not a repair at all: it reproduces the naive table exactly, 573 states and one stuck state, which is the check that the repair is the n−1 and not the room idea in general.

Example 6 — semaphore arithmetic you will be asked for

A counting semaphore starts at s. After m waits and p signals its value is s − m + p. Under the standard definition a negative value of magnitude k means k processes are queued. So on the first readers–writers trace, with wsem starting at 1 and one writer waiting while readers hold it, the value is −1 and exactly one process is queued on it.

This is where conventions bite: some texts clamp the value at 0 and keep the queue separately. Both are used, the numbers differ, and the question usually tells you which one it means. The simulator on this page uses the negative-value convention, which is the one that makes “how many are waiting” a reading of the number rather than a separate count.

Boundary 1 — a room semaphore of 5 is not a repair

The repair is n − 1, not “a room”. Initialise the room to 5 on a five-philosopher table and the search returns the naive result exactly: 573 reachable states and one stuck state. The permit count is what removes the possibility of all five competing; a permit for everyone removes nothing.

Mathematical derivation With k permits and k < n, at least one philosopher is outside the pickup phase, so at least one fork is free for its neighbour. With k = n every philosopher may hold one fork at once, which is precisely the deadlock configuration.

Boundary 2 — one philosopher, and two

With one philosopher and one fork, the code asks for the same fork twice: wait(fork[0]) succeeds and wait(fork[1 mod 1]) is wait(fork[0]) again, so the philosopher blocks for ever on his own fork. The general statement “five philosophers, five forks” hides this: the ring needs at least two forks to make sense of “left” and “right”.

With two philosophers and two forks, both reach left, both hold one fork, and both wait for the other. That is the smallest instance of the same deadlock, and it is worth being able to draw in one line.

Boundary 3 — zero readers is a state you must handle

The condition if (readcount == 0) signal(wsem) is what releases the writer. Drop it, or test it before the decrement, and the writer is never released: the system deadlocks with every reader gone and every writer blocked. The order is decrement, test, signal — in that order, on the shared count.

The matching boundary on the way in is if (readcount == 1), tested after the increment. Testing before the increment makes every reader believe it is first, so every reader takes wsem, and the readers serialise — safe, and back to one mutex.

Boundary 4 — asymmetric ordering with an even number of philosophers

The odd/even rule removes the cycle for any ring, because the first-fork choices no longer form a closed loop: some philosophers reach clockwise and some anticlockwise. With an even number of philosophers the split is even, and the argument is the same; with an odd number one side has one more philosopher, and the argument is also the same. What breaks is not the rule but the assumption that all forks are requested in index order.

A cleaner statement of the same repair: number the forks and require every philosopher to take the lower-numbered fork first. That is the resource-ordering rule used for real locks, and it is the version to quote if a question asks for the general principle rather than the parity trick.

Boundary 5 — starvation is not deadlock, and the difference is visible

In the reader-preference trace, readers keep entering and the writer never does. Nothing is stuck: at every moment some process is running and making progress. A deadlock has no such moment. The two therefore differ in the repair as well — a deadlock is removed by breaking a cycle or removing hold-and-wait, while starvation is removed by changing the admission rule, which is exactly what readTry does.

The matching statement for philosophers: the room and asymmetric repairs remove deadlock and leave starvation possible, because a philosopher can still be unlucky about which neighbour eats. Removing deadlock and removing starvation are two different jobs, and a question that asks for one is not asking for the other.

Misconception 1 — “the first solution is wrong because writers can starve”

The belief. Since a writer can wait for ever, the code must be incorrect.

Why it is wrong. The first readers–writers problem is defined as: no reader waits unless a writer already holds the section. That definition forces reader preference, and reader preference allows writer starvation. The code is a correct solution to the first problem and a wrong one to the third. Mathematical derivation The trace on this page shows the writer released exactly when readcount reaches 0, which is the specified behaviour.

The fix in your head. Answer the question that was asked: which problem, then which property. “Correct” without a named property is not an answer here.

Misconception 2 — “a negative semaphore value is an error”

The belief. A value of −1 means something went wrong, or that the semaphore is “over-signalled”.

Why it is wrong. Under the standard definition wait decrements first and blocks if the value went negative, so the magnitude is the number of queued processes. Minus one means one process waiting, which is normal and is what the exam asks for.

Watch the other convention. Some texts clamp at 0 and keep the queue separately. Both exist, and the numeric answers differ, so read which one the question uses before computing.

Misconception 3 — “only one process may be in a critical section”

The belief. A critical section always holds one process, so three readers inside is a violation.

Why it is wrong. Mutual exclusion is a property of the problem, not of the words “critical section”. Here the requirement is that a writer is alone, which permits any number of readers together. Mathematical derivation In the computed trace four readers are inside at once with no writer, and the safety invariant never fires.

The tell. If a question says readers may read together, the answer to “maximum processes inside” is not 1.

Misconception 4 — “the monitor solution is starvation-free”

The belief. Because a monitor grants both forks or neither, nobody can starve.

Why it is wrong. The monitor removes hold and wait, so it removes deadlock. It does not order the requests, so an unlucky philosopher can be passed over repeatedly while his neighbours alternate. Deadlock-freedom and starvation-freedom are different properties, and the monitor gives only the first.

The fix. Fairness needs a queue — a FIFO waiter, or a fair semaphore. That is an extra design decision, not a consequence of the monitor.

Misconception 5 — “a single processor prevents the philosophers deadlock”

The belief. With one core, two philosophers cannot hold forks at the same time, so the deadlock needs a multicore machine.

Why it is wrong. A preemption between wait(fork[i]) and wait(fork[i+1]) is enough. Each philosopher completes his first wait and is then switched out; the forks are held across the switch because they are held by the process, not by the core. The search that finds the stuck state assumes nothing about parallelism — only that any interleaving is possible.

The tell. Any question that says “the scheduler may switch at any point” allows this interleaving on one core.

Misconception 6 — “more forks fix the philosophers”

The belief. Adding a sixth fork, or a second fork per philosopher, removes the deadlock.

Why it is wrong. Extra forks change the arithmetic of how many can eat, not the ordering rule that creates the cycle. The cycle exists because every philosopher requests in the same order; six forks with the same rule still admit a configuration where a set of philosophers each holds one fork and waits for the next.

What does fix it. Break the cycle (asymmetric or resource ordering), remove hold-and-wait (waiter or monitor), or cap the competitors at n − 1. Each names a condition, which is what the question usually wants.

The four question shapes in this family

Shape 1 — complete the code. Blanks in a readers–writers solution: which statement goes in each box. Solve by asking what the box must guarantee, not by recalling the text.

Shape 2 — state the values. “Twelve readers are reading and thirty-one writers are waiting; give the value of every shared variable and semaphore.” Solve by running the code, keeping a table, and reading negative values as queue lengths.

Shape 3 — name the failure. Which class may starve, or which of the four conditions is removed by a given repair. Solve by naming the condition, then the class.

Shape 4 — count. The largest number of processes inside at once, the maximum number eating, the number of semaphores. Solve from the resource arithmetic, then check against the code.

Verified fact GATE CSE 1987, Q8a. A proposed readers–writers solution with counters ar, aw, rr, rw and semaphores mutex, reading, writing, asking for the variable values with 12 readers and 31 writers, whether either class can starve the other, and why the solution is incorrect.

How the 1987 shape is answered

Read the procedure off the code rather than the numbers: grantread releases a reader only while aw = 0, so a waiting writer stops new readers, while grantwrite checks rr and not ar, so writers are admitted while readers are still inside.

That asymmetry is the answer to all three parts: readers do not starve writers because the gate closes for readers as soon as a writer waits; writers can starve readers because nothing stops a second writer; and the solution is incorrect because two writers can be inside together. This is a shape to practise on any proposed solution, not a fact to memorise.

Traps that survive a careless check

Trap 1. Marking the single-mutex readers–writers code correct. It is safe and it violates rule 2.

Trap 2. Answering “one” to “maximum processes in the critical section” on a readers–writers question.

Trap 3. Calling writer starvation a deadlock. Nothing is stuck; the writer is simply never chosen.

Trap 4. Answering “five” to the maximum number eating at once. Two forks per meal, five forks, so two.

Trap 5. Saying a repair “prevents deadlock” without naming the condition it removes, when the question asks for the condition.

MCQGATE CSE 1996 Q2.19

A solution to the Dining Philosophers Problem which avoids deadlock is to

  1. ensure that all philosophers pick up the left fork before the right fork
  2. ensure that all philosophers pick up the right fork before the left fork
  3. ensure that one particular philosopher picks up the left fork before the right fork, and that all other philosophers pick up the right fork before the left fork
  4. None of the above

Answer: C

Options A and B keep the code symmetric, and symmetry is exactly what allows all five to hold one fork at once. Option C breaks the symmetry: one philosopher reaches the other way, so the first-fork choices no longer form a closed loop, and the cycle of waiting cannot be completed. The search on this page confirms the mechanism on the parity form of the same rule: 492 reachable states, none stuck.

Why D is tempting. Option C does not make anyone eat sooner and does not by itself guarantee fairness, so a reader may think it “does not solve the problem”. The question asks only about deadlock, and C removes it.

NATGATE CSE 2000 Q20 — adapted

A readers–writers solution uses one binary semaphore mutex initialised to 1, with counters R (readers present) and W (a writer present), and busy waiting. The reader does:

L1: wait(mutex); if (W == 0) { R = R + 1; signal(mutex); } else { signal(mutex); goto L1; } ... read ... wait(mutex); R = R - 1; signal(mutex);

The writer loops at L2 until it may enter. Which condition must its test check, if it is to be admitted only when the section is empty?

Answer: it must loop while R > 0 or W != 0.

The writer may enter only when no reader is present and no writer is present. So the test at L2 is the negation of that: keep waiting if either is non-zero. Once it passes, it sets W = 1 and releases mutex, and the reader's test on W then keeps new readers out.

Why R > 0 alone is wrong. Two writers would both pass the test and both enter, so a second writer meets the first. Why the reader's test is on W only. A reader may enter beside other readers, so R is not a bar to it. The trap. This solution uses busy waiting, so it is not the semaphore-blocking form on this page; the condition is the same, the mechanism is not.

NATOriginal practice

In the first readers–writers solution (readcount, rmutex, wsem), suppose two readers are reading, then one writer arrives and blocks, then two more readers arrive and enter. Give the value of readcount and of wsem at that moment.

Answer: readcount = 4, wsem = −1

Each arriving reader increments the count: 2, then 3, then 4. Only the reader that took the count from 0 to 1 touched wsem, and it is still held, so the writer's wait took it to −1 and it stays there. The minus one is one queued writer.

Why 0 appears. Reading “a writer is waiting” as “a writer holds the section”, which would be the value while writing. Why −2 appears. Counting the new readers as also waiting on wsem; they never touch it.

MSQOriginal practice

Which of the following are true of the dining philosophers solution that lets at most four philosophers attempt the pickup at once?

  1. It removes the possibility of a deadlock.
  2. It raises the maximum number of philosophers eating at once to three.
  3. It leaves starvation possible.
  4. It works by removing the circular-wait condition.

Answer: A and C

The search on this page finds no stuck state among the 491 reachable states, so A is true. The ceiling stays at two, because two meals need four forks and a third needs six, so B is false. The permit does not order the requests, so an unlucky philosopher can still be passed over: C is true. And the condition removed is the possibility that all five compete, not circular wait as such — the room prevents the cycle from forming rather than forbidding it: D is the tempting wrong answer.

Why D is arguable and still wrong. Textbooks sometimes say the room “breaks circular wait”. Precisely, it makes the deadlock configuration unreachable, which is a statement about reachability; naming the condition it removes is the safer answer when the options distinguish the two.

NATOriginal practice

Six philosophers sit round a table with six forks, one between each pair, running the naive left-then-right code. What is the largest number of philosophers who can be eating at the same time?

Answer: 3

Each meal holds two forks and no fork serves two meals, so the number eating is at most the number of forks divided by two, rounded down: six forks, three meals. The arrangement exists: philosophers 0, 2 and 4 hold forks 0 and 1, forks 2 and 3, and forks 4 and 5 respectively, so three eat together. The general answer is the floor of n over 2, which is 2 for five philosophers and 3 for six.

Why 6 appears. Counting philosophers instead of forks. Why 2 appears. Carrying the five-philosopher answer across without redoing the arithmetic.

MCQOriginal practice

In the second readers–writers solution with readTry, which process can be starved, and by what?

  1. A writer, by a steady stream of readers
  2. A reader, by a steady stream of writers
  3. Both, by each other
  4. Neither, because the gate makes the solution fair

Answer: B

The first writer to arrive takes readTry and holds it until the last writer leaves. A stream of writers keeps readTry held, so new readers queue at the gate: the computed trace ends with one blocked reader and no reader inside. Writers are therefore protected, and readers are the class that can starve.

Why A appears. That is the first solution's failure, not this one's. Why D appears. The gate changes who is preferred; it does not add a queue with a bound, so it does not make either class safe.

MCQOriginal practice

A system is running the naive dining philosophers code with five philosophers. Which statement is exactly right?

  1. A deadlock is possible and a deadlock is also reachable from every execution
  2. Exactly one reachable state is a deadlock, and it is all five holding the first fork
  3. No deadlock is possible because a philosopher releases a fork when it cannot get the second
  4. The deadlock needs at least two processors

Answer: B

The exhaustive search on this page enumerates 573 reachable states and finds exactly one with no legal move, the state where every philosopher holds his first fork. That makes a deadlock possible and unique among reachable states.

Why A appears. “Reachable from every execution” is far too strong: most interleavings never deadlock. Why C appears. This code never releases a held fork; that is a different solution (try-lock and back off). Why D appears. A preemption after the first wait is enough on one processor.

The sheet

Readers–writers, first solution. readcount plus rmutex plus wsem. First reader takes wsem, last reader releases it, everyone else passes. Readers share; a writer is alone. Writers can starve. Two semaphores and one integer.

Readers–writers, second solution. Add readTry; the first waiting writer closes it and the last writer opens it. Writers are protected; readers can starve. Four semaphores and two integers.

Third problem. Neither class starves. Paid for with a queue semaphore that every process passes through, which gives up both preferences.

Dining philosophers. Five forks, two per meal, so at most two eat. The naive left-then-right code has exactly one stuck state: all five holding the first fork. Three repairs: a room of n − 1, asymmetric or resource ordering, and a waiter or monitor that never holds one fork while waiting.

Decision procedure for any question here

1. Name the problem: readers–writers, or philosophers. They have different failures.

2. Name the version, if readers–writers: reader preference, writer preference, or fair.

3. List the shared variables and find the semaphore guarding each.

4. Match every wait to its signal, and check every path reaches it.

5. Ask which class can be bypassed, then count.

6. If it asks about deadlock, name the condition removed, not just the verdict.

Formulas to keep

Semaphore value after m waits and p signals, from s: s − m + p.

Blocked processes on a semaphore: the magnitude of a negative value, |value| when the value is below zero.

Maximum philosophers eating: the floor of n divided by 2, from two forks per meal.

Permits that remove the philosophers deadlock: n − 1, never n.

States of the philosophers table: at most 4n, since each philosopher has four situations.

Five sentences worth memorising, and their exact scope

“Only the first reader takes wsem and only the last gives it back.” — scope: the first solution; not true of the second.

“A negative semaphore value is the number waiting.” — scope: the decrement-first convention only.

“The room repair is n − 1.” — scope: it removes the deadlock, and does not remove starvation.

“Asymmetric ordering breaks the cycle.” — scope: any ring, provided the rule is genuinely asymmetric.

“A monitor removes hold-and-wait.” — scope: it removes deadlock, not starvation, and not contention.

Standard references. The readers–writers problems are attributed to Courtois, Heymans and Parnas (1971) and the three versions are the standard statement of the family. The dining philosophers problem is attributed to Dijkstra; the monitor solution with a per-philosopher state array and a test procedure is the version in Tanenbaum's operating-systems text; the n − 1 permits repair is the one attributed to Stallings. The asymmetric and resource-ordering repairs are standard in the same literature.

Community discussions. Public solution threads on these papers were read to see which wrong options attract students. Those threads are somebody's reasoning, not authority, and nothing in this lesson rests on them alone: every number was recomputed by the code in lesson.js.

What was verified, and how

Semaphore behaviour. Restated as code and checked: five assertions on wait, signal, the negative value and the s − m + p formula.

Both readers–writers traces. Executed statement by statement with a resume-on-wake simulator; the safety invariant (never a writer with a reader, never two writers) is asserted after every statement of every script.

Philosophers claims. Decided by breadth-first search over every reachable state, with fork ownership derived from the state rather than stored separately, and the deadlock claim cross-checked by an independent wait-for graph cycle count.
