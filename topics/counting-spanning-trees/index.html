Topic and objective

TOPIC: Counting the spanning trees of a graph — the count that sits behind "minimum spanning trees" in Section 5 and behind counting in Section 1 of the GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Count the spanning trees of a small graph four independent ways — enumerate every (n−1)-subset, apply deletion–contraction, take a Laplacian cofactor, and use Cayley's formula with its Prüfer code — and know which method a given question is asking for. Recognise a disconnected graph before doing any arithmetic, and separate the labelled count from the unlabelled one and from the Catalan count of binary search trees.

I read the topic as one number, four computations: what is being counted is fixed by the definition, and every method is a different route to the same integer. The page computes all four and reports where they agree.

Prerequisites

  • Graphs: connectivity and structure — trees, cycles, connectivity, cut edges.
  • Trees, binary search trees and heaps — for the Catalan comparison.
  • Counting and combinatorics — C(n, k) and the counting argument.
  • Matrices and determinants — a cofactor expansion, for the Matrix–Tree theorem.

Approximate learning time: 45 to 60 minutes, including the practice set. That figure is an estimate, not a measurement.

The five ideas

  1. A spanning tree has all n vertices, exactly n−1 edges, and no cycle.
  2. Disconnected means zero, before any formula is reached.
  3. Complete graph → n^(n−2). Cycle → n. Complete bipartite → m^(n−1)·n^(m−1).
  4. Anything else: delete–contract if it is small, Laplacian determinant if it is not.
  5. Labelled, unlabelled and binary-search-tree counts are three different numbers.

Intuition first: how many skeletons can hold this graph together

Think of the graph as a set of towns and roads. You want the cheapest set of roads that still lets you travel between any two towns. Any such set is a spanning tree, and its cost depends on which one you pick — which is why the minimum spanning tree problem exists. The question here is the one underneath it: how many candidates are there at all?

Educational interpretation The analogy is exact for weighted graphs: a spanning tree is a road network that connects everything with no redundant road. It is an analogy for the counting only in the sense that it explains why anyone cares.

Formal definition

A spanning tree of a graph G on n vertices is a subgraph T such that T contains every vertex of G, T has exactly n−1 edges, and T contains no cycle.

Two of the three conditions are redundant, which is worth knowing: on n vertices, a connected subgraph with n−1 edges is acyclic, and an acyclic subgraph with n−1 edges on all n vertices is connected. So any two of the three conditions imply the third.

Verified fact This is the standard definition, as in Silberschatz, Korth and Sudarshan's Database System Concepts chapter on formal query languages for the algebra side and in any discrete-mathematics text for the graph side. The equivalence of the three conditions is the standard tree characterisation.

Symbols, in words

  • n — the number of vertices.
  • m — the number of edges.
  • C(m, k) — the number of ways to choose k of m things, read "m choose k".
  • G − e — the graph with edge e deleted.
  • G / e — the graph with e's two endpoints merged into one vertex.
  • Kn — the complete graph: every pair joined.
  • Km,n — complete bipartite: every vertex of one side joined to every vertex of the other.
  • Cn — the cycle through n vertices.
  • L — the Laplacian matrix, defined below.

The exam almost always wants the fourth, with the third as the check. The first two exist so that you can see the number is forced rather than remembered.

The conditions each formula carries

Cayley's n^(n−2) needs a complete graph. The cycle rule needs a cycle, not merely a graph with n edges. The bipartite formula needs complete bipartite. The determinant needs no condition at all — that is precisely why it is the safe route — but a determinant of 0 is a real answer, meaning disconnected.

Every one of these conditions is a place where a correct-looking answer is wrong. The Edge cases tab takes them one at a time.

Worked example 1 — K4, three ways, all 16

  1. Enumerate. Six edges, choose three: C(6,3) = 20. A three-edge set fails only when it is a triangle, and K4 has 4 triangles, one per omitted vertex. 20 − 4 = 16.
  2. Delete–contract. Split on edge A-B. Omitting A-B leaves C4, which has 4 trees. Contracting A-B gives two vertices joined by two parallel edges plus two edges to a third vertex, which also has 4. 4 + 4 = 8 on the first split; the recursion finishes the rest and totals 16.
  3. Laplacian. L has 3 on the diagonal and −1 off it. Delete row 1 and column 1: the 3×3 minor is 3,−1,−1 / −1,3,−1 / −1,−1,3. Expanding along its first row gives 3(9−1) − (−1)(−3−1) + (−1)(1+3) = 24 − 4 − 4 = 16. All four cofactors give 16.
  4. Cayley. n^(n−2) = 4^2 = 16.

Every number above is recomputed by the page, including all four cofactors, so the "any cofactor" claim is checked rather than asserted.

Worked example 2 — the diamond

The diamond is K4 with one edge removed: five edges, four vertices. Enumerating three-edge subsets gives C(5,3) = 10 candidates, of which 8 are trees.

By deletion–contraction on the missing edge's neighbour: omitting the diagonal leaves C4 (4 trees); contracting it gives a triangle with a doubled edge (4 trees). 4 + 4 = 8.

The Laplacian agrees. Note that the diamond is not complete, so Cayley's 16 would be wrong here — and 16 is exactly the tempting answer.

Worked example 3 — a six-vertex tree to a Prüfer code and back

Tree edges: 1-2, 1-3, 2-4, 4-5, 4-6. Degrees: 3, 5 and 6 have degree 1.

  1. Smallest leaf is 3; its neighbour is 1. Write 1, delete 3.
  2. Now 1 is a leaf; its neighbour is 2. Write 2, delete 1.
  3. Now 2 is a leaf; its neighbour is 4. Write 4, delete 2.
  4. Now 5 is a leaf; its neighbour is 4. Write 4, delete 5.
  5. Two vertices remain, 4 and 6. Stop. Code: 1, 2, 4, 4.

Decoding: degrees are 1 + occurrences = 2, 2, 1, 3, 1, 1. Repeatedly join the smallest degree-1 label to the next code entry, then join the last two. The page checks the round trip on this tree and on all 125 codes over five labels.

Worked example 4 — the Laplacian of C5

For the five-cycle, every vertex has degree 2, so L has 2 on the diagonal and −1 at each cycle neighbour, with zeros elsewhere. Delete row 1 and column 1, leaving a 4×4 minor, and take its determinant: 5.

This matches the cycle rule: Cn has exactly n spanning trees. Two methods, one number — which is the pattern of the whole topic.

n = 1: one tree, the empty one

A single vertex with no edges has one spanning tree, itself. Cayley's formula gives 1^(−1), which is 1 by the convention that a tree on one vertex counts once; the page special-cases it rather than relying on the exponent.

This is why the Cayley table starts 1, 1, 3, 16 rather than 0, 1, 3, 16.

Disconnected: the answer is 0, not "a few"

Two disjoint triangles on six vertices have six edges and no spanning tree at all. Both the determinant and the contraction return 0.

Check connectivity before any formula. A zero option in a multiple-choice question is usually a signal that this is the point.

A multigraph: parallel edges multiply the count

Two vertices joined by two parallel edges have two spanning trees, one per edge. Contraction keeps parallel edges on purpose — they are distinct choices — but a self-loop created by a contraction must be deleted.

The page computes the defect: keeping self-loops gives 111 for K3,3 instead of the correct 81.

The boundary of each formula

C4 has 4 spanning trees, not 16: it lacks both diagonals. K2,3 has 12, not 2^(3−1)·3^(2−1) misapplied as 2·3. The bipartite formula needs the graph complete bipartite; a subgraph of it has fewer.

Each formula is a statement about a family, and a graph outside the family gets a smaller number, never a larger one.

The one boundary that catches people: "any cofactor"

The Matrix–Tree theorem says any cofactor works — delete row i and column i for the same i. Deleting row 1 and column 2 is not a cofactor and gives a wrong number. The page checks all four proper cofactors of K4 and gets 16 from each.

A second boundary: the theorem counts spanning trees of the graph as given. If the question asks for spanning trees of a subgraph, or after deleting a vertex, the matrix changes.

"n^(n−2) is the number of spanning trees"

Why it tempts: it is the only formula most learners meet, and it is stated without its hypothesis.

Why it is wrong: it counts trees that may use any pair of vertices as an edge. A graph missing edges cannot contain some of them.

Minimal counterexample: C4. The formula says 16; the true count is 4, because only the four edges of the cycle exist.

Correct rule: n^(n−2) is the count for Kn, and an upper bound for everything else on n vertices.

"Choosing n−1 edges is enough"

Why it tempts: a spanning tree does have exactly n−1 edges, so C(m, n−1) looks like the answer.

Why it is wrong: the chosen edges may form a cycle and leave a vertex isolated.

Minimal counterexample: K4, where 20 three-edge sets exist and 4 of them are triangles.

Correct rule: choose, then test connectivity. The count is the number of choices that pass.

"Cayley and Catalan are the same sequence"

Why it tempts: both count "trees", both appear near graph questions, and both are memorised as lists.

Why it is wrong: Cayley counts labelled trees on n vertices; Catalan counts binary tree shapes, and binary search trees on n keys.

Minimal counterexample: n = 4 gives 16 by Cayley and 14 by Catalan. They already differ at the first nontrivial size.

Correct rule: Cayley: 1, 1, 3, 16, 125. Catalan: 1, 1, 2, 5, 14.

"Labelled and unlabelled give the same count"

Why it tempts: the picture of a tree looks the same however you name its vertices.

Why it is wrong: a labelled count distinguishes trees whose edge sets differ, even when a relabelling matches them.

Minimal counterexample: four vertices: 16 labelled trees, 2 shapes. The GATE 2024 question says "labelled" for exactly this reason.

Correct rule: read the word. Unlabelled means up to relabelling; labelled means edge sets.

"A graph with few edges has few spanning trees — so 1"

Why it tempts: with n−1 edges there is at most one tree, so "few edges" feels like "about one".

Why it is wrong: below n−1 edges in a connected graph is impossible; at exactly n−1 the answer is 1 only if connected.

Minimal counterexample: two disjoint triangles: six edges, and 0 spanning trees, not 1.

Correct rule: disconnected is 0. A connected graph with exactly n−1 edges is a tree and counts 1.

The one-line summary

Name the graph, check connectivity, then count — and check the count a second way, because every method here is cheap enough to run twice.

Which question categories apply, and what each demands

Categories A, B, C, E and G apply here. D (construction) applies only as "produce the Prüfer code", which is a mechanical procedure rather than a design task. F and H are rare on this topic because the count is usually one step from a named graph.

A — direct definition

"Which of these subgraphs is a spanning tree?" Test the three conditions, remembering that two of them suffice.

Wrong approach: checking only that there are n−1 edges, and accepting a triangle plus an isolated vertex.

C — calculation

"The number of spanning trees of K4 is ___." Identify the family, apply the formula, and check by a second method if time allows.

Wrong approach: applying n^(n−2) to a graph that is not complete, which is the single most common error on this topic.

E — counterexample reasoning

"Which statement is true for every connected graph?" A single small graph kills a false option: C4 for the Cayley claim, two triangles for the "few edges means one" claim.

Wrong approach: testing the options only on K4, where several false statements happen to hold.

G — misconception trap

The 2024 question is one: the word "labelled" separates 16 from 2, and the number 20 is offered by the choose-only reasoning.

Wrong approach: reading "complete graph of 4 vertices" and answering 2, the number of shapes.

B — property verification, and the reasoning it needs

"Is the number of spanning trees of this graph 0, 1, or more?" Connectivity first: 0 if disconnected. Then n−1 edges: if connected with exactly n−1 edges it is a tree and the count is 1. Otherwise it is at least 2, and usually much more. That three-way decision answers most qualitative items without any arithmetic.

NATGATE CSE 2024, Set 1

The number of spanning trees in a complete graph of 4 vertices labelled A, B, C, and D is _________.

Answer: 16

Cayley's formula: Kn has n^(n−2) labelled spanning trees, so K4 has 4^2 = 16. The direct count agrees: 6 edges, choose 3, gives 20 sets, and the 4 triangles leave a vertex isolated, so 20 − 4 = 16. They are the 4 stars and the 12 paths.

The likely errors. 2 is the number of tree shapes on four vertices, which the word "labelled" rules out. 20 forgets the triangles. 12 counts only the paths. 4 counts only the stars.

The official GATE 2024 answer key gives 16. Question catalogues number this item 24, 34 or 39 depending on the archive, so no number is quoted here.

MCQOriginal practice question

The number of spanning trees of the cycle C6 on six vertices is

  1. 1
  2. 5
  3. 6
  4. 64

Answer: C — 6

Deleting any one of the six edges leaves a path through all six vertices; deleting two disconnects it. So there is one tree per edge: 6.

Why D appears. 64 is 6^(6−2) — Cayley applied to a graph that is not complete, which over-counts by exactly the trees that would use a diagonal. Why B appears. 5 is the answer for C5, one off. Why A appears. 1 is the count for a tree, where no edge can be removed.

NATOriginal practice question

Let K3,3 be the complete bipartite graph with three vertices on each side. The number of spanning trees of K3,3 is _________.

Answer: 81

The bipartite formula gives m^(n−1)·n^(m−1) = 3^2 · 3^2 = 81. The Laplacian determinant of the 5×5 minor gives 81 as well, and the page computes both.

The likely error. 729 = 3^6, from multiplying the two exponents instead of applying them to the right bases. Another. 12, which is K2,3's count — the formula is right but the substitution is not.

MSQOriginal practice question

Which of the following statements are true for every graph?

  1. A tree on n vertices has exactly one spanning tree.
  2. A disconnected graph has zero spanning trees.
  3. K4 has 16 spanning trees.
  4. Every connected graph on n vertices has n^(n−2) spanning trees.

Answer: A, B and C

A: a tree is its own spanning tree and has no other. B: a spanning tree is connected and reaches every vertex, which a disconnected graph forbids. C: 4^2 = 16, and the enumeration 20 − 4 = 16 agrees.

Why D is false. C4 is connected on four vertices and has 4 spanning trees, not 16. Cayley's formula is an upper bound that only the complete graph attains.

Partial marking exists in the real exam; no marks are assigned here.

MCQOriginal practice question

The diamond graph is K4 with one edge removed. Its number of spanning trees is

  1. 4
  2. 6
  3. 8
  4. 16

Answer: C — 8

Enumerate: C(5,3) = 10 three-edge sets, of which 8 are trees. Delete–contract: omitting the diagonal leaves C4 with 4 trees; contracting it gives a triangle with a doubled edge, also 4. 4 + 4 = 8.

Why D appears. 16 is K4's count — Cayley applied to a graph that is missing an edge. Why A appears. 4 is one branch of the split, not the total. Why B appears. 6 is the number of edges, a distractor that looks like a count.

NATOriginal practice question

A Prüfer code for a tree on 6 labelled vertices is a sequence of 4 labels, each between 1 and 6, with repetition allowed. The number of such sequences is _________.

Answer: 1296

Four positions, six choices each, repetition allowed: 6^4 = 1296. Because encoding is a bijection, that is also the number of labelled trees on six vertices, which is Cayley's 6^(6−2).

The likely error. 360, from treating the labels as distinct without repetition, 6·5·4·3. A code may repeat a label: the tree in this lesson has 4 twice.

MCQOriginal practice question

On five keys, the number of distinct binary search trees is

  1. 42
  2. 125
  3. 120
  4. 14

Answer: A — 42

The number of binary search trees on n distinct keys is the n-th Catalan number. The Catalan numbers are 1, 1, 2, 5, 14, 42, so five keys give 42.

Why B appears. 125 is 5^3, the number of spanning trees of K5 — Cayley, not Catalan. This is the confusion the question exists to test. Why C appears. 120 is 5!, the orderings, which counts permutations rather than tree shapes. Why D appears. 14 is the count for four keys, one row too early.

Revision sheet

A spanning tree: all n vertices, exactly n−1 edges, no cycle. Any two of those three conditions imply the third. The count is a property of the labelled graph.

Decision procedure

  1. Connected? If not, answer 0 and stop.
  2. Complete on n vertices? Answer n^(n−2).
  3. Exactly one cycle, length n? Answer n.
  4. Complete bipartite m by n? Answer m^(n−1)·n^(m−1).
  5. Otherwise: delete–contract if small, else the Laplacian determinant.
  6. Check with a second method when the graph is small.

Traps, each with its counterexample

Cayley on a sparse graph → C4 is 4, not 16.

C(m, n−1) as the answer → K4's 20 includes 4 triangles.

Labelled ignored → 16 versus 2 on four vertices.

Cayley confused with Catalan → 16 versus 14 at n = 4.

Self-loops kept after contraction → K3,3 gives 111, not 81.

Five quick checks

1. Spanning trees of K5? 125.

2. Spanning trees of C7? 7.

3. Spanning trees of K2,4? 2^3 · 4^1 = 32.

4. Spanning trees of a graph with two components? 0.

5. BSTs on 4 keys? 14.

Where this connects

The count is the search space behind minimum spanning trees, where Kruskal and Prim pick one tree without enumerating them. The cycle rule explains why a graph with exactly one cycle has as many minimum spanning trees as the cycle is long, when all edges are tied. The Prüfer bijection is the counting proof behind Cayley's formula, which that lesson states; this lesson supplies the mechanism. And the labelled-versus-unlabelled distinction is the same one that separates permutations from combinations.
