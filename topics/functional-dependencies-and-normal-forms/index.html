Topic and objective

TOPIC: Functional dependencies, attribute closure, candidate keys, the normal-form ladder from 1NF to BCNF, and the two decomposition properties — lossless join and dependency preservation. This is the clause "Integrity constraints, normal forms" in Section 9 of the official GATE 2027 CS syllabus, together with the theory you need before it.

LEARNING OBJECTIVE: Given a schema and a set of functional dependencies, compute any attribute closure, find every candidate key, mark the prime attributes, reduce the set to a minimal cover, place the schema at the highest normal form it reaches, and then decide whether a proposed decomposition is lossless and dependency preserving — with the reason, not by memory.

I read this topic as one mechanical procedure, not a list of definitions. Every question in this area reduces to four operations: closure, keys, minimal cover, and two decomposition tests. The lesson teaches the four operations and then runs them on eight real GATE questions, so the definitions arrive with a use attached.

Relations and their properties — relations-and-their-properties. A functional dependency is a property of a relation as a set of ordered pairs; this lesson reuses that vocabulary.

The relational model — relational-algebra-and-sql. Schema versus instance, degree and cardinality, projection as set semantics, and the join. The lossless-join scene is a join of two projections, so that lesson is assumed.

The five ideas this lesson turns on

  1. A dependency is given, not observed. The set is part of the schema. Data can refute a candidate dependency; it can never establish one.
  2. Closure is the only primitive. Keys, prime attributes, 2NF, 3NF, BCNF and dependency preservation are all read off closures. Learn one algorithm and the rest are questions you ask it.
  3. 3NF is BCNF plus one exemption. The exemption is "or the right side is prime". That single clause is the whole difference, and it is what most questions test.
  4. Losslessness and preservation are independent. A decomposition can pass one and fail the other. GATE has asked each one separately.
  5. 3NF synthesis always works; BCNF sometimes forces a choice. A lossless, dependency preserving 3NF decomposition always exists. A BCNF one need not, and no search avoids that.

Build-up, page 1 of 2 — from a rule to a closure

Level 1 is the analogy, level 2 is the definition, and level 3 is the one algorithm everything else is built from. Nothing here needs the animation to be running.

Intuition: the badge and the department

Every employee carries a badge number, and the badge number decides the department. Two people with the same badge number are in the same department — always, not usually. That is one functional dependency: badge determines department.

Two people in the same department may carry different badges, and often do. So department does not determine badge. The arrow is one-way, and that asymmetry is the first thing to internalise.

Educational interpretation The badge is not a proof of anything. It is a picture of a one-way determination, which is all an FD is.

Formal definition

Let R be a relation schema with attribute set U, and let X and Y be subsets of U. The functional dependency X → Y holds on R if, in every legal instance r of R, and for every pair of tuples t1, t2 in r:

t1[X] = t2[X] implies t1[Y] = t2[Y]If the two rows agree on every attribute in X, they must agree on every attribute in Y.

Verified fact "Every legal instance" is the load-bearing phrase. One printed table is one instance; the dependency is a claim about all of them.

Three ways a dependency is described

Trivial. Y is contained in X, as in AB → A. It holds in every relation and tells you nothing.

Non-trivial. Y is not contained in X. This is what every normal-form test is about.

Completely non-trivial. X and Y share no attribute at all, as in A → BC. Exam questions usually say "non-trivial" and mean this.

Armstrong's three axioms

These generate exactly the set of dependencies implied by a given set F. The set of all implied dependencies is written F+, the closure of the set.

if Y ⊆ X then X → YReflexivity. The trivial dependencies, true in every relation.
X → Y gives XZ → YZAugmentation. The same attributes added to both sides.
X → Y and Y → Z give X → ZTransitivity. Chaining through an exact match.

Mathematical derivation Union, decomposition and pseudotransitivity are theorems of these three, not extra rules. Splitting the left side is not one of them: AB → C does not give A → C.

The closure of an attribute set — the one algorithm

X+ = the smallest set containing X and closed under FStart with X. Repeatedly add the right side of any FD whose left side is already inside. Stop when a whole pass adds nothing.

Read the two closures apart, because the notation is the same. F+ is the closure of a set of dependencies and is usually infinite in size. X+ is the closure of a set of attributes and is always a subset of the schema, so it is small and computable by hand. Everything in this lesson uses the second one.

Build-up, page 2 of 2 — keys, prime attributes, and the ladder

Four definitions that all read off the closure, then the ladder they place a schema on.

Superkey, candidate key, prime attribute

Superkey: a set X with X+ = U. It determines every attribute.

Candidate key: a superkey with no proper subset that is also a superkey. Equivalently, drop any one attribute and the closure falls short.

Primary key: one candidate key, chosen by the designer. It carries no extra mathematical meaning, and questions that say "the key is ..." often mean only one of several.

Prime attribute: an attribute that belongs to at least one candidate key. Everything else is non-prime. Prime is a property of an attribute, not of a key.

Minimal cover

A minimal cover of F is a set G equivalent to F with three properties: every right side is a single attribute, no left side has an extraneous attribute, and no dependency in G is redundant.

It is the shortest set of tests. Normal-form questions are answered against a minimal cover, because a redundant dependency can hide or fake a violation.

Mathematical derivation A minimal cover is not unique. Two different minimal covers of the same set can exist, and both are correct — so an option that shows a different minimal cover from yours may still be right.

The ladder, stated precisely

1NF. Every attribute holds a single atomic value. No sets, no repeating groups. This is about the domain, not about dependencies.

2NF. In 1NF, and no non-prime attribute depends on a proper subset of any candidate key. If every candidate key is a single attribute, 2NF holds automatically and the condition is vacuous.

3NF. For every non-trivial X → A: X is a superkey, or A is prime.

BCNF. For every non-trivial X → A: X is a superkey. The second clause of 3NF is deleted.

Mathematical derivation BCNF implies 3NF implies 2NF implies 1NF. The converses all fail, and the lesson shows a schema for each failure. So "highest normal form" is a position on one ladder, not a list of independent properties.

The two decomposition properties

Lossless join. Joining the fragments must give back exactly the original relation: r1 ⋈ r2 ⋈ ... = r. For two fragments there is a shortcut — the shared attributes must determine all of one fragment. For three or more, run the chase.

Dependency preservation. Project F onto each fragment — keep a dependency only when all its attributes fit inside that fragment — and check that the union of those projections still implies every dependency of F.

What "lossy" actually means

A lossy decomposition does not lose rows. It invents them. The join is always a superset of the original relation, and lossy means the superset is strictly larger.

This is why GATE 2005 could ask, for a lossy decomposition, which statement is true, and the answer was r ⊂ s. Rows appeared, not disappeared.

Worked examples, page 1 of 2 — closure and keys

Each step carries its justification. Every number below is computed by the model on this page and printed on the canvas in the same scene.

Example 1 — the closure of AB

Schema R(A,B,C,D,E) with AB → C, BC → D, C → E. This is the schema GATE CSE 2022 used for its superkey question.

  1. Start: {A, B}. Reflexivity puts both in.
  2. AB → C fires, since A and B are held. Now {A,B,C}.
  3. BC → D fires, since B and C are held. Now {A,B,C,D}.
  4. C → E fires. Now {A,B,C,D,E}.
  5. A fourth pass adds nothing. Stop.
(AB)+ = ABCDEThe whole schema, so AB is a superkey.

Example 2 — the 32 subsets, and why the answer is 8

The model enumerates all 31 non-empty subsets and computes each closure. A subset closes to ABCDE exactly when it contains both A and B, because C is reachable only through AB → C, and D only through BC → D.

So the superkeys are AB together with any choice from {C, D, E}. That is one set for each of the eight subsets of a three-element set.

|superkeys| = 2|U| - |key| = 25-2 = 8The formula holds when there is exactly one candidate key.

Mathematical derivation With two or more candidate keys the formula overcounts, because a superset of both keys is counted twice. Use inclusion and exclusion, or count directly.

Example 3 — which subsets are not keys, and why

E+ = E. No dependency has E on the left, so E forces nothing. It is the most tempting wrong answer, because E sits on the right of C → E and appears in every row.

C+ = CE. C reaches E but not D, because BC → D needs B, and not A, because nothing determines A.

(BD)+ = BD and (CD)+ = CD. Partial progress is not a superkey. A set either closes to all of U or it does not.

Example 4 — the four schemas of GATE 2018 Q42

Each schema is tested by the model, not by inspection. R is rollno, C is courseid, E is email, M is marks, G is grade, r is credit.

I — Registration(rollno, courses) with courses set-valued: not 1NF. The ladder stops before it starts.

II — (rollno, courseid, email), RC → E, E → R. Keys RC and CE, so R, C, E are all prime. E → R fails BCNF and passes 3NF: 3NF.

III — (rollno, courseid, marks, grade), RC → MG, M → G. Key RC; M is in no key, so M → G is transitive: 2NF.

IV — (rollno, courseid, credit), RC → r, C → r. C is a proper subset of the key and r is non-prime, so this is partial: 1NF.

Example 5 — GATE 2004 studentPerformance

studentPerformance(Name, CourseNo, RollNo, Grade) with NC → G, RC → G, N → R, R → N.

  1. Closures give two candidate keys: NC and RC.
  2. Prime attributes: N, C, R. Non-prime: G alone.
  3. Minimal cover: CR → G, N → R, R → N.
  4. N → R: N is not a superkey, but R is prime, so 3NF holds and BCNF fails.
  5. Highest normal form: 3NF.

To reach BCNF, split on N → R: fragments R1(N,R) and R2(N,C,G), then re-test both.

Example 6 — GATE 2001 and 2005, the lossy join

R(A,B,C,D) with A → B and C → D, decomposed into AB and CD.

Both dependencies survive, one per fragment, so the split is dependency preserving. But the fragments share no attribute, so the join pairs every row with every row.

|r| = 2, |r1 ⋈ r2| = 4The instance from GATE 2005 Q30. Two original rows survive and two spurious rows appear.

Hence the answer to GATE 2001 is dependency preserving but not lossless join. And the answer to GATE 2005, for a lossy decomposition, is r ⊂ s.

Example 7 — GATE 2001 Q2.23, where no BCNF decomposition works

For R(A,B,C,D) with AB → C and C → AD, the split ABC and CD is lossless and preserves everything — C → A lands inside ABC. But C → A makes ABC fail BCNF.

The model enumerates all 14 partitions of {A,B,C,D} into two or more blocks. For this dependency set, none is BCNF, lossless and dependency preserving at once.

So the answer is option (C), and it is a theorem rather than a failure of search. The same enumeration on the other three options of that question finds a working decomposition for each: AB | BCD, AB | BC | CD, and ABCD itself.

Example 8 — GATE 2008, the library schemas

Book(Title, Author, Catalog_no, Publisher, Year, Price) with TA → C, C → TAPY, PTY → Price.

Keys: TA and C. Prime: T, A, C. Non-prime: P, Y, Price. The dependency PTY → Price has a left side that is not a proper subset of any key, so no partial dependency: 2NF holds. But Price is non-prime and PTY is not a superkey, so 3NF fails. Book is in 2NF.

Collection(Title, Author, Catalog_no) with TA → C and C → TA has every attribute prime and both left sides superkeys, so it is in BCNF. See the Edge cases tab for the nuance in how that question's option is worded.

Boundaries and counterexamples

Every card here is a case where the rule still holds but a shortcut fails, or where a familiar sentence is true but not tight. Each one is checked by the model, and the check is named.

Counterexample — BCNF does not imply dependency preserving

R(A,B,C,D) with AB → C, C → AD. The decomposition ABC | CD is lossless and preserving but not BCNF. Pushing to BCNF forces A away from C, and then AB → C has no fragment holding A, B and C together.

Mathematical derivation Checked by enumerating all 14 partitions: zero satisfy all three requirements. This is the schema in GATE 2001 Q2.23.

Counterexample — a decomposition that is BCNF and preserving, yet lossy

R(A,B,C,D) with A → B, C → D, split into AB | CD. Both fragments are in BCNF, both dependencies are preserved, and the join invents two rows.

Mathematical derivation The two-fragment test fails at once: the shared attribute set is empty, so it cannot determine anything. This kills the belief that a decomposition is automatically lossless because each piece is well designed.

Every binary schema is in BCNF

With two attributes, the only non-trivial dependencies are A → B and B → A. In each case the left side is a candidate key, hence a superkey, so BCNF holds.

Mathematical derivation Both cases are checked by the model. This is why questions about 3NF-but-not-BCNF always need at least three attributes — the smallest witness is a three-attribute schema, and Schema II of GATE 2018 is exactly that.

If every attribute is prime, the schema is in 3NF

When no non-prime attribute exists, the 3NF exemption applies to every dependency, so 3NF cannot fail. BCNF can still fail, because BCNF ignores primeness.

Mathematical derivation Collection(Title, Author, Catalog_no) is the example: every attribute is prime, and it reaches BCNF. Schema II of GATE 2018 is the other shape: every attribute is prime, 3NF holds, BCNF fails. Both are checked.

The 2008 option that is true but not tight

GATE 2008 Q69 asks for the true statement about Book and Collection. The accepted answer is option (C): "Book is in 2NF and Collection in 3NF".

That option is true — and Collection is in fact in BCNF, which is stronger. Since BCNF implies 3NF, the sentence stays true. The other three options are false, so (C) is the only answer.

Community observation Published discussions of this question disagree on whether to call Collection 3NF or BCNF. The disagreement does not change the key, and the honest reading is: BCNF, which is also 3NF.

When 2NF is vacuous

If every candidate key of a schema is a single attribute, no proper subset of a key can exist, so 2NF cannot fail. The condition is not wrong; it has nothing to test.

Mathematical derivation This is why R(A,B,C,D,E) with a single-attribute key is never a 2NF question, and why 2NF questions always have a composite key.

A superkey with a redundant attribute

ABC can be a superkey while AB already closes to everything. Then ABC is a superkey and not a candidate key, and the normal-form tests must be run against the candidate keys, never against the stated "key".

Mathematical derivation The model always enumerates candidate keys by minimality rather than trusting a declared key, which is why its verdicts match the published answers on all eight previous-year items.

An FD that holds in the instance but not in the schema

In R(A,B,C) holding only the rows (1,7,a) and (2,9,b), both A → B and A → C happen to hold, and so does B → C. None of them is implied by the schema.

A question that gives you a table and asks "which FD holds" is asking about that table, and must say so. A question that gives you a dependency set is asking about every instance, and the table is then irrelevant or a counterexample.

Six beliefs that cost marks

Each card gives the belief as a learner would state it, why it is tempting, the smallest structure that kills it, and the rule to use instead. The misconceptions are drawn from the standard textbook treatment and from published discussion of these questions; the counterexamples are computed here.

1. "X → Y means the two attributes are related, so Y → X too"

Why it tempts: the arrow looks like an equals sign, and in a small table the two directions often hold together.

Why it is wrong: the definition quantifies over pairs of rows in one direction only. A → B constrains rows that agree on A; it says nothing about rows that agree on B.

Minimal counterexample: R(A,B) with rows (1,7), (2,7). Then A → B holds and B → A fails on those two rows.

Correct rule: the arrow is one-way. Two dependencies in both directions mean A and B are two candidate keys, which is a much stronger claim.

2. "Every schema has a lossless, dependency preserving BCNF decomposition"

Why it tempts: the BCNF decomposition algorithm always terminates, so it feels as if it always succeeds.

Why it is wrong: the algorithm always produces a lossless BCNF decomposition. It does not always preserve the dependencies.

Minimal counterexample: R(A,B,C,D) with AB → C, C → AD. All 14 partitions are tested; none is BCNF, lossless and preserving.

Correct rule: a lossless, dependency preserving 3NF decomposition always exists. For BCNF, losslessness is guaranteed and preservation is not.

3. "3NF and BCNF differ only in rare, contrived cases"

Why it tempts: most textbook examples are in both, so the gap looks academic.

Why it is wrong: the gap is exactly the set of dependencies whose right side is prime and whose left side is not a superkey. Any schema with a prime attribute determined by a non-key lands there, which is common in practice.

Minimal counterexample: R(A,B,C) with AB → C and C → A. Keys are AB and BC; C → A fails BCNF and passes 3NF.

Correct rule: name the exempt dependency explicitly. If you cannot name one, the schema is in BCNF and saying "3NF" is merely weaker.

4. "I can split the left side of a dependency"

Why it tempts: decomposition is a valid rule, and it is easy to forget which side it applies to.

Why it is wrong: only the right side may be split. Splitting the left side is the reverse of augmentation, which is not sound.

Minimal counterexample: R(A,B,C) with AB → C, rows (1,2,9) and (1,3,8). AB → C holds; A → C fails, because the two rows agree on A and disagree on C.

Correct rule: X → YZ gives X → Y and X → Z. XY → Z gives nothing about X → Z unless Y is redundant, and "redundant" must be checked by closure.

5. "Lossy means rows were lost"

Why it tempts: the word says "loss".

Why it is wrong: a natural join of projections always contains every original row, so the join is a superset. The failure is extra rows, not missing ones.

Minimal counterexample: r with (1,2,3,3) and (1,5,3,4), projected onto ABC and AD and joined, gives four rows. Both originals survive; two spurious rows appear.

Correct rule: lossless means the join equals r exactly. Lossy means the join is strictly larger, and the extra tuples violate the dependencies that were supposed to hold.

6. "A schema with no visible redundancy is in BCNF"

Why it tempts: normalisation is taught as removing redundancy, so the absence of repeated data looks like the goal has been reached.

Why it is wrong: a normal form is a statement about the dependency set. A particular instance can show no repetition while the schema still admits a violation, and can show repetition that the dependencies permit.

Minimal counterexample: R(A,B,C) with AB → C, C → A holding a single row shows no repetition at all, and is still not in BCNF.

Correct rule: test the dependencies, not the rows. Compute the closure, find the keys, test each dependency of a minimal cover.

How this topic is examined

Six of the eight question categories in the method apply here. Construction and multiple-conditions are the two that carry most of the marks, and both are procedural — which is good news, because a procedure can be practised.

Categories that apply

A — Direct definition. "Which statement about 1NF is true?" Answered from the definition, not from a worked example.

B — Property verification. "Is this schema in 3NF?" The closure and the minimal cover decide it.

C — Calculation. "How many superkeys?" or "the highest normal form is ___". Counting and classification.

E — Counterexample reasoning. "Which does not have a lossless, dependency preserving BCNF decomposition?" One failure kills an option.

F — Multiple conditions. Lossless and preserving and BCNF. Partial satisfaction is the trap, and it is the single most common way this topic is lost.

H — Multi-step. Closure, then keys, then primeness, then the ladder. Four steps before an answer appears.

The decision procedure

  1. Closures. Compute X+ for each single attribute, then for each pair that did not already close to everything. Stop when a set closes to U.
  2. Keys. A candidate key is a closure of U with nothing removable. List every one, not just the declared primary key.
  3. Prime attributes. Union of all candidate keys. Everything else is non-prime.
  4. Minimal cover. Split right sides, remove extraneous left-side attributes, remove redundant dependencies.
  5. Two questions per dependency. Is the left side a superkey? Is the right side prime? Superkey means BCNF. Non-superkey with prime right side means 3NF. Non-superkey with non-prime right side means at most 2NF — or 1NF if the left side is a proper subset of a key.
  6. Decomposition. Chase for losslessness, projection for preservation. Two independent answers.

Step 5 is the whole ladder in one line, and it is worth memorising as a sentence rather than as four separate definitions.

The four wrong approaches that recur

Reading the table. Answering from the printed rows when the question gave a dependency set. The rows cannot establish a dependency.

Stopping at the declared key. Questions say "the key is X" meaning the primary key. There may be three candidate keys, and missing one moves the schema down a rung.

Assuming 3NF means BCNF. Writing "BCNF" because no redundancy is visible, when one exempt dependency exists.

Checking one property only. Declaring a decomposition good because it is lossless, without testing preservation — or the reverse.

What a full-mark answer looks like

State the candidate keys. Name the violating dependency. Say whether its right side is prime. Then place the schema. Three sentences, each checkable, and each one earns the mark separately.

NATMediumPYQ — GATE CSE 2022

Consider a relation R(A, B, C, D, E) with the functional dependencies AB → C, BC → D, C → E. The number of superkeys of R is ______.

Answer: 8

(AB)+ = ABCDE, and neither A+ nor B+ closes to everything, so AB is the only candidate key. Every superkey is AB plus any subset of {C,D,E}, giving 23 = 8.

Answering 32 counts every subset; answering 1 counts only the candidate key; answering 4 assumes two attributes outside the key instead of three. The model enumerates all 31 non-empty subsets and finds exactly 8 with a full closure.

MCQMediumPYQ — GATE CSE 2018, Q42

Four relational schemas, with all non-trivial dependencies listed. Which one is in 3NF but not in BCNF?

I: Registration(rollno, courses), courses is set-valued, rollno → courses.
II: Registration(rollno, courseid, email), rollno,courseid → email, email → rollno.
III: Registration(rollno, courseid, marks, grade), rollno,courseid → marks,grade, marks → grade.
IV: Registration(rollno, courseid, credit), rollno,courseid → credit, courseid → credit.

(A) I   (B) II   (C) III   (D) IV

Answer: (B) Schema II

Schema II has candidate keys {rollno, courseid} and {email, courseid}, so rollno, courseid and email are all prime. email → rollno has a non-superkey on the left and a prime right side: 3NF allows it, BCNF does not.

I fails 1NF because courses is set-valued. III fails 3NF on marks → grade, where grade is non-prime, so it stops at 2NF. IV fails 2NF on courseid → credit, so it stops at 1NF.

Choosing IV is the common error: it looks like II but its right side is non-prime. The whole question turns on that one difference.

MCQMediumPYQ — GATE CSE 2004, Q37

The relation scheme studentPerformance(Name, CourseNo, RollNo, Grade) has the dependencies Name, CourseNo → Grade, RollNo, CourseNo → Grade, Name → RollNo, RollNo → Name. The highest normal form of this relation scheme is

(A) 1NF   (B) 2NF   (C) 3NF   (D) BCNF

Answer: (C) 3NF

Candidate keys are {Name, CourseNo} and {RollNo, CourseNo}, so Name, CourseNo and RollNo are prime and Grade alone is non-prime. Grade depends on the whole of a key, never on part of one, so 2NF holds.

Name → RollNo has a non-superkey on the left but a prime right side, so 3NF holds and BCNF fails. The model's minimal cover is CR → G, N → R, R → N.

MCQEasyPYQ — GATE CSE 2001

Consider a schema R(A, B, C, D) with functional dependencies A → B and C → D. Then the decomposition of R into R1(AB) and R2(CD) is

(A) dependency preserving and lossless join
(B) lossless join but not dependency preserving
(C) dependency preserving but not lossless join
(D) not dependency preserving and not lossless join

Answer: (C)

A → B fits entirely inside AB and C → D fits entirely inside CD, so the decomposition is dependency preserving.

But the fragments share no attribute. The shared set is empty, so it cannot determine all of either fragment, and the two-fragment test fails immediately. The model also runs the chase and gets the same verdict.

MCQHardPYQ — GATE CSE 2001, Q2.23

R(A, B, C, D) is a relation. Which of the following does not have a lossless join, dependency preserving BCNF decomposition?

(A) A → B, B → CD   (B) A → B, B → C, C → D
(C) AB → C, C → AD   (D) A → BCD

Answer: (C)

For (C), the split ABC | CD is lossless and preserving, but C → A lives inside ABC and makes it fail BCNF. Removing that violation separates A from C, and then AB → C has no home.

The model enumerates all 14 partitions of {A,B,C,D} and finds none that is BCNF, lossless and preserving for (C). For the other three options it finds working decompositions: AB | BCD for (A), AB | BC | CD for (B), and ABCD unchanged for (D), which is already in BCNF.

The trap is stopping at "lossless and preserving" for (C) and moving on. BCNF is a third, independent requirement.

MCQMediumPYQ — GATE CSE 2005, Q30

Let r be a relation instance with schema R = (A, B, C, D). Define r1 = πA,B,C(r) and r2 = πA,D(r), and let s = r1 * r2 where * is the natural join. Given that the decomposition of r into r1 and r2 is lossy, which one of the following is TRUE?

(A) s ⊂ r   (B) r ∪ s = r   (C) r ⊂ s   (D) r * s = s

Answer: (C) r is a subset of s

On the instance in this lesson, r holds (1,2,3,3) and (1,5,3,4). Both projections hold two rows, and the join holds four: the two originals plus (1,2,3,4) and (1,5,3,3).

A natural join of projections always contains every original row, so r ⊆ s unconditionally. Lossy means the inclusion is strict, which rules out (A) and (B). Option (D) is a different identity and does not follow.

MCQMediumPYQ — GATE CSE 2008, Q69

Book(Title, Author, Catalog_no, Publisher, Year, Price) and Collection(Title, Author, Catalog_no), with Title,Author → Catalog_no; Catalog_no → Title,Author,Publisher,Year; Publisher,Title,Year → Price. Assume {Author, Title} is a key for both schemes. Which statement is true?

(A) Both Book and Collection are in BCNF
(B) Both Book and Collection are in 3NF only
(C) Book is in 2NF and Collection in 3NF
(D) Both Book and Collection are in 2NF only

Answer: (C)

Book has candidate keys {Title,Author} and {Catalog_no}. The dependency Publisher,Title,Year → Price has a left side that is not a proper subset of any key, so no partial dependency exists and 2NF holds. But Price is non-prime and the left side is not a superkey, so 3NF fails. Book is in 2NF.

Collection has keys {Title,Author} and {Catalog_no}, every attribute prime, and both left sides superkeys — so it is in BCNF, and therefore also in 3NF. Option (C) is true; the others are false because Book is not in BCNF or 3NF. See the Edge cases tab for why (C) is accepted although Collection is stronger than 3NF.

MCQMediumPYQ — GATE CSE 2020, Q15

Consider a relational table R that is in 3NF but not in BCNF. Which one of the following statements is TRUE?

(A) A cell in R holds a set instead of an atomic value.
(B) There is a dependency X → A where X is not a superkey, A is non-prime, and X is not a proper subset of any key.
(C) There is a dependency X → A where X is not a superkey, A is non-prime, and X is a proper subset of some key.
(D) There is a dependency X → A where X is not a superkey and A is a prime attribute.

Answer: (D)

3NF is BCNF plus the exemption "or A is prime". A schema in 3NF but not BCNF therefore has exactly one kind of violation: a non-superkey left side with a prime right side.

(A) is a 1NF failure, and a table in 3NF is already in 1NF. (B) is a transitive dependency, which fails 3NF. (C) is a partial dependency, which fails 2NF. Only (D) describes a schema that survives 3NF and fails BCNF, and it is the pattern behind both Schema II of GATE 2018 and studentPerformance of GATE 2004.

Practice, page 3 of 3 — original questions

These four are written for this lesson in GATE format. They are original practice questions, not previous-year items, and they carry no official marks. Every answer was computed by the model.

NATMediumOriginal practice question

Let R(A, B, C, D, E) have the dependencies A → BC, CD → E, B → D, E → A. The number of candidate keys of R is ______.

Answer: 4

The candidate keys are A, E, BC and CD.

A+: A gives B and C; B gives D; C and D give E. All five. E+: E gives A, and then the same chain. All five. (BC)+: B gives D, C and D give E, E gives A. All five, and neither B nor C alone does. (CD)+: C and D give E, E gives A, A gives B. All five, and neither C nor D alone does.

Answering 2 usually means stopping after A and E, which misses the two composite keys. This schema is also in 3NF and not BCNF, since B → D has a non-superkey on the left and D is prime.

MCQEasyOriginal practice question

A minimal cover of F = {A → BC, B → C, A → B, AB → C} is

(A) {A → B, B → C, AB → C}   (B) {A → B, B → C}
(C) {A → BC, B → C}   (D) {A → C, B → C}

Answer: (B)

Split the right sides: A → B, A → C, B → C, A → B, AB → C. Then A → C is redundant, because A → B and B → C give it by transitivity. Then AB → C is redundant for the same reason, and B is extraneous on its left side.

(A) keeps a redundant dependency, so it is not minimal. (C) has a two-attribute right side, so it is not in minimal-cover form. (D) drops A → B, which is not implied by the rest.

MSQHardOriginal practice question

Let R(A, B, C, D) have A → B and BC → D. Which of the following decompositions are lossless join?

(A) AB and ACD   (B) ABC and CD
(C) BCD and AB   (D) AB and CD

Answer: (A) only

(A): the shared attribute is A, and A+ = AB contains all of AB, so the two-fragment test passes and the join is lossless. The chase agrees.

(B): shared C, and C+ = C, which contains neither fragment. Lossy. (C): shared B, and B+ = B. Lossy. (D): shared set empty. Lossy.

Notice that (A) is lossless but not dependency preserving: BC → D needs B, C and D together, and no fragment holds all three. Losslessness and preservation are independent, which is exactly what this question is built to expose.

MCQHardOriginal practice question

Which one of the following statements is FALSE?

(A) Every schema in BCNF is also in 3NF.
(B) A lossless, dependency preserving 3NF decomposition always exists for a schema whose dependencies are given.
(C) A lossless, dependency preserving BCNF decomposition always exists for a schema whose dependencies are given.
(D) A decomposition can be in BCNF and dependency preserving while being lossy.

Answer: (C) is false

(C) is the classic overreach. The BCNF decomposition algorithm guarantees losslessness, not preservation. R(A,B,C,D) with AB → C and C → AD has no such decomposition: all 14 partitions are checked and none qualifies.

(A) is true by definition, since BCNF deletes a clause from 3NF. (B) is the 3NF synthesis theorem. (D) is true and is the AB | CD case: both fragments BCNF, both dependencies preserved, and the join invents two rows.

(D) is the option most often marked wrong by learners, because "well-decomposed" feels as though it should imply "lossless". It does not; the two properties are tested separately.

Revision sheet

One screen. Definitions, formulas with their conditions, the decision procedure, the traps, and six quick checks with the answers inverted at the bottom of the card.

Definitions, one line each

FD X → Y: in every legal instance, two rows agreeing on X agree on Y.

Trivial: Y ⊆ X. Non-trivial: not that.

Closure X+: everything X forces, computed by the fixpoint pass.

Superkey: X+ = U. Candidate key: minimal superkey.

Prime: in at least one candidate key.

Minimal cover: equivalent set, single-attribute right sides, no extraneous attribute, no redundant dependency.

Lossless: the join of the fragments equals r. Preserving: the union of the projected dependency sets still implies F.

Formulas, and when each holds

|superkeys| = 2n-kOnly when there is exactly one candidate key of size k. Otherwise count directly.
lossless(R1,R2) iff (R1 ∩ R2)+ ⊇ R1 or (R1 ∩ R2)+ ⊇ R2Two fragments only. For three or more, run the chase.
r ⊆ r1 ⋈ r2 ⋈ ...Always true. Lossy means the inclusion is strict.
3NF = BCNF or (A is prime)The exemption, applied per dependency. It is the only difference.

The three decompositions of the axiom set — union, decomposition, pseudotransitivity — are theorems, so using them is safe. Splitting the left side is not one of them.

The procedure, compressed

  1. Closure each candidate left side.
  2. List every candidate key by minimality.
  3. Union the keys to get the prime attributes.
  4. Reduce to a minimal cover.
  5. Per dependency: superkey left? prime right?
  6. For a decomposition: chase, then project.

Steps 1 to 3 are the same in every question. Doing them first turns the rest into lookups.

Traps, each with its defusing case

The arrow is one-way. (1,7),(2,7) satisfies A → B and breaks B → A.

BCNF may cost preservation. AB → C, C → AD has no decomposition with all three properties.

Lossy means extra rows. Two rows become four on AB | CD.

Lossless does not imply preserving. AB | ACD under A → B, BC → D is lossless and loses BC → D.

Missing a key costs a rung. email → rollno looks like a 2NF failure until the second key is found.

Do not split the left side. AB → C does not give A → C.

Six quick checks

1. R(A,B,C), AB → C, C → A. Highest normal form?

2. Same schema: how many candidate keys, and which?

3. R(A,B,C), A → B. Is it in BCNF?

4. R(A,B,C,D), AB → C, split into ABC | D. Lossless?

5. R(A,B,C), AB → C, C → B. Is C → B a 3NF violation?

6. Does X → Y and Y → Z give XZ → Y?

Answers, inverted: 1 — 3NF (keys AB and BC; C → A has a prime right side). 2 — two, AB and BC. 3 — yes; A is a superkey, so every non-trivial dependency is fine. 4 — no; the shared set is empty. 5 — no; B is prime, so the exemption applies, which makes it 3NF and not BCNF. 6 — yes, by augmentation then transitivity.
