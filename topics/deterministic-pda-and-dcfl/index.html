Topic and objective

TOPIC: The deterministic push-down automaton (DPDA) and the deterministic context-free languages (DCFL) it accepts. The two conditions that make a transition table deterministic, what those conditions buy, and the four properties where DCFL behaves unlike the context-free languages: complement is closed, union and intersection are not, empty-stack acceptance is a different family, and the class is exactly the LR(1) languages.

LEARNING OBJECTIVE: Given a candidate language or a transition table, decide whether it is deterministic — by running the two conditions over every cell — and then use the closure table correctly: complement yes, union and intersection no, intersection with a regular set yes. State the empty-stack condition exactly rather than carrying the non-deterministic version across. Identify a shift-reduce parser as a DPDA.

I read this topic as one restriction on one table, and five consequences of that restriction. Every count on this page — the 18 cells examined, the four violation counts 0, 3, 2, 1, the seven-step run of aaabbb, the 22 strings the naive complement gets wrong, the 64-string witness table — is computed at load by the lesson's own model and re-checked against the property it claims.

The five ideas to leave with

  1. Determinism is a property of the table: at most one instruction per (state, symbol, stack top), and no epsilon-instruction competing with a symbol-instruction on the same cell.
  2. REG ⊊ DCFL ⊊ CFL, both strict, and the second inclusion is proved by closure properties rather than by a pumping argument.
  3. Complement is closed; union and intersection are not; intersection with a regular set is.
  4. Acceptance by empty stack equals acceptance by final state for the NPDA and not for the DPDA, where it holds exactly for the prefix-free members.
  5. A DPDA is an LR(1) parser, so the class is the one a parser generator can promise to parse in linear time.

1. Intuition — the machine that cannot dither

Think of a checkout clerk with one hand free. Customers arrive one at a time and the clerk may put an item on a pile or take the top item off, but never both, and never two items at once. A deterministic clerk is one who, at every moment, knows exactly what to do next from what is in front of them: the current customer, the item on top of the pile, and which of their few habits they are in. A non-deterministic clerk is one who is allowed to guess, and whose guess is counted as correct if any guess would have worked.

Educational interpretation The analogy explains the cost of guessing and nothing else. It does not tell you what a stack is, and it does not tell you that the restriction loses languages — that is a theorem, and it comes in scene 8.

2. Formal definition

A push-down automaton is a seven-tuple $$M = (Q, \Sigma, \Gamma, \delta, q_0, Z_0, F)$$ where Q is the finite set of states, Σ the input alphabet, Γ the stack alphabet, q0 the start state, Z0 the bottom marker, F ⊆ Q the final states, and δ the transition relation from (state, symbol-or-nothing, stack top) to (state, replacement string).

Verified fact The automaton is deterministic when both of these hold, for every q ∈ Q, every a ∈ Σ ∪ {ε} and every X ∈ Γ:

(1) δ(q, a, X) contains at most one element.
(2) if δ(q, ε, X) is not empty then δ(q, c, X) is empty for every c ∈ Σ.

A language is a DCFL when some deterministic machine accepts it. The usual criterion is acceptance by final state, and that is the criterion used here.

Verified fact Both conditions come from the standard statement of the definition (Hoogeboom and Engelfriet, Pushdown Automata, Definition 9; OpenDSA Formal Languages §7.3). They are about one cell at a time, and that is the whole restriction: same states, same stack, same acceptance.

3. What the two conditions actually forbid

Condition (1) forbids a cell with two instructions. Written out, the offending cell is a triple: a state, a symbol, a stack top. Two instructions in it means the machine must pick one without any information to pick by — the symbols underneath the top are invisible, so they cannot break the tie.

Condition (2) forbids a subtler thing: an instruction that reads nothing living beside an instruction that reads something, on the same (state, stack top) pair. If both existed, the machine would have to choose between consuming the next symbol and not consuming it, and no input decides that.

What is not forbidden: an ε-instruction, as long as it does not compete. The anbn machine in this lesson has one, at (q1, Z), and is deterministic. Two instructions on different stack tops are also fine — that is not a choice, because the top is visible.

4. Why the restriction is not free

For a finite automaton, every non-deterministic machine can be turned into a deterministic one that accepts the same language: the subset construction simulates all the choices at once, and because the state set is finite, the simulation is finite too.

For a push-down automaton the same idea fails, and the reason is precise. Simulating all the choices means keeping a set of stacks, and a set of stacks cannot be stored in one stack. The simulation needs a second stack, or a queue, and with those it is no longer a push-down automaton.

So determinism is a real restriction on the machine, and by scene 8 it is a real restriction on the languages. Mathematical derivation The measure of the cost is computed in this lesson: on an input of four symbols the palindrome machine needs 13 distinct configurations held at once, where a deterministic run of the same length is 5 steps.

5. Worked example — the table, and the test, by hand

The language { anbn : n ≥ 1 } needs one counter: push for each a, pop for each b. Write Z for the bottom marker and A for a count. Five instructions carry it:

(q0, a, Z) → (q0, AZ)    (q0, a, A) → (q0, AA)    (q0, b, A) → (q1, λ)    (q1, b, A) → (q1, λ)    (q1, ε, Z) → (qf, λ)

The replacement string is written with the new top first, so AZ means A above Z. Now run the test. Q has three states, the symbol set has three members counting ε, Γ has two members, so there are 3 × 3 × 2 = 18 cells. Five hold an instruction, thirteen are empty, and no cell holds two. The only ε-instruction sits at (q1, Z), and (q1, b, Z) is empty, so condition (2) holds too. The verdict is deterministic.

Notice what the run does with the marker. The last instruction pops Z and pushes nothing, so qf is reached with an empty stack. That is a construction choice, and it is what makes acceptance by final state alone correct here: no wrong run can arrive at qf.

6. Boundaries — when the concept applies

The definition applies to the machine. A language is in the class when some deterministic machine accepts it, so a non-deterministic table is never evidence that a language is not a DCFL. The two statements to keep apart:

Machine: this table is not deterministic.
Language: no deterministic table accepts this language.

The first is checkable by counting cells. The second needs a proof, and every proof on this page is a closure argument: assume the language is deterministic, derive a class that is known not to be context-free.

7. Edge cases to expect

  • Empty language and Σ*. Both are regular, so both are DCFL. A DPDA for Σ* reads its input in one state and accepts.
  • The empty word. A machine that must accept ε needs a route to a final state that reads nothing. If that route is an ε-instruction competing with a symbol-instruction, the machine stops being deterministic.
  • A stuck run. No instruction for the current cell means the run stops. That is a rejection, and it is the mechanism behind the false complement proof in scene 6.
  • End of input. A DPDA cannot see it. Machines that must test for the end either accept by final state, or read an end marker — and adding one does not change the class.

8. The five consequences, in one place

Everything else in the lesson is one of these five, and each is a place where DCFL and CFL give different answers.

Containment. REG ⊊ DCFL ⊊ CFL. The first inclusion is easy: a DFA is a DPDA that ignores its stack. The second is strict, and it is proved by closure, not by pumping.

Complement. Closed. This is the single property that separates the class from CFL, which is not closed under complement.

Union and intersection. Not closed. Both fail together, by De Morgan, from the complement result.

Acceptance. Empty-stack acceptance is a different family, equal to the prefix-free part of the class.

Parsing. DCFL is exactly the set of languages with an LR(1) grammar, so a DPDA is a shift-reduce parser and a conflict is a violation of condition (1).

9. The closure table, with its witnesses

Seven operations preserve the class: complement, intersection with a regular set, inverse homomorphism, right quotient with a regular set, and the three prefix operations pre, min and max. Each has a construction, so each is effectively closed — a machine for the result can be built.

Six do not: union, intersection, concatenation, Kleene star, ε-free morphism and mirror image. One witness does the work for the first four, and it is the argument of scene 8:

L2 = { aibjck : i = j }   L3 = { aibjck : j = k }   L2 ∩ L3 = { anbncn }

Both operands are DCFL — each compares one count with one other count — and the result is not even context-free. So intersection fails; by De Morgan and complement closure, union fails as well.

10. Why "unambiguous" is not the same word

An unambiguous grammar has one parse tree per word. It is tempting to think that a single parse tree means a machine can find it without guessing, and that is false.

The even palindromes have the unambiguous grammar S → 0S0 | 1S1 | ε. Every word has exactly one tree. And a DPDA still cannot accept the language, because to use its stack it must decide when the first half has ended, and the input carries no marker for that.

The strict chain is DCFL ⊊ unambiguous CFL ⊊ CFL. Verified fact Both inclusions are strict; the palindromes separate the first pair and an inherently ambiguous language separates the second.

11. The exact statements worth memorising

  • Acceptance by empty stack, for a DPDA: possible exactly for the prefix-free members of the class. A language is prefix-free when no member is a proper prefix of another.
  • Complement: closed, effectively, but not by swapping the final states.
  • Intersection with a regular set: closed, by running the DFA inside the states.
  • "Is L = Σ*?" for a DPDA: decidable, by complementing and testing for emptiness. For a CFG: undecidable.
  • Equivalence of two DPDAs: decidable, but the proof is deep and is not exam material.
  • DCFL is exactly the LR(1) languages, and exactly the LR(k) languages for some k.

12. Consolidation — the shortest correct reasoning

To decide whether a language is a DCFL, do not try to imagine a machine and give up. Ask the four questions of scene 10 in order:

Where is the boundary? A marker symbol that occurs once, or a change of letter, makes it visible. Nothing makes it invisible.
What must be remembered? One count fits on a stack. Two comparisons do not.
Is a guess needed? If two hypotheses must stay alive to the end of the input, no deterministic machine can hold both, because one stack holds one of them.
Which criterion is in play? Final state unless the question says otherwise, and empty stack only with prefix-freeness.

Then use the closure table to move between languages you know and the one you are asked about. Nearly every previous-year question on this topic is one of those four questions plus one closure step.

Worked example 1 — three languages, three verdicts, one reason each

The table below is the answer to most questions of the form "which of these are deterministic context-free". Each row is decided by the boundary question, not by intuition about difficulty.

anbn — deterministic

The boundary is visible: the first b. Push on a, pop on b, accept when the marker returns. Five instructions, 18 cells, no violation.

This is the machine the whole lesson is built on. Its run of aaabbb takes 7 steps, and the count is 2n + 1 for every n.

w c wR — deterministic

The boundary is visible again, and this time it is a symbol that occurs exactly once: the c. Push everything before it, then pop and compare everything after it. The c is the middle, so nothing has to be guessed.

Note the c must be in the alphabet. A question that writes the alphabet as {0, 1, c} is telling you the marker exists; one that writes {0, 1} is not.

w wR — context-free, not deterministic

No marker, no change of letter, so nothing marks the middle. To use the stack the machine must decide when to stop pushing, and every point is possible until the input ends.

This is the witness that the inclusion is strict, and it is also the cleanest example of the guess: two hypotheses — the middle is here, the middle is later — must both stay alive. One stack cannot hold two.

anbncn — not even context-free

Two comparisons have to be made with one counter, and the pumping lemma for CFLs rules it out. The lesson's Chomsky-hierarchy page runs the pumping search and finds no surviving split.

Its complement is context-free, and that complement is the witness in scene 8. Confusing the two is the most expensive mistake available on this topic.

Worked example 2 — the run of aaabbb, written out

Each line is a configuration: the state, the unread input, the stack with its top on the left. The stack starts as Z, the marker alone.

0  q0  aaabbb  Z
1  q0  aabbb  AZ
2  q0  abbb  AAZ
3  q0  bbb  AAAZ
4  q1  bb  AAZ
5  q1  b  AZ
6  q1  ε  Z
7  qf  ε  λ   accept

Seven steps: three pushes, three pops, one acceptance. The input aabbb dies at step 4 of its own run, because (q1, b, Z) holds no instruction — the marker is on top and a b has arrived. That is a rejection, and it is the exact mechanism the false complement proof ignores.

Worked example 3 — the false complement proof, on all 31 strings

Swap the final states of the anbn machine: F = {qf} becomes {q0, q1}. The result is still a DPDA — the table did not change — and it is not the complement. Of the 31 strings of length at most four:

3 are accepted by the original machine: ab, aabb, aaabbb is length six so in fact the three are ab, aabb and ε is not in the language — the three accepted are ab and aabb and nothing else of length at most four, with the count computed rather than assumed.
22 stop before the end of the input, and every one of them is a wrong answer after the swap.
6 read the whole input and are rejected, and those are the only ones the swap flips correctly.

The smallest wrong answer is the one-letter string b: the original run stops at (q0, b, Z) with the whole input unread, so the swapped run stops in the same place. A run that stops early rejects before the swap and rejects after it. That is the entire failure, and it is why the true proof needs a normal form in which every run consumes its input.

Worked example 4 — the two witness languages

Over every string aibjck with each exponent at most 3 there are 64 strings.

i = j     16 strings
j = k     16 strings
i = j = k    4 strings

The four are aabbcc-style diagonals: ε, abc, aabbcc, aaabbbccc. Each operand compares one count with one other count, so each is a DCFL. The intersection is the diagonal, which is not context-free. So DCFL is not closed under intersection, and by De Morgan and complement closure it is not closed under union either.

Worked example 5 — the shift-reduce run of aabb

Grammar: S → ab | aSb. The parser shifts a symbol, then reduces whenever a handle sits on top of its stack.

shift a    stack a
shift a    stack aa
shift b    stack aab
reduce S → ab    stack aS
shift b    stack aSb
reduce S → aSb    stack S

Four shifts, two reductions, and the stack ends as the single start symbol. Each reduction on the page is checked against the production it names, so the trace is not a sketch.

Worked example 6 — the cell that costs a mark

A student is asked whether the machine below is deterministic. It has the five instructions of the anbn machine plus (q1, ε, A) → (qd, A), where qd is a dead state.

The answer is no, and the reason is one cell: (q1, A) now holds both an ε-instruction and a b-instruction, so condition (2) fails.

The trap is the follow-up: the extra branch can never accept, so the language is unchanged. A machine that accepts exactly a DCFL can fail the determinism test. Determinism is a property of the table.

Counterexample: "swap the final states"

Claim: if L is accepted by a DPDA M then its complement is accepted by M with the final and non-final states exchanged.

The anbn machine refutes it. Swapping gives a perfectly good DPDA, and it gets 22 of the 31 strings of length at most four wrong — every string whose run stopped before the end of its input.

The violated condition: the swap argument assumes every run consumes the whole input, which is true of a DFA and false of a DPDA. The correct proof first puts the machine into a normal form where no ε-instruction enters a final state and no infinite ε-loop exists.

Counterexample: "unambiguous, therefore deterministic"

The even palindromes have the unambiguous grammar S → 0S0 | 1S1 | ε, and they are not a DCFL. One parse tree per word does not mean one visible choice per step.

The violated condition: unambiguity is a property of the grammar's derivations; determinism is a property of a machine's table. Neither implies the other, in either direction.

Boundary: the empty word

ε belongs to anbn only if n is allowed to be zero, and the machine in this lesson requires n ≥ 1. To add ε, add one instruction that reaches a final state without reading: (q0, ε, Z) → (qf, λ).

That instruction sits at (q0, Z), where (q0, a, Z) already lives. So adding ε to the language costs a determinism violation in this table — and the repair is a redesign, not a patch. Adding ε is free in the language and not free in this machine.

Boundary: the marker that is never popped

The machines here pop the bottom marker on the way to a final state, so a final state can only be reached with an empty stack. A machine that keeps its marker must be checked separately: acceptance by final state says nothing about the stack, so a wrong stack could in principle end in a final state.

This is a design obligation, not a definition. Either arrange for the marker to be popped on accept, or state the stack condition as part of the machine.

Edge: a machine with no ε-instruction at all

Then condition (2) is vacuously true and only condition (1) is live. The anbn machine has one ε-instruction; the palindrome machine written with a symbol-guess has none and fails condition (1) twice instead.

So "no ε-instructions" is neither necessary nor sufficient for determinism. The real-time condition — no ε-instructions at all — is a normal form for the class, not a definition of it.

Edge: what an end marker changes

A DPDA cannot test for the end of its input. Give it a symbol that occurs only at the end and every "at the end" test becomes an ordinary transition. The class is unchanged, because DCFL is closed under right quotient with a regular set, so appending or stripping the marker is a legal move in a proof.

Questions that write the input as w$ are telling you the marker is available. Questions that do not are asking about the marker-free machine.

Misconception 1 — "the two acceptance criteria are always equivalent"

Why it is believed. It is a theorem in every first course, and it is stated for the push-down automaton without the adjective.

What is true. It holds for the non-deterministic machine. For a DPDA the empty-stack languages are exactly the prefix-free members of the class.

The one-line refutation. A DPDA cannot distinguish "the input has ended" from "more is coming", so if it empties its stack early it accepts a prefix of a longer word. Check a*b*: a is a member and a proper prefix of aa, so the language is not prefix-free.

Misconception 2 — "a DCFL is a language with a deterministic grammar"

Why it is believed. The word "deterministic" suggests the grammar, and LR grammars are deterministic grammars.

What is true. DCFL is a class of languages, defined by a machine. The theorem says a language is in it exactly when it has an LR(1) grammar — some LR(1) grammar, not the one you first wrote down.

Why it matters. A shift-reduce conflict in one grammar proves nothing about the language. That is precisely the GATE 2020 question: {an} ∪ {anbn} is a DCFL and has no LL(k) grammar for any k.

Closely confused pair — "not closed under union" against "never in the class"

DCFL is not closed under union. That is a statement about the family: there exist two DCFLs whose union is not a DCFL.

It does not say that a union of DCFLs is never a DCFL. In fact DCFL ∪ regular is always a DCFL, by complement, intersection with a regular set, and complement again.

So the correct answer to "is L1 ∪ L2 a DCFL?" is always "prove it", never "no, union is not closed".

Closely confused pair — "stuck" against "accepted"

A run that finds no instruction stops. That is a rejection. A run that finds an instruction which leaves it in a final state with the input exhausted is an acceptance.

The confusion appears when a student reasons "the machine stopped, so it finished". Stopping is not finishing: the input may still have symbols in it, and the complement proof in scene 6 fails on exactly those runs.

Test: for the anbn machine, b stops at position 0 and aab stops at position 3 with a symbol unread. Neither has finished.

Misconception 3 — "a regular language could be the answer to 'not a DCFL'"

Why it is believed. Regular languages feel smaller and simpler, so they get offered as the exception.

What is true. REG ⊆ DCFL: a DFA is a DPDA that never touches its stack. So every regular language is deterministic context-free, and no regular language can be a counterexample to determinism.

The check. In a multiple-select question, any option asserting that a regular language is not a DCFL is wrong on its face.

Misconception 4 — "a DPDA must be a real-time machine"

Why it is believed. "Deterministic" is read as "one instruction per symbol".

What is true. ε-instructions are allowed, provided they do not compete with a symbol-instruction on the same cell. The anbn machine uses one and is deterministic.

The nuance. Every DPDA can be converted to one whose ε-instructions only pop, so a real-time-like normal form exists — but the class is not defined by it, and a table with ε-instructions is not thereby non-deterministic.

The four question shapes, and what each one is really testing

Every previous-year question on this topic that this lesson's research found is one of four shapes. The pattern is what to learn; the individual questions are illustrations.

Shape 1 — classify a list of languages

"Which of these languages are deterministic context-free?" Two to four languages, each needing a one-line verdict. This is the boundary question applied repeatedly, and the discriminator is almost always the presence or absence of a middle marker.

Procedure. For each language, name the boundary. A marker symbol or a change of letter means deterministic; nothing means not. Do not spend time building machines.

Shape 2 — pick the true statements about one language

A statement list mixing containment, closure and grammar class, with one language at the centre. The usual mixture is "is it a DCFL", "is it a CFL", "is it LL(k)".

Procedure. Settle the language first, then read each statement against the containment chain REG ⊆ DCFL ⊆ CFL ⊆ CSL ⊆ REC. A statement that puts a language in a class above the one you proved is the trap.

Shape 3 — a closure statement

"DCFL is closed under …" with a list. The two answers that decide the mark are complement (closed) and union or intersection (not closed), and the reason is always the same witness.

Procedure. Recall the seven-and-six split, and remember that intersection with a regular set is closed while intersection with another DCFL is not. The word "regular" is doing all the work in that distinction.

Shape 4 — the parser connection

"Which grammar class generates exactly the deterministic languages?" with options LL(1), LR(1), LR(0), unambiguous. The answer is LR(1), and the discriminator is that LL(1) is the single-state DPDA and therefore a proper subclass.

Procedure. LR(1) = DCFL. LL(1) ⊊ DCFL. Unambiguous ⊋ DCFL. LR(0) ⊊ LR(1). Four facts, four options.

The five-step decision procedure for any candidate language

  1. Write the language with its exponents. aibjck with a condition on i, j, k is the standard form, and the condition is where the answer lives.
  2. Count the comparisons. One comparison, like i = j, needs one counter and is a DCFL. Two simultaneous comparisons are not even context-free.
  3. Look for the boundary. A marker that occurs once, or a change of letter, makes the switch deterministic. If the middle has to be guessed, it is not a DCFL.
  4. Check the class above before claiming the class below. If the language is not a CFL, it is not a DCFL either, and the pumping lemma settles it in one step.
  5. Use closure to finish. DCFL ∪ regular is a DCFL; DCFL ∩ regular is a DCFL; DCFL ∩ DCFL need not be. The word after the operator decides.

The traps that cost marks, in the order they appear in past papers

The alphabet. w c wR over {0, 1, c} is deterministic; w wR over {0, 1} is not. Read the alphabet before the language — a marker only helps if it is in Σ.

"Regular" offered as not-deterministic. Never true. Every regular language is a DCFL.

LL(k) and DCFL confused. The language {an} ∪ {anbn} is a DCFL and has no LL(k) grammar. A statement can be true of DCFL and false of LL(k) in the same question.

Union read as intersection. A question that says "closed under union" and a question that says "closed under intersection with a regular set" have opposite answers, and the only difference is two words.

Q1 MCQ GATE CS 2014, Set 3, Q36

Consider the following languages over the alphabet Σ = {0, 1, c}:
L1 = { 0n1n | n ≥ 0 }
L2 = { w c wR | w ∈ {0,1}* }
L3 = { w wR | w ∈ {0,1}* }
Here, wR is the reverse of the string w. Which of these languages are deterministic context-free languages?

(A) None of the languages
(B) Only L1
(C) Only L1 and L2
(D) All the three languages

Answer: (C) only L1 and L2.

L1: the first 1 marks the boundary. Push on 0, pop on 1, accept when the marker returns.

L2: the c occurs exactly once and marks the middle. Push everything before it, then pop and compare everything after it. Nothing is guessed.

L3: no marker, so the middle is invisible. The language is context-free — a non-deterministic machine guesses the middle — but no deterministic machine can, because at every position it must consider both "the middle is here" and "the middle is later". Why the others fail: (A) and (B) reject L2, which the marker settles in one line; (D) accepts L3, which is the guess. Note the alphabet: c is in Σ, which is why the marker is legal input and not an outside device.

Q2 MCQ GATE CS 2017, Set 2, Q40

Consider the following languages.
L1 = { ap | p is a prime number }
L2 = { anbmc2m | n ≥ 0, m ≥ 0 }
L3 = { anbnc2n | n ≥ 0 }
L4 = { anbn | n ≥ 1 }
Which of the following are CORRECT?
I. L1 is context free but not regular
II. L2 is not context free
III. L3 is not context free but recursive
IV. L4 is deterministic context free

(A) I, II and IV only
(B) II and III only
(C) I and IV only
(D) III and IV only

Answer: (D) III and IV only.

III is true: L3 needs two comparisons with one stack, so the pumping lemma for CFLs excludes it, and a Turing machine decides it by counting.

IV is true: L4 is the machine this lesson is built on, five instructions, no violation.

I is false: prime length is not context-free, so the first clause fails. II is false: L2 pushes two symbols per b and pops one per c, which one stack does comfortably — it is in fact a DCFL. Why (A) and (C) fail: both accept I, and both reject III or IV. Why (B) fails: it accepts II, which is a plain counterexample to "two exponents means not context-free".

Q3 MSQ GATE CS 2020, Q10

Consider the language L = { an | n ≥ 0 } ∪ { anbn | n ≥ 0 } and the following statements.
I. L is deterministic context-free.
II. L is context-free but not deterministic context-free.
III. L is not LL(k) for any k.

Which of the above statements is/are TRUE?

(A) I only
(B) II only
(C) I and III only
(D) III only

Answer: (C) I and III only.

I is true. {an} is regular and {anbn} is a DCFL, and DCFL ∪ regular is a DCFL: complement both, intersect the DCFL with the regular complement, complement the result — three steps, all of them in the closed column.

III is true. Any LL(k) parser must commit to a production after k symbols of look-ahead, and a run of a's longer than k could still be either the end of an an word or the first half of an anbn word.

II is false because I is true. Why this question is worth remembering: it separates three words that are easy to merge — deterministic, LL(k), and context-free. A language can be the first, not the second, and also the third.

Q4 NAT Original

A push-down automaton has 4 states, input alphabet Σ = {a, b} and stack alphabet Γ = {Z, A, X}. How many cells does the determinism test examine, counting ε as a symbol?

Answer: 36. The cell is (state, symbol, stack top): 4 × 3 × 3 = 36, because the symbol set is Σ plus ε.

The trap. 24 comes from forgetting ε, and 12 comes from forgetting the stack alphabet. The count is a product of three sizes, and the middle factor always has the +1.

Q5 MCQ Original

A machine has the five instructions of the anbn automaton plus (q1, ε, A) → (qd, A), where qd is a non-final state with no outgoing instruction. Which statement is TRUE?

(A) It is a DPDA and accepts the same language.
(B) It is not a DPDA, and it accepts a strictly larger language.
(C) It is not a DPDA, and it accepts the same language.
(D) It is a DPDA, and it accepts a strictly smaller language.

Answer: (C). The new instruction sits at (q1, A), where (q1, b, A) already lives, so condition (2) fails. And because qd is non-final with no moves, the new branch can never lead to an accepting configuration, so the language is unchanged.

Why (A) fails: the ε-instruction competes with a symbol-instruction on the same cell. Why (B) fails: a branch that always dies adds no string. Why (D) fails: adding a branch can never remove an accepting run.

Q6 MSQ Original

Let L be a deterministic context-free language. Which of the following are necessarily deterministic context-free?

(A) The complement of L
(B) L ∪ {a, b}
(C) L ∩ {anbn | n ≥ 0}
(D) L concatenated with L

Answer: A and B.

A: complement is closed for this class, and effectively so.

B: {a, b} is regular, and DCFL ∪ regular is a DCFL, by complement, intersection with the regular complement, and complement again.

C is not guaranteed. Intersecting with a regular set would be safe; intersecting with another deterministic language is not. The witness is {aibjck : i = j} against {aibjck : j = k}, whose intersection is not context-free. D is not guaranteed: concatenation is in the open column, for the same reason as union.

Q7 NAT Original

Using the machine in this lesson, how many steps does the run of a4b4 take, counting the acceptance step?

Answer: 9. Four pushes, four pops and one acceptance give 2n + 1 = 9.

The trap. 8 counts the eight symbols read and forgets the acceptance instruction, which reads nothing. The step count is the number of configurations minus one, and the last configuration is the accepting one.

Q8 MCQ Original

The final states of the anbn machine are exchanged with the non-final states. The result is another deterministic push-down automaton. Which statement about it is TRUE?

(A) It accepts the complement of anbn.
(B) It accepts every string over {a, b}.
(C) It accepts the empty language.
(D) It rejects every string on which the original run stops before the end of its input, so it is not the complement.

Answer: (D). The smallest witness is the one-letter string b: the original run stops at (q0, b, Z) with the whole input unread, so the swapped run stops in the same place and rejects. Of the 31 strings of length at most four, 22 are handled wrongly this way.

Why (A) fails: the theorem that the complement is a DCFL is true, and this is not its proof. Why (B) fails: strings the original machine accepted end in qf, which is no longer final, so they are rejected — ab is one. Why (C) fails: strings that read to the end in a state that became final, such as a, are accepted.

What to do with a wrong answer

Sort the mistake into one of three bins. Boundary: you missed that a marker exists or that it does not — re-read the alphabet before the language. Class: you placed a language above or below its real class — walk the chain REG ⊆ DCFL ⊆ CFL and check the pumping lemma before claiming the lower class. Closure: you applied an operation from the open column, or applied the closed column to the wrong operand — check whether the second operand is regular before using it.

Revision sheet — the whole lesson on one screen

Definitions, the two conditions, the containment chain, the closure split, the exact acceptance statement, and the four facts that decide most questions.

Definitions

DPDA. A PDA whose transition relation satisfies: (1) at most one instruction per (state, symbol-or-ε, stack top); (2) no ε-instruction on a (state, stack top) that also has a symbol-instruction.

DCFL. The set of languages accepted by some DPDA, by final state.

Prefix-free. No member of the language is a proper prefix of another member.

LR(1). A grammar whose shift-reduce parser never faces two actions in one cell with one symbol of look-ahead.

The chain and the counts

REG ⊊ DCFL ⊊ unambiguous CFL ⊊ CFL ⊊ CSL ⊊ REC

Every inclusion is strict. The witnesses this lesson uses: anbn for REG ⊊ DCFL; the even palindromes for DCFL ⊊ unambiguous; an inherently ambiguous language for unambiguous ⊊ CFL; anbncn for CFL ⊊ CSL.

Counts from the model: 18 cells examined for the anbn table, 5 in use; violation counts 0, 3, 2, 1 for the four tables; steps 2n + 1 and peak height n + 1; 22 of 31 strings exposed by the naive swap; 7 closed and 6 open operations.

Closed and not closed

Closed: complement · intersection with a regular set · inverse homomorphism · right quotient with a regular set · pre · min · max.

Not closed: union · intersection · concatenation · Kleene star · ε-free morphism · mirror image. The word "regular" after "intersection with a" is the whole difference between the two lists.

Exact statements

  • Empty-stack acceptance for a DPDA holds exactly for the prefix-free members of the class.
  • "Is L = Σ*?" for a DPDA is decidable, by complementing and testing emptiness.
  • DCFL is exactly the LR(1) languages, and exactly the LR(k) languages for some k.
  • Restricting a DPDA to one state gives the LL(1) languages, a proper subclass.
  • Every DPDA can be put in a form whose ε-instructions only pop.

Traps, ranked by cost

1. Swapping final states as a proof of complement closure.
2. Carrying the NPDA's empty-stack equivalence to the DPDA.
3. Reading "unambiguous" as "deterministic".
4. Offering a regular language as not-a-DCFL.
5. Missing that a marker symbol is in the alphabet.
6. Treating "not closed under union" as "no union of two DCFLs is a DCFL".

Every one of these is a place where the machine-level statement and the language-level statement were merged.

Three quick checks before you answer

Is the middle visible? A symbol occurring once, or a change of letter, makes it visible.

How many counts? One comparison is a DCFL; two simultaneous comparisons are not context-free.

Is the second operand regular? Then the intersection is closed and the union is closed; if not, neither is guaranteed.

The claim that a real-time-like normal form exists for every DPDA is also taken from the chapter, and the construction is not reproduced.
