Topic and objective

TOPIC: Red-black trees — a binary search tree that stores one colour bit per node and obeys five rules. The rules, the black-height that rule five equalises, the height bound that follows from it, and the three insertion cases that keep the rules true.

LEARNING OBJECTIVE: Given a drawn tree, decide whether it is a red-black tree by checking the five rules at every node, not only at the root. Given n, state the maximum height a red-black tree on n keys can have — 5 for n = 15, not the 8 that the formula suggests. Given an insertion, name the case from the uncle's colour and the shape, and say how many rotations it costs. And reject the three answers that look right: "a red-black tree is an AVL tree", "no two reds in a row is enough", and "each insertion needs O(log n) rotations".

I read this topic as one counting rule plus three repairs. Rule five is the only rule that does any work, and every number in the lesson — the height bound, the minimum-node table, the black-heights — is a consequence of it, so the lesson spends its time there and on making the three repairs mechanical.

Prerequisites

  • Binary search trees and the search property. Left subtree smaller, right subtree larger, in-order walk sorted. Built in Trees, Binary Search Trees and Heaps.
  • Height and the empty-tree convention. This lesson uses height(empty) = −1 and height(leaf) = 0, the same convention as the AVL lesson.
  • Rotations as three pointer writes. A rotation moves three pointers and leaves the in-order walk unchanged. Built in AVL Trees, scene 5; this lesson assumes it and never re-derives it.
  • Logarithms and asymptotic notation. log base 2, and O(log n) against O(n). Built in Asymptotic Complexity and Recurrences.
  • Proof by induction. The counting claim is an induction on the height of a node. Built in Mathematical Induction and Well-Ordering.

No AVL balance factor is needed to follow the proofs, though the last scene uses it once, to show that a red-black tree need not be AVL. No B-tree is assumed.

Conventions used throughout

bh(x) = black nodes below x, NIL included, x excludedThe black-height of a NIL leaf is 0, so a node whose children are both NIL has black-height 1. Counting the node itself shifts every number by one.

a red node has two black childrenRule four, stated downwards. Stated upwards it says the parent of a red node is black. Both forms are the same rule.

every path from x to a NIL holds the same number of blacksRule five. Equivalently: the two children of every node have equal black-height.

n ≥ 2^bh − 1  and  h ≤ 2 · bh ≤ 2 log₂(n + 1)The counting claim, the height claim, and the composition of the two. Every count in this lesson comes from the first inequality.

Mathematical derivation The table of fewest keys at each height, 1, 3, 5, 7, 11, 15, 23, is computed by the page by exhaustive dynamic programming over height, black-height and root colour — it is not quoted from a book, and the checks re-derive it.

How this differs from the lesson next door

AVL Trees: Balance, Rotations and the Height Bound teaches a different shape rule: the balance factor at every node stays inside ±1, and the repair is one of four rotations named LL, RR, LR, RL. It derives the height bound 1.44 log₂(n + 2) and the minimum-node row 1, 2, 4, 7, 12, 20.

This lesson keeps the same rotations and adds a different invariant: five rules about colour, and a black-height that must be equal on both sides of every node. The height bound is looser (2 log₂(n + 1) instead of 1.44 log₂(n + 2)), the minimum-node row is different (1, 3, 5, 7, 11, 15, 23), and the repairs are recolourings as well as rotations. The two structures are not interchangeable, and the last scene shows a valid red-black tree that is not an AVL tree.

Intuition, then definition

A search tree is a filing cabinet whose speed depends on how many drawers you must open. Insert keys in sorted order and the cabinet becomes one long corridor; insert them well and it becomes a shallow fan. AVL keeps it shallow by demanding that the two sides of every drawer be the same depth. A red-black tree asks for something weaker and cheaper to maintain: paint every drawer either red or black, forbid two reds in a row, and make every route to the bottom pass the same number of black drawers. The painting is the whole trick — the black drawers are the skeleton, and the skeleton is forced to be bushy.

Definition — the five rules

A red-black tree is a binary search tree in which every node carries one colour bit and the following hold. Verified fact The five rules below are the standard statement (CLRS chapter 13; the same five appear in the lecture notes listed on the Sources tab).

  1. Every node is red or black.
  2. The root is black.
  3. Every leaf is black. Here a leaf is the NIL marker, not a key without children.
  4. If a node is red, both its children are black.
  5. For every node x, every simple path from x down to a NIL leaf contains the same number of black nodes.

Rules 1 to 3 are bookkeeping. Rule 4 limits how red can be spread along a path. Rule 5 is the counting rule, and it is the only one that bounds the height.

What each rule costs and buys

Rule 1 costs one bit per node and nothing else. No key, pointer or count is added to the structure.

Rules 2 and 3 cost nothing: they remove cases from proofs. Because the NIL leaves are black, the black-height of a leaf key is 1 rather than 0, and every formula becomes uniform.

Rule 4 is the only rule a single insertion can break, and it can break it in exactly one place: between the new node and its parent.

Rule 5 is the one that does the work. It forces every branch to carry the same black weight, which forces every branch to be long enough to hold that weight, which is what keeps the tree shallow.

The one definition worth writing down exactly

bh(x) = the number of black nodes on any path from x down to a NIL leaf, counting the NIL leaf and not counting x

Two consequences follow immediately and are used everywhere. First, bh(NIL) = 0. Second, a node whose two children are NIL leaves has black-height 1. Rule 5 can then be restated in the form used by every computation in this lesson: the two children of every node have equal black-height. If you count the node itself, every black-height in this lesson is one too large and a correct tree looks broken.

The two claims, and how they compose

Everything the lesson counts comes from two inequalities. The first turns a black-height into a size. The second turns a black-height into a height. Composing them gives the promise that makes the structure worth having.

Claim 1 — a black-height of b needs 2^b − 1 keys

Mathematical derivation The subtree rooted at any node x holds at least 2^bh(x) − 1 keys.

  1. Base: x is a NIL leaf, bh(x) = 0, and the subtree holds 0 = 2⁰ − 1 keys. the empty case is the only one where the count is zero
  2. A black child has black-height bh(x) − 1; a red child has black-height bh(x). a black child contributes one to x's count, a red child contributes none
  3. So each child subtree holds at least 2^(bh(x) − 1) − 1 keys. apply the induction hypothesis to the smaller height
  4. Two children plus x: 2 · (2^(bh−1) − 1) + 1 = 2^bh − 1. the arithmetic of the two subtrees plus the node

The bound is attained exactly by the all-black perfect tree, so the row for bh = 1, 2, 3, 4 is 1, 3, 7, 15, and no colouring does better.

Claim 2 — the height is at most twice the black-height

Mathematical derivation Take any path from the root to a NIL leaf with h edges. By rule 4 its colours alternate at worst red, black, red, black, so at least half of the h edges lead to black nodes. The root's black-height is that count, so h ≤ 2 · bh(root).

Composing with Claim 1: n ≥ 2^bh − 1 gives bh ≤ log₂(n + 1), and therefore

h ≤ 2 · bh(root) ≤ 2 log₂(n + 1)

Verified fact This is CLRS Lemma 13.1, stated as "a red-black tree with n internal nodes has height at most 2 lg(n + 1)", and the same theorem appears with the same proof in the university lecture notes on the Sources tab.

What the two claims do not say

The composition is a ceiling, and a loose one. For 15 keys it gives 8, while no red-black tree on 15 keys is taller than 5. The exact answer comes from inverting Claim 1: the fewest keys at heights 0 to 6 are 1, 3, 5, 7, 11, 15, 23, computed by the page, so 15 keys allow height 5 and not 6.

A question that asks "what is the maximum height of a red-black tree with n nodes" wants the table, not the logarithm. A question that asks "show the height is O(log n)" wants the logarithm. The two are different questions and they have different answers.

The one line to remember

Rule five makes every branch carry the same black weight; Claim 1 says a black weight of b needs at least 2^b − 1 keys; so a tree with n keys cannot be taller than about 2 log₂ n. The colour is the bookkeeping, the black-height is the quantity, and the logarithm is the consequence.

Four worked examples, every tree computed by the page

The trees below are produced by the red-black implementation in this page, not drawn by hand, and the case log after each insertion is the algorithm's own record. Height uses empty = −1, leaf = 0. Colour is written as a letter after the key: 20B means 20 coloured black.

Example 1 — build 10, 20, 30, 15, 25, 12, 5

Each line is one insertion, the cases the fix-up took, and the rotations it used. The parenthesised form is (left subtree, right subtree), with . for a NIL.

+10 → 10B(.,.) — no repair; the root is blackened.

+20 → 10B(.,20R) — no repair.

+30 → 20B(10R,30R) — case 3, one rotation.

+15 → 20B(10B(.,15R),30B) — case 1, no rotation.

+25 → 20B(10B(.,15R),30B(25R,.)) — no repair.

+12 → 20B(12B(10R,15R),30B(25R,.)) — case 2 then case 3, two rotations.

+5 → 20B(12R(10B(5R),15B),30B(25R,.)) — case 1, no rotation. Total: 3 rotations, case 1 twice, height 3, black-height 2.

Example 2 — reading black-heights off that tree

The final tree is 20B(12R(10B(5R),15B),30B(25R)). Its black-heights, computed by the page:

20 → 2   12 → 2   10 → 1   5 → 1   15 → 1   30 → 1   25 → 1

Check rule five at three nodes. At 20 the children 12 and 30 both have black-height 2. At 12 the children 10 and 15 both have black-height 1. At 10 the children 5 and the NIL leaf both have black-height 1.

Check the bound: height 3 ≤ 2 · bh = 4, and 2 log₂(7 + 1) = 6. A search for 25 visits 20, 30, 25: three keys.

Example 3 — the same insertion done twice, black then red

Start from the two-key tree 10B(.,20R) and insert 30.

Coloured black, no repair: 10B(.,20R(.,30B)). At node 20 the left path holds one black and the right path holds two. Rule 5 fails; rule 4 holds. This is why a new node is never black.

Coloured red, no repair: 10B(.,20R(.,30R)). Every black-height is unchanged, so rule 5 holds, and rule 4 fails on the single edge 20–30. One broken rule in one place is what makes the repair local — and with the uncle NIL (black) and the node on the outside, the repair is case 3: recolour two nodes, rotate once, giving 20B(10R,30R).

Example 4 — a valid red-black tree that is not AVL

Insert 10, 35, 8, 37, 20, 36. The result is

10B(8B, 35R(20B, 37B(36R,.)))

All five rules hold — the page re-tests them. The root 10 has a left subtree of height 0 and a right subtree of height 2, so its balance factor is +2 and the tree is not AVL.

The fifteen-key tree of the bound scene is a second example: height 5, black-height 3, valid, and not AVL either. Red-black trees are not AVL trees with a colouring added; they permit a taller tree and charge less for repairs.

Counting, repairing and deleting — the three tables the model produces

These are the numbers a question is most likely to ask for. Each one is computed at load by the page and re-checked against its defining property.

Fewest keys at each height

Computed by exhaustive dynamic programming over height, black-height and root colour:

h = 0 → 1, 1 → 3, 2 → 5, 3 → 7, 4 → 11, 5 → 15, 6 → 23

Read it in both directions. Fifteen keys allow height 5, because height 6 needs 23. Seven keys allow height 3, because height 4 needs 11. One key allows height 0.

Compare with the AVL row 1, 2, 4, 7, 12, 20: an AVL tree on 15 keys is allowed height 4 (since 12 ≤ 15 < 20), a red-black tree height 5. The red-black structure is genuinely looser.

The three insertion cases, counted

Case 1 — uncle red. Parent and uncle go black, grandparent goes red, and the fault moves up to the grandparent. Rotations: 0. Recolours: 3.

Case 2 — uncle black, node on the inside. One rotation at the parent turns the zig-zag into a straight line. Rotations: 1. Recolours: 0. The result is case 3.

Case 3 — uncle black, node on the outside. Parent goes black, grandparent goes red, then one rotation at the grandparent. Rotations: 1. Recolours: 2. The repair ends.

So one insertion needs at most two rotations, and the recolouring of case 1 can repeat at every level. Both are O(log n); only the second one can be large.

What a deletion breaks

Plain binary search tree deletion, then all five rules re-tested by the page:

Delete the red leaf 25 → 20B(12R(10B(5R),15B),30B). Valid. A red node contributes no black to any path, so removing it changes no black-height and creates no red-red edge.

Delete the black leaf 15 → 20B(12R(10B(5R),.),30B(25R)). Invalid: at node 12 the left path holds two blacks and the right path one.

Delete the black 20 (two children, successor promoted) → 25B(12R(10B(5R),15B),30B). Valid. So "a black deletion always breaks the tree" is false: it is the black leaf that leaves a path short.

One worked trace of a cascade

Build 5, 10, 9, 1, 2, 8, 7, 4, 3, 6 and watch two insertions:

Inserting 4 takes case 1 at 7, then case 2 and case 3 at 2 and 9: three cases, two rotations.

Inserting 6 takes case 1 at 4, then case 1 again at 7: two recolourings, two levels of climbing, and no rotation at all. A question that asks "how many rotations" is not asking "how many times was the tree touched".

Boundaries, and the two counterexamples that matter most

Every card here is a case where a rule that works in general fails at the boundary, or where a plausible shortcut gives the wrong answer.

Counterexample 1 — no two reds in a row, and still not a red-black tree

Insert 10, then 20, then 30 coloured black with no repair: 10B(.,20R(.,30B)). Rule 4 holds (the only red is 20, whose children are 30B and NIL). Rule 2 holds. Rule 1 holds. Rule 5 fails: at node 20 the left path holds one black and the right path holds two.

The condition violated is rule 5, and no amount of looking for red-red pairs will find it.

Counterexample 2 — a black deletion that is perfectly safe

Deleting the black leaf 15 from the seven-key tree breaks rule 5. But deleting the black root 20, whose successor 25 is promoted, leaves 25B(12R(10B(5R),15B),30B), which passes all five rules.

The condition violated by the first deletion is "the removed node was a black leaf on a path that had no other black to spare". Deleting a black node with two children does not automatically break anything, which is exactly why the fix-up is stated in terms of a deficit and not in terms of colour alone.

The empty tree, and the single node

The empty tree is a red-black tree: rules 1, 3 and 5 hold vacuously, rule 2 has no root to violate, and rule 4 has no red node. Its height is −1 and its black-height is 0.

A single node must be black, by rule 2. Its two children are NIL, so its black-height is 1, and 1 ≥ 2¹ − 1. This is the base case of the counting claim and the reason the row starts at 1 rather than 0.

A red root is legal during the repair

Case 1 turns the grandparent red, and when the grandparent is the root the tree is momentarily invalid. The last line of the fix-up colours the root black, which restores rule 2 and, because the root has no parent, cannot create a new violation.

A question that shows a tree with a red root and asks whether it is a red-black tree has answer "no", but a question about the algorithm must allow the intermediate state.

An all-black colouring is valid exactly for perfect trees

Mathematical derivation If every node is black then rule 5 says every root-to-NIL path has the same length, which is the definition of a perfect tree. The page checks this exhaustively: over all binary tree shapes with up to six keys, the all-black colouring is valid for exactly the perfect ones.

So "colour everything black" is not a way to make an arbitrary tree a red-black tree; it is a way to test whether the tree is perfect.

The bound is loose, and at small n it is very loose

For n = 15 the bound is 2 log₂ 16 = 8 and the exact maximum height is 5. For n = 7 the bound is 6 and the exact maximum is 3. For n = 3 the bound is 4 and the exact maximum is 1.

The gap matters in both directions: the bound is what proves the operations are logarithmic, and the table is what answers a question that names a number of keys.

Duplicate keys

Inserting a key already in the tree changes nothing: the search reaches the existing node, and the model returns the tree unchanged. Size stays 3 for the sequence 10, 20, 30, 20.

This is a property of the search-tree half, not of the colour rules, and it is worth remembering when a question gives a sequence with a repeated key.

A tree with every rule but rule 1 is not a tree

Rule 1 is the only rule that mentions the colour domain. A node whose colour is unset is neither red nor black, and then rule 4 and rule 5 have no meaning. In an exam this appears as a node drawn with no fill and no label; the safe reading is that the tree is not a red-black tree.

Every other rule can be checked mechanically once rule 1 is granted.

Six wrong beliefs, each with the smallest example that ends it

Each card states the belief, why it is tempting, the minimal counterexample, and the rule that replaces it.

1. "A red-black tree is an AVL tree with colours"

Why it tempts: both are balanced binary search trees, both use the same two rotations, and the two lessons sit next to each other in most syllabi.

Counterexample: insert 10, 35, 8, 37, 20, 36. The result 10B(8B,35R(20B,37B(36R,.))) passes all five rules, and its root has balance factor +2, so it is not AVL.

The correct rule: the AVL rule bounds the difference of heights at ±1; the red-black rules bound the black-height on each side and allow red nodes to lengthen a path. The red-black promise, 2 log₂(n + 1), is looser than the AVL promise, 1.44 log₂(n + 2).

2. "No two reds in a row is the whole rule"

Why it tempts: rule 4 is the only rule a single insertion can break, so it is the one everybody watches.

Counterexample: 10B(.,20R(.,30B)) has no two reds in a row and fails rule 5 at node 20, one black against two.

The correct rule: check the black-height on both sides of every node. A tree is not a red-black tree until rule 5 has been checked everywhere, and rule 5 is the rule that bounds the height.

3. "The height is about log₂ n"

Why it tempts: the operations are all O(log n) and the constant disappears in the O.

Counterexample: the fifteen-key tree of this lesson has height 5 while log₂ 15 is about 3.9, and a red-black tree may reach 2 log₂(n + 1), which is 8 for n = 15.

The correct rule: the height is at most 2 log₂(n + 1) — a factor of two above a perfectly balanced tree, and that factor is the price of the cheaper repair.

4. "Insert red because red is less important"

Why it tempts: red sounds like the softer choice, and the fix-up only ever talks about red nodes.

Counterexample: insert 30 black into 10B(.,20R) and rule 5 fails immediately at node 20. Insert it red and only rule 4 fails, on one edge.

The correct rule: a red node adds no black to any path, so rule 5 is preserved by construction. The colour is chosen so that the damage is the kind that can be repaired locally.

5. "Each insertion needs O(log n) rotations"

Why it tempts: the fix-up is written as a loop that can climb to the root, so it looks like every level rotates.

Counterexample: inserting 6 into the ten-key build of this lesson fires case 1 twice, climbs two levels and rotates zero times. Across 250 random insertion orders the page never records more than two rotations in a single insertion.

The correct rule: at most two rotations per insertion; the O(log n) part is the recolouring of case 1. For deletion the figure is at most three rotations, and there the AVL structure can rotate at every level — which is the real difference between the two.

6. "The black-height counts the node itself"

Why it tempts: "the height of this node" in AVL counts downwards from the node, so symmetry suggests the black-height should include it.

Counterexample: with the node included, a leaf key would have black-height 1 and the NIL would have 0, so a node with two NIL children would have children of black-heights 0 and 0 while its own count was 1 — and the identity "the two children have equal black-height" would still hold, but 2^bh − 1 would then predict 1 key for bh = 1 at a node that has 3.

The correct rule: bh(x) excludes x and includes the NIL leaf. Written that way, bh(NIL) = 0, a leaf key has bh = 1, and the counting claim is 2^bh − 1 exactly.

A belief that is true, and worth stating precisely

"Every red-black tree has logarithmic height" is true, and the proof needs both claims: 2^bh − 1 ≤ n and h ≤ 2 · bh. Neither claim alone is enough, and a solution that quotes only one of them is incomplete.

"Every AVL tree can be coloured as a red-black tree" is a claim this lesson does not settle. The page checks it exhaustively for every AVL shape on up to seven keys — all 35 admit a valid colouring — and says so on the Revision tab. A finite check is not a proof, and no more is claimed.

The habit that prevents all six

Before answering any red-black question, write two things on the paper: the black-height under every node, and the case name of any insertion. Almost every wrong answer in this topic comes from skipping one of those two columns.

Five question shapes, the reasoning each demands, and the usual wrong approach

Red-black trees are not named in the GATE 2027 syllabus, so nothing here is a prediction that a question will appear. These are the shapes such a question takes when it does, and each one is a different kind of reasoning.

Shape 1 — is this tree a red-black tree?

Demands: the five rules checked at every node, with the black-heights written down. The cheapest procedure is a single bottom-up pass computing black-heights from the NIL leaves, then a comparison at each node.

Usual wrong approach: looking for red-red pairs only, which misses rule 5 entirely. Second usual error: forgetting that the NIL leaves are black and so under-counting every black-height by one.

Shape 2 — counting nodes, height or black-height

Demands: the two inequalities, and then the exact table if a number is asked for. "Minimum nodes with black-height b" is 2^b − 1. "Maximum height with n nodes" is the largest h whose minimum does not exceed n. "Minimum nodes at height h" is 1, 3, 5, 7, 11, 15, 23.

Usual wrong approach: answering the ceiling 2 log₂(n + 1) when the question asks for the exact maximum, and confusing the perfect-tree count 2^(h+1) − 1 (a maximum) with the minimum.

Shape 3 — which case fires, and how many rotations?

Demands: insert red, read the uncle's colour, then the inside/outside question. Report the case numbers in the order they fire and count rotations only.

Usual wrong approach: counting a recolouring as a rotation, or reporting one rotation for a case 2 that is immediately followed by case 3. The correct count for that pair is two.

Shape 4 — which colour sequence can a path have?

Demands: rule 4 forbids two consecutive reds, rule 2 fixes the first node black, and rule 3 fixes the last node black, so a path reads B … B with no RR inside.

Usual wrong approach: accepting a sequence because it has the right number of blacks; the black count is rule 5 and is a statement about all paths at once, not about one sequence.

Shape 5 — complexity and structure comparisons

Demands: the height bound, the rotation counts, and the distinction from AVL. Search, insert and delete are O(log n) in both structures; the difference is the constant in the height and the number of rotations on deletion.

Usual wrong approach: treating the two structures as interchangeable, which is false in both directions — a valid red-black tree need not be AVL, and the two height bounds differ.

Q1 MCQ Original

What is the maximum possible height of a red-black tree with 15 internal nodes?

(A) 3   (B) 4   (C) 5   (D) 8

Answer: C. The fewest keys a red-black tree of height h can hold are 1, 3, 5, 7, 11, 15, 23 for h = 0 to 6. Height 5 needs exactly 15, and height 6 needs 23, so 15 keys allow height 5 and no more.

D is 2 log₂(15 + 1) = 8, the ceiling from the height lemma — an upper bound, not the answer. A is the height of a perfect tree on 15 keys, the other end of the same question. B is the AVL answer: the AVL row is 1, 2, 4, 7, 12, 20, so 15 keys allow AVL height 4.

Check: the page constructs a valid fifteen-key red-black tree of height 5 by inserting 9, 1, 2, 13, 4, 3, 11, 5, 6, 10, 7, 15, 12, 8, 14.

Q2 NAT Original

What is the minimum number of internal nodes in a red-black tree whose root has black-height 4?

Answer: 15. A black-height of b forces at least 2^b − 1 keys, so 2⁴ − 1 = 15. The bound is attained by the all-black perfect tree of height 3.

Two traps sit on this question. Counting the root itself would give black-height 4 for a perfect tree of height 4, and 31 instead of 15. And answering 2⁵ − 1 = 31 mixes the height convention with the black-height convention.

Q3 MCQ Original

Insert 10, then 20, then 30 into an initially empty red-black tree. Which case fires, and how many rotations are performed?

(A) case 1, 0 rotations   (B) case 2 then case 3, 2 rotations   (C) case 3, 1 rotation   (D) case 1, 1 rotation

Answer: C. After 10 and 20 the tree is 10B(.,20R). Inserting 30 puts a red node on the right of the red 20; the uncle is the NIL leaf on the left of 10, which is black, and the new node is on the outside, so it is case 3: recolour 20 black, 10 red, then rotate left at 10. The result is 20B(10R,30R).

A would be right if the uncle were red, which needs a grandparent with two children. B is the inside case, which needs the new node on the opposite side from its parent. D is not a case the algorithm has: case 1 never rotates.

The page's own model records exactly this: inserting 30 into that tree logs one case 3 and one rotation.

Q4 MSQ Original

A new key is inserted into a red-black tree and coloured red, before any repair. Which of the following are true?

(A) Rule 5 cannot be violated by the insertion itself.
(B) Rule 4 may be violated, in at most one place.
(C) Rule 2 may be violated, and is repaired by colouring the root black.
(D) The insertion may need more than two rotations.

Answer: A, B and C.

A red node adds no black to any path, so every black-height is unchanged — A. The new node is a leaf, so the only possible red-red edge is between it and its parent — B. If the tree was empty, the new node is the root and is red until the last line of the fix-up colours it black — C.

D is false. Cases 2 and 3 each rotate once and end the repair, so one insertion performs at most two rotations. What can repeat at every level is the recolouring of case 1, and that rotates nothing.

Q5 MCQ Original

A red-black tree is modified by plain binary search tree deletion, with no fix-up. Deleting which kind of node is guaranteed to leave all five rules intact?

(A) a red leaf   (B) a black leaf   (C) a black node with two children   (D) none: every deletion needs a fix-up

Answer: A. A red leaf contributes no black to any path, so removing it changes no black-height, and it cannot create a red-red edge because it has no children.

B is the standard failure: the path through it is left one black short. C can go either way — deleting the black root 20 of the seven-key tree and promoting 25 leaves a valid tree, so it is not guaranteed to break, but it is also not guaranteed to be safe, which is why it is not the answer. D overstates: the page checks that deleting the red leaf 25 needs no repair at all.

This is the distinction between "may break" and "is guaranteed to keep the rules", and the question is written to test it.

Q6 NAT Original

What is the minimum number of internal nodes in a red-black tree of height 5, with the height of a single node equal to 0?

Answer: 15. The computed row for the fewest keys at each height is 1, 3, 5, 7, 11, 15, 23 for h = 0 to 6, so height 5 needs 15.

Compare the two rows that this question is designed to confuse: the AVL minimum at height 5 is 20, and the perfect count 2⁶ − 1 = 63 is the maximum. A red-black tree reaches a given height with fewer keys than an AVL tree, because a red node lengthens a path without adding black weight.

Q7 MCQ Original

Which of these colour sequences, read from the root down to a NIL leaf, is impossible in a red-black tree?

(A) B R B R   (B) B B B   (C) B R R B   (D) B R B B

Answer: C. Rule 4 forbids a red node with a red child, so two consecutive reds cannot appear anywhere on a path.

A is the alternating pattern that reaches the 2 log₂(n + 1) ceiling. B is a perfect all-black skeleton. D is an ordinary mixed path.

Careful with what this question does not ask: a sequence being possible says nothing about whether a whole tree with that path satisfies rule 5, which is a statement about all paths at once.

Q8 MSQ Original

Which of the following statements about red-black trees are true?

(A) Every red-black tree is an AVL tree.
(B) The height of a red-black tree on n keys is at most 2 log₂(n + 1).
(C) One insertion performs at most two rotations.
(D) One deletion performs at most three rotations.

Answer: B, C and D.

B is the height lemma. C is the count of the three insertion cases: case 2 and case 3 rotate once each and end the repair. D is the standard count for the deletion fix-up, whose four cases stop at the first rotation.

A is false. Inserting 10, 35, 8, 37, 20, 36 gives a valid red-black tree whose root has balance factor +2, so it is not AVL. The converse direction — whether every AVL tree admits a red-black colouring — is not settled by this lesson; the page verifies it exhaustively for all AVL shapes on up to seven keys and claims no more.

One-screen revision sheet

Everything on this tab is either a definition, a computed table, or a counted fact about the three repairs.

The five rules

1 · every node is red or black

2 · the root is black

3 · every leaf (NIL) is black

4 · a red node has two black children

5 · every path from a node to a NIL holds the same number of blacks

The quantities

bh(x) = blacks below x, NIL counted, x not counted

bh(NIL) = 0; a node with two NIL children has bh = 1; rule 5 ⇔ both children of every node have equal bh.

n ≥ 2^bh − 1   ·   h ≤ 2 · bh   ·   h ≤ 2 log₂(n + 1)

AVL for comparison: h ≤ 1.44 log₂(n + 2) − 0.328.

The tables

Fewest keys at height h (computed): 1, 3, 5, 7, 11, 15, 23 for h = 0…6.

Fewest keys at black-height b: 2^b − 1, so 1, 3, 7, 15, 31.

Most keys at height h: 2^(h+1) − 1, the perfect tree.

Read both ways: 15 keys → height ≤ 5; 7 keys → height ≤ 3; 3 keys → height ≤ 1.

The three insertion cases

1 · uncle red — parent and uncle black, grandparent red, climb. 0 rotations, 3 recolours.

2 · uncle black, inside — one rotation at the parent; becomes case 3. 1 rotation.

3 · uncle black, outside — parent black, grandparent red, one rotation at the grandparent. 1 rotation, 2 recolours.

Finish: colour the root black. Total rotations per insertion: at most 2.

Traps, in the order they cost marks

· checking rule 5 at the root only

· counting the node itself in the black-height

· answering 2 log₂(n + 1) when the exact maximum is asked

· counting recolourings as rotations

· assuming a red-black tree is an AVL tree

· assuming a black deletion always breaks the tree (it breaks it when the deleted black is a leaf on a path with no spare black)

Three sentences

A red node is inserted because it costs no black on any path.

The repair is local because the damage is one red-red edge.

Rule five is the reason the tree is short, and 2^bh − 1 is the reason rule five is enough.
