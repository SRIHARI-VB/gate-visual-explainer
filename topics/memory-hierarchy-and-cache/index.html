Topic and objective

TOPIC: Memory hierarchy and cache — the middle clause of GATE 2027 Section 3: "Memory interfacing and hierarchy: performance, cache memory mapping."

LEARNING OBJECTIVE: Given a cache capacity, a block size, an associativity and an address width, split the address into offset, index and tag and check the bits add up. Given a trace of block numbers, simulate the cache under least-recently-used replacement and count misses. Given a hit rate and a miss penalty, produce the average access time — and say which of the three conventions the question is using. Given a miss rate, an accesses-per-instruction figure and a base CPI, produce the stall cycles and the speedup.

I read this topic as one address, one table, one average. The address is the three-field split. The table is the cache, one row per set, filled and evicted access by access. The average is the hit time plus the miss rate times the penalty. Every question in the GATE archive on this topic is one of those three, asked in a different costume. The cycles-per-instruction machinery used in the last scenes comes from Pipelining and Hazards.

Section 3 of the official GATE 2027 CS syllabus (IIT Madras, CS_GATE2027_Syllabus.pdf, read for this run) reads: "Instruction set and addressing modes. Design of arithmetic and logic unit (ALU). Design of control unit – hardwired and microprogrammed. Memory interfacing and hierarchy: performance, cache memory mapping. I/O interface (interrupt and DMA). Instruction pipelining, pipeline hazards."

Community observation Topic-indexed archives of past papers list between forty and seventy cache and memory-hierarchy items across the last three decades, with several in every recent paper. That is a count of what has been asked, not a forecast for 2027, and no official marks distribution exists.

Class A means a question here is inside the declared boundary. It does not mean one is guaranteed. Every previous-year item quoted in this lesson carries its year and paper, and its answer was recomputed here rather than copied.

Prerequisites

This lesson needs less machinery than most in Computer Organization:

  • Powers of two and logarithms. Every bit count here is a log base 2, and every capacity is a power of two. Nothing else is used.
  • The idea of a clock cycle. Hit times and penalties are quoted in nanoseconds and converted to cycles; the cycle is introduced in Sequential Circuits.
  • Execution time = instruction count × CPI × clock period, from Pipelining and Hazards, for scene 9 only.

There is no published lesson on main-memory devices in this library yet, so nothing is assumed about DRAM. Where a question needs a memory access time, the paper gives it.

The five ideas to leave with

  1. A cache does not make memory faster. It makes the average access faster, by betting on locality.
  2. The address split is forced, not chosen: offset is log of the block size, index is log of the number of sets, and the tag is the remainder.
  3. Associativity is an exchange of index bits for tag bits at a fixed rate of log base 2 of the associativity.
  4. On a trace, count misses and name victims. Never count addresses.
  5. Average access time and speedup are two different questions; the miss rate enters a speedup only through the stall cycles.

Intuition: the desk, the shelf and the storeroom

You are writing an essay. The books you are using right now sit on the desk. The rest of the library is on shelves behind you. Everything else is in the storeroom downstairs. Fetching from the storeroom takes an hour; taking a book from the shelf takes a minute; the book on the desk is already open.

Three facts about this arrangement are the three facts about a cache, and each is easy to get wrong. First, the desk is small and that is the point — you cannot fit the library on it, so you must choose what stays. Second, the average visit is what matters: nine quick reaches and one hour downstairs average out to six minutes, which is far better than an hour every time, and far worse than you might guess from "mostly hits". Third, you carry a whole armful, not one page: when you go to the shelf you bring the neighbouring chapters too, because you usually need them next. That armful is a block.

Educational interpretation The analogy is a teaching device, not a model of a memory system. It is chosen because it keeps three separate questions separate: what is close, what does a miss cost, and what travels together.

Definitions, every symbol in words

Block (also called a line when it is in the cache): a fixed run of consecutive bytes, the unit of transfer. A cache copies whole blocks.

Line: one slot in the cache, holding one block plus its tag and status bits.

Set: a group of lines that a given block is allowed to occupy. Number of sets times lines per set equals the number of lines.

Hit: the block you asked for is in the cache. Miss: it is not.

Hit time: the time to read the cache when the block is there. Miss penalty: the extra time to bring the block from below.

Hit rate h and miss rate m: m = 1 − h. They always sum to one; that is a check, not a formula to memorise.

Locality, stated formally

Temporal locality: if an address is referenced at time t, it is likely to be referenced again soon. This is what justifies keeping a block after using it.

Spatial locality: if an address is referenced, nearby addresses are likely to be referenced soon. This is what justifies transferring a block rather than a byte.

Mathematical derivation Both are statements about a probability distribution over addresses, not about any particular program. That is why a cache can be a good bet in general and a bad bet for one specific loop, and why the same cache can help one access pattern and hurt another.

The one formula everything rests on

Tavg = Thit + m × P

In words: the average time per access is the time you pay when the block is there, plus the fraction of accesses where it is not, times the extra time those cost.

Mathematical derivation Weight the two outcomes: h·Thit + (1 − h)(Thit + P). Expanding gives h·Thit + Thit + P − h·Thit − h·P, which is Thit + (1 − h)P. The hit time appears once, not twice.

The address is cut into three fields, and the cut is forced

Take a byte address of w bits. A cache of C bytes with blocks of B bytes has C/B lines. Divide those lines into sets of k lines each, so there are (C/B)/k sets. Then:

offset = log2 B   ·   index = log2(C / (B·k))   ·   tag = w − offset − index

Offset counts position inside the block, because a block is a contiguous run and the low bits of an address are the position within a run. Index chooses the set. Tag is the rest, and it is what the cache compares: two blocks that share a set differ exactly in their tags.

Mathematical derivation The three fields are disjoint and together cover the address, so they must sum to w. Any question that hands you a tag width and a cache geometry is handing you an equation with one unknown.

Direct mapped (k = 1)

One line per set, so the number of sets equals the number of lines. Block b can live only in line b mod (C/B). One tag comparison; no replacement policy; no choice.

Index width is log2(C/B). Two blocks whose numbers differ by a multiple of the line count fight for one line for ever — that is the conflict miss.

Fully associative (k = lines)

One set containing every line. Block b may live anywhere, so there is no index field at all and the tag is w − log2 B. Every line's tag is compared, usually in parallel.

Index width is 0. A replacement policy is needed on every miss.

Set associative (1 < k < lines)

Block b goes to set b mod v where v = (C/B)/k, and may sit in any of that set's k lines. Index width is log2 v, and k tags are compared.

If the lines are laid out set by set, block j occupies a line in the range (j mod v)·k to (j mod v)·k + k − 1, which is the answer GATE 2013 wanted.

One sentence that separates the three

Only the set is forced. Direct mapping forces the line as well; full associativity forces nothing. Everything else — tag width, comparators, need for a replacement policy — follows from that one difference.

Replacement policies

LRU — evict the line whose last use is furthest in the past. A stack algorithm: more lines can never mean more misses.

FIFO — evict the line that arrived earliest, ignoring use. Not a stack algorithm, and it can suffer Belady's anomaly: more lines, more misses.

Random — cheap, no state, no guarantee.

Optimal / Belady / MIN — evict the line whose next use is furthest in the future. Needs the future, so it is used only as a lower bound on misses.

Write policies

Write-through: every store updates the cache and memory. Memory is never stale, so no dirty bit and nothing to write back on eviction. Costs a memory write per store.

Write-back: a store updates only the cache and sets the dirty bit. The line goes to memory when evicted, so one memory write can cover many stores.

Separately, on a write miss: write-allocate fetches the block into the cache first, no-write-allocate writes around it to memory. The two choices are independent.

The three Cs, defined by a counterfactual

Compulsory: the first reference to that block in the trace. Survives every cache change.

Capacity: a miss that would still happen in a fully associative cache of the same size — the working set does not fit.

Conflict: a miss that would not happen in a fully associative cache of the same size — the mapping forced two live blocks into one set.

Two levels, and the convention that decides the answer

T = h1t1 + m1h2t2 + m1m2tm

This form applies when each quoted time is the total time incurred once that level is reached. The three probabilities must sum to one: h1 + m1h2 + m1m2 = 1.

If instead each time is the level's own access time under a serial convention, add the levels: a miss costs t1 + t2, and so on. The paper's wording decides; scene 9 shows both answers to the same numbers.

Four previous-year items where the address split is the whole question

Each is recomputed step by step here. The page recomputes every one of them again in its model and reports the result in the Model checks panel of the Animation tab.

1. GATE 2021 Set 1 — a tag width

"A byte-addressable primary memory of size 232 bytes, a direct-mapped cache of 32 KB, each block 64 bytes. The size of the tag field is ___ bits."

  1. Lines = 32768 ÷ 64 = 512, so index = log2 512 = 9.
  2. Offset = log2 64 = 6.
  3. Tag = 32 − 9 − 6 = 17.

Answer: 17 bits Check: 17 + 9 + 6 = 32.

2. GATE 2025 Set 1 — tag storage, not tag width

"1 M bytes of main memory, a 20-bit address, 16 K bytes of cache, block size 16 bytes, direct mapping. How many bits are required to store all the tag values?"

  1. Lines = 16384 ÷ 16 = 1024, so index = 10.
  2. Offset = log2 16 = 4, so tag = 20 − 10 − 4 = 6.
  3. Every line stores its own tag: 1024 × 6 = 6144 bits.

Answer: 6144 bits (210 × 6) The published key for this paper is option A, which is exactly this.

3. GATE 2017 Set 1 — associativity, no capacities given

"A cache of N words with block size B words. Direct mapped, the TAG field is 10 bits. As a 16-way set-associative cache, the TAG field is ___ bits."

  1. Capacity and block size are unchanged, so the number of lines is unchanged.
  2. 16-way means 16 lines per set, so the number of sets falls by 16, and the index falls by log2 16 = 4 bits.
  3. The address width is fixed, so the tag rises by the same 4: 10 + 4 = 14.

Answer: 14 bits The page instantiates a concrete cache consistent with a 10-bit tag and confirms 14.

4. GATE 2021 Set 2 — solving for associativity

"A set-associative cache of 2 KB, block size 64 bytes, byte-addressable, 32-bit address, tag field 22 bits. The associativity is ___."

  1. Offset = 6, tag = 22, so index = 32 − 22 − 6 = 4.
  2. 4 index bits means 16 sets.
  3. Lines = 2048 ÷ 64 = 32, so associativity = 32 ÷ 16 = 2.

Answer: 2 The page solves for the associativity from the tag width and gets 2.

Three previous-year items where the average or the trace is the whole question

These three are the ones the animation walks through, because their reasoning is a table or a weighted sum rather than a subtraction.

5. GATE 2015 Set 2 — the weighted average

"A read request takes 5 ns on a cache hit and 50 ns on a cache miss. 80 per cent of read requests result in a hit. The average access time is ___ ns."

  1. The paper gives the whole miss time, not the penalty, so weight the two outcomes.
  2. 0.8 × 5 = 4 ns from hits.
  3. 0.2 × 50 = 10 ns from misses.
  4. 4 + 10 = 14 ns.

Answer: 14 ns Using Thit + m × P with P = 50 would give 15, double counting the hit time.

6. GATE 2004 — the LRU walk

"A small two-way set-associative cache of four blocks, LRU replacement. The number of cache misses for the block addresses 8, 12, 0, 12, 8 is ___."

  1. Four blocks, two-way, so two sets. Set = block mod 2, so every even block lands in set 0.
  2. 8 misses and fills; 12 misses and fills; 0 misses and evicts 8 (least recently used).
  3. 12 hits, which refreshes its recency.
  4. 8 misses again and evicts 0.

Answer: 4 misses The page simulates this and reports 4 misses, of which 1 is a conflict miss.

7. GATE 2025 Set 1 — two levels

"L1: hit rate 95 per cent, access time 10 ns. L2: hit rate 85 per cent, access time 20 ns including the L1 miss penalty. Main memory: 200 ns including both miss penalties. The average access time is ___ ns (two decimals)."

  1. Three exclusive outcomes: 0.95, then 0.05 × 0.85 = 0.0425, then 0.05 × 0.15 = 0.0075. They sum to 1.
  2. 0.95 × 10 = 9.5; 0.0425 × 20 = 0.85; 0.0075 × 200 = 1.5.
  3. Total = 11.85 ns.

Answer: 11.85 ns The published key allows 11.83 to 11.87. Adding the L1 time again inside the lower terms gives 12.5, which is outside it.

8. GATE 2024 Set 1 — the miss rate becomes a CPI

"25 per cent of instructions are loads or stores. Ideal CPI without memory stalls is 2. Miss rate 2 per cent on the instruction cache and 8 per cent on the data cache. Miss penalty 100 cycles. The speedup with a perfect cache is ___ (two decimals)."

  1. Instruction stalls per instruction: 0.02 × 100 = 2.
  2. Data stalls per instruction: 0.25 × 0.08 × 100 = 2.
  3. CPI with stalls = 2 + 2 + 2 = 6; CPI with a perfect cache = 2.
  4. Speedup = 6 ÷ 2 = 3.00.

Answer: 3.00 The 0.25 belongs on the data term only. Charging data misses to every instruction gives 0.08 × 100 = 8 stalls, CPI 12 and a wrong speedup of 6.00.

Boundaries where the standard recipe changes shape

Each of these is a case a previous-year question has actually reached, or a case where a formula silently stops applying. The condition each one violates is named.

When the index field is zero

Fully associative means one set, so log2 1 = 0 index bits, and the tag is the whole address above the offset. Condition violated: none — this is the definition working correctly. What breaks is the habit of writing "index = log2(lines)".

GATE 2019 asked for the fields of a 16 KB fully associative cache with 16-byte blocks in a 32-bit address. Offset 4, index 0, tag 28. Public sources disagree on this question's key, which is why it is not used as a practice item here.

When the tag is the whole block number

A fully associative cache of 1 MB with 1-byte blocks in a 20-bit address has offset 0 and index 0, so the tag is all 20 bits: the block number itself, with nothing stripped off.

Condition violated: the habit of thinking of the tag as "the high bits left over". It is, and here nothing else was taken away. A tag field reaches zero width only when offset plus index already covers the whole address, which means the cache holds the entire address space at one block per line.

When the block size is given in words

GATE 2014 Set 2: a 4-way set-associative cache of 16 KB, block size 8 words, word length 32 bits, physical address space 4 GB. The block is 8 × 4 = 32 bytes, not 8.

Lines = 16384 ÷ 32 = 512; sets = 128 so index = 7; offset = 5; tag = 32 − 7 − 5 = 20.

Condition violated: the assumption that every length is already in bytes. Notice what the conversion does and does not change: the offset and index both move, and the tag stays at 20, because tag = width − log2 capacity + log2 associativity has no block size in it. The mistake that actually costs a mark here is dropping the associativity, which gives index 9 and tag 18.

When a "hit rate" belongs to a different denominator

An L2 hit rate of 85 per cent almost always means 85 per cent of the accesses that reached L2, not of all accesses. In the 2025 question the global L2 hit rate is 0.0425.

Condition violated: the assumption that a rate is taken over the same population as the others. Multiplying the two hit rates, 0.95 × 0.85, is the error this creates.

When a lower miss rate makes the average worse

A cache with a hit rate of 0.8, access time 10 ns and penalty 100 ns averages 10 + 0.2 × 100 = 30 ns. An optimisation cuts the miss rate to 0.1 but raises the access time to 25 ns: 25 + 0.1 × 100 = 35 ns. Worse.

Condition violated: the assumption that hit time is constant while miss rate falls. Both terms move, and the average is what is asked for. (This is an original illustration, not a previous-year item.)

When FIFO gets worse with more memory

On the block sequence 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5, FIFO with three lines misses 9 times and with four lines misses 10 times. LRU with the same trace misses 10 and 8.

Condition violated: FIFO is not a stack algorithm, so the monotonicity that LRU enjoys does not hold. The page computes all four counts and checks them.

Two pairs that are constantly confused

Both pairs look like synonyms in ordinary English and are not synonyms in this subject. Getting either wrong costs marks on questions that are otherwise trivial.

Miss time against miss penalty

Miss time is everything you pay when the block is absent: the lookup plus the fetch.

Miss penalty is only the extra part, the fetch, excluding the lookup you would have paid anyway.

So miss time = hit time + penalty. A question that quotes 50 ns on a miss and 5 ns on a hit has given you miss time, and the average is 0.8 × 5 + 0.2 × 50 = 14, not 5 + 0.2 × 50 = 15.

Associativity against number of sets

Associativity k is the number of lines per set. Number of sets v is what the index field counts.

Lines = v × k. "An 8-way cache with 64 KB and 32-byte blocks" has 2048 lines and therefore 256 sets, so 8 index bits — not 3. GATE 2023 asks exactly this shape of question, and the answer needs the line count first.

Write policy against write-miss policy

Write-through or write-back answers "when does memory learn about this store".

Write-allocate or no-write-allocate answers "does a store to a missing block fetch that block first". Four combinations, all of which have existed in real machines. A statement about one does not imply anything about the other.

The one boundary that decides many questions

Is the quoted time per level or per path? If per level, add the levels along a miss path. If per path, weight the exclusive outcomes. GATE states it in words — "including the miss penalty of the previous level" means per path. When a question does not say, the safe move is to write both answers, then choose the one that is among the options.

Six beliefs that cost marks here

Each is stated the way a learner states it, followed by the smallest structure that kills it and the rule that replaces it. All six were checked against the textbook treatment and against the previous-year items this lesson quotes.

1. "A bigger cache is always faster."

Why it tempts: a bigger cache misses less, and fewer misses sounds strictly better.

Why it is wrong: a bigger cache is slower to search, so the hit time rises while the miss rate falls, and the average is the sum of both terms.

Minimal counterexample: hit 0.8 at 10 ns with a 100 ns penalty averages 30 ns; hit 0.9 at 25 ns averages 35 ns.

Correct rule: compare average access times, never miss rates. The page's model computes both figures.

2. "You can choose the tag width."

Why it tempts: the tag is the field nobody derives first, so it looks like a design choice.

Why it is wrong: tag = address width − index − offset. Given the other three, it is determined.

Minimal counterexample: a 32-bit address with a 64-byte block and 512 lines forces 6 offset bits and 9 index bits, leaving exactly 17.

Correct rule: treat a quoted tag width as an equation, and solve for whichever of the four quantities is missing — that is exactly what GATE 2021 Set 2 does.

3. "More associativity is strictly better."

Why it tempts: associativity removes conflict misses, and conflict misses are the ones that feel wasteful.

Why it is wrong: it widens every tag, adds comparators and usually lengthens the hit time; and it does nothing at all for capacity or compulsory misses.

Minimal counterexample: the 2004 trace gains exactly one miss from associativity — 4 down to 3 — while the tag grows by a bit and the comparison widens from 1 to 2.

Correct rule: associativity trades hit time for conflict misses. State both sides.

4. "Write-back means memory is never written, and both caches need a dirty bit."

Why it tempts: "back" sounds like the cache is the only copy, and "dirty bit" sounds like part of any cache line.

Why it is wrong: write-back defers the write to eviction, so memory is written less often, not never. And write-through never needs a dirty bit because memory is never stale.

Minimal counterexample: GATE 2022, where statements A, B and D are false for exactly these reasons and only C is true.

Correct rule: the dirty bit exists to answer "is the cached copy newer than memory", and under write-through the answer is always no.

5. "LRU is the optimal replacement policy."

Why it tempts: LRU is the policy the syllabus names, it is provably good, and it is a stack algorithm.

Why it is wrong: optimal means evicting the block used furthest in the future, which needs the future. LRU only approximates it, and on a cyclic scan it is the worst possible choice.

Minimal counterexample: on 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5 with four lines, LRU misses 8 and optimal misses 6. The page computes both.

Correct rule: LRU is never worse than FIFO on these traces, and never better than optimal. Its guarantee is monotonicity in cache size, not optimality.

6. "Halving the miss rate doubles the speed."

Why it tempts: a miss rate is the number the question emphasises, so it feels like the performance measure.

Why it is wrong: the miss rate enters a time only through stall cycles, and the base CPI is still there.

Minimal counterexample: base CPI 2 with 4 stall cycles gives CPI 6; halving the stalls gives 4, which is a speedup of 1.5, not 2.

Correct rule: speedup = new CPI ÷ old CPI. Halving the miss rate halves the stall cycles, and the speedup depends on how large they were.

What the six have in common

Every one is a claim about one term of an average or a ratio, presented as a claim about the whole. The antidote is mechanical: write the formula, mark which term the claim changes, and ask whether any other term moves. That single habit resolves all six.

A reported difficulty, not a measured one

Community observation Discussions of this topic repeatedly report two specific sticking points: deciding whether a quoted miss time includes the hit time, and remembering that a hit updates recency. Both are addressed in scenes 2 and 6. This is what learners report, not a measurement of error rates, and no source was found that quantifies it.

The seven question shapes this topic actually uses

Categories follow the standard eight. Category D, construction of a structure, does not appear in this topic's archive and is not covered. Everything else does.

A — Direct definition (rare, 1 mark)

Reasoning path: recall a definition precisely — which policy needs a dirty bit, what a set is, what associativity counts.

Common wrong approach: answering from the sound of the word. "Write-back" does not mean memory is never written.

B — Property verification

Reasoning path: take the given structure and test a property: is this trace's fourth access a hit, does this mapping range hold k lines, is this statement about eviction true.

Common wrong approach: testing the property on one example and generalising. The 2013 distractor set is built for exactly that.

C — Calculation (the majority)

Reasoning path: split the address, or weight the outcomes, or count the misses. Three procedures, all mechanical.

Common wrong approach: doing the arithmetic in the wrong order — converting units before finishing, or rounding a period before multiplying by a large count.

E — Counterexample reasoning

Reasoning path: to disprove a universal claim about caches, build one trace. "Associativity always helps" dies on a trace with no conflict misses.

Common wrong approach: trying to argue from the definition alone. One valid trace is enough, and it is faster.

F — Multiple conditions (MSQ)

Reasoning path: evaluate each statement independently and note that partial credit exists in the real exam, so a statement you cannot decide is a real loss.

Common wrong approach: treating an MSQ as an MCQ and stopping at the first true statement. GATE 2022's answer is three of four.

G — Misconception trap

Reasoning path: notice that the options are built from the six beliefs in the previous tab, and check which term of the formula each distractor changes.

Common wrong approach: picking the option that matches the intuition rather than the arithmetic. 15 ns instead of 14 ns is this trap exactly.

H — Multi-step reasoning

Reasoning path: an address width becomes a bit split, the split becomes an associativity, the associativity becomes a miss count, and the miss count becomes a CPI. Four steps, each mechanical.

Common wrong approach: jumping to the last step and guessing. Write the intermediate quantities down; each one is checkable.

How to spend two minutes on any of them

Write the three field widths first, even if the question does not ask for them. They cost ten seconds and they convert almost every variant of this topic into arithmetic on numbers you already have.

Practice set, part 1 — five questions on the address split

Answers are hidden until you press Show answer. Items marked PYQ carry their year and paper; items marked Original were written for this lesson and are not previous-year questions.

NATEasyPYQ — GATE CSE 2021 Set 1, 1 mark

A computer system has a byte-addressable primary memory of size 232 bytes, a direct-mapped cache of size 32 KB (1 KB = 210 bytes), and each cache block is 64 bytes. The size of the tag field is ______ bits.

Answer: 17

Lines = 32768 ÷ 64 = 512 → index 9. Offset = log2 64 = 6. Tag = 32 − 9 − 6 = 17.

The page recomputes this and checks that 17 + 9 + 6 = 32. The usual slip is using 32 KB as the address space, which would give a different tag entirely.

NATMediumPYQ — GATE CSE 2025 Set 1, 2 marks

A memory system has 1 M bytes of main memory and 16 K bytes of cache memory. The processor generates a 20-bit memory address and the cache block size is 16 bytes. The cache uses direct mapping. How many bits are required to store all the tag values? (Assume the memory is byte addressable.)

Answer: 6144

Lines = 16384 ÷ 16 = 1024 → index 10. Offset = 4. Tag = 20 − 10 − 4 = 6 bits per line.

Storage = 1024 × 6 = 6144 bits. The published key is option A, 210 × 6. Answering 6 answers a different question.

NATMediumPYQ — GATE CSE 2017 Set 1, 2 marks

A cache memory unit with capacity of N words and block size of B words is to be designed. Designed as a direct-mapped cache, the length of the TAG field is 10 bits. If the cache unit is now designed as a 16-way set-associative cache, the length of the TAG field is ______ bits.

Answer: 14

Capacity and block size are unchanged, so the line count is unchanged. Sixteen lines per set divides the set count by 16, so the index loses log2 16 = 4 bits.

The address width is fixed, so the tag gains those 4 bits: 10 + 4 = 14. The page instantiates a concrete cache with a 10-bit tag and confirms the 16-way version needs 14.

NATMediumPYQ — GATE CSE 2014 Set 2, 2 marks

A 4-way set-associative cache memory unit with a capacity of 16 KB is built using a block size of 8 words. The word length is 32 bits. The size of the physical address space is 4 GB. The number of bits for the TAG field is ______.

Answer: 20

Block = 8 words × 4 bytes = 32 bytes, so offset = 5. Lines = 16384 ÷ 32 = 512; sets = 512 ÷ 4 = 128, so index = 7.

4 GB = 232 bytes, so tag = 32 − 7 − 5 = 20. Forgetting to divide by the associativity gives 512 sets, index 9 and the wrong tag 18.

NATMediumPYQ — GATE CSE 2021 Set 2, 2 marks

A set-associative cache of size 2 KB (1 KB = 210 bytes) has a cache block size of 64 bytes. The cache is byte-addressable and a 32-bit address is used. The width of the tag field is 22 bits. The associativity of the cache is ______.

Answer: 2

Offset = 6 and tag = 22, so index = 32 − 28 = 4, which is 16 sets. Lines = 2048 ÷ 64 = 32.

Associativity = lines ÷ sets = 32 ÷ 16 = 2. The page solves for the associativity from the tag width and gets 2.

Practice set, part 2 — five questions on traces, averages and policies

These are the ones where the arithmetic is easy and the modelling is not. Read each question's convention before computing.

NATEasyPYQ — GATE CSE 2015 Set 2, 1 mark

For a certain processor, a read request takes 50 nanoseconds on a cache miss and 5 nanoseconds on a cache hit. While running a program, 80 per cent of the processor's read requests result in a cache hit. The average access time in nanoseconds is ______.

Answer: 14

The 50 ns is the whole miss time, so weight the two outcomes: 0.8 × 5 + 0.2 × 50 = 4 + 10 = 14 ns.

The trap is Thit + m × P with P = 50, which gives 15 because it counts the hit time inside the penalty as well as outside it.

NATEasyPYQ — GATE CSE 2004, 2 marks

Consider a small two-way set-associative cache memory consisting of four blocks. For choosing the block to be replaced, the least-recently-used (LRU) scheme is used. The number of cache misses for the following sequence of block addresses — 8, 12, 0, 12, 8 — is ______.

Answer: 4

Four blocks at two-way means two sets. Set = block mod 2, and every block here is even, so all five accesses land in set 0 and set 1 stays empty.

8 misses, 12 misses, 0 misses and evicts 8, 12 hits, 8 misses and evicts 0. Four misses.

The page simulates this under LRU and reports 4 misses, of which exactly 1 is a conflict miss.

NATMediumPYQ — GATE CSE 2020, 2 marks

A direct-mapped cache memory of 1 MB has a block size of 256 bytes. The cache has an access time of 3 ns and a hit rate of 94 per cent. During a cache miss, it takes 20 ns to bring the first word of a block from main memory, while each subsequent word takes 5 ns. The word size is 64 bits. The average memory access time in ns (rounded to one decimal place) is ______.

Answer: 13.5

Words per block = 256 bytes ÷ 8 bytes = 32, so 31 subsequent words. Penalty = 20 + 31 × 5 = 175 ns.

Average = 3 + 0.06 × 175 = 3 + 10.5 = 13.5 ns. Using 32 subsequent words instead of 31 gives 13.8, which is the intended slip.

NATHardPYQ — GATE CSE 2025 Set 1, 2 marks

A computer has a memory hierarchy of a two-level cache (L1 and L2) and a main memory. L1 has hit rate 95 per cent and access time 10 ns. L2 has hit rate 85 per cent and access time 20 ns, including the L1 cache miss penalty. Main memory has access time 200 ns, including the L1 and L2 cache miss penalties. The average memory access time in ns (rounded to two decimal places) is ______.

Answer: 11.85

Outcome probabilities: 0.95, 0.05 × 0.85 = 0.0425, and 0.05 × 0.15 = 0.0075. They sum to 1, which is the check.

0.95 × 10 + 0.0425 × 20 + 0.0075 × 200 = 9.5 + 0.85 + 1.5 = 11.85 ns.

The published key allows 11.83 to 11.87. Adding the 10 ns L1 time again inside the lower terms gives 12.5, outside the range.

MSQMediumPYQ — GATE CSE 2022, 1 mark

Let WB and WT be two set-associative cache organisations that use the LRU algorithm for block replacement. WB is a write-back cache and WT is a write-through cache. Which of the following statements is/are FALSE?

  1. Each cache block in WB and WT has a dirty bit.
  2. Every write hit in WB leads to a data transfer from cache to main memory.
  3. Eviction of a block from WT will not lead to data transfer from cache to main memory.
  4. A read miss in WB will never lead to eviction of a dirty block from WB.

Answer: A, B and D

A is false: write-through never needs a dirty bit, because memory is never stale.

B is false: a write hit in write-back updates only the cache and sets the dirty bit; the transfer waits for eviction.

C is true: a write-through block is never newer than memory, so eviction moves nothing.

D is false: LRU may select a dirty victim on a read miss, and it must then be written back. The page records the answer as A, B and D.

Practice set, part 3 — two more previous-year items and three originals

The originals are written in GATE format and are labelled as originals. They carry no official marks.

NATMediumPYQ — GATE CSE 2024 Set 1, 2 marks

A program has 25 per cent load/store instructions. The ideal CPI without any memory stalls is 2. The program exhibits a 2 per cent miss rate on the instruction cache and an 8 per cent miss rate on the data cache. The miss penalty is 100 cycles. The speedup (rounded to two decimal places) achieved with a perfect cache, that is with no data or instruction cache misses, is ______.

Answer: 3.00

Instruction stalls per instruction = 0.02 × 100 = 2. Data stalls per instruction = 0.25 × 0.08 × 100 = 2.

CPI = 2 + 2 + 2 = 6; perfect-cache CPI = 2; speedup = 3.00. The 0.25 belongs on the data term only — charging data misses to every instruction gives CPI 12 and a speedup of 6.00.

MCQMediumPYQ — GATE CSE 2013, 2 marks

In a k-way set-associative cache, the cache is divided into v sets, each consisting of k lines. The lines of a set are placed in sequence one after another, and the lines in set s are sequenced before the lines in set s+1. Main memory blocks are numbered from 0 onwards. Main memory block number j must be mapped to any one of the cache lines from:

  1. (j mod v) × k to (j mod v) × k + (k − 1)
  2. (j mod v) to (j mod v) + (k − 1)
  3. (j mod k) to (j mod k) + (v − 1)
  4. (j mod k) × v to (j mod k) × v + (v − 1)

Answer: A

The set is j mod v, because the index counts sets. Set s occupies the k consecutive lines starting at s × k.

So the range is (j mod v) × k through that plus k − 1. The page checks, for every block in a small example, that the range holds exactly k lines and that all of them lie in set j mod v. Options B, C and D all use the right modulus with the wrong multiplier, or the wrong modulus.

NATHardOriginal

Blocks are accessed in the order 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5. Count the misses under FIFO replacement with 3 lines, then with 4 lines, and then under LRU with 4 lines. Enter the three counts in the order asked, separated by commas.

Answer: 9, 10, 8

FIFO with 3 lines misses 9 times. FIFO with 4 lines misses 10 times — more memory, more misses, which is Belady's anomaly and is only possible because FIFO is not a stack algorithm.

LRU with 4 lines misses 8 times. The page runs all three and checks these exact counts. This is the smallest standard demonstration of the anomaly, and the reason LRU is preferred despite needing per-line recency state.

MSQMediumOriginal

A 2-way set-associative cache has 4 blocks and 16-byte blocks. The block sequence is 8, 12, 0, 12, 8, as in the 2004 question. Which of the following statements are TRUE?

  1. The trace produces exactly one conflict miss and no capacity miss.
  2. Making the cache fully associative with the same four blocks would reduce the miss count to 3.
  3. Making the cache 4-way with the same four blocks would reduce the miss count to 3.
  4. FIFO replacement produces a different miss count from LRU on this trace.

Answer: A, B and C

A is true: the page classifies the four misses as 3 compulsory, 0 capacity and 1 conflict.

B is true: four lines in one set gives 3 misses, since 8, 12 and 0 all fit.

C is true and is the same cache as B — four blocks at 4-way means one set, which is full associativity. This is the distinction worth noticing.

D is false: the page runs both policies and gets 4 misses either way. The policies agree here, and that is not a coincidence you should generalise.

MCQEasyOriginal

A cache has a hit time of 4 cycles and a miss penalty of 60 cycles. An optimisation raises the hit time to 6 cycles and lowers the miss rate from 10 per cent to 5 per cent. Which statement is correct?

  1. The average access time falls by 10 per cent.
  2. The average access time rises, even though the miss rate halved.
  3. The average access time is unchanged, because the two effects cancel exactly.
  4. Average access time cannot be computed without knowing the block size.

Answer: A

Before: 4 + 0.10 × 60 = 10 cycles. After: 6 + 0.05 × 60 = 9 cycles.

A fall of 1 cycle out of 10 is a 10 per cent improvement, so the optimisation does pay — but far less than the halved miss rate suggests. B is the answer only if the hit time rises faster than the misses save, which is the mistake to check for; C would need the two effects to be exactly equal, and 2 cycles is not 3; D is false because the block size never enters an average access time.

The one-screen revision sheet

Definitions, formulas with their conditions, the decision procedure, and the traps with the counterexample that defuses each. Everything here was derived or computed in this lesson.

Definitions in one line each

Block — the unit of transfer, B bytes. Line — one cache slot holding one block plus tag and status.

Set — the lines a block may occupy; index counts sets.

Associativity k — lines per set; lines = sets × k.

Hit time — time to read the cache. Miss penalty — extra time to fetch. Miss time = hit time + penalty.

Dirty bit — set only by write-back, meaning the cached copy is newer than memory.

Formulas, and when each holds

offset = log2 B · index = log2(C/(Bk)) · tag = w − index − offset

Holds for any power-of-two geometry. Check the three sum to w.

T = Thit + m·P

Holds when P is the penalty alone. If the paper gives the whole miss time, weight the outcomes instead.

T = h1t1 + m1h2t2 + m1m2tm

Holds when each t is the total time once that level is reached. The three probabilities must sum to 1.

Decision procedure

  1. Convert every length to bytes, including word-based block sizes.
  2. Lines = capacity ÷ block size. Sets = lines ÷ associativity.
  3. Offset = log2 block size; index = log2 sets; tag = width − both. Check the sum.
  4. If a trace is given: set = block mod sets, then compare tags in that set; update recency on a hit.
  5. Choose the average convention the paper's words imply, compute in one unit, convert once at the end.
  6. For a speedup, convert misses into stall cycles and divide CPIs or times.

Each step is separately checkable, which is why the order matters more than the arithmetic.

Five traps, each with its counterexample

Miss time used as penalty — 2015 Set 2 gives 15 instead of 14.

Tag width answered for total tag storage — 2025 Set 1 gives 6 instead of 6144.

Block size left in words — 2014 Set 2 gives 17 instead of 20.

Lower level time added to itself — 2025 Set 1 gives 12.5 instead of 11.85.

Data miss charged to every instruction — 2024 Set 1 gives 5 instead of 3.00.

Six quick revision questions, answers inverted

1. A 32 KB 4-way cache with 32-byte blocks, 32-bit address: tag width? — 17 − 3 = 14? Work it: lines 1024, sets 256, index 8, offset 5, tag 19.

2. Fully associative: how many index bits? — zero.

3. Which policy can miss more with a bigger cache? — FIFO, Belady's anomaly.

4. Which write policy needs a dirty bit? — write-back only.

5. A miss that survives full associativity is called? — capacity, unless it is the first touch, which is compulsory.

6. Halving the miss rate halves the speedup? — no: it halves the stall cycles, and the base CPI remains.
