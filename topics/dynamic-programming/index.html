Topic and objective

TOPIC: Dynamic programming — how a recurrence with repeating subproblems becomes a table: the state, the transition, the base case and the fill order, executed on 0/1 knapsack, longest common subsequence, matrix chain multiplication, longest increasing subsequence and Floyd-Warshall.

LEARNING OBJECTIVE: Given a problem, name its state in one phrase, write the recurrence and its base case, say in which order the table may be filled, and quote the cost as states times work per state. Fill the knapsack and LCS tables by hand and read the right number out of the right cell. Say why a one-row knapsack must be updated with descending capacity. Place a new problem in greedy, divide-and-conquer or dynamic programming by testing optimal substructure and overlap.

I read this as the third of the three design techniques in the syllabus line "greedy, dynamic programming and divide-and-conquer". Greedy is its own lesson in this repository; divide-and-conquer recurrences are solved in Recurrence Relations. This lesson is the dynamic-programming third, and it assumes both.

Prerequisites

You need four things, each with a lesson in this repository:

  • Recursion — a recurrence is written in the language of recursive calls.
  • Asymptotic complexity — "states times work per state" is a big-O statement.
  • Greedy algorithms — the contrast that makes the third property visible.
  • Trees and heaps — graphs and matrices are drawn as tables here.

No advanced mathematics is assumed. Every symbol is explained in words the first time it appears.

Approximate learning time

Educational interpretation About 55 to 75 minutes: roughly 25 minutes of prose and worked examples, 15 minutes of animation, 15 minutes of practice. The estimate is a guide, not a measurement.

If you only have ten minutes, watch the animation scenes 1, 2, 4 and 10. They carry the whole argument: overlap, the table, the two-way choice, and the loop direction that silently changes the problem.

The five key ideas

  1. Overlap is the reason. A recurrence whose subproblems repeat wastes work; the table removes the repetition.
  2. The state is the examinable part. Name what the subproblem is allowed to depend on, and the recurrence usually writes itself.
  3. Cost is states times work per state, not "the number of loops". Knapsack is O(nW), which is pseudo-polynomial.
  4. Fill order is a topological order of the dependency graph. Row-major works for grids, length order for intervals.
  5. Greedy needs one property more than DP: a provably safe local choice. Without it, greedy is a guess and DP is the fallback.

Intuition: the exam you have already sat

You are answering a long paper. Question 12 uses a result from question 4. You have already worked question 4 on the back of a rough sheet. Do you redo it, or look it up?

You look it up, because redoing it costs the same time again and buys nothing. Educational interpretation That rough sheet is the DP table: a place where each subproblem's answer is written once, so later questions read instead of recompute.

Now the two conditions that make the analogy legal. The paper must ask the same question twice — otherwise the sheet is empty at the end. And a big answer must be buildable from small answers — otherwise the sheet cannot help you.

Formal definition

Dynamic programming solves a problem by defining a set of states, each of which is a subproblem, and computing the answer to every state exactly once, in an order in which every state is computed after the states its recurrence reads.

Two properties are needed, and both are needed:

  • Optimal substructure — an optimal solution to a state contains optimal solutions to the states its recurrence reads.
  • Overlapping subproblems — the same state is reached by more than one route, so its answer is reused rather than recomputed.

The state is the tuple of numbers that pins down one subproblem. Mathematical derivation If a state is reached r times and costs w to solve, storing it turns r·w work into w. Nothing else about the technique is essential.

Two spellings of the same idea

Memoisation keeps the recursive definition and adds a cache: look up the state, return if present, otherwise compute, store, return. It is top-down and it only ever visits states that are reachable.

Tabulation throws the recursion away: create the table, write the base cases, then fill every state in a legal order. It is bottom-up and it visits every state, including ones the answer never needed.

Both are dynamic programming. The distinction that matters is not "recursive or not", it is each state computed once. Verified fact This is the standard presentation in CLRS, chapter 15, and in Dasgupta–Papadimitriou–Vazirani, chapter 6.

The recurrence has five parts

1 State — what the answer depends on. Knapsack: (item index, capacity left).
2 Choice — what the state may do. Knapsack: take this item or skip it.
3 Transition — the state written in terms of smaller states. Knapsack: the max of the two choices.
4 Base case — where it stops. No items, or capacity zero, gives value 0.
5 Fill order — a topological order of the dependencies. Knapsack: row by row, left to right.

An answer missing any of the five is incomplete, and in an exam it is usually the state or the fill order that is missing.

Formal recurrence, written out

Let K(i, c) mean "the best value using only the first i items with capacity c left". Let item i have weight wi and value vi.

K(i, c) = K(i−1, c) if wi > c K(i, c) = max( K(i−1, c), vi + K(i−1, c−wi) ) otherwise K(0, c) = K(i, 0) = 0

In words: if the item does not fit, the answer is the answer without it. If it fits, the answer is the better of leaving it out and taking it, where taking it adds its value and leaves less capacity. Mathematical derivation The base case holds because no item set has value zero-cost greater than nothing, and no positive-weight item fits in capacity zero.

Where the two properties actually bite

Optimal substructure is what lets the recurrence exist. Overlap is what makes it worth a table. They fail in different places, so name which one you are invoking.

Divide and conquer has the first and not the second: merge sort's two halves are disjoint, so a table would store answers nobody asks for twice.

Greedy has the first and adds a third — a provably safe local choice — and needs no table at all.

Neither happens too: longest simple path in a general graph has no optimal substructure, because the best path to a vertex may block the best continuation. That is why it is NP-hard and no DP fixes it.

What the table is, geometrically

Draw one dot per state and one arrow from a state to every state its recurrence reads. The result is a directed graph of states. A DP is correct exactly when that graph has no cycle, and the fill order is any topological order of it.

Two familiar cases:

  • A grid of prefix pairs (knapsack, LCS) has arrows up, left and diagonally up-left, so row-major and column-major both work.
  • An interval table (matrix chain, optimal BST) has arrows to strictly shorter intervals, so only a sweep by length works.

Mathematical derivation Any order in which every arrow points from a later cell to an earlier cell is legal, and any order in which some arrow points forward reads an unwritten cell.

One sentence to hold

Dynamic programming is a recurrence plus a table plus an order, and the exam asks for the state, the recurrence, the order and the cost — in that order, because each one depends on the one before it.

Example 3 — matrix chain, dimensions 40, 20, 30, 10, 30

Four matrices. Cost of multiplying a p×q by a q×r matrix is p·q·r. State: the interval (i, j). Choice: the split point k.

length 2: M12 = 24000 M23 = 6000 M34 = 3000
length 3: M13 = 26000 M24 = 9000
length 4: M14 = 26000

Answer 26000, split after the third matrix. Mathematical derivation Four matrices have only five parenthesisations, so the page enumerates all five and confirms 26000 is the minimum. The interval table is filled by increasing length, never row by row.

Example 4 — LIS of 3, 2, 6, 4, 5, 1

Let L[i] be the longest increasing subsequence starting at index i. Then L[i] = 1 + max over later j with A[j] > A[i] of L[j].

A = 3 2 6 4 5 1
L = 3 3 1 2 1 1
answer = max L = 3, witness 2, 4, 5

Mathematical derivation The page computes L and checks the maximum against an exhaustive search over all subsequences. Both give 3. Note the answer is the maximum of the array, not L[0]: starting at the largest element hides longer sequences.

Example 5 — edit distance, kitten to sitting

Allowed moves: insert, delete, substitute, one character each. State: (prefix of the first word, prefix of the second).

d(i,j) = d(i−1, j−1) if the characters match
d(i,j) = 1 + min( d(i−1,j−1), d(i−1,j), d(i,j−1) ) otherwise
d(i,0) = i d(0,j) = j

Answer 3: substitute k for s, substitute e for i, insert g. Mathematical derivation The page computes the table and confirms the result is symmetric, d(kitten, sitting) = d(sitting, kitten) = 3, which a correct edit distance must be.

Example 6 — coin change, coins 1, 2, 5, amount 11

This is the unbounded version: a coin may be used any number of times. State: the amount still to be paid. dp[0] = 0, dp[v] = 1 + min over coins c ≤ v of dp[v − c].

dp[0..11] = 0 1 1 2 2 1 2 2 3 3 2 3

Answer 3 coins: 5 + 5 + 1. Mathematical derivation Compare with the greedy lesson's counterexample: on coin set 1, 3, 4 for amount 6, largest-first spends 3 coins where 2 suffice. The same DP answers both correctly, which is why the coin set does not have to be examined.

Example 7 — Floyd-Warshall on a four-vertex graph

Edges: 0→1 (3), 0→3 (8), 1→2 (1), 2→3 (1), 0→2 (7). State: (i, j, k), the shortest i-to-j path using only vertices 1..k as intermediates.

k = 0: d(0,3) = 8
k = 1: d(0,2) = min(7, 3+1) = 4
k = 2: d(0,3) = min(8, 4+1) = 5
k = 3: no further improvement

Mathematical derivation The page compares the final matrix against Dijkstra run from every source, and against the triangle inequality d(i,j) ≤ d(i,k) + d(k,j). All three agree, so the table is correct and not merely plausible.

Example 8 — the wrong loop direction, computed

Items: A (weight 2, value 3), B (weight 5, value 6). Capacity 6. The 0/1 optimum is 6, taking B alone; A twice would weigh 4 and give 6 as well, but 0/1 does not allow it.

one row, capacity descending → 6 (correct for 0/1)
one row, capacity ascending → 9 (three copies of A)

Mathematical derivation Ascending reads the cell it has just written in the same item pass, so the item is taken again. The page checks that the ascending value equals the unbounded-knapsack optimum and the descending value equals the full two-row answer. One loop direction, two different problems.

Boundary case — empty input or zero capacity

LCS of an empty string and anything is 0, and the table's row zero and column zero are exactly that. Knapsack with capacity 0 is worth 0 whatever the items. Matrix chain on one matrix costs 0, not the product of its dimensions.

The base case is not bookkeeping. Every longer state reads it, so a wrong base case poisons the whole table silently — the program still runs and prints a number.

Counterexample — "DP is always better than greedy"

Subset sum with target T and n items has a table with n·T cells. With T equal to 109 that table does not fit in any machine, while the greedy approximation runs instantly. Mathematical derivation The bound O(nT) is polynomial in the value of T, not in its bit length, which is why subset sum and knapsack are called weakly NP-hard rather than polynomial.

So "use DP" is a claim about tractability, and tractability depends on the size of the state space, not on the elegance of the recurrence.

Counterexample — two longest common subsequences

For A = abc and B = bac the table gives length 2, and both ab and bc achieve it. The length is unique; the subsequence is not.

GATE CSE 2014 Set 2 asked for the number of longest common subsequences of "qpqrr" and "pqprqrp". The length table cannot answer that; it needs a second table counting optimal paths. Community observation GateOverflow discussion records disagreement over whether index-distinct copies of the same string count; the accepted answer is 34, which counts distinct strings, giving x = 4 and y = 3.

Counterexample — the wrong fill order still runs

Fill an interval table row by row and no exception is thrown. Cells simply read zeros that were never written, and the answer comes out too small. For dimensions 40, 20, 30, 10, 30 a row-major sweep does not produce 26000.

Silent wrongness is the reason the fill order is examinable. Always ask which cells the recurrence reads before choosing the loop nesting.

Edge case — negative edges and cycles

Floyd-Warshall and Bellman-Ford tolerate negative edges; Dijkstra does not. But no DP tolerates a negative cycle, because then no shortest path exists at all.

A DP needs the state graph to be acyclic. A negative cycle makes the "shortest walk" unbounded below, so the recurrence has no least solution. Detecting the cycle is a separate check, not part of the table.

Edge case — memoisation depth and state explosion

A top-down memoised solution on a 104-state chain can overflow the call stack before it finishes, while the bottom-up table is happy. Conversely, memoisation wins when most states are unreachable: it never visits them.

Choose by the shape of the reachable state set, not by taste. Both spellings are DP, and the difference is which states get computed.

Closely confused pair 1 — LCS and longest common substring

A substring must be contiguous; a subsequence need not be. So LCS of AGGTAB and GXTXAYB is 4 (GTAB), while the longest common substring is 2 (GT or AB).

The tables differ in one line: on a mismatch the substring table resets the cell to 0 and keeps a running maximum, while the subsequence table takes the max of two neighbours. Mathematical derivation Read the answer off the maximum of the whole substring table, not its corner.

Closely confused pair 2 — 0/1 knapsack and unbounded knapsack

Same items, same capacity, same objective, one difference: whether an item may be used more than once. The two-row table differs in one index — K(i−1, c−w) against K(i, c−w) — and the one-row table differs in one loop direction.

Both are DP and both are correct. Reading K(i, c−w) in a 0/1 question is a lost mark that looks like a typo and is not.

M1 — "Dynamic programming means recursion with a cache"

Why it tempts: the first DP most people write is a memoised recursive function, and the cache is visible.

Minimal counterexample: the bottom-up knapsack table in this lesson has no recursive call anywhere and is DP. A memoised function that caches nothing useful — because no state repeats — is not DP in any useful sense.

Correct rule: DP is "each state computed once and reused". Memoisation and tabulation are two ways to arrange that, and either one qualifies.

M2 — "Optimal substructure is enough for DP"

Why it tempts: the textbook definition lists optimal substructure first, and it is the property that lets a recurrence be written at all.

Minimal counterexample: merge sort has optimal substructure and no overlapping subproblems. A DP table for it would store answers nobody asks twice, so the table is pure overhead.

Correct rule: both properties are required. Optimal substructure without overlap is divide and conquer; with overlap it is DP.

M3 — "DP can solve anything greedy solves, so always use DP"

Why it tempts: DP is more general, and it is the safe answer when no exchange argument is available.

Minimal counterexample: the DP for the activity-selection problem must index the state by "which activities are still available", which is exponential in the number of activities. Greedy solves it in n log n.

Correct rule: DP is more general in correctness and not in cost. Prefer greedy when a greedy-choice proof exists; prefer DP when it does not and the state is small.

M4 — "A filled table is dynamic programming"

Why it tempts: every DP answer in the textbook has a table in it, so the table looks like the defining feature.

Minimal counterexample: a table that stores the brute-force answer for every subset of n items is a table, is correct, and is exponential. Nothing is reused, because no state is shared.

Correct rule: the table is a consequence of overlap. If states do not overlap, a table changes nothing about the cost.

M5 — "Memoisation makes any exponential recursion polynomial"

Why it tempts: on Fibonacci the speed-up is dramatic, and it is the first example everyone sees.

Minimal counterexample: the naive recursion for the n-queens or the travelling-salesman problem has an exponential number of distinct states. Caching them all is still exponential, and usually runs out of memory first.

Correct rule: the cost is the number of distinct states times work per state. Memoisation removes repeated work, not the size of the state space.

M6 — "One array is one array, the loop direction does not matter"

Why it tempts: both loops visit every capacity once, so the code looks equivalent.

Minimal counterexample: items (2, 3) and (5, 6) with capacity 6. Descending gives 6, the 0/1 optimum. Ascending gives 9, which takes the weight-2 item three times. Both are computed and checked on this page.

Correct rule: the loop direction decides whether a cell reads the previous item's row or the current one. Descending for 0/1, ascending for unbounded.

M7 — "The LCS table entry counts the number of optimal subsequences"

Why it tempts: the entry is a number, and on a small example it happens to equal the count of something.

Minimal counterexample: for abc and bac the corner holds 2 while there are two distinct longest subsequences, and for other inputs the corner and the count diverge completely.

Correct rule: the table stores lengths. Counting optimal solutions needs a second table that sums over the optimal branches — the pattern behind the GATE 2014 count question.

M8 — "Floyd-Warshall is greedy because Dijkstra is"

Why it tempts: both compute shortest paths, both are taught in the same week, and Dijkstra's local choice is genuinely greedy.

Minimal counterexample: Floyd-Warshall commits to nothing. It relaxes every pair through every intermediate vertex, in n passes over the whole matrix — the definition of a DP over the state (i, j, k).

Correct rule: GATE CSE 2016 Set 2 asked exactly this and the answer is dynamic programming. Naming the state (i, j, k) settles the question immediately.

Pattern 1 — paradigm identification

The question shows an algorithm or a named method and asks which design technique it belongs to. The reasoning: find the state and check whether the answers are stored and reused.

Wrong approach: deciding by the presence of a loop or of a recursion. Both appear in all three paradigms.

Worked instance: GATE CSE 2016 Set 2 asked which paradigm the Floyd-Warshall algorithm is based on; the answer is dynamic programming, because the state (i, j, k) is filled in order of k. GATE CSE 2015 Set 1 asked the same thing as a matching question across four algorithms.

Pattern 2 — fill order and initialisation

The question gives a recurrence and a table, then asks which statement about computing it is true: what must be initialised, and which cell must precede which.

Wrong approach: assuming "smaller row before bigger row" or "smaller column before bigger column". Both are stronger than the actual dependency.

Worked instance: GATE CSE 2009 asked this about the LCS table. Only row zero and column zero need initialising, and the table may be filled row-major or column-major, because each cell reads the cell above, the cell to the left and the diagonal.

Pattern 3 — table entry as a numerical answer

A small instance and a request for one number: an LCS length, a matrix-chain cost, a knapsack value, an edit distance. These are NAT questions and the arithmetic must be exact.

Wrong approach: reading the wrong cell. The corner is the answer for the full instance only; a middle cell answers a different question.

Worked instance: GATE CSE 2014 Set 2 gave two strings and asked for x + 10y, where x is the LCS length and y the number of longest common subsequences. x = 4 and y = 3, so the answer is 34.

Pattern 4 — counting optimal solutions

A cost or length question with "and how many ways attain it". This needs a second table that adds the counts along optimal branches, plus a decision about whether identical strings count once.

Wrong approach: trying to read a count out of the length table. It does not contain one.

Worked instance: the same GATE 2014 question. Three distinct strings of length 4 are common to both inputs, so y = 3. The counting convention — distinct strings rather than distinct index mappings — is the whole difficulty.

Pattern 5 — complexity of a DP

State the number of states, multiply by the work per state, and say what the state variables are. For knapsack that is O(nW) with W the capacity value.

Wrong approach: counting nested loops. A DP can have three loops and a linear table if one of them walks a chain.

Worked instance: matrix chain has O(n²) states and O(n) splits per state, hence O(n³); Floyd-Warshall has O(n²) states and O(1) work per (i, j, k) triple, hence O(n³). Both are cubic, for entirely different reasons.

Pattern 6 — reconstructing the solution

The question gives a filled table and asks for the chosen items, the split, or the subsequence. The answer comes from walking back from the final cell, comparing with the neighbours the recurrence used.

Wrong approach: re-solving the subproblem at each step, which is correct but slow and easy to get wrong under time pressure.

Worked instance: the LCS walk in scene 5. Start at the corner, take the diagonal on a match, otherwise step to the larger neighbour. The walk is at most m + n steps.

The four sentences an answer needs

State what the state is · write the transition and the base case · say which order fills the table · give the cost as states times work per state. Any DP answer in the paper is a special case of those four, and a missing one is usually where the marks went.

MCQ Original

Q1. For 0/1 knapsack solved by a table, which pair of quantities is a complete state?

(A) The current item's weight and value.
(B) The number of items considered so far and the capacity still available.
(C) The total weight chosen so far.
(D) The index of the last item taken and the number of items left.

Answer: (B). Every subproblem is "the best value from the first i items with capacity c left", so (i, c) pins it down, and the table is (n+1) by (W+1).

Why the others fail: (A) is data about one item, not a subproblem. (C) loses which items were used, so two different subproblems collapse into one state and the answer is wrong. (D) cannot express "capacity remaining", so it cannot price the next choice. Trap: a state that is too small is worse than a state that is too large — it gives a confident wrong answer.

NAT GATE CSE 2014 Set 2

Q2. For A = "qpqrr" and B = "pqprqrp", let x be the LCS length and y the number of distinct longest common subsequences. Then x + 10y = ______.

Answer: 34. The LCS table gives x = 4. The strings of length 4 common to both are qprr, pqrr and qpqr, so y = 3 and 4 + 30 = 34.

Where marks are lost: counting index mappings instead of strings. "qpqr" can be formed in two ways from A because A has two r's at the end, and counting that way gives 44. Community observation GateOverflow discussion records the disagreement; the accepted reading counts distinct strings, giving 34.

MCQ GATE CSE 2009

Q3. For the LCS recurrence l(i,j) with l(i,j) = 0 when either index is 0, filled into an array L of size (m+1) by (n+1), which statement is true?

(A) All elements of L must be initialised to 0 for l to be computed correctly.
(B) The values may be computed in row-major order or in column-major order of L.
(C) The values cannot be computed in either row-major or column-major order.
(D) L[p,q] must be computed before L[r,s] whenever p < r or q < s.

Answer: (B). Each cell reads the cell above, the cell to the left and the diagonal. Row-major supplies all three before they are read, and so does column-major.

Why the others fail: (A) — only row 0 and column 0 are the base case; every other entry is overwritten by the recurrence. (C) contradicts (B). (D) is stronger than the truth: it would demand L[2,1] before L[1,3] and also L[1,3] before L[2,1], which is impossible, while the real requirement is only "above, left, diagonal". Trap: an option that is true but too strong is still false.

MCQ GATE CSE 2016 Set 2

Q4. The Floyd-Warshall algorithm for all-pairs shortest paths is based on which paradigm?

(A) Greedy
(B) Divide and conquer
(C) Dynamic programming
(D) Neither greedy nor divide-and-conquer nor dynamic programming

Answer: (C). The state is (i, j, k): the shortest i-to-j path using only vertices 1..k as intermediates. The table is filled for k = 0, 1, …, n, and each entry reuses the entry for k−1.

Why the others fail: (A) is the trap, because Dijkstra is greedy and the two are taught together — but Floyd-Warshall never commits to a locally best edge. (B) does not apply: the subproblems overlap heavily, since every k reuses the whole matrix. Trap: name the state before naming the paradigm.

MCQ GATE CSE 2015 Set 1

Q5. Match: (P) Prim's MST, (Q) Floyd-Warshall, (R) mergesort, (S) Hamiltonian circuit, against (i) backtracking, (ii) greedy, (iii) dynamic programming, (iv) divide and conquer.

(A) P-ii, Q-iii, R-iv, S-i
(B) P-ii, Q-iv, R-iii, S-i
(C) P-i, Q-iii, R-iv, S-ii
(D) P-iii, Q-ii, R-iv, S-i

Answer: (A). Prim's grows a tree by taking the lightest crossing edge — greedy. Floyd-Warshall fills a table over intermediates — DP. Mergesort splits into disjoint halves and merges — divide and conquer. The Hamiltonian circuit search tries an edge, recurses, and undoes the choice on failure — backtracking.

Why the others fail: (B) and (D) swap DP and divide-and-conquer, which the overlap test settles: Floyd-Warshall's subproblems repeat, mergesort's do not. (C) makes Prim backtracking, which it never does. Trap: this question is answerable in ten seconds from two properties, without knowing any of the four algorithms in detail.

NAT Original

Q6. Matrices with dimensions 40×20, 20×30, 30×10 and 10×30 are multiplied in the cheapest order. The minimum number of scalar multiplications is ______.

Answer: 26000. Length-2 intervals cost 24000, 6000 and 3000. Length-3 intervals cost 26000 and 9000. The full interval costs 26000.

Cross-check: the page enumerates all five parenthesisations of four matrices and confirms 26000 is the smallest. Multiplying left to right costs 40·20·30 + 40·30·10 + 40·10·30 = 24000 + 12000 + 12000 = 48000, so the saving is real. Trap: the table must be filled by increasing interval length; a row-major sweep reads unwritten cells.

MCQ Original

Q7. A 0/1 knapsack is solved with a single array dp[0..W] instead of a full table. Which loop direction is correct, and what goes wrong otherwise?

(A) Ascending; descending would read stale values and undercount.
(B) Descending; ascending reuses the current item and solves the unbounded problem instead.
(C) Either; the two orders give the same array.
(D) Neither; 0/1 knapsack cannot be solved with one row.

Answer: (B). Descending capacity means the cell dp[c−w] is read before it is written in this item's pass, so it still holds the previous item's value — exactly the two-row recurrence.

Why the others fail: (A) is backwards. (C) is refuted by items (2,3) and (5,6) at capacity 6: descending gives 6, ascending gives 9, which takes the weight-2 item three times. (D) is false — one row is enough, because a row reads only the row above. Trap: the same ascending loop is correct for unbounded knapsack, so the direction encodes which problem you are solving.

MSQ GATE CSE 2011

Q8. An algorithm computes L[i], the length of the longest monotonically increasing sequence starting at index i, using L[i] = 1 + L[i+1] when A[i] < A[i+1] and 1 otherwise, with L[n−1] = 1, and reports the maximum of L. Which statements are true? (The paper asked for one; here treat it as multiple-select.)

(A) The algorithm uses the dynamic programming paradigm.
(B) The algorithm runs in linear time.
(C) The algorithm uses branch and bound.
(D) The algorithm uses divide and conquer.

Answer: (A) and (B). Each L[i] is stored and then reused by the next index, which is the dynamic-programming pattern, and the single right-to-left pass is linear. The paper's keyed answer was (A).

Why the others fail: branch and bound requires branching over candidate solutions and pruning, which never happens here; divide and conquer requires disjoint subproblems and a merge step, which also never happens. Community observation GateOverflow discussion notes that the printed recurrence tracks a contiguous increasing run rather than a subsequence, so the question tests paradigm recognition rather than the definition of a subsequence. Trap: the real LIS recurrence needs a maximum over all later indices, not only i+1.

MSQ Original

Q9. Which of the following are true of dynamic programming as used in GATE questions?

(A) Optimal substructure alone is enough to justify a DP formulation.
(B) The running time is the number of states times the work per state.
(C) Any valid fill order is a topological order of the state-dependency graph.
(D) Memoisation and tabulation must produce the same table values for the same recurrence.

Answer: (B), (C), (D). (B) is the cost model used throughout this lesson. (C) is the reason an interval table needs a length sweep while a prefix table does not. (D) holds because both compute the same recurrence; a disagreement means a wrong base case or a wrong order.

Why (A) fails: merge sort has optimal substructure and no overlap, so a table buys nothing; and the general longest-simple-path problem has neither. Overlap is the second required property, and the greedy-choice property is the extra one greedy needs. Trap: (A) is the most commonly believed false statement in this topic.

Definitions in one line each

State — the tuple that pins down one subproblem.

Transition — the state written in terms of smaller states.

Base case — the smallest state, answered directly.

Fill order — a topological order of the state-dependency graph.

Memoisation / tabulation — the same table, filled from the top or from the bottom.

The recurrences to know

0/1 knapsack: K(i,c) = max(K(i−1,c), vi+K(i−1,c−wi))
unbounded: K(i,c) = max(K(i−1,c), vi+K(i,c−wi))
LCS: L(i,j) = 1+L(i−1,j−1) if equal, else max(L(i−1,j),L(i,j−1))
edit distance: 1 + min(diag, up, left) on a mismatch
matrix chain: M(i,j) = min over k of M(i,k)+M(k+1,j)+pi−1pkpj
LIS: L(i) = 1 + max over j>i with A[j]>A[i] of L(j)
Floyd-Warshall: Dk(i,j) = min(Dk−1(i,j), Dk−1(i,k)+Dk−1(k,j))
coin change: dp[v] = 1 + min over c≤v of dp[v−c]

Costs and states

0/1 knapsack — state (i, c), O(nW) time, O(nW) or O(W) space.

LCS — state (i, j), O(mn) time, O(mn) or O(min(m,n)) space.

Matrix chain — state (i, j), O(n³) time, O(n²) space.

LIS — state i, O(n²) time by DP; O(n log n) exists for the length only.

Floyd-Warshall — state (i, j, k), O(n³) time, O(n²) space with in-place updates.

Traps, ranked by how often they cost marks

  1. Quoting a complexity without naming the state.
  2. Filling an interval table row-major instead of by length.
  3. Ascending capacity in a one-row 0/1 knapsack.
  4. Reading a middle table cell instead of the corner.
  5. Counting index mappings where the question asked for distinct strings.
  6. Saying "DP" for Floyd-Warshall's cousin Dijkstra, or "greedy" for Floyd-Warshall.
  7. Calling a table of brute-force answers "dynamic programming".

Decision procedure for a new problem

Ask: does an optimal solution contain optimal subproblem solutions? If no, no DP. If yes, do the subproblems repeat? If no, divide and conquer. If yes, is there a provably safe local choice? If yes, greedy is cheaper; if no, DP. Then name the state, write the transition and base case, choose the order, and cost it as states times work.

Ten-second self-test

1. Why is fib(6) 25 calls but 7 states?

2. Why can LCS be filled row-major but matrix chain cannot?

3. What is the state for Floyd-Warshall, and why must k be outermost?

4. Which single index changes between 0/1 and unbounded knapsack?

5. Why is O(nW) called pseudo-polynomial?
