Topic and objective

TOPIC: Asymptotic complexity and recurrences — the five notations, the growth ladder, the ratio test, best/average/worst case, the recursion tree, and the master theorem with its gap.

LEARNING OBJECTIVE: Given a comparison of two functions, decide whether it is an upper bound, a lower bound or both, and prove it with witnesses rather than with a table of values. Given a recurrence from a divide-and-conquer algorithm, get its growth rate by adding level costs, and know when the master theorem is silent. Given a code fragment, count the operations and say which of time, space, or operation count was asked for.

I read this topic as one skill — comparing growth rates — applied three times: to two functions, to a recurrence, and to a program. Recurrence solving by characteristic roots and generating functions lives in the Recurrence Relations lesson; this lesson uses recurrences as cost models and does not re-teach their algebra.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 5 of the official GATE 2027 CS syllabus (IIT Madras) reads: "Searching, sorting, hashing. Asymptotic worst case time and space complexity. Algorithm design techniques: greedy, dynamic programming and divide-and-conquer. Graph traversals, minimum spanning trees, shortest paths."

The phrase asymptotic worst case time and space complexity is the whole of this lesson, and it is the second sentence of the Algorithms section. Note what it names: worst case, and both time and space.

Class A means a question here is inside the declared boundary. It does not mean one is guaranteed, and it says nothing about how many marks. The previous-year questions quoted in this lesson are observations about old papers, not a forecast.

Prerequisites

Four published lessons carry the machinery this one uses:

  • Recurrence Relations — unrolling, the characteristic equation, the recursion tree and the three master-theorem cases with the gap. Scene 8 is the cost-model side of that lesson, not a repeat of it.
  • Trees, BSTs and Heaps — the height of a tree is a logarithm, and a heap's two operations are the standard examples of log n work.
  • Arrays, Stacks and Queues — index arithmetic and the loop-counting style that scene 7 and the practice set use.
  • Counting and Combinatorics — sums and products of counts, which is what a cost function is.

The only mathematics assumed beyond that is the logarithm: log base 2 of n is the number of times you can halve n before reaching 1. If that sentence is unfamiliar, read it twice — every logarithm in this lesson is that one.

What you should be able to do afterwards

Answer any complexity question in this order: which bound is asked for?, is every exponent constant?, which quantity and whose?, which assumption was given?

The most expensive mistake in this topic is answering an ordering question by looking at the functions. Order them by a proof — the ratio, the log trick, or the ladder — because a table of values ranks functions by the n you happened to print.

Level 1 — Intuition: the two delivery vans

A running time is a rate, not a duration. Two vans deliver parcels on the same route. Van A makes one stop for every parcel; van B makes a stop for every pair of parcels. For three parcels, A stops three times and B stops six — B is not much worse. For a thousand parcels, A stops a thousand times and B stops about half a million times. The interesting fact is not which van is quicker today; it is that the second van's work explodes as the load grows.

Constants are the vans, growth is the route. Van A might be a slow van that takes twice as long per stop. That doubles its time and changes nothing about the shape. Asymptotic notation keeps the shape and discards the van, the driver and the fuel price — which is exactly what survives when the input grows.

Educational interpretation The van is a good picture of a constant factor and a poor one of memory: two algorithms can have the same growth rate and differ by a factor of a hundred in practice. Asymptotics is a filter, not a benchmark.

Level 2 — The five definitions, symbol by symbol

All five assume f and g are functions from positive integers to non-negative reals — that is, f(n) is a count of something and g(n) is eventually positive.

f(n) = O(g(n)) there exist c > 0 and n₀ such that f(n) ≤ c·g(n) for every n ≥ n₀ — g is an eventual ceiling, up to a constant
f(n) = Ω(g(n)) there exist c > 0 and n₀ such that f(n) ≥ c·g(n) for every n ≥ n₀ — g is an eventual floor, up to a constant
f(n) = Θ(g(n)) both of the above at once: c₁·g(n) ≤ f(n) ≤ c₂·g(n) past some n₀ — the two bounds differ only by a constant
f(n) = o(g(n)) f is O(g) but not Ω(g): for every c > 0 there is an n₀ with f(n) < c·g(n) beyond it — the ceiling can be squeezed to nothing
f(n) = ω(g(n)) g is o(f): f outgrows every constant multiple of g — the mirror of little-o

Mathematical derivation Θ is exactly O ∩ Ω, because "both inequalities with constants" is literally the conjunction of the two definitions. The lesson's checks verify this identity on seven pairs, and verify that O, Ω and Θ agree with a witness search.

The one sentence that prevents most errors

O is not "about", and it is not "equals". The notation f(n) = O(g(n)) is a claim that a certain inequality holds eventually, and the "=" is a convention that is not symmetric: n = O(n²) is true and n² = O(n) is false. Writing O(g(n)) = f(n) is meaningless, and treating the two sides as interchangeable is the single most common way to lose a mark on an option that says "f(n) = O(g(n)) therefore g(n) = Ω(f(n))" — which happens to be the one true implication, but only because Ω is defined as the mirror.

Read every occurrence as: "f is a member of the set of functions that g bounds". That reading makes O(n) a set, and f ∈ O(n) a membership claim, and both facts follow: membership is not equality, and the relation is not symmetric.

Level 3 — Visual understanding: what each notation looks like

Draw g once, in grey. Then:

  • O — draw a copy of g scaled up by some constant. f must stay under it from some point onward, and may cross it any number of times before that point.
  • Ω — draw a copy scaled down. f must stay above it eventually.
  • Θ — draw both. f must be trapped between them eventually.
  • o — f must fall below every scaled copy of g, however small the scaling. No ceiling survives.
  • ω — f must rise above every scaled copy, however large.

Mathematical derivation The little-o picture is why o is strict: O asks for one ceiling, o asks that no ceiling exist. Since n/n = 1, no scaling of n gets below n, so n is not o(n). Since n/n² = 1/n falls to zero, n is o(n²).

Level 4 — Worked example: find the witnesses

Claim. 3n² + 5n + 2 is O(n²).

Work. We need 3n² + 5n + 2 ≤ c·n² for all large n. Try c = 4: the inequality becomes 3n² + 5n + 2 ≤ 4n², that is n² − 5n − 2 ≥ 0. The quadratic n² − 5n − 2 has its positive root at (5 + √33)/2 ≈ 5.37, so the inequality first holds at the integer n = 6 and stays true after that, because the left side is increasing.

Witness. c = 4, n₀ = 6. That pair, plus the sentence "and it stays true after", is a complete proof.

Same claim by the ratio. f(n)/g(n) = 3 + 5/n + 2/n², which tends to 3. A limit that is finite and positive is Θ, and Θ implies O. Both routes are acceptable; the ratio is faster when the algebra is easy.

Level 4 — Worked example: order three functions

Claim. Put 10ⁿ, n^(log n) and n^(√n) in increasing order of growth.

Work. Powers of n are compared by their exponents, and exponentials are compared by taking logarithms. Take log base 2 of each:

  • log(10ⁿ) = n·log 10, which is Θ(n).
  • log(n^(log n)) = (log n)·(log n) = (log n)².
  • log(n^(√n)) = √n · log n.

Now compare the three logarithms: (log n)² < √n·log n < n. The first inequality is the claim that log n < √n, true for every n ≥ 1 with equality only at n = 1; the second is that √n·log n < n, i.e. log n < √n again.

Answer. n^(log n) < n^(√n) < 10ⁿ. This is GATE CSE 2021 Set 1, question 3, and the answer there is the same order.

Level 4 — Worked example: a recurrence by level sums

Claim. T(n) = 2T(n/2) + n, with T(1) = 1, is Θ(n log n).

Work. At depth i there are 2ⁱ subproblems, each of size n/2ⁱ, and the work done at that depth (the "+n" of each of those subproblems) is 2ⁱ · n/2ⁱ = n. So every depth costs n. The depths run from 0 to log₂ n, which is log₂ n + 1 depths, so the total is n(log₂ n + 1).

Check against small cases. T(2) = 4, T(4) = 12, T(8) = 32, T(16) = 80, and n(log₂ n + 1) gives 4, 12, 32, 80 exactly. The page computes this identity for every power of two up to 2²⁰.

Mathematical derivation The exact solution is n log₂ n + n; the +n is absorbed, so the class is Θ(n log n). Note that the leaf level is a level, and dropping it is what produces the wrong "n log n − n" or "3 levels for n = 8" answers.

Level 4 — Worked example: a split that does not halve

Claim. T(n) = T(n/2) + T(2n/5) + 7n is Θ(n).

Work. The two subproblem sizes add to n/2 + 2n/5 = 9n/10, which is less than n. Draw the tree: the root costs 7n, and the total size at depth i is (9/10)ⁱ n, so the work at depth i is 7·(9/10)ⁱ·n. Summing a geometric series with ratio 9/10 gives 7n · 10 = 70n.

Rule. When the subproblem sizes sum to a fraction α < 1 of n and the per-node cost is linear, the total is Θ(n) with constant 1/(1−α). This is GATE CSE 2021 Set 1, and the answer there is Θ(n). The same argument with α = 1 is exactly why the halving case needs a logarithm instead.

Level 5 — Boundaries: when each tool is allowed

A tool used outside its conditions is a guess. The conditions, in the order they bite:

  • Positive functions. All five notations assume g(n) > 0 for large n, because a bound is a multiplicative comparison and multiplying by zero destroys it. f(n) = 0 for all n is O(g) for any positive g, and is Θ(g) for none.
  • The ratio test needs a limit. If f/g has no limit — oscillating, or visiting zero and infinity — the three outcomes do not apply and only the definitions decide.
  • The ladder needs constant exponents. n^(1+sin n) is not on the ladder, and no rearrangement of the ladder will place it.
  • The master theorem needs the polynomial gap. It compares f(n) with n^(log_b a) and requires a polynomial separation; a factor of log n between them is not enough.
  • An average needs a distribution. Without one, "average case" is not a function of n at all.

Mathematical derivation The master-theorem condition is a real restriction, not a formality: T(n) = 2T(n/2) + n/log n is Θ(n log log n), and no case of the theorem produces that.

Level 6 — Counterexample: order is not total

The claim being killed. "For any two functions, one is O of the other."

The counterexample. f(n) = n and g(n) = n^(1+sin n). The exponent swings between 0 and 2, so g is sometimes as small as 1 and sometimes as large as n², for arbitrarily large n.

Why f is not O(g). The ratio f/g = n^(−sin n) reaches about n whenever sin n ≈ −1, so no constant c survives. Why g is not O(f). The same ratio falls to about 1/n whenever sin n ≈ +1, so no constant c·f bounds g.

The correct rule. Asymptotic order is a partial order on functions. Any option of the form "one of these must be O of the other" is false without further hypotheses. The page's sweep over n ≤ 4·10⁵ finds the ratio above 10³ and below 10⁻⁶, which is the numeric shadow of the proof that uses the equidistribution of n modulo 2π.

Level 6 — Counterexample: the average is not the midpoint

The claim being killed. "Average case = (best + worst)/2."

The counterexample. Linear search on n cells where the key is present with probability 1/2 in the first cell and with probability 1/(2(n−1)) in each of the others. The best case is 1, the worst is n, so the midpoint is (n+1)/2 — but the average is about 1/2 · 1 + 1/2 · (n+1)/2, which for n = 100 is about 26, not 50.5.

The correct rule. The average is the weighted mean of the per-input costs under the stated distribution. What is always true is only the inequality best ≤ average ≤ worst, and the page verifies that inequality for two hundred random distributions.

Level 6 — Edge cases worth naming

Four that change an answer rather than decorate it:

  • n = 1 and n = 2. At n = 2, n² = 4 and n log n = 2, so a small test case ranks them opposite to the asymptotics. Any conclusion drawn from small n is a conjecture.
  • A constant that beats a logarithm. n log n is not O(n), but a table of values at n ≤ 10⁶ shows log₂ n ≤ 20, so c = 32 appears to work. The constant must exceed log of every n you will run, which is why "log n is bounded by a constant" is the quietest false statement in the topic.
  • Loose but true. n² is O(n³) and also O(n²). An option is wrong when it is false, not when it is loose.
  • Space conventions. Merge sort is Θ(n) auxiliary and Θ(n log n) total if you count the input. Say which convention you are using, because the options usually pick one.

Community observation The two that learners report losing marks on most often are the log-versus-constant one and the loose-but-true one; both are cheap to check and both are checked in the practice set.

Example 1 — Witnesses for a lower bound

Claim. n² is not O(n), and n² is Ω(n²).

Not O(n). Suppose c and n₀ worked. Then n² ≤ c·n for every n ≥ n₀, so n ≤ c for every n ≥ n₀. Taking n larger than both c and n₀ gives a contradiction, so no pair exists. A single counterexample is enough: any n > max(c, n₀).

Ω(n²). Take c = 1 and n₀ = 1: n² ≥ 1·n² holds everywhere.

The shape of the argument. To prove a bound, produce the pair. To refute one, show that the inequality fails for arbitrarily large n — which usually means showing the ratio grows without bound.

Example 2 — The constant does not survive, the degree does

Claims. 100n is Θ(n). 100n² is not Θ(n). n/100 is Θ(n).

100n is Θ(n). With c₁ = 100, c₂ = 100 and n₀ = 1, the two inequalities 100n ≤ 100n and 100n ≥ 100n both hold. A constant multiplier is a choice of c, so it never changes the class.

n/100 is Θ(n). c₁ = 1/100, c₂ = 1/100. Dividing by a constant is multiplying by another one.

100n² is not Θ(n). The ratio 100n grows, so no constant ceiling exists. What decides the class is the exponent, never the coefficient. This is why every answer to "what is the complexity of this loop" is written without the leading constant.

Example 3 — A recurrence with unequal splits

Claim. T(n) = T(n/3) + T(2n/3) + n is Θ(n log n).

Why the fraction sum matters. Here 1/3 + 2/3 = 1, so the sizes are not shrinking in total — this is the boundary case. At depth i the total subproblem size is exactly n, so the work per depth is n.

How deep. The shortest path to a leaf divides by 3 each time, giving log₃ n; the longest divides by 3/2, giving log_{1.5} n. Both are constant multiples of log₂ n, so the number of depths is Θ(log n).

Answer. n work per depth for Θ(log n) depths is Θ(n log n). Note the technique: for unequal splits, the depth is bounded between the shortest and longest root-to-leaf paths, and a constant factor between them is enough.

Example 4 — Change of variable: T(n) = 2T(√n) + 1

Claim. T(n) = 2T(√n) + 1, with T(n) = 2 for n ≤ 2, is Θ(log n).

Step 1 — substitute the exponent. Put n = 2^m and S(m) = T(2^m). Then √n = 2^(m/2), so the recurrence becomes

S(m) = 2·S(m/2) + 1 the same shape, with the exponent as the variable: a halving split, two subproblems, constant work per node

Step 2 — solve S. Here a = 2, b = 2 and f(m) = m⁰, so a > b^k. The master theorem's third case gives S(m) = Θ(m^(log₂ 2)) = Θ(m). By levels: the tree has 1 + 2 + 4 + … + 2^(log₂ m) = Θ(m) nodes, each costing a constant.

Step 3 — substitute back. m = log₂ n, so T(n) = S(log₂ n) = Θ(log n).

Check the numbers. T(2) = 2, T(4) = 5, T(16) = 11, T(256) = 23, T(65536) = 47. Each value is 3·(log₂ n) − 1: at n = 65536, log₂ n = 16 and 3·16 − 1 = 47. A linear function of log n, which is what Θ(log n) says. The page checks this identity at every n = 2^(2^k) up to a large bound.

Example 4, done properly

Claim. T(n) = 2T(√n) + 1, with T(2) = 2, is Θ(log n).

Substitute m = log₂ n. Then n = 2^m and √n = 2^(m/2), so with S(m) = T(2^m):

S(m) = 2·S(m/2) + 1 the same recurrence with the exponent as the variable — a halving split, a doubling of subproblems, and constant work per node

Solve S. Here a = 2, b = 2 and f(m) = m⁰, so a > b^k and the master theorem gives S(m) = Θ(m^(log₂ 2)) = Θ(m). Equivalently, the recursion tree has m leaves' worth of nodes: 1 + 2 + 4 + … + 2^(log₂ m) = Θ(m).

Back-substitute. m = log₂ n, so T(n) = Θ(log n). The lesson's checks do not test this recurrence, so treat the algebra above as the argument and verify it on small cases yourself: T(4) = 2·T(2) + 1 = 5, T(16) = 2·5 + 1 = 11, T(256) = 2·11 + 1 = 23, and log₂ of those is 2, 4, 8 — the doubling of the log matches the doubling of the value, so T is linear in log n.

Example 4b — the coefficient in front is not decoration

Two recurrences that look alike.

T₁(n) = T₁(√n) + 1 → Θ(log log n) one subproblem per level, so the cost is the number of levels, and the levels halve the logarithm
T₂(n) = 2·T₂(√n) + 1 → Θ(log n) two subproblems per level, so the node count doubles as the level count grows, and the two effects balance into a linear function of log n

Why. In T₁ every level has one node, so only the depth matters: n → √n → n^(1/4) → … reaches a constant after log log n steps. In T₂ the number of nodes doubles at every level, so level i has 2ⁱ nodes: the total is the number of nodes, not the number of levels.

The rule this kills. "A recurrence with √n in it is Θ(log log n)." The √n decides the number of levels; the coefficient decides whether the node count or the level count is the answer. Change the 2 to a 1 and the answer changes from log n to log log n.

Example 5 — Counting a nested loop

The fragment.

while (n > 1) { for (i = 1; i <= n; i++) x++; n = floor(n/2); } the inner loop runs n times, then n/2, then n/4, and so on, while the outer variable is halved

Count. The total is n + n/2 + n/4 + … < 2n, a geometric series with ratio 1/2. So the count is Θ(n).

Compare. A second fragment for (i = 1; i <= 100*n; i++) x++; does exactly 100n iterations, also Θ(n). So the two counts are Θ of each other. This is GATE CSE 2023, an MSQ, where the true statements are that the two counts are Θ of each other and that the first is O(n).

Example 6 — Three cases, counted

The algorithm. Linear search over n cells, comparing cell by cell until the key is found.

  • Best. The key is in the first cell: 1 comparison. As a function of n this is the constant 1.
  • Worst. The key is in the last cell, or absent: n comparisons.
  • Average. If the key is equally likely to be in each of the n positions, the cost is the mean of 1, 2, …, n, which is (n+1)/2.

All three are Θ(n) except the best case, which is Θ(1). The distinction only changes the class when the best and worst differ in order — as in quicksort, where the best is Θ(n log n) and the worst is Θ(n²).

The page verifies best = 1, worst = n and average = (n+1)/2 exhaustively for every n from 1 to 60, and verifies the general inequality best ≤ average ≤ worst on two hundred random distributions.

Example 7 — Space, three ways

Merge sort. Time Θ(n log n). Auxiliary space Θ(n) for the merge buffer. Stack Θ(log n) frames, because the call tree is log₂ n deep. If you count the input, total space is Θ(n) as well.

Quicksort. Time Θ(n log n) average, Θ(n²) worst. Auxiliary space Θ(log n) on average for the recursion stack, Θ(n) worst if the splits are maximally uneven and the recursion is not tail-eliminated.

Heapsort. Time Θ(n log n) always. Auxiliary space Θ(1): it permutes inside the given array, keeping a few indices.

Read the question. "In place" means Θ(1) auxiliary, so heapsort qualifies and merge sort does not, even though both are Θ(n log n) in time. A question offering both as options is testing exactly this.

Example 8 — From a function to a class, four times

Given f(n) = 4n² + 3n log n + 7, state O, Ω, Θ and whether it is o(n³).

  • Θ(n²). The dominant term is 4n²; the others are lower order. Witnesses: c₁ = 4 and c₂ = 5 work from some n₀ onward, since 4n² ≤ f(n) and f(n) ≤ 5n² for all large n.
  • O(n²) follows, and so does O(n³).
  • Ω(n²) follows from Θ.
  • o(n³)? Yes: the ratio f/n³ ≈ 4/n falls to zero, so f is little-o of n³ as well as O of it.

The lesson. One function has infinitely many true O statements. An option is wrong only if it is false, so a question that lists several bounds usually has more than one true one — which is why such questions are MSQs.

Example 9 — The gap, worked

Claim. T(n) = 2T(n/2) + n/log₂ n is Θ(n log log n).

Why no case applies. Here a = 2, b = 2, so n^(log_b a) = n. The driving term is n/log n. Is it polynomially smaller than n? It would need n/log n = O(n^(1−ε)) for some ε > 0, which is false for every ε. Is it Θ(n)? No. So cases 1 and 2 both fail, and case 3 fails too.

Do it by levels. At depth i the work is 2ⁱ · (n/2ⁱ)/log(n/2ⁱ) = n/(log n − i). Summing over i from 0 to log n − 1 gives n · (1/log n + 1/(log n − 1) + … + 1/1) = n·H_{log n}, and the harmonic sum H_m is Θ(log m).

Answer. n log log n. The page verifies that T/(n log log n) stays inside a narrow band for n = 2⁶ to 2¹⁸, which is what Θ means numerically.

Example 10 — Two functions that share a class

Claim. log₂ n, log₁₀ n and ln n are all Θ of each other.

Work. Change of base: log_a n = log_b n / log_b a. So log₂ n = log₁₀ n / log₁₀ 2 = 3.3219… · log₁₀ n. The ratio of any two is a constant, so each is Θ of the others.

Consequence for questions. When a question gives functions in different bases, the base is noise; when it gives log n and log² n, the power is the signal.

The page checks that the ratio log₂ n / log₁₀ n equals 3.321928094887362 for every n it samples, to twelve decimal places.

Crossing back is fatal

The condition. O requires the inequality to hold for every n ≥ n₀, not for most of them and not on average.

The counterexample. f(n) = n + 10·sin²(n) and g(n) = n. Take c = 11 and n₀ = 1: f(n) ≤ 11n holds everywhere, so f is O(n). Now try to prove f is O(n/2) with the same reasoning from a sample: f(n) ≤ c·n/2 fails whenever sin² n is near 1, for ever.

Rule. A bound proved from a finite table is a conjecture. The proof must be an argument about all n, and a single infinite family of violations kills it.

g must be positive, and f non-negative

The definitions are multiplicative, so a zero destroys them. If g(n) = 0 for arbitrarily large n, then c·g(n) = 0 and the only function that is O(g) is one that is eventually 0.

The usual convention in this syllabus is that both f and g map positive integers to non-negative reals, and that g is eventually positive. Under that convention every statement in this lesson is well formed.

Why it matters in an exam. A question that offers "f(n) = 1/n is O(1)" is fine, because 1/n is positive for positive n and bounded by 1. A question that offers a function which is zero infinitely often is testing whether you noticed.

Small n reverses the ladder

At n = 2: n² = 4, n log₂ n = 2, n = 2, √n ≈ 1.41, log₂ n = 1. The order is n log n = n = n² > √n > log n — nothing like the asymptotic order, and two of them are equal.

At n = 4: n² = 16, n log n = 8, n = 4, √n = 2, log n = 2. Still n² < 2^n only barely, and 2^n = 16 ties with n².

Rule. Asymptotics is a statement about the tail. If a question gives you n = 10 and asks which function is largest, it is not asking an asymptotic question, and answering with the ladder may be wrong.

The master theorem's gap is real

The claim being killed. "Every recurrence of the form T(n) = aT(n/b) + f(n) is covered by one of the three cases."

The counterexample. a = 2, b = 2, f(n) = n/log₂ n. Then n^(log_b a) = n, and f is smaller than n but not polynomially smaller: for every ε > 0, n/log n is not O(n^(1−ε)). So case 1 fails, case 2 fails because f is not Θ(n), and case 3 fails because f is not polynomially larger. The answer is Θ(n log log n).

Rule. Between the cases lies a band separated by logarithmic factors, and inside that band you must solve the recurrence yourself — by levels, as in Example 9.

Best case is not a bound on the algorithm

"Linear search is O(1)" is true of one input and false as a statement about the algorithm's worst case. The three cases are three different functions, and the syllabus asks for the worst one.

The same trap appears with average case: "quicksort is Θ(n log n)" is a statement about the average under a random pivot, and is false for the worst case.

Rule. Every complexity claim carries an implicit quantifier: for every input of size n (worst), for the best input (best), or in expectation over this distribution (average). Name it or the claim is incomplete.

What "space" includes is a convention

Three conventions are in use and questions pick one by their options:

  • Auxiliary space — memory used beyond the input. Merge sort Θ(n), heapsort Θ(1).
  • Total space — input plus auxiliary. Merge sort Θ(n) as well, because the input is Θ(n).
  • Stack space counted separately — recursion depth. Merge sort Θ(log n), quicksort Θ(log n) average and Θ(n) worst.

Rule. State the convention in your answer, and when an option's convention differs from yours, check whether it is the one the question intended. The number of frames is the depth, never the call count: merge sort makes 2n − 1 calls and needs log n frames.

“O means roughly equal to”

The belief. f(n) = O(g(n)) means f and g grow at about the same rate.

Why it tempts. Almost every O you meet in a textbook is also a Θ, so the two notations look interchangeable in examples.

Why it is wrong. O is one inequality. Θ is two. The difference is exactly the case where the upper bound is slack, and that case is what the exam asks about.

Minimal counterexample. n is O(n²) and n is not Θ(n²). One pair, one line.

The correct rule. O = ceiling, Ω = floor, Θ = both. Write Θ when you can and O when the ceiling is all you know or all that was asked.

Where it is exposed. Practice Q4 and Q10. On screen. Scene 3 shows the three panels side by side, and scene 4 shows why O does not imply Θ.

“Big-O is the worst case”

The belief. O always describes the worst-case running time, so "O(n²)" and "worst case n²" are the same statement.

Why it tempts. Most textbook sentences are of the form "the worst case is O(n²)", and the two words appear together so often that they fuse.

Why it is wrong. O is a kind of bound; worst case is a choice of which input to bound. They are independent: you can give an O bound on the best case, and a Θ bound on the worst case.

Minimal counterexample. Insertion sort's best case is O(n) and also O(n²). Both are true of the best case, so O is not carrying "worst" at all.

The correct rule. Name both: the case (best / average / worst) and the bound (O / Ω / Θ). "Worst case Θ(n²)" is a complete claim; "O(n²)" is half of one.

Where it is exposed. Practice Q11. On screen. Scene 7 separates the three cases and then applies one bound to each.

“One of any two functions must be O of the other”

The belief. For any f and g, either f = O(g) or g = O(f).

Why it tempts. Every pair in a textbook is comparable, because textbook functions are drawn from the ladder, and the ladder is totally ordered.

Why it is wrong. Comparability is a property of the pair, not a law. A function whose exponent oscillates leaves the ladder and need not be comparable with anything on it.

Minimal counterexample. f(n) = n and g(n) = n^(1+sin n): neither is O of the other. This is GATE CSE 2015 Set 3.

The correct rule. Asymptotic order is a partial order. Before ranking functions, check that every exponent is constant; if not, fall back on the definitions and be ready for "neither".

Where it is exposed. Practice Q8. On screen. Scene 6 plots the pair and shows the ratio leaving every constant in both directions.

“n! is O(2ⁿ), because both are exponential”

The belief. Factorial and exponential are both "very fast", so they are in the same class.

Why it tempts. Both beat every polynomial, and both appear in the same breath in informal discussion.

Why it is wrong. n! has n factors, and most of them are larger than 2. Formally, log(n!) ≈ n log n − 1.44n, which grows faster than n, so n! outgrows every exponential.

Minimal counterexample. At n = 20: 2²⁰ ≈ 1.05×10⁶ while 20! ≈ 2.43×10¹⁸. A factor of 10¹² at n = 20, and the gap widens.

The correct rule. 2ⁿ is o(n!). On the ladder, n! is the top rung, above every exponential. GATE CSE 2008 asks exactly this, with 2ⁿ, n! and n^(log n).

Where it is exposed. Practice Q3. On screen. Scene 5 draws n! above 2ⁿ on log-log axes, and the ladder check confirms each rung is little-o of the next.

“The average case is halfway between best and worst”

The belief. Average = (best + worst)/2, so the average of linear search is (1 + n)/2.

Why it tempts. For uniform linear search the average is (n+1)/2, so the formula matches the one example everyone works.

Why it is wrong. The average is a weighted mean under a distribution. Uniformity is an assumption, and a different assumption gives a different number — sometimes far from the midpoint.

Minimal counterexample. If the key sits in the first cell with probability 1/2 and uniformly in the rest otherwise, the average is about 1/2 + (n+1)/4, which is roughly half the midpoint.

The correct rule. Quote the distribution with the average, or quote only the worst case. The one unconditional fact is best ≤ average ≤ worst.

Where it is exposed. Practice Q7. On screen. Scene 7 states the uniform assumption explicitly before using it.

“A plot settles a comparison”

The belief. If f(n) is above g(n) for every n up to a million, then f grows faster.

Why it tempts. Plotting is how everyone builds intuition, and it is usually right.

Why it is wrong. The definition is about all n, and the interesting cases turn over later than any table. log n beats every fixed constant only when n exceeds 2^constant.

Minimal counterexample. n log n against n^1.01. Their ratio is log n / n^0.01, still rising at n = 10¹², and it turns over only past n = e¹⁰⁰ ≈ 2.7×10⁴³. Yet n log n is O(n^1.01).

The correct rule. Use the ratio, the log trick, or the ladder. A plot is evidence for a conjecture, never the proof.

Where it is exposed. Practice Q6. On screen. Scene 4 prints the derivative's turning point next to the ratio panel.

“Merge sort is O(n log n) space, because it does n log n work”

The belief. Space and time have the same answer, or space is the time with "log n" attached.

Why it tempts. The two are taught together and the time answer is the one people memorise.

Why it is wrong. Space counts cells, not steps. Merge sort allocates one buffer of n cells and one frame per level of recursion; neither count involves the number of merges.

Minimal counterexample. Merge sort: time Θ(n log n), auxiliary space Θ(n). Heapsort: time Θ(n log n), auxiliary space Θ(1). Same time, different space.

The correct rule. For space, count the largest number of cells live at any one moment — for a recursion, that is the depth, not the number of calls.

Where it is exposed. Practice Q12. On screen. Scene 9 contrasts the 31 calls of a 16-element merge sort with the 5 live frames.

The pattern behind all seven

Each wrong belief is a true statement in a narrower setting, promoted to a rule. O ≈ Θ is true for every function on the ladder. One of two functions is always comparable when both are on the ladder. A plot settles a comparison between n² and n³. The average is the midpoint under a symmetric distribution. Time equals space for an algorithm with no buffer.

So the defence is not to memorise seven corrections. It is to ask, every time: which condition made this true, and does the question give it? That single habit is what the four questions in scene 10 are for.

Shape 1 — Order these functions

What it looks like. Three to five functions, "arrange in increasing order of asymptotic growth rate".

The reasoning it demands. Take logarithms of every function, then order the logarithms. Powers of n become exponents times log n; exponentials become n times a constant; factorials become n log n by Stirling. Once every function is a sum of terms in log n and n, the ladder decides.

The common wrong approach. Comparing the functions themselves. n^(log n) and n^(√n) look nearly identical until you compare log n with √n.

Seen in. GATE CSE 2017 Set 1, 2021 Set 1, 2026 Set 2. Scene 5 is the ladder this shape tests.

Shape 2 — Which of these statements is true

What it looks like. An MSQ with four statements about one pair of functions, or four separate claims each with its own hypothesis.

The reasoning it demands. Test each statement against its own quantifier and its own hypothesis. A statement that says "for all positive functions" is refuted by one function; a statement with a hypothesis is refuted only inside that hypothesis.

The common wrong approach. Checking the statements that look alike and guessing the rest. Each option is an independent one-line proof or one-line counterexample, and GATE 2022's f(n²) item turns entirely on the word "polynomial".

Seen in. GATE CSE 2022, 2023, 2015 Set 3. Misconceptions 1 and 3 are the beliefs this shape probes.

Shape 3 — Solve this recurrence

What it looks like. A recurrence with a base case, and four Θ options.

The reasoning it demands. First check whether the master theorem applies and which case. If a change of variable is needed (√n, n^(1/a)), do it and re-derive both the number of levels and the work per level. If neither works, use levels or unrolling.

The common wrong approach. Applying the master theorem to a recurrence whose driving term sits in the gap, or forgetting that a substitution changes the variable of the answer. GATE 2020's T(n) = T(n^(1/a)) + 1 needs the second substitution, not the master theorem.

Seen in. GATE CSE 2017 Set 2, 2020, 2021 Set 1, 2021 Set 2, 2024 Set 1, 2025 Set 1. Scene 8 and Examples 3, 4, 9.

Shape 4 — Complexity of this code fragment

What it looks like. A short C or pseudocode fragment with nested loops or recursion, asking for Θ or for the number of times a statement runs.

The reasoning it demands. Count the innermost statement exactly as a sum, then evaluate the sum. A loop bound that depends on the outer variable, or a variable that is halved each iteration, is the whole question.

The common wrong approach. Multiplying the outer bound by the inner bound without checking whether the inner bound depends on the outer index. GATE 2017 Set 2's for (j = 1; j < n; j += i) is harmonic, not n per outer step.

Seen in. GATE CSE 2017 Set 2, 2023, 2024 Set 1. Example 5.

Shape 5 — Best, average, worst

What it looks like. A statement about a named algorithm's three cases, or a table to match.

The reasoning it demands. Name the input that achieves each case, then bound that input. For the average, find the distribution in the stem before doing any arithmetic.

The common wrong approach. Treating the average as the midpoint, or assuming the best case bounds the algorithm.

Seen in. GATE CSE 2017 Set 2 (matching algorithms to complexities), 2024 Set 1 (the sorted-check item, whose answer is both O(N) and Ω(N)). Scene 7 and Misconception 5.

Shape 6 — Space

What it looks like. "The auxiliary space required is ___", or an option pair that differs only in the space answer.

The reasoning it demands. Decide the convention (auxiliary or total), then count the maximum simultaneously live cells. For recursion that is the depth; for a buffer it is the buffer size; for both, take the larger.

The common wrong approach. Reusing the time answer, or counting the number of calls instead of the depth.

Seen in. Any question pairing merge sort with heapsort. Scene 9 and Misconception 7.

Which question categories this topic uses

Covered here:

  • A — Direct definition. "Θ is the intersection of O and Ω" is a recall item.
  • B — Property verification. Decide whether a stated bound holds for a given pair.
  • C — Calculation. Solve a recurrence; count a loop; find a witness.
  • E — Counterexample reasoning. One function refutes "for all positive f".
  • G — Misconception trap. The loose-bound option, the average-as-midpoint option, the n! = O(2ⁿ) option.
  • H — Multi-step reasoning. Substitute, solve, substitute back, then read the class.

Not covered here: D — Construction appears only weakly (constructing a witness), because this topic asks you to verify bounds rather than to build structures. Nothing in the syllabus's asymptotic clause asks for a construction.

MCQEasyOriginal GATE-style

For f(n) = 3n² + 5n + 2, which of these is the tightest correct statement?

  1. f(n) = Θ(n)
  2. f(n) = Θ(n²)
  3. f(n) = o(n)
  4. f(n) = Ω(n³)

Answer: B — f(n) = Θ(n²)

The ratio f/n² = 3 + 5/n + 2/n² tends to 3, a finite positive constant, so f is Θ(n²). Equivalently, witnesses c₁ = 3 and c₂ = 4 both work past n = 6.

A fails because f/n = 3n + 5 grows. C fails because o(n) would require f/n → 0. D fails because f/n³ → 0, so f is O(n³) but never Ω(n³).

The page checks this pair with a witness search: it finds c = 4, n₀ = 6 for the upper bound, and finds no witness for f = O(n).

MCQEasyOriginal GATE-style

Which relation holds between 2^(n+1) and 2ⁿ?

  1. 2^(n+1) = Θ(2ⁿ)
  2. 2^(n+1) = o(2ⁿ)
  3. 2^(n+1) = ω(2ⁿ)
  4. They are not comparable

Answer: A — 2^(n+1) = Θ(2ⁿ)

2^(n+1) = 2·2ⁿ, so the ratio is exactly 2 for every n. A constant ratio means Θ, with c₁ = c₂ = 2 and n₀ = 1.

B would need the ratio to fall to 0. C would need it to grow without bound. D is false because a constant ratio makes them comparable.

The page verifies this pair with the witness search, and separately verifies that 2^(2n) is not O(2ⁿ), where the ratio is 2ⁿ and does grow.

MCQMediumOriginal GATE-style

Which of the following is not O(n log n)?

  1. n
  2. √n · log n
  3. n^1.01
  4. n · log log n

Answer: C — n^1.01

Compare ratios with n log n: A gives 1/log n → 0, so n is even o(n log n). B gives log n/√n → 0. D gives log log n/log n → 0. C gives n^0.01/log n, which grows without bound, so n^1.01 is not O(n log n).

Why C tempts. 1.01 looks like a constant multiplier's worth of difference from 1. It is not: any exponent above 1 beats n log n, because log n is smaller than any positive power of n.

This is the same fact as Example 4 in the Build-up, used in the other direction: n log n = O(n^1.01), and n^1.01 is not O(n log n).

MSQMediumOriginal GATE-style

Let f(n) = n log₂ n and g(n) = n^1.5. Which statements are true?

  1. f(n) = O(g(n))
  2. f(n) = o(g(n))
  3. f(n) = Ω(g(n))
  4. f(n) = Θ(g(n))

Answer: A and B

The ratio is n log n / n^1.5 = log n / √n, which tends to 0 because √n outgrows log n. A limit of 0 means little-o, and little-o implies big-O but not Θ.

C and D fail: Ω would need the ratio bounded below by a positive constant, and Θ needs both directions.

Both A and B being true is the point: little-o is the stronger statement, and an MSQ can have both as correct options. The page's ladder check confirms log n < √n on log-log axes, and its ratio test classifies this pair as "small".

MCQMediumPYQ · 2021 Set 1, Q3

Arrange f₁ = 10ⁿ, f₂ = n^(log n), f₃ = n^(√n) in increasing order of asymptotic growth rate.

  1. f₃, f₂, f₁
  2. f₂, f₁, f₃
  3. f₁, f₂, f₃
  4. f₂, f₃, f₁

Answer: D — f₂, f₃, f₁

Take log₂ of each: log f₁ = n·log 10 = Θ(n); log f₂ = (log n)²; log f₃ = √n·log n. Ordering the logarithms: (log n)² < √n·log n < n, because log n < √n. So f₂ < f₃ < f₁.

A reverses the first two. B places the exponential in the middle. C reads the exponents as if 10ⁿ were the smallest.

Verified fact Year, set, question number and answer were checked against two independent question sources. This is the same worked example as Example 2 in the Build-up.

MSQMediumPYQ · 2023

Function_1 is while (n > 1) { for (i = 1 to n) x++; n = ⌊n/2⌋; } and Function_2 is for (i = 1 to 100n) x++;. Let f₁(n) and f₂(n) count the executions of x++. Which are true?

  1. f₁(n) ∈ Θ(f₂(n))
  2. f₁(n) ∈ o(f₂(n))
  3. f₁(n) ∈ ω(f₂(n))
  4. f₁(n) ∈ O(n)

Answer: A and D

f₁(n) = n + n/2 + n/4 + … < 2n, a geometric series, so f₁ = Θ(n). f₂(n) = 100n = Θ(n). Two functions both Θ(n) are Θ of each other, and each is O(n).

B would need f₁/f₂ → 0, but the ratio is a constant. C would need it to grow.

Verified fact The year and the answer (A and D) were checked against two independent question sources. The pseudocode is paraphrased. Example 5 in the Examples tab works the same count.

MSQMediumOriginal GATE-style

Which statements about the three cases of an algorithm are always true?

  1. average(n) ≤ worst(n) for every n
  2. average(n) = (best(n) + worst(n))/2
  3. an average case is meaningless without a stated distribution
  4. average(n) ≥ best(n) for every n

Answer: A, C and D

The average is a weighted mean of the per-input costs, so it cannot leave the interval spanned by the smallest and largest of them. That gives A and D. C is true by definition: "average" is an expectation, and an expectation needs a distribution.

B is false. For linear search with the key in the first cell with probability 1/2 and uniform elsewhere, the average is about 1/2 + (n+1)/4, not (n+1)/2.

The page verifies A and D for two hundred random cost vectors with random weights, and verifies best = 1, worst = n, average = (n+1)/2 exhaustively for uniform linear search.

MCQHardPYQ · 2015 Set 3

Let f(n) = n and g(n) = n^(1+sin n) for positive integers n. Which of these hold? I. f(n) = O(g(n))   II. f(n) = Ω(g(n))

  1. Only I
  2. Only II
  3. Both I and II
  4. Neither I nor II

Answer: D — neither

The ratio f/g = n^(−sin n). When sin n ≈ +1 the ratio is about 1/n, so f is not Ω(g). When sin n ≈ −1 the ratio is about n, so f is not O(g). Both situations recur for arbitrarily large n, so neither constant survives.

Why C tempts. Many solvers note that the exponent lies between 0 and 2, conclude that g is "between 1 and n²", and then assert both bounds. Bounds need a single constant for all large n, and g's exponent is not fixed.

Verified fact Year, set and answer (neither) were checked against two independent question sources. The page's sweep over n ≤ 4·10⁵ finds the ratio above 10³ and below 10⁻⁶; the full proof uses the fact that multiples of 2π are spread evenly, so sin n comes arbitrarily close to both ±1.

NATMediumOriginal GATE-style

Let T(1) = 1 and T(n) = 2T(n/2) + n for n a power of two. What is T(8)?

Answer: 32

Unroll: T(2) = 2·1 + 2 = 4; T(4) = 2·4 + 4 = 12; T(8) = 2·12 + 8 = 32. Equivalently, n(log₂ n + 1) = 8·(3 + 1) = 32.

Common wrong answers. 24 comes from counting only the three internal levels (3 × 8) and dropping the leaf level. 40 comes from using n log n + n with log₂ 8 read as 4. 12 is T(4), from stopping one level early.

The page verifies T(n) = n(log₂ n + 1) exactly for every power of two from 2 to 2²⁰.

MCQHardOriginal GATE-style

Which statement about n log n and n^1.01 is true?

  1. n log n = o(n^1.01)
  2. n^1.01 = O(n log n)
  3. n log n = Θ(n^1.01)
  4. n log n = Ω(n^1.01)

Answer: A — n log n = o(n^1.01)

The ratio is log n / n^0.01. Its derivative has the sign of 1 − 0.01·ln n, so the ratio rises until n = e¹⁰⁰ ≈ 2.7×10⁴³ and falls to 0 after that. A ratio that tends to 0 means little-o.

B and D are false: they would need the ratio bounded away from 0. C needs a finite positive limit.

The trap. Any table of values a paper can print shows n log n larger at every n you can compute, so the naive reading is D. The page's check prints the derivative's turning point precisely to make the point that sampling cannot settle this.

MSQHardOriginal GATE-style

Which statements are true?

  1. the best case of insertion sort is O(n)
  2. the worst case of insertion sort is Ω(n²)
  3. an algorithm whose best case is Θ(1) has worst case Θ(1)
  4. if an algorithm is O(n²) then its worst case is n²

Answer: A and B

On an already sorted array, insertion sort makes n − 1 comparisons and no moves, so its best case is Θ(n), hence O(n). On a reversed array it does about n²/2 moves, so its worst case is Θ(n²), hence Ω(n²).

C confuses the cases: linear search has best case Θ(1) and worst case Θ(n). D confuses a bound with an equality — O(n²) allows the worst case to be n, n log n or n², and it allows the true class to be anything smaller.

Both wrong options are the two halves of Misconception 2: O is a kind of bound, worst case is a choice of input, and neither implies the other.

NATMediumOriginal GATE-style

Merge sort is run on 16 elements. What is the maximum number of activation records alive on the call stack at any one moment?

Answer: 5

The call tree has depth log₂ 16 = 4 below the root, and the root itself is one frame, so the deepest path holds 5 frames. The tree makes 2·16 − 1 = 31 calls in total, but they are not simultaneous.

Common wrong answers. 31 counts every call. 4 forgets the root frame. 16 confuses the input size with the depth.

The page computes the peak depth of a halving recursion for n = 2¹ to 2²⁰ and confirms it is always log₂ n + 1.

The five notations
O: f ≤ c·g eventually. Ω: f ≥ c·g eventually. Θ: both. o: O but not Ω, i.e. f/g → 0. ω: g/f → 0. All require g eventually positive.
The ratio test
f/g → 0 gives o; → c with 0 < c < ∞ gives Θ; → ∞ gives ω. If the limit does not exist, the test does not apply — go back to the two witnesses.
The log trick
To order functions, take log₂ of each. A power becomes exponent × log n; an exponential becomes n × constant; n! becomes Θ(n log n). The base of a log is a constant factor and never matters.
The ladder
log log n < log n < √n < n < n log n < n² < n³ < 2ⁿ < n!. Each is little-o of the next. Any polynomial loses to any exponential; any exponential loses to n!.
Absorbed, and not
Absorbed: a constant multiplier, the base of a logarithm, a lower-order term. Not absorbed: a factor of n, a factor of log n, an exponent that is not constant.
Recursion tree
Total = (work per level) × (number of levels). For T(n) = 2T(n/2) + n: n per level, log₂ n + 1 levels, total n(log₂ n + 1) = Θ(n log n). For a split whose sizes sum to αn with α < 1 and linear per-node cost: Θ(n).
Master theorem
With T(n) = aT(n/b) + n^k and c = log_b a: if k < c then Θ(n^c); if k = c then Θ(n^c log n); if k > c then Θ(n^k). Requires a polynomial gap — a factor of log n is not enough.
The gap
T(n) = 2T(n/2) + n/log n is Θ(n log log n). No case applies; solve by levels and use the harmonic sum.
Substitution
For T(n) = aT(√n) + f(n), put n = 2^m. T(n) = 2T(√n) + 1 becomes S(m) = 2S(m/2) + 1 = Θ(m), so T = Θ(log n). With a coefficient of 1 instead: Θ(log log n).
Three cases
Best, average and worst are three functions. Best ≤ average ≤ worst always; the average needs a distribution; the syllabus asks for the worst. Average = (best + worst)/2 is false in general.
Space
Count the maximum simultaneously live cells. Auxiliary excludes the input; total includes it. For recursion, that is the depth (log₂ n + 1 frames for a halving split), never the number of calls (2n − 1).
Traps, with the counterexample
Loose ≠ false: n = O(n²) is true. O ≠ Θ: n is O(n²) and not Θ(n²). Comparable is not guaranteed: n against n^(1+sin n). Plot ≠ proof: n log n against n^1.01. Factorial ≠ exponential: n! is ω(2ⁿ).

Six quick questions, answers inverted

1. Is 100n = Θ(n)? (yes)  ·  2. Is n² = O(n log n)? (no)  ·  3. Is log₃ n = Θ(log₂ n)? (yes)  ·  4. Is 2^(n+1) = Θ(2ⁿ)? (yes)  ·  5. Is T(n) = 2T(n/2) + n/log n covered by the master theorem? (no — it is in the gap, and is Θ(n log log n))  ·  6. Does merge sort need Θ(n log n) auxiliary space? (no — Θ(n) auxiliary, Θ(log n) stack)

The one habit. Before answering, name the bound and the case. Almost every wrong option is a true statement about a different bound, or about a different case.
