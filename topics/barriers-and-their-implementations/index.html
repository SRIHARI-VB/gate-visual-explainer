Topic and objective

TOPIC: Barriers — what one is, the arrival gate and the departure gate, the GATE CSE 2006 barrier and its defect, the four candidate repairs of its second question, the naive counter barrier, the sense-reversing barrier, and the two-phase semaphore barrier.

LEARNING OBJECTIVE: Given a barrier implementation, say whether it is correct for one invocation and whether it is correct for two; find the counter and the process that resets it; explain in one sentence why a fast process can push the counter past n; decide all four options of the 2006 repair question; and write down a barrier that survives repeated use, with the sense-reversing and the two-phase designs both available.

I read this as the waiting-and-releasing construct, the third of the synchronisation primitives after the semaphore and the monitor: the prerequisite lessons build exclusion and the classical problems, and this one owns the barrier, its two gates, and the counting questions that come with them.

The five ideas

1. A barrier has an arrival gate and a departure gate; only the second is hard.

2. The spin must be outside the critical section, so the value it reads is unprotected.

3. Resetting the counter to a constant reuses a value, so a late reader sees the wrong round.

4. Sense reversal flips a flag, so two rounds never look alike.

5. Two phases count up and then down, so nothing is ever reset at all.

Intuition first: a meeting point with a door on each side

Picture a corridor with two doors and a room between them. Everyone working on step one of a job must pass through the first door before anybody may pass through the second. A person who arrives early waits in the room. The last person to arrive opens the second door and everybody leaves together. Then the room has to be empty and ready before the next job, because the same people will come back for step two.

Educational interpretation The first door is the arrival gate, the second is the departure gate, and the room is the counter. The whole difficulty of a barrier is not the first door. It is making the room ready again without anybody slipping into it twice.

Barrier, precisely

A barrier for n processes is a point in the code with two properties. Safety: no process passes the barrier until all n processes have reached it. Progress: once all n have reached it, all of them pass in finite time.

A barrier used more than once adds a third: a process may pass the k-th barrier only after all processes have passed the (k−1)-th. A barrier that satisfies safety and progress for one use and fails this third property is not a barrier; it is a barrier-shaped bug.

Mathematical derivation The third property is what forbids “two processes in adjacent rounds at the same time”. Hensgen, Finkel and Manber state it exactly this way: no two processes may be in adjacent epochs.

The arrival gate

One shared counter, incremented under a lock. A process that finds the counter below n waits; the process that brings it to n releases everyone.

arrive: lock; arrived++; unlock; if (arrived < n) wait until released;

Mathematical derivation The increment must be atomic with respect to other increments, or two processes can read the same value and write the same value and one arrival is lost. It need not be atomic with respect to the wait, and it must not be: holding the lock while spinning would block the arrivals you are waiting for.

The departure gate

After the release, the counter must be restored and the next round must be distinguishable from this one. There are only three known ways to do it, and they are the three designs of this lesson.

1. reset a constant to 0 (2006 code — wrong) 2. flip a shared sense flag (sense reversing) 3. count up then count down (two phase)

Educational interpretation Designs 2 and 3 differ in what the shared word means. In design 2 it names the round; in design 3 it counts the processes still inside. Neither ever reuses a value with a new meaning.

The 2006 barrier, read as three blocks

1 P(S); arrival gate 2 process_arrived++; (protected — correct) 3 V(S); 4 while (process_arrived != 3); the wait (unprotected) 5 P(S); departure gate 6 process_left++; (protected — correct) 7 if (process_left == 3) { 8 process_arrived = 0; 9 process_left = 0; 10 } 11 V(S);

Both critical sections are correct. The defect is in the interaction between the unprotected wait on line 4 and the reset on line 8. A process can read three on line 4, leave, re-enter the barrier, and increment on line 2 before another process has read line 4 at all. The counter is then four, and the two remaining processes spin for three for ever.

Mathematical derivation The reset on line 8 happens only when process_left reaches three, and process_left reaches three only when all three processes pass line 6, and a process cannot pass line 6 unless it passed line 4. So the reset is always after the release, and a fast process has a window between the two.

Example 1 — one invocation is correct

Three processes, one invocation, binary semaphore S = 1, both counters starting at 0.

  • P1 P(S) → process_arrived = 1 → V(S) → tests 1 ≠ 3, spins.
  • P2 P(S) → 2 → V(S) → tests 2 ≠ 3, spins.
  • P3 P(S) → 3 → V(S) → tests 3 = 3, falls through.
  • All three leave line 4, take the lock one at a time, and process_left reaches 3, which resets both counters to 0.

    • Measured. 416 reachable states, 0 deadlocked end states, 0 processes released early, the counter never above 3, and at most 2 processes spinning at once. So the first invocation passes, and the exam question is about the second.

    Example 2 — the interleaving that deadlocks

    The same three processes, now calling the barrier twice. The search finds the shortest deadlocking trace in 18 statements; these are its last steps.

  • All three arrive; process_arrived = 3; P1 reads 3 and leaves the loop.
  • P1 takes the lock, process_left = 1, which is not 3, so it does not reset; V(S); P1 returns.
  • P1 calls the barrier again: P(S), process_arrived = 4, V(S).
  • P1, P2 and P3 all test process_arrived != 3. It is 4. None of them ever leaves.

    • Measured. 8 deadlocked end states out of 1538 reachable states, and the counter reaches 5 = 2n − 1 somewhere in the graph. That figure is the signature: round one contributes n arrivals, round two contributes n − 1 more, and then the last process is stuck.

    Example 3 — the four candidate repairs, run

    Each option of the second question was transcribed and searched. “Early departures” counts reachable states in which a process completes a round while fewer than n processes have arrived in that round.

  • A — lines 6 to 10 replaced by process_arrived--. 450 early departures. A process decrements, re-enters, increments, and the counter reads 3 again while the others are still arriving. — fails
  • B — wait at the start until process_arrived is 0. The counter never exceeds 3. This is the keyed answer, and it removes the defect the first question names. — keyed
  • C — context switch disabled across the barrier. Stuck at the very first invocation: a process that finds the counter at 1 spins, and nobody else can run to make it 3. — fails
  • D — process_left made private. No process ever sees 3, so the reset never happens, and the counter climbs to 6 = 2n. — fails

    • Mathematical derivation D reaches 2n rather than 2n − 1 because every process now arrives twice: with no shared departure count there is no reset to stop the second round from adding a full n.

    Example 4 — what option B does not fix

    Option B is the keyed answer, and it does bound the counter. The same search, run on B, still finds stalled end states.

  • All three pass round 1; the last one out resets process_arrived to 0.
  • P1 enters round 2: the gate reads 0, so P1 passes, and increments to 1.
  • P2 and P3 reach the gate, read 1, and wait for 0.
  • Only a completed round 2 can reset the counter, and round 2 needs P2 and P3.

    • Measured. 12 stalled end states out of 1115 states, with the counter correctly capped at 3. Mathematical derivation The gate is a condition on a variable the barrier itself must change, which is circular. It is a symptom fix, not a reuse fix — and it is still the right answer to the question the paper asks.

    Example 5 — sense reversing and two phase, measured

    sense: local = !local; if (fetch_and_dec(count) == 1) count = n; sense = local; else repeat until sense == local; two: P(arrival); if (++counter < n) V(arrival); else V(departure); P(departure); if (--counter > 0) V(departure); else V(arrival);

    Sense reversing, two invocations, three processes: 2396 states, 0 deadlocked end states, 0 early departures, 6 runs that finish both rounds.

    Two phase, same setting: 1669 states, 0 deadlocked, 0 early departures. With the counter deliberately split into a read and a write (non-atomic): 7054 states and still 0 deadlocked — because both the increment and the decrement sit inside a region protected by a semaphore, so the atomicity is never needed.

    Mathematical derivation For the naive barrier (spin until the counter returns to n), the same search finds 6 runs that finish and 18 deadlocked end states. A barrier that works for some schedules is not a barrier.

    Where the rules stop applying, and what breaks when they do

    Each card names the boundary, the exact condition that fails, and the smallest case that shows it. Read these before the misconceptions: several of them are the counterexample a misconception needs.

    n = 1: a barrier that is not a barrier

    With one process the arrival gate is always already satisfied, so a barrier degenerates to no-ops. The 2006 code still works: the counter reaches 1, which is n, and the process passes immediately.

    Where it bites: a question that fixes n = 1 makes every deadlock question vacuous, and any “n − 1 processes spin” answer becomes 0. Check n before reasoning about spins.

    n = 2: the deadlock still happens

    With two processes and two invocations the 2006 barrier still deadlocks: the counter reaches 3 = 2n − 1 and both processes spin. Measured by the same search.

    Why it matters: the smallest interesting case is n = 2, not n = 3, so a question with two processes is not a simplified version that avoids the bug. It is the same bug with fewer moving parts.

    The last arrival never spins

    The process that brings the counter to n finds the test already true, so it does not spin. That is why at most n − 1 processes spin at once, measured here for n from 2 to 5.

    Where it bites: an option claiming “all n processes spin” is wrong by one, and the off-by-one is the whole point of the option.

    A spinning process is runnable, not blocked

    A spin loop consumes the processor. The operating system sees a running process, not a sleeping one, so it cannot detect this deadlock and cannot break it by scheduling someone else.

    The consequence for questions: “the OS will detect the deadlock and recover” is false for any spin barrier. It is also why real systems spin only for a bounded time and then block.

    Holding the lock while spinning blocks the release

    If line 4 were moved inside P(S) and V(S), the spinning process would hold the only lock, and the processes whose arrivals would satisfy the test could never take it.

    The condition that fails: the lock is needed by the very processes the waiter is waiting for. So the spin must be outside, and the counter read must be unprotected — which is exactly why the design has to make stale reads harmless.

    Memory ordering: the counter may not be visible

    On a machine with a weak memory model, a write to the counter may not be visible to another core in program order. A correct implementation inserts a release store after the write and an acquire load inside the spin.

    Verified fact The implementations in the sources below (Scott’s pseudocode and the OpenMP runtime) use acquire/release annotations for exactly this reason. Educational interpretation GATE questions model a sequentially consistent machine, so this appears only as a conceptual point; it is stated here so the model is not mistaken for hardware.

    Deadlock, starvation and an early release are three different failures

    Deadlock: no process can make progress. Starvation: some process never gets its turn while others proceed. Early release: a process passes the barrier before all have arrived, which is a safety violation, not a liveness one.

    How to tell them apart: the search reports them separately, and so should you. Option A of the 2006 question fails by early release (450 states) and not by deadlock; the original code fails by deadlock and never by early release.

    What the model assumes

    Each C statement is one atomic step; the read inside the spin test is atomic; process_arrived++ is atomic when it is inside a critical section; processes run on separate cores.

    Why it is stated: a real compiler may split process_arrived++ into a load and a store even inside a critical section that is only a semaphore, and a real machine may reorder. Neither changes the deadlock, which survives all of them — but a claim about a specific step count does depend on the assumption.

    Six beliefs that are wrong, and the smallest thing that refutes each

    Each card gives the belief as it is usually stated, why it is tempting, a counterexample small enough to check by hand, and the rule that replaces it.

    1. “A barrier is just a mutex that lets everybody in”

    Why it tempts. Both use one shared variable and both involve waiting, and a barrier does provide a kind of exclusion — exclusion between rounds.

    Minimal counterexample. A mutex with n processes lets one in at a time and never releases them together. A barrier releases all n together and excludes nothing within a round.

    The rule. A mutex orders processes against each other. A barrier orders rounds against each other. The variable in a barrier answers “has everybody arrived”, not “is somebody inside”.

    2. “If it is correct for one invocation it is correct”

    Why it tempts. The single invocation is what you can trace by hand, and it works: 416 states, no deadlock, no early release.

    Minimal counterexample. Two invocations, three processes, eighteen statements: the counter reaches 4 and all three spin. The 2006 paper is built on exactly this gap.

    The rule. A barrier is a reuse mechanism, so correctness means correctness for every k. Test two invocations, always.

    3. “The spin should be inside the critical section”

    Why it tempts. Everything else in the program is inside one, and the counter is shared data.

    Minimal counterexample. Move line 4 inside P(S)/V(S): the first process to arrive holds the only lock and spins, and the other two block on P(S) and never arrive. The barrier now deadlocks with one invocation.

    The rule. The spin must not hold a resource that an arrival needs. That is precisely why the counter is read without protection, and why the design has to tolerate a stale read.

    4. “Making the counter atomic fixes the deadlock”

    Why it tempts. Atomicity is the usual repair for a lost update, and the counter is shared.

    Minimal counterexample. The 2006 code already increments inside a critical section, so the increment is effectively atomic, and it still deadlocks. The bug is not a lost update; it is a value being reused with a new meaning.

    The rule. Atomicity makes one operation indivisible. It says nothing about whether the value means the same thing in the next round.

    5. “The OS will see the deadlock and recover”

    Why it tempts. Deadlock detection is a standard topic, and there is a wait-for graph in the chapter before this one.

    Minimal counterexample. A spinning process holds the processor and holds no resource. A wait-for graph built from resource ownership has no edge to show, so the detector reports nothing while the system makes no progress.

    The rule. Spin-based deadlock is invisible to resource-based detection. It is one reason real barriers bound the spin and then block.

    6. “Option B is wrong because a full search finds a stall”

    Why it tempts. This page’s own search finds 12 stalled states under B, which looks like a refutation of the answer key.

    What is actually true. B bounds the counter at n, which is exactly the defect the first question names, and the key is B. A stricter question — “which change makes this a reusable barrier” — would not have B as its answer.

    The rule. Answer the question that was asked. Keep the exam judgement and the engineering judgement in separate sentences, and say which one you are making.

    The five question shapes this topic produces

    Each card names the shape, the reasoning it demands, and the approach that loses the mark. Verified previous-year items are named with their year and paper; nothing is called a PYQ on resemblance alone.

    Shape 1 — is this barrier correct, and if not why

    A barrier is given and one statement about it is true: a deadlock, a missing critical section, a wrong semaphore, or a bound on n. The reasoning is about the second invocation.

    Verified fact GATE CSE 2006 asks exactly this about the code in this lesson, as the first of a linked pair of questions, and the key is that two invocations in immediate succession may deadlock.

    The wrong approach. Checking that every shared update is inside a critical section and concluding the code is correct. Both critical sections here are correct, and the code is still wrong.

    Shape 2 — which change rectifies it

    Four candidate repairs, each a small edit: replace a block, add a wait at the start, disable context switching, or change a variable's scope.

    Verified fact GATE CSE 2006 asks this as the second of the linked pair; the key is the wait at the start until process_arrived becomes zero.

    The wrong approach. Choosing the option that removes the symptom you just traced. Option A removes the departure counter, and it lets a single process pass the barrier alone.

    Shape 3 — what value does the counter reach

    A barrier is given with n processes and two invocations, and the question asks for the largest value of a counter, or its value at a named point.

    Method. Count arrivals per round: round one can contribute n, round two can contribute n − 1 before the last process is stuck, so the maximum is 2n − 1. If the reset cannot happen at all — option D — the maximum is 2n.

    The wrong approach. Answering n + 1, which is what the shortest deadlock trace shows (4 for n = 3) but not the largest value any run reaches (5). Read the question: “at least” and “at most” give different answers.

    Shape 4 — how many processes are spinning or blocked

    Questions asking how many processes can be inside the barrier, spinning, or blocked on a semaphore at one moment.

    Method. In a spin barrier at most n − 1 spin, because the last arrival never spins; in a semaphore barrier at most n − 1 are blocked at the departure semaphore, because the last arrival is the one that opens it. In both cases exactly one process is doing something.

    The wrong approach. Answering n, or answering “all of them, because they are all waiting”. The releaser is never waiting.

    Shape 5 — which of these is a correct reusable barrier

    Four implementations, one correct. The options usually differ in one of three ways: whether the counter is reset to a constant, whether a sense flag is flipped, or whether there are two phases.

    Method. Ask what each design does about round k + 1. A reset to a constant reuses a value and is wrong unless something else prevents the reuse. A sense flip makes the two rounds different. A two-phase design never resets, so nothing is reused.

    The wrong approach. Choosing the shortest code. The two-phase barrier is longer than the naive one and is correct; the naive one is four lines and deadlocks in the second round.

    MCQGATE CSE 2006, linked answer question 78

    Barrier is a synchronization construct where a set of processes synchronizes globally, i.e. each process in the set arrives at the barrier and waits for all others to arrive and then all processes leave the barrier. Let the number of processes in the set be three and S be a binary semaphore with the usual P and V functions. Consider this C implementation, with line numbers on the left:

    1: P(S);   2: process_arrived++;   3: V(S);
    4: while (process_arrived != 3);
    5: P(S);   6: process_left++;
    7: if (process_left == 3) {   8: process_arrived = 0;   9: process_left = 0;   10: }
    11: V(S);

    The variables process_arrived and process_left are shared among all processes and are initialized to zero. The implementation above is incorrect. Which one of the following is true?

    1. The barrier implementation is wrong due to the use of binary semaphore S.
    2. The barrier implementation may lead to a deadlock if two barrier invocations are used in immediate succession.
    3. Lines 6 to 10 need not be inside a critical section.
    4. The barrier implementation is correct if there are only two processes instead of three.

    Answer: B

    A process can read three on line 4, leave the loop, finish the barrier without resetting the counters (because process_left is not yet 3), and call the barrier again. Its second arrival makes process_arrived four, and the other two processes spin on line 4 for ever. This page’s search finds that interleaving in 18 statements and finds 8 deadlocked end states overall.

    Why A fails. A binary semaphore is sufficient: it is only used to protect the two counter updates, and both critical sections are correct. Why C fails. Lines 6 to 10 must be protected, or two processes can both read process_left as 1 and both write 2, and the reset never happens. Why D fails. The search confirms the deadlock for n = 2 as well: the counter reaches 3 = 2n − 1 and both processes spin.

    Provenance note. The question is the first of the linked pair 78–79 in the GATE CSE 2006 paper, whose text is available in public archives of the paper. It is quoted here because the year and the paper are known; the answer B is the published key.

    MCQGATE CSE 2006, linked answer question 79

    For the same barrier implementation as Question 1, which one of the following rectifies the problem?

    1. Lines 6 to 10 are simply replaced by process_arrived--.
    2. At the beginning of the barrier the first process to enter the barrier waits until process_arrived becomes zero before proceeding to execute P(S).
    3. Context switch is disabled at the beginning of the barrier and re-enabled at the end.
    4. The variable process_left is made private instead of shared.

    Answer: B

    The problem is that process_arrived can pass n. A gate at the start stops a process from beginning a new invocation while the previous one has not finished, so the counter cannot exceed three. This page runs all four options: under B the counter never exceeds 3, whereas the original reaches 4 and D reaches 6.

    Why A fails. With the departure counter gone, a process can decrement, re-enter, increment, and read 3 again while the others are still arriving. The search finds 450 states in which a process completes a round before all three have arrived. Why C fails. The spin needs other processes to run; with context switching off, the first process to find the counter at 1 spins and nobody can arrive. The search is stuck at the very first invocation. Why D fails. A private process_left never reaches 3, so the reset never happens and the counter climbs to 6 = 2n.

    Honest note. A full search on the literal transcription of B still finds 12 stalled end states in the second invocation, because the gate can only be cleared by a reset that round two must produce. The key is B, and it does fix the counter bound the paper is asking about; a barrier for repeated use needs the sense or two-phase design.

    MSQOriginal practice

    Which of the following are true of the sense-reversing centralized barrier (count starts at n, shared sense, private local)?

    1. Each process flips its own local before it decrements the count.
    2. The last process to arrive resets the count and then publishes its own sense.
    3. A process waiting in round k can be released by a flip belonging to round k + 1.
    4. It needs the count to be reset before the sense is published.

    Answer: A, B, D

    A is the first line of the procedure, and it is what makes the local value a round marker. B is the last process’s branch. D is the ordering that matters: publishing the sense releases the waiters, so the count must already be back at n when a waiter wakes.

    Why C is false. The whole point is that it cannot. Round k and round k + 1 use opposite sense values, so a flip belonging to round k + 1 sets the shared sense to the value round k + 2 will want, not the one a round-k waiter is watching. That is exactly the property that makes a stale read harmless, and the search confirms it: 0 deadlocked end states and 0 early releases over two invocations.

    NATOriginal practice

    The GATE CSE 2006 barrier is used with n = 5 processes, and every process calls it twice in immediate succession. What is the largest value process_arrived can reach?

    Answer: 9

    The counter is never reset, because the reset needs all five processes to pass line 6 and the deadlock prevents that. Round one contributes five arrivals, so the counter reaches 5. One process then slips through line 4 and re-enters the barrier, and four more can do the same before the last one is stuck at the spin. That gives 5 + 4 = 9 = 2n − 1.

    This page measures the maximum for n = 2, 3 and 4 as 3, 5 and 7, which is 2n − 1 in each case; the general form is the derivation above, not a measurement at n = 5.

    Why 6 appears. It is n + 1, the value in the shortest deadlock trace: one process escapes and the other four spin immediately. That is a reachable value, not the largest one. Why 10 appears. It is 2n, which is the bound for option D, where the reset never happens even in round one.

    NATOriginal practice

    An 8-process barrier is implemented with the spin loop while (process_arrived != 8);. At most how many processes can be executing that spin at the same instant?

    Answer: 7

    The process that brings the counter to 8 finds the test already false, so it never enters the loop; it proceeds to the departure section. Every other process can be spinning, so the maximum is n − 1 = 7.

    Measured here for n = 2 to 5: 1, 2, 3, 4. The bound is a derivation, not a measurement at n = 8.

    Why 8 appears. It counts the releasing process as a spinner. Why 6 appears. It also excludes the process currently inside the critical section of the departure block, which is a different moment — the question asks about the spin.

    MCQOriginal practice

    A two-phase barrier uses arrival = 1, departure = 0 and counter = 0, with three processes. After all three have arrived and the last one has opened the exit, but before any process has left, what are the values of counter and departure?

    1. counter = 3, departure = 0
    2. counter = 3, departure = 1
    3. counter = 0, departure = 1
    4. counter = 3, departure = 3

    Answer: B

    The counter counts arrivals minus departures, so with three arrivals and no departures it is 3. The last arrival issues exactly one V(departure), which releases one waiter, so departure is 1: the baton has been handed over and the first process has not yet taken it.

    Why A appears. It forgets the V(departure) the last arrival performs. Why C appears. It applies the invariant to the wrong moment: the counter reaches 0 only after all three have decremented. Why D appears. It assumes the exit is broadcast to everybody; here the baton is passed one process at a time, so departure is never more than 1.

    MCQOriginal practice

    The naive centralized barrier decrements a shared count (initial n) and spins until the count is n again, the last arrival resetting it. Which statement is true?

    1. It is correct, because the decrement is atomic.
    2. It is incorrect, and making the decrement atomic repairs it.
    3. It is incorrect for two invocations, because a fast process can decrement the reset count before a slow process reads it.
    4. It is incorrect only when n is greater than the number of processors.

    Answer: C

    The last arrival sets the count back to n. A slow process is spinning for exactly that value. A fast process that has already left the barrier decrements it to n − 1, and the slow process now waits for a value that has already been and gone. The search finds 18 deadlocked end states alongside 6 runs that do finish — the mixture that makes this bug so easy to miss.

    Why A fails. Atomicity is necessary and irrelevant here: every operation in the trace is already atomic. Why B fails. Same reason. Why D fails. The failure is a scheduling interleaving, not a shortage of processors; it reproduces with two processes.

    Definitions, the three designs, the counts, the traps. If you remember one sentence, remember the one at the bottom of this card.

    Definitions in one line each

    Barrier: no process passes until all n have arrived, and then all pass.

    Arrival gate: a protected counter that counts arrivals and releases at n.

    Departure gate: the part that re-arms the barrier for the next round.

    Spin: a busy wait. The process stays runnable and holds no resource.

    Sense reversal: each process flips a private flag; the last arrival publishes the shared one.

    The three designs, side by side

    2006 code: resets a constant to 0. Correct once, deadlocks on the second invocation.

    Sense reversing: flips a shared boolean each round. Correct for repeated use; one shared word.

    Two phase: counts up to n and down to 0 with arrival and departure semaphores. Correct for repeated use; never resets anything.

    Mathematical derivation The three differ only in how they answer “which round is this”. The first answers with a value that both rounds produce, which is the bug.

    The counts

    processes spinning at once: at most n − 1
    arrivals needed to release: n
    largest counter, two invocations of the 2006 code: 2n − 1
    largest counter under option D: 2n
    wake-ups issued by the last arrival in a two-phase barrier: 1, then one per departure

    Mathematical derivation 2n − 1 = n arrivals in round one plus n − 1 in round two, because the last process is stuck at the spin. Option D reaches 2n because no reset happens at all.

    The traps

    1. One working trace is not a proof — the naive barrier finishes 6 runs and is still broken.

    2. A spinning process is runnable, so the OS cannot detect the deadlock.

    3. Atomicity does not fix a reused value.

    4. n + 1 is the shortest deadlock value, not the maximum value.

    The reading procedure

    1. Find the counter and the process that resets it.

    2. Ask when that reset can be late.

    3. Ask what a stale read of the counter can see.

    4. Try two invocations, not one.

    The sentence to keep

    A barrier needs an arrival gate and a departure gate, and the departure gate must make round k + 1 distinguishable from round k.

    That sentence answers the code questions, the counting questions and the option questions, and it tells you which of the four traps a wrong option has fallen into.

    Where the “strawman” and “sense” explanations come from

The GHC OpenMP runtime appendix documents the same design in production code and states that the sense trick avoids the resetting race.

    Where this lesson stops

    No audio file is shipped, so the caption timings are estimated from the timeline at a normal speaking rate rather than measured. No video file exists.

    The searches use three processes and two invocations. The counter-bound and spin-bound figures were measured for n from 2 to 5 and generalised by the derivations stated in the lesson, not measured at larger n.

    Tree barriers, dissemination barriers, tournament barriers and combining-tree barriers are named but not developed: they change the cost of a barrier, not its correctness, and they are outside the syllabus clause this lesson serves.
