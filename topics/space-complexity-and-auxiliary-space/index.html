Topic and objective

TOPIC: Space complexity — the auxiliary space of an algorithm, the recursion stack, and what the words "in place" actually claim. This is the second half of one clause of GATE 2027 Section 5, Algorithms.

LEARNING OBJECTIVE: Answer a space question the way the syllabus asks it: find the instant at which the most memory is live, count what is live at that instant — buffers, frontier or path, and one stack frame per level of recursion — separate the input from the addition if the question asks for "extra" or "auxiliary" space, and then simplify. Compute the recursion depth of a program by running it rather than recalling a formula, add the depth to the buffer instead of quoting whichever is smaller, and say which of the three meanings of "in place" you are using.

I read this clause as one measurement asked of every program in the paper: how much is alive at the worst moment. The same three components — a buffer, a traversal structure, a stack — recur in sorting, in graph search and in dynamic programming, and the arithmetic is addition followed by simplification, exactly as in a time answer.

The five ideas to leave with

  1. Space is a peak, not a total. Count what is alive at the worst instant; ignore what has already returned.
  2. The number of calls is a time quantity. The depth of the call tree is the space quantity, and they can differ by a factor of 89,751.
  3. A recursion contributes its depth, not its size. Add the depth to the buffer, then keep the larger term.
  4. Total space includes the input; auxiliary space does not. Only the auxiliary column can rank two sorts.
  5. "In place" has three meanings — O(1), O(log n), and "does not copy the array". Name the one you are using.

Intuition: the desk, not the filing cabinet

Picture two people doing the same job of checking a thousand invoices against a rule. The first pulls one invoice at a time onto the desk, checks it, puts it back, and pulls the next. At any moment the desk holds one invoice. The second pulls invoice 1, then needs invoice 2 to check invoice 1, then needs invoice 3 to check invoice 2, and never puts anything back until the whole pile is resolved. At the worst moment the desk holds a thousand invoices.

Both people handle a thousand invoices — that is the time answer, and it is the same for both. Only one of them needs a desk the size of the pile — that is the space answer, and it is different. Every space question in GATE is that question: not how much work happened, but how much was still on the desk at the worst moment.

Level 1 — intuition, stated as a rule

Memory is not consumed by an event; it is occupied by a live thing. A variable is live from the moment it is created to the moment it is destroyed. A stack frame is live from the call to the return. So the space an algorithm needs is the maximum, over all instants, of the total size of everything live at that instant.

This is why the phrase "peak, not total" is not a slogan but the definition. Anything already destroyed contributes zero, however much it contributed a moment ago.

Level 2 — the formal statement

Let $$M(x, t)$$ be the number of cells live at time $$t$$ when the algorithm runs on input $$x$$. Then the space used on that input is

$$S(x) = \max_t M(x, t)$$

and the space complexity of the algorithm is a function of the input size, taken over the worst input:

$$S(n) = \max_{|x| = n} S(x)$$

"The algorithm uses O(f(n)) space" means there are constants c and n₀ with $$S(n) \le c\,f(n)$$ for all $$n \ge n_0$$. The symbol means: the peak cell count is at most a constant multiple of f, once n is large enough.

Level 2b — the model, in one line

One cell is one word. One activation record is a constant number of words, whatever the function does. An array of k keys is k cells. A matrix with V² entries is V² cells. Under this model a space answer is arithmetic, and the arithmetic is exact.

Real machines differ — a frame may be 48 bytes or 96, a cache line may punish a linked list — and those differences change the constant, never the order. Every number on this page is computed under the stated model, and the model is printed on the canvas so you can see what was assumed.

Level 3 — the picture: three kinds of live memory

Every space answer in this subject is a sum of at most three terms, and naming them is most of the work.

1. Buffers

Arrays, tables and temporary copies that the algorithm allocates itself. An array of n keys used as a merge buffer is n cells; a matrix of V² distances is V² cells; a dynamic-programming table of m × n is mn cells.

Buffers are usually the largest term and the one most often forgotten.

2. The traversal structure

A queue, a stack, a set or a heap that holds work in progress. BFS holds a frontier, DFS holds a path, Dijkstra holds a priority queue of up to V entries, and a visited array of V flags is itself a term.

Its size is bounded by V or by the widest layer, never by the number of edges.

3. The stack of frames

One frame per unfinished call, so the total is the depth of the recursion times the frame size — not the number of calls. Linear recursion reaches depth n; a balanced divide reaches depth ⌈log₂ n⌉ + 1; a chain of n calls on a sorted array reaches depth n.

A returned call holds nothing, which is why the count is a depth and not a total.

The addition, and then the simplification

Merge sort on an array: buffer n, stack ⌈log₂ n⌉ + 1, so the peak is

$$S(n) = n + \lceil \log_2 n \rceil + 1 = \Theta(n)$$

The logarithm vanishes because n + log n is Θ(n). The buffer decided the answer.

Quick sort on a sorted array: buffer 1, stack n, so $$S(n) = 1 + n = \Theta(n)$$. Here the stack decided it. Same addition, different winner.

Total against auxiliary, written out

$$\text{total}(n) = \text{input}(n) + \text{auxiliary}(n)$$

For an array of n keys the input term is n, so merge sort's total is 2n + log n = Θ(n) and its auxiliary is n + log n = Θ(n). Both happen to be Θ(n) here, which is exactly why the distinction is easy to miss.

Pick a pair where it bites: insertion sort has total Θ(n) and auxiliary Θ(1). A question asking for "extra space" wants the second number.

Levels 5 and 6 — when it applies, and what breaks

A space bound is a claim about a model, and each model assumption has a failure mode. These are the four that change an answer rather than a constant.

Assumption: the recursion is the only stack

A recursive function that calls a library sort inside each frame holds the library's stack too. On this page the model counts only the frames of the function under discussion.

A question about a real program has to count the library, which is why such questions print the whole code.

Assumption: a frame is constant

A frame that contains a variable-length array, or a copy of a struct passed by value, is not constant. Passing an n-key array by value in C copies it into the frame, making each frame Θ(n) and the space Θ(n²).

This is a real GATE trap, and it lives in Functions, Scope, Lifetime and the Preprocessor.

Assumption: recursion costs a stack

A tail call can be compiled into a jump, reusing one frame. Then a linear recursion costs O(1) space. But the C standard does not require it, so a question about C must not assume it — and a question that wants it will say "with tail-call optimisation".

Under the model used here, the frame stays, so a tail recursion is still O(n) space unless the question says otherwise.

Assumption: the answer is a single number

The same problem has several space answers depending on the algorithm: Fibonacci costs Θ(n) naively, Θ(n) memoised, and Θ(1) with two variables. A question that offers two bounds is usually asking which technique achieves which.

So a space question is answered by naming the algorithm, never by naming the problem.

Five worked examples, all computed on this page

Each one names the three terms first, adds them, then simplifies. The numbers on the Animation tab come from the same model, so the two agree by construction rather than by copying.

Example 1 — the GATE 2005 function, recomputed

PYQ — GATE CSE 2005, Q81a

double foo(int n) { int i; double sum; if (n == 0) return 1.0; sum = 0.0; for (i = 0; i < n; i++) sum += foo(i); return sum; }

Terms. Buffer: none. Traversal structure: none. Stack: the depth of the recursion, times a constant frame.

Depth. Inside foo(k) the loop calls foo(0), foo(1), … in that order, and each returns before the next begins — so those do not overlap. The overlap is down the chain: foo(k) is alive while it calls foo(k−1), which is alive while it calls foo(k−2). The longest chain is n + 1 frames, reached by taking the last iteration every time. The page runs the recursion and records 9 frames at n = 8.

Answer. Θ(n). The tempting alternative counts the 2ⁿ = 256 calls made over the run, which is the time answer.

Derivation C(n) = 1 + C(0) + … + C(n−1) with C(0) = 1 solves to C(n) = 2ⁿ, and the page checks that closed form against the enumeration for n = 0 … 12.

Example 2 — merge sort on 1,024 keys

Buffer. One array of n = 1,024 cells, reused at every level.

Stack. The interval halves at each level, so the number of levels is ⌈log₂ 1,024⌉ + 1 = 11.

Peak. The deepest frame is merging while the outer frames wait, so both are live: 1,024 + 11 = 1,035 cells.

Simplify. n + log n is Θ(n). Auxiliary space Θ(n); total space n + 1,035 = Θ(n).

Derivation The depth formula is checked against an actual split for every n from 1 to 256, including the non-powers of two where the ceiling matters.

Example 3 — quick sort on a sorted array

Input. 64 keys in ascending order; pivot is the last element; partition is Lomuto's.

What happens. The pivot is the largest key, so everything else goes left and the right part is empty. Each level removes exactly one key, so the recursion is a chain of 64 levels. Comparisons: 63 + 62 + … + 1 = 2,016 = 64·63/2.

Peak. Buffer 1 (the array is partitioned in place) plus stack 64 frames, so Θ(n).

Balanced case. With a median pivot the same array gives depth 7 = ⌈log₂ 64⌉ + 1, so Θ(log n). The pivot decides the space as well as the time. The page runs both.

Example 4 — two traversals of one graph

The graph. Nine vertices, eight edges: a hub (vertex 0) joined to 1, 2, 3 and 4, with a chain 4 → 5 → 6 → 7 → 8.

BFS. Layer widths 1, 4, 1, 1, 1, 1, so the queue peaks at 4. Bounded by V, so Θ(V).

DFS. The hub is entered, its three leaves return immediately, and the fourth leads down the chain: the stack peaks at 6 frames. Also Θ(V), for a different reason.

Storage. Matrix 9² = 81 cells against list 9 + 2·8 = 25 slots. The total is representation + traversal + visited, and which term dominates depends on the representation.

Example 5 — the same computation, three space answers

Fibonacci. Naive recursion: Θ(n) space (depth n) and Θ(2ⁿ) time. Memoised: Θ(n) space and Θ(n) time. Bottom-up with two variables: Θ(1) space and Θ(n) time.

Longest common subsequence. The recurrence reads the previous row and the current row only, so a full table of 1,000 × 1,000 = 1,000,000 cells can be replaced by two rows of 1,000, which is 2,000 cells — a factor of 500, with no change in time.

Floyd–Warshall. Every entry is read again at the next intermediate vertex, so the V² table cannot be rolled: 10,000 cells at V = 100, and Θ(V³) time. Rolling is a property of the recurrence, not a general trick.

Six boundaries, each with the condition it turns on

A space bound is true of a model. These are the six places where the answer changes because the model changed, not because the arithmetic did.

1. n = 0, and the base case

The 2005 function at n = 0 returns immediately: one frame, no recursion. Its depth is n + 1 = 1, which is Θ(1) as well as Θ(n) — both bounds hold, and Θ(n) is the tight one for the family of inputs. A question that fixes n = 0 is asking about one instance, not about complexity.

Merge sort at n = 1 has depth 1 and buffer 1, and the formula n + ⌈log₂ n⌉ + 1 gives 1 + 0 + 1 = 2, which over-counts. Small cases are where a formula and a program disagree, and the program is right.

2. The last level of the recursion

For n = 1,024 the depth is 11 and not 10, because the level that holds the whole array counts. Dropping the +1 is the commonest arithmetic slip in this topic: it turns 11 into 10 and 1,035 into 1,034.

The formula ⌈log₂ n⌉ + 1 is checked here for every n from 1 to 256; the ceiling matters whenever n is not a power of two. At n = 100 the depth is 8, since ⌈6.64⌉ + 1 = 8.

3. Recursion converted to iteration

Replacing recursion by an explicit stack does not reduce the order: the same n frames now live in an array you allocated. The space is unchanged and the code is longer.

The exception is a recursion whose stack you can replace by a constant — a tail recursion rewritten as a loop, or a DFS that keeps only a parent pointer. Then the space really does drop, and the drop is the point of the rewrite.

4. Peak against cumulative allocation

A program that allocates and frees n buffers of n cells, one after another, has a peak of n but allocates n² over its life. The peak is the space; the cumulative figure is a different quantity and is what an amortised space argument would bound.

A dynamic table that doubles its capacity has peak n and cumulative allocation about 2n, which is why its amortised cost is constant — the two numbers are related but not equal.

5. Structures that store keys by reference

A binary search tree of n keys costs n nodes, each holding a key and two pointers. If the keys are large and stored by pointer, the node is constant-size; if each node copies the key, the node is Θ(key size).

So "a BST is Θ(n) space" assumes constant-size keys. A question that says the keys are strings of length up to L is asking for Θ(nL).

6. Space counted at the wrong moment

Counting at the start of a pass rather than at the deepest point under-counts; counting after the recursion has unwound gives 1 for every recursive program. Both are mistakes of when, not of arithmetic.

The safe habit: draw the call chain at its deepest, then count the cells in that drawing. Every scene on the Animation tab does exactly that.

Six wrong beliefs, and the smallest thing that refutes each

Each belief is stated in the form in which it is usually held, then refuted with one example rather than with an argument.

"Exponential time means exponential space"

Refuted by naive Fibonacci: 21,891 calls at n = 20 and 20 frames. The calls are made one after another down a single path, and each returns before its sibling starts. At n = 30 the ratio is 89,751 calls per frame.

Time counts work done; space counts work in progress. An exponential amount of work can be done in linear space, and often is.

"In place means O(1) space"

Refuted by quick sort on a sorted array: it never allocates a second array, and it holds 64 frames at n = 64, so Θ(n) auxiliary space. The array is in place; the stack is not.

The phrase describes where the data is moved, not how much memory is used. A question that offers both O(1) and O(log n) is testing exactly this.

"Merge sort needs O(log n) space, because its recursion is logarithmic"

Refuted by the buffer: 1,024 cells at n = 1,024 against 11 frames. The peak is 1,035, and Θ(n) survives the addition while Θ(log n) does not.

The logarithm is real and countable; it is simply the smaller term. Quoting it alone has counted the stack and missed the buffer.

"The number of calls is the space"

Refuted by the 2005 function: 256 calls, 9 frames. The published key is O(n), and O(2ⁿ) is the option written for this error.

A call that has returned occupies nothing. Only the calls still waiting occupy memory, and they form one chain.

"Auxiliary space and space complexity are the same thing"

Refuted by insertion sort against merge sort: their total space is Θ(n) for both, because the input array is Θ(n) for both, while their auxiliary space is Θ(1) against Θ(n).

The total column cannot rank them. A question asking for "extra space" is asking the column that can.

"Every recursion costs linear space"

Refuted by recursive binary search: depth ⌈log₂ n⌉ + 1, so Θ(log n). Also by merge sort's stack, and by any recursion that halves its argument.

What matters is the depth, and the depth is decided by how fast the argument shrinks: by 1 gives n, by half gives log n.

Four closely confused pairs, side by side

Total against auxiliary

Total includes the input; auxiliary does not. For an array of n keys they differ by exactly n.

Read the question's adjective: "extra", "additional", "auxiliary" mean the second; "space" alone means the first. If neither appears, say which you computed.

Height against node count

Height is how many frames are alive together; node count is how many calls are made. For fib(4) that is 4 against 9; for fib(20), 20 against 21,891.

Only the height is a space quantity. The node count is the time quantity, and drawing a tree makes the difference visible at once.

Buffer against stack

Both are live at the same moment, so both are in the peak. Merge sort is buffer-dominated; quick sort is stack-dominated; heapsort is neither.

A complete answer names both, adds them, and then says which survived the simplification.

Space against time

The same structure produces both answers and they are not proportional: a chain recursion is Θ(n) time and Θ(n) space, while a doubling recursion is Θ(2ⁿ) time and Θ(n) space.

Never carry an answer across from one column to the other without recomputing it. The two are separate claims about the same program.

Four shapes a space question takes, and the reasoning each demands

The wording of the question tells you which shape it is. Recognising the shape is most of the work; the arithmetic is then short.

Shape 1 — a printed program

The question gives a function and asks for its space complexity. What is being tested: whether you count frames alive together rather than calls made.

Procedure. Find the longest chain of unfinished calls. If the recursion shrinks its argument by 1, the depth is n + 1. If it halves, the depth is ⌈log₂ n⌉ + 1. If it loops over all smaller values, the depth is still n + 1 — the loop makes the time exponential and leaves the depth linear.

Then check whether the function allocates anything: an array inside the frame changes the frame from constant to linear, and the answer with it.

Shape 2 — a named algorithm

The question names an algorithm and asks for its auxiliary space. What is being tested: whether you know which of the three components dominates.

Procedure. Buffer first (does it copy the input?), then traversal structure (a queue, a stack, a table), then stack depth. Add, then keep the largest term. For a sort, the answer is usually one of Θ(1), Θ(log n), Θ(n).

Watch for the qualifier: "worst case" changes quick sort from Θ(log n) to Θ(n), and "on a linked list" changes merge sort from Θ(n) to Θ(log n).

Shape 3 — a numerical answer

The question fixes n, or fixes the graph, and wants a number of cells or frames. What is being tested: exact arithmetic under the stated model, including the +1.

Procedure. Compute each term as a number, add, and give the total. At n = 1,024 merge sort is 1,024 + 11 = 1,035; at 9 vertices the matrix is 81 and the list is 25; at V = 100 Floyd–Warshall is 10,000.

Do not simplify a numerical answer to a class: if the question wants cells, give cells.

Shape 4 — a comparison or a classification

The question offers several algorithms or several bounds and asks which is smallest, which is in place, or which statement is true. What is being tested: the vocabulary, and whether the conventions are being applied consistently.

Procedure. Write each candidate's auxiliary space as a class, then order them. If the words "in place" appear, decide which of the three meanings the option list uses — and if two options differ only by that convention, the question is testing it.

A statement that is true of the array but false of the stack is the usual trap here.

The three-step routine that covers all four shapes

1. Fix the model. One cell is one word; one frame is a constant. Say so in a line if the question does not.

2. Add what is live at the peak. Buffers, plus the traversal structure, plus the stack depth times the frame size. Find the instant of maximum occupancy and count that instant only.

3. Separate input from auxiliary, then simplify. Add the input term only if the question asks for total space. Drop constants and keep the largest term, exactly as in a time answer.

And the four traps to check your answer against: calls counted over time, tree size read as tree height, "in place" read as Θ(1), and total space answered where auxiliary was asked.

Q1 PYQ — GATE CSE 2005, Q81a MCQ

Consider the following C function. The space complexity of the function is

double foo(int n) { int i; double sum; if (n == 0) return 1.0; sum = 0.0; for (i = 0; i < n; i++) sum += foo(i); return sum; }

(A) O(1)   (B) O(n)   (C) O(n!)   (D) nⁿ

Answer: B

The function stores only local variables, so each frame is constant and the space is the depth of the recursion. The deepest chain is foo(n) → foo(n−1) → … → foo(0), which is n + 1 frames, so Θ(n).

A fails because n + 1 frames cannot be a constant. C and D both come from counting the calls made over the run: the call count is 2ⁿ, and neither of those expressions is the depth.

The page executes the function: at n = 8 it records 256 calls and a peak of 9 frames. The wording and the key are reported by question archives; the paper itself was not opened, so treat the option ordering as reported.

Q2 Original practice MCQ

Which one of the following statements about merge sort on an array of n keys is TRUE?

(A) Its auxiliary space is Θ(log n) and its total space is Θ(n)   (B) Its auxiliary space is Θ(n) and its total space is Θ(n)   (C) Its auxiliary space is Θ(1) and its total space is Θ(n)   (D) Its auxiliary space is Θ(n log n) and its total space is Θ(n log n)

Answer: B

The merge buffer is n cells, so the auxiliary term is Θ(n) whatever the recursion depth contributes. Total space adds the input, which is also Θ(n), so the total is Θ(n) too.

A counts only the stack and forgets the buffer. C confuses merge sort with an in-place sort. D would require a separate buffer at every level simultaneously, which a standard implementation avoids by reusing one buffer.

Note the shape: two options are wrong about the auxiliary column and one about the total, so the question is testing both columns at once.

Q3 Original practice NAT

A recursive algorithm splits its input of size n into two halves, recurses on both, and then does Θ(n) work to combine. Its recursion holds one frame per level, each of constant size, and the combine step uses a temporary array of n cells. For n = 1,024, how many cells are live at the deepest point of the recursion? Give a number.

Answer: 1,035

The combine buffer is n = 1,024 cells and the stack holds ⌈log₂ 1,024⌉ + 1 = 11 frames, each of constant size. Both are live together, so the peak is 1,024 + 11 = 1,035.

Traps. 1,024 is the answer to "how big is the buffer"; 11 is the answer to "how deep is the recursion"; 10 is what you get by dropping the +1. The question asks for the peak, so it is the sum.

If the algorithm allocated a fresh buffer at every level instead of reusing one, the peak would rise to about 2n — worth checking in the question's wording.

Q4 Original practice MSQ

For an array of n keys, which of the following algorithms have auxiliary space Θ(1) in their standard implementations? More than one answer may be correct.

(A) insertion sort   (B) heapsort with an iterative sift-down   (C) quick sort with a median pivot   (D) selection sort

Answer: A, B, D

Each of these uses a constant number of variables and moves keys inside the given array.

C is not Θ(1): quick sort's recursion holds Θ(log n) frames with a median pivot, and Θ(n) in the worst case. It is in place in the sense that it copies no array, which is a different claim.

B is qualified on purpose. The recursive sift-down holds log n frames, so heapsort with a recursive sift is Θ(log n), not Θ(1). The implementation detail is part of the question.

Q5 Original practice MCQ

A graph has V vertices and E edges. Breadth-first search is run from one vertex using an adjacency list. Which is the tightest bound on the auxiliary space of the traversal itself, excluding the graph's storage?

(A) Θ(1)   (B) Θ(V)   (C) Θ(E)   (D) Θ(V + E)

Answer: B

The queue holds discovered but unprocessed vertices, and the visited array holds V flags. No layer of a BFS can contain more than V vertices, so the queue is O(V), and it is Θ(V) on a graph with a wide layer — a star, for instance.

C fails because the queue holds vertices, never edges. D is the space of the adjacency list itself, which the question excludes. A fails on any graph with a layer of growing width.

The page's example graph peaks at 4 of its 9 vertices, so the bound is not tight on every graph — a bound is a worst case over graphs of that size.

Q6 Original practice MCQ

Consider the naive recursive computation of the n-th Fibonacci number, with no memoisation. Which statement is TRUE?

(A) Time Θ(2ⁿ) and space Θ(2ⁿ)   (B) Time Θ(2ⁿ) and space Θ(n)   (C) Time Θ(n) and space Θ(n)   (D) Time Θ(2ⁿ) and space Θ(1)

Answer: B

The call count is 2·F(n+1) − 1, which is Θ(2ⁿ), and the frames alive together lie on one root-to-leaf path of length n + 1.

A counts the nodes of the call tree instead of its height. C is the memoised version, not the naive one. D would require the recursion to hold no frames, which it does not.

The page runs both recursions: at n = 20 that is 21,891 calls and 20 frames, a ratio of about 1,095 to 1 — and at n = 30, about 89,751 to 1.

Q7 Original practice NAT

An algorithm stores all-pairs shortest-path distances in a matrix and runs Floyd–Warshall over it. For a graph with 100 vertices, how many cells does that matrix occupy?

Answer: 10,000

The table is V × V = 100 × 100 = 10,000 cells, and it cannot be reduced to a rolling pair of rows: at each intermediate vertex every entry is read again, so the whole matrix must be live at once.

Trap. 1,000,000 is the same question at V = 1,000, and 100 is the number of vertices rather than of cells. Read the exponent off the quantity the table indexes, not off the input.

Contrast LCS, whose recurrence reads only two rows: there, a table of 1,000,000 cells does reduce to 2,000.

Q8 Original practice MSQ

Which of the following are TRUE about the space used by quick sort on an array of n distinct keys?

(A) The array is never copied, so no buffer proportional to n is needed   (B) With a median pivot the recursion depth is Θ(log n)   (C) With the last element as pivot on a sorted array the depth is Θ(n)   (D) Because it is an in-place sort, its auxiliary space is Θ(1) in every case

Answer: A, B, C

A is true: partitioning moves keys inside the given array. B and C are the two depth regimes, and both are computed on this page — 7 levels with a median pivot at n = 64, and 64 levels with the last-element pivot on sorted input.

D is false, and it is the sentence this topic exists to refute: no buffer does not mean constant space, because the stack is counted. At n = 64 the stack is 64 frames in the worst case.

A and D can both feel true because they use "in place" in different senses; the question separates them by naming the stack.

Q9 Original practice MCQ

A program allocates a buffer of 1,000 cells, frees it, and repeats this 1,000 times. Which is its space complexity?

(A) Θ(1)   (B) Θ(1,000) = Θ(1)   (C) Θ(10⁶)   (D) Θ(10³)

Answer: B

Only one buffer is alive at any moment, so the peak is 1,000 cells — a constant, independent of any input size, which is Θ(1) written with its actual value.

C is the cumulative allocation over the run: 10⁶ cells allocated in total, none of them simultaneously. That is a different quantity, and it is what an amortised space argument would bound.

A is the right class but hides the constant; D is the same as B written confusingly. B states the peak and its class together, which is the answer a marker wants.

This is the peak-against-cumulative distinction from the Edge cases tab, in its smallest form.

Revision sheet

Everything below is a definition, a computed number, or a rule with its condition stated. Nothing here is a claim about what the 2027 paper will contain.

Definitions

Space used on an input = the maximum, over all instants of the run, of the number of cells live at that instant.

Space complexity = that maximum, taken over the worst input of size n, expressed as a class of n.

Auxiliary space = the peak, excluding the memory that holds the input. Total space = the peak including it.

In place = one of three claims: O(1) auxiliary; O(log n) auxiliary with no copy of the array; or "the input array is the only array". Always say which.

Formulas worth memorising — with their conditions

Linear recursion, argument reduced by 1: depth $$n + 1$$, so Θ(n) space.

Balanced divide, argument halved: depth $$\lceil \log_2 n \rceil + 1$$, so Θ(log n).

Merge sort on an array: $$n + \lceil \log_2 n \rceil + 1 = \Theta(n)$$, the buffer dominating.

Quick sort, worst case: depth n, so Θ(n); median pivot: Θ(log n).

Naive Fibonacci: $$2\,F(n+1) - 1$$ calls and $$n$$ frames, since the chain stops at fib(1).

Graphs: matrix $$V^2$$ cells, list $$V + 2E$$ slots, BFS queue and DFS stack both O(V).

Decision procedure, and the traps to check against

1. Fix the model: one cell is one word, one frame is a constant.

2. Add what is live at the peak: buffers + traversal structure + stack depth × frame.

3. Add the input only if the question asks for total space; then keep the largest term.

Check 1. Did you count calls instead of frames? Did you read the tree's size instead of its height?

Check 2. Did "in place" make you answer Θ(1) for something with a Θ(n) stack?

Check 3. Did you answer total space where auxiliary was asked — or drop the +1 in ⌈log₂ n⌉ + 1?

Six questions to ask yourself in a minute

  1. What is the depth of the recursion, and what makes it that deep?
  2. Does the algorithm allocate anything proportional to the input?
  3. Are the buffer and the stack live at the same moment?
  4. Is the question asking for total space or for extra space?
  5. Does "in place" here mean O(1), O(log n), or "no copy"?
  6. Which term survived the simplification, and does the answer say so?
