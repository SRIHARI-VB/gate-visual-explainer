Topic and objective

TOPIC: Algorithm correctness for loops — the loop invariant, the three obligations (initialization, maintenance, exit), and the variant that proves termination.

LEARNING OBJECTIVE: Given a loop, name the sentence that is true at the top of every iteration, prove it in two steps, derive the answer from it at the exit, and name a positive integer that strictly decreases — then use those four sentences to decide whether a program terminates, whether it answers correctly, and what the exam's intended correction does and does not repair.

I read the request as the reasoning method behind the searching and sorting clause: not a survey of proofs, but one loop (binary search) and one non-search loop (the running maximum), each proved and then checked by exhaustive enumeration. Formal program logic (Hoare triples as a proof system, weakest preconditions) is named once and not developed.

Prerequisites

  • Sorted order and binary search. The lesson's main example is binary search; its mechanism is on Binary search and variants.
  • Induction. Initialization is the base case and maintenance is the step; the shape is on Mathematical induction.
  • Loop and array notation. Index from 0, A[i] is the value at position i, and a window is a pair of positions written [lo, hi].
  • Complexity as a separate claim. Best, average, worst and amortised.

Approximate time and what you will be able to do

About 45 minutes: 15 for the animation and the two loops, 15 for the examples, 15 for the practice set.

  • State an invariant in one sentence, and say why it is stated with “at least one occurrence”.
  • Prove initialization and maintenance in two paragraphs, not two pages.
  • Derive the postcondition from invariant plus not-guard.
  • Name a variant and show it strictly decreases.
  • Explain the GATE CSE 2008 item, and why its published correction is not the complete fix.

The five ideas

1. Termination, correctness and speed are three independent claims. 2. The invariant is true at the top of the loop, not on every line. 3. Invariant plus not-guard gives the answer; that is the whole exit argument. 4. Termination needs a different object: a positive integer that strictly decreases. 5. A correction that restores termination can leave the answer wrong, and only the invariant shows where.

Intuition: the sentence on the whiteboard

Think of a shop that checks its safe at opening, after every customer, and at closing. The check is the same sentence each time — the day's takings equal the sum of the receipts in the box — and it is checked at three moments, not continuously. Between checks, notes are being moved and the sentence is briefly neither true nor false of the half-sorted state; nobody cares, because the next check will either confirm it or catch the mistake.

A loop invariant is that sentence. It is checked before the loop starts and at the top of every iteration. If it survives both, it survives every number of iterations — and when the loop stops, the sentence plus the reason for stopping is the answer.

Formal definitions, every symbol in words

Precondition P: what is assumed true before the loop starts — here, that the array is sorted in non-decreasing order and that the target is a number.

Postcondition Q: what must be true after the loop — here, that the returned position holds the target, or that the target occurs nowhere.

Partial correctness: if the loop terminates, then Q holds. The “if” is not a weakness to be fixed; it is the definition.

Termination: on every input allowed by P, the loop stops after finitely many iterations.

Total correctness: partial correctness and termination together.

Loop invariant I: a statement true (i) before the first iteration and (ii) at the top of every iteration that is reached. Loop variant V: a quantity that is a positive integer at the top of every iteration and strictly smaller after the body than before it.

The three obligations, and what each one buys

1 Initialization. I holds before the first iteration. Buys: the base case of the induction.

2 Maintenance. If I holds at the top of an iteration and the body runs, I holds at the top of the next. Buys: the induction step, and hence I at every iteration.

3 Exit. When the guard fails, I together with the failed guard implies Q. Buys: the answer, with no testing.

4 Variant. V is a positive integer and strictly decreases. Buys: the ending. This is a separate obligation because it is a separate claim: obligations 1–3 never mention whether the loop stops.

Why “at least one occurrence”

The tempting invariant is “the occurrence of x is inside the window”. In a sorted array with duplicates there is no the occurrence: [1, 1, 1] searched for 1 has three.

The existential form — “if x occurs at all, some occurrence is inside the window” — is the one that survives duplicates, and it is exactly the statement the exit argument needs: an empty window then means no occurrence exists anywhere. Derivation

What is deliberately not developed here

Hoare logic as a formal proof system, weakest preconditions, and total-correctness calculi are the general theory behind these four obligations. They are named so that you know the words exist; they are not needed for any GATE question on searching or sorting, and nothing on this page depends on them. Educational interpretation

The array used everywhere on this page

A = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]   n = 10, positions 0 to 9

Every trace below is computed by lesson.js from this array, not typed from memory; the probe counts and window sizes printed in the captions are the same numbers the page checks.

Example 1 — a value that is present: x = 23

Window [0,9], size 10. Invariant: if 23 occurs, an occurrence is inside the window. True, since the window is everything.

Probe position 4: 16. 16 < 23 and the array is sorted, so every position at or below 4 holds at most 16. Window becomes [5,9], size 5. Justification: sortedness.

Probe position 7: 56. 56 > 23, so every position at or above 7 holds at least 56. Window becomes [5,6], size 2.

Probe position 5: 23. Equal, so the loop exits at the second exit — found — and no further argument is needed.

Answer: position 5, three probes. The invariant was true at four moments: before the loop and after each of the three probes.

Example 2 — a value that is absent: x = 3

Probe position 4: 16 > 3. Window [0,3], size 4.

Probe position 1: 5 > 3. Window [0,0], size 1.

Probe position 0: 2 < 3. Window becomes [1,0] — lo has passed hi — size 0.

Guard fails: 1 ≤ 0 is false, so the loop stops without finding anything.

Exit argument: the invariant says an occurrence would be inside [1,0]; that window is empty; therefore no occurrence exists. Answer: absent, three probes.

Example 3 — the same search, written as GATE CSE 2008 wrote it

i = 0; j = 9; do { k = (i+j)/2; if (Y[k] < x) i = k; else j = k; } while (Y[k] != x && i < j);

Probe 4: 16 < 3? No — 16 > 3, so j = 4. Window [0,4], size 5.

Probe 2: 8. j = 2. Window [0,2], size 3.

Probe 1: 5. j = 1. Window [0,1], size 2.

Probe 0: 2 < 3, so i = 0 — unchanged. Window [0,1] again, size 2.

The state repeats, so the loop repeats, for ever. Window sizes 10, 5, 3, 2, 2, 2, … and the program never prints anything. This is a failure of termination, not of the answer.

Example 4 — a loop that is not a search: the running maximum

best = A[0]; for (i = 1; i < n; i++) if (A[i] > best) best = A[i];

Invariant: at the top of iteration i, best is the maximum of positions 0 to i−1.

Initialization: i = 1, the prefix is just position 0, and its maximum is A[0].

Maintenance: either A[i] is larger and best becomes it, or best already was the maximum of the longer prefix.

Exit: i = n, the prefix is the whole array, so best is the maximum.

Variant: n − i, which falls by one each iteration.

On [3, 9, 4, 7, 1, 8] the best values are 3, 9, 9, 9, 9, 9 — each checked against a direct scan of the prefix in code.

The empty array

n = 0 gives lo = 0 and hi = −1, so the guard is false before the body ever runs. The invariant is true (the empty window holds everything there is: nothing), and the answer is “absent”.

The 2008 program is a do–while, so it runs the body once before testing the guard: with n = 0 it computes k = (0 + (−1))/2, which in C truncates towards zero and gives 0, and reads Y[0] of an empty array. A do–while cannot be guarded at the top, which is one reason the invariant argument is phrased for a while.

One element

lo = hi = 0, one probe, then lo = 1 or hi = −1. The window size goes 1, then 0: the variant argument is at its shortest and still works. This is exactly the case that the guard i < j in Example 3's program skips, and it is why option A of the 2008 question still reports present values as absent.

Duplicates: the smallest hang

Array [1, 1], target 2. The 2008 program sets i = 0, j = 1, computes k = 0, sees 1 < 2, and sets i = 0 again. The state repeats for ever.

Two elements are enough to hang the program, and the target does not even have to be present. Duplicates also show why the invariant must be existential: [1,1,1] searched for 1 has three occurrences, so “the occurrence” is not a well-defined phrase.

Target at the first or last position

The last position is the dangerous one. With option A alone, x = 91 is reported absent: the search ends with i = j = 9 and the guard i < j stops the loop before position 9 is compared.

On the ten-value array, option A alone answers wrongly for exactly four of the targets 0 to 99: 2, 12, 38 and 91 — the four values that end alone in a final window. Derivation computed in lesson.js.

Midpoint arithmetic

Written as (lo + hi) / 2, the sum overflows a 32-bit signed int once lo + hi exceeds 231−1 = 2,147,483,647 — which happens for arrays of roughly 1.07 billion elements. The sum then wraps negative, the computed mid is outside the window, and the loop reads out of range.

lo + (hi − lo) / 2 never exceeds hi, so it cannot overflow. Derivation from the range of a 32-bit signed integer; no claim is made about any particular compiler's optimiser.

The condition every claim here depends on

Sortedness. Every exclusion step — “everything at or below mid is at most A[mid]” — uses non-decreasing order and nothing else. On an unsorted array the loop still terminates (the variant argument is untouched) and still returns an index or −1, but the invariant is false and the answer is unreliable. Termination does not need sortedness; correctness does.

1. “The invariant must be true on every line of the loop body.”

Why it tempts: the name suggests a property of the loop, and a property of the loop sounds like a property of everything inside it.

Why it is wrong: while mid is being compared, the window is neither the old pair nor the new pair, so the sentence is not even meaningful there. It is asserted at the loop boundary.

Minimal counterexample: any correct binary search. At the instruction between mid = (lo+hi)/2 and the branch, the invariant is true; immediately after lo = mid + 1 it is true again; between them there is a moment when lo still equals the old value and hi has not yet moved, and the sentence is fine — but a stronger invariant such as “the window is exactly the candidates” would be false mid-update.

Correct rule: initialization plus maintenance, at the top of the loop. Nothing else is claimed.

2. “It never gives a wrong answer, so it is correct.”

Why it tempts: we test by comparing output, and a wrong answer is what a bug produces.

Why it is wrong: a hang produces no output at all. The 2008 program answers wrongly in 0 of 3,688 enumerated cases and fails to answer in 1,736 of them.

Minimal counterexample: [1, 1] with target 2 — two elements, no output, for ever.

Correct rule: count wrong answers and non-terminations separately. They are two obligations, not one.

3. “An invariant that is true is therefore useful.”

Why it tempts: it is true, it is at the top of the loop, and it satisfies the definition.

Why it is wrong: lo ≥ 0 is a perfectly true invariant of binary search, and it implies nothing about the answer. The exit argument needs an invariant that, conjoined with the failed guard, yields the postcondition.

Correct rule: choose the invariant backwards from the exit — ask what must be true when the guard fails for the answer to follow.

4. “A decreasing quantity is the invariant.”

Why it tempts: both are “the sentence about the loop”, and both are proved by induction on iterations.

Why it is wrong: they answer different questions. The invariant is a truth that is preserved; the variant is a number that falls. A variant proves nothing about the answer, and an invariant proves nothing about the ending.

Correct rule: two objects, two proofs. Invariant: true at the top, preserved. Variant: positive, strictly smaller after the body.

5. “It runs in O(log n), so it must be right.”

Why it seems reasonable: the complexity is the famous part of binary search, and the famous part is usually the examined part.

Why it is wrong: the 2008 program is also fast on the inputs where it stops. Complexity counts steps; it does not check that the steps compute the answer, and a fast wrong program is still wrong.

Correct rule: three separate claims — terminates, correct, fast — and a proof of one is not evidence for the others.

The pair most often confused

Partial correctness vs termination. Partial correctness is a conditional: if it stops, the answer is right. Termination is the unconditional part: it does stop. The 2008 program is the cleanest witness — partially correct on every case where it stops, and not terminating on 1,736 of 3,688.

Invariant vs postcondition. The postcondition is what you want at the end; the invariant is what you can maintain at every step. They meet only at the exit, and only because the guard has failed. Community observation Reported as a frequent confusion in discussion of the 2008 item; not measured.

Verified previous-year item: GATE CSE 2008, 2 marks, MCQ

Verified fact The program and the question below are reproduced from a paper reproduction of GATE CSE 2008 (2-mark MCQ); the year, the marks and the option set come from that source, not from memory. The options are paraphrased to one line each; the arithmetic and every count in the solution are this page's own computation.

f(int Y[10], int x) { int i, j, k; i = 0; j = 9;
do { k = (i+j)/2; if (Y[k] < x) i = k; else j = k; } while ((Y[k] != x) && (i < j));
if (Y[k] == x) printf("x is in the array"); else printf("x is not in the array"); }

Question: the program is erroneous. The correction needed to make it work properly is —

(A) change line 6 to if (Y[k] < x) i = k + 1; else j = k − 1;   (B) change the same line to i = k − 1 / j = k + 1   (C) change it to Y[k] <= x with i = k   (D) change the loop condition to while (Y[k] == x)

Answer: (A), which is the answer given by the reproducing source. Why: the probe k is kept inside the new window, so when j = i + 1 the midpoint is k = i and i = k leaves the window unchanged — the state repeats for ever. Excluding the probe makes the window strictly smaller, so the variant argument goes through. (B) moves the bounds the wrong way; (C) leaves the window [k, k+1] intact; (D) stops after the first probe that misses.

What the item does not say, and this page does: with (A) alone, the guard i < j still skips a window of one position, so 407 of 1,260 present targets are reported absent. A complete fix also changes the guard to i ≤ j, after which the missed count is 0. Derivation computed here over the 3,688-case enumeration.

Categories that apply

  • B — property verification. “Is this program correct?” Given a listing, decide whether it terminates and whether the answer follows.
  • C — calculation. How many probes, how many iterations, which state repeats, how many cases hang.
  • D — construction. “Give the correction”: produce the rewrite that restores an obligation.
  • E — counterexample reasoning. One array kills a proposed invariant or a proposed correction.
  • F — multiple conditions. Termination and correctness together; repairing one and not the other is the trap in the 2008 item.
  • G — misconception trap. “It never gives a wrong answer” is true of the 2008 program and irrelevant.
  • H — multi-step reasoning. Trace, then name the repeated state, then say which obligation failed.

The reasoning each pattern demands

  • “What does this print?” Trace to the exit, then state the invariant at the exit and read the answer off it. If the trace does not end in a few steps, suspect a repeat.
  • “How many times does the loop run?” Count iterations of the variant, not lines of code. For binary search the size halves, so the count is ⌈log₂(n+1)⌉.
  • “Which of these is a loop invariant?” Test each candidate twice: true before the loop, and preserved by the body. A candidate that fails preservation is out however plausible it sounds.
  • “Find the error” Check the three obligations in order. Termination failures show up as a window that stops shrinking; correctness failures show up as an exit whose window is not empty.

The common wrong approach

Reading the program and running one example in your head. On the 2008 program, one example with a present target looks fine — the trace ends and prints “in the array”. The defect lives in the cases nobody tries: absent targets, and present targets that end alone in a window.

Do this instead: ask what the loop keeps true, and what shrinks. Both answers are checkable in a minute and neither needs an example.

MCQ Original Q1 · basic

A loop invariant is a statement that must be true

(A) on every line of the loop body   (B) before the first iteration and at the top of every iteration   (C) only after the loop ends   (D) only when the loop terminates normally

Answer: (B). That is the definition, and it is what makes initialization plus maintenance an induction.

(A) is the most common misreading: the window is mid-update between the two boundary moments. (C) describes the postcondition. (D) adds a condition the definition does not have — the invariant is what the exit argument uses, so it must hold even when the loop ends by the guard failing.

NAT Original Q2 · basic

A sorted array has 1000 elements. The while-loop binary search on this page makes at most ______ probes.

Answer as an integer.

Answer: 10. The window size is at most 1000 and each probe at least halves it, so the count is ⌈log₂ 1000⌉ = 10, and 210 = 1024 ≥ 1000 confirms the ceiling.

9 is the floor of log₂ 1000 and is the usual wrong answer: with 29 = 512 a thousand elements cannot be covered. 11 comes from counting the failed final comparison as a probe.

MCQ Original Q3 · basic

In while (lo <= hi) { mid = (lo+hi)/2; ... } with lo = mid+1 or hi = mid−1, which quantity is the loop variant?

(A) hi − lo + 1   (B) mid   (C) A[mid]   (D) the number of values found so far

Answer: (A). It is a positive integer at the top of every iteration and it strictly decreases by at least one.

(B) moves both up and down. (C) is not a measure of progress at all — it is the data. (D) stays 0 until the loop ends, so it never decreases.

NAT Original Q4 · application

With A = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], the correct while-loop binary search for x = 56 makes ______ probes.

Answer: 2. Window [0,9], probe 4 (16 < 56) moves lo to 5; window [5,9], probe 7 gives 56 and the loop exits.

3 is the answer for a search that keeps the probe inside the window. 1 is the answer if you assume the midpoint lands on the target, which it does only for position 4 of a ten-element array.

MCQ Original Q5 · application

The GATE CSE 2008 program searches the ten-value array for x = 3. Which pair (i, j) repeats for ever?

(A) i = 0, j = 1   (B) i = 1, j = 1   (C) i = 0, j = 0   (D) i = 2, j = 2

Answer: (A). At i = 0, j = 1 the midpoint is 0, A[0] = 2 < 3, so i is set to k = 0 — unchanged. The guard i < j is still true, so the body runs again with the same state.

(B) and (D) are states the loop never reaches: once i = j the guard fails and the loop stops. (C) is the correct search's final state, not this program's.

NAT Original Q6 · application

Take option (A) of the 2008 question only — i = k+1 / j = k−1 with the guard still i < j. On the ten-value array, for how many of the targets 0, 1, …, 99 does it answer wrongly?

Answer: 4. The targets 2, 12, 38 and 91 — the four values of the array that end alone in a final window. All four are present and all four are reported absent.

0 is the answer if you assume the published correction is complete. 10 is what you get by counting the array's length instead of the failing positions.

MSQ Original Q7 · conceptual

Which of the following statements are true?

(A) Total correctness is partial correctness together with termination.   (B) A loop that never terminates is not partially correct.   (C) A positive integer that strictly decreases every iteration proves termination.   (D) An invariant that holds at the top of every iteration implies the postcondition on its own.

Answer: (A) and (C).

(B) is false by the definition: partial correctness is a conditional statement, and a loop that never stops satisfies it vacuously. (D) is false because the invariant needs the failed guard as well — lo ≥ 0 holds for ever and implies nothing.

MCQ Original Q8 · conceptual

The binary-search invariant is stated as “if x occurs, at least one occurrence is inside the window” rather than “the occurrence of x is inside the window”. The reason is that

(A) the array may contain duplicates   (B) the target may be absent   (C) mid may equal lo   (D) the loop may fail to terminate

Answer: (A). With duplicates there is no unique occurrence, so the definite article is not defined. In [1,1,1] searched for 1, all three positions qualify.

(B) is handled by the “if x occurs” clause, which makes the statement vacuously true; that is a separate matter from the existential. (C) and (D) are unrelated to the wording.

MCQ Original Q9 · conceptual

A program passes 500 tests and fails on the 501st. Which claim is refuted?

(A) the program is partially correct   (B) the program terminates on every input   (C) the program is correct on all inputs   (D) the program runs in O(log n)

Answer: (C). One failing input refutes a universal claim, and “correct on all inputs” is a universal claim.

(A) is not refuted: the failing run terminated and gave a wrong answer, which refutes correctness but not the conditional form. (B) needs a non-terminating run, not a wrong one. (D) is a complexity claim, untouched by a wrong answer.

MCQ Original Q10 · tricky

Over all 3,688 enumerated cases, the 2008 program sometimes halts. When it halts, can it report “x is not in the array” for a value that is present?

(A) never   (B) sometimes, for values at the last position   (C) always, when the array has duplicates   (D) only when x is larger than every element

Answer: (A). The computed count of wrong answers among halted runs is 0. The program's failure is termination: it either finds the value or hangs.

This is the item's trap. “Never answers wrongly” is true and useless — 1,736 of the 3,688 cases produce no answer at all. (B) confuses this program with option (A) of the 2008 question, which does miss the last position.

NAT Original Q11 · tricky

Of the 1,260 enumerated cases in which the target is present, the 2008 program fails to answer in ______ of them.

Answer: 246. One case in five of the present cases hangs; the remaining 1,014 halt and are all correct.

0 is the trap answer, from counting only wrong outputs. 1,490 is the corresponding count for absent targets, which is the larger and less obvious number.

MSQ Original Q12 · tricky

For the exit argument “invariant and not-guard imply the postcondition” to be valid, which of the following are necessary?

(A) the invariant is true at the top of the iteration after which the loop exits   (B) the guard is false at the moment of exit   (C) the variant strictly decreases   (D) the loop body executes at least once

Answer: (A) and (B). Those are the two premises of the implication, and both must be true at the exit.

(C) belongs to the termination argument, which is a separate obligation. (D) is false: an empty array exits on the first test of the guard, and the argument still works — which is precisely why a while loop is easier to reason about than the do–while of the 2008 program.

Definitions in one line each

  • Partial correctness: if it stops, the answer is right.
  • Termination: it stops on every allowed input.
  • Total correctness: both.
  • Invariant: true before the loop and at the top of every iteration.
  • Variant: a positive integer that strictly decreases every iteration.

The decision procedure

  1. Write the postcondition: what must be true when the loop ends.
  2. Guess the invariant backwards from it: what, plus the failed guard, gives it.
  3. Check initialization: true before the first iteration.
  4. Check maintenance: every branch of the body re-establishes it.
  5. Name the variant and show it decreases, on every branch.
  6. Only then trace an example — the trace checks arithmetic, not the argument.

The numbers on this page

3,688 enumerated cases · 0 invariant violations · 8,091 probes · at most 3 probes per search for length ≤ 5 · 2008 program hangs 246 of 1,260 present and 1,490 of 2,428 absent · 0 wrong answers when it halts · option A alone misses 407 of 1,260 · complete fix misses 0 · 36,288,000 test cases for one array length.

Traps, with the counterexample that defuses each

  • “No wrong answers, so correct” — [1,1] with target 2 hangs.
  • “The correction fixes it” — option A misses 91 on the ten-value array.
  • “Any true invariant will do” — lo ≥ 0 proves nothing.
  • “The invariant holds on every line” — it holds at the loop boundary only.
  • “O(log n) implies correct” — the 2008 program is fast when it stops.

Six quick questions

  1. State the binary-search invariant in one sentence. — If x occurs, some occurrence is in [lo,hi].
  2. What does the exit argument need besides the invariant? — That the guard failed.
  3. Name the variant of binary search. — hi − lo + 1.
  4. Name the variant of the running-maximum loop. — n − i.
  5. Which obligation does the 2008 program fail? — Termination; the window stops shrinking.
  6. Which obligation does option A alone still fail? — The exit: a window of one position is never examined.

What this lesson does not claim

The enumeration proves the stated counts for arrays of length 1 to 5 over the values 1 to 6 and targets 0 to 7. It is evidence, not a proof, for longer arrays — the proof for all lengths is the four-line argument, not the count. No claim is made about how often this topic appears in GATE papers.
