Topic and objective

TOPIC: File organisation and indexing — heap, sorted and hashed files; dense, sparse, clustered and unclustered indexes; the multilevel index; the structure of the B-tree and the B+ tree; insertion and deletion; and the cost of a query in block reads. This is the clause "File organization, indexing (e.g., B and B+ trees)" in Section 9 of the official GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Given a block size and the field sizes, compute the order of a B-tree or B+ tree node; given a maximum key count, compute the minimum occupancy; given an index, count the nodes a point query or a range query fetches; and carry out an insertion or a deletion with splits, borrows and merges while keeping every node within its bounds — with the reason, not by memory.

I read this topic as two computations and one structure, not a list of definitions. The two computations are the block equation and the occupancy rule; the structure is a tree whose nodes are disk blocks. Every question in this area is one of those three, and the lesson teaches them in that order.

Prerequisites

Read these first if any is unfamiliar. Each is a full lesson in this repository.

Trees, binary search trees and heaps — trees-bst-and-heaps. A B-tree is a search tree with more than two children, and the vocabulary of height, root and leaf is used unchanged.

Asymptotic complexity — asymptotic-complexity. The height bound of a B+ tree is a logarithm with the fan-out as its base, and the cost of a query is stated as a function of the height.

Relational algebra and SQL — relational-algebra-and-sql. An index exists to answer a selection and a range predicate faster; the lesson assumes you know what those predicates are.

Linked lists — linked-lists. The chain of leaf pointers is a linked list of blocks, and it is the reason a range scan is cheap.

The five ideas this lesson turns on

  1. Cost is counted in blocks. A node is a block. A query costs one block read per level plus one per extra leaf. Nothing else is being measured.
  2. Order is solved, not chosen. A node must fit in a block, so the order is a floor of a ratio of byte sizes. Every order question is one inequality.
  3. Occupancy is order arithmetic. Maximum keys are order minus one; the minimum for a non-root node is ceil(order/2) - 1; the root is exempt.
  4. The B+ tree moves every record pointer to the leaves. That single change raises the fan-out, shortens the tree, and creates the leaf chain that makes range scans sequential.
  5. A separator is a copy. The key above a leaf duplicates a key in it, so key slots outnumber keys — and the number of records is the number of leaf entries, never the total.

Intuition: the library and the card catalogue

A library keeps its books on shelves in no particular order. To find one book you walk the shelves. That is a heap file, and the walk is the cost.

A card catalogue is a small set of drawers listing title and shelf position, in alphabetical order. You look up the card, then go straight to the shelf. The catalogue is the index: it holds one column plus an address, so it is far smaller than the shelves.

Educational interpretation The analogy carries the cost argument, not the structure. What makes the catalogue fast is not that it is alphabetical; it is that it is small enough to search in three steps.

Formal definition: what a file is

A file is a sequence of records, stored in blocks of a fixed size, read from disk one block at a time. The blocking factor is the number of records that fit in one block.

blocking factor = floor(block size / record size)How many records share one disk read. It is a floor: a partial record does not fit.

File organisation is the rule that decides which block a record goes in:

— heap: any block with free space. Insert is one block; search is a full scan.
— sequential (sorted): records kept in key order. Search is a binary search; an insert may have to move records across blocks.
— hashed: block chosen by a hash of the key. Equality lookup is one block; a range query is useless.

Verified fact The syllabus names file organisation as a separate item from indexing. They are separate decisions: a file can be a heap and still carry an index.

Formal definition: what an index is

An index is a file of entries, each holding a search key and a pointer to where the record (or the block) lives, kept sorted on the search key.

Four adjectives describe it, and they are two independent pairs:

Dense / sparse — how many entries. Dense: one per record. Sparse: one per block, holding that block's first key.

Clustered / unclustered — whether the file order matches the key order. Clustered (also called primary): the file is sorted on this key, so matches sit in neighbouring blocks. Unclustered (secondary): the records are scattered.

Mathematical derivation A sparse index requires a sorted file. Without order, the entries would not delimit blocks: you could not tell which block a key between two entries fell into.

Level 4, worked once: why an index is cheap

One million records, one hundred per block, so ten thousand data blocks.

  1. No index: expected half the file. 5,000 block reads.
  2. Index entry: key plus block pointer. On the GATE 2020 figures, one block holds 204 entries.
  3. Leaves needed: ceil(106/204) = 4,902.
  4. Internal nodes at order 205: ceil(4,902/205) = 24, then ceil(24/205) = 1 root.
  5. Three index levels, then one read for the record. 4 block reads.

The ratio, about 1,250 to 1, is the entire argument for the rest of the lesson. Every number in step 2 onwards is computed by the model on this page.

The sentence this page earns

An index is fast because it is small and sorted, not because it is clever: three levels of it replace five thousand reads.

Build-up, page 2 of 2 — the two trees, precisely

Page 1 said why an index exists. This page says what a B-tree and a B+ tree are, and gives the occupancy and height bounds the questions test.

Definition: order and occupancy

The order p of a B-tree or B+ tree is the maximum number of children a node may have. A node of order p therefore holds at most p - 1 keys and p child pointers.

The model in this lesson is parameterised by the minimum degree t instead, because the bounds are then unambiguous:

max keys = 2t - 1    min keys (non-root) = t - 1Two ways of saying the same thing: order p = 2t, so max keys = p - 1 and min keys = ceil(p/2) - 1.

Mathematical derivation ceil(p/2) - 1 with p = 2t gives t - 1. Both formulas are the same rule; the second is easier to apply without an off-by-one.

Definition: the B-tree

A B-tree of order p is a search tree in which:

— every node holds at most p - 1 keys in sorted order and at most p children;
— every key carries a record pointer, in internal nodes as well as leaves;
— a key appears exactly once in the whole tree;
— every leaf is at the same depth;
— every non-root node holds at least ceil(p/2) - 1 keys.

Verified fact "Same depth" is what the word balanced means here. GATE 2016 Set 2 asks for exactly this and keys the option "the lengths of the paths from the root to all leaf nodes are all equal".

Definition: the B+ tree

A B+ tree is a B-tree in which:

— every record pointer lives in a leaf; internal nodes hold only keys and child pointers;
— the leaves hold all (key, record pointer) entries, in key order;
— the leaves are chained left to right by pointers;
— a key may therefore appear twice: once in a leaf and once as a separator above it.

The separator rule, which the questions depend on:

keys[j] = smallest key in the subtree of children[j+1]The key copied up is the smallest key of the new right node. So "at least the separator" means "go right".

Verified fact GATE 2025 Set 2 states this rule in the question: "when a leaf is created, the smallest key in it is copied up into its parent". The model on this page uses exactly that convention.

The height bound, computed

For order p and height h (a root alone counts as height 1), a B+ tree packed full holds

max keys = (p - 1) · ph-1Every leaf holds p-1 keys, and there are p^(h-1) leaves when every internal node is full.

and a B+ tree at its emptiest holds

min keys = ceil(p/2)h-1 · (ceil(p/2) - 1)Every internal node keeps only its minimum number of children, and every leaf only its minimum number of keys.

Mathematical derivation Both are computed by the model, and the lesson's own tree is checked against them: nine keys at order 4 lie between the minimum of 2 and the maximum of 12 for height 2, which is why its height is 2 and not 1 or 3.

The sentence this page earns

Both structures are search trees of blocks; the only structural difference that matters is where the record pointers live, and every cost difference follows from it.

Worked examples, page 1 of 2 — the block equation, four times

Each step carries its justification. Every number below is computed by the model on this page and printed on the canvas in the same scene.

Example 1 — internal node keys, GATE CSE 2015 Set 3

Search key 12 bytes, block 1024 bytes, record pointer 10 bytes, block pointer 8 bytes. Maximum keys in a non-leaf node?

  1. A non-leaf node of order p holds p block pointers and p - 1 keys. No record pointers — they are all in the leaves.
  2. Bytes: 8p + 12(p - 1) ≤ 1024.
  3. 20p - 12 ≤ 1024, so 20p ≤ 1036, so p ≤ 51.8.
  4. Floor: p = 51. Keys: 51 - 1 = 50.
50The paper's key. The 10-byte record pointer is a decoy: including it gives order 34 and 33 keys.

Verified fact Reported as Q46 of GATE CSE 2015 Set 3 by one archive and Q56 by another; the year and set are agreed, the question number is not. Answer 50.

Example 2 — leaf order, GATE CSE 2007

Block 1K = 1024 bytes, data record pointer 7 bytes, value field 9 bytes, block pointer 6 bytes. Order of a leaf node?

  1. A leaf entry is a (value, record pointer) pair, so 16 bytes each.
  2. Plus one pointer to the next leaf: 6 bytes, counted once.
  3. 16n + 6 ≤ 1024, so 16n ≤ 1018.
  4. n ≤ 63.625, so n = 63.
63Forgetting the single chain pointer gives 64, which is option B in the original paper and is wrong.

Verified fact GATE CSE 2007, Q42. Answer 63.

Example 3 — levels and accesses, GATE CSE 2020

Block 4 KB = 4096 bytes, search key 12 bytes, tree/disk pointer 8 bytes, one million records, each record in one block. Minimum disk accesses to retrieve any record?

  1. Internal order: 8p + 12(p-1) ≤ 4096 gives p ≤ 205.4, so p = 205.
  2. Leaf capacity: 20n + 8 ≤ 4096 gives n = 204.
  3. Leaves: ceil(106/204) = 4,902. Above them ceil(4,902/205) = 24, then one root.
  4. Three index levels, then one read for the record's block.
3 + 1 = 4Three index blocks plus the record. Answering 3 forgets the record itself.

Verified fact GATE CSE 2020, Q54. Answer 4.

Example 4 — occupancy, GATE CSE 2010

A B+ tree in which the maximum number of keys in a node is 5. Minimum number of keys in any non-root node?

  1. Maximum keys 5 means maximum children 6, so the order is 6.
  2. Minimum children for a non-root node: ceil(6/2) = 3.
  3. Minimum keys: children minus one, so 3 - 1 = 2.
2Answering 3 is the child count. Answering 4 assumes the maximum, not the minimum.

Verified fact GATE CSE 2010, Q18. Answer 2, option (B).

Worked examples, page 2 of 2 — counting nodes fetched

The second computation: not how wide a node is, but how many nodes a query touches.

Example 5 — a range query, GATE CSE 2015 Set 2

A B+ tree index of order 1, with leaves [1,3] [5,7] [9,11] [13,15], internal nodes [5] and [13], and root [9]. Minimum nodes fetched for 7 ≤ key < 15?

  1. Root [9]: 7 < 9, so go left. 1 node.
  2. [5]: 7 ≥ 5, so go right. 2 nodes.
  3. Leaf [5,7] holds the lower bound. 3 nodes.
  4. Follow the chain to [9,11]. 4 nodes.
  5. Follow the chain to [13,15], needed for 13. 5 nodes.
53 in the descent, 2 more from the chain. Keys returned: 7, 9, 11, 13.

Verified fact GATE CSE 2015 Set 2. Answer 5. The model rebuilds this index and runs the traversal: it fetches 5 nodes and returns exactly 7, 9, 11 and 13.

Example 6 — a point query on the same index

Same tree, searching for key 11.

  1. Root [9]: 11 ≥ 9, go right.
  2. [13]: 11 < 13, go left.
  3. Leaf [9,11]: found.
3 nodes = the heightA point query costs exactly the height, because no B+ tree search can end above the leaves.

Mathematical derivation This is not a coincidence of this tree: with no record pointer above the leaf level, every search must reach a leaf, so every search costs the height. The model checks that the measured count equals the height for this index.

Example 7 — dense against sparse, on one file

A sorted file of 10,000 records, 50 records per block.

  1. Dense index: one entry per record, so 10,000 entries.
  2. Sparse index: one entry per block, so 10,000/50 = 200 entries.
  3. Both answer an equality query in the same number of index levels, but the sparse index is 50 times shorter, so its tree is shallower.

Mathematical derivation The saving is exactly the blocking factor, because a sparse entry replaces a whole block's worth of dense entries. The condition is that the file is sorted: on a heap file the 200 entries would not delimit anything.

Example 8 — how many keys fit at a given height

A B+ tree of order 100, height 3.

  1. Full internal nodes: each has 100 children, so 1002 = 10,000 leaves.
  2. Each leaf holds 100 - 1 = 99 keys.
  3. Total: 99 × 10,000 = 990,000 keys in three levels.
  4. At the other extreme, every node at its minimum: 502 × 49 = 122,500 keys.
122,500 ≤ keys ≤ 990,000Any key count in this range is consistent with height 3. Below 99,001 keys, height 2 may suffice.

Mathematical derivation Both bounds are computed by the model from the two formulas on the Build-up tab, and checked against the lesson's own nine-key tree, whose count lies between the height-2 bounds of 2 and 12.

Edge cases — where the rules stop applying, and what breaks

Each card states the boundary, the condition that fails, and what the correct answer becomes. Every counterexample is recomputed by the model.

The root is exempt from the occupancy rule

A non-root node must hold at least ceil(p/2) - 1 keys. The root must not: a two-level tree needs a root with a single key and two children.

The lesson's own tree is exactly this case. Its root holds one key, 40, and two children — below the minimum for a non-root node, and correct.

Verified fact GATE CSE 2024 Set 1 asks which node the half-full requirement is relaxed for, and keys "only the root node".

A sparse index over a heap file does not exist

Sparse means one entry per block. It works only if the file is sorted on the key, so that each block owns a contiguous key range.

In a heap file the records in a block are unrelated in key order, so no single entry can stand for the block. The only legal index is dense.

Mathematical derivation A sparse lookup works by finding the last entry at or below the key, then scanning that one block. Without order, "the last entry at or below" does not identify the block.

An open upper bound still costs the last leaf

For 7 ≤ key < 15 on the GATE 2015 Set 2 index, the leaf [13,15] must be read because it holds 13. Fifteen itself is excluded, and that is irrelevant.

Change the bound to < 13 and the answer becomes 4. Change it to ≤ 15 and the answer stays 5, because 15 is already in a leaf that was read.

Mathematical derivation The cost is the number of leaves whose key range intersects the query range. The last leaf's range is [13, 15], which intersects [7,15) because of 13.

The leaf equation has exactly one chain pointer

A leaf of a B+ tree carries a pointer to the next leaf. It is counted once per node, not once per entry, and the last leaf carries none — but the capacity is computed for the worst case, so it is always subtracted.

GATE 2007 turns on exactly 6 bytes: 16n + 6 ≤ 1024 gives 63, while 16n ≤ 1024 gives 64.

Verified fact GATE CSE 2007, Q42. The options include both 63 and 64.

Two textbooks, two definitions of "order"

Most GATE material defines order as the maximum number of children. Some texts define it as the maximum number of keys. Under the first, a node of order 5 has 4 keys; under the second, 5.

GATE 2005 says "B-tree of order 5 (maximum number of children a node can have is 5)" and asks for the maximum keys: 4. The paper disambiguates in the question, which is a signal that the examiners know the clash exists.

Community observation The clash is a recurring source of disagreement in published solution threads, which is why the wording of the question, not the textbook, decides.

A B-tree search can end early; a B+ tree search cannot

In a B-tree the record pointer sits beside the key in every node, so finding the key at an internal node ends the search. In a B+ tree the internal node holds no record pointer, so the search always continues to a leaf.

Consequence: in a B+ tree, a successful and an unsuccessful search cost the same number of blocks. In a B-tree they can differ.

Mathematical derivation The model measures this: a point query for a key that is absent costs the same as one for a key that is present, both equal to the height.

Duplicate keys break the separator rule

If the search key is not unique, two leaves can begin with the same value, and "the smallest key of the right node" no longer separates them: a lookup for that value cannot tell which leaf to enter.

Real systems index (key, record id) so the index key is unique. Every tree in this lesson uses distinct keys, which is why the rule is stated without qualification.

Mathematical derivation The separator rule needs strict ordering across the boundary. Equal boundary values satisfy "at least the separator" on both sides, so the descent is ambiguous.

An empty tree is one leaf, not zero levels

Deleting every key leaves a single empty leaf as the root. Height 1, no keys, no children. A tree with height 0 does not occur in this model.

The model deletes all nine keys of the lesson tree one at a time and checks the result: a single leaf with no keys, and every invariant still holding.

Mathematical derivation Counting height as the number of node levels, a root-only tree has height 1. The height-decrease event is a root contraction, which can only take height from 2 to 1.

Misconceptions — the wrong belief, why it tempts, and the smallest thing that refutes it

Each card gives one belief, the reason it feels right, a counterexample small enough to check by hand, and the rule to use instead.

1. "Order p means a node holds p keys"

Why it tempts: the word order is used loosely, and a node does hold about p things — but they are pointers.

Counterexample: a B-tree of order 5 has at most 4 keys. GATE 2005 asks exactly this, and 5 is an offered option.

Rule: order counts children. Maximum keys = order - 1. Say the sentence "order p, so p pointers and p-1 keys" before computing anything.

2. "The minimum keys per node is ceil(p/2)"

Why it tempts: the half-full rule is stated as a fraction of the node, and the fraction is of the pointers.

Counterexample: maximum keys 5, so order 6, so minimum children 3, so minimum keys 2 — not 3. GATE 2010 offers 3.

Rule: compute children first, then subtract one. In minimum-degree form, min keys = t - 1 with no subtraction to remember.

3. "A B+ tree stores each key once, like a B-tree"

Why it tempts: it is a search tree, and a search tree normally stores each key once.

Counterexample: the lesson's tree holds nine keys but 12 key slots — nine in the leaves and three separators. The model counts them.

Rule: the number of records is the number of leaf entries. Separators are copies. GATE 2025 Set 2's copy-up rule is the mechanism that creates them.

4. "Round the order to the nearest integer"

Why it tempts: 51.8 looks like 52, and 52 is a tidier number.

Counterexample: GATE 2015 Set 3 gives p ≤ 51.8. Order 52 needs 8(52) + 12(51) = 1028 bytes, which does not fit in 1024. The node would not exist.

Rule: floor, always. A capacity that does not fit is not a capacity. Then check the arithmetic by substitution.

5. "A B+ internal node needs a record pointer too"

Why it tempts: the question gives a record pointer size, so it must be used somewhere.

Counterexample: including the 10-byte record pointer in GATE 2015 Set 3 gives 30p - 22 ≤ 1024, so order 34 and 33 keys — not 50.

Rule: ask what the node holds before writing the equation. A B+ internal node holds keys and child pointers only. The record pointer appears only in a B-tree internal node, or in a B+ leaf.

6. "Balanced means the paths differ by at most one"

Why it tempts: that is what balanced means for an AVL tree, and the word is reused.

Counterexample: a B-tree's paths are equal, not nearly equal. GATE 2016 Set 2 offers "differ from each other by at most 1" as option B, and it is wrong.

Rule: every leaf at the same depth. That is why the worst-case search cost is exactly the height, with no slack term.

7. "Clustered and dense are the same property"

Why it tempts: both describe how an index relates to its file, and textbooks introduce them together.

Counterexample: a clustered index can be sparse (sorted file, one entry per block) and an unclustered index must be dense. Both combinations exist.

Rule: dense/sparse is about how many entries; clustered/unclustered is about whether the file order matches. Two questions, two answers.

8. "The animation is the proof"

Why it tempts: a picture of a tree that satisfies the bounds looks like a demonstration that it must.

Counterexample: a single correct tree proves nothing about all trees. The lesson's model instead validates every node against the invariant list after every operation, and reports the count under the canvas.

Rule: a picture is an example; the invariant check is the argument. State which one you are relying on.

GATE patterns — five question shapes, and the reasoning each one demands

This is not a forecast. It is a description of the shapes that have appeared, with the procedure each one rewards. No year is claimed for a shape unless a verified item is cited.

Shape 1 — order from byte sizes

Given block size, key size, pointer sizes, and a node type, find the order or the number of keys. Usually NAT, sometimes MCQ.

Reasoning demanded: decide what the node holds, write one inequality, floor it, then convert pointers to keys if asked.

Common wrong approach: using the leaf equation for an internal node, or including a record pointer that the node does not hold. Both produce an option that is present.

Shape 2 — occupancy and bounds

Given a maximum key count or an order, find the minimum keys, the maximum keys, or the number of nodes.

Reasoning demanded: convert to order, apply ceil(order/2) - 1, and exempt the root.

Common wrong approach: reporting the child count as the key count. GATE 2010 is this question with options 1, 2, 3, 4.

Shape 3 — count the nodes a query fetches

A drawn tree plus a range predicate, asking for the minimum nodes fetched. NAT.

Reasoning demanded: walk the descent comparing against the separators, then follow the chain while the leaf's range intersects the query, and stop as soon as a leaf begins at or above the upper bound.

Common wrong approach: counting only the leaves, or treating an open bound as closed. GATE 2015 Set 2 is this shape, and the answer is 5.

Shape 4 — disk accesses including the record

Fan-out, record count, and a request for the minimum accesses to retrieve a record.

Reasoning demanded: order, then leaf capacity, then levels, then add one for the record's block.

Common wrong approach: stopping at the index levels. GATE 2020 keys 4 where 3 is the tempting answer.

Shape 5 — insertion and deletion on a drawn tree

A small tree, one key inserted or deleted, then a question about what changed: the number of splits, whether the height rose, what a separator became.

Reasoning demanded: descend, insert, split on overflow copying the smallest key of the right node up, and propagate; for deletion, remove, then borrow before merging.

Common wrong approach: moving the separator instead of copying it, which changes a key in the leaf and breaks the search rule below.

Recently seen variants, described but not reproduced

GATE 2025 Set 1 carries an MSQ in which a value is inserted into a drawn B+ tree and the options ask whether a node splits, whether the node count changes, and whether the height rises. GATE 2025 Set 2 carries a NAT that asks for a particular separator value after an insertion, and states the copy-up rule explicitly.

I have not reproduced either question here, because I did not verify their figures node by node, and inventing a tree to match a remembered answer would be worse than omitting it. The shapes are what matters: both are Shape 5, and both are decided by the copy-up rule on the B+ tab.

The habit that covers all five

Before computing, write one sentence: "this node holds ___, so its bytes are ___." Every one of the five shapes is decided by that sentence being right.

MCQEasyPYQ — GATE CSE 2010, Q18

Consider a B+-tree in which the maximum number of keys in a node is 5. What is the minimum number of keys in any non-root node?

(A) 1   (B) 2   (C) 3   (D) 4

Answer: (B) 2

Maximum keys 5 means maximum children 6, so the order is 6. A non-root node must have at least ceil(6/2) = 3 children, and a node with 3 children has 2 keys.

Option (C) is the child count, not the key count. Option (A) is the minimum for the root. Option (D) would be the minimum if the rule were "at least two thirds full", which it is not. The model evaluates ceil(order/2) - 1 for every odd maximum from 3 to 31 and reports the same rule each time.

NATMediumPYQ — GATE CSE 2015 Set 3

Consider a B+ tree in which the search key is 12 bytes long, block size is 1024 bytes, record pointer is 10 bytes long and block pointer is 8 bytes long. The maximum number of keys that can be accommodated in each non-leaf node of the tree is ______.

Answer: 50

A non-leaf node holds p block pointers and p - 1 keys, and no record pointers. So 8p + 12(p - 1) ≤ 1024, giving 20p ≤ 1036 and p ≤ 51.8. Floor: p = 51, so keys = 50.

Two wrong routes, both available: including the 10-byte record pointer gives 30p - 22 ≤ 1024, order 34, 33 keys; rounding 51.8 up gives order 52, which needs 1028 bytes and does not fit. The model computes this from the field sizes rather than storing 50.

MCQMediumPYQ — GATE CSE 2007, Q42

The order of a leaf node in a B+ tree is the maximum number of (value, data record pointer) pairs it can hold. Given that the block size is 1K bytes, data record pointer is 7 bytes long, the value field is 9 bytes long and a block pointer is 6 bytes long, what is the order of the leaf node?

(A) 63   (B) 64   (C) 67   (D) 68

Answer: (A) 63

Each entry costs 9 + 7 = 16 bytes, and the leaf carries one 6-byte pointer to the next leaf. 16n + 6 ≤ 1024, so 16n ≤ 1018, so n ≤ 63.6, so 63.

Option (B) is the answer if the chain pointer is forgotten: 1024/16 = 64. Options (C) and (D) come from dropping the record pointer or the value field. The model solves the same inequality from the four sizes and floors it.

NATMediumPYQ — GATE CSE 2015 Set 2

With reference to the B+ tree index of order 1 shown below, the minimum number of nodes (including the root node) that must be fetched in order to satisfy the following query: "Get all records with a search key greater than or equal to 7 and less than 15" is ______.

The figure: leaves [1,3] [5,7] [9,11] [13,15] chained left to right; internal nodes [5] and [13]; root [9].

Answer: 5

Root [9] (1), then [5] because 7 < 9 (2), then the leaf [5,7] because 7 ≥ 5 (3), then the chain to [9,11] (4), then the chain to [13,15] (5). Keys returned: 7, 9, 11, 13.

Four is the tempting answer, and it is wrong because 13 lies in the last leaf even though 15 is excluded. Three counts only the leaves. The model rebuilds this exact index, runs the traversal, and reports 5 nodes fetched and the key list 7, 9, 11, 13.

NATHardPYQ — GATE CSE 2020, Q54

Consider a database implemented using B+ tree for file indexing and installed on a disk drive with block size of 4 KB. The size of search key is 12 bytes and the size of tree/disk pointer is 8 bytes. Assume that the database has one million records. Also assume that no node of the B+ tree and no records are present initially in main memory. Consider that each record fits into one disk block. The minimum number of disk accesses required to retrieve any record in the database is ______.

Answer: 4

Internal order 8p + 12(p-1) ≤ 4096 gives p = 205. Leaf capacity 20n + 8 ≤ 4096 gives n = 204. Leaves needed ceil(106/204) = 4,902; above them ceil(4,902/205) = 24 nodes, then one root. Three index levels, plus one read for the record block.

Three is the standard error: it stops at the leaf and forgets that the record lives in its own block. Two comes from assuming a two-level index. The model computes the order, the leaf capacity and the level count from the given sizes and reports 3 + 1.

MCQEasyPYQ — GATE CSE 2016 Set 2

B+ trees are considered balanced because

(A) the lengths of the paths from the root to all leaf nodes are all equal.
(B) the lengths of the paths from the root to all leaf nodes differ from each other by at most 1.
(C) the number of children of any two non-leaf sibling nodes differ by at most 1.
(D) the number of records in any two leaf nodes differ by at most 1.

Answer: (A)

The split and merge rules preserve one invariant about depth: all leaves sit at the same level. That is what makes the worst-case search cost exactly the height.

(B) is the AVL definition, imported by association. (C) and (D) are false even in a valid tree: a node may have 2 children beside a sibling with 5, and one leaf may hold 1 key beside a sibling holding 3. The model's own tree shows both — leaves hold two keys except the last, which holds three.

MCQEasyPYQ — GATE CSE 2024 Set 1

In a B+ tree, the requirement of at least half-full (50%) node occupancy is relaxed for which one of the following cases?

(A) Only the root node   (B) All leaf nodes   (C) All internal nodes   (D) Only the leftmost leaf node

Answer: (A) Only the root node

A two-level tree needs a root with one key and two children, which is below half of any order above 3. Every other node must respect the minimum, leaves and internal nodes alike.

(D) is a distractor built on the leaf chain: the leftmost leaf is not special, and it must meet the same minimum as any other. The model checks that its own tree's root holds one key while every non-root node holds at least one.

MCQEasyPYQ — GATE CSE 2005

Consider a B-tree of order 5 (maximum number of children a node can have is 5). What is the maximum number of keys that can be stored in a single node?

(A) 5   (B) 4   (C) 3   (D) 2

Answer: (B) 4

A node with p children separates them with p - 1 keys. With p = 5, that is 4.

Option (A) is the definition confusion this question is built to catch: order counts children, not keys. The question even parenthesises the definition, which tells you the examiners expect the confusion.

NATEasyOriginal practice — not a PYQ

A B+ tree is built with the rule that a node holds at most 7 keys. What is the minimum number of keys in a non-root node?

Answer: 3

Maximum keys 7 means order 8. Minimum children ceil(8/2) = 4, so minimum keys 4 - 1 = 3. In minimum-degree form, 2t - 1 = 7 gives t = 4, and t - 1 = 3.

The two forms must agree; if they do not, the order was computed from the wrong quantity. Here both give 3.

NATMediumOriginal practice — not a PYQ

An index is built on a file with block size 2048 bytes. The search key is 10 bytes and every pointer, whether a child pointer or a record pointer, is 6 bytes. A B+ tree is used, with 2 bytes reserved at the start of every node for its header. What is the maximum number of keys in a non-leaf node?

Answer: 127

Usable bytes: 2048 - 2 = 2046. A non-leaf node holds p child pointers and p - 1 keys: 6p + 10(p - 1) ≤ 2046, so 16p - 10 ≤ 2046, so 16p ≤ 2056, so p ≤ 128.5. Floor: p = 128 pointers, so 128 - 1 = 127 keys.

Check by substitution: 6(128) + 10(127) = 768 + 1270 = 2038 ≤ 2046. One more key needs 129 pointers and 128 keys: 774 + 1280 = 2054, which does not fit, so 127 is the maximum. Answering 128 forgets to subtract one for the key count; answering 129 also forgets the 2-byte header. The header must come out of the block before the inequality, not after.

MCQMediumOriginal practice — not a PYQ

A sorted file holds 10,000 records at 50 records per block. A dense index and a sparse index are both built on the key. How many entries does each have?

(A) dense 10,000, sparse 10,000
(B) dense 10,000, sparse 200
(C) dense 200, sparse 10,000
(D) dense 10,000, sparse 50

Answer: (B) dense 10,000, sparse 200

Dense: one entry per record, so 10,000. Sparse: one entry per block, and 10,000/50 = 200 blocks, so 200.

(D) confuses the blocking factor with the block count. (C) reverses the definitions. (A) is the belief that the two index types differ in nothing, which is misconception 7 on the previous tab in another form.

MSQMediumOriginal practice — not a PYQ

Which of the following statements are TRUE of a B+ tree used as a database index? Select all that apply.

(A) Every successful search fetches exactly one node per level, down to a leaf.
(B) The same key value may be stored in two different nodes.
(C) A search may terminate at an internal node when the key is found there.
(D) The total number of keys stored in the tree equals the number of records.

Answer: (A) and (B)

(A) is true because internal nodes carry no record pointer, so no search can end above the leaf level. (B) is true because a separator is a copy of a key that also sits in a leaf.

(C) describes a B-tree, not a B+ tree — the distinction the two structures turn on. (D) is false for the same reason as (B): the lesson's tree holds nine records in twelve key slots. The model counts both numbers and reports 9 and 12.

Revision sheet — one screen, everything load-bearing

Definitions, the two computations, the decision procedure, and the traps. Every number here is computed by the model on this page.

Definitions

Blocking factor = floor(block size / record size).

Order p = maximum children. A node has at most p - 1 keys and p pointers.

Dense = one entry per record. Sparse = one entry per block, and it requires a sorted file.

Clustered = file order matches key order. Unclustered = it does not.

B-tree: record pointers in every node; each key once; search may end at an internal node.

B+ tree: record pointers only in leaves; leaves chained; separators are copies; every search reaches a leaf.

The four equations

internal: p·ptr + (p-1)·key ≤ blockNo record pointer in a B+ internal node.
leaf: n·(key+recptr) + one chain ptr ≤ blockExactly one next-leaf pointer per node.
min keys = ceil(order/2) - 1Non-root nodes only. The root is exempt.
max keys at height h = (p-1)·ph-1All nodes full. Minimum is ceil(p/2)^(h-1) · (ceil(p/2)-1).

Order is always a floor. Keys are always one fewer than the pointers that hold them.

Decision procedure

  1. Name the node: internal or leaf, B-tree or B+ tree.
  2. Write its byte equation and floor the solution.
  3. Re-read what is asked: pointers, keys, or entries.
  4. Occupancy: order = max keys + 1, then ceil(order/2) - 1, root exempt.
  5. Cost: fan-out, then levels, then add one for the record block. For a drawn tree: descent plus extra leaves.

Insertion: descend, insert, split on overflow, copy the smallest key of the right node up, propagate; a root split is the only height increase. Deletion: remove, borrow from a sibling with spare keys, merge only if neither can spare, and contract the root when it empties.

Traps, in the order they cost marks

1. Forgetting the final record block — GATE 2020, answer 4 not 3.

2. Treating an open upper bound as closed — GATE 2015 Set 2, answer 5 not 4.

3. Reporting the child count as the key count — GATE 2010, answer 2 not 3.

4. Putting a record pointer in a B+ internal node — GATE 2015 Set 3, answer 50 not 33.

5. Forgetting the single leaf chain pointer — GATE 2007, answer 63 not 64.

6. Rounding the order up — 51.8 gives 51, because 52 does not fit in the block.

Three sentences worth memorising

A node is a block, so every question is a byte count.

A separator is a copy, so key slots outnumber keys.

A B+ tree spends its internal nodes on keys alone, and buys a shorter tree and a leaf chain with the duplication.

Textbook material

The structural definitions — order, occupancy, the separator convention, split and merge — follow the standard database-systems treatment (Silberschatz, Korth and Sudarshan; Elmasri and Navathe), which is also the source of the "smallest key of the right node" convention used throughout.

The minimum-degree formulation and the pre-emptive-split B-tree insertion follow the algorithms literature (Cormen, Leiserson, Rivest and Stein), which is where 2t - 1 and t - 1 come from. The two formulations are equivalent; the lesson uses the minimum-degree form internally because the bounds have no off-by-one.
