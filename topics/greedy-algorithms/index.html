Topic and objective

TOPIC: Greedy algorithms — the greedy-choice property, the exchange argument, and the four greedy problems GATE keeps asking about: activity selection, fractional knapsack, Huffman coding and unit-time job sequencing, with the two standard counterexamples that show where greed fails.

LEARNING OBJECTIVE: Given a problem and a proposed rule, say whether the rule is a greedy rule at all, name the criterion it sorts on, and either produce the exchange step that proves it safe or produce a small instance that refutes it. Execute activity selection, fractional knapsack and Huffman coding by hand and report the right number. Distinguish fractional knapsack from 0/1 knapsack by naming the one word that changes and the one step of the proof it destroys.

I read this topic as one lesson on greedy only. The syllabus line is "greedy, dynamic programming and divide-and-conquer", which is three techniques and too much for one screen-based lesson. Dynamic programming gets its own lesson next, and divide-and-conquer recurrences are already solved in Recurrence Relations. This lesson covers the first third of the line and stops there, on purpose.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 5 of the official GATE 2027 CS syllabus (IIT Madras, CS_GATE2027_Syllabus.pdf) reads: "Algorithm design techniques: greedy, dynamic programming and divide-and-conquer." Greedy is the first of the three named techniques.

The same section also names "minimum spanning trees" and "shortest paths", which are Kruskal, Prim and Dijkstra — three greedy algorithms in disguise. Those are taught as algorithms in their own lesson; the greedy reasoning that makes them correct is taught here.

Class A means a question here is inside the declared boundary. It does not mean one is guaranteed in GATE 2027, and it says nothing about marks. The previous-year questions quoted in this lesson are observations about old papers, not a forecast.

Prerequisites

Four published lessons carry the machinery this one uses:

  • Asymptotic Complexity and Recurrences — why one sort plus one pass is O(n log n), and what "the sort dominates" means. Every running time in this lesson is read off that ladder.
  • Recursion — the exchange argument in scene 5 is an induction, and the subproblem after a greedy choice is a smaller instance of the same problem.
  • Trees, Binary Search Trees and Heaps — Huffman builds a binary tree, and the "merge the two lightest" step is a priority queue. The heap is why Huffman is n log n and not n^2.
  • Sorting Algorithms — every greedy algorithm in this lesson begins with a sort, and the comparison lower bound explains why that sort is usually the bottleneck.

No new mathematics is needed beyond elementary arithmetic and one idea: an exchange, which is a single swap inside a solution, not a new algorithm.

What you should be able to do afterwards

Answer any greedy question in this order: what is the criterion?, what makes the exchange step safe?, which instances does that hold on?

The most expensive mistake in this topic is treating "greedy" as a verdict about a problem instead of a claim about a rule. Fractional knapsack is solved by greedy; 0/1 knapsack, with the same items and the same capacity, is not. Nothing about the problem changed except divisibility, and the whole proof depended on it.

Level 1 — Intuition: packing a bag in one pass

You already run a greedy algorithm every morning. You have a bag of a fixed size and a pile of things to carry. You pick the most useful thing that still fits, then the next most useful that still fits, and you stop when nothing more fits. You never unpack to reconsider.

That procedure has three parts: a rule that ranks the things, a check that the next thing fits, and a commitment. The rule is the whole of the algorithm's intelligence. Everything else is bookkeeping.

Educational interpretation The bag is exact for knapsack and only an analogy for activity selection, where "fits" means "does not overlap in time" rather than "does not exceed a weight". The shared shape — rank, check, commit — is the part that transfers.

Level 2 — The formal definition

An optimisation problem asks for a feasible solution of maximum or minimum value. A greedy algorithm for it builds the solution one element at a time; at each step it selects the element that maximises a fixed local measure among those that keep the partial solution feasible, adds it, and never removes it.

Two properties are then named separately:

Optimal substructure. An optimal solution to the whole problem contains optimal solutions to the subproblems that remain after any first choice.

Greedy-choice property. There exists an optimal solution that makes the choice the greedy rule makes first. Equivalently: some optimal solution agrees with greedy at the first step.

Verified fact These are the standard definitions; both properties, and the exchange argument that establishes the second, are developed in CLRS Chapter 16 (Greedy Algorithms), §16.1–16.2, and in the Cal Poly and Oakland University lecture notes listed in the Sources tab.

Level 3 — The picture that carries the mechanism

Draw a solution as a row of slots. Greedy fills slot 1 with its best choice, then slot 2, and so on, moving only rightward. An optimal solution fills the same slots, possibly differently.

The exchange argument is then a statement about two rows: find the first slot where they differ, and swap the optimal row's entry for greedy's. If the swap preserves feasibility and does not reduce the value, the rows can be made to agree slot by slot, which means greedy's value is optimal.

The picture also shows why the proof can fail: if the swap can break feasibility, or if no swap exists because the entries are not interchangeable, the argument stops. Scene 7 is exactly that failure.

Level 4 — Worked example: activity selection

Eleven activities: a1 [1,4], a2 [3,5], a3 [0,6], a4 [5,7], a5 [3,9], a6 [5,9], a7 [6,10], a8 [8,11], a9 [8,12], a10 [2,14], a11 [12,16].

Sort by finish time — the list above is already in that order. Take a1, last finish 4. a2 starts at 3, rejected. a3 starts at 0, rejected. a4 starts at 5, kept, last finish 7. a5 starts at 3, rejected. a6 starts at 5, rejected. a7 starts at 6, rejected. a8 starts at 8, kept, last finish 11. a9 starts at 8, rejected. a10 starts at 2, rejected. a11 starts at 12, kept.

Answer: a1, a4, a8, a11, four activities. Mathematical derivation The page enumerates all 2048 subsets of the eleven activities, filters to compatible families, and confirms that four is the maximum and that this family is the only one of size four. The enumeration is evidence about this instance, not a proof about all instances — scene 5 supplies that.

Level 5 — Boundaries: when the concept applies

A greedy algorithm is a candidate only when the problem has a numerical objective and its solutions can be built by a sequence of decisions. Three conditions decide whether it is correct:

  • The subproblem must be an instance of the same problem. After activity selection takes a1, what remains is activity selection on the activities starting at or after 4. That closure is what lets the induction run.
  • The swap must preserve feasibility. In fractional knapsack you can move any amount of value between items, because any fraction is legal. In 0/1 knapsack you cannot.
  • The local measure must be the right one. Finish time works for activity selection; duration and start time do not. Value per unit weight works for fractional knapsack; total value does not.

Drop any one and the algorithm still runs, still returns a feasible answer, and is simply no longer guaranteed to be optimal. A feasible wrong answer is the normal failure mode of a greedy algorithm, which is why testing it on the sample input is not enough.

Level 6 — Edge cases that change the answer

Intervals that touch. If a1 finishes at 4 and a4 starts at 4, they are compatible when intervals are half-open. Treat them as closed and the count changes. GATE questions state the convention or use strictly separated times; when they do not, say which convention you used.

Ties in the sort key. Two activities with the same finish time may be taken in either order, and both orders give the same count. Two items with the same value-per-weight ratio likewise. Ties change which optimal solution you get, not its value.

Everything fits. If the total weight is at most the capacity, fractional and 0/1 knapsack agree: take everything. The counterexample needs a capacity that forces a choice.

One item. With a single item, greedy and DP agree on both knapsacks. Counterexamples need at least three items, because with two the ratio rule can only pick the better one.

Equal Huffman weights. When several symbols tie, several trees are valid, all with the same cost. A question that asks for the minimum length is well posed; one that asks for "the" code may not be.

Level 7 — Two counterexamples you should be able to write from memory

Coins 1, 3, 4 for the amount 6. Largest-first gives 4 + 1 + 1, three coins. Two coins of 3 also pay 6. So largest-first is not optimal for this set. The same rule is optimal for 1, 2, 5, which is why the everyday habit feels safe.

Knapsack, capacity 50, items (10, 60), (20, 100), (30, 120). Ratio order is 6, 5, 4, so greedy takes the first two for 160 and 30 units of weight. The remaining 20 cannot hold the third item. Taking items 2 and 3 uses exactly 50 units and is worth 220. Greedy loses by 60.

Mathematical derivation The page computes both, including the full DP table for the 0/1 instance, so the 220 is not quoted from a book but derived in front of you. Both instances are small enough to check by hand in an exam, which is exactly why they are the standard ones.

Level 8 — GATE application

Four question shapes appear, and they are answered by four different moves:

  • Execute it. "Run Huffman on these frequencies; give the average code length." The move is a table of merges, and the answer is the sum of the merge weights.
  • Classify it. "Which of these problems is solved optimally by a greedy algorithm?" The move is to test each candidate against a counterexample you already know.
  • Compare techniques. "Fractional knapsack is solved by X, 0/1 by Y." The move is to name divisibility, then say which property it breaks.
  • Cost it. "What is the running time of this greedy algorithm?" The move is to find the sort, because the sort dominates.

A fifth shape exists and is rarer: give a proof step and ask which property it establishes. There the answer is a name — optimal substructure, or greedy-choice property — and the words must be exact.

Level 9 — Consolidation

Four sentences carry the lesson. Greedy commits, so it is fast and it is fragile. Correctness needs the greedy-choice property, which is established by an exchange argument and never by examples. The exchange step needs a swap that preserves feasibility, and divisibility is the most common reason a swap exists. When the swap cannot be built, the problem is a dynamic-programming problem, not a broken greedy one.

Keep one table in your head: activity selection and fractional knapsack and Huffman are greedy with proofs; 0/1 knapsack and coin change with arbitrary sets are not; MST and Dijkstra are greedy because a cut or a non-negative weight makes the swap safe.

Example 1 — Huffman average length (GATE CSE 2007, 2-mark MCQ)

"Suppose the letters a, b, c, d, e, f have probabilities 1/2, 1/4, 1/8, 1/16, 1/32, 1/32 respectively. What is the average length of Huffman codes?" Options given in that paper were 2.0, 2.0625, 2.125 and 1.9375.

Merge the two lightest repeatedly, keeping a running total of the merge weights:

e+f = 1/16 → running 0.0625
d+(e+f) = 1/8 → running 0.1875
c+that = 1/4 → running 0.4375
b+that = 1/2 → running 0.9375
a+that = 1 → running 1.9375

The sum of the five merges is 1.9375, which is the average code length. Mathematical derivation The page recomputes this and checks it equals the sum over symbols of probability times depth, which is 1/2·1 + 1/4·2 + 1/8·3 + 1/16·4 + 1/32·5 + 1/32·5. Both routes give 1.9375. Note this equals the source entropy, which happens exactly when every probability is a power of one half.

Example 2 — Huffman on a short string (GATE CSE 2021, Set 2, MCQ)

"Consider the string aabbccddeee. Each letter must be assigned a binary code such that no code is a prefix of another, and among letters of equal frequency the earlier letter in dictionary order gets a code no longer than the later one. What is the minimum length of the encoded string?"

Frequencies: a = 1, b = c = d = 2, e = 3. Merge the two lightest, reinserting each parent:

1+2 = 3 → running 3
2+2 = 4 → running 7
3+3 = 6 → running 13
4+6 = 10 → running 23

The encoded string is 23 bits. Mathematical derivation The page computes the merges and checks the total two ways: sum of merge weights is 23, and the resulting depths give 1·3 + 2·3 + 2·2 + 2·2 + 3·1 = 23. The dictionary-order condition picks one of the tied trees; the length is the same for all of them.

Example 3 — Fractional knapsack, capacity 50

Items I1 (weight 10, value 60), I2 (20, 100), I3 (30, 120). Ratios: 6, 5, 4. Take I1 whole (value 60, weight 10), I2 whole (value 160, weight 30), then 20 of I3's 30 units, worth 120 × 20/30 = 80.

Total value 240, weight exactly 50, one partial item. Mathematical derivation The page computes this by the same ratio rule it draws, and separately verifies that no feasible assignment beats 240 by checking the two boundary cases: taking all of I3 first gives 120 + 20/10 of I1 = 120 + 120 = 240 as well. Both are optimal, which is a useful reminder that the optimal solution need not be unique even when the optimal value is.

Example 4 — The same items, 0/1 knapsack

Same three items, capacity 50, each item whole or not at all. The ratio rule takes I1 and I2: value 160, weight 30, and I3 does not fit. The DP table over capacities 0 to 50 gives a maximum of 220, attained by I2 + I3 (weight exactly 50).

Greedy is 60 short. Mathematical derivation The page fills the table row by row with the recurrence K(i,c) = max(K(i-1,c), v_i + K(i-1, c-w_i)) and reports the last cell. The gap is not a tie: 220 > 160, and no choice of tie-breaking in the ratio rule closes it, because the rule never considers the pair (I2, I3) at all.

Example 5 — Optimal merge pattern (GATE CSE 2014, Set 2)

"Suppose P, Q, R, S, T are sorted sequences having lengths 20, 24, 30, 35, 50. They are to be merged into a single sequence by merging two at a time. The number of comparisons needed in the worst case by the optimal algorithm is ______."

Merging runs of lengths m and n costs at most m + n − 1 comparisons. To minimise the total, always merge the two shortest remaining runs, which is the Huffman rule applied to lengths:

20+24 = 44 (43 comparisons)
30+35 = 65 (64)
44+50 = 94 (93)
65+94 = 159 (158)

Total 43 + 64 + 93 + 158 = 358. Verified fact This instance and the answer 358 come from the GATE CSE 2014 Set 2 paper; the arithmetic above is recomputed by the page. The reason the rule is optimal is Huffman's exchange argument, which is why this problem and Huffman coding share a lesson.

Example 6 — Unit-time job sequencing

Jobs with a deadline in slots and a profit: J1 (deadline 2, profit 100), J2 (1, 19), J3 (2, 27), J4 (1, 25), J5 (3, 15). Each job takes one slot, and a job must finish by its deadline.

Greedy: sort by profit descending (100, 27, 25, 19, 15), and give each job the latest free slot at or before its deadline. J1 takes slot 2. J3 takes slot 1. J4 finds slot 1 taken and no earlier slot, so it is dropped. J2 likewise dropped. J5 takes slot 3.

Schedule slots 1, 2, 3 = J3, J1, J5; profit 142. Mathematical derivation The page runs this and then checks the answer by enumerating every subset of jobs and every feasible assignment, confirming 142 is the maximum. Note the greedy rule here is highest profit first, not highest profit per slot, and it is safe because the feasible sets form a matroid.

Example 7 — Reading a running time off the structure

For each greedy algorithm, the cost is one sort plus one pass, unless a data structure is doing more:

  • Activity selection: sort by finish O(n log n), then one scan O(n). Total O(n log n).
  • Fractional knapsack: sort by ratio O(n log n), then one fill O(n). Total O(n log n).
  • Huffman: n-1 extract-two-and-insert steps on a heap, each O(log n). Total O(n log n), and no sort at all.
  • Job sequencing, simple version: sort O(n log n), then for each job a scan for a free slot, up to n steps. Total O(n^2).

The last one is the interesting case: the same greedy choice with a better data structure is faster, so a running time always belongs to an implementation, not to a rule.

Example 8 — Where the exchange step is written out in full

Claim: earliest-finish-time greedy is optimal for activity selection. Proof, in the four moves an exam expects:

1. Setup. Let S^* be an optimal solution, and let g be the activity of smallest finish time overall, which greedy takes first.

2. Case. If g ∈ S^*, continue. Otherwise let s be the member of S^* with the smallest finish time. Since g has the smallest finish time overall, f(g) ≤ f(s).

3. Swap. Form S' = S^* ∖ \{s\} \{g\}. Then |S'| = |S^*|. And S' is feasible: any activity of S^* other than s starts at or after f(s), hence at or after f(g), so it does not overlap g.

4. Induction. So some optimal solution contains g. What remains is activity selection on the activities starting at or after f(g), a strictly smaller instance, so the argument repeats. Mathematical derivation Each step is checked by the page against the eleven-activity instance, including that the swap preserves feasibility on every optimal solution of that instance.

Edge case 1 — Touching intervals

An activity [1,4] and an activity [4,7] share the instant 4. If intervals are half-open, they are compatible and the answer is 2. If they are closed, they conflict and the answer is 1.

GATE convention, where stated, is that a room freed at 4 can be used from 4. The exam-safe habit is to write the convention down before you count. The page's model uses half-open intervals, so the comparison is s ≥ f_{{last}} with equality allowed.

Edge case 2 — Ties in the criterion

Two activities with equal finish times: greedy may take either, and both give the same count. Two items with equal value per unit weight: the fractional value is the same either way. Several Huffman symbols with equal frequency: several trees, one cost.

A tie therefore changes which optimal answer you produce, never the optimal value. If an exam option claims a unique code or a unique optimal set, check for ties before accepting it.

Edge case 3 — Degenerate knapsack instances

If the total weight of all items is at most the capacity, both knapsacks return the sum of all values, and the fractional and 0/1 answers coincide. If one item's weight exceeds the capacity, it is dropped by both. If every item has the same ratio, any maximal packing is optimal for the fractional version, but not necessarily for 0/1.

A counterexample to the ratio rule needs a capacity that forces a genuine choice, which means at least three items with different ratios, and a capacity that no two highest-ratio items fill exactly. The standard instance satisfies all three.

Edge case 4 — Zero and negative weights

A zero-weight item with positive value should always be taken in both knapsacks; in the ratio rule it has an infinite ratio, which most implementations handle badly. Negative values, or negative edge weights, break the greedy argument outright: Dijkstra with a negative edge can finalise a vertex that a later path would have improved.

Verified fact Non-negative weights are a stated hypothesis of Dijkstra's correctness, and the cut property of MSTs is stated for undirected weighted graphs. Both are assumptions of the theorem, not incidental details.

Edge case 5 — Empty and single-element inputs

No activities: greedy returns the empty set, which is optimal. One activity: it takes it. No items: value 0. One symbol: Huffman needs no merges, and the average code length is 0 bits under the usual convention that a single symbol needs no bits, or 1 bit if a code is required.

These are where a recurrence's base case lives, and where an implementation that assumes at least two elements crashes. A hand-execution question rarely asks, but a proof question sometimes does.

Edge case 6 — A greedy algorithm can be optimal and still not unique

Fractional knapsack with capacity 50 and the standard items has value 240 from the ratio order, and also 240 from a different order. Both are optimal. Activity selection can have several optimal families when finish times tie.

So "the greedy answer" is one optimal answer among possibly many. A question that asks for the optimal value is well posed; one that asks you to identify the optimal set may have more than one right option, which is why GATE usually asks for the value or the count.

Misconception 1 — "Greedy is a synonym for optimal"

What it sounds like: "The algorithm is greedy, so it finds the best answer."

Why it is wrong: greedy names the shape of the algorithm, not a guarantee. Coins 1, 3, 4 for 6 give 3 coins from greedy and 2 from the optimum. The algorithm is perfectly greedy and perfectly wrong.

Replace with: greedy is optimal when the greedy-choice property holds, and that is a theorem about the pair (rule, instance family), established by an exchange argument.

Misconception 2 — "It works on every example I tried, so it is correct"

What it sounds like: "I ran it on three inputs and got the right answer."

Why it is wrong: the failure mode of a greedy algorithm is a feasible answer that is slightly worse, which small examples often miss. Largest-coin-first works for the sets 1, 2, 5 and 1, 5, 10 and 1, 2, 5, 10 and 1, 2, 5, 10, 20 and fails for 1, 3, 4.

Replace with: examples can refute, never confirm. One counterexample ends the discussion; agreement on a hundred inputs proves nothing.

Misconception 3 — "0/1 knapsack is solved by greedy, or fractional needs DP"

What it sounds like: "Knapsack is a DP problem" or the reverse pairing.

Why it is wrong: it is the other way round. Fractional knapsack is solved optimally by the ratio rule in O(n log n). 0/1 knapsack has no correct greedy algorithm and is solved by DP in O(nW), which is pseudo-polynomial.

Replace with: divisibility is the discriminator. Items that can be split make the exchange step work; items that cannot, break it. Say the word "divisible" in your answer and the marks follow.

Misconception 4 — "Optimal substructure is enough"

What it sounds like: "The optimal solution contains optimal subsolutions, so greedy works."

Why it is wrong: 0/1 knapsack has optimal substructure and greedy still fails. Optimal substructure is shared with dynamic programming; it says nothing about whether a single local choice can be committed to.

Replace with: two properties, two names. Optimal substructure licenses a recursive decomposition; the greedy-choice property licenses committing to one branch of it. Greedy needs both, DP needs only the first.

Misconception 5 — "Sort by whatever is largest or smallest"

What it sounds like: "Activity selection sorts by duration" or "knapsack sorts by value".

Why it is wrong: duration fails (the long activities 0 to 5 and 5 to 10 plus a short one from 4 to 6: shortest-first takes one, the optimum is two), and value fails for knapsack (sorting by value puts the heaviest item first).

Replace with: the criterion is a claim with a proof, not a guess. Finish time for intervals; value per unit weight for divisible goods; weight for Huffman merges; profit for unit-time jobs.

Misconception 6 — "Huffman cost is the sum of the leaf weights"

What it sounds like: adding 1 + 2 + 2 + 2 + 3 = 10 and calling it the encoded length.

Why it is wrong: 10 is the number of symbols, not the number of bits. The cost is each weight times its depth, which equals the sum of the internal node weights: 3 + 4 + 6 + 10 = 23.

Replace with: add the merges. Every merge you perform contributes its own weight to the total, and the running total after the last merge is the answer.

Misconception 7 — "Dijkstra and Prim are DP because they build answers from smaller ones"

What it sounds like: "Bellman-Ford, Floyd-Warshall and Prim all use dynamic programming."

Why it is wrong: Prim and Dijkstra make one irrevocable choice per step from a frontier, which is greedy. Bellman-Ford and Floyd-Warshall fill tables of overlapping subproblems, which is DP. The distinction is commitment versus tabulation.

Replace with: ask whether the algorithm ever revises a finalised decision. Dijkstra never unfinalises a vertex; Bellman-Ford revises every distance up to V − 1 times.

Misconception 8 — "A greedy algorithm is always faster than DP"

What it sounds like: "Use greedy, it is the efficient one."

Why it is wrong: greedy is usually faster when it is correct, and a fast wrong answer scores zero. There are also greedy algorithms that are slower than the best DP: the simple job-sequencing scan is O(n^2) while other formulations are O(n log n).

Replace with: choose by correctness first, then by cost. If no exchange argument exists, the faster algorithm is the wrong one.

Pattern 1 — Execute and report a number

Shape: "Apply Huffman to these frequencies; give the average code length or the encoded length." Move: a merge table with a running total. Never draw the whole tree unless the question asks for codes.

Seen as: GATE CSE 2007 (average length of Huffman codes, 1.9375) and GATE CSE 2021 Set 2 (minimum encoded length of a short string, 23). Both are single-answer MCQs worth 2 marks. Verified fact Years and paper labels are from the question listings at ExamSIDE; the numerical answers were recomputed by this page's own model rather than copied.

Pattern 2 — Classify a problem

Shape: "Which of the following is solved optimally by a greedy algorithm?" or "Which technique solves X?" Move: for each candidate, try to recall a counterexample. Fractional knapsack, activity selection, Huffman, MST and Dijkstra are the safe yes answers; 0/1 knapsack, subset sum, LCS and matrix chain are the safe no answers.

Trap: the options usually pair the two knapsacks in a swapped way. Read the word "fractional" before answering, and check whether the question says "efficiently" or "optimally", because an exponential greedy search is optimal and useless.

Pattern 3 — Cost the algorithm

Shape: "The time complexity of this greedy algorithm is ______." Move: locate the sort or the heap. A sort of n items is O(n log n); n heap operations are O(n log n); a linear scan per item is O(n^2).

Trap: the answer must name the implementation. Job sequencing with a slot scan is O(n^2); the same rule with a disjoint-set structure is near linear after the sort. An option that says O(n) for activity selection ignores the sort.

Pattern 4 — Identify the property, or the failing step

Shape: a proof sketch with a blank, or a statement to judge: "The greedy-choice property fails here because ____." Move: name the property precisely, then name the fact that makes the swap safe or unsafe — divisibility, non-negative weights, the cut property, the matroid exchange axiom.

Trap: "optimal substructure" and "greedy-choice property" are not interchangeable. 0/1 knapsack has the first and lacks the second, so an option claiming it lacks optimal substructure is false.

Decision procedure — five questions, in this order

  1. Is there a numerical objective? If not, this is not an optimisation problem and greedy does not apply.
  2. Can the solution be built by a sequence of decisions? If not, greedy has nothing to commit to.
  3. What exactly is the local criterion? Write it as a phrase you could sort by. "Earliest finish time", not "the best one".
  4. Can you break it? Try one small instance with ties or indivisibility. If it breaks, greedy is out.
  5. Can you close the exchange? If yes, greedy is correct and you can state the proof in four moves. If no, and subproblems overlap, use DP.

Closely confused pairs, side by side

Fractional vs 0/1 knapsack. Divisible vs indivisible; ratio rule vs DP table; O(n log n) vs O(nW); exchange closes vs exchange fails.

Greedy vs DP. One branch vs all branches; commitment vs tabulation; needs greedy-choice property vs needs overlapping subproblems; no revisiting vs revisiting stored answers.

Optimal substructure vs greedy-choice property. Shared with DP vs specific to greedy; about decomposition vs about commitment.

Prim vs Kruskal. Grow one tree from a vertex, cheapest crossing edge vs sort all edges and union-find; both greedy, both proved by the cut property.

Dijkstra vs Bellman-Ford. Greedy, non-negative weights, O(E log V) vs DP, negative edges allowed, O(VE).

MCQ Original

Q1. Activities with intervals [0,5], [4,6], [5,10] are given, and the task is to choose as many non-overlapping activities as possible. Which statement is true?

(A) Shortest-activity-first returns 2 activities, which is optimal.
(B) Shortest-activity-first returns 1 activity, while the optimum is 2.
(C) Earliest-start-first returns 1 activity, because [0,5] blocks everything else.
(D) The optimum is 1 activity, because every pair overlaps.

Answer: (B). Durations are 5, 2 and 5, so shortest-first takes [4,6] first, and [4,6] overlaps both other activities. It returns 1. The pair [0,5] and [5,10] is compatible, so the optimum is 2. (A) misreports the count. (C) is false: earliest-start takes [0,5], rejects [4,6], then takes [5,10], returning 2 — it is not blocked. (D) is false because [0,5] and [5,10] do not overlap under half-open intervals.

Trap: under the closed-interval convention, [0,5] and [5,10] would conflict and the optimum would be 1, making (D) right. The convention is part of the question, and the page states it.

MCQ GATE CSE 2007

Q2. Letters a, b, c, d, e, f have probabilities 1/2, 1/4, 1/8, 1/16, 1/32, 1/32. The average length of the Huffman code is:

(A) 2.0
(B) 2.0625
(C) 2.125
(D) 1.9375

Answer: (D) 1.9375. Merge the two lightest repeatedly and add the merge weights: 1/16 + 1/8 + 1/4 + 1/2 + 1 = 1.9375. Equivalently, depths are 1, 2, 3, 4, 5, 5, so the average is 1/2 + 1/2 + 3/8 + 1/4 + 5/32 + 5/32 = 1.9375.

Why the others fail: 2.0 is the fixed-length code length for six symbols, which is the number Huffman must beat; it does, so (A) is wrong. 2.0625 and 2.125 are what you get by miscounting one depth or by summing leaf weights with one extra pass. This equals the source entropy because every probability is a power of one half, which is a coincidence of this instance, not a rule.

NAT GATE CSE 2021 Set 2

Q3. For the string aabbccddeee, under a prefix-free binary code with the tie-breaking rule stated in the paper, the minimum length of the encoded string is ______ bits.

Answer: 23. Frequencies are a=1, b=2, c=2, d=2, e=3. Merges: 1+2=3, 2+2=4, 3+3=6, 4+6=10, and the sum of merges is 3+4+6+10 = 23.

Cross-check: one valid tree gives depths a=3, b=3, c=2, d=2, e=1, so the total is 1·3 + 2·3 + 2·2 + 2·2 + 3·1 = 23. A fixed-length code over five symbols needs 3 bits each, 30 bits total, so Huffman saves 7 bits.

MSQ Original

Q4. Which of the following problems are solved optimally by a greedy algorithm, with no need for dynamic programming?

(A) Fractional knapsack
(B) 0/1 knapsack
(C) Huffman coding
(D) Activity selection

Answer: (A), (C), (D). Fractional knapsack: ratio rule, exchange closes because fractions can be trimmed. Huffman: merge the two lightest, exchange on the two least frequent symbols. Activity selection: earliest finish, exchange on the first activity.

Why (B) fails: capacity 50 with items (10, 60), (20, 100), (30, 120) gives greedy 160 and the optimum 220. No tie-breaking of the ratio rule fixes it, because the rule never compares a pair against a pair.

MCQ Original

Q5. Which single fact makes the exchange argument for fractional knapsack work, and is absent in the 0/1 version?

(A) The objective is linear in the chosen quantities.
(B) An item may be taken in any fraction, so value can be moved between items in arbitrarily small amounts.
(C) All weights and values are positive.
(D) The problem has optimal substructure.

Answer: (B). The swap in the fractional proof moves value from a lower-ratio item to a higher-ratio one in whatever amount is needed, and divisibility guarantees that amount is legal. With whole items the smallest legal move is a whole item, so the improving swap may not exist.

Why the others are wrong: (A) and (C) hold in both versions, so neither can explain the difference. (D) also holds in both — 0/1 knapsack has optimal substructure and still defeats greedy. Only (B) distinguishes them.

MSQ Original

Q6. Statements about the two knapsack problems. Which are true?

(A) 0/1 knapsack is efficiently solved by the value-per-weight greedy rule.
(B) Fractional knapsack is solved optimally in O(n log n) time.
(C) 0/1 knapsack lacks optimal substructure.
(D) The 0/1 knapsack DP table is O(nW) in time, which is pseudo-polynomial in the capacity.

Answer: (B), (D). (B) is one sort plus one fill. (D) is the standard table cost, and "pseudo-polynomial" is the right word because the cost is polynomial in the numeric value of W but exponential in the number of bits of W.

Why (A) and (C) fail: (A) is refuted by the capacity-50 instance, 160 against 220. (C) is the classic confusion: optimal substructure does hold — the optimal solution minus an item is optimal for the reduced capacity — so the failure is in the greedy-choice property, not in the substructure.

NAT Original

Q7. Runs of lengths 20, 24, 30, 35 and 50 are merged two at a time. Using the optimal merge order, the worst-case number of comparisons is ______.

Answer: 358. Merge the two shortest each time: 20+24 = 44 costs 43 comparisons; 30+35 = 65 costs 64; 44+50 = 94 costs 93; 65+94 = 159 costs 158. Total 43 + 64 + 93 + 158 = 358.

Why the rule is optimal: each merge of m and n costs at most m + n − 1, so the total is (sum of merge weights) − (number of merges). The number of merges is fixed at four, so minimising the total means minimising the sum of merge weights, which is exactly Huffman's problem. Shortcut and its assumption: the formula m + n − 1 assumes worst-case comparison merging of two sorted lists, and that assumption is stated in the question.

MCQ Original

Q8. Largest-coin-first is used to make change for the amount 6 from the coin set {1, 3, 4}. Which is the correct description of the outcome?

(A) It returns 3 coins, which is optimal.
(B) It returns 3 coins, while 2 coins suffice.
(C) It returns 2 coins, which is optimal.
(D) It cannot terminate, because no coin divides 6.

Answer: (B). Greedy takes 4, then 1, then 1: three coins. Two coins of 3 pay 6, so the optimum is 2 and greedy is not optimal for this set.

Contrast: for the set {1, 2, 5} the same rule is optimal for 6, giving 5 + 1, two coins. Correctness belongs to the pair (rule, coin set), which is the point of the counterexample. (D) is false because the coin 1 always divides the remainder.

Revision sheet — one screen

Definitions. Greedy algorithm: builds a solution element by element, taking at each step the best element under a fixed local measure, with no backtracking. Optimal substructure: an optimal solution contains optimal solutions to the subproblems left after a choice. Greedy-choice property: some optimal solution makes the choice greedy makes first. Exchange argument: transform an arbitrary optimal solution into one that agrees with greedy, one swap at a time, preserving feasibility and value.

Proof template, four moves. (1) Let S^* be optimal and g greedy's first choice. (2) If g ∈ S^*, skip to (4); else let s be the element of S^* that g replaces. (3) Show S' = S^* ∖ \{s\} \{g\} has the same value and is still feasible. (4) The remainder is the same problem on a smaller instance; induct.

Criteria, and what each one sorts on

  • Activity selection: smallest finish time among compatible activities. O(n log n).
  • Fractional knapsack: largest value per unit weight; last item split. O(n log n).
  • Huffman: merge the two lightest; cost = sum of merge weights. O(n log n).
  • Optimal merge pattern: same as Huffman, on run lengths.
  • Unit-time job sequencing: highest profit first, latest free slot at or before the deadline. O(n^2) simple, better with union-find.
  • Kruskal: lightest edge that joins two components. O(E log E).
  • Prim: lightest edge leaving the grown tree. O(E log V) with a heap.
  • Dijkstra: nearest unfinalised vertex; needs non-negative weights. O(E log V).

Counterexamples to keep

Coins {1,3,4}, amount 6: greedy 4+1+1 (3 coins), optimum 3+3 (2 coins).

0/1 knapsack, capacity 50, items (10,60),(20,100),(30,120): greedy 160, optimum 220.

Shortest-activity-first, intervals [0,5],[4,6],[5,10]: greedy 1, optimum 2.

Earliest-start-first on the eleven-activity instance: returns 3, earliest-finish returns 4.

Sorting by total value for knapsack: puts the heaviest item first and can be worse than the ratio order.

Traps, in the order they cost marks

  1. Reading "greedy" as "optimal". It is a shape, not a guarantee.
  2. Confusing the two knapsacks. Fractional is greedy; 0/1 is DP.
  3. Saying 0/1 knapsack lacks optimal substructure. It has it; the greedy-choice property is what fails.
  4. Adding leaf weights for a Huffman cost instead of merge weights.
  5. Quoting O(n) for activity selection and forgetting the sort.
  6. Forgetting that Dijkstra needs non-negative weights, and that Prim's correctness is the cut property.
  7. Treating one matching example as a proof, or one counterexample as a coincidence.
