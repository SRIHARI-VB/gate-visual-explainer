Topic and objective

TOPIC: Network security, in the four pieces the syllabus names: authentication, the basics of private-key (symmetric) and public-key cryptography, digital signatures and certificates, and firewalls. The lesson builds the key arrangements from the three properties they buy, then makes RSA arithmetic explicit, then shows where a hash and a signature fit, then what a certificate binds, and finally what a device at a given layer can and cannot see.

LEARNING OBJECTIVE: Name the property a question is about before choosing any key, and then apply the direction rule: encrypt with the receiver public key for secrecy, sign with the sender private key for proof. Build an RSA key pair from two primes and recover a private exponent as a modular inverse, including the case where n and phi(n) are given and the primes must be found. Verify a signature under the correct key and explain why a wrong key fails. Read a certificate as a signed binding and separate it from a MAC. Evaluate an ordered packet-filter table by first match, and state what a layer-4 firewall cannot do.

I am reading this microtopic as one decision and four procedures: the decision is which property the words ask for, and the procedures are the key count, the RSA inverse, the sign-and-verify pair, and the first-match rule evaluation.

Level 1 — Intuition, and Level 2 — the formal definitions

Educational interpretation A network is a postcard, not a sealed letter. Every router on the path can read the back, and anyone sharing the wireless link can copy it. Security is the set of tricks that make a postcard behave like a sealed letter with a signature: encrypt it, hash it, sign the hash, and check the signature against a name you already trust.

Symmetric encryption. A pair of algorithms (encrypt, decrypt) with one key K such that decrypt(encrypt(m, K), K) = m. Both parties hold K, so the confidentiality rests entirely on K staying secret.

Public-key encryption. A pair (K+, K-) generated together, such that either undoes the other. K+ may be published; K- never leaves its owner. Encrypting with K+ gives secrecy because only K- opens it.

Digital signature. A value sigma = sign(H(m), K_sender-) computed over a hash of the message, checkable by anyone holding K_sender+. It gives integrity and authenticity, and — unlike a MAC — it can be shown to a third party.

Level 3 — Visual understanding: two keys, one rule

Draw each person as a circle with two keys attached: a green public key on the outside, a red private key inside. Every question in this topic is then an arrow between two circles, and the arrow direction is decided by which property is wanted.

Secrecy: the arrow leaves the sender carrying the receiver green key, and only the receiver red key opens it. Proof: the arrow carries the sender red key, and any green key checks it. A message that needs both is signed at one end and encrypted at the other, in that order, which is four key uses and one fixed sequence.

Level 4 — Worked examples, one line each

Shared keys. N = 10 people, every pair with its own secret: 10 × 9 / 2 = 45 keys. The page counts the pairs in a nested loop and gets 45.

RSA, small. p = 13, q = 17 gives n = 221 and phi(n) = 192; with e = 35 the inverse is d = 11, because 35 × 11 = 385 = 2 × 192 + 1.

RSA, exam. n = 3007 and phi(n) = 2880 give p + q = 128, and the primes are 31 and 97.

Modular power. 3^51 mod 5 = 2, in nine multiplications rather than fifty.

Level 5 — Boundaries: what each tool does not do

Symmetric encryption gives confidentiality only. It cannot prove who sent a message, because both holders of the key could have made it.

Public-key encryption gives confidentiality only. It is also far slower than symmetric encryption, which is why real protocols use it to agree a session key and then switch to symmetric encryption for the data.

A signature gives integrity, authenticity and non-repudiation, but no confidentiality: anyone with the sender public key can read the signed value.

A certificate gives none of these by itself. It binds a name to a key, so that the other tools have a key worth using. Trust has to start somewhere, which is the root key already installed on the machine.

Level 6 — Edge cases and a counterexample

The counterexample to "public-key means secure". Encrypt with your own private key and publish the result. Every holder of your public key can read it, so there is no confidentiality at all — and if the value was meant as a signature, it is still a valid signature. The operation is the same; the property depends entirely on which key was used.

n = 1 in the key count. One person, nobody to talk to: the formula gives 0 keys, correctly.

e and phi(n) not coprime. No inverse exists, so no private exponent, so the pair is invalid. The page checks gcd before trusting d.

A digest of zero length. A hash of an empty message is a perfectly ordinary digest, so "no message" is signable. This is why protocols sign a message that includes a length and a purpose, not just the payload.

Example 1 — the shared-key count, used directly

Twelve people want pairwise secret communication, each pair with its own key. How many keys are needed in the system?

Answer: 12 × 11 / 2 = 66. The count is the number of unordered pairs, because the key between A and B is the key between B and A. The page counts pairs in a nested loop for N = 2 to 10 and every value matches the formula; at N = 12 the same loop gives 66.

The trap that is not here. Nothing needs the identity of the keys. The question is a counting question, and the only thing to get right is that a shared key has no direction.

Example 2 — an RSA key pair, built and checked

Take p = 13 and q = 17, and publish e = 35. Find n, phi(n) and d, and show that the pair works.

n = 221, phi(n) = 192, d = 11. The inverse exists because gcd(35, 192) = 1, and 35 × 11 = 385 = 2 × 192 + 1. The page then encrypts and decrypts every message from 1 to 220 and recovers all 220.

Why the check matters: e × d = 385, and 385 mod 221 = 164, not 1. The relation is modulo phi(n), and a student who checks against n concludes the pair is broken when it is not.

Example 3 — the reverse question: n and phi(n) give the primes (GATE CSE 2019)

In an RSA system the public modulus is n = 3007 and Euler totient phi(n) = 2880. Find the prime factor of n that is greater than 50.

Step 1 — turn phi(n) into a sum. phi(n) = (p-1)(q-1) = pq - p - q + 1 = n - (p + q) + 1. So p + q = n - phi(n) + 1 = 3007 - 2880 + 1 = 128.

Step 2 — turn product and sum into a quadratic. The primes are the roots of x² - 128x + 3007 = 0, whose discriminant is 128² - 4 × 3007 = 16384 - 12028 = 4356 = 66².

Step 3 — read the roots. (128 - 66)/2 = 31 and (128 + 66)/2 = 97. Check: 31 × 97 = 3007 and 30 × 96 = 2880. The factor above 50 is 97.

Why this is not a factorisation question: trial division of 3007 works too, but it is slow and unnecessary. The totient is a gift: it hands over the sum of the primes, and two equations decide two unknowns.

Example 4 — a modular power by two routes

Compute 3^51 mod 5.

Route 1, square-and-multiply. 51 = 110011 in binary, so five squarings and four multiplications: nine modular multiplications, ending at 2. The page instruments the routine and counts them.

Route 2, the cycle. The powers of 3 mod 5 are 3, 4, 2, 1 and then repeat with period 4. Since 51 mod 4 = 3, the answer is the third element, 2.

Why both: the cycle argument is a proof for a small modulus and useless for a 2048-bit one, where only the ladder is practical. Knowing both is what lets you answer quickly and check.

Example 5 — a signature, and a failed verification

Using n = 221, private exponent d = 11, public exponent e = 35, sign the digest 42 and verify.

Sign: 42^11 mod 221 = 87. Verify: 87^35 mod 221 = 42, which matches the digest, so the check passes.

Verify with the wrong exponent (13 instead of 35): 87^13 mod 221 = 100, which is not 42, so the check fails. Nothing about the signature changed; only the key did.

What this shows: verification is a comparison, and a passing comparison is evidence that the holder of d produced the value. That is the whole security argument, and it needs no further assumption.

Example 6 — a rule table evaluated by first match

Rules, in order: (1) deny tcp any → 10.0.0.5:23; (2) deny tcp 200.1.1.0/24 → any:80; (3) allow tcp 10.0.0.0/8 → any:443; (4) deny udp any → any:53; (5) allow tcp any → any:22; (6) deny any → any.

P1 tcp 10.0.0.7 → 10.0.0.5:23 meets rule 1: denied. P2 tcp 200.1.1.9 → 10.0.0.5:80 meets rule 2 by its /24 prefix: denied. P3 tcp 10.0.0.7 → 93.184.216.34:443 meets rule 3 by its /8 prefix: allowed. P4 udp → 8.8.8.8:53 meets rule 4: denied.

P5 tcp 10.0.0.7 → 10.0.0.9:80 matches no rule above the catch-all, so rule 6 denies it. P6 tcp 10.0.0.7 → 10.0.0.9:22 meets rule 5 first: allowed.

The reordering check: move rule 6 to the top and every packet meets it first, so all six are denied. That single experiment is the proof that first-match order is part of the policy rather than a presentation detail.

A signature is not encryption

The same modular exponentiation produces both, which is why they get confused. Signing uses the private exponent and hides nothing; encrypting uses the public exponent and proves nothing. A signature that anyone can read is working correctly.

The test that settles it: ask who should be able to read the value. If everyone, it is a signature. If only one party, it is encryption. If the answer is "everyone, but only one party could have made it", it is a signature again — and that is the normal case.

e and phi(n) sharing a factor

If gcd(e, phi(n)) is greater than 1, no inverse exists, so there is no d and the pair cannot be completed. With p = 13, q = 17 the totient is 192 = 2^6 × 3, so e = 35 works (35 = 5 × 7) but e = 33 does not, since gcd(33, 192) = 3.

What the exam does: it hands you an e that works, and expects the inverse. The edge case matters because it explains why e is usually a small prime such as 65537, which shares a factor with almost nothing.

Message 0 and message n

RSA is defined for 0 < m < n in the textbook statement, and the page tests exactly that range: 220 messages for n = 221. In practice m = 0 encrypts to 0 and m = n to 0 as well, which is why real schemes pad the message before exponentiating.

The exam convention: questions state the range explicitly. If a question does not, assume 0 < m < n and say so.

n = 1, and the empty group

The shared-key formula N(N-1)/2 gives 0 at N = 1 and 0 at N = 0, both correctly: nobody to talk to, nothing to share. The public-key count 2N gives 2 and 0, which is also right — one person still holds a key pair.

Why it is worth a line: the two counts disagree at the boundary, and a boundary case is the cheapest place to see that they are counting different objects.

Collision is not second preimage

A collision is two messages you chose with the same digest, at about the square root of the space. A second preimage is a different message matching a digest someone else fixed, at the full size of the space. For a 64-bit digest those are 2^32 and 2^64.

Where it decides an answer: the 2017 item asks who can mount a birthday attack on a signed message. Only the signer, because only the signer chooses both messages before signing. A receiver or a third party would need a second preimage.

A firewall rule that can never fire

Any rule placed below an allow-all rule is dead code: no packet reaches it, so it changes nothing. The page shows this by moving the catch-all to the top, where it kills every rule below it at once.

The habit: read a rule table top to bottom, and for each rule ask which packet could still reach it. If none, the rule is decoration.

"Encrypt with your private key so that only you could have sent it"

Half right, and the wrong half is the word encrypt. Applying the private key gives a value anyone can open with your public key, so it gives no secrecy at all. It gives proof, which is what a signature is.

The precise statement: for secrecy, encrypt with the receiver public key. For proof, apply the sender private key to a hash. The two operations look identical and mean opposite things.

"e × d = 1, so e × d mod n = 1"

Wrong modulus. The relation is e × d = 1 modulo phi(n). With p = 13, q = 17, e = 35, d = 11: e × d = 385 = 2 × 192 + 1, and 385 mod 221 = 164.

Where it costs marks: GATE CSE 2009 offered "ed = 1 mod n" and "ed = 1 mod phi(n)" as separate statements, with the arithmetic mod n and the keys mod phi(n) both correct. The pair was I and III.

"A MAC and a signature are the same thing with different names"

No. A MAC uses one shared key, so both parties can produce it and neither can prove authorship to a third party. A signature uses one private key, so exactly one party can produce it and a judge can be convinced.

The one-line test: can it be shown to someone who holds neither key? If yes, it is a signature. If no, it is a MAC.

"More keys must mean more security, so public key is always better"

Wrong for two reasons. Public-key systems need 2N keys against N(N-1)/2, which is fewer only above N = 5 — and the number of keys is not the cost that matters. Public-key operations are orders of magnitude slower than symmetric ones.

What real protocols do: use public-key operations once, to agree a session key, then symmetric encryption for the data. Both systems appear in one connection, and neither replaces the other.

"A firewall stops viruses"

Not the packet filter. A layer-4 device sees addresses and ports; it cannot see a file, a URL path or a script. An application proxy can read the request, which is why content filtering lives there and why it is slower.

The exam form: the 2011 item asks precisely what a layer-4 device cannot do, and the answer is the one requiring an identity that no header up to the transport layer carries.

"Blocking all HTTP traffic needs layer 7"

It does not. HTTP is TCP port 80, so blocking every packet to port 80 blocks all HTTP without reading a single application byte. Blocking "HTTP requests to a particular path" is what needs layer 7.

The distinction to carry into the exam: blocking an entire protocol is a port rule; blocking a part of a protocol is a content rule. The 2011 options separate exactly those two.

The procedure, in the order you should run it

1. Name the property. Secrecy, integrity, authentication, or a capability statement about a device. 2. Choose the keys from the property. Secrecy: receiver public to encrypt, receiver private to decrypt. Proof: sender private to sign, sender public to verify. Both: sign then encrypt. 3. If it is RSA, write the three numbers first. n = pq, phi(n) = (p-1)(q-1), e × d = 1 mod phi(n). Then read what is given: two primes, or n with phi(n), or e with the primes. 4. If it is a count, decide what is being counted. Pairs for shared keys, 2N for a public-key system, 2^32 for a birthday collision on a 64-bit digest. 5. If it is a firewall, evaluate by first match and check which layer the filter is allowed to read.

If the options are key names, the answer is a direction. If the options are numbers, the answer is an inverse or a count. If the options are statements about what a device can do, the answer is a layer.

Closely confused pairs, side by side

Signature against MAC. One private key against one shared key; provable to a third party against not.

Collision against second preimage. Square root of the space against the whole space; the attacker chooses both messages against one.

Symmetric against public key. One key against a pair; N(N-1)/2 against 2N; fast against slow.

Packet filter against application proxy. Layer 3 and 4 headers against the request itself; no state and cheap against state and expensive.

NATGATE CSE 2017 Set 1

In an RSA cryptosystem a participant A uses two prime numbers p = 13 and q = 17 to generate her public and private keys. If the public key of A is 35, then the private key of A is ______.

Answer: 11

n = 13 × 17 = 221 and phi(n) = 12 × 16 = 192. The private exponent is the inverse of 35 modulo 192: 35 × 11 = 385 = 2 × 192 + 1, so d = 11. The page runs Euclid, confirms gcd(35, 192) = 1, and then encrypts and decrypts all 220 messages below 221 with (35, 11) and recovers every one.

The trap: reducing modulo n instead of modulo phi(n). That gives the wrong inverse and, worse, invites the answer 164 — which is 385 mod 221 and is not a key at all.

NATGATE CSE 2019

In an RSA cryptosystem, the value of the public modulus parameter n is 3007. If it is also known that phi(n) = 2880, where phi() denotes Euler totient function, then the prime factor of n which is greater than 50 is ______.

Answer: 97

phi(n) = n - p - q + 1, so p + q = 3007 - 2880 + 1 = 128. The primes are the roots of x² - 128x + 3007, with discriminant 16384 - 12028 = 4356 = 66². The roots are (128 - 66)/2 = 31 and (128 + 66)/2 = 97. The page checks 31 × 97 = 3007 and 30 × 96 = 2880, and confirms both are prime.

The trap: trying to factor 3007 by trial division. It works, and it wastes the one piece of information the question gave you.

MCQGATE CSE 2016 Set 2

Anarkali digitally signs a message and sends it to Salim. Verification of the signature by Salim requires

  1. Anarkali's public key
  2. Salim's public key
  3. Salim's private key
  4. Anarkali's private key

Answer: A — Anarkali's public key

The signature was produced with Anarkali's private key, so it is checked with the matching public key. The page signs the digest 42 with d = 11 and verifies with e = 35, recovering 42 exactly; under a different exponent it recovers 100 and the check fails.

Why C fails: Salim's private key has nothing to do with a value Anarkali produced — it belongs to a different key pair. Why D fails: nobody needs the signer's private key to check a signature; needing it would make verification impossible for everyone else.

MCQGATE CSE 2015 Set 1

Suppose that everyone in a group of N people wants to communicate secretly with the N - 1 others using a symmetric key cryptographic system. The communication between any two persons should not be decodable by the others in the group. The number of keys required in the system as a whole is

  1. 2N
  2. N(N - 1)
  3. N(N - 1)/2
  4. (N - 1)²

Answer: C — N(N - 1)/2

Each pair needs its own key, and the number of unordered pairs is the binomial coefficient N choose 2. The page counts pairs in a nested loop for N = 2 to 10 and matches the formula at every N: at N = 5 both give 10, at N = 10 both give 45.

Why B fails: N(N-1) counts each pair twice, once from each end, so it is exactly double the answer. Why A fails: 2N is the key count for a public-key system, where each person holds a public and a private key. Why D fails: (N-1)² counts keys per person against keys per person, which is not a count of anything here.

MCQGATE CSE 2011

A layer-4 firewall (a device that can look at all protocol headers up to the transport layer) CANNOT

  1. block entire HTTP traffic during 9:00 PM and 5:00 AM
  2. block all ICMP traffic
  3. stop incoming traffic from a specific IP address but allow outgoing traffic to the same IP address
  4. block TCP traffic from a specific user on a multi-user system during 9:00 PM and 5:00 AM

Answer: D

A user identity is not in any header up to the transport layer. On a multi-user host all users share one IP address and may use any port, so no rule over addresses and ports can single one out. Options A, B and C need only port 80, the protocol field and the addresses, all of which a layer-4 device reads.

Why A is possible: HTTP is TCP port 80, so blocking that port for a time window blocks all of it — the word "entire" is what makes it a port rule rather than a content rule. Why C is possible: it uses direction and an address, both of which are visible. The general test: blocking a whole protocol is a port rule; blocking a part of it, or a person, is a content rule.

MSQOriginal practice question

A message must reach the receiver so that only the receiver can read it, and so that the receiver can prove to a third party who sent it. Which of the following are true of the arrangement?

  1. The sender applies the sender private key to a hash of the message
  2. The sender encrypts with the receiver public key
  3. The receiver decrypts with the receiver private key and then verifies with the sender public key
  4. The sender encrypts with the sender public key

Answer: A and B and C

This is sign-then-encrypt: sign with the sender private key (proof), encrypt with the receiver public key (secrecy), and at the far end decrypt with the receiver private key and verify with the sender public key. Each key is used by the party that holds it, in the direction that produces the wanted property.

Why D fails: encrypting with the sender public key gives no secrecy, because everyone holds that key. It would also give no proof, since anyone can encrypt with a public key — the value could have been made by anybody.

MCQOriginal practice question

Two parties share a secret key K and exchange a message together with a tag computed from K and the message. Which property can this arrangement NOT provide?

  1. Detection of a changed message
  2. Assurance that the sender holds K
  3. Proof to a third party that a particular one of the two parties sent the message
  4. Detection of a truncated message, if the tag covers the length

Answer: C — proof to a third party

This is a MAC. Both parties can compute the tag, so either could have produced it, and a judge has no way to tell which. That missing property is called non-repudiation, and only a signature provides it, because only one party holds the private key.

Why A is provided: a changed message changes the tag. Why B is provided: a correct tag means the sender holds K. Why D is provided: if the length is inside the tagged data, a truncation changes the tag like any other change. The single failure is the third-party proof.

NATOriginal practice question

A firewall applies these rules in order: (1) allow tcp any to any port 22; (2) deny tcp any to any port 23; (3) allow tcp any to any port 443; (4) deny any to any. A packet arrives with tcp, source 10.0.0.7, destination 10.0.0.9, port 23. What is the number of the rule that decides it?

Answer: 2

Rule 1 mentions port 22 and does not match. Rule 2 mentions port 23 and matches, so it decides and the packet is denied. Rules 3 and 4 are never examined — first match ends the evaluation.

The trap: answering 4, the catch-all, by treating the table as a set of conditions rather than an ordered list. The related trap: assuming the most specific rule wins. Nothing in a packet filter says that; order decides, which is why moving the catch-all to the top of the page's own table denies every packet.

NATOriginal practice question

An RSA modulus is n = 77 and the public exponent is e = 17. What is the private exponent d?

Answer: 53

77 = 7 x 11, so phi(n) = 6 x 10 = 60. The inverse of 17 modulo 60: 17 x 53 = 901 = 15 x 60 + 1, so d = 53. The page's own routine returns 53 and then checks the product modulo 60.

Why 13 looks tempting: 17 x 13 = 221, which is a number that appears all over this lesson (it is the modulus of the worked example). It is not an inverse here, because 221 mod 60 = 41, not 1.

Why 43 also looks tempting: 17 x 43 = 731 = 12 x 60 + 11, and 11 is close to 1. Only a substitution settles it. What to carry away: multiply the candidate by e, take the remainder modulo phi(n), and require exactly 1.

The one-screen revision sheet

Everything here is either a definition or a one-line consequence of one. If you can rebuild the right-hand column from the left, this topic is finished.

The direction rule

Secrecy: encrypt with the receiver public key; decrypt with the receiver private key.

Proof: sign with the sender private key; verify with the sender public key.

Both: sign first, encrypt second. Sending: X- then Y+. Receiving: Y- then X+.

Encrypting with your own public key gives nothing. Encrypting with your own private key gives proof, not secrecy.

The key counts

Shared: N(N-1)/2 — the number of pairs. N(N-1) double counts; N-1 is one person's keys.

Public key: 2N keys in total, N pairs. The two counts agree only at N = 5.

N = 10: 45 shared keys, or 20 public-key keys.

A shared key has no direction, which is why the count is pairs and not people.

RSA, the three numbers

n = p q · phi(n) = (p-1)(q-1) · e d = 1 mod phi(n)

Ciphertext: m^e mod n. Plaintext: c^d mod n. The arithmetic is mod n; the keys are mod phi(n).

p = 13, q = 17: n = 221, phi = 192, e = 35, d = 11 (35 × 11 = 2 × 192 + 1).

Given n and phi(n): p + q = n - phi(n) + 1. 3007 and 2880 give 128, hence 31 and 97.

Modular powers

Square-and-multiply: squarings = bits - 1, multiplications = number of set bits.

3^51 mod 5: 51 = 110011, so 5 + 4 = 9 multiplications instead of 50, answer 2.

Cycle check: 3^k mod 5 is 3, 4, 2, 1 with period 4; 51 mod 4 = 3, third element, 2.

Signatures, hashes, certificates

Signature: {m, K_sender-(H(m))}. Verification needs the signer public key.

Digest functions: SHA-1, MD5. RSA and DES encrypt, they do not digest.

Birthday: 23 items on 365 values collide with probability 0.507297; 366 must collide; a 64-bit digest collides at about 2^32, while a second preimage costs 2^64.

Certificate: name + public key + validity, signed by an authority. The chain ends at a root already trusted.

Firewalls

Semantics: first match decides. A rule below an allow-all can never fire.

Layer 3: addresses, protocol. Layer 4: plus ports and flags. Layer 7: plus the request itself.

2011 answer: a layer-4 device cannot block one user on a multi-user host. Blocking all HTTP is only a port-80 rule.

The five-step procedure

  1. Name the property — secrecy, integrity, authentication, or a device capability.
  2. Pick the keys from the property — receiver public for secrecy, sender private for proof.
  3. For RSA, write n, phi(n), and the inverse relation before reading the question's numbers.
  4. For a count, decide the object — pairs, 2N, or the square root of the digest space.
  5. For a firewall, evaluate by first match and check the layer it may read.

What the page computes for itself

Nothing on the canvas is copied from a table. The pair count is produced by a nested loop for N = 2 to 10 and matched against N(N-1)/2; the RSA inverse is found by Euclid, checked against gcd, and then used to encrypt and decrypt all 220 messages below 221; the 2019 primes are recovered from n and phi(n) and put back into both formulas; square-and-multiply is instrumented, so the nine multiplications are counted rather than asserted, and the result is compared with a naive loop and with the cycle of powers; a signature is produced and verified under the correct exponent and under a wrong one; the birthday probabilities are multiplied out from the falling product, with 366 items giving exactly 1; the firewall table is evaluated packet by packet, then re-evaluated after moving the catch-all, and the difference is reported; and the four firewall options are matched against what each layer can read. 47 model checks re-derive the lot a second way.
