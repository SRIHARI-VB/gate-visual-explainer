Topic and objective

TOPIC: Intermediate code generation as its own object. What the intermediate form is for; the six three-address forms and the rule that gives the form its name; how an expression tree becomes instructions; the four different counts a question can mean (operators, fresh temporaries, live temporaries, registers); static single assignment form and the two numbers GATE has keyed for it; the translation of indexing, pointers, calls, loops and boolean conditions; and the three tables — quadruples, triples and indirect triples — that store one instruction list. This is the phrase Intermediate code generation in Section 7 of the GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Given an expression, produce its three-address code, state how many instructions it takes, and give the right temporary count for the wording asked — fresh names under SSA, or the least simultaneously-live number. Given a loop or a boolean condition, produce the translation, count its instructions, labels and jumps, and say which evaluations the translation performs. Given one instruction list, write it as quadruples, triples and indirect triples, and say what each table costs.

I read the topic as one form, four counts, three tables. Everything else in the clause — indexing, calls, loops, short circuit, SSA — is that form used in a particular place. Every number on this page is computed by the page at load time and printed on the canvas.

Prerequisites

  • Lexical analysis, parsing and syntax-directed translation — the attributes and semantic actions that emit each instruction as a production reduces.
  • Runtime environments and activation records — why a temporary needs storage and where that storage lives.
  • Local optimisation and basic blocks — the DAG of a block, which is this form read as a graph.
  • Expression evaluation and operator precedence if you want the order-of-evaluation background; otherwise the tree on the Animation tab supplies it.

Approximate learning time: 55 to 75 minutes including the practice set. That figure is an estimate, not a measurement.

The five ideas

  1. The form exists so that one optimiser and one analysis can serve every language and every machine.
  2. One operator per instruction is what makes the order of evaluation explicit and readable by a later pass.
  3. Four counts share one expression: operators, fresh temporaries, live temporaries, registers. They are not interchangeable.
  4. SSA means one name per definition, so its temporary count is the operator count — that is the number GATE 2015 keyed.
  5. Labels are positions, not operands, but they are still rows: a row count and an instruction count differ by the number of labels.

Intuition first: the note two cooks leave each other

One cook writes recipes and another runs the kitchen. The recipe says "fold in the cream until it coats the spoon" — perfectly clear to a cook, useless to a machine that has no spoon. So the first cook rewrites each recipe as a numbered list of single actions: beat, fold, rest, bake. The second cook can follow that list on any stove, and if the kitchen changes the list still stands.

Educational interpretation The analogy is deliberately thin and it is mine. It explains why a middle language exists, and it stops explaining anything the moment you ask how many temporaries an expression needs — which is the actual subject, and which the page computes rather than illustrates.

Formal statements

Three-address code (TAC). An intermediate language in which each instruction has at most one operator and at most three addresses: two operands and a result.

Temporary. A name that holds the result of one instruction and is not a variable of the source program. Written t1, t2, … on this page.

Definition and use. An instruction defines its result and uses its operands. A temporary is live from its definition to its last use.

Quadruple. A four-field row: operator, first operand, second operand, result.

Triple. A three-field row: operator and two operands. The result is not named; it is identified by the row's position, written (i).

Indirect triple. A triple table plus a statement table of row numbers, so statements can be reordered without rewriting operands.

Static single assignment (SSA). A property of a form: every name is defined exactly once. Where control flow merges, a phi function names the value that arrives from each predecessor.

Symbols, in words

  • x = y op z — x receives the result of applying op to y and z. op is one of +, −, ×, ÷.
  • t1 — the first temporary: a place to keep one computed value.
  • L1, L2, L3 — labels: names for positions in the instruction list. They hold no value.
  • if x < y goto L2 — if the comparison holds, continue at the instruction after L2; otherwise continue with the next instruction.
  • relop — a relational operator: <, ≤, >, ≥, =, ≠.
  • operators — the internal nodes of the expression tree. Each one becomes one instruction.
  • fresh temporaries — one new name per definition. This is the SSA count.
  • live temporaries — how many hold a value that will still be read. Their peak is the minimum number of slots needed.
  • register number — the Sethi-Ullman count, which adds one when both children need the same number, and which also counts the leaf values.

The expressions, and the assumptions under which they are counted

E1  (a+b)*(c+d)
E2  a*b+c*d+e*f
E3  ((a+b)*(c+d))+((e+f)*(g+h))
E4  q+r/3+s-t*5+u*v/w
E5  a-b-c

All arithmetic is over integers, and division truncates toward zero, as in C for positive operands. Precedence and left associativity are the usual ones, so E2 is ((a*b + c*d) + e*f) and E5 is ((a-b)-c). No algebraic rewriting is allowed: the count is for the tree as written, not for a mathematically equal tree.

A leaf that is a digit is a literal, not a variable — the page's evaluator treats it that way, which matters for E4.

The four counts, defined once

Operators. Internal nodes of the tree. For a straight-line expression this is also the number of instructions.

Fresh temporaries. One name per definition. Equal to the operator count, and equal to the SSA count.

Live temporaries. Peak of the set of temporaries holding a value that is still needed, minimised over every evaluation order that computes children before parents. The page finds this by exhaustion.

Register number. Sethi-Ullman: a leaf is 1; a node whose children have different numbers takes the larger; a node whose children have equal numbers k takes k+1.

Mathematical derivation The live count can be smaller than the register number because a leaf value need not occupy a slot of its own: it is read from memory. The register number counts it, and that is exactly where the two counts part company.

The three translation schemes used here

while (x < n) { x = x + 1; }

L1: if x < n goto L2
    goto L3
L2: t1 = x + 1
    x = t1
    goto L1
L3:

Five instructions, three labels, three jumps. The test sits at the top, which is what makes a zero-iteration loop possible.

if (a < b) x = 1; else x = 2;

    if a < b goto L1
    goto L2
L1: x = 1
    goto L3
L2: x = 2
L3:

Five instructions, three labels. A shorter scheme exists — test, else-branch, jump, then-branch — which uses two labels and saves one jump; both are correct, and a count question must say which scheme it means.

Eight worked examples, every number computed

Each example below is produced by the model on this page: the code is generated from the expression tree, the minimum temporary count comes from an exhaustive search over legal evaluation orders, the control-flow translations are executed in a three-address interpreter and compared with the source statement's own meaning, and the three tables are built from one instruction list and evaluated. The Animation tab prints how many checks passed.

Example 1 — (a+b)*(c+d) to three instructions

Question. Translate the expression and give the instruction count.

Step 1, postorder. Left child a+b first, then right child c+d, then the root.

t1 = a + b
t2 = c + d
t3 = t1 * t2

Step 2, the count. Three operators, three instructions, three temporaries. A fourth instruction, x = t3, would appear if the source assigns the value to a variable.

Example 2 — the same expression with two temporaries

Question. What is the least number of temporaries that must exist at once?

t1 = a + b
t2 = c + d
t1 = t1 * t2

Why this is legal. t1 is read for the last time by the third instruction, so its slot may hold that instruction's result. t2 dies at the same instruction.

The check. The page simulates this code over all 81 assignments of 1 to 3 to the four variables and gets the same value as the tree every time.

Example 3 — the four counts, side by side

Expression Operators Fresh temps (SSA) Least live temps Register number
(a+b)*(c+d)3323
a*b+c*d+e*f5523
((a+b)*(c+d))+((e+f)*(g+h))7734
q+r/3+s-t*5+u*v/w8823
a-b-c2212

Mathematical derivation The least-live column is the minimum, over every order that computes children before parents, of the peak number of live temporaries. The page enumerates those orders — 2 for E1, 80 for E3, 84 for E4 — simulates each, and keeps the smallest peak. The last column is the Sethi-Ullman number, computed by its own recursion. Notice that a*b+c*d+e*f is the clearest case where the two differ: 2 temporaries, 3 registers.

Why they differ: the register number charges one slot for each leaf value that must be held, while the temporary count lets a leaf be read from memory. A question that says "temporaries" and a question that says "registers" are asking different things.

Example 4 — GATE 2015 Set 1, Q55

Verified fact Official question. "The least number of temporary variables required to create a three-address code in static single assignment form for the expression q + r/3 + s − t*5 + u*v/w is ______." Two-mark numerical question. The keyed answer is 8. (Question number as the archive consulted labels it; sources differ in numbering.)

Why 8. In SSA form every definition needs its own name, and the expression has eight operators: r/3, t*5, u*v, (u*v)/w, q + r/3, + s, − t*5, and the final +.

t1 = r/3   t2 = q+t1  t3 = t2+s  t4 = t*5
t5 = t3-t4 t6 = u*v   t7 = t6/w  t8 = t5+t7

Why 2 also looks right, and is not. With reuse, two slots carry the whole expression. The question forbids reuse by naming SSA form. The page recomputes 8 from the tree and prints it on the canvas.

Example 5 — GATE 2016 Set 1, Q19

Verified fact Official question. For the segment x = u−t; y = x*v; x = y+w; y = t−z; y = x*y; the minimum number of total variables required to convert it to SSA form is ______. Numerical question; keyed answer 10.

Why 10. Five variables are read before being defined: u, t, v, w, z. Each of the five statements defines a new name. 5 + 5 = 10.

x#1 = u - t      y#2 = x#1 * v
x#3 = y#2 + w    y#4 = t - z
y#5 = x#3 * y#4

The trap. The question asks for total variables, not temporaries. Answering 5 counts the definitions only; the five inputs are variables too.

Example 6 — a loop, counted and executed

Question. Translate while (x < n) { x = x + 1; } and count.

The translation. Test at the top, body, jump back; three labels mark the test, the body and the exit.

The counts. 5 instructions, 3 labels, 3 jumps. Every jump target is a label that exists — the page checks that mechanically.

The semantic check. The generated code is executed for x and n from 0 to 4, 25 pairs, and the final x equals max(x, n) in all 25. Translation is correct only if it computes the same function, and this is how the page proves it for a finite grid rather than asserting it.

Example 7 — one condition, two translations

Question. Translate if (a < b && c < d) x = 1; else x = 0; in control context and in value context.

Control context. The second test sits behind the first test's true branch: 7 instructions, 4 labels, 5 jumps. Executed over the 16 boolean combinations, the c < d comparison runs in exactly the 4 cases where a < b holds.

Value context. Each comparison is turned into a 0/1 temporary with its own diamond, then multiplied: 14 instructions, 7 labels, and the second comparison runs in all 16 cases.

Both agree on the value. The page executes both and compares with (a<b and c<d) in all 16 cases. They differ in what they evaluate, not in what they return — which is why only one of them honours short circuit.

Example 8 — one list, three tables

The list. t1 = a+b; t2 = c+d; t1 = t1*t2.

Quadruples. Three rows of four fields; the result is named, so any row can move.

Triples. Three rows of three fields; the third row reads (0) and (1), which are the positions that defined t1 and t2.

Indirect triples. The same three rows plus a statement table 0, 1, 2. Reordering that table reorders the program; inserting a row in the triple table would instead shift every later (i) reference.

Where the counts and the translations change shape

The rules on this page hold under stated assumptions. Each card below names an assumption and says what happens when it fails.

The final assignment is an instruction too

An expression with n operators is n instructions while it is being evaluated. If the source says x = (a+b)*(c+d), one more instruction, x = t3, appears unless the code generator is allowed to write the last temporary straight into x.

That is why "3 instructions" and "4 instructions" can both be defended for the same expression: the question has to say whether the store counts.

Integer division truncates, and by zero it does not exist

The page's evaluator truncates toward zero, which is C's rule for positive operands. If a question's expression contains a division, the answer depends on that convention for negative operands, and a compiler may not fold a division whose divisor is a literal zero.

Never state a value for an expression that divides by zero: the program has no defined result, and no count of instructions makes it have one.

Labels are rows but not instructions

A label computes nothing, yet it occupies a row in a quadruple table and it can be a jump target. So a row count and an instruction count for the same program differ by the number of labels.

For the while loop on this page: 5 instructions and 8 rows. A question that asks for rows and gets 5 is short by 3.

Counterexample: the loop with the test at the bottom

Take the while loop and move the test to the end, which is the natural translation of do … while:

L1: t1 = x + 1
    x = t1
    if x < n goto L1

This is two instructions shorter and it is wrong: with x = 5 and n = 0 the body runs once, while the while loop runs zero times. The page's 25-pair check catches exactly this — the pair (5, 0) returns 6 instead of 5. Shorter code is not the same as equivalent code.

Counterexample: reuse across a call

Two slots are enough for q+r/3+s-t*5+u*v/w within one straight-line block. Put f() between two instructions and the temporary holding a value across the call may be clobbered by the callee's own frame if it lives in a register the callee does not save.

The safe statement is narrower than the slogan: reuse is justified by liveness within a block, and a call is a barrier that liveness analysis must be told about.

Repeated subexpressions are not free

The counts here are for the tree as written. If b*c appears twice, a naive translation emits it twice and pays two temporaries; a value-numbering pass merges the two into one node of a DAG, which is a different representation of the same block.

That merge belongs to local optimisation and basic blocks, not to generation. Generation produces the tree's code; the DAG is what an optimiser builds from it.

Unary minus, n-ary sums, and assignment inside an expression

-a is one operator and one instruction, t1 = -a. A sum written a+b+c+d is three binary operators, so three instructions — the source's n-ary appearance does not make it one.

In C, x = (y = 3) + 1 is an assignment used as a value: two instructions, and the order in which y's store and x's read happen is fixed by the tree, not by the text.

An element of one byte hides the multiplication

With 4-byte integers, a[i] is t1 = i*4 then t2 = a[t1]. With a char array the scale is 1, and many generators fold i*1 away, so the same source shape costs one instruction instead of two.

The element size is part of the answer, so a question about instruction counts for indexing must state it — or state the array's type.

Six beliefs that cost marks, each with the case that refutes it

Every refutation below is a computation the page performs, not an appeal to authority.

1. "The SSA count and the least-temporaries count are the same"

The belief. Both ask how many temporaries an expression needs, so they must agree.

The refutation. For q+r/3+s-t*5+u*v/w the SSA count is 8 and the least live count is 2. Both are correct answers to their own question; the page computes both and prints them in the same table row.

The rule. SSA forbids reuse by definition. "Least temporaries" permits it. Read the phrase "in static single assignment form" before you count.

2. "Instructions always equal operators"

The belief. The operator count is the instruction count, so control flow does not change it.

The refutation. The while loop has no operators in the source's expression sense beyond one addition, yet it takes 5 instructions, 3 labels and 3 jumps. The if-else takes 5 instructions and defines nothing.

The rule. Operators give instructions for a straight-line expression. Control flow adds jumps and labels on top.

3. "Quadruples and triples are the same table with a column removed"

The belief. A triple is a quadruple without the result field, so anything true of one is true of the other.

The refutation. In a triple the result is a position. Insert a row at the top and every later (i) reference silently points at a different computation; in quadruples, names are unaffected. That is why indirect triples exist.

The rule. Quadruples name, triples number, indirect triples number through a movable table.

4. "Intermediate code is machine-dependent, and it exists to improve register allocation"

The belief. The form mentions temporaries, so it is about the machine; and since it is about storage, it helps register allocation.

The refutation. This is exactly GATE 2014 Set 3 Q17, whose keyed answer is optimiser reuse. Register allocation is machine-dependent and belongs to the back end, so it cannot be the purpose of a machine-independent form.

The rule. Machine independence is the whole point; anything register-shaped happens after the form.

5. "A label is one of the three addresses"

The belief. if x < y goto L2 names three things, so it is a three-address instruction in the same sense as t1 = a + b.

The refutation. L2 is a position, not a value; it cannot be an operand of arithmetic. The three addresses in the name refer to operands and result, and a jump uses none of them.

The rule. Labels are rows and targets. They are never operands.

6. "Short circuit is an optimisation, so any translation may drop it"

The belief. Skipping the second test is just a speed-up; the value is the same either way.

The refutation. The values do agree — the page checks all 16 combinations and both translations match. What differs is which evaluations happen: 4 of 16 against 16 of 16. If the second test divides by zero or writes a variable, the value-context translation changes the program's behaviour.

The rule. Short circuit constrains evaluation, not just results.

The five steps

  1. Read whether the form is SSA, plain three-address code, or registers.
  2. Count operators: each one is an instruction while the expression is evaluated.
  3. If SSA, count definitions: each needs a fresh name, so the answer is the operator count.
  4. If reuse is allowed, find the peak live count — at most the operator count, often much less.
  5. If the code has control flow, add labels and jumps, and say which count the question wants.

Step 1 decides the answer for the two questions in the table above, and it takes ten seconds.

Question shapes

Count a temporary or a variable. Numerical. Decide SSA or not, then count operators or definitions.

Identify the SSA form. MCQ. Reject any option that assigns the same name twice.

Identify the purpose. MCQ. The answer is machine independence and optimiser reuse, never registers.

Count instructions or rows. Numerical. Decide whether labels and stores are counted; the question's wording usually settles it.

Read a table. MCQ. Given quadruples or triples, say what a row computes — in triples, resolve (i) to row i before anything else.

Traps that recur

  • Answering the reuse count when the question says SSA. (8 against 2 on the same expression.)
  • Counting temporaries when the question says total variables. (5 against 10 on the 2016 segment.)
  • Counting operators for a program with a loop. (1 against 5 instructions.)
  • Treating a label as an operand or as an instruction.
  • Reading (1) in a triple as the value 1 instead of row 1.
  • Assuming short circuit holds in a translation that builds truth values first.

NATGATE 2015 Set 1, Q55

The least number of temporary variables required to create a three-address code in static single assignment form for the expression q + r/3 + s − t*5 + u*v/w is ______.

Answer: 8

SSA form gives every definition its own name, and the expression has eight operators: r/3, t*5, u*v, (u*v)/w, q+r/3, that plus s, that minus t*5, and the final addition. Eight definitions, eight temporaries.

Why 2 appears. Two slots suffice with reuse allowed — t1 = r/3, t2 = q+t1, t2 = t2+s, t1 = t*5, t2 = t2−t1, t1 = u*v, t1 = t1/w, t2 = t2+t1. Correct arithmetic, wrong question: the words "static single assignment form" forbid the reuse.

Why 3 appears. That is the Sethi-Ullman register number for this tree, which also charges a slot for each leaf value.

The page generates both forms and checks that each computes the expression's value on every input in its grid.

NATGATE 2016 Set 1, Q19

Consider the code segment x = u − t; y = x * v; x = y + w; y = t − z; y = x * y;. The minimum number of total variables required to convert it to static single assignment form is ______.

Answer: 10

Five variables are read before being defined — u, t, v, w, z — and each of the five statements defines a new name: x#1, y#2, x#3, y#4, y#5. Five plus five is ten.

Why 5 appears. That counts only the new definitions, which is the answer to "how many temporaries". Why 8 appears. That typically comes from counting the distinct names on the left of the original segment (x and y) as one each and then adding the five inputs — the renaming is what turns two source names into five definitions.

The page renames the segment, checks that no name is defined twice, and executes the renamed version to confirm it computes the same function on a grid of inputs.

NATOriginal practice question

For the expression a*b + c*d + e*f, how many temporary variables must hold a value at the same time if a temporary may be reused as soon as its value is dead? Give the least number.

Answer: 2

t1 = a*b; t2 = c*d; t1 = t1+t2; t2 = e*f; t1 = t1+t2. At most two values are live at any instruction, and the parent of two computed children forces at least two, so the minimum is exactly 2.

Why 5 appears. That is the fresh-name count: one per operator. Why 3 appears. That is the Sethi-Ullman register number, which also charges for the leaf values held during evaluation.

The page finds 2 by trying every legal evaluation order and keeping the smallest peak; it also runs the two-slot code over a grid of inputs and compares with the tree.

MSQOriginal practice question

Which of the following are true of the three-address code generated for while (x < n) { x = x + 1; } by the translation used in this lesson?

  1. It uses three labels.
  2. It contains five instructions that compute something, plus three label markers.
  3. Moving the test to the end of the loop leaves the loop's meaning unchanged.
  4. Every jump target is the name of a label that appears in the code.

Answer: A, B, D

The test, the body and the exit are three labels; the instructions are the conditional jump, the exit jump, the addition, the copy back and the loop-back jump; and each of the three jumps targets a label that exists.

Why C is wrong. Moving the test to the bottom turns the while into a do-while: with x = 5 and n = 0 the body runs once instead of zero times. The page's 25-pair check catches exactly this pair.

The page checks target validity mechanically and executes the code against max(x, n) for every pair in the grid.

MCQOriginal practice question

A triple table contains the rows 0: + a b, 1: + c d, 2: * (0) (1). What does row 2 compute?

  1. The product of the numbers 0 and 1
  2. The product of the values computed by rows 0 and 1
  3. The product of a and b
  4. The value stored in a variable named (0)

Answer: B

In a triple, the result of a row is identified by the row's position. (0) is the value defined by row 0, which is a+b; (1) is c+d. So row 2 computes (a+b)*(c+d).

Why A is wrong. It reads the position as a literal, which is the single most common error in reading triples. Why C is wrong. It stops one row too early: a*b is not in the table. Why D is wrong. There is no variable with that name; parentheses mark a position reference, not an identifier.

The page builds this triple table from the same instruction list as the quadruple table and evaluates both.

NATOriginal practice question

An array a has 4-byte integer elements. How many three-address instructions does x = a[i] take, counting the final store to x and not counting any label?

Answer: 3

t1 = i*4; t2 = a[t1]; x = t2. The multiplication that turns an index into a byte offset is an instruction of its own, and the store to x is a third.

Why 2 appears. That is the count without the store, which is right for "how many instructions to compute the value" and wrong for "how many to execute the assignment". Why 1 appears. That treats the indexed load as a single instruction, which is only true of the machine's addressing mode, not of the intermediate form.

The page prints the two-instruction load on the canvas with the scale of 4, and states the store separately.

Revision sheet

Everything on this tab is a rule or a number already derived above; nothing new is introduced.

Definitions in one line each

  • TAC: at most one operator, at most three addresses per instruction.
  • Temporary: a name for one computed value; not a source variable.
  • Live: defined and not yet last-used.
  • Quadruple: op, arg1, arg2, result.
  • Triple: op, arg1, arg2; result is the row number, written (i).
  • Indirect triple: triple rows plus a statement table of row numbers.
  • SSA: every name defined exactly once; phi at joins.

The counts

  • Straight-line expression: instructions = operators = fresh temporaries.
  • SSA: temporaries = definitions = operators.
  • Least live temporaries ≤ operators, and ≤ the register number.
  • Register number: leaf 1; unequal children take the larger; equal children k take k+1.
  • Loop: 5 instructions, 3 labels, 3 jumps (this scheme).
  • If-else: 5 instructions, 3 labels, 3 jumps (this scheme).
  • Short circuit: 7 instructions in control context, 14 in value context.
  • Indexed load: 2 instructions plus the store, at scale = element size.
  • Total SSA variables: inputs + definitions.

The decision procedure

  1. Is the form SSA? Then answer with the definition count.
  2. Is reuse allowed? Then answer with the least live count.
  3. Does the question say registers? Then use the Sethi-Ullman number.
  4. Does the question say total variables? Then add the inputs.
  5. Does the code contain control flow? Then decide whether labels count as rows.

Each step is a yes/no that fixes one number. Do them in order.

Three numbers to remember

8 — SSA temporaries for q+r/3+s−t*5+u*v/w (GATE 2015 Set 1).

10 — total SSA variables for the five-statement segment (GATE 2016 Set 1).

2 against 3 — the least live temporaries against the register number for a*b+c*d+e*f, the cleanest case where the two counts differ.

Quick self-checks

1. (a+b)*(c+d) in SSA form: how many temporaries? — 3, the operator count.

2. The same expression with reuse: how many live at once? — 2.

3. A while loop's translation has 5 instructions; how many rows does its quadruple table have? — 8, because the three labels are rows.

4. In a triple table, what does the operand (4) mean? — the value defined by row 4.

5. Which translation of a && keeps short circuit, and how do you tell from the counts? — the control translation: 7 instructions, and the second test runs in only 4 of 16 cases.
