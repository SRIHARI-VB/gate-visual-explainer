Topic and objective

TOPIC: Strings in C — the null terminator, string literals against character arrays, sizeof against strlen, escapes, the size_t return type, and the byte budget of the copy and append functions. This is a microtopic inside Section 4 of the official GATE 2027 CS syllabus, whose whole text for the section is "Programming in C. Recursion. Arrays, stacks, queues, linked lists, trees, binary search trees, binary heaps, graphs."

LEARNING OBJECTIVE: Given any declaration or fragment that involves a character array or a string literal, state the number of bytes stored and the number of characters before the first zero; decide whether the object is a string at all; say whether a write to it is defined; and trace a fragment that copies, prints or measures a string to its exact output — including the cases where the honest answer is that the behaviour is undefined.

I read this as one question asked four ways: how many bytes are stored, how many characters count, is it writable, and where does it stop. Almost every GATE item on strings in the last twenty years is one of those four, asked on a short literal and a small array.

The five ideas, in one line each

  • A string is bytes up to the first zero. The zero is data, and it is counted by sizeof and not by strlen.
  • A literal is not an array you own. char *s = "GATE" stores a pointer to somebody else's five bytes; char t[] = "GATE" stores the five bytes.
  • sizeof counts the object; strlen counts characters. For an array sized by its initialiser they differ by exactly one; for a pointer they are unrelated.
  • strlen returns size_t. A difference of two lengths is never negative, so a comparison against zero is almost always true.
  • A copy is not finished until the zero is written. Every library budget is strlen plus the text plus one.

Intuition first: a sentence with a full stop

Suppose every message you send must be written as one long strip of paper, and the reader is not told how long it is. The reader starts at the left and reads until a full stop. Everything after the full stop is ignored, even if it is written down. That is a C string: a strip of bytes and a full stop of value zero.

Three consequences fall out immediately, and they are the whole topic. One: the full stop takes a character's worth of paper, so a four-letter word uses five cells. Two: if you forget the full stop, the reader keeps reading past your strip into whatever is on the table. Three: if you are handed a slip of paper that only says where a strip begins, you cannot know how long it is without reading it — which is exactly why sizeof cannot measure a string you were handed. Educational interpretation The analogy carries the terminator, the extra cell and the walk to the stop. It does not carry writability, which is the subject of scene 2.

Formal vocabulary, every term in words

String. A contiguous sequence of characters terminated by and including the first null character. The null character is the byte whose value is zero; it is written '\0' in source and is not the digit zero.

Character string literal. A sequence of zero or more multibyte characters in double quotes. The compiler appends a byte of value zero and uses the result to initialise an array of static storage duration, of length just sufficient to hold it.

Character array. An array of char. It may or may not contain a zero, so it may or may not be a string.

size_t. The unsigned integer type that sizeof and strlen return. Its width is the machine's; its signedness is not negotiable.

Terminator. The zero byte that ends the string. It is stored, it is counted by sizeof, it is not counted by strlen, and it is not printed by %s.

The three rules this lesson rests on

Verified fact Initialising an array from a literal. "Successive bytes of the string literal (including the terminating null character if there is room or if the array is of unknown size) initialize the elements of the array." So the zero is stored when there is room, and dropped when the array is exactly one byte short.

Verified fact The literal's own array. "It is unspecified whether these arrays are distinct provided their elements have the appropriate values. If the program attempts to modify such an array, the behavior is undefined." So identical literals may share storage, and a write through a pointer to a literal has no defined result.

Verified fact strlen. It returns the number of characters that precede the terminating null character, and its declared return type is size_t.

Worked examples, page 1 of 2 — sizing and escapes

Each step states the rule it uses. Nothing is quoted from a table: the page's model builds the byte array and then reads the first zero, and the count of passing checks under the canvas includes every example here.

E1. Four declarations, four answers

  1. char a[] = "GATE"; — no size written, so the compiler makes the array just big enough. Content 4 bytes, plus the terminator. sizeof 5, strlen 4.
  2. char b[10] = "GATE"; — size written, so the array is 10. The literal fills five bytes including the zero, and the initialisation zero-fills the rest. sizeof 10, strlen 4.
  3. char c[4] = "GATE"; — 4 bytes for 5 needed. The rule stores the literal "including the terminating null character if there is room", and there is no room. sizeof 4, and no zero is present, so it is not a string.
  4. char *p = "GATE"; — the literal's array is five bytes elsewhere; p holds its address. sizeof p is the pointer width; strlen p is 4.

Mathematical derivation Step 3 is the one that decides marks. The declaration is legal; the use is not. Saying "strlen is 4" there is wrong, because no zero exists to stop the walk.

E2. Counting the bytes of an escaped literal

char t[] = "a\tb\\c\x41"; — count bytes, not source characters.

  1. a — one byte, value 97.
  2. \t — two source characters, one byte, value 9.
  3. b — one byte, value 98.
  4. \\ — one byte, value 92 (a backslash).
  5. c — one byte, value 99.
  6. \x41 — one byte, value 65, the letter A. A hex escape takes every following hex digit, so the next character must not be a hex digit or it is swallowed.

Six content bytes plus the terminator: sizeof 7, strlen 6. Written out, the array holds a, tab, b, backslash, c, A, zero.

E3. GATE 2017 Set 1 Q53 — the unsigned difference

int len = ((strlen(s) - strlen(t)) > c) ? strlen(s) : strlen(t); with s = "abc", t = "defgh", unsigned c = 0.

  1. strlen(s) is 3 and strlen(t) is 5. Both have type size_t.
  2. The subtraction is performed in the unsigned type. 3 − 5 is reduced modulo one more than the largest size_t, giving 4294967294 at 32 bits and 18446744073709551614 at 64 bits.
  3. That value is greater than 0, so the condition is true.
  4. The conditional selects strlen(s), which is 3, and 3 is stored in the int.

Answer 3. Verified GATE PYQ GATE CSE 2017, Set 1, Q53 (NAT, 2 marks). The answer does not depend on the width of size_t, only on the sign — which is why the question never states the width.

E4. GATE 2017 Set 2 Q55 — the reversed subscript

char *c = "GATECSIT2017"; char *p = c; printf("%d", (int)strlen(c + 2[p] - 6[p] - 1));

  1. a[i] is defined as *(a + i), and addition commutes, so 2[p] is p[2].
  2. The literal has twelve characters. p[2] is 'T' and p[6] is 'I'; letters are consecutive, so the difference is 11.
  3. c + 2[p] - 6[p] - 1 groups as (c + 11) - 1 = c + 10. The element type is char, so the offset is a byte count with no scaling.
  4. From index 10 the remaining characters are '1' and '7', then the zero at index 12. strlen is 2.

Answer 2. Verified GATE PYQ GATE CSE 2017, Set 2, Q55 (NAT, 2 marks).

E5. GATE 2025 Set 2 Q9 — the copy that stops one byte early

char a[30] = "@#Hello World!"; stringcopy(a, a + 2); where stringcopy is while (*t) *s++ = *t++;

  1. The array holds 14 characters at indices 0–13 and the zero at index 14. The other 15 bytes are zero-filled.
  2. a + 2 is the 'H'. The loop copies while the source byte is non-zero, so it copies the 12 characters at indices 2–13 into indices 0–11.
  3. The loop tests the zero and exits before copying it, so no terminator is written.
  4. Indices 12 and 13 still hold the original 'd' and '!', and the original zero at index 14 is untouched.
  5. printf("%s", a) prints twelve copied characters plus the two leftovers: Hello World!d!, 14 characters.

Answer: option D, Hello World!d! Verified GATE PYQ GATE CSE 2025, Set 2, Q9 (MCQ, 1 mark). Note that the source and destination overlap; copying forward from a higher index to a lower one is the safe direction, and here it is what makes the trace work.

E6. The 2004 segment, and why the answer is "nothing"

char p[20]; char *s = "string"; int length = strlen(s); for (i = 0; i < length; i++) p[i] = s[length - i]; printf("%s", p);

  1. length is 6. At i = 0 the code reads s[6 - 0], which is the terminator — reading it is defined, because the array has seven bytes and index 6 is inside it.
  2. p[0] therefore becomes the zero byte. The later iterations fill p[1] onwards, but a string ends at its first zero.
  3. printf("%s", p) stops immediately, so it prints the empty string — visually, nothing.

Answer: no output. Verified GATE PYQ GATE CSE 2004, 2-mark MCQ. The archives disagree on the question number (one numbers it 33, others 25, 49 or 78), so only the year is quoted as certain. The corrected loop is p[i] = s[length - 1 - i] followed by p[length] = '\0'.

The boundaries, each with the condition it violates

Six cases that decide marks. Each one is a rule applied at its limit, not a curiosity.

1. The empty string

char e[] = ""; — content zero bytes plus the terminator. sizeof 1, strlen 0. It is a perfectly good string: the zero is the first byte.

The condition people miss: strlen of it is 0, so strlen(e) - 1 is not −1. It is the largest value of size_t.

2. An embedded zero

char g[] = "GA\0TE"; — six bytes, sizeof 6, strlen 2. The array is complete; the string it holds stops at index 2.

The condition people miss: "the literal need not be a string", because an escape can put a zero inside it. sizeof still reports all six bytes.

3. One byte short

char c[4] = "GATE"; — the zero does not fit and is dropped. sizeof 4, and no zero byte exists.

The condition people miss: the declaration is legal and the object is not a string. strlen(c) reads past the array; the behaviour is undefined, not "4".

4. Two bytes short

char c[3] = "GATE"; — the initialiser would have to provide a value for an element the array does not have. The standard's initialisation rule permits exactly one dropped byte, the terminator, and only when the array is one short.

The condition people miss: this is not "the same as one byte short, but more so". It is not valid C, and a conforming compiler must diagnose it.

5. A pointer to a literal, written through

char *s = "GATE"; s[0] = 'g'; — undefined behaviour. The literal's array may sit in read-only memory, and identical literals may share one array.

The condition people miss: "undefined" is not a value. An answer of "gATE", "GATE" or a crash is equally unsupported; the correct answer is that there is no defined output.

6. strncpy with a short count

char d[8]; strncpy(d, "GATE", 4); — four bytes copied, no terminator. The destination is not a string.

The condition people miss: strncpy pads with zeros only when the source is shorter than the count. When the source is at least as long, nothing terminates the result.

The arithmetic boundary that catches the most people

for (i = strlen(s) - 1; i >= 0; i--) with an unsigned i, or with i declared size_t, never terminates when the string is empty: the start value wraps to the largest unsigned value, and i >= 0 is true for every unsigned value. The fix is a signed index, or the test i != 0 after decrementing, or a pointer walk that stops at the first byte.

Mathematical derivation The page checks the predicate v >= 0 over the whole 4-bit unsigned type and finds it true for all sixteen values; the same argument holds at 64 bits because every value of an unsigned type is non-negative by definition.

Five beliefs that cost marks

Each is stated as a learner states it, then killed with the smallest case that kills it.

M1. "A four-letter string is four bytes."

Why it tempts: the word has four letters, and strlen says 4, so 4 feels like the size.

Why it is wrong: the terminator is a stored byte. char a[] = "GATE" occupies five bytes.

Minimal counterexample: char e[] = ""; — zero characters, one byte. sizeof is 1 and strlen is 0.

Correct rule: for an array sized by its initialiser, sizeof = strlen + 1. That identity fails for a pointer and for a fixed larger array.

M2. "char *s = "GATE" and char t[] = "GATE" are the same."

Why it tempts: both print identically, both give 4 from strlen, and the initialiser looks the same.

Why it is wrong: one is a pointer to somebody else's static array; the other is your own array.

Minimal counterexample: s[0] = 'g'; is undefined behaviour; t[0] = 'g'; is fine. And sizeof gives the pointer width against 5.

Correct rule: the three differences are writability, sizeof, and assignability (s = "OTHER" is legal, t = "OTHER" is not).

M3. "sizeof tells you how long the string is."

Why it tempts: for char a[] = "GATE" it gives 5, one more than the length, so the two look interchangeable with an offset.

Why it is wrong: sizeof is answered by the compiler from the type and never reads the bytes.

Minimal counterexample: char b[10] = "GATE" gives sizeof 10 and strlen 4. And inside a function taking char t[], sizeof(t) is the pointer width.

Correct rule: sizeof measures the object; strlen measures the string. An array passed to a function arrives as a pointer, so its length must be passed separately.

M4. "strlen(s) - strlen(t) can be negative."

Why it tempts: the arithmetic is ordinary subtraction and the true value is −2.

Why it is wrong: both operands have type size_t, so the operation is unsigned and the result is reduced modulo the width.

Minimal counterexample: GATE 2017 Set 1 Q53: lengths 3 and 5, the comparison against 0 is true, and the program prints 3 rather than 5.

Correct rule: decide the sign first. A difference of two lengths is a length only when the first is at least the second.

M5. "A copy loop copies the whole string."

Why it tempts: the loop reads every character and writes every character, so it looks complete.

Why it is wrong: while (*t) stops before the zero, so the zero is never stored. The destination keeps whatever was there.

Minimal counterexample: GATE 2025 Set 2 Q9 — twelve bytes copied, the old 'd' and '!' survive, and the print is Hello World!d!.

Correct rule: the library strcpy copies the terminator too. A hand-written loop must add *s = '\0'; after it, and then the answer changes.

Two pairs that are constantly confused

String against character array. Every string is a character array that happens to contain a zero; not every character array is a string. The test is one scan for a zero byte, not a look at the declaration.

Undefined against unspecified. Writing to a literal is undefined — the standard imposes no requirement at all, so no output can be predicted. Whether two identical literals share storage is unspecified — the implementation must choose one behaviour and document nothing, so "ab" == 2 + "abcdef" may be 1 or 0 and both are conforming. An exam answer may rely on neither.

The question categories that apply, and the reasoning each demands

Categories A, B, C, E and G of the standard set apply here. D (construction) and F (multiple conditions) appear only as small parts of a trace; H (multi-step) is the commonest of all, because a string trace is several steps of index arithmetic.

A — direct definition, and C — calculation

Demands: the byte count and the character count for a stated declaration, including the escapes.

Expected path: find the object (array or pointer), lay out the bytes, mark the first zero, read off both numbers.

Common wrong approach: counting source characters instead of bytes, which turns "\t" into two and "\\n" into one.

B — property verification, and E — counterexample reasoning

Demands: "is this a string?", "is this write defined?", "does this copy produce a valid string?".

Expected path: scan for a zero; check writability against the declaration; check that the loop or function writes the zero.

Common wrong approach: answering from the code's intent rather than its bytes — assuming a copy loop terminates the result because a copy should.

H — multi-step trace, the dominant shape

Demands: the exact printed output of a fragment with pointer arithmetic, subscripts, or a loop over characters.

Expected path: write the index table, resolve each subscript to a character, convert characters to offsets only where the code does arithmetic, then count to the zero.

Common wrong approach: reading the expression left to right and adding bytes, instead of applying a[i] = *(a + i) and the scaling rule.

G — the misconception trap

Demands: notice that the intuitive answer is the one the question is built to punish.

Expected path: when the numbers are small and the code looks pointless, suspect a type or a terminator. The 2017 Set 1 item prints 3, not 5; the 2004 item prints nothing, not gnirts.

Common wrong approach: choosing the answer that matches the obvious intent of the code.

NAT original basic

char s[] = "GATE2027"; — what is sizeof(s)?

9. Eight characters and the terminator. strlen(s) is 8; sizeof adds the zero.

Wrong answer 8: counting characters instead of bytes. The array is sized by its initialiser, so it holds the content and the terminator.

MCQ original basic

Which declaration produces a character array that is not a string? (A) char a[] = ""; (B) char b[] = "x"; (C) char c[] = {'x'}; (D) char d[2] = "x";

(C). The brace form stores exactly the bytes listed, so c has one byte and no zero. (A) has sizeof 1 and is a string of length 0; (B) and (D) both store the terminator.

This is the one place the initialisation itself must write the zero.

NAT original basic

What is strlen("a\0b")?

1. The literal is a, a zero byte, b, and the appended zero: sizeof 4. The string ends at the embedded zero, at index 1.

A character string literal need not be a string, precisely because an escape can put a zero inside it.

MCQ original application

char buf[6]; strcpy(buf, "GATE"); strcat(buf, "!"); — what is the result, and is it safe?

buf holds "GATE!" and it is safe, exactly fitting. strcpy needs strlen(src) + 1 = 5 bytes, filling indices 0–4. strcat needs strlen(dst) + strlen(src) + 1 = 4 + 1 + 1 = 6, overwriting the zero at index 4 and writing a new one at index 5.

One more character would need 7 bytes and overflow. The buffer has no spare room at all.

NAT original application

char *p = "GATE"; on a machine where a pointer is 4 bytes. What does sizeof(p) + strlen(p) equal?

8. sizeof(p) is the pointer width, 4, not the text length. strlen(p) is 4. The sum is 8.

The trap is answering 5 + 4. A pointer's size never depends on what it points at.

MCQ original application

char d[8]; strncpy(d, "GATE", 4); printf("%s", d); — what is printed?

Nothing can be predicted. The count 4 copies G, A, T, E and no terminator, because the source was not shorter than the count. d is not a string, so %s reads past it.

strncpy pads with zeros only when the source is shorter than the count. The correct pattern is a count of sizeof(d) - 1 followed by an explicit terminator.

MCQ original conceptual

Inside a function int f(char t[]) { return sizeof(t); }, called with char a[100], what does f(a) return?

The pointer width, not 100. A parameter written char t[] is adjusted to char *t, so sizeof(t) is the size of a pointer.

This is the same rule as the literal-against-array distinction, one level up: the array decayed. Pass the length, or use a terminator.

NAT original conceptual

char *s = "GATE2011"; printf("%s", s + (s[4] - s[5])); — what is printed, and how many characters is it?

TE2011, six characters. s[4] is the digit '2' and s[5] is the digit '0'. Digits are consecutive too, so the difference is 2, and s + 2 is the 'T'.

The arithmetic works because the digits 0 to 9 are consecutive in every character set C permits — the same fact the 2017 item uses for letters. Any offset that leaves the array is undefined behaviour, so check that the difference lands inside before you trust it.

MSQ original conceptual

Which of these are guaranteed by the C standard? (A) sizeof(char) is 1. (B) Two identical string literals have the same address. (C) strlen returns size_t. (D) Writing to a string literal's array is undefined behaviour.

A, C and D. sizeof of a character type is 1 by definition. strlen is declared to return size_t. Modification of a literal's array is undefined.

B is unspecified, not guaranteed: "It is unspecified whether these arrays are distinct provided their elements have the appropriate values." Either behaviour is conforming, so no question may depend on it.

NAT original tricky

char a[] = "GATE"; printf("%d", (int)(sizeof(a) - strlen(a))); — what is printed? And what would it print if a were char *a = "GATE"; on a 64-bit machine?

1, then 4. As an array: 5 − 4 = 1. As a pointer: sizeof is 8 and strlen is 4, so 8 − 4 = 4.

The subtraction is unsigned but the result is positive here, so the wrap of the previous trap does not bite. Change the order and it would: strlen(a) - sizeof(a) gives a huge value, not −1.

MCQ original tricky

char p[20]; char *s = "string"; int n = strlen(s); int i; for (i = 0; i < n; i++) p[i] = s[n - 1 - i]; p[n] = '\0'; printf("%s", p); — what is printed?

gnirts. This is the 2004 segment with both defects repaired: the index is n - 1 - i so the first write is the last character, and the terminator is written explicitly at index n.

The original wrote s[n - i], which put the zero at p[0] and printed nothing. One index and one missing byte are the whole difference.

MSQ original tricky

char a[30] = "Hello"; stringcopy(a, a + 1); with while (*t) *s++ = *t++;. Which statements are true? (A) The loop copies four characters. (B) No terminator is written by the loop. (C) The output is ello. (D) The output is elloo.

A, B and D. The source a + 1 is "ello", four characters, copied to indices 0–3. The loop never writes the zero. Index 4 still holds the original 'o', and the original zero at index 5 still ends the string, so the print is elloo.

C is the tempting answer, and it is wrong for exactly the reason the 2025 question exists: the destination beyond the written region is untouched. Overlap is safe here only because the copy moves to a lower index.

One-screen revision sheet

Definitions, formulas with their conditions, the procedure, and the traps with the case that defuses each.

Definitions, one line each

String — bytes up to and including the first null character.

Null character — the byte of value zero, '\0', not the digit.

Literal — an unnamed array of static storage duration, initialised with the characters and a zero; may be shared; may not be modified.

Character array — an array of char; a string only if it contains a zero.

size_t — the unsigned type returned by sizeof and strlen.

Formulas and their conditions

sizeof = characters + 1 — only for an array sized by its initialiser with no embedded zero.

strlen = index of the first zero — only if a zero exists in the object.

Copy needs strlen(src) + 1 bytes; append needs strlen(dst) + strlen(src) + 1.

a[i] = *(a + i) = i[a], with the offset scaled by sizeof of the element type.

char names[R][C] is R*C bytes with stride C; char *names[R] is R pointer widths.

Decision procedure

  1. Read the declaration: array of known size, or pointer?
  2. Lay out the bytes, including every zero, with indices.
  3. Read sizeof from the object and strlen from the first zero's index.
  4. Check every subtraction or comparison involving lengths for unsignedness.
  5. Ask whether the terminator was written; if not, say "not a string" and "undefined".

If the fragment writes to a literal, the answer is undefined behaviour and no output may be predicted.

Traps, with the case that defuses each

"Four letters, four bytes" → char e[] = ""; is one byte.

sizeof as a length → char b[10] = "GATE"; gives 10 against 4.

Pointer as array → sizeof(p) is the pointer width.

Negative length difference → 2017 Set 1 Q53 prints 3, not 5.

Copy loop terminates the result → 2025 Set 2 Q9 prints Hello World!d!.

Writing to a literal → undefined, never a value.

Five sentences worth remembering

The zero is data: it is stored, counted by sizeof, invisible to strlen. A literal behind a pointer is not yours to write. sizeof answers from the type and strlen from the bytes. A difference of two lengths is unsigned, so its sign is not the arithmetic sign. And a copy is finished only when the zero has been written.

What this lesson was built from

Grouped by kind. Official material is separated from textbook material, and community material is labelled as observation rather than proof.

Official

  • GATE 2027 CS syllabus, IIT Madras, CS_GATE2027_Syllabus.pdf — Section 4: "Programming in C. Recursion. Arrays, stacks, queues, linked lists, trees, binary search trees, binary heaps, graphs." Source for the Class A classification and the scope boundary of this lesson.
  • Previous-year papers — the wording and data for GATE 2017 Set 1 Q53, GATE 2017 Set 2 Q55, GATE 2025 Set 2 Q9 and the GATE 2004 segment. Every numerical answer was recomputed by this page's model; no answer was taken from a key. Question numbering for the 2004 item differs between archives, so only the year is quoted.

Standard and textbook level

  • ISO/IEC 9899 (the C standard) — 6.4.5 for string literals (the appended zero, "if there is room" initialisation, unspecified distinctness, undefined modification), 7.1.1 for the definition of a string, 6.5.3.4 for sizeof of a character type, 7.24.2 for strlen, strcpy, strncpy, strcat and strcmp.
  • Kernighan and Ritchie, The C Programming Language — the character-array and pointer chapters, and the remark that strings are no longer modifiable and may be placed in read-only memory.
  • CERT C Secure Coding Standard, STR30-C — do not attempt to modify string literals; the rule this lesson's scene 2 enforces.
  • cppreference, string literals — the read-only placement, and the note that identical or overlapping literals may be combined.

Community material, used as observation only

Discussion threads on the 2004, 2017 and 2025 items were read to see which answers people reach and where the reasoning breaks. They are not cited as proof of anything: every claim above is supported either by the standard's own wording or by this page's computation. Community observation The commonest reported error across those threads is the same one in both directions — counting source characters instead of bytes, and expecting a copy loop to write the terminator. That is a report about discussion, not a measurement of difficulty.

What this lesson does not claim

No C compiler was run to produce these numbers; every sizeof, strlen and trace is computed by the page's model from the standard's rules and re-checked against those rules, and the page cannot detect a rule it has misread. Pointer sizes are carried as 8 and 4 and stated wherever they matter. No audio file exists. No video file exists. The timings in the subtitle files are estimated from the timeline at a normal speaking rate, not measured from recorded audio.
