Topic and objective

TOPIC: Command-line arguments in C — the two parameters of main, what the shell puts in them, the null pointer the standard requires at argv[argc], and the conversion of a word into a number.

LEARNING OBJECTIVE: Given a command line and a small C program that reads argc and argv, say exactly what the program prints, how many slots it reads, and whether it reads a null pointer — or say that its behaviour is undefined and therefore has no answer. State for each slot whether it holds the program name, a parameter or the sentinel, and choose between atoi and strtol on the evidence of whether the program must distinguish zero from nonsense.

I read this topic as the last untouched piece of Section 4's "Programming in C". C fundamentals covers types and control flow, Pointers covers addresses and dereferencing, Strings covers the zero byte, and File I/O covers the library's file functions. None of them owns the argument vector, and argc appeared in no lesson body before this one.

Prerequisites

  • C fundamentals — declarations, the int type, and an if statement.
  • Pointers in C — an address, a dereference, and a pointer that holds zero. Everything here is a pointer plus a subscript.
  • Strings and the null terminator — a C string ends at a zero byte, and that is one level below the sentinel on this page.
  • Arrays — an index is an offset, and an array name is not a value you can copy.
  • Helpful, not required: File I/O in C, for the habit of reading a library call's return value as a signal.

The six ideas, in one line each

  • argc counts the program name. Three typed parameters give argc equal to four.
  • argv holds pointers, not characters. The characters are separate objects behind them.
  • argv[argc] is a null pointer by requirement, so the array has one slot more than the count.
  • Test the sentinel; never print it. Comparing a null pointer is defined; following it is not.
  • atoi cannot report failure. The word abc and the word 0 both give zero.
  • sizeof(argv) is one pointer. The array was rewritten as a pointer at the parameter list.

1. Intuition — the tray of numbered slips

A clerk hands you a tray before you start work. The tray holds numbered slips, and the first slip is a label with your own desk number on it. Everything you were told is on a slip, and the slips are already separated: nobody hands you the sentence with its spaces, only the words. argv is that tray, argc is the number of slips, and argv[0] is your own desk number. Educational interpretation

Two details of the tray matter more than the rest. It always has one empty slot at the end, and the empty slot is not a mistake — it is a marker the clerk is required to leave, so you can stop when you reach it without knowing the count in advance. And the slips are not the words: a slip carries the address of a word written somewhere else in the building.

2. Formal definitions

argc. An int holding the number of strings in argv. The standard requires it to be nonnegative.

argv. An array of pointers to char, written char *argv[]. Slots 0 to argc − 1 hold pointers to strings supplied by the host environment. Slot argc holds a null pointer.

Null pointer. A pointer whose value is zero. It points at no object. The constant for it in C is NULL.

atoi(s). Skips leading blanks, takes an optional sign, reads digits, and returns the value of that prefix as an int. It reports no error, so a string with no digits returns zero.

strtol(s, &end, base). The same conversion, which also stores in end the address of the first character not converted. Comparing end with s is the error test.

3. Visual understanding — what the drawing has to show

The structure is two levels deep, and prose flattens it. A sentence like "argv holds the arguments" hides the fact that the slots hold addresses and the characters live elsewhere, which is exactly what a question about sizeof or about argv[2][0] tests. So the animation draws five pointer boxes, an arrow out of each, and the character cells behind them, with the terminator drawn as its own cell.

The second thing the drawing must show is that a loop bound is a count of slots fetched, not a warning. So the canvas draws the strict loop and the inclusive loop side by side and prints three reads against five, and marks the slot where the second one meets the null.

4. Worked example — one run, traced

The command line is ./prog 10 20 +. The shell produces four words. So argc is 4, and the slots are:

argv[0] = "./prog"
argv[1] = "10"
argv[2] = "20"
argv[3] = "+"
argv[4] = NULL

A loop for (i = 1; i < argc; i++) reads indices 1, 2 and 3. atoi gives 10, 20 and 0, because the plus sign has no digits after it. The total is 30, and the loop reads three slots.

5. Boundaries — when the rules apply

Hosted only. The two-parameter form of main and the null at argv[argc] are promises of a hosted environment, one running under an operating system. A freestanding program may define startup however it likes. Verified fact

Not a keyword. argc and argv are ordinary parameter names. int main(int n, char **v) is the same program.

No recovery of the line. Once the shell has split the line, the original spacing is gone. A program that needs it must be given it another way.

6. Edge cases that decide marks

No parameters. argc is 1, and argv[1] is the null pointer. Reading it is undefined, not zero.

argc may be 0. The standard requires only that it be nonnegative, and the clause making argv[0] the program name begins "if the value of argc is greater than zero".

An empty name. If no program name is available, argv[0][0] is the null character, so the name is a string of length zero.

7. GATE application

Questions on this material are almost always one of three shapes: give a command line and ask for argc; give a loop and ask for its output or its read count; give a declaration and ask what sizeof reports. All three are decided by the two-level picture and the off-by-one, so a candidate who can draw the five slots answers all three.

The fourth shape, which carries the most risk, is the one where the correct answer is undefined. A program that prints a plausible number is not evidence that its behaviour is defined.

Example 1 — counting

printf("%d\n", argc);

Run as ./a.out 10 20 this prints 3, not 2. Run as ./a.out it prints 1, not 0.

Mathematical derivation The count is the number of words the shell produced. The name is always one of them, so the count is the parameter count plus one.

Example 2 — printing every parameter

for (i = 1; i < argc; i++)
  printf("[%s]\n", argv[i]);

On ./a.out alpha beta this prints [alpha] then [beta].

Starting at 0 would print the program name first, which is the same loop with one word too many.

Example 3 — the sentinel loop

i = 1;
while (argv[i] != NULL) {
  puts(argv[i]);
  i++;
}

Same output as Example 2, and argc is never mentioned.

It is safe because the loop body only runs when the pointer is non-null. The sentinel ends the loop instead of entering it.

Example 4 — the counterexample

for (i = 0; i <= argc; i++)
  printf("%s\n", argv[i]);

At i = argc the counter is still inside the bound, and argv[argc] is a null pointer. printf with %s then asks the library to read a string at address zero.

Verified fact This is undefined behaviour, so there is no output to predict. The null is there to be tested, and this loop uses it instead. That single word separates this example from Example 3.

Example 5 — reading a number safely

char *end;
long v = strtol(argv[1], &end, 10);
if (end == argv[1]) {
  puts("not a number");
  return 1;
}

On ./a.out 42 the value is 42 and end points past the last digit. On ./a.out hello nothing is consumed, so end still equals argv[1] and the program says so.

Example 6 — the same conversion through atoi

int n = atoi(argv[1]);

On ./a.out 0 the value is 0. On ./a.out hello the value is also 0. On ./a.out + the value is 0 again.

Three different inputs, one value. The function did its job; its job is smaller than the question a program usually has.

One worked line, end to end

Run ./sum 5 7 through int s = 0; for (i = 1; i < argc; i++) s += atoi(argv[i]);. The words are "./sum", "5", "7", so argc is 3. The loop reads indices 1 and 2, converts to 5 and 7, and the total is 12. The bound i < 3 stops the loop before index 3, which is where the null sits. Every number in that sentence came from the run, and the page recomputes it.

No parameters at all

Run ./a.out and argc is 1, with argv[1] holding the null pointer.

A program that goes straight to atoi(argv[1]) follows a null pointer on exactly this run. The repair is a test of argc placed before any slot is read.

argc can be zero

Verified fact The standard requires only that argc be nonnegative, and the clause that makes argv[0] the program name begins "if the value of argc is greater than zero".

So a portable program reads argv[0] only after checking that argc is at least one. The case is rare in practice and legitimate in the language.

An empty program name

If the host environment cannot supply a name, argv[0][0] is the null character. The string then has length zero, and printing it prints nothing.

A program that parses its own name to decide a mode of operation has to survive that empty string.

Modifying the strings

Verified fact The parameters argc, argv and the strings the array points to are modifiable, and keep their last-stored values until the program terminates.

So overwriting a character in place is allowed. Writing past the string's own terminator is not: the permission covers the characters that exist, and says nothing about space that does not.

Writing to the sentinel

The constraint says argv[argc] shall be a null pointer. Storing a non-null pointer there breaks the constraint the standard places on the parameters.

Index argc + 1 is a different matter: it is outside the array, and reading it is out of bounds. The array has exactly argc + 1 slots.

Where the characters live

The standard fixes the shape of the argument vector and not its storage. On one system the strings sit at the base of the stack; on another they are copied to the heap.

So the addresses are implementation-defined. A question that asks for an address has no portable answer, and a question that asks for the count does.

A very long argument

The operating system imposes a limit on the total size of the argument list, and a program that exceeds it is never started. The C language states no limit.

So a failure to start is a fact about the environment, not about argc. Nothing in the language promises how many words fit.

Blanks inside one parameter

A word containing a space reaches the program as one string, because the shell joined it before startup. The program sees the space inside argv[1] and never sees the quoting.

The animation's splitter is a simplified shell: it separates on blanks and knows nothing of quoting. That is a modelling choice for this page, not a rule of the language.

“argc is the number of arguments”

Wrong. It is the number of strings in argv, and the program name is one of them. Three typed parameters give argc equal to 4.

Repair. Say the sentence out loud as "argc counts the name too" until the off-by-one is automatic. Then write the bound as argc and never as a remembered constant.

“argv[argc] is out of bounds”

Wrong. It is inside the array and its value is a null pointer by requirement. That is why a loop can stop on it.

Repair. Count the slots: argc + 1. What is out of bounds is argv[argc + 1], and the difference between the two indices is the whole point.

“The null at the end can be printed”

Wrong. It can be compared and it cannot be read through. printf with %s on a null pointer is undefined.

Repair. Keep two verbs apart: test the sentinel, use the strings. A loop whose body runs only on a non-null pointer does both correctly.

“char *argv[] and char **argv differ”

Wrong. In a parameter list the array type is adjusted to a pointer type, so the two declarations describe the same parameter.

Repair. The distinction that does exist is between an array object and a parameter. The object has a size; the parameter has only an address.

“sizeof(argv) tells you how many arguments there are”

Wrong. It reports the width of one pointer, because the array became a pointer. Dividing it by anything cannot recover the count.

Repair. The count is argc. The measurement is a fact about the machine's addresses, and it is the same number for a run with one parameter and a run with ten.

“The argument strings are read-only, like literals”

Wrong. The standard says the strings pointed to by argv are modifiable. The rule about string literals is a different rule about different objects.

Repair. Modifiable is not roomy. A two-character argument has no third slot to write, so overwriting in place is allowed and growing is not.

“If atoi returns 0, the argument was not a number”

Wrong. The argument may have been the word zero. atoi returns 0 for both, and has no way to say which happened.

Repair. Use strtol and compare the end pointer with the start. Equality means nothing was converted; a difference means something was.

The pair most often confused

Two nulls, two jobs. A string is ended by a zero byte, which is data: one character in a character array. The argument vector is ended by a zero pointer, which is an address: one slot in an array of pointers.

They are the same value written two ways and they live in different objects. A question that asks how many bytes the terminator occupies is asking about the byte; a question that asks how many slots the sentinel occupies is asking about the pointer.

How this topic is set, and the reasoning each shape demands

Three shapes cover almost every question on command-line arguments. Each is answered by the same drawing, and each has one trap. No question below is claimed as an official previous-year question; they are patterns, labelled as patterns.

Shape 1 — give the command line, ask for the output

The question supplies a run and a loop, and asks what is printed. The reasoning is a count of words and a count of slots read.

Procedure. Split the line. Add one for the name. Apply the bound. Convert each word with the function named.

Trap. A loop that starts at 0 still prints the right total when the name converts to 0. The output is not the evidence; the bound is.

Shape 2 — ask what is guaranteed

The question offers four statements and asks which hold. The reasoning is the split between the standard's promises and the implementation's choices.

Promised. Nonnegative argc; null at argv[argc]; string pointers below it; modifiable strings.

Not promised. Where the characters live; whether argv[0] is a bare name or a path; any particular argument count.

Shape 3 — the answer is "undefined"

A program reads a slot that may be null, or prints one. The correct answer is that the behaviour is undefined, and the tempting wrong answer is a plausible number or an empty line.

Procedure. Find the highest index the program can reach. Compare it with argc. If it reaches argc and uses the value, stop and answer undefined.

Trap. Reasoning from a remembered compiler. One implementation printing (null) is not the language's answer, and the standard imposes no requirement at all.

Shortcuts, and the assumptions they need

"argc = parameters + 1" needs argc at least one. At zero the subtraction gives minus one, and a loop bounded by it silently does nothing.

"atoi gives the number" needs the word to begin with a number. On a word that does not, the value is zero and the error is invisible.

"sizeof(argv) is the list size" needs the array to have survived the parameter list. It did not; the value is one pointer.

MCQOriginal practice question

The program is started as

./a.out 10 20

and its first statement is printf("%d", argc);. What is printed?

(A) 2   (B) 3   (C) 4   (D) undefined

Answer: B

Three words reach the program: the name, then 10, then 20. argc counts all three, so it is 3.

Why A is wrong. It counts only the two parameters you typed, and forgets that the program name is a word like any other.

The distinction being tested. argc is a count of strings in argv, not a count of what you typed after the name.

MCQOriginal practice question

Which one of the following is guaranteed by the C standard for a hosted program's main?

(A) argv[0] is an absolute path
(B) argv[argc] is a null pointer
(C) argc is at least 1
(D) argv holds argc slots

Answer: B

The program startup clause states that argv[argc] shall be a null pointer, as one of the constraints on the parameters of main.

Why A is wrong. The text of argv[0] is implementation-defined: a bare name, a relative path or an absolute path are all permitted.

Why C is wrong. The standard requires only that argc be nonnegative, and zero satisfies that.

Why D is wrong. The array has argc + 1 slots, because the sentinel needs one of its own.

MCQOriginal practice question

The program is started as ./a.out ab and runs

for (i = 0; i <= argc; i++)
  printf("[%s]", argv[i]);

Which statement is correct?

(A) It prints [./a.out][ab]
(B) It prints [./a.out][ab][]
(C) Its behaviour is undefined
(D) It fails to compile

Answer: C

Here argc is 2, so the loop reaches i = 2, and argv[2] is the null pointer. Handing a null pointer to printf with %s is undefined behaviour.

Why B is wrong. It assumes a null pointer prints as an empty string. Nothing in the standard promises that, and an implementation is free to abort instead.

Why D is wrong. The program is well formed. Its problem is at run time, and the compiler is not required to diagnose it.

The counterexample in this set. The null at argv[argc] exists, and this loop proves that existing is not the same as being printable.

NATOriginal practice question

The program is started as

./a.out a b c d

How many usable slots does argv have, counting the slot that holds the sentinel?

Answer: 6

Five words reach the program, so argc is 5. The array has argc + 1 slots: indices 0 to 5, with index 5 holding the null pointer.

The trap. Answering 4 counts only the parameters; answering 5 counts only the strings. The array is one slot larger than the count.

MCQOriginal practice question

On a machine where every pointer is 8 bytes, and for the run ./a.out 10 20 +, what does printf("%zu", sizeof(argv)); print inside main?

(A) 8   (B) 32   (C) 40   (D) 5

Answer: A

argv is a parameter, and a parameter declared with an array type is adjusted to a pointer type. So sizeof(argv) is the size of one pointer, which is 8.

Why C is wrong. 40 is five slots times eight bytes. That is what the array would measure if the type had survived, and it did not.

Why D is wrong. 5 is the slot count, which comes from argc + 1. No measurement recovers it.

The closely confused pair. An array object has a size; a parameter has an address. This question is decided by that difference alone.

MCQOriginal practice question

The program is started as ./a.out +. What does printf("%d", atoi(argv[1])); print?

(A) 0   (B) undefined, because + is not a number
(C) the value of + as a character   (D) it does not compile

Answer: A

atoi reads the optional sign and then finds no digit. With nothing to convert, it returns zero, and it has no channel for reporting the failure.

Why B is wrong. The behaviour is defined. It is the value that is uninformative, not the behaviour.

Why C is wrong. atoi converts text to an integer value. It never returns a character code.

The trap. Reading "defined but uninformative" as "undefined". The two are different diagnoses and they need different repairs.

MSQOriginal practice question

Which of the following statements about the strings that argv points to are true?

(A) They are modifiable by the program.
(B) Each is terminated by a null character.
(C) Their storage location is fixed by the standard.
(D) They retain their last-stored values until the program terminates.

Answer: A, B, D

A is the standard's explicit permission: the strings pointed to by the array are modifiable. B follows from their being strings at all. D is the second half of the same sentence, which says they retain their last-stored values between startup and termination.

Why C is wrong. Where the characters live is implementation-defined. One system puts them at the base of the stack, another on the heap, and the standard fixes neither.

Note on A. Modifiable does not mean roomy: writing past a string's own terminator is still out of bounds.

MCQOriginal practice question

The program is started as ./a.out, with nothing after the name, and its first statement is int n = atoi(argv[1]);. Which statement is correct?

(A) n is 0, because there was no argument
(B) n is undefined in value, because a null pointer was read through
(C) n is the value of argv[0]
(D) n is 1

Answer: B

With no parameters argc is 1, so argv[1] holds the null pointer. Passing it to atoi asks the library to read a string at address zero, which is undefined behaviour.

Why A is wrong. It treats a missing string as an empty string. There is no string there at all; the slot holds a null pointer, not a pointer to a zero byte.

The distinction being tested. An empty string is a real object of length zero. A null pointer is the absence of any object. atoi handles the first and is undefined on the second.

NATOriginal practice question

The program is started as ./sum 5 7 and runs

int s = 0;
for (i = 1; i < argc; i++)
  s += atoi(argv[i]);
printf("%d", s);

What is printed?

Answer: 12

argc is 3, so the loop reads indices 1 and 2, which hold "5" and "7". The conversions are 5 and 7, and the total is 12.

The trap. Starting the loop at 0 adds atoi("./sum"), which is 0, so the printed total would still be 12. The bound is what makes the loop right, not the output.

MCQOriginal practice question

A program must run with exactly two parameters and reject every other count. Which test is correct?

(A) if (argc != 2)
(B) if (argc != 3)
(C) if (argc != 1)
(D) if (sizeof(argv) != 2)

Answer: B

Two parameters plus the program name gives argc equal to 3, so any other count is the error case.

Why A is wrong. It is the off-by-one in its most common form: the count of parameters written where the count of strings belongs.

Why D is wrong. sizeof(argv) is the width of one pointer and never changes with the number of arguments.

MCQOriginal practice question

Which call distinguishes the argument 0 from the argument abc?

(A) atoi(argv[1])
(B) strtol(argv[1], &end, 10) followed by a test of end
(C) (int)argv[1]
(D) strlen(argv[1])

Answer: B

On "0" one digit is consumed and end moves past it. On "abc" nothing is consumed and end still equals the start. The comparison separates the two cases.

Why A is wrong. Both return 0, which is exactly the ambiguity the question is about.

Why C is wrong. A cast reinterprets an address as an integer. It reads no digits at all.

Why D is wrong. The lengths are 1 and 3, which distinguishes these two particular words and tells you nothing about whether either is a number.

Definitions to hold exactly

argc — the number of strings in argv, including the program name. Nonnegative.

argv — an array of char * with argc + 1 slots. Slot argc is a null pointer.

Sentinel — the null pointer that ends the array, present so a loop can stop without the count.

atoi / strtol — the same prefix conversion; the second also reports where reading stopped.

Decision procedure

  1. Split the command line into words.
  2. Add one for the program name: that is argc.
  3. Write the slots: 0 is the name, 1 to argc − 1 are parameters, argc is the sentinel.
  4. Find the highest index the program can reach and compare it with argc.
  5. If the program uses a slot that may be null, the answer is undefined.
  6. Otherwise convert each word and follow the loop.

Traps, in the order they cost marks

  1. Answering argc as the number of typed parameters.
  2. Answering 0 for a run with no parameters.
  3. Calling argv[argc] out of bounds.
  4. Assuming a null pointer prints as an empty line.
  5. Reading sizeof(argv) as the list size.
  6. Testing atoi's result against zero to detect a bad argument.
  7. Treating the argument strings as read-only literals.

Language behaviour

ISO/IEC 9899 committee draft N2731, clause 5.1.2.2.1 Program startup, read directly. It supplies, in the standard's own words: the two permitted definitions of main and the note that char **argv is equivalent; that argc shall be nonnegative; that argv[argc] shall be a null pointer; that argv[0] represents the program name and argv[0][0] is the null character when no name is available; and that the parameters and the strings are modifiable and retain their values.

cppreference, atoi and strtol — the prefix conversion, the absence of error reporting in atoi, and the end-pointer test in strtol. The atoi page was used for the claim that a string with no digits converts to zero.

Community discussion, used as observation only

Two points on this page were checked against community discussion rather than taken from the standard: whether the array of pointers itself may be modified, and whether writing to argv[argc] is permitted. The discussion records that the committee deliberately left the modifiability of the pointer array unspecified, and that the constraint on argv[argc] is a requirement on the program's parameters. Community observation Both points are marked as open on this page rather than settled, because the standard's text does not settle them.

Where the standard leaves a choice

Four behaviours are marked implementation-defined or undefined here rather than answered: the text of argv[0]; where the argument strings are stored; whether the array of pointers may itself be modified; and every program that reads through a null pointer. Each is labelled where it appears, so that a learner can tell a fact about C from a fact about one compiler.

What this page does not cover

The third parameter of main, the environment vector, is not developed: the standard makes it implementation-defined, and the syllabus does not name it. Shell quoting, redirection and globbing are named once as the shell's work and not taught, because they belong to a different program. Both omissions are recorded in the execution log so a later run can pick them up if the syllabus makes them explicit.
