Topic and objective

TOPIC: Memory interfacing and interleaving — the first half of GATE 2027 Section 3's memory clause: "Memory interfacing and hierarchy". The hierarchy and cache half is a separate published lesson.

LEARNING OBJECTIVE: Given a chip described as W words of b bits and a memory required as N words of B bits, compute chips across, rows, total chips, total address bits, the bits each chip takes, the bits left for the decoder, and the decoder size. Given a chip-select condition on address bits, name the exact address range it enables. Given m interleaved banks with a bank cycle time and a bus that accepts one word per bus cycle, compute the time to fetch n consecutive words and the sustained bandwidth — and state the condition under which the clean formula is allowed.

I read this topic as two divisions, one bit budget, one schedule. The two divisions turn two rectangles into an array. The bit budget turns the address into a split between what a chip needs and what a decoder needs. The schedule turns many slow banks into one fast-looking stream. Every question in this area is one of those three, wearing a different costume. Nothing here repeats the cache lesson: mapping, tags, replacement and average access time live there.

Prerequisites

  • Powers of two and logarithms. Every bit count is a log base 2 and every capacity is a power of two. That is the whole mathematical toolkit.
  • Binary and hexadecimal. Chip-select ranges are asked in hex; a 16-bit address in binary converts by grouping four bits.
  • What a decoder is. An n-input, 2n-output part that asserts exactly one output line. Built and counted in Design of Combinational Circuits.
  • The idea of a clock cycle and of overlapping work. For the interleaving half only. Pipelining and Hazards covers the same reasoning about overlap.

Nothing from Memory Hierarchy and Cache is assumed, but the two lessons are designed to be read in either order. Where a cache is mentioned here it is only as the thing that asks for a block.

Visualization plan

Ten scenes, each one argument:

  1. The rectangle. One chip, then the array built row by row from two divisions.
  2. The bit budget. Fourteen bits cut into four for the decoder and ten for every chip, with both checks.
  3. Wiring. What is broadcast, what is decoded — and the 2023 wiring that puts the decoder in the middle of the address.
  4. Chip select. Five fixed bits, eleven free, the window C800–CFFF drawn to scale on a 64 KB line.
  5. Decoder arithmetic. A 4-to-16 built from 2-to-4s, counted by the tree.
  6. Interleaving. The same sixteen addresses placed into four banks under both orders.
  7. The schedule. Two Gantt charts, four banks against two, 110 ns against 170.
  8. Bandwidth. The rising-then-flat curve and its knee, then the 2014 store count.
  9. A real block fetch. 24 banks, 48 bytes a round, two rounds, 184 ns and the dissent.
  10. The recipe. Four steps, five traps.

The five ideas to leave with

  1. Interfacing is two independent divisions: bits for width, words for depth. Never one division for both.
  2. The address split is forced: each chip consumes log of its own word count, and the remainder must choose a row.
  3. A chip-select region's size comes from the bits that were not decoded, not from the chip behind it.
  4. Low-order interleaving is what turns a sequential stream into parallel bank work; high-order does not.
  5. The formula tc + (n−1)tbus is a licensed shortcut. The licence is m·tbus ≥ tc, and several questions exist to revoke it.

Intuition: the shelf, the box and the trolley

A chip is a box with a fixed number of pigeonholes, and each pigeonhole holds a fixed number of letters. The box you can buy holds 1024 pigeonholes of 8 letters. The memory you need holds 16384 pigeonholes of 16 letters. You cannot buy that box, so you buy boxes and join them.

Two things must grow and they grow in different directions. To make a pigeonhole wider you put two boxes side by side and read both at once: that is the width direction. To make the shelf longer you stack rows of those pairs: that is the depth direction. One division gives each. Nothing about the width ratio tells you anything about the depth ratio, and confusing them is the first mistake in this topic.

Educational interpretation The analogy is a teaching device. It keeps two multiplications visibly separate, which is exactly what the exam asks you to keep separate.

Formal vocabulary, every symbol glossed

Chip organisation is written W × b: W words, each b bits. W is depth — how many different addresses the chip answers to. b is width — how many bits arrive on one access.

Target memory is written N × B: N words of B bits. Then:

across = B / b    rows = N / W    chips = across × rows

Address width of the finished memory is log2 N bits, because 2k addresses need k bits. Each chip takes log2 W of them; the remainder, log2 N − log2 W, is the select field that drives the row decoder.

Chip select (CS) is an input pin that enables a chip. Aliasing is the same physical word answering at two different addresses because too few bits were decoded.

Two checks that catch almost every slip

Both are arithmetic on numbers you already have, and both are cheap:

Check one. per-chip address bits + select bits = total address bits. In the running example, 10 + 4 = 14.

Check two. 2select bits = rows. In the running example, 24 = 16 rows.

The page computes both for every array it shows, and the Animation tab's model-check panel lists them. A design that fails either check is not a smaller or larger memory; it is a design that cannot be addressed.

Worked, in one line each

16K × 16 from 1K × 8. across = 16/8 = 2, rows = 16384/1024 = 16, chips = 32, select = 14 − 10 = 4 → a 4-to-16 decoder. Verified fact This is GATE 2013's array.

32K × 32 from 128 × 8. across = 4, rows = 256, chips = 1024.

256 KB from 32K × 1. across = 8/1 = 8, rows = 262144/32768 = 8, chips = 64.

Notice that the second and third examples give the same total bit capacity by completely different arrays. Capacity alone never determines the array.

From an array to a circuit: broadcast and decode

The array is now a rectangle of chips. What remains is to say which address lines go where. The rule is short: the bits that name a word inside a chip are broadcast to every chip that participates in the access, and the bits that name which row go to a decoder whose outputs are chip-select pins.

Inside a row, all chips receive the same address, because they are delivering different slices of the same word at the same instant. Exactly one row is enabled, because the decoder is one-hot. Two rows enabled at once is not a wider word; it is two chips driving the same data lines, which is a bus conflict.

The decoded bits need not be the top bits

Verified fact GATE 2023 (paper Q42, official key IIT Kanpur) realises a 4 KB byte-addressable memory from four 1 KB blocks, with IA4 and IA3 feeding a 2-to-4 decoder for chip select and the other ten lines feeding the address port of every block.

Nothing in the hardware requires the row bits to be contiguous or high. The consequence is worth seeing clearly: block k owns the addresses whose bits 4 and 3 spell k, so it owns eight bytes out of every thirty-two. The blocks start at 0, 8, 16, 24 and each holds 1024 bytes — but no block is a contiguous 1024 bytes.

Mathematical derivation Enumerating all 4096 addresses by their bits 4 and 3 partitions them into four sets of 1024, with minima 0, 8, 16, 24. The page does this enumeration and checks that the four sets partition the space exactly once.

The four options, and why three of them exist

The paper offered (0,1,2,3), (0,1024,2048,3072), (0,8,16,24) and (0,0,0,0). Each wrong option is a specific error:

(0,1,2,3) — believing a decoder always means consecutive blocks one byte apart.

(0,1024,2048,3072) — believing "four 1 KB blocks" means four contiguous kilobyte regions, which is what you would get if IA11 and IA10 drove the decoder.

(0,0,0,0) — reading only the ten address-port lines and ignoring the decoder input entirely.

Chip select as a logic condition

A chip-select pin is an AND gate over address bits, some inverted. A bit wired straight in demands a 1; a bit through an inverter demands a 0; a bit not wired at all is free.

range size = 2(address bits − fixed bits)

Verified fact GATE 2019 asks for the range enabled by A15A14A13'A12'A11. Five bits are fixed, eleven are free, so 211 = 2048 addresses, from 1100 1000 0000 0000 to 1100 1111 1111 1111, that is C800 to CFFF. The page enumerates all 65 536 addresses, counts the enabled ones and confirms 2048.

Interleaving: making many slow banks look like one fast one

A bank of memory accepts one request per cycle time. It cannot do better. But if memory is split into m banks and consecutive addresses land in different banks, then m requests can be in flight at once, and the only shared resource is the bus.

Two mappings are worth knowing by name. Low-order interleaving takes the bank number from the low bits, so bank = address mod m and consecutive words go to different banks. High-order interleaving takes it from the high bits, so consecutive words stay in one bank and each bank holds one contiguous block of the address space.

The schedule, and the condition

Under low-order interleaving with m banks, bank b serves words b, b+m, b+2m, … The bus returns to that bank after m bus cycles. The bank needs its full cycle time tc before it can accept the next request.

if m·tbus ≥ tc  then  T(n) = tc + (n−1)·tbus

Mathematical derivation The first word costs the full bank cycle because nothing can overlap with it. Every later word costs one bus cycle, because a bank is free exactly when its turn comes. If the condition fails, the bus waits, and the formula understates the time.

Counterexample: two banks, 40 ns cycle, 10 ns bus

The condition is 2 × 10 = 20 < 40, so the formula is not licensed. The formula would say 40 + 7×10 = 110 ns for eight words.

Simulating the schedule: word 0 starts at 0, word 1 at 10, word 2 at 40 (bank 0 busy until 40), word 3 at 50, word 4 at 80, word 5 at 90, word 6 at 120, word 7 at 130 — finishing at 170 ns.

So the true answer is 170, not 110. Mathematical derivation The page simulates this and asserts the 170.

Bandwidth is the interval, inverted

Once the pipeline is running, words emerge at a fixed rhythm:

interval = max(tbus, tc / m)    bandwidth = word width / interval

So bandwidth rises with m while the banks are the limit, then flattens at one word per bus cycle. The knee is exactly m·tbus = tc. Past the knee, extra banks cost money and buy nothing.

Five worked examples, each with its justification

Every number below is recomputed by the page's model, and the Animation tab's check panel lists which ones passed. The three previous-year items carry their paper; the two others are marked as original practice in the same shape.

1. Build a 16K × 16 memory from 1K × 8 chips

Step 1. across = 16 bits / 8 bits = 2. Why: one chip supplies half a word, so two share every address.

Step 2. rows = 16384 words / 1024 words = 16. Why: each row holds 1024 words, and 16 rows reach 16384.

Step 3. chips = 2 × 16 = 32. Why: it is a grid, so the count is the product.

Step 4. address bits = log2 16384 = 14; per chip = log2 1024 = 10; select = 4.

Step 5. Decoder = 4-to-16. Check: 24 = 16 = rows. Verified fact This is the GATE 2013 array; its answer, 5 two-to-four decoders, follows below.

2. Count the decoders (GATE 2013, Q46)

The parts bin holds only 2-to-4 decoders with an enable input. Build the 4-to-16 row decoder.

Step 1. Sixteen rows means sixteen outputs, so the row decoder is 4-to-16 — not 32-to-anything, because there are 32 chips but only 16 rows.

Step 2. One 2-to-4 takes the top two bits and produces four enable signals.

Step 3. Four more 2-to-4s, each enabled by one of those signals, produce four outputs each: 16 in total.

Step 4. Count the tree: 1 + 4 = 5. Verified fact Official key: option B, 5.

3. The chip-select range (GATE 2019)

Sixteen address lines. The chip-select gate requires A15 = 1, A14 = 1, A13 = 0, A12 = 0, A11 = 1.

Step 1. Five bits are fixed; eleven are free.

Step 2. Lowest address: free bits 0 → 1100 1000 0000 0000 = C800.

Step 3. Highest address: free bits 1 → 1100 1111 1111 1111 = CFFF.

Step 4. Size = 211 = 2048 = CFFF − C800 + 1. Verified fact Official key: option A, C800 to CFFF. The page enumerates all 65 536 addresses and counts 2048 enabled.

4. Four banks, 40 ns cycle, 10 ns bus, eight words

Step 1. Condition: 4 × 10 = 40 ≥ 40, so it holds — exactly, with no slack.

Step 2. First word finishes at 40 ns.

Step 3. Each later word is issued one bus cycle after the previous, and its bank is free by then.

Step 4. T = 40 + 7 × 10 = 110 ns. Bandwidth = 4 bytes / 10 ns = 0.4 bytes per ns. Mathematical derivation The page simulates the schedule and gets 110.

5. Store throughput (GATE 2014 Set 2)

Eight modules on a one-word bus. A write occupies the bus for 100 ns; the addressed module is then busy for a further 500 ns. Different modules may overlap; only one request may be on the bus.

Step 1. Module cycle = 100 + 500 = 600 ns.

Step 2. Condition: 8 × 100 = 800 ≥ 600, so no request ever waits for a module.

Step 3. The bus is therefore the only limit: one store per 100 ns.

Step 4. 1 ms / 100 ns = 10 000 stores initiated. Verified fact Official key: 10 000. With five modules it would be 8 330 instead, and the page computes both.

6. A 64-byte block through 24 banks (GATE 2006, Q41)

A CPU has a cache with block size 64 bytes. Main memory has k banks, each c bytes wide, with consecutive c-byte chunks mapped to consecutive banks with wrap-around. All k banks are accessed in parallel, but two accesses to the same bank are serialised. Each parallel round requires decoding the bank numbers, costing k/2 ns. One bank access costs 80 ns. Take c = 2 and k = 24, and find the latency of retrieving a cache block starting at address zero.

Step 1. One round moves 24 × 2 = 48 bytes.

Step 2. 64 bytes needs ⌈64/48⌉ = 2 rounds, moving 96 bytes for 64 wanted.

Step 3. Each round: 24/2 = 12 ns decode + 80 ns access = 92 ns.

Step 4. 2 × 92 = 184 ns.

Community observation Published solutions disagree. Most give 184 ns (option D). Some give 172 ns (option C) by overlapping the second round's decoding with the first round's fetch, which is only valid if the bank addresses are latched in a buffer. The question says each round requires decoding, so 184 is the reading this lesson takes — and the disagreement is stated rather than hidden.

Edge case 1: a block is a set of addresses, not a range

GATE 2023's four 1 KB blocks each hold 1024 bytes, and none of them is a contiguous 1024 bytes. Block 2 owns addresses 16–23, 48–55, 80–87, … — eight bytes in every thirty-two. A design description that says "four 1 KB blocks" tells you their sizes and nothing about their addresses; the wiring tells you the addresses.

This is also the cleanest bridge in the syllabus from interfacing to interleaving: the same question that looks like chip select is really asking you to describe a four-way interleave at eight-byte granularity.

Edge case 2: aliasing when too few bits are decoded

A 256-byte chip enabled by a condition that leaves 11 free bits answers at 2048 addresses — eight distinct physical regions collapse onto the same 256 bytes. That is address aliasing.

It is silent: every access succeeds and returns plausible data. It only fails when a program assumes two addresses are distinct. The fix is to decode more bits, which is why real designs decode every unused high bit.

Edge case 3: the condition holds with no slack

Four banks, 40 ns cycle, 10 ns bus gives 4 × 10 = 40, exactly equal. The formula holds, but any extra bus delay — a refresh, a bus arbitration cycle, one wait state — breaks it immediately, because there is zero margin.

Exact equality is the boundary, not a comfortable design point. Questions often sit on it deliberately, because the arithmetic is cleanest there.

Edge case 4: initiated is not completed

In the 2014 question, 10 000 stores are initiated in a millisecond. The first completes at 600 ns, and the last initiated one has not completed when the window closes. Counting completions gives 9 995.

Read the verb. "Initiated", "issued", "accepted" and "completed" are four different counts, and the difference is the pipeline depth.

Edge case 5: a chip wider than the word needed

If the target word is 8 bits and the chip is 16 bits wide, across is a half, which is meaningless. You use one chip and waste half its width, or you build a 16-bit memory instead. The divisions must be checked for integrality before they are multiplied.

The same trap appears the other way: a target word of 24 bits from 8-bit chips needs three chips across, and no power of two is involved.

Edge case 6: refresh is part of the cycle budget

DRAM must be refreshed row by row. If a chip has r rows, each refresh takes tref, and the whole array must be refreshed within a period P, then the fraction of time unavailable is r·tref / P.

Example: 213 rows at 60 ns within 4 ms costs 8192 × 60 ns = 491 520 ns, which is 12.3% of the period, leaving 87.7% for reads and writes. This is original practice, not a quoted paper. The page computes it.

Edge case 7: a bank conflict can erase the whole benefit

Interleaving only helps when consecutive requests go to different banks. A stride of exactly m words under low-order interleaving sends every request to the same bank, and the system performs exactly like a single bank. That is why the number of banks is a power of two in almost every real design — it makes the bank field a clean slice of the address — and why compilers and array layouts care about the stride.

"The number of chips is the capacity ratio, and that is the answer"

Why it tempts: the capacity ratio really does give the right chip count, so the first half of every question checks out.

The counterexample: 32K × 32 from 128 × 8 is 1024 chips, and the array is 256 rows of 4. Answering 1024 is right; answering 1024 to "how many rows" is wrong by a factor of 4.

The rule: do both divisions. The chip count is their product and the row count is one of them.

"A 4 KB memory built from four 1 KB blocks has blocks at 0, 1024, 2048, 3072"

Why it tempts: that is what happens when the decoder takes the top address bits, which is the usual textbook drawing.

The counterexample: GATE 2023 wires IA4 and IA3 to the decoder and gets 0, 8, 16, 24.

The rule: read which lines go to the decoder. The block boundaries are wherever those lines change, not wherever the capacity suggests.

"The chip-select range is as big as the chip"

Why it tempts: in a well-designed system they are equal, so the two numbers agree and the error never shows.

The counterexample: five fixed bits out of sixteen leave 2048 addresses regardless of whether a 256-byte or a 2 KB chip sits behind the gate.

The rule: the range comes from the address logic; the chip size comes from the chip. Equality is a property of a correct design, not a definition.

"Interleaving makes memory faster"

Why it tempts: the bandwidth really does multiply, and bandwidth is what "faster" usually means.

The counterexample: the latency of one isolated access is unchanged, and may even rise because of the bank decoder. A single dependent load chain gains nothing.

The rule: interleaving raises throughput for independent or sequential requests. It does not lower the latency of one request.

"High-order interleaving is just the worse one"

Why it tempts: it loses on the sequential stream, which is the case every example uses.

The counterexample: for a program whose working set is one contiguous block, high-order interleaving keeps that block inside one bank, so it never contends with another bank's traffic.

The rule: low-order suits sequential streams; high-order suits locality. Neither dominates.

"The overlap formula is the formula for interleaved access"

Why it tempts: it is in every set of notes, and it gives the right answer for the examples those notes use.

The counterexample: two banks, 40 ns cycle, 10 ns bus. The formula says 110 ns for eight words; the schedule takes 170.

The rule: check m·tbus ≥ tc first, then use the formula. If the check fails, simulate.

"The decoder size follows from the chip count"

Why it tempts: the decoder question and the chip-count question usually sit in the same part, so the last number computed gets reused. The counterexample: the 2013 array has 32 chips and 16 rows, and the row decoder has 16 outputs. Dividing 32 by 4 gives 8, which is not a decoder size in the options. The rule: the row decoder's output count equals the number of rows, which is the depth ratio, and the width ratio never enters it.

Six question shapes, and the reasoning each demands

Every previous-year item in this area that this lesson examined is one of these six. None of them needs a formula you have not seen; all of them need the two divisions and the bit split to be done in the right order.

Shape 1 — count the chips

"How many 128 × 8 RAMs are required to design a 32K × 32 RAM?"

Reasoning: across = 32/8 = 4, rows = 32768/128 = 256, chips = 1024.

Common wrong approach: dividing the two capacities in bits and treating the result as final, which here happens to give the right count but no array shape.

Shape 2 — size the decoder

"How many 2 × 4 decoders with enable are needed to build a 16K × 16 RAM from 1K × 8?"

Reasoning: rows = 16, so a 4-to-16 decoder, built as 1 + 4 = 5 small decoders.

Common wrong approach: counting chips (32/4 = 8) or answering 4 and forgetting the root that drives the enables.

Shape 3 — name the address range

"The chip select is generated by A15A14A13'A12'A11. What range does it enable?"

Reasoning: write the fixed bits, zero the free bits for the base, one them for the top.

Common wrong approach: treating the free bits as a low-byte suffix, which gives C800–C8FF instead of C800–CFFF.

Shape 4 — find the block start addresses

"Two address lines drive a decoder into four blocks; give the starting address of each block."

Reasoning: zero the address-port bits, set the decoder inputs to k, read the whole address as one number.

Common wrong approach: assuming the decoder takes the top bits, which is the option (0, 1024, 2048, 3072) sitting there waiting.

Shape 5 — time a sequence of words

"m banks of tc ns behind a bus that takes one word per tbus: how long for n consecutive words?"

Reasoning: check m·tbus ≥ tc; if it holds use tc + (n−1)tbus, otherwise lay out the schedule.

Common wrong approach: n × tc (ignoring overlap entirely) or the formula without the check.

Shape 6 — throughput under overlap

"Eight modules, 100 ns bus, 600 ns module cycle: how many stores can be initiated in 1 ms?"

Reasoning: check the condition, then divide the window by the limiting interval.

Common wrong approach: dividing by the module cycle (1666) or answering completions (9995) when the question asked for initiations.

The procedure, in the order the exam wants it

Write down both rectangles. Do the two divisions and keep them labelled. Compute the three bit counts and check both identities. If a decoder is asked for, count by the tree, from rows. If a range is asked for, fix and free the bits, then read the hex. If a time is asked for, write the condition first and the formula second. Convert units once, at the end.

NATEasyOriginal practice

A memory of 64K words of 32 bits is built from chips of 8K words of 4 bits. How many chips are required?

Answer: 64

across = 32/4 = 8, rows = 65536/8192 = 8, chips = 64.

The array is 8 rows of 8 chips. Answering 64 by dividing bit capacities gives the same number and hides the shape — which is what the next part of such a question usually asks for.

NATEasyOriginal practice

For that 64K × 32 memory, how many address bits go to each chip, and how many go to the row decoder?

Answer: 13 to each chip, 3 to the decoder

Total = log2 65536 = 16. Per chip = log2 8192 = 13. Select = 3.

Check: 23 = 8 = rows. The row decoder is 3-to-8.

MCQMediumPYQ — GATE CSE 1991, Q1(ii)

In interleaved memory organisation, consecutive words are stored in consecutive memory modules in ______ interleaving, whereas consecutive words are stored within the module in ______ interleaving.

(A) high-order, low-order   (B) low-order, high-order   (C) horizontal, vertical   (D) block, cyclic

Answer: (B) low-order, high-order

Under low-order interleaving the bank is the low part of the address, so consecutive addresses sit in consecutive modules. Under high-order interleaving the bank is the high part, so consecutive addresses stay inside one module until its word field runs out.

"Cyclic" and "block" are the informal names for the same two ideas, and are not the answer here. The page maps addresses 0–3 under both orders and checks that one spreads and the other does not.

MCQMediumPYQ — GATE CSE 2023, Q42

A 4 KB byte-addressable memory is realised from four 1 KB blocks. IA4 and IA3 drive a 2-to-4 decoder whose outputs are the chip selects; the other ten lines IA11–IA0 drive the address port of every block. The starting addresses of the four blocks are:

(A) 0, 1, 2, 3   (B) 0, 1024, 2048, 3072   (C) 0, 8, 16, 24   (D) 0, 0, 0, 0

Answer: (C) 0, 8, 16, 24

At a block's starting address the ten address-port bits are zero, so only IA4 and IA3 carry weight: 24 = 16 and 23 = 8. For k = 0,1,2,3 those give 0, 8, 16, 24.

Option B is the top-bits assumption. The page enumerates all 4096 addresses by their bits 4 and 3, confirms four sets of 1024, and confirms they partition the space exactly once.

Two previous-year items with numbers, one multiple-select, and one counterexample question that exists because the formula is usually trusted.

NATMediumPYQ — GATE CSE 2014 Set 2

A main memory system has 8 modules attached to a one-word-wide system bus. A write occupies the bus for 100 ns; during that time and for 500 ns thereafter the addressed module executes one cycle. Module operations may overlap, but only one request may be on the bus. The maximum number of one-word stores that can be initiated in 1 ms is ______.

Answer: 10000

Condition: 8 × 100 = 800 ≥ 600, so the bus never waits for a module. The bus, not the module, is the limit: 1 ms / 100 ns = 10 000.

Dividing by 600 gives 1666 and answers a different question. With five modules the answer would be 8 330, because 5 × 100 = 500 < 600 forces a stall after every fifth store — the page simulates both and checks the first wait lands on store six.

NATHardPYQ — GATE CSE 2006, Q41

Cache block 64 bytes; main memory has k banks of c bytes each, consecutive c-byte chunks on consecutive banks, all k banks accessed in parallel, two accesses to one bank serialised. Each parallel round costs k/2 ns to decode, and one bank access costs 80 ns. With c = 2 and k = 24, the latency of retrieving a block starting at address zero is ______ ns.

Answer: 184

One round moves 24 × 2 = 48 bytes; 64 bytes needs 2 rounds; each round is 12 + 80 = 92 ns; total 184 ns.

Published solutions disagree: 172 ns is obtained by overlapping the second round's decode with the first round's fetch, which requires latching the bank addresses. The question states that each round requires decoding, so 184 is the reading taken here.

MSQMediumOriginal practice

A memory has 4 banks of cycle time 60 ns behind a bus that accepts one word per 20 ns. Which statements are TRUE?

(A) The clean overlap formula applies.
(B) Eight consecutive words take 60 + 7 × 20 = 200 ns.
(C) Sustained bandwidth is one word per 20 ns.
(D) Doubling the banks to eight would double the bandwidth.

Answer: (A), (B), (C)

4 × 20 = 80 ≥ 60, so (A) holds and (B) follows. The steady interval is max(20, 60/4 = 15) = 20 ns, so the bus is the limit and (C) holds.

(D) is false: the system is already bus-limited, so more banks change nothing. This is the knee, and it is where a "more banks is better" instinct fails.

NATHardOriginal practice — the counterexample

Two interleaved banks, cycle time 40 ns, bus accepts one word per 10 ns. How many nanoseconds does it take to fetch 8 consecutive words?

Answer: 170

2 × 10 = 20 < 40, so the formula is not licensed. Laying out the schedule: starts at 0, 10, 40, 50, 80, 90, 120, 130 ns; the last finishes at 130 + 40 = 170 ns.

The formula would have said 110. This is the distinction the lesson insists on: the formula is a shortcut with a condition, and the condition is checkable in one multiplication.

NATMediumOriginal practice

A DRAM chip has 213 rows. Each refresh operation takes 60 ns and the whole chip must be refreshed every 4 ms. What percentage of the time remains available for read and write operations? Give your answer to one decimal place.

Answer: 87.7 per cent

Refresh cost = 8192 × 60 ns = 491 520 ns = 0.49152 ms. As a fraction of 4 ms that is 12.288%.

Available = 100 − 12.288 = 87.712%, so 87.7%. The page computes this and checks the value. The usual slip is comparing one refresh with the whole period instead of all rows with it.

One distinction to carry into the exam

Interfacing answers "how is the memory built" — chips, rows, bits, decoder, range. Interleaving answers "how is the memory used" — bank mapping, schedule, bandwidth. The two meet in exactly one place: the address bits. Interfacing splits the address into chip bits and row bits; interleaving splits it into bank bits and word bits. Both are the same bit budget, spent for different purposes, and a question that seems to mix them is usually asking you to say which split it means.

One-screen revision sheet

Everything on this tab is a definition, a derivation or a check. Nothing here is a rule of thumb that needs a condition you have not been given.

Build

across = B/b   rows = N/W   chips = across × rows

addrBits = log2N   chipBits = log2W   select = addrBits − chipBits

Checks: chipBits + select = addrBits, and 2select = rows.

Wire

Word bits → every chip in the selected row (broadcast). Row bits → decoder → chip-select pins (one-hot).

The decoded bits need not be the top bits, and the decoder size follows from rows, never from the chip count.

Select

range size = 2(address bits − fixed bits)

Base = fixed bits written, free bits zero. Top = free bits one. Size comes from the free bits, not from the chip.

Interleave

low-order: bank = addr mod m    high-order: bank = top bits

interval = max(tbus, tc/m)    bandwidth = word width / interval

Low-order spreads a sequential stream; high-order keeps a block in one bank.

The condition, stated before the formula

T(n) = tc + (n−1)tbus   only if   m·tbus ≥ tc

If it fails, the bus waits and the true time is larger. Simulate: word i goes to bank i mod m, starts at the later of its bus slot and that bank's freedom, and occupies it for tc.

Five traps, in one line each

1. Bits read as bytes — divide by the word size before taking a logarithm.

2. One division for both axes — the chip count is right and the array shape is wrong.

3. Chips counted where rows are asked — the row decoder's size is the depth ratio.

4. Range size taken from the chip — it comes from the undecoded bits.

5. The formula used without its condition — two banks at 40/10 breaks it.

Numbers worth remembering

16K × 16 from 1K × 8 → 32 chips, 4-to-16 decoder, 5 two-to-four decoders. 32K × 32 from 128 × 8 → 1024 chips. 256 KB from 32K × 1 → 64 chips. Five fixed bits in a 16-bit address → 2048 addresses. Decoder at bits 4 and 3 → blocks at 0, 8, 16, 24. Four banks, 40 ns cycle, 10 ns bus, eight words → 110 ns; two banks → 170 ns. Eight modules of 600 ns behind a 100 ns bus → 10 000 stores initiated per ms. 24 banks of 2 bytes, 64-byte block → 184 ns.
