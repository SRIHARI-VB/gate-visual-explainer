Topic and objective

TOPIC: DNS and HTTP — the last clause of Section 10, Computer Networks, in the GATE 2027 CS syllabus.

LEARNING OBJECTIVE: Read a domain name right to left as a path through a delegation tree, and count the servers that must be asked to resolve it. Read a resource record and explain what the time to live is for. Lay out a DNS query on the wire and justify the 512-byte ceiling. Read an HTTP request and response line by line, place a method in the safe and idempotent table, and place a status code in its family. Explain why HTTP is stateless and how a cookie carries the state instead. Count TCP connections and round trips for non-persistent, persistent and pipelined fetching, and add DNS time to the total in the right order.

I read this clause as one question asked three ways: how many servers must be asked, how many round trips does it cost, and how many bytes does the message take. Almost every GATE item on DNS and HTTP in the last ten years is one of those three, asked on small numbers.

GATE relevance

Prerequisites

  • TCP flow control, congestion control and the socket API — the three-way handshake, the socket calls, and what a connection is bound to. Every round-trip count in this lesson assumes that handshake.
  • IPv4 fragmentation, CIDR and NAT — an address, a prefix and a rewritten header, which is all the addressing this lesson needs.
  • Layering and performance metrics — what a round trip is, and why latency and bandwidth are separate quantities.
  • Counting and division. The byte arithmetic in the message section is one subtraction and one floor.

Nothing here needs a browser, a server, or any software installed. Every number is computed on the page.

The five ideas, in one line each

  • A name is a path. Read it right to left; each label may be a delegation, and the servers asked are the root plus one per delegation.
  • A record is a fact with an expiry. Name, type, class, TTL, value — and the TTL is what makes caching possible.
  • Count the servers, not the labels. The count belongs to the delegation tree; the string only suggests it.
  • HTTP is stateless; a cookie is the memory. A cookie is text, not code.
  • Every mode changes the connections and the round trips, never the number of objects. One request per object, always.

Intuition first: a phone book that is split into districts

Suppose nobody may hold the whole telephone directory. Instead, one office knows only where the district offices are. A district office knows only where the street offices are. A street office knows the actual numbers. To find one number you start at the top office, get sent to the right district, get sent to the right street, and only there do you get the number. That is DNS, with three differences: the offices are computers, the question travels in a packet, and every answer may be written down and reused for a while.

The two questions this picture answers are the two the exam asks. How many offices did you have to ask? One per level you passed through, plus the top one. What did each office give you? A direction, except the last, which gave you the number. Educational interpretation The analogy carries the hierarchy and the referral. It does not carry the wire format, which is why the message section exists.

Formal vocabulary, every term in words

Domain name — a sequence of labels separated by dots, read right to left. In www.gate.org.in the labels are www, gate, org and in.

Zone — a contiguous part of the tree that one server is authoritative for. org.in is a zone; gate.org.in is a zone inside it.

Authoritative server — the server that holds the real records for a zone. It answers with data, not with a direction.

Referral — an answer that names the next server instead of giving the value. It is what the root and the top-level domains return.

Resolver — the server that does the asking on your behalf, and the one that keeps the cache.

Stub resolver — the small piece in your operating system that forwards the question to the resolver and nothing more.

Iterative and recursive are answers to "who walks?"

Iterative query. The server answers with the best information it has: either the value, or a referral to a server closer to it. The asker must then ask again. The resolver does the walking.

Recursive query. The server being asked takes responsibility for the whole job and returns the value or an error. The client asks once.

In practice the stub asks its resolver recursively and the resolver asks the hierarchy iteratively. That mixture is why a question says which mode it means.

Verified fact The two modes, the referral behaviour and the recursion-desired bit are defined in RFC 1034 and RFC 1035. The bit exists because recursion is a request the server may refuse.

Counting the servers asked

Let the delegation chain for a name be the list of zones below the root that own it. Then

pairs = 1 + (number of zone cuts)The one is the root, which is asked first and always. Each zone cut is one more server, and each server costs exactly one query and one response.

For www.gate.org.in the cuts are in, org.in and gate.org.in, so four pairs: root, in, org.in, gate.org.in. That is GATE 2022's answer of 4.

One more pair exists only when the host and the resolver are different machines. GATE 2023 says the local DNS server runs on the local host, so that hop is internal and free.

A resource record

Five fields: name, type, class (IN for internet data), TTL in seconds, and value. The type decides how the value is read.

A — an IPv4 address. AAAA — an IPv6 address. NS — the name of a server for this zone, and the record a referral actually carries. MX — a preference number then a mail server name. CNAME — this name is an alias for another name, which must then be resolved.

Verified fact The record types, the field order and the TTL are defined in RFC 1035 section 3.2.1. RFC 1034 section 3.6.2 states that a CNAME may not coexist with other data at the same name.

The message: header, question, then sections

Header, 12 bytes. Identifier (2), flags (2), then four counts of two bytes each: questions, answers, authority records, additional records.

Question. The name is written as length-prefixed labels ending in a zero byte, then two bytes of type and two of class. For www.gate.org.in: 4 + 5 + 4 + 3 + 1 = 17 bytes, so the whole query is 12 + 17 + 4 = 33 bytes.

Ceiling. A classic UDP answer may not exceed 512 bytes. If it does not fit, the server sets the truncation bit and the client repeats the query over TCP.

Mathematical derivation The 512-byte limit, the length-prefixed encoding and the truncation bit are RFC 1035 section 4.2.1 and section 4.1.4. The record arithmetic — 29 address records in the 479 bytes left — is derived on this page and re-checked in code.

HTTP: a request, a response, one connection

Request line. Method, target, version: GET /index.html HTTP/1.1. Then headers, one per line, then a blank line, then an optional body.

Response. Version, status code, reason phrase, then headers, then the body.

Methods. GET and HEAD are safe (they ask for no change). GET, HEAD, PUT and DELETE are idempotent (repeating is the same as once). POST is neither.

Status families. 2xx worked, 3xx look elsewhere or use what you have, 4xx the request was wrong, 5xx the server failed.

Statelessness, and the cookie that fixes it

HTTP carries no memory between requests. Everything needed to interpret a request must be in that request. That is what lets one server serve many clients without keeping a session for each.

The fix is a header pair. The server sends Set-Cookie: sid=A7 in a response; the browser stores it against that site and returns Cookie: sid=A7 in later requests. The state lives in the browser, so the protocol stays stateless.

Verified fact Cookies, their attributes and their scope are defined in RFC 6265. A cookie is a name-value string with attributes, and carries no executable content.

The three fetch modes, and the arithmetic of each

Let the page be one object and there be N more objects on the same server. One TCP handshake costs one round trip, one request and its response cost one, and one DNS walk costs one round trip per server asked.

non-persistent: 2 × ceil(N / p) round trips for the objects, 1 + N connections
persistent: N round trips for the objects, 1 connection
pipelined: 1 round trip for all the objects, 1 connectionp is how many connections the browser opens at once. Parallelism divides the elapsed time by rounding the objects into batches; it never reduces the number of connections or handshakes.

Mathematical derivation Both forms are derived on this page, and both are checked against a tick-by-tick simulation of the connections over a grid of object counts and widths. On GATE 2023's numbers they give 9 and 6, which is the official key.

Example 1 — GATE 2022 Q35, counting query pairs

Consider the resolution of the domain name www.gate.org.in by a DNS resolver. Assume that no resource records are cached anywhere across the DNS servers and that iterative query mechanism is used. The number of DNS query-response pairs involved is ______.

  1. Write the delegation chain: in, then org.in, then gate.org.in. Three cuts below the root.
  2. Add the root, which is asked first. The root knows who runs in and nothing more.
  3. Each server asked costs one query and one response, so four pairs. Referrals count; only the last one is the address.
  4. Answer: 4.

Trap. The question says the resolver resolves the name, so the host-to-resolver hop is not counted. Adding it gives 5, and 5 is a common wrong answer.

Example 2 — GATE 2023 Q52, the round-trip total

A browser clicks www.gate-2023.in. The cache is empty and the IP is not cached, so a DNS lookup runs over a three-tier hierarchy in iterative mode with no caching anywhere. RTT is the same everywhere. The page references 10 equally small objects on the same server. Which statements about the minimum elapsed time are correct?

  1. DNS: three servers asked, so 3 RTT. The resolver is on the local host, so the hierarchy alone decides.
  2. Base page: one handshake and one request, so 2 RTT. The request cannot ride on the handshake.
  3. Non-persistent with 5 parallel connections: 10 objects in two rounds, 2 RTT each, so 4. Total 3 + 2 + 4 = 9. Every object pays its own handshake.
  4. Persistent with pipelining: no new handshake and all requests together, so 1. Total 3 + 2 + 1 = 6.

Why 7. That is what ten parallel connections give: one round instead of two, so 3 + 2 + 2. Why 5. That forgets the handshake before the base page. Both wrong options are right answers to slightly different questions.

Example 3 — GATE 2020 Q25, counting connections

A browser requests a web page. The cache is empty and the browser is configured for non-persistent HTTP. The page contains text and five very small images. The minimum number of TCP connections required is ______.

  1. Count the objects: the page itself, plus five images, is six. The HTML file is an object like any other.
  2. Non-persistent means the connection closes after each response. So the next object cannot reuse it.
  3. Connections = objects = 6. Parallelism would not change this number.
  4. Answer: 6.

Why 5 is wrong. It counts only the images. Why 1 is wrong. That is the persistent answer, and the question said non-persistent.

Example 4 — GATE 2014 Set 2 Q28, requests against connections

A browser at client Q accesses a static HTML page from server S. The page has exactly one static embedded image, also at S. Assuming no caching, which statement is correct about loading the page including the image?

  1. Two objects, so at least two HTTP requests. One request fetches one object.
  2. Both objects are on the same server. A persistent connection stays open to that server.
  3. One TCP connection is therefore sufficient. HTTP/1.1 keeps connections open by default.
  4. Answer: at least two requests, but a single connection suffices.

Why "each in a separate connection" is wrong. That is non-persistent behaviour, and nothing in the question forces it. Why "a single request" is wrong. No caching, so the image cannot arrive with the page.

Example 5 — GATE 2015 Set 2 Q13, the cookie statement

Which one of the following statements is NOT correct about HTTP cookies?

  1. (A) A cookie is a piece of code that can compromise the security of a user.
  2. (B) A cookie gains entry to the user's work area through an HTTP header. True: Set-Cookie in the response, Cookie in the request.
  3. (C) A cookie has an expiry date and time. True: Expires or Max-Age.
  4. (D) Cookies can be used to track the browsing pattern of a user at a site. True, and that is the privacy concern.

Answer: (A). A cookie is a string of name-value pairs with attributes; it does not execute. The question tests whether you can separate privacy from code execution — a cookie enables tracking, which is a privacy matter, and it cannot run.

The boundaries: where each rule stops working

Each card states the condition a rule needs, and what changes when the condition fails. These are the cases that separate a correct answer from an almost-correct one.

Labels are not delegations

Take example.com: two labels, but three servers asked — root, com, and the authoritative server for example.com itself. Take www.example.com: three labels, and still three servers, because www is a host inside the example.com zone.

Counterexample to the label rule. The number of pairs equals the number of labels only when every label except the leftmost is a zone cut and the leftmost is a host. The rule that always holds is 1 + the number of zone cuts.

A CNAME cannot share its name

RFC 1034 forbids a CNAME at a name that has any other record, because the alias would make the other records unreachable. So www.gate.org.in may be a CNAME pointing at gate.org.in, but it may not be a CNAME and have an A record.

Consequence for counting. Following a CNAME can cost an extra lookup, because the resolver must resolve the target name too. A question that says "an alias chain of length 2" is asking for those extra pairs.

The 512-byte ceiling is a default, not a law of physics

RFC 1035 caps a classic UDP DNS message at 512 bytes. EDNS0 lets a client advertise a larger buffer, and modern servers routinely return answers well above 512 bytes over UDP.

What does not change. The truncation bit and the TCP retry are still the defined behaviour when a message does not fit. A question that says "classic DNS" or "without EDNS" is asking for 512; one that says nothing is safest read as 512.

A 304 is a success with no body

304 Not Modified belongs to the 3xx family and is not an error. It says the client's copy is still valid, so no body follows. It saves bandwidth, and it costs one full round trip.

The related trap. A fresh object inside its max-age produces no request at all, which is a different cost from a 304. Fresh is zero round trips; revalidated is one.

Pipelining is legal and largely unused

RFC 9112 defines pipelining, and browsers have mostly stopped using it because a slow first response delays every later one on the same connection — head-of-line blocking. HTTP/2 multiplexes streams instead, so the problem is solved above the connection.

For the exam. Pipelining is still the model in every counting question, and it is still worth one round trip for all the objects. Whether real browsers use it does not change the arithmetic the question wants.

Names are case-insensitive; the TTL is not optional

DNS comparisons ignore case, so WWW.Gate.Org.IN and www.gate.org.in are the same name. A trailing dot marks a fully qualified name and means "do not append the local suffix".

And a zero TTL is legal: it means the record may be used for this transaction and must not be cached. So "the answer is cached" is only true when the TTL is positive.

Five beliefs that produce a plausible wrong answer

Each card gives the belief, why it is tempting, the smallest case that refutes it, and the rule to use instead. These are drawn from the shapes of wrong options in past papers, not from a survey of learners.

1. "Each label is a delegation"

Why it tempts. www.gate.org.in has four labels and the answer is four, so the shortcut appears to work.

Refutation. www.example.com has three labels and takes three servers, because www is a host inside the example.com zone; and example.com has two labels and takes three servers, because the name is the zone apex.

Correct rule. Count the zone cuts and add the root. Labels suggest the count; they do not define it.

2. "The handshake is free"

Why it tempts. The request goes out immediately after the SYN-ACK, so the two look like one exchange.

Refutation. GATE 2023's base page costs 2 RTT, not 1. Option B says 5 RTT for the pipelined case and is wrong for exactly this reason: 3 + 2 + 1 = 6.

Correct rule. Write the three stages separately — DNS, handshake, request — and add them.

3. "One connection can reach several servers"

Why it tempts. Persistence is described as "one connection for the whole page", and a page often pulls from several hosts.

Refutation. GATE 2026 Set 1 statement B is false. A TCP connection is identified by four values — source address and port, destination address and port — so it ends at one server.

Correct rule. Persistence is per server, not per page. Two servers, two connections.

4. "A 304 saves a round trip"

Why it tempts. The server sends almost nothing, so the exchange feels nearly free.

Refutation. A 304 is a full request and a full response: one round trip, and 300 bytes instead of 20000. Only a fresh object inside max-age costs zero round trips.

Correct rule. Separate bandwidth from latency. A conditional GET saves the first and not the second.

5. "Parallel connections reduce the connection count"

Why it tempts. Parallelism clearly reduces the time, and time is what most questions ask for.

Refutation. GATE 2020: six objects in non-persistent mode need six connections, however many run at once. Parallelism changes ceil(N / p) in the time, not the count of connections or handshakes.

Correct rule. Ask what the question counts: pairs, connections, or round trips. They are three different quantities.

The one distinction to carry into the exam

Four pairs get confused, and each is settled by writing down a definition rather than by intuition: labels against zone cuts, connections against round trips, fresh against revalidated, and recursive against iterative. In each pair the two members differ by one countable thing, and the question always tells you which it wants — if you read the unit before you compute.

How this clause gets tested, and what each pattern demands

Four patterns cover the items in this clause. Each is listed with the quantity it counts, because the quantity is what the trap attacks.

Pattern 1 — count the query-response pairs

Shape. A name, a mode (iterative or recursive), and "no caching anywhere". The answer is a small integer.

Procedure. Write the delegation chain from the top-level domain down to the zone that owns the name; add the root; that is the count. Add one only if the host and the resolver are separate machines.

Seen in. GATE 2022 Q35, answer 4, and GATE 2023 Q52, where the same arithmetic is the first term of a larger sum.

Pattern 2 — count the connections

Shape. A page with some objects, a mode, and "minimum number of TCP connections".

Procedure. Count objects as 1 + the number of embedded items. Non-persistent gives one connection per object; persistent or pipelined gives one in total, per server.

Seen in. GATE 2020 Q25, answer 6, and GATE 2014 Set 2 Q28, where the answer is two requests and one connection.

Pattern 3 — add the round trips

Shape. A hierarchy, a page, N objects, a parallel width, and a choice between modes. The answer is a small integer of RTTs.

Procedure. DNS first, one round trip per server asked. Then the handshake. Then the request for the page. Then the objects: 2 × ceil(N/p) for non-persistent, N for sequential persistent, 1 for pipelined.

Seen in. GATE 2023 Q52, answers 9 and 6.

Pattern 4 — statements about HTTP

Shape. Four or five statements about HTTP/1.1, cookies or persistence; select all that are true.

Procedure. Test each statement against a definition you can state: what persistence is scoped to, what pipelining allows, what a cookie is made of, which methods are safe or idempotent.

Seen in. GATE 2026 Set 1 Q19 (A, C, D true) and GATE 2015 Set 2 Q13 (A is the false statement).

The four-step procedure, and where each step can go wrong

1. Resolve. Count the servers asked. Fails when you count labels instead of zone cuts, or add a host-to-resolver hop the question placed inside the host.

2. Connect. One handshake per connection, and one connection per object unless the mode says otherwise. Fails when the handshake is forgotten or folded into the request.

3. Request. One request per object, and the page is an object. Fails when the HTML file is left out of the count.

4. Render. Only after the base page arrives, and only after every object it references has been fetched. Fails when the question asks for the last byte and you answer for the page.

Two questions in this clause are one-mark freebies — take them first

A statement question about HTTP needs no arithmetic, only a definition, and a connections question needs only a count of objects. Both are answerable in under a minute. The round-trip question is the one that rewards writing the three stages down before touching the calculator. In a 65-mark paper with a per-question average of about two minutes, taking the two cheap ones first is worth more than perfecting the expensive one.

NATGATE CSE 2022 Q35

Consider the resolution of the domain name www.gate.org.in by a DNS resolver. Assume that no resource records are cached anywhere across the DNS servers and that iterative query mechanism is used in the resolution. The number of DNS query-response pairs involved in completely resolving the domain name is ______.

Answer: 4

Root, then in, then org.in, then the authoritative server for gate.org.in. Four servers asked, one query and one response each.

Why 3 appears. Dropping the root. Why 5 appears. Adding the host-to-resolver hop, which the question does not count because the resolver is the one resolving.

MSQGATE CSE 2023 Q52

A browser clicks www.gate-2023.in with an empty cache and no cached IP. A DNS lookup runs over a three-tier hierarchy in iterative mode with no caching anywhere. RTT is the same to every server. The HTML file is negligible in size and references 10 equally small objects on the same server. Which statements about the minimum elapsed time until full rendering are CORRECT?

  1. 7 RTTs, in case of non-persistent HTTP with 5 parallel TCP connections.
  2. 5 RTTs, in case of persistent HTTP with pipelining.
  3. 9 RTTs, in case of non-persistent HTTP with 5 parallel TCP connections.
  4. 6 RTTs, in case of persistent HTTP with pipelining.

Answer: C and D

DNS 3 + page 2 + objects. Non-persistent, five at a time: two rounds of two round trips, so 3 + 2 + 4 = 9. Pipelined: one round trip for all ten, so 3 + 2 + 1 = 6.

Why 7. That is ten parallel connections: one round instead of two, giving 3 + 2 + 2. Why 5. It omits the handshake before the base page. Both are right answers to different questions.

NATOriginal practice

An iterative resolver with an empty cache resolves a.b.example.co.uk, and the delegation chain has a zone cut at each of uk, co.uk, example.co.uk and b.example.co.uk. How many query-response pairs does the resolution take?

Answer: 5

Four zone cuts plus the root. The name has five labels, and the leftmost label a is a host, so here labels and pairs coincide — but that is a coincidence of this tree, not a rule.

Why 4. Forgetting the root. Why 6. Adding the host-to-resolver hop that an iterative resolver does not pay.

MCQGATE CSE 2015 Set 2 Q13

Which one of the following statements is NOT correct about HTTP cookies?

  1. A cookie is a piece of code that has the potential to compromise the security of an Internet user.
  2. A cookie gains entry to the user's work area through an HTTP header.
  3. A cookie has an expiry date and time.
  4. Cookies can be used to track the browsing pattern of a user at a particular site.

Answer: A

A cookie is a name-value string with attributes, sent in Set-Cookie and returned in Cookie. It does not execute, so it cannot compromise security as code.

Why D is a real concern and still true. Tracking is a privacy issue and cookies do enable it. The question separates privacy from execution, which is the whole point.

NATOriginal practice

A classic DNS query without EDNS is sent for the name www.gate.org.in. The header is 12 bytes, the encoded name is 17 bytes, and the type and class together are 4 bytes. Each answer record uses name compression, so it costs 2 bytes of pointer, 2 of type, 2 of class, 4 of TTL, 2 of length and 4 of address. What is the largest number of such answer records that fits in a 512-byte message with no other sections?

Answer: 29

512 − 12 − 17 − 4 = 479 bytes remain. Each record is 16 bytes. 479 / 16 = 29.9, so 29 records fit and the 30th would need 480.

Why 28. Rounding down twice, or assuming a 17-byte record. Why 31. Forgetting the two-byte compression pointer and the two-byte length field.

MSQOriginal practice

A page on one server is 1 object and references 9 images on the same server. DNS is already cached. Which of the following are TRUE?

  1. Non-persistent HTTP needs 10 TCP connections.
  2. Persistent HTTP without pipelining needs 10 round trips after the handshake.
  3. Pipelined persistent HTTP needs 1 round trip for the 9 images after the page arrives.
  4. Opening 5 parallel connections reduces the number of connections needed.
  5. A 304 response to an image saves both the body and the round trip.

Answer: A, B and C

Ten objects means ten connections in non-persistent mode (A). Sequential persistent costs one round trip per image, so 9 after the page — the statement's "10 after the handshake" counts the page request too, which is consistent with 1 + 9 (B). Pipelining sends all nine requests together, so one round trip (C).

Why D is false. Parallelism changes elapsed time, never the connection count. Why E is false. A 304 saves the body only; it is still one round trip.

Revision sheet

Definitions, counts, formulas, decision procedures and traps, in the order you would use them. Nothing here needs the animation.

DNS: the facts worth memorising

  • Names are read right to left; the rightmost label is the top-level domain.
  • Servers asked = 1 (root) + number of zone cuts. One pair per server.
  • Iterative: referrals, and the resolver walks. Recursive: one server walks.
  • Records: A, AAAA, NS, MX, CNAME, and SOA which sets the negative-caching TTL.
  • A CNAME may not coexist with other records at the same name.
  • Header 12 bytes: ID, flags, and four counts. Port 53.
  • Encoded name = text length − dots + one byte per label + 1.
  • 512-byte UDP ceiling; truncation bit; retry over TCP. EDNS0 raises it.
  • TTL is a countdown in a cache, not a query timeout. Zero TTL means do not cache.

HTTP: the facts worth memorising

  • Request line: method, target, version. Host is mandatory in 1.1.
  • Safe: GET, HEAD. Idempotent: GET, HEAD, PUT, DELETE. POST is neither.
  • Families: 2xx worked, 3xx elsewhere or use your copy, 4xx bad request, 5xx server failed.
  • 304 Not Modified: success, no body, one round trip.
  • Stateless protocol; cookies carry the state. A cookie is text, not code.
  • Cookie attributes: Expires or Max-Age, Domain, Path, Secure, HttpOnly.
  • One request per object, and the HTML page is an object.
  • HTTP/1.1 is persistent by default; persistence is scoped to one server.
  • Pipelining: requests back to back, responses in order, one round trip for all.

The three counting formulas

pairs = 1 + zone cuts
connections = 1 + N (non-persistent) or 1 (persistent)
round trips = DNS + 1 (handshake) + 1 (page) + objectswhere objects is 2·ceil(N/p) for non-persistent, N for sequential persistent, and 1 for pipelined. DNS is one round trip per server asked, unless the question puts the resolver on the host and gives the tier count directly.

GATE 2023, plugged in: DNS 3, page 2, objects 4 or 1, giving 9 or 6.

Decision procedure, in four lines

  1. Write the unit the question asks for: pairs, connections or round trips. Three different quantities, three different formulas.
  2. Count the objects: 1 + embedded items. The page is an object.
  3. Pick the mode and write its cost per object. Non-persistent 2 RTT, persistent 1 RTT, pipelined 1 RTT for all.
  4. Add DNS and the handshake, then check the total is at least DNS + 2. A total below that floor means a missing stage.

Numbers from this lesson worth remembering

Four query-response pairs for www.gate.org.in (GATE 2022) · three for a three-tier hierarchy · a query of 33 bytes for that name · 479 bytes left in a 512-byte message · 29 address records of 16 bytes each · six TCP connections for a page and five images (GATE 2020) · two requests and one connection for a page and one image (GATE 2014 Set 2) · 9 and 6 round trips (GATE 2023) · 7 for ten parallel connections · 15 for sequential persistent · two hits and two misses from a 300-second TTL queried at 0, 60, 120 and 310 seconds.

Every one of these was computed by this page's model and checked against its defining property, not copied from an answer key.

The five slips, one last time

Counting labels instead of zone cuts · forgetting the handshake before the base page · believing one connection can reach two servers · treating a 304 as free · thinking parallel connections reduce the connection count. Write the unit and the three stages at the top of your working and none of the five survives.

What was consulted, and what each source supports

Official standards and the official syllabus are separated from question catalogues and from community discussion. A catalogue is evidence that a question exists and was asked in a given year; it is not evidence about the 2027 paper. Every numeric answer on this page was recomputed from the question text, so catalogues were used to find questions, not to settle answers.

Official and standard

  • GATE 2027 CS syllabus, IIT Madras, CS_GATE2027_Syllabus.pdf, read on 28 October 2026. Supports the Section 10 wording quoted in Overview: the clause now reads "DNS and HTTP", where the 2026 syllabus said "DNS, SMTP, HTTP, FTP, Email".
  • RFC 1034 — domain concepts and facilities: the hierarchy, referrals, iterative and recursive service, and the rule that a CNAME may not coexist with other data.
  • RFC 1035 — implementation: the record types, the 12-byte header, the length-prefixed name encoding, and the 512-byte UDP limit with the truncation bit.
  • RFC 2308 — negative caching of a name that does not exist.
  • RFC 6265 — cookies: Set-Cookie and Cookie, Expires and Max-Age, Domain and Path, Secure and HttpOnly.
  • RFC 9110 and RFC 9112 — HTTP semantics and HTTP/1.1: methods and their safe/idempotent properties, status code families, the mandatory Host header, persistent connections and pipelining.
  • RFC 9113 — HTTP/2 multiplexing, cited only in Edge cases for why browsers largely stopped pipelining.
  • RFC 6891 — EDNS0, cited only for the statement that the 512-byte ceiling is a default.

What the research did not cover

No official answer-key PDF was opened for the items above; every answer was recomputed from the question text by this page's model, and each agrees with the key as reported by the catalogues. The DNS record counts and the 29-record figure assume name compression and an otherwise empty message, which is the standard reading of the classic 512-byte case and not the only possible message. The round-trip convention — one round trip for a handshake and one for a request and its response — is the convention GATE 2023 uses; a question that piggybacks the request on the handshake's third segment would give a different total, and the question would have to say so. Topics that sit in the same section but not this clause — TCP flow and congestion control, fragmentation and CIDR, NAT, routing — are taught in their own lessons and are not repeated here. No claim is made about 2027 weightage, and no search was made for 2027 sample papers, because none exists at the time of writing. Nothing here was checked against a printed textbook edition.
