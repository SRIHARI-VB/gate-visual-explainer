Topic and objective

TOPIC: Arrays, stacks and queues — the three linear structures named in one phrase in the GATE 2027 syllabus, taught from the address arithmetic upward.

LEARNING OBJECTIVE: Given a question about any of the three, produce the answer from the implementation rather than from a remembered rule: compute an element's address from a base and two indices, run a stack or a circular queue through its index variables, decide whether an output order is reachable with one stack, and state the cost of building one structure out of another.

I read this topic as the implementations and their boundary conditions, because that is what every GATE question in it turns on: an off-by-one in a full test, an order of operands in a postfix evaluation, or a count of reachable permutations. Linked lists, trees and heaps are separate lessons in this repository, and they are linked from here rather than repeated.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 4 of the official GATE 2027 CS syllabus (IIT Madras) reads: "Programming in C. Recursion. Arrays, stacks, queues, linked lists, trees, binary search trees, binary heaps, graphs." The three words appear together, as named items.

Class A means a question on this is inside the declared boundary. It does not mean a question is guaranteed. The previous-year questions quoted in this lesson are observations about old papers, not a forecast.

What you should be able to do afterwards

Take any question in this topic and answer, in this order: what are the indices and what do they mean?, what are the boundary states?, which operation is expensive, and once or every time?

The most expensive mistake here is answering from the name of a structure instead of from its code. "Circular queue of size n" does not determine the capacity; the full test does.

Level 1 — Intuition: three queues you have stood in

The array: a row of numbered lockers. The lockers are the same size and stand in one wall. Nobody writes the address of locker 7 on it; you count from the first locker. That is why reaching locker 7 costs the same as reaching locker 2 — one multiplication, not seven steps.

The stack: a pile of plates. You add a plate on top and take a plate off the top. You cannot take the second plate without moving the first. One number, the height of the pile, tells you everything.

The queue: the ticket counter. People join at the back and leave from the front. The person who has waited longest is served next. If the line shuffles forward along the floor and nobody walks back to the start, the floor behind the counter fills up with empty space that the line can no longer use — that is exactly the linear-queue problem of scene 7.

Educational interpretation The locker wall is a good picture of address arithmetic and a poor one of resizing: a real locker wall is fixed, and so is a C array.

Level 2 — Formal definitions

Array. A collection of n elements of one type, stored in one contiguous block, each element reached by an index. In C, T a[n] gives indices 0 to n−1 and the length is fixed at definition.

Base address. The address of a[0], written B. Every other address is computed from it.

Element size. The number of bytes one element occupies, written w. w = sizeof(T).

Stack. A collection with one insertion point and one deletion point, both the same end, called the top. Operations: push(x), pop(), and a read of the top. Discipline: last in, first out (LIFO).

Queue. A collection where insertion happens at the rear and deletion at the front. Operations: enqueue(x), dequeue(). Discipline: first in, first out (FIFO).

Circular queue. A queue whose two indices are computed modulo the array size, so the array is used as a ring.

The three formulas, in words

address(a[i]) = B + (i − L) × w

"Start at the base, step i − L elements forward, and each element is w bytes." L is the lower bound of the index range: 0 for a C array, 1 for a declaration written A[1..10].

row-major: B + ((i − L₁) × cols + (j − L₂)) × w

"Skip i − L₁ whole rows of cols elements, then j − L₂ more elements along the row."

column-major: B + ((j − L₂) × rows + (i − L₁)) × w

"Skip j − L₂ whole columns of rows elements, then i − L₁ more elements down the column."

circular: rear = (rear + 1) mod N

"The next cell after the last one is the first one." N is the number of cells in the array — not necessarily the capacity of the queue.

The assumptions each formula needs

Every address formula assumes one contiguous block and equal element sizes. Both are true of a C array of one type, and neither is true of a linked list.

The row-major formula assumes the second index varies fastest; the column-major one assumes the first does. C guarantees row-major for a declared array, because the standard requires the elements to be contiguous with the last index varying fastest.

The circular formula assumes N > 0 and that both indices are always reduced modulo N. A single un-reduced index breaks the full test silently.

Verified fact A C array is "a contiguously allocated nonempty set of objects with a particular member object type" (C11 6.2.5p20), and a[i] is defined as *(a+i) (6.5.2.1p2).

Level 3 — Visual understanding: the memory line

Draw one line of cells and write the byte offset of each. For int A[3][4] with 4-byte ints, row-major gives offsets 0, 4, 8, 12 for A[0][0..3], then 16 for A[1][0]. Column-major gives 0, 4, 8 for A[0..2][0], then 12 for A[0][1].

The picture that answers every order question: ask which index changes when the offset goes up by one element. Row-major: j changes. Column-major: i changes.

The picture that answers every queue question: draw the array with two arrows and the modulo. The arrows move; the cells do not.

The stack, drawn

Cells 0 to N−1, one arrow called top. Start with top = −1, which points at nothing: that is empty.

push(x): test top == N−1 first (full), else a[++top] = x.

pop(): test top == −1 first (empty), else return a[top--].

After three pushes of 7, 4, 9 the cells hold 7, 4, 9 with top = 2. A pop returns 9 and leaves top = 1. The 9 is still in the cell — popping does not erase it — but the stack no longer contains it.

Educational interpretation "The 9 is still there but not in the stack" is exactly why pop must not be implemented as return a[top] without the decrement.

The circular queue, drawn

Eight cells in a ring, two arrows. front points at the oldest element, rear at the next cell to write. Both advance by (x + 1) mod 8.

With the sacrifice convention, one cell is always empty, so rear can never catch front in the full state. With the count convention, a separate integer holds the size and every cell is usable.

Number of elements with the sacrifice convention: (rear − front + N) mod N. Read it as "how far ahead of front is rear, going round".

Where the drawing beats the formula

A question can give you indices and ask for the number of elements. If the two indices are equal, the formula says 0 — and the formula is right, unless a count variable is in play, in which case the answer is whatever the count says.

A question can give you rear = 4, front = 3, N = 8. The count formula gives 1. A drawing confirms it: one element, at cell 3.

Whenever a formula and a drawing disagree, the drawing is usually being read with the wrong convention. Fix the convention first, then re-read.

Level 4 — Worked example 1: an address, three inputs

Let int A[10][20] sit with base address 1000 and 4-byte ints. Find the address of A[5][7].

  1. Lower bound. L₁ = L₂ = 0 in C. A C array starts at index 0 unless the question declares otherwise.
  2. Order. Row-major, because the declaration is C. C stores the last index varying fastest.
  3. Element size. w = 4. Given, or read as "assume 4-byte ints".
  4. Substitute: 1000 + (5 × 20 + 7) × 4 = 1000 + 107 × 4. 107 elements precede it: five full rows of 20, then seven.
  5. Result: 1428. The page's model computes the same value.

In column-major the same element sits at 1000 + (7 × 10 + 5) × 4 = 1300. Different address, same element.

Worked example 2: a postfix trace

Evaluate 10 5 + 60 6 / * 8 -.

  1. 10: push. Stack [10]. A number is always pushed.
  2. 5: push. Stack [10, 5]. Second number, second cell.
  3. +: pop 5, pop 10, push 15. Stack [15]. The operator consumes the top two and replaces them with one.
  4. 60, 6: push both. Stack [15, 60, 6]. Two operands waiting for an operator.
  5. /: pop 6, pop 60, push 10. Stack [15, 10]. First pop is the divisor: 60 / 6, never 6 / 60.
  6. *: pop 10, pop 15, push 150. Stack [150]. Multiplication is commutative, so this step cannot expose an operand-order error.
  7. 8, then −: pop 8, pop 150, push 142. 150 − 8, not 8 − 150. The answer is 142.

This is GATE 2015 Set 3, and the page reproduces the trace from its own evaluator.

Worked example 3: a circular queue, run

Array of 8 cells, sacrifice convention, front = rear = 0. Perform seven insertions, then one more.

  1. Insert 1 at cell 0, rear becomes 1. Write, then advance.
  2. … after seven insertions, cells 0–6 are used and rear = 7. Seven elements is the capacity.
  3. Test full: (7 + 1) mod 8 = 0 = front. The test fires before the write, so nothing is overwritten.
  4. The eighth insertion is refused. Capacity is N − 1 = 7, not 8.
  5. Now dequeue three, then insert three. Cells 0, 1, 2 become free and are reused — the wrap.

With a count variable instead, all eight insertions succeed and the full test is count == N. Same array, different capacity: the test decides.

Levels 5 and 6, named before they are used

Every structure here has a boundary state that is not a value of the data but a value of the index: top = −1, front = rear, rear + 1 ≡ front, top1 + 1 = top2.

Every one of them has a closely confused pair: empty against full for the circular queue, first pop against second pop in postfix, "possible order" against "possible sequence of operations" for permutations, worst case against amortised for the two-stack queue.

Both lists are developed in the Edge cases and Misconceptions tabs, with a minimal counterexample for each.

GATE CSE 1998, Q 2.14 — the address formula

"Let A be a two dimensional array declared as follows: A: array [1 … 10][1 … 15] of integer; Assuming that each integer takes one memory location, the array is stored in row-major order and the first element of the array is stored at location 100, what is the address of the element A[i][j]?"

Options were 15i+j+84, 15j+i+84, 10i+j+89, 10j+i+89.

Answer: 15i + j + 84. Substituting L₁ = L₂ = 1, cols = 15, w = 1, B = 100:

100 + ((i − 1) × 15 + (j − 1)) = 100 + 15i − 15 + j − 1 = 15i + j + 84.

Why the others are wrong. 15j+i+84 is the column-major formula with the same numbers. 10i+j+89 uses 10 — the number of rows — where the number of columns belongs, and its constant is then wrong too. 10j+i+89 is the column-major version of that same mistake. Verified fact Question text and key confirmed on gateoverflow (question 1686) and on ExamSIDE.

The check the page performs on it

Rather than trust one substituted example, the model evaluates three things for all 150 cells: the direct formula, the simplified expression 15i+j+84, and the position in the storage order.

The third one is the strong check. If A[i][j] is the k-th element in storage order, its address must be exactly 100 + k. The model confirms this for every cell, which validates the formula's structure and not merely its arithmetic.

It also confirms the two orders agree when one dimension has length 1, which is the sanity check that the two formulas are the same formula with the roles swapped.

GATE CSE 2015 Set 3, Q12 — postfix evaluation

"The result evaluating the postfix expression 10 5 + 60 6 / * 8 − is" — options 284, 213, 142, 71.

Answer: 142. The stack after each token: [10], [10,5], [15], [15,60], [15,60,6], [15,10], [150], [150,8], [142].

Why the others are wrong. 213 comes from finishing 60/6 = 10 and 150−8 = 142 but then adding 71 from somewhere — in practice, from mis-pairing the multiplication. 284 is 2 × 142, which happens when the final subtraction is applied twice. 71 is 142 / 2, the usual result of dividing by 2 instead of subtracting 8.

Verified fact Question text and answer confirmed on gateoverflow (question 8408) and in a GATE 2015 Set 3 paper listing.

GATE CSE 2007, Q38 — a state in the middle

"The following postfix expression with single digit operands is evaluated using a stack: 8 2 3 ^ / 2 3 * + 5 1 * −. Note that ^ is the exponentiation operator. The top two elements of the stack after the first * is evaluated are" — options 6,1 · 5,7 · 3,2 · 1,5.

Answer: 6, 1. Trace: 8 → [8]; 2 → [8,2]; 3 → [8,2,3]; ^ → 2³ = 8 → [8,8]; / → 8/8 = 1 → [1]; 2 → [1,2]; 3 → [1,2,3]; * → 2×3 = 6 → [1,6]. The top two are 6 and 1.

Why the others are wrong. 5,7 is the state after the second multiplication, which the question has not reached. 3,2 is the state before the first multiplication. 1,5 is a pair that never appears. Finishing the whole evaluation gives 2, which is not an option — the question deliberately asks about a state, not the value. Verified fact Confirmed on gateoverflow (question 1236) and on ExamSIDE.

GATE CSE 1994, Q 1.14 — reachable orders

"Which of the following permutations can be obtained in the output (in the same order) using a stack assuming that the input is the sequence 1, 2, 3, 4, 5 in that order?" — (a) 3,4,5,1,2 · (b) 3,4,5,2,1 · (c) 1,5,2,3,4 · (d) 5,4,3,1,2.

Answer: (b) 3,4,5,2,1. push 1, push 2, push 3, pop 3, push 4, pop 4, push 5, pop 5, pop 2, pop 1.

Why each other fails. In (a), after emitting 3, 4, 5 the stack holds 1 below 2, so the next pop can only be 2, never 1. In (c), after emitting 1 and 5 the stack holds 2, 3, 4 with 4 on top, so 2 cannot come next. In (d), the full reversal is reachable, but swapping the last two makes it impossible: to emit 1 before 2 requires 1 on top, and 2 was pushed after it.

Verified fact Question text found in the GATE CS 1994 paper listing and on gateoverflow (question 2457), key (b) in both.

GATE CSE 2012, Q35 — the circular queue's two tests

"Suppose a circular queue of capacity (n − 1) elements is implemented with an array of n elements. Assume that the insertion and deletion operations are carried out using REAR and FRONT as array index variables, respectively. Initially, REAR = FRONT = 0. The conditions to detect queue full and queue empty are" — four options pairing a full test with an empty test.

Answer: full is (REAR+1) mod n == FRONT, empty is REAR == FRONT.

Why the others fail, one line each. Option B makes empty (FRONT+1) mod n == REAR, which is false at the initial state — it would call the queue non-empty before anything is inserted. Option C swaps the roles, so it calls the initial state full. Option D uses the one-element condition as "full" and the wrong equality as "empty".

The decisive observation is that the initial state, REAR = FRONT = 0, must test as empty. Any option whose empty test is false there is eliminated without further work. Verified fact Confirmed on gateoverflow (question 1756) and on ExamSIDE.

Original worked example: the greedy reachability test

Input 1, 2, 3, 4, 5; target order 2, 4, 1, 5, 3. Reachable?

  1. Want 2. Push 1, push 2. Top is 2. Pop. Output 2. Stack: 1.
  2. Want 4. Push 3, push 4. Top is 4. Pop. Output 4. Stack: 1, 3.
  3. Want 1. Top is 3, not 1. Push 5. Top is 5, not 1. The input is exhausted and 1 is buried.
  4. Verdict: not reachable. No legal move frees 1 without popping 3, which the order does not allow.

This is an original practice example, not a previous-year question. The page's model runs the same test on all 120 permutations of five elements and finds 42 reachable ones — the fifth Catalan number.

Original worked example: a queue from two stacks

Operations: enqueue 1, 2, 3; dequeue; enqueue 4; dequeue, dequeue, dequeue.

  1. Push 1, 2, 3 onto in. in = [1, 2, 3] with 3 on top.
  2. Dequeue: out is empty, so pour. Pouring pops 3, 2, 1 from in and pushes them, so out = [3, 2, 1] with 1 on top.
  3. Pop from out → 1. The oldest element. FIFO holds.
  4. Enqueue 4: push onto in. in = [4]. out = [3, 2].
  5. Three dequeues → 2, 3, then pour and pop → 4. Output is 1, 2, 3, 4: exactly the arrival order.

Total moves across the pour: 3 elements, once each. The page checks that every element crosses at most once, which is the whole argument for amortised O(1).

Counterexample

A linear queue that refuses an insertion while three cells are free

N = 5, front = 0, rear = -1. Insert 1…5, delete three times, then insert once more.

After the deletions front = 3 and rear = 4. Cells 0, 1, 2 hold nothing that will ever be read again. The insertion test rear == N-1 fires, so the sixth insertion is refused.

This is the minimal case that refutes "a queue with fewer than N elements has room". It is why the circular queue exists, and why "number of elements = rear − front + 1" is only true of a linear queue that has never wrapped.

Counterexample

3, 1, 2 is not reachable with one stack

Input 1, 2, 3. To emit 3 first, all three must be pushed. The stack then holds 1 below 2, so the next pop must be 2. The order 3, 1, 2 therefore requires popping 1 through 2.

This is the permutation containing the pattern 312 — the largest value first, then the smallest, then the middle. It is the unique unreachable order for n = 3, which is why 5 of the 6 permutations are reachable.

The page checks the equivalence "reachable ⇔ avoids 312" on all 873 permutations of one to six elements and finds no exception.

Boundaries that change the answer

One column. With cols = 1, row-major and column-major give the same address for every cell. The formulas are still different; the arrays are not.

Empty stack. top = −1. A pop here is underflow, and the value returned by a buggy implementation is whatever was in cell −1, which is outside the array.

Circular queue of one cell. With the sacrifice convention, N = 1 gives capacity 0: the full test (0+1) mod 1 == 0 is true at once, so the queue can never hold anything. With a count variable it holds one element.

Two stacks in one array of size 1. The overflow test top1 + 1 == top2 is true immediately, so the array holds exactly one element between them.

Conditions the formulas depend on

The address formulas need equal-sized elements in one block. For an array of structs, w = sizeof(struct), which includes padding — the padding is part of the element.

The postfix evaluator needs a valid expression. An operator with fewer than two operands, or a stack with more than one value at the end, means the expression was not postfix. Division by zero in integer arithmetic is undefined behaviour in C, not an infinity.

The circular full test needs both indices reduced modulo N after every operation, and needs the convention to be fixed before the test is written.

Amortised O(1) for the two-stack queue needs the pour to happen only when the output stack is empty. Pouring on every dequeue is correct but linear per operation.

The closely confused pair, side by side

Empty against full in a circular queue. Empty: front == rear. Full: (rear + 1) mod N == front. The two are one step apart, and at the initial state both indices are 0, so only the empty test can be true.

Worst case against amortised. One dequeue from the two-stack queue can move n elements — that is the worst case. A sequence of m operations moves at most m elements in total — that is the amortised statement. A question that says "the worst case of dequeue is" wants Θ(n).

Number of orders against number of operation sequences. Five orders for three elements, but many more push/pop sequences: the sequence push 1, pop 1, push 2, pop 2, … and the sequence push 1, push 2, pop 2, pop 1, … produce different orders, while a push immediately followed by its pop can be inserted anywhere without changing the output.

Two more limits worth knowing

An array's length is fixed at definition in C. There is no length stored with the block, so "the array grows" always means a new block and a copy, which is O(n) and invalidates any pointer into the old block.

A stack's depth in a fixed array is bounded by N, but a recursion's depth is bounded by the process stack, which the C standard does not size. The two overflows look alike in a question and are governed by different rules.

Misconception 1

"In row-major order the row index changes fastest."

Why it tempts: the name. "Row-major" sounds like the row is the thing being counted step by step.

Minimal counterexample: int A[2][3], row-major. The address of A[0][1] is one element after A[0][0]: the column index changed. To reach the next row you skip three elements.

Correct rule: the order is named for what is stored as a unit — whole rows, one after another — so within a unit the last index varies fastest. Row-major: j varies fastest, multiplier is the number of columns.

Misconception 2

"A circular queue built on an array of size N holds N elements."

Why it tempts: capacity is usually the array size, and the sacrifice convention is an implementation detail rather than a definition.

Minimal counterexample: N = 8 with full as (rear+1) mod 8 == front. Seven insertions succeed and the eighth is refused. The capacity is 7.

Correct rule: read the full test. If it advances rear before comparing, capacity is N − 1. If the code keeps a count, capacity is N. GATE 2012 states the capacity in the question precisely because the two conventions exist.

Misconception 3

"An array knows its own length, so a function can compute it."

Why it tempts: sizeof(a)/sizeof(a[0]) works at the call site, so it looks like a property of the array.

Minimal counterexample: in a callee taking int a[], sizeof(a) is the size of a pointer. On a 64-bit build with 4-byte ints the expression evaluates to 2 regardless of the array's real length.

Correct rule: an array parameter is a pointer, so the length must be passed. The size is recoverable only where the array type is still visible — the same scope that declared it.

Misconception 4

"If a program with an out-of-bounds index prints the right answer, the index was fine."

Why it tempts: it usually does print something plausible — the neighbouring cell often happens to hold the expected value or zero.

Minimal counterexample: int a[10]; a[10] = 5; writes one element past the block. It compiles, often runs, and is undefined behaviour. The standard permits the compiler to assume it never happens.

Correct rule: "compiles" and "has a defined result" are different properties. A question that asks for the output of undefined behaviour has no defined answer; saying so is the correct answer.

Misconception 5

"A stack can produce any permutation of its input."

Why it tempts: the identity order and the full reversal are both reachable, which suggests everything in between is too.

Minimal counterexample: input 1, 2, 3; output 3, 1, 2. Emitting 3 first forces all three pushes, leaving 1 under 2 — so 1 cannot come next.

Correct rule: exactly the 312-avoiding orders are reachable, and there are C(n) = (2n)!/((n+1)! n!) of them: 5 for three elements, 42 for five.

Misconception 6

"A queue from two stacks costs O(n) per dequeue, so it is not worth it."

Why it tempts: one dequeue really can move every element, and that dequeue is the one people remember.

Minimal counterexample: push n elements, then dequeue n times. The single pour moves n elements; the other n − 1 dequeues move nothing. Total work is Θ(n) for Θ(n) operations.

Correct rule: each element crosses from the input stack to the output stack at most once, so m operations cost O(m) — amortised O(1) per operation, with Θ(n) worst case for a single one. The reverse construction, a stack from two queues, has no such argument: every pop is Θ(n).

Four question shapes, four procedures

Everything GATE has asked in this topic is one of these. Each has a written procedure, and each has one characteristic wrong approach.

Shape 1 — compute an address

Reasoning demanded: read three inputs out of the question (lower bound, storage order, element size), then substitute once.

Procedure: write the general formula first, then substitute. Never substitute into a remembered special case.

Characteristic wrong approach: using the number of rows as the multiplier in a row-major question. The multiplier is always the length of the other dimension.

Shape 2 — trace an expression or an operation sequence

Reasoning demanded: reproduce the algorithm's state after each token or operation, and stop where the question says.

Procedure: draw the array or the stack, write the state after every step, and mark the step the question asks about.

Characteristic wrong approach: answering a state question with the final value, as in GATE 2007 where the whole expression evaluates to 2 but the asked-for pair is 6 and 1.

Shape 3 — decide reachability, or count

Reasoning demanded: either run the greedy test on one candidate order, or apply the Catalan count when the question asks how many.

Procedure: for each option, push until the next wanted element is on top; if it is buried, reject. For a count, use (2n)!/((n+1)! n!).

Characteristic wrong approach: testing one option and generalising. Each option needs its own pass, and a rejected option says nothing about the next.

Shape 4 — state a condition or a cost

Reasoning demanded: fix the convention, then write the test; or separate worst case from amortised.

Procedure: for conditions, check the initial state first — the correct empty test must be true when both indices are 0. For costs, ask "expensive once, or expensive every time?"

Characteristic wrong approach: assuming an array of size N implies capacity N, which is false for the sacrifice convention (GATE 2012).

MCQModerateGATE CSE 1994, 1 mark

Input 1, 2, 3, 4, 5 is pushed in that order, with pops allowed at any time. Which output order is NOT reachable?

  1. 2, 3, 1, 5, 4
  2. 3, 1, 2, 5, 4
  3. 5, 4, 3, 2, 1
  4. 1, 2, 3, 4, 5

Answer: B — 3, 1, 2, 5, 4

To emit 3 first, 1 and 2 must already be on the stack, with 1 below 2. So after 3 the only available pop is 2, never 1. The order contains the pattern 312 and is therefore impossible.

A is reachable: push 1, push 2, pop 2, push 3, pop 3, pop 1, push 4, push 5, pop 5, pop 4. C is five pushes then five pops. D alternates push and pop.

This is an original question written in the shape of GATE 1994, whose four options are worked in the Examples tab. The page's model confirms that exactly 5 of the 6 orders on three elements and 42 of the 120 on five are reachable.

NATModerateGATE CSE 2012, 2 marks

An array of 12 cells implements a circular queue whose full test is (rear + 1) mod 12 == front. What is the largest number of elements the queue can hold at one time?

Answer: 11

The full test advances rear before comparing, so one cell is always left empty: capacity is N − 1 = 11. Inserting into all 12 cells would make rear equal front, which is the empty state.

Common wrong answer: 12. That is the array size, and it is correct only for the count-variable convention, where the full test is count == N. The question states the test, so the test decides.

This is the reasoning of GATE CSE 2012 Q35 applied to a numerical answer. The page's model simulates both conventions on the same array and reports capacities 11 and 12.

MSQHardOriginal GATE-style

A queue is implemented with two stacks as described in scene 9: push onto in; on dequeue, if out is empty, move every element from in to out, then pop from out. Which statements are TRUE?

  1. The worst-case cost of a single dequeue is Θ(n) for n elements in the queue.
  2. Any sequence of m enqueues and dequeues moves at most m elements between the stacks.
  3. Pouring on every dequeue, rather than only when out is empty, still produces FIFO order.
  4. The amortised cost per operation is O(1).

Answer: A, B and D

A is true because the pour moves every element once. B is true because each element crosses at most once — it enters in once, crosses once, and leaves out once. D follows from B: total work is linear in the number of operations.

C is false and is the misconception this question exists to catch. Pouring on every dequeue reverses the whole queue each time, so the second dequeue returns the most recently enqueued element, not the oldest. The structure becomes a stack.

The page's model runs a mixed sequence and checks that the output is exactly FIFO and that the move count never exceeds the number of operations.

NATModerateOriginal GATE-style

Two stacks share one array of 10 cells, growing from opposite ends. One stack receives 4 pushes and the other receives 6. How many of the 10 pushes succeed?

Answer: 10

Overflow happens only when top1 + 1 == top2, that is when the two tops meet with no free cell between them. Ten pushes into ten cells meet exactly at the end, so all ten succeed and the next push fails.

Common wrong answer: 5 and 5. That assumes each stack is given half the array. Splitting the array is a different (and worse) design: it lets one stack overflow while the other half is empty.

The page's model pushes alternately until the overflow test fires and confirms exactly 10 successes for N = 10.

MCQModerateGATE CSE 2015 Set 3, 1 mark

The postfix expression 6 2 3 * - 4 5 * + evaluates to

  1. 20
  2. 0
  3. −4
  4. 16

Answer: A — 20

6 → [6]; 2 → [6,2]; 3 → [6,2,3]; * → 6 → [6,6]; − → 0 → [0]; 4 → [0,4]; 5 → [0,4,5]; * → 20 → [0,20]; + → 20.

B is the trap for the minus: the stack holds 6 and 6 at that step, so 6 − 6 = 0 either way — a coincidence that hides an operand-order error. C comes from reading the minus as 6 − 2 × 3 with the multiplication applied after, which is the infix reading. D drops the leading 6.

This question is an original variant in the shape of GATE 2015 Set 3, whose own expression evaluates to 142 in the Examples tab.

MCQHardOriginal GATE-style

A circular queue of 6 cells uses the sacrifice convention with front = 4 and rear = 2. How many elements does it contain, and is it full?

  1. 4 elements, not full
  2. 2 elements, not full
  3. 3 elements, full
  4. 4 elements, full

Answer: A — 4 elements, and not full

Count = (rear − front + N) mod N = (2 − 4 + 6) mod 6 = 4. Full test: (rear + 1) mod N = 3, which is not equal to front = 4, so the queue is not full.

Cells 4, 5, 0, 1 hold the four elements; cell 2 is the next write position and cell 3 is the sacrificed cell. A fifth insertion succeeds, and the sixth is refused.

Option D is the trap: four elements out of a capacity of five is close to full, and the arithmetic (2 − 4 + 6) mod 6 is easy to mis-sign into 0 or 6. Option B subtracts front from rear the other way and gets 2. Option C treats three as the count, which would need front = 5.

NATModerateOriginal GATE-style

How many distinct output orders can be produced by pushing 1, 2, 3, 4 through one stack, with pops allowed at any time?

Answer: 14

Catalan: (2n)!/((n+1)! n!) with n = 4 gives 8!/(5! · 4!) = 40320/(120 · 24) = 14.

Common wrong answer: 24. That is 4!, the number of all orders, which assumes every permutation is reachable. 16 is 2⁴, the number of push/pop interleavings up to a symmetry, and it is not the count of distinct outputs — several interleavings produce the same order.

The page's model enumerates all 24 permutations, tests each with the greedy pass, and counts 14 — matching the closed form and matching the 312-avoidance test.

The revision sheet

Everything here is either a verified fact, a formula whose assumptions are written beside it, or a number the page's model computed. Nothing depends on an unstated convention.

Definitions

Array: one contiguous block of equal-sized elements, reached by index arithmetic from a base address.

Stack: insertion and deletion at one end; LIFO.

Queue: insertion at the rear, deletion at the front; FIFO.

Circular queue: a queue whose indices are reduced modulo the array size, so cells are reused.

Amortised cost: total cost of a sequence divided by its length, which can be smaller than the worst case of one operation.

Formulas, with their assumptions

1-D address — B + (i − L)·w. Assumes one contiguous block of equal elements.

Row-major — B + ((i − L₁)·cols + (j − L₂))·w. Assumes the second index varies fastest.

Column-major — B + ((j − L₂)·rows + (i − L₁))·w.

Stack on an array — push: a[++top] after testing top == N−1; pop: a[top--] after testing top == −1.

Circular, sacrifice — empty front == rear; full (rear+1) mod N == front; count (rear − front + N) mod N; capacity N − 1.

Circular, count — empty count == 0; full count == N; capacity N.

Two stacks in one array — overflow exactly when top1 + 1 == top2; holds all N.

Reachable orders — C(n) = (2n)!/((n+1)! n!) = 1, 2, 5, 14, 42, 132 for n = 1…6.

Decision procedure

  1. Address question: lower bound, order, element size — then substitute. Three inputs, one substitution.
  2. Trace question: draw the cells and the index arrows; write the state after each step. Stop at the step the question names.
  3. Postfix: first pop is the right operand. Only − and ÷ can expose the error.
  4. Reachability: greedy push-until-on-top. Exhaustive, and cheap per option.
  5. Counting: Catalan, not n!. Not every order is reachable.
  6. Full/empty: test the initial state first. It eliminates half the options at once.
  7. Cost: expensive once, or expensive every time? Worst case against amortised.

Traps, one line each

Row-major means the column index varies fastest.

The multiplier is the length of the other dimension.

An array parameter is a pointer, so sizeof inside the callee is a pointer size.

Out of bounds compiles; it is not thereby defined.

Capacity is N − 1 or N depending on the full test.

front == rear is empty in the sacrifice convention, not full.

3, 1, 2 is unreachable with one stack.

The two-stack queue is amortised O(1); the two-queue stack is Θ(n) per pop.

A state question wants a state, not the final value.

Mathematical and textbook references

Catalan numbers and 312-avoidance. The count (2n)!/((n+1)! n!) and the characterisation "reachable with one stack iff the order avoids the pattern 312" are Knuth's results, restated in the note "Stackable and queueable permutations" (Doyle, Dartmouth). The lesson does not rely on the citation alone: the page enumerates every permutation up to six elements, tests reachability by simulation, and confirms both the counts and the equivalence.

Standard textbook treatment of array address calculation, the stack and queue abstract data types, postfix evaluation and the circular-queue conventions. The derivations are worked in the page's model rather than quoted.
