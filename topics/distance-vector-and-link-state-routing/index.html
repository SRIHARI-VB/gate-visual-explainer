Topic and objective

TOPIC: The fourth clause of Section 10 of the official GATE 2027 CS syllabus — distance vector and link state routing. Two families of algorithm that answer the same question in opposite ways: what should a router put in its table, and what is it allowed to know?

LEARNING OBJECTIVE: Apply the Bellman-Ford update to a router given its neighbours' vectors, and report both the cost and the next hop; trace a distance vector exchange for exactly one round after a link cost change; follow the count-to-infinity loop and state what split horizon, poison reverse, triggered updates and hold-down timers each change; run Dijkstra on a small graph, record the settlement order and convert the shortest-path tree into next hops; and state the protocol facts that separate RIP from OSPF.

I read this clause as one question asked with two kinds of knowledge. A distance vector router believes what its neighbours say; a link state router holds the whole map. Every contrast in the clause — convergence, messages, loops, memory — is a consequence of that one difference, and the practice set is built on it.

GATE relevance

Verified fact Class A — explicitly in the syllabus.

Section 10 of the official GATE 2027 CS syllabus (IIT Madras, CS_GATE2027_Syllabus.pdf) reads: "Principles of Layering; Basics of switching (circuit, packet and virtual circuit) and performance metrics; link layer: error detection, Medium Access Control, Ethernet; Distance vector and link state routing; IPv4 - Fragmentation, CIDR Notation, Network Address Translation; TCP- flow control and congestion control, socket API; DNS and HTTP."

This lesson is the clause distance vector and link state routing, in full. The clause before it is taught in error detection, MAC and Ethernet.

Class A means a question here is inside the declared boundary. It does not mean one is guaranteed. The previous-year items below are an observation about past papers, never a forecast for 2027.

The five ideas this lesson turns on

  1. Distance vector is one line of arithmetic. The best route through any neighbour is that neighbour's advertised distance plus the link cost. The minimum over neighbours is the answer, and the neighbour that achieved it is the next hop.
  2. Count to infinity is a provenance problem. Nothing in a distance vector says where the number came from, so a router can believe a route it is itself the source of.
  3. Split horizon is not a cure. It removes two-router loops; a loop that closes through a third router survives it, and the page simulates that case.
  4. Link state removes the loop by removing the disagreement. Flood first, so every router holds the same map, then compute locally with Dijkstra.
  5. Both find the same distances. The families differ in knowledge, messages and convergence time — never in the final answer on a converged network.

Intuition: asking directions versus carrying a map

You want to reach a town you have never visited. Two strategies. Ask each person at the crossroads how far the town is, add the distance you just walked, and take the shortest answer. Or buy a map of the whole region and work out the shortest route yourself.

The first strategy is cheap and local, and it fails when the person you asked is repeating what you told them last week. The second is expensive to obtain and cannot lie to you, because every road is drawn on the same map.

Educational interpretation The analogy carries the separation of local belief from global knowledge, which is the whole clause. It does not carry the terminology, and asking directions is not literally the Bellman-Ford equation.

Formal definitions

A routing table maps each destination to a next hop and a cost. Forwarding is reading that table once per packet. Routing is the process that builds it.

A distance vector is a router's row of costs, one entry per destination. The Bellman-Ford equation says the cost from $$x$$ to $$y$$ is the smallest, over neighbours $$v$$, of the link cost from $$x$$ to $$v$$ plus the cost that $$v$$ reports to $$y$$.

D(x, y) = minv ∈ N(x) [ c(x, v) + D(v, y) ]D(x,y) is the cost x records for y; c(x,v) is the cost of the link from x to v; N(x) is the set of x's direct neighbours. The minimisation is over neighbours only.

Verified fact This is the standard form of the distance-vector update, as given in Kurose and Ross, Computer Networking, and in the Duke CompSci 356 link-state and RIP lecture notes used for this lesson.

What "one round" means

All routers send their current row to their neighbours. Then all routers recompute from the rows as they were before the round. The new rows take effect together.

A stabilised (converged) set of rows is a fixed point: recomputing every row from its neighbours reproduces the same numbers. The model on this page checks that property for all five rows of the GATE 2011 network.

Mathematical derivation If no row changes, every row satisfies the Bellman-Ford equation simultaneously, which is exactly the definition of a set of shortest-path distances. So a fixed point is a solution, and Bellman-Ford's convergence theorem makes it the unique one for non-negative costs.

Link state, precisely

A link state advertisement (LSA) carries one router's own links and their costs — adjacency and cost, never a distance. Advertisements are flooded to every router; the collected set is the link state database.

Each router then runs Dijkstra on that database with itself as the root. The output is a shortest-path tree, and the next hop for a destination is the first step from the root along that tree.

settle the unsettled router with the smallest tentative cost, then relax its linksRelaxing means offering each neighbour (settled cost + link cost) and keeping whichever is smaller. Repeat until every router is settled.

Verified fact The flooding-plus-Dijkstra structure, the OSPF carriage directly in IP protocol 89, and the RIP ceiling of 15 hops with 16 meaning infinity are all stated in the Duke CompSci 356 lecture notes, which follow RFC 2328 and RFC 2453.

The two failure modes, stated before they are used

Count to infinity. A router can accept a route whose next hop is the router it just advertised to, so a dead destination stays alive with a rising cost.

Disagreement. In link state the danger is the opposite: routers holding different maps. Reliable flooding with sequence numbers exists to prevent exactly that.

Mathematical derivation If every router holds the same graph and every cost is non-negative, every shortest-path tree is a subgraph of that graph, and a path assembled from two such trees cannot close a cycle unless it repeats a node. That is why link state is loop-free by construction rather than by repair.

Takeaway from page 1

Distance vector is a minimisation over neighbours; link state is a shortest-path computation over a map. Say which one a question is about before touching the numbers.

Build-up, page 2 of 2 — loops, repairs, and the honest limits of each

Levels 5 to 7: when the equation breaks, what the standard repairs actually repair, and the boundaries that decide whether a shortcut applies.

Counterexample: the loop in three exchanges

Routers A and B are one hop apart. A destination hangs off B, which reaches it in 1; A reaches it in 2 through B. The link from B to the destination dies.

B sets infinity. Before B's update reaches A, A advertises 2. B adds its link cost and records 3 through A. A hears 3 and records 4. The two keep handing each other an inflated number: 2, 3, 4, 5, …

Mathematical derivation Each update is a correct application of the Bellman-Ford equation to the numbers available. The equation is not wrong; the inputs are stale. That is why the loop is a protocol problem and not an arithmetic one.

The four standard repairs, each as a rule

Split horizon — never advertise a route back out of the interface you learned it from.

Poison reverse — the same rule said out loud: advertise it back, but with metric 16.

Triggered update — send the bad news at once instead of waiting for the periodic timer.

Hold-down — refuse to believe good news about a route for a while after bad news.

Verified fact All four are described in the Duke CompSci 356 RIP notes and in RFC 2453's account of RIP's loop-avoidance measures.

Where the repairs stop working

Put three routers in a line, A to B to C, with the destination hanging off A. Split horizon silences B in both directions. The two outer routers then oscillate between a real cost and infinity while B climbs — the loop persists.

This is exactly why GATE CSE 2014 Set 1 calls the claim "a distance vector protocol with split horizon avoids persistent routing loops" false.

Mathematical derivation Split horizon only removes a two-router loop, because it only suppresses one direction per router. A cycle of length three or more has an edge on which neither endpoint learned from the other, so nothing is suppressed there.

Boundaries that decide a shortcut

Non-negative costs. Dijkstra's settle-the-minimum step is only safe when no later route can undercut a settled cost.

Symmetric links. Most GATE items state that costs are the same in both directions. When they are not, each direction is its own problem.

Convergence, not one round. A one-round answer is a transient value; the true distance may be smaller.

A finite ceiling. RIP's 16 makes count to infinity terminate, and simultaneously caps usable paths at 15 hops.

Worked examples, page 1 of 2 — vector arithmetic on real papers

Every number below is recomputed by the model on this page; the checks are printed under the canvas in the Animation tab.

Example 1 — GATE CSE 2021 Set 2 Q45

Router R measures its links to X, Y, Z as 3, 2, 5. Their vectors say P is at 7, 6, 5 and Q is at 4, 6, 8.

To P: 3+7 = 10, 2+6 = 8, 5+5 = 10 → 8 through Y. To Q: 3+4 = 7, 2+6 = 8, 5+8 = 13 → 7 through X.

So the statements "distance to Q is stored as 7" and "next hop for P is Y" are correct, and "distance to P is stored as 10" is false. The official key is B and C in the paper's original ordering.

Example 2 — GATE CSE 2011 Q52

Five stabilised vectors; the cost of N2–N3 drops from 6 to 2. Recompute N3 from its neighbours N2, N4, N5, using the vectors as they stood before the round.

To N1: 2+1 = 3, 2+8 = 10, 6+4 = 10 → 3. To N2: 2. To itself: 0. To N4: min(2+7, 2, 2+4) = 2. To N5: min(2+3, 2+4, 6) = 5.

New row: 3, 2, 0, 2, 5 — option A. The model gets the same row whether N2's vector is the old one or the already-updated one, which is why this item is not sensitive to the round convention.

Example 3 — GATE CSE 2011 Q53

Next, N1–N2 fails. N2 immediately reports infinity to N1. N3's three neighbours offer 2+∞, 2+8 and 6+4, so N3 records 10.

The true shortest path after the failure is N1–N5–N2–N3 at 4+3+2 = 9. The algorithm reaches 9 in a later round, not this one.

Mathematical derivation The question asks for the value after the next round of updates, not the converged value. Both facts are checked in the model, and the difference between 10 and 9 is the point of the item.

Example 4 — reading a table off a tree

Dijkstra from A on the six-router graph settles A, C, B, D, E, F at costs 0, 2, 3, 8, 10, 13. The predecessors are A, A, C, B, D, E.

To reach F the path is A→C→B→D→E→F, so the routing table entry for F is cost 13, next hop C — the child of the root, not E.

Mathematical derivation A router can only hand a packet to a direct neighbour, so the stored next hop must be the first node after the root on the tree path. The model checks, for every destination, that the link cost to the next hop plus that neighbour's distance equals the total distance.

Worked examples, page 2 of 2 — a Dijkstra run, a loop, and a probability

Three longer examples: the full settlement table, the count-to-infinity trace, and the 2022 probability item.

Example 5 — the settlement table, in full

Edges: A–B 4, A–C 2, B–C 1, B–D 5, C–D 8, C–E 10, D–E 2, D–F 6, E–F 3. Run Dijkstra from A and write the tentative column after each settlement.

settle C (2) → B 3, D 10, E 12  ·  settle B (3) → D 8  ·  settle D (8) → E 10, F 14  ·  settle E (10) → F 13Each settle step takes the smallest unsettled cost, then offers every neighbour that cost plus the link cost. A larger offer never replaces a smaller recorded one.

Final costs 0, 2, 3, 8, 10, 13 in settlement order. The C–D edge of cost 8 is never used: D is reached at 8 through B, and the direct route from C would cost 10. That is a deliberate distractor of the kind papers include.

Example 6 — the count-to-infinity trace

A and B one hop apart, destination on B. After the failure, alternating updates give A = 2, B = 3, A = 4, B = 5, … until both reach 16.

The model runs this and reports how many exchanges it takes. Because RIP caps at 16, the climb terminates; without a cap it would not.

Mathematical derivation Each exchange adds exactly one link cost to the value it received, so the sequence is arithmetic with common difference 1. With a ceiling of 16 it terminates in a number of exchanges bounded by 16.

Example 7 — GATE CSE 2022, the probability

Three routers P, Q, R in a line, all links unit cost, converged. The link Q–R fails. P and Q send updates at random times at the same average rate.

If Q's update arrives first, Q says infinity and P has no other route, so both settle. If P's update arrives first, Q adopts P's stale value and the loop runs.

Probability = 0.5. Two equally likely orders, exactly one of which loops. The model enumerates both and counts the looping one.

What the seven examples have in common

Every one is a small table of numbers and one rule applied honestly. None needs a diagram to be solved; the diagram only makes the rule visible.

Edge cases and boundaries

Each card names a boundary, the condition it violates, and what changes when it is violated.

One round is not convergence

After a link failure, the first round can produce a cost larger than the true shortest path, because the neighbours are still advertising pre-failure numbers. GATE CSE 2011 Q53 is the clean example: the answer is 10, the true distance is 9.

The condition violated is "the vectors have stabilised". Answer the question that was asked, then check the magnitude against the true value.

A tie for the minimum

In GATE CSE 2011 Q53 the minimum of 10 is achieved twice, through N4 (2+8) and through N5 (6+4). The cost answer is unique; the next hop is not.

If a question asks for the next hop and a tie exists, the item is under-specified unless it also fixes a tie-breaking rule. Cost questions are safe; next-hop questions are not.

16 in RIP is not a distance

RIP reserves 16 for "unreachable", so a usable path is at most 15 hops. Writing 16 as a cost, or treating a 16-hop path as reachable, is the most common RIP error.

The condition violated is the metric range: 1 to 15 for a real route, 16 for no route.

Negative or zero link costs

Dijkstra's greedy step assumes no later route can undercut a settled cost. With a negative link that assumption fails and the settled set is no longer final.

GATE routing items use positive costs, so this is a boundary rather than a trap in the exam. It is still worth stating, because it is why the algorithm is allowed to settle a minimum.

A disconnected graph

If a destination becomes unreachable, the distance vector row holds infinity and Dijkstra leaves the tentative cost at infinity because it never settles that node.

Both algorithms agree: the entry is unreachable, not "very far". A table with a finite cost to an unreachable destination is a bug or a loop in progress.

Asymmetric link costs

If the cost from A to B differs from B to A, the problem becomes directed and the two directions are separate shortest-path problems.

Most GATE items state explicitly that links are symmetric. When they do not, check before assuming a single weight per edge.

Different trees, same map

Two OSPF routers hold the same link state database and compute different shortest-path trees, because each roots its tree at itself.

So "all routers have the same routing table" is false, and "all routers have the same topology database" is true. Both statements appear in question banks.

Takeaway

Almost every edge case in this clause is a violated assumption: convergence, a unique argmin, a bounded metric, non-negative costs, a connected graph. Name the assumption and the edge case answers itself.

Misconceptions, each with the smallest counterexample

The wrong belief, why it is tempting, what breaks it, and the rule to use instead.

"Distance vector routers know the whole graph but only use part of it"

Why it tempts: the vectors contain a number for every destination, which looks like a compressed map.

What breaks it: a router has no link costs except its own, and no idea how many hops a neighbour's number represents.

Rule: a distance vector router holds beliefs about costs, not facts about links.

"Count to infinity means the numbers are computed wrongly"

Why it tempts: the cost rises even though nothing got further away, which looks like an arithmetic error.

What breaks it: every step is a correct Bellman-Ford update on stale inputs.

Rule: the protocol lacks provenance — nothing records where a number came from. Fix the provenance, not the arithmetic.

"Split horizon removes persistent loops"

Why it tempts: it demonstrably fixes the two-router case, which is the case drawn in most notes.

What breaks it: three routers in a line with split horizon still oscillate — the page simulates exactly this, and GATE CSE 2014 Set 1 marks the claim false.

Rule: split horizon removes two-router loops only. Longer cycles survive it.

"OSPF is carried over TCP because it needs reliability"

Why it tempts: flooding needs acknowledgements, and TCP provides acknowledgements.

What breaks it: OSPF runs directly in IP with protocol number 89 and implements its own acknowledgement. It is not in TCP and not in UDP.

Rule: RIP over UDP 520; OSPF directly over IP protocol 89; BGP over TCP.

"Link state finds shorter paths than distance vector"

Why it tempts: Dijkstra on a complete map feels stronger than gossip.

What breaks it: at convergence both compute shortest paths, and the model checks that the two agree on four graphs.

Rule: they differ in knowledge, messages and convergence time, never in the converged answer.

"A routing table stores the full path"

Why it tempts: a solved example draws the whole route, so the route looks like the answer.

What breaks it: a router hands a packet to one neighbour, so only the first hop can be stored.

Rule: destination, next hop, cost. The rest of the path is other routers' business.

Question categories in this clause

Four shapes account for every previous-year item I could verify. Each demands a different reasoning step, and each has its own common wrong approach.

1. Vector-update arithmetic (1 to 2 marks)

Given: link costs and neighbour vectors. Asked: a new row, a cost, or a next hop after one round.

Procedure: list only the neighbours; write one candidate sum per neighbour; take the minimum; record the argmin.

Common wrong approach: using the updated neighbour vector inside the same round, or letting a non-neighbour contribute directly.

2. Loop and convergence behaviour (1 to 2 marks)

Given: a topology and a failure. Asked: a cost after the next round, a probability of looping, or a true-or-false statement about split horizon.

Procedure: decide who hears what, in which order; then apply the update once.

Common wrong approach: assuming convergence, or assuming the failure is known everywhere immediately.

3. Dijkstra and the tree (2 marks)

Given: an edge list. Asked: the settlement order, a distance, or a next hop.

Procedure: draw the graph, settle by increasing cost, keep the predecessor, then take the first hop from the root.

Common wrong approach: reading a next hop off the end of the path, or skipping the drawing and mis-reading an edge.

4. Protocol facts (1 mark, MCQ or MSQ)

Given: statements about RIP and OSPF. Asked: which are correct or incorrect; or a two-column matching.

Procedure: sort each fact into algorithm, metric, transport, limit, scope.

Common wrong approach: confusing intra-domain with inter-domain, or swapping the transport of the two protocols.

Where the marks are actually lost

In the verified items, the recurring losses are: (i) answering a cost when a next hop was asked, or the reverse; (ii) treating a one-round value as the converged value; (iii) writing 16 as a distance in RIP; (iv) accepting "split horizon prevents all loops"; (v) believing OSPF uses TCP. None of these is a conceptual gap — each is a single sentence of care.

Community observation The pattern of errors above is reported consistently in discussion threads for the 2011, 2014, 2021 and 2023 items. It is an observation about how learners answer, not a measurement.

GATE CSE 2025 Set 2 Q1 (MCQ, 1 mark)

Match List I with List II. (i) Distance vector routing, (ii) Link state routing; (a) Bellman-Ford, (b) Dijkstra.

(A) (i)-(a) and (ii)-(b)   (B) (i)-(a) and (ii)-(a)   (C) (i)-(b) and (ii)-(a)   (D) (i)-(b) and (ii)-(b)

(A). Distance vector is the distributed Bellman-Ford equation; link state floods the map and runs Dijkstra.

(B), (C) and (D) each pair at least one protocol with the wrong algorithm. The item is numbered Q17 in two archives and Q7 in another; the wording and the key agree across them.

GATE CSE 2023, Q25 Q2 (MSQ, 1 mark)

Which statements are INCORRECT about OSPF? (A) OSPF implements Bellman-Ford to find shortest paths. (B) OSPF uses Dijkstra for least-cost routing. (C) OSPF is used as an inter-domain routing protocol. (D) OSPF implements hierarchical routing.

(A) and (C). OSPF is link state, so Dijkstra, not Bellman-Ford; and it is an interior gateway protocol, not an inter-domain one.

(B) and (D) are correct statements: Dijkstra is used, and OSPF divides a domain into areas with a backbone. Hierarchical inside a domain is not inter-domain routing — that distinction is the whole of option (C).

GATE CSE 2021 Set 2, Q45 Q3 (MSQ, 2 marks)

Router R has neighbours X, Y, Z at distances 3, 2, 5. Their vectors give distance to P as 7, 6, 5 and to Q as 4, 6, 8. Which statements are correct about R's new table?

(A) Distance to P stored as 10   (B) Distance to Q stored as 7   (C) Next hop for P is Y   (D) Next hop for Q is Z

(B) and (C). To P: min(10, 8, 10) = 8 via Y. To Q: min(7, 8, 13) = 7 via X.

(A) quotes the candidate sum through X rather than the minimum. (D) names Z, which is the worst of the three routes to Q. The model computes both minima and both argmins, and the official key is B, C.

GATE CSE 2011, Q52 Q4 (MCQ, 2 marks)

Five routers N1 to N5 use distance vector routing. Stabilised vectors: N1 (0,1,7,8,4), N2 (1,0,6,7,3), N3 (7,6,0,2,6), N4 (8,7,2,0,4), N5 (4,3,6,4,0). The cost of N2–N3 reduces to 2 in both directions. After the next round of updates, N3's vector is:

(A) (3,2,0,2,5)   (B) (3,2,0,2,6)   (C) (7,2,0,2,5)   (D) (7,2,0,2,6)

(A). N3's neighbours are N2, N4 and N5. To N1 the candidates are 3, 10 and 10; to N5 they are 5, 6 and 6.

(C) and (D) keep the old cost of 7 to N1, i.e. they ignore the new link cost entirely. (B) and (D) keep 6 to N5, which ignores the shorter route through N2. The model recomputes the whole row and gets 3,2,0,2,5. Some archives number this item 51 or 54.

GATE CSE 2011, Q53 Q5 (MCQ, 2 marks)

After the update above, the link N1–N2 goes down. N2 immediately records infinity to N1. After the NEXT ROUND of update, what is the cost to N1 in N3's vector?

(A) 3   (B) 9   (C) 10   (D) ∞

(C). N3's neighbours give 2+∞, 2+8 and 6+4, so the minimum is 10.

(B) is the true converged distance, 9 through N5, and it is the trap: the question asks for one round, not convergence. (A) would need a cheaper route through N2, which is now unreachable. (D) ignores N4 and N5 entirely. The model checks that 10 is achieved twice and that the converged value is 9.

GATE CSE 2014 Set 1, Q23 Q6 (MCQ, 1 mark)

For a network with 500 nodes and 4000 links: [S1] computational overhead is higher in link state than in distance vector. [S2] A distance vector protocol with split horizon avoids persistent routing loops, but a link state protocol does not. [S3] After a topology change, link state converges faster than distance vector. Which is correct?

(A) all true   (B) all false   (C) S1 and S2 true, S3 false   (D) S1 and S3 true, S2 false

(D). S1 is true — every router floods and runs a full shortest-path computation. S3 is true — the new map reaches every router at once. S2 is false, and backwards: it is distance vector that has the loop problem, and split horizon does not remove all of it.

(A) is the common wrong answer, because S2 sounds like a reasonable statement about split horizon. (C) inverts S3. The page simulates the three-router case that makes S2 false.

GATE CSE 2014 Set 2, Q23 Q7 (MCQ, 1 mark)

Which is TRUE about the interior gateway protocols RIP and OSPF?

(A) RIP uses distance vector and OSPF uses link state   (B) OSPF uses distance vector and RIP uses link state   (C) both use link state   (D) both use distance vector

(A). RIP is the distance vector protocol in the Internet stack; OSPF is the link state one.

(B) swaps the two, which is the standard slip when the acronyms are memorised without the algorithms. (C) and (D) are wrong for one of the two protocols each. The five-slot table in the Animation tab is the fastest way to keep this straight.

GATE CSE 2017 Set 2 Q8 (MCQ, 1 mark)

Statements: I. RIP uses distance vector routing. II. RIP packets are sent using UDP. III. OSPF packets are sent using TCP. IV. OSPF operation is based on link-state routing. Which are CORRECT?

(A) I and IV only   (B) I, II and III only   (C) I, II and IV only   (D) II, III and IV only

(C). I, II and IV are correct. III is false: OSPF runs directly in IP with protocol number 89, with its own acknowledgements.

(A) drops the true statement about UDP port 520. (B) and (D) accept the false TCP claim. Some archives number this item Q9.

GATE CSE 2022 Q9 (NAT, 2 marks)

Three routers P, Q, R in a line with unit-cost links have converged. The link Q–R fails. P and Q send updates at random times, each at the same average rate. The probability of a routing loop forming between P and Q, to one decimal place, is ______.

0.5. Two equally likely orders of the two updates; only "P first" produces the loop.

The tempting wrong answers are 1.0 (assuming the loop always forms) and 0.0 (assuming the failure is known everywhere at once). The item is numbered 47 in one archive, 57 in another and 16 in a third; the wording and the answer agree.

Original practice Q10 (NAT)

A distance vector network uses the six-router graph of this lesson (A–B 4, A–C 2, B–C 1, B–D 5, C–D 8, C–E 10, D–E 2, D–F 6, E–F 3). Every row starts as the direct link costs, with infinity where no link exists. What cost does A record for E after the FIRST round of updates?

12. A's only neighbours are B and C, and in round one their rows still hold direct costs: B has no link to E, so 4 + ∞ is useless, and C reports 10, so A records 2 + 10 = 12.

The tempting answer is 10, which is the converged value, reached through A→C→B→D→E once B has learned D's 2. Writing 10 here answers a different question. The model's round-by-round trace gives 12 for round one and 10 at convergence, and both are checked.

Original practice Q11 (MSQ)

Which of these are TRUE of the six-router Dijkstra run in this lesson?

(A) The settlement order is A, C, B, D, E, F. (B) The cost to F is 13. (C) The next hop for F is E. (D) The edge C–D of cost 8 is on a shortest path from A.

(A) and (B). The settled costs are 0, 2, 3, 8, 10, 13. The next hop for F is C, the child of the root — so (C) is false. C–D is never used: D is reached at 8 through B, and the direct edge would cost 10.

(C) confuses the predecessor with the next hop, which is the single most common table-building error. (D) mistakes an edge that exists for an edge that is used.

Original practice Q12 (MCQ)

A network uses RIP. A route is advertised with metric 15. A router one hop away receives that advertisement. What does it record, and what happens if the route later becomes unreachable?

(A) 16, which is a usable cost; on failure it becomes 17.   (B) 16, which means unreachable; the route is already unusable.   (C) 15, since RIP does not add the link cost.   (D) 16, which is usable; on failure it stays 16.

(B). Adding the link cost gives 16, and 16 is RIP's definition of infinity, so the route is unusable from the moment it is received.

(A) and (D) treat 16 as a distance, which is the classic error; there is no 17 in RIP. (C) ignores the Bellman-Ford addition. The practical consequence is that a RIP domain cannot contain a path longer than 15 hops.

Revision sheet — one screen

Definitions, the two algorithms, the repairs, the protocol facts, and the five traps.

Definitions

Routing table: destination → next hop + cost. Distance vector: one row of costs per router. Converged: every row is a fixed point of the Bellman-Ford update.

LSA: one router's own links and costs. LSDB: all LSAs, identical at every router. SPT: the shortest-path tree rooted at one router.

Next hop: the first step from the root on the tree — never the last.

The two algorithms

DV: D(x,y) = minv ∈ N(x) [ c(x,v) + D(v,y) ]Neighbours only; value and argmin are two answers.
LS: settle min tentative cost, then relaxNeeds the whole graph and non-negative costs.

Both converge to the same distances. DV needs no map; LS needs flooding but no repair.

The repairs, and their limit

Split horizon — do not advertise a route back where you learned it. Removes two-router loops.

Poison reverse — advertise it back with 16.

Triggered update / hold-down — shorten the window in which stale numbers are believed.

Limit: a three-router loop survives all of them; the page simulates it.

Protocol facts

RIP: distance vector · hop count · UDP 520 · 15 hops, 16 = ∞ · interior · periodic updates.

OSPF: link state · cost · IP protocol 89 · areas with a backbone · interior · flooded LSAs.

BGP: the exterior protocol. Neither RIP nor OSPF routes between domains.

Five traps, one line each

1. One round is not convergence — 2011 Q53 answers 10 while the true cost is 9. 2. Sixteen means unreachable, not a distance. 3. Split horizon does not remove every loop. 4. Link state trees differ between routers while the map does not. 5. The next hop is the first step from the root, not the destination.
