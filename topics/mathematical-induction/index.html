Topic and objective

TOPIC: Mathematical induction and its three siblings — strong induction, the well-ordering principle, and structural induction — plus the place the same argument appears in algorithm correctness and in solving recurrences. This is the proof technique underneath Section 1 of the official GATE 2027 CS syllabus, not a syllabus clause of its own.

LEARNING OBJECTIVE: Write a complete induction proof with a stated predicate, a base case that sits where the step is legal, and a step proved for an arbitrary n in the claim's range; recognise which of the four forms a given claim needs; verify a guessed closed form for a recurrence; and name the exact check that is missing when an induction argument is wrong.

I read this topic as the arithmetic of "and so on". Every induction question, in the exam or in your own head, comes down to two numbers: where the base sits, and on what range the step is valid. The lesson is built around those two, and the four failure modes at the end are all one of them being wrong.

Prerequisites

  • Propositional logic — implication, its one false row, and universal quantification. The step is an implication and the conclusion is a universal statement; without those two, the rule cannot be stated.
  • Sets and set operations — the least-counterexample proof is about a set of counterexamples being non-empty.
  • Arithmetic with fractions and powers. Nothing else: this lesson assumes no calculus and no linear algebra.

Five ideas that decide almost every question here

  1. The predicate is a sentence with n in it. "It holds for n" is not a predicate; "1³ + … + n³ = (1 + … + n)²" is. The step is checked at n + 1 by rewriting that same sentence.
  2. The base must sit where the step is legal. 2n > n2 has a true base at n = 1 and a step valid only from n = 3, so the chain cannot leave n = 1. The base has to be 5.
  3. Strong induction is a convenience, not extra power. It lets the step use every smaller case, which is what a recurrence and a factorisation need; anything it proves, ordinary induction proves with a wider predicate.
  4. Induction, strong induction and well-ordering are one argument in three formats. Something is checked at the bottom and something carries you upward. Which format you write in is a readability choice.
  5. A finite check is evidence, not proof. The page verifies the cube identity to n = 300, insertion sort's invariant on 24 arrays, and the recurrence at 20 inputs. None of those is the proof, and Fermat's numbers show why: five confirming cases and a counterexample at the sixth.

Intuition: you already do this, and you already distrust it

Somebody asks whether the sum of the first n odd numbers is always n squared. You try 1 = 1, 1 + 3 = 4, 1 + 3 + 5 = 9, 1 + 3 + 5 + 7 = 16. Four cases agree. Do you know it? No — and you already know you do not, because you have met a sequence that agreed for a while and then stopped.

Induction is the move that turns "and so on" into something checkable. Instead of verifying case 5 and case 6 and case 7, you verify two things: that the statement is true at the start, and that whenever it is true at some n it must also be true at n + 1. The second thing is a single proof, because n is arbitrary. Given those two, case 500 arrives by 499 applications of the second, and no case is left unchecked.

Educational interpretation The dominoes picture is an analogy for the shape of the argument, not an argument. It is accurate in one respect that matters: the base is a push, the step is a link, and a chain with one broken link settles nothing beyond the break.

The induction principle

if P(0) and for every n in N: P(n) implies P(n+1) then for every m in N: P(m)

Read the second line carefully: it is one statement with a universal quantifier inside it, not a family of statements you prove separately. Proving it for an arbitrary n is what makes the step cover every n at once. When the claim starts at some other integer k, replace 0 by k and "every n in N" by "every n at least k".

Strong induction

if P(k) and for every n at least k: P(k) and P(k+1) and ... and P(n) imply P(n+1) then for every m at least k: P(m)

The hypothesis is widened: instead of assuming the claim at n, assume it at every value from the base up to n. This is what a claim needs when the case at n + 1 is built from a case much smaller than n — a factor n/2 in a recurrence, a factor n − 3 in the coin problem, two factors in a prime factorisation.

The well-ordering principle

every non-empty set of natural numbers has a least element

It fails for the rationals — the positive rationals have no least element — and it fails for the empty set, which has no element at all. Those two exclusions are the whole content: it is a fact about the naturals being discrete and starting somewhere. To prove a claim by it, take the set of counterexamples, assume it is non-empty, and derive a smaller counterexample.

Structural induction

a full binary tree is a leaf, or an internal node over two full binary trees

When the objects are defined recursively, the definition supplies the base and the step. Prove the claim for a leaf, then prove it for a node assuming it for both children. The same shape proves statements about strings, about derivation trees in a grammar, and about lists.

The five parts of a written proof

A complete induction argument names its parts. Omitting one is the commonest lost mark, and the predicate is the one most often omitted.

  1. State that the proof is by induction, and in which form.
  2. Define P(n) as a complete sentence containing n.
  3. Prove the base case, at the smallest n the claim names.
  4. Prove the step for an arbitrary n in the claim's range, using the hypothesis.
  5. Invoke the rule and state the conclusion.

Level 1 and 2: what the rule says, in words and in symbols

In words: if the first statement is true, and every statement forces the next one, then every statement is true. In symbols the rule is two premises and one conclusion. The second premise is where all the mathematical work happens, and the reason a proof is worth writing is that this premise must hold for every n in range, including the ones where the algebra is awkward.

premise 1 P(k) the base premise 2 for every n at least k, P(n) implies P(n+1) the step conclusion for every m at least k, P(m)

Mathematical derivation Nothing here is circular. The step is the implication P(n) → P(n+1) for arbitrary n; the hypothesis P(n) is used only inside that implication, and the conclusion P(m) is obtained from the base together with the chain of implications, never from the hypothesis alone.

Level 3: why a picture helps, and where it lies

The domino picture is exact for one thing: the number of applications. From P(5) to P(20) is fifteen applications of the step, and the picture makes that countable.

It lies about one thing: dominoes are physical and a real chain of forty would have a last domino. The claim usually has no last case. Draw the chain with an ellipsis, never with a final domino, or you will start believing the finite case is the theorem.

Level 5: the boundaries that matter

Four boundaries decide whether an argument works, and each is a number rather than an idea:

• the smallest n in the claim — that is where the base goes;

• the smallest n where the step's inequality or divisibility holds;

• whether the two ranges overlap, which they must;

• whether the hypothesis at n is enough, or whether the step needs a value below n.

The one-sentence test

Before writing, answer this: which n does my step cover, and does my base sit inside that range? If you cannot answer with two numbers, the proof is not ready to be written.

Every failure on the last scene of the animation is a violation of that sentence: the horse argument's step starts at n = 2 while its base is at n = 1; the powers-of-two recurrence step covers only powers of two; the coin claim's ordinary step covers no n at all.

Worked example 1 — the sum of the first n cubes

Claim: for every n at least 1, 1³ + 2³ + … + n³ = (1 + 2 + … + n)². The right side is the square of the triangular number T(n) = n(n+1)/2.

Base case

n = 1: 1³ = 1 and T(1)² = 1² = 1

Both sides are 1. The claim's smallest n is 1, so this is the base; nothing smaller is in the claim.

Hypothesis

assume sum(i³, i = 1..k) = T(k)²

One sentence, with k in it. This is what the step is allowed to use, and the only thing it is allowed to use.

Step, in two lines that each say why

sum(i³, i = 1..k+1) = T(k)² + (k+1)³ by the hypothesis = T(k+1)² because T(k+1) = T(k) + (k+1) and T(k+1) + T(k) = (k+1)²

The second line is the whole proof and it is worth seeing why it is true rather than trusting it: the difference of two consecutive squares is (T(k+1) − T(k))(T(k+1) + T(k)), which is (k+1)·(k+1)² = (k+1)³. So the two sides grow by exactly the same amount at every step.

Mathematical derivation The page checks the identity for n = 1 to 300 (residual 0 at every n) and checks the growth identity at every k in that range, because a slip in the algebra is easy and a computed residual catches it. The check is not the proof.

What the example teaches

An induction step is almost always a rewrite: start from the (k+1) case, split off the last term, apply the hypothesis, and simplify until it reads like the (k+1) case of the claim. The example is a template for every sum identity in the counting chapter.

Worked example 2 — where the base case has to move

Claim to prove: for every n at least 5, 2n > n2. Note what is not claimed: nothing about n = 1 to 4.

The truth table, computed

n : 1 2 3 4 5 6 7 8 2^n: 2 4 8 16 32 64 128 256 n^2: 1 4 9 16 25 36 49 64 ok : T F F F T T T T

The claim is true at n = 1, false at 2, 3 and 4 (equality counts as failure for a strict inequality), and true from 5 upward. The first n from which it never fails again is 5.

The step, and its domain

want 2^(n+1) > (n+1)^2 given 2^n > n^2, so 2^(n+1) > 2n^2 enough if 2n^2 >= (n+1)^2 i.e. n^2 - 2n - 1 >= 0

That last inequality holds from n = 3 onward (at n = 3: 9 − 6 − 1 = 2 ≥ 0; at n = 2: 4 − 4 − 1 = −1). So the step is legal for n ≥ 3, and the base is at n = 5.

What goes wrong if you take the base at n = 1

The base is true, the step is true for n ≥ 3, and the proof proves nothing about n ≥ 5. The chain from 1 needs the links 1→2 and 2→3, and the step is not available at either. Computed on the page: following the step from a base at 1 reaches exactly {1}, while following the same step from a base at 5 reaches 5, 6, 7, … 20.

This is the same hole as the horse argument, in a claim that is actually true. The failure mode is not "the claim is false"; it is "the proof covers a different claim".

Worked example 3 — strong induction on a coin problem

Claim: every amount of 8 rupees or more is a sum of 3 rupee and 5 rupee coins.

Why the ordinary step is unavailable

The ordinary step would need P(n) → P(n+1). But 3 is payable and 4 is not, and 6 is payable while 7 is not. A payable amount is followed by an unpayable one, so no such implication exists for those n.

What the arithmetic does give is P(n) → P(n+3): add one 3 rupee coin. The step moves by three, so three base cases are needed, at 8, 9 and 10.

The three bases, spelled out

8 = 3 + 5 9 = 3 + 3 + 3 10 = 5 + 5

The amounts the step cannot reach, because reaching them would need a base below 8 that does not exist.

The step, and the bound that makes it legal

assume P holds for every amount from 8 to n to pay n+1: pay (n+1)-3 = n-2, then add a 3 coin this needs n-2 >= 8, i.e. n >= 10

So the argument is: bases at 8, 9, 10, and for every n ≥ 10 the hypothesis covers n − 2. Every amount from 8 to 120 is payable, computed on the page; the only unpayable amounts are 1, 2, 4 and 7, all below the claim's range.

Worked example 4 — verifying a guessed recurrence solution

T(n) = 2T(n/2) + n for n a power of two, with T(1) = 0. Guess: T(n) = n log₂ n.

Base and guess, checked

T(1) = 0 and 1 · log₂1 = 0 T(16) = 64 and 16 · 4 = 64 T(1024) = 10240 and 1024 · 10 = 10240

The page computes the recurrence exactly, in integers, for all twenty powers of two up to 2²⁰ = 1048576, and every value matches.

The step is a substitution

T(2k) = 2T(k) + 2k recurrence = 2k log₂k + 2k hypothesis = 2k (log₂k + 1) = 2k log₂(2k) closed form at 2k

The last line is exactly the guess written at 2k, which is what the step had to produce. Nothing else is needed.

The assumption you must state

This proves the guess for powers of two and for nothing else, because the step only moves from k to 2k. Stated honestly, the result is T(n) = n log₂ n for n = 2m, and Θ(n log n) for the general case. Writing "T(n) = n log n for all n" after this proof is the one error the argument cannot survive — see the Misconceptions tab.

Worked example 5 — structural induction on full binary trees

Claim: a full binary tree with i internal nodes has i + 1 leaves, 2i + 1 nodes and 2i edges.

Base: the lone leaf

A leaf has 0 internal nodes, 1 leaf, 1 node and 0 edges. The three formulas read 1 = 0 + 1, 1 = 0 + 1 and 0 = 0.

Note there is no second base case. The tree with one internal node is not a base; it is the step applied to two leaves.

Step: a node over two trees

parent internal = i₁ + i₂ + 1 parent leaves = (i₁+1) + (i₂+1) = i₁+i₂+2 = (parent internal) + 1

Both hypotheses are used, one for each child, which is why this is a structural induction rather than an induction on a number.

The enumeration that checks it

The page builds every full binary tree with 0 to 6 internal nodes by recursion: 1, 1, 2, 5, 14, 42, 132 trees, the Catalan numbers, 197 in total. In all 197, leaves = internal + 1, nodes = 2·internal + 1 and edges = 2·internal. That is a check on the claim and on the enumeration; the two paragraphs above are the proof.

The same induction proves statements about strings generated by a grammar, which is why the Theory of Computation lesson on context-free grammars uses the identical recursion for derivation trees.

Edge cases that change the answer

Each of these is a place where a correct-looking proof or a correct-looking formula is wrong for one input. The value of the list is that each item names the check that catches it.

n = 0 against n = 1

Whether the naturals start at 0 or 1 changes the base case and nothing else. A sum identity over 1..n has base 1; a count of binary strings of length n has base 0, where the empty string is one string. Writing "base case n = 0: 1³ = 1" is a category error, not a typo.

The rule: the base is the smallest n the claim quantifies over, which is the number in the claim, not the number you find easiest.

A step that is valid but starts too high

2n > n2 has a step valid for n ≥ 3 and a base at n = 1. Both are true; together they prove nothing. The check is arithmetic: does the base sit inside the step's domain, and does the chain from the base cover the claim?

Computed: from base 1 the chain reaches {1}; from base 5 it reaches 5 to 20.

Equality counted as a failure

A strict inequality 2n > n2 fails at n = 2 and n = 4, where the two sides are equal, not less. Questions that ask "for how many n does 2n > n2 hold" turn on this: within n = 1..10 the count is 7, not 9.

The same trap appears with ≥ and with divisibility where n = 0 is allowed: every integer divides 0, so a divisibility claim at n = 0 is usually trivially true and usually not what the question means.

Well-ordering needs a non-empty set of naturals

The least-counterexample argument starts by asserting the set of counterexamples is non-empty. That assertion is a proof by contradiction, and it must be explicit. If the claim is over the reals, or over an open interval, there need not be a least counterexample at all: the positive rationals have no least element.

The restriction to naturals is what makes "one smaller counterexample" a contradiction rather than an infinite descent.

Edge cases in the applications

Recurrences defined only on powers of two

T(n) = 2T(n/2) + n is not defined at odd n unless you say what n/2 means. Two honest repairs: restrict the claim to powers of two and say so, or state the bound as Θ(n log n) with floor and ceiling arguments. A proof for 2m is not a proof for 3.

The page computes the exact recurrence for n = 2m only, and the caption says so.

Loop invariants need the exit condition

The invariant after the last pass of insertion sort says "the first n entries are sorted and are a permutation of the input". That happens to be the whole array only because the loop ran to i = n. If the loop exits early — a break, an error path, a bounded search — the invariant plus the exit condition is what you must state, and the invariant alone is not the goal.

For a bounded search the useful pair is: invariant (the target is not in the scanned prefix) plus exit condition (the loop ended because the prefix is the whole array) gives "not present".

Structural induction on an empty structure

If the recursive definition allows the empty tree, the empty list or the empty string, the base case is that object and the claim must be true of it. A leaf count of 0 for an empty tree breaks "leaves = internal + 1", which is why the theorem is stated for non-empty full binary trees.

Read the definition's base clause before writing the base case; the definition is doing the work for you.

Two variables, one induction

Claims like "for every m and n, …" need one variable fixed while the other is inducted on, and the proof must say which. Inducting on the sum m + n is the standard repair when neither alone works, because both m and n decrease while the sum does.

The Pascal's-rule identity and the binomial theorem both need this, and both appear in the counting lesson.

Six beliefs that produce wrong answers

Each is stated the way it is usually believed, then corrected, then given a witness you can compute.

1. "Induction is circular: you assume what you are proving."

Correction: the hypothesis is P(n) for an arbitrary n, and what you derive is the implication P(n) → P(n+1). The conclusion P(m) comes from the base plus the chain, never from the hypothesis alone.

Witness: with the base deleted, the rule derives nothing. With the step deleted, it derives only P(k).

2. "Checking many cases is induction."

Correction: a finite check is evidence about those cases. The step is what covers the rest, and the step is a proof about a symbol, not about a value.

Witness: 22k + 1 is prime for k = 0, 1, 2, 3, 4 (3, 5, 17, 257, 65537) and composite at k = 5, where it equals 641 × 6700417. Five confirmations, one counterexample, no induction.

3. "Strong induction is a stronger theorem."

Correction: it is the same theorem with a wider hypothesis. Any strong proof reformats as ordinary induction by replacing P(n) with "P holds for everything from k to n".

Witness: the coin claim proved by strong induction is also proved by ordinary induction on the wider predicate, and by least counterexample. Three formats, one argument.

4. "Inductive reasoning and mathematical induction are the same thing."

Correction: inductive reasoning generalises from observed cases and is never certain — that is the General Aptitude sense, and the analytical-aptitude lesson treats it. Mathematical induction is a deduction: its conclusion follows from its premises with no residue of doubt.

Witness: a sequence of six terms determines infinitely many continuations; the seventh term is a guess. An induction proof has exactly one conclusion.

5. "A step that works for n ≥ 2 is fine."

Correction: it is fine only if a base at n = 2 (or above) is proved. A base at n = 1 with a step from n = 2 leaves the first link unproved, and everything above it hangs on nothing.

Witness: the horse argument. Two groups of n horses share n − 1 horses, which is 0 exactly when n = 1, so the step is legal for n ≥ 2 and the case that must be the base, P(2), is the false one.

6. "The loop invariant proves the algorithm correct."

Correction: the invariant proves what it says, at every pass. Correctness needs the invariant and the exit condition, plus the fact that the loop terminates. An invariant that is true but irrelevant — "the array has n entries" — proves nothing at all.

Witness: for insertion sort the useful invariant has two halves, sorted prefix and permutation of the input prefix. Drop the second and you cannot conclude the output is a permutation.

Closely confused pair: the predicate and the statement

P(n) is a sentence with a free n; the theorem is the universally quantified sentence. "The sum of the first n cubes is a perfect square" is a predicate, and it is a different predicate from the identity, and it is weaker — it is true and easier, and proving it does not prove the identity.

When a question asks which predicate to use, it is asking which sentence the step can actually be checked on. The identity's step works because both sides can be rewritten; the weaker predicate's step does not, because "is a perfect square" gives you nothing to add (k+1)³ to.

One-line repair for all six

Write the predicate as a sentence, write the base at the claim's smallest n, write the step's range as an inequality, and check that the two ranges overlap. Four lines, and every belief above dies on one of them.

How induction shows up in the exam

The syllabus does not name induction, so no question is labelled "induction". What the exam does is ask for a result that only an induction establishes, or ask you to pick the correct proof of one. Five shapes cover what I could verify; I found no GATE CSE paper whose official question is itself an induction proof, and I am not going to invent one.

Shape 1 — the closed form of a recurrence

A recurrence is given and one of its values or its asymptotic order is asked. The reliable route is to compute the first few values, guess, then verify by substitution — which is an induction.

Worked on the Examples tab: T(n) = 2T(n/2) + n with T(1) = 0 gives T(n) = n log₂ n, so T(1024) = 10240.

Shape 2 — a count that satisfies a recurrence

"The number of X of size n is f(n). Find f(5)." Catalans, Fibonacci-like counts, and the full-binary-tree counts are all recurrences; the answer is usually a small integer obtained by running the recurrence, and the induction is what justifies the closed form if one is offered.

Full binary trees with 4 internal nodes: Catalan(4) = 14.

Shape 3 — which proof or which predicate

An MSQ gives four statements about an induction and asks which are true. The statements are almost always about the base case, the step's range, or the difference between the four forms — exactly the boundaries this lesson draws.

The dependable move is to compute the truth table at the small values, because a claim's true range is visible there.

Shape 4 — correctness of an algorithm

"Which invariant, together with the exit condition, establishes that this loop sorts the array?" The answer must contain both halves: what is true of the prefix, and that the prefix is the whole array.

Greedy and DP correctness arguments in the algorithms section are the same idea in another costume: an exchange argument is an induction over the choices.

Shape 5 — a bound that is proved by induction

Claims like "for all n ≥ 1, the number of leaves is at least n/2", or a sum bound inside an asymptotic argument, are proved by induction with a base chosen where the inequality first holds. Section 5's asymptotic questions are usually answered by a sum formula, and a sum formula is an induction.

Cross-link: asymptotic complexity and recurrence relations.

The procedure, in the order that avoids the traps

  1. Write the predicate as a sentence. If you cannot read it aloud with a number substituted, it is not a predicate.
  2. Find the claim's smallest n. That is the base case. Not the smallest n you can check.
  3. Compute the small values. The truth table tells you where the claim actually starts, and whether the base needs to move.
  4. Derive the step and find its range. Write the inequality or divisibility condition the step needs, and solve it for n.
  5. Check the overlap. The base must lie inside the step's range, and the chain must reach the claim's largest n — which, for a claim over all n, means the chain must be infinite.
  6. Say which form you used and why: ordinary if the hypothesis at n suffices, strong if the step needs something smaller, structural if the object is recursive.

The four marks that are actually lost

Not the algebra — the algebra is usually fine. What is lost is: no stated predicate; a base case outside the claim; a step quoted for the wrong range; and a conclusion that claims more than was proved, such as "for all n" after a proof about powers of two.

In an MCQ the wrong options are built from exactly these four: the option with the wrong base, the option that concludes the false general claim, the option that calls strong induction stronger, and the option that treats a finite check as a proof.

Original practiceNAT

For how many integers n with 1 ≤ n ≤ 10 is 2n > n2 true?

Answer: 7

The truth values for n = 1 to 10 are true, false, false, false, then true for 5, 6, 7, 8, 9, 10. The three failures are at n = 2 (4 = 4), n = 3 (8 < 9) and n = 4 (16 = 16).

Trap: counting the equality cases as successes gives 9. A strict inequality fails on equality, and this question is built on exactly that.

Induction link: the same table is what tells you the base case for the general claim must be 5, not 1.

Original practiceMCQ

To prove that every amount of 8 rupees or more is a sum of 3 and 5 rupee coins, the correct induction is

  1. Ordinary induction: base 8, step P(n) → P(n+1) for n ≥ 8.
  2. Strong induction: bases 8, 9, 10, and for n ≥ 10 assume P(8), …, P(n) to prove P(n+1).
  3. Strong induction: base 8, and for n ≥ 8 assume P(8), …, P(n) to prove P(n+1).
  4. Ordinary induction on the number of coins used.

Answer: B

The step the arithmetic supports adds a 3 coin, so it moves from n to n+3, equivalently from n−2 to n+1. Three bases, at 8, 9 and 10, are needed because the step cannot reach them, and the hypothesis must cover down to n−2, which is why it is strong induction and why the bound is n ≥ 10.

Why the others fail: A is impossible — 3 is payable and 4 is not, so P(n) → P(n+1) is false at n = 3. C states the step with only base 8, so the amounts 9 and 10 are never reached. D changes the quantity being inducted on and does not prove the claim about amounts.

Original practiceMSQ

Consider the false claim "all horses are the same colour", proved by induction on n with P(n): in every set of n horses, all horses are the same colour. Which statements are true?

  1. The base case P(1) is false.
  2. The inductive step is valid for every n ≥ 2.
  3. The base case that the argument would need is P(2).
  4. The argument shows that induction is an invalid proof method.

Answer: B and C

The step compares the first n horses with the last n; the shared middle has n − 1 horses, computed on the page for every n. That middle is empty exactly when n = 1, so the step is valid from n = 2 and fails only at the link 1 → 2. The case that link would have to start from is P(2), which is the false statement.

Why the others fail: A is wrong — a set of one horse is trivially monochromatic, so P(1) is true. D is wrong — the rule is sound; the proof violates the requirement that the base reach the step's domain.

Closely confused pair: this is not a counterexample to induction, it is a counterexample to "any true base plus any true step".

Original practiceNAT

How many full binary trees are there with exactly 4 internal nodes?

Answer: 14

The count satisfies C(i) = Σa=0..i−1 C(a)·C(i−1−a) with C(0) = 1, which gives 1, 1, 2, 5, 14, 42, 132 — the Catalan numbers. The page generates them by recursion and counts 14 at i = 4, and 197 in total for i = 0 to 6.

Link: each such tree has 5 leaves and 8 edges, by the structural induction on the Examples tab.

Original practiceMCQ

Let T(1) = 0 and T(n) = 2T(n/2) + n for n a power of two. Then T(1024) is

  1. 1024
  2. 10240
  3. 20480
  4. 1048576

Answer: B — 10240

The closed form is T(n) = n log₂ n, verified by substitution: T(2k) = 2T(k) + 2k = 2k log₂k + 2k = 2k log₂(2k). With n = 1024 = 2¹⁰, that is 1024 × 10 = 10240.

Why the others are wrong: A is n log₂ n with log taken as 1; C is the same with an extra factor of 2, the value you get if the base were T(1) = 1 and the leaves were counted twice; D is n², the answer to a different recurrence such as T(n) = 2T(n/2) + n².

Trap: with T(1) = 1 instead of 0, the closed form becomes n log₂ n + n, and T(1024) = 11264. Read the base case before substituting.

Original practiceMCQ

A proof uses base case n = 1 (true) and a step valid for n ≥ 3, to prove a claim stated for all n ≥ 1. Which is the accurate verdict?

  1. The proof is complete, because the base is true and the step is true.
  2. The proof establishes the claim only for n = 1.
  3. The proof establishes the claim for every n ≥ 1, since the step covers all large n.
  4. The proof establishes the claim for every n ≥ 3.

Answer: B

The chain from 1 needs the links 1 → 2 and 2 → 3, and the step is not available at n = 1 or n = 2. Computed on the page: following that step from a base at 1 reaches exactly {1}, while from a base at 5 it reaches 5 to 20.

Why the others are wrong: A ignores the gap. C assumes the step can be applied outside its range. D would be right if the base were at 3 or above — the fault is the base, not the step.

Repair: either prove the missing links by hand, or move the base to the smallest n in the step's range.

Original practiceMCQ

For insertion sort, which pair of facts establishes that the output is a sorted permutation of the input?

  1. The invariant alone: after pass i, the first i entries are sorted.
  2. The invariant alone: after pass i, the first i entries hold the same values as the input's first i entries.
  3. The invariant — the first i entries are sorted and hold the same values as the input's first i — together with the exit condition i = n.
  4. The fact that each pass performs at most i comparisons.

Answer: C

Sortedness comes from the invariant's first half, permutation from its second, and both apply to the whole array only because the loop ends with i = n. That is the standard initialization–maintenance–termination argument, which is an induction over passes.

Why the others fail: A gives sortedness of a prefix, not of the array, and says nothing about values. B gives the right values but not sortedness. D is a cost, not a correctness fact.

Checked on the page: the invariant holds at every index of all 24 orderings of four values, and the final array is sorted in all 24.

Original practiceMCQ

The numbers 22k + 1 are prime for k = 0, 1, 2, 3, 4. What does that establish about the statement "22k + 1 is prime for every k ≥ 0"?

  1. Nothing beyond those five cases, and the statement is in fact false at k = 5.
  2. The statement is true, because five cases with no exception is strong evidence.
  3. The statement is true by induction once the step is verified for k = 4.
  4. Nothing, because the statement is undecidable.

Answer: A

At k = 5 the number is 4294967297, and it equals 641 × 6700417. The page verifies the product and the primality of 641 directly. So the five cases are consistent with the statement and the sixth refutes it.

Why the others fail: B confuses evidence with proof. C confuses a check with a step: verifying k = 4 says nothing about k = 5, because the step would need an argument, not a computation. D is wrong — a single counterexample settles it.

Moral: this is the counterexample to "it held for the first five, so it holds".

Original practiceMSQ

Which of the following are true of mathematical induction as used in this lesson?

  1. It is a form of deductive reasoning.
  2. It can establish a statement about infinitely many natural numbers from finitely many lines of proof.
  3. Strong induction can prove statements that ordinary induction cannot.
  4. The well-ordering principle is equivalent to it.

Answer: A, B and D

A: the conclusion follows from the premises with certainty, which is what deduction means — the contrast is with inductive generalisation in the aptitude sense. B: the step is one universally quantified implication, and it is what covers the infinitely many cases. D: induction, strong induction and well-ordering are provably equivalent, each reformattable as the others.

Why C fails: strong induction assumes more inside the step, but every strong proof reformats as ordinary induction on the wider predicate "P holds from k to n". It is a convenience, not extra power.

Original practiceNAT

A full binary tree has 9 internal nodes. How many leaves does it have?

Answer: 10

By the structural induction, leaves = internal + 1, so 10. The same tree has 19 nodes and 18 edges.

Cross-check without induction: 9 internal nodes have 18 children between them, of which 8 are internal (all but the root), so 10 are leaves. The two routes agree, and the second is a counting argument, not an induction — a useful independent check.

Revision sheet

Everything on this page in the order you would write it in an exam.

The three rules

induction P(k), and for all n >= k: P(n) -> P(n+1) therefore for all m >= k: P(m) strong P(k), and for all n >= k: P(k)..P(n) -> P(n+1) therefore for all m >= k: P(m) well-order every non-empty set of naturals has a least element

All three are equivalent. Induction is easiest when the step follows from P(n) alone; strong when it needs a smaller case; well-ordering when a minimal counterexample is easier to describe than a chain.

The four checks

  1. The predicate is a sentence with n in it.
  2. The base is the claim's smallest n.
  3. The step's range, as an inequality, contains the base.
  4. The chain from the base covers every n the claim names.

Formulas worth knowing

1 + 2 + ... + n = n(n+1)/2 1^3 + ... + n^3 = (n(n+1)/2)^2 1 + 2 + 4 + ... + 2^(n-1) = 2^n - 1 T(n) = 2T(n/2) + n, T(1)=0 => T(n) = n log2 n full binary tree: leaves = internal + 1

Each is proved by the same two-line step: split off the last term, substitute the hypothesis, simplify.

Traps, in the order they bite

Base outside the step's range (2n > n2 with base 1). Equality treated as success under a strict inequality. A step proved only for powers of two, concluded for all n. A finite check offered as a proof. Strong induction called stronger. "Inductive reasoning" confused with induction.

Computed witnesses: base 1 reaches {1}; the Fermat number at k = 5 is 641 × 6700417; the horse argument's middle is empty exactly at n = 1.

Decision procedure for an unfamiliar claim

Compute the first five or six values. If they all satisfy the claim, ask what the step needs — if the answer is "only the previous case", use ordinary induction; if it is "a case well below n", use strong; if the object is defined recursively, use structural induction; if a minimal counterexample is easier to picture, use well-ordering. Then write the four checks above in order, and state the conclusion no more widely than the proof reached.
