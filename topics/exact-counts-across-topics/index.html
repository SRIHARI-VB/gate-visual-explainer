Topic and objective

TOPIC: Exact counts across the syllabus — the four units GATE asks you to count (a comparison, a probe, a block transfer, a multiplication) and the four-step procedure that produces the integer on the answer sheet. This is the connective lesson between Section 5 ("searching, sorting, hashing; asymptotic worst case time and space complexity"), Section 3 (memory hierarchy) and the dynamic-programming and divide-and-conquer items of the same syllabus.

LEARNING OBJECTIVE: For any algorithm already taught in this repository, name the unit being counted, count the units in one level or one partition, multiply by the structure's own identity, and reach the same integer a second way. Count merge sort as 24 units of work and 17 comparisons and say why both are right. Count quicksort's two GATE CSE 2014 Set 1 inputs as 10 and 7. Read floor(lg n) + 1 off a halving and off a doubling loop. Turn a cache miss count into an average access time. Count table cells and table transitions separately.

I read this as the counting discipline rather than as a new algorithm: every algorithm in the syllabus is already taught in its own lesson, and what is missing is the one skill those lessons share — producing an exact integer, and knowing which integer the question wants. The algorithms themselves are not re-taught here; each section links to the lesson that teaches it.

Prerequisites

  • Asymptotic complexity and recurrences — the class-versus-count distinction this lesson depends on throughout.
  • Sorting algorithms — merge sort and quicksort as procedures; this lesson counts them.
  • Binary search and its variants — the halving, which is the level count here.
  • Hashing — chaining and open addressing; this lesson counts probes in a stated table.
  • Memory hierarchy and cache — the hit time, miss rate and miss penalty whose arithmetic is used on the cache scene.
  • Dynamic programming — the tables whose cells and transitions are counted.
  • Divide and conquer — the recursion tree and Karatsuba, counted here in a different unit.

Six sentences worth keeping

  • Unit first. Work, comparisons, probes and transfers are four different questions about the same run.
  • Levels. Count one level, then multiply by the number of levels — never guess the total first.
  • Pairs. n(n−1)/2 is the number of element pairs, which is why it is quicksort's worst case.
  • Plus one. lg n counts halvings; the test on the last element is one more.
  • Shape. Cells come from the table's shape, transitions from what each cell reads.
  • Two routes. A closed form and an enumeration rarely agree by accident; one route can be wrong.

1. Intuition — the shop that counts different things

A shopkeeper is asked how busy the day was. She can answer in customers served, in items sold, in deliveries received, or in money taken. All four are true, none of them is the same number, and the useful answer depends on the question. Educational interpretation An algorithm is the same shop. A sort serves elements, compares keys, and moves blocks. Which one you count is decided by the question, not by the algorithm.

The mistake that costs marks is answering the customer question with the money figure — reporting merge sort's 24 units of level work when the paper asked for its 17 comparisons. Both numbers are correct; only one is an answer.

2. The four units, formally

A comparison is one evaluation of a predicate on two keys, as in "is L[i] smaller than R[j]". A probe is one table slot examined while looking for a key. A block transfer is one block moved between main memory and the cache. A multiplication is one scalar product of two digits or machine words.

Mathematical derivation The four are not interchangeable because they do not move together: merge sort's work is fixed at n·ceil(lg n) while its comparisons vary from 12 to 17 at n = 8. A quantity that varies while the other is fixed cannot be the same quantity.

3. The procedure, in four steps

Step 1 — name the unit. Write down what one operation is. Step 2 — count one level. How many units does one level, one partition, one call, one access cost. Step 3 — use the identity. Multiply by the number of levels, partitions or pairs, using the structure's own identity rather than a remembered formula. Step 4 — a second route. Reach the same integer by a closed form, an enumeration, or a simulation.

Educational interpretation Step 4 is what turns a plausible answer into a checked one. Two routes that share an assumption are one route; the second must count something different or derive it differently.

4. Why the identity matters more than the formula

Each structure supplies one identity, and every count in this lesson is that identity applied: a partition compares the pivot with each other element, so n − 1; a halving reaches one element in floor(lg n) steps and then tests it, so floor(lg n) + 1; a worst-case partition peels one element per level, so the counts are n − 1, n − 2, …, 1, whose sum is n(n−1)/2.

Mathematical derivation Summing 1 + 2 + … + (n−1) gives n(n−1)/2 by the standard pairing argument. At n = 8 that is 28, which the page reaches both by the sum and by running quicksort on sorted and on reverse-sorted input.

5. The class is still needed

An exact count is not a replacement for the asymptotic class. The class says how the count behaves as n grows, which is what makes one algorithm preferable to another; the count says what happens on the input in front of you. Both are in the syllabus, and they answer different questions.

count(n) is Theta(f(n))The class bounds the count for large n; it does not give the count for the n in the question. 17 and 24 are both Theta(n log n) at n = 8.

6. The identity table this lesson uses

Merge
m + n − 1 comparisons at most; work = n per level

Partition
n − 1 comparisons, exactly, per range

Halving
floor(lg n) + 1 tests to reach one element

Chain
p probes for position p; one more for a miss

Mathematical derivation Each line is an argument, not a convention. The merge bound holds because one list is exhausted before every pair is tested, so at least one comparison is saved — and the page enumerates every interleaving up to m = n = 4 to confirm both ends of the bound are attained.

7. Two counting conventions that decide answers

The exit test. In while (j <= n) j = j * 2 the comparison that fails is made by the loop condition but not "during the execution of the loop". GATE CSE 2007 Q15 excludes it, which makes the answer floor(lg n) + 1.

The terminating null. A chained search that fails reads every key in the chain and then the null, so it costs one more probe than the chain length. The page's table shows 2.43 probes per home slot against a mean chain length of 1.43.

8. Where an estimate stops being an answer

Uniform hashing gives 1/(1−alpha) for an unsuccessful search and 1 + alpha/2 for a successful one under chaining. Those are averages over random hash functions. A question that states a table and an insertion order wants the table simulated, not the formula quoted.

Mathematical derivation This page's seven-slot table gives 1.4 successful probes against a predicted 1.71 and 2.43 unsuccessful against a predicted 1.43. Being on opposite sides of the estimate is the point: the estimate is a mean over hash functions, the table is one draw.

9. Assumptions each count rests on

  • Merge sort's worst-case formula assumes the halving split and a merge that stops when one list is empty.
  • Quicksort's n(n−1)/2 assumes one comparison per element per partition and a pivot rule that can be worst-case.
  • floor(lg n) + 1 assumes the range is halved by index, not by value.
  • The cache count assumes block size four words and the stated associativity.
  • 3k assumes the three-multiplication form of Karatsuba and counts multiplications only.

Example 1 — merge sort at n = 8, two units

Work: eight elements move at each of three levels, so 8 × 3 = 24. Comparisons: the model sorts all 40,320 orderings and records 12 at best, 15.73 on average, 17 at worst.

Mathematical derivation The two numbers differ because a merge stops comparing as soon as one list empties; the remaining elements are copied with no test. The gap is at least one comparison per merge, and there are seven merges: 24 − 7 = 17.

Example 2 — the merge-sort closed form

At n = 8: 8 × ceil(lg 8) − 2ceil(lg 8) + 1 = 24 − 8 + 1 = 17. At n = 5: 5 × 3 − 8 + 1 = 8, and the enumeration also gives 8.

Mathematical derivation The formula is checked against the enumerated worst case at every n from 1 to 8 — 0, 1, 3, 5, 8, 11, 14, 17 both ways — so the formula is not being trusted, it is being verified.

Example 3 — quicksort on the 2014 inputs

On {1,2,3,4,5} with the first element as pivot: partitions of size 5, 4, 3, 2 cost 4, 3, 2, 1 comparisons, total 10. On {4,1,5,3,2}: the first partition costs 4 and the left part {1,3,2} costs 2, after which both sides are single elements, total 6.

Mathematical derivation Both inputs cost 4 in the first partition, so the whole difference comes from the recursion — 6 more comparisons for the sorted input, 2 for the other. A count that stops after one partition cannot see it.

Example 4 — binary search at 1024, and at 1000

1024 halves to 512, 256, 128, 64, 32, 16, 8, 4, 2, 1 — ten halvings — and the remaining element still needs one test: 11. At n = 1000, floor(lg 1000) = 9, so 10.

Mathematical derivation 210 = 1024 and 29 = 512, so 1000 sits between nine and ten halvings; the floor takes nine and the plus one gives ten. The model runs every size to 64 and every target, successful and unsuccessful, with no exception.

Example 5 — sixteen accesses, two orders

A 4 × 4 array of words, block size four words (one row), a two-block cache. Row-major: words 0–3 are one block, so M H H H, four times — 4 misses, 12 hits. Column-major: 0, 4, 8, 12, then 1, 5, 9, 13 — every access a new block after the second, so 16 misses.

Mathematical derivation Average access time is hit time plus miss rate times miss penalty: 1 + 0.25 × 40 = 11 row-major, 1 + 1.00 × 40 = 41 column-major. The same array, the same cache, a factor of 3.7 in time.

Example 6 — matrix chain at n = 5

Cells: the subproblems are the ranges i..j with i < j, which is 5 × 4 / 2 = 10. Transitions: a chain of length L has 5 − L + 1 positions and L − 1 break points, so 4 + 6 + 6 + 4 = 20.

Mathematical derivation The total is n(n²−1)/6, which the model checks at every n from 2 to 10: at n = 10 that is 45 cells and 165 transitions. Quadratic cells, cubic transitions — and the paper asks for one, not both.

Boundaries, counterexamples and the condition each one violates

Each card names a case where a remembered formula gives the wrong integer, and the condition that the case breaks.

n = 1 and n = 2

Merge sort at n = 1 does 0 comparisons, and the closed form gives 1 × 0 − 1 + 1 = 0, so it survives. Binary search at n = 1 does 1 comparison, and floor(lg 1) + 1 = 1. Quicksort at n = 2 does 1 comparison and n(n−1)/2 = 1.

Condition at risk: ceil(lg n) and floor(lg n) agree only at n = 1, so a single case cannot distinguish the candidate formulas. Always test a second size.

Powers of two are the trap, not the rule

At n = 16 the doubling loop makes 5 comparisons and both floor(lg n) + 1 and ceil(lg n) + 1 give 5. At n = 15 the count is 4, floor(lg n) + 1 gives 4, and ceil(lg n) + 1 gives 5.

Condition violated: the two formulas coincide exactly when n is a power of two, so a power-of-two test case cannot tell them apart — which is why GATE CSE 2007 Q15 needs n = 15 to settle it.

Sorted input is the best case for one sort and the worst for another

Merge sort on sorted input does 12 comparisons at n = 8 — its minimum. Quicksort with a first-element pivot on sorted input does 28 — its maximum.

Condition violated: "sorted input is easy" is a claim about a particular algorithm, not about sorting. Merge sort's structure ignores order; quicksort's pivot choice is defeated by it.

A stated table is not a random hash function

The seven-slot table of this lesson gives 1.4 successful and 2.43 unsuccessful probes. Uniform hashing predicts 1.71 and 1.43.

Condition violated: the formulas assume every probe sequence is equally likely. Ten keys in seven slots is one draw, and it lands on both sides of the prediction at once.

Block size changes the transfer count by its own factor

A sequential scan of 1024 words costs 1024 transfers with block size one, 256 with block size four, and 64 with block size sixteen. The word count never changes.

Condition at risk: a transfer count is meaningless without the block size. Any answer that omits it is an answer to a different question.

alpha above one is legal in one scheme and impossible in the other

Chaining allows alpha = 10/7 = 1.43, as in this lesson's table. Open addressing cannot exceed alpha = 1, and 1/(1−alpha) is undefined at alpha = 1.

Condition violated: the formula 1/(1−alpha) belongs to open addressing. Applying it to a chained table with alpha = 1.43 gives a negative number, which is the fastest possible signal that the scheme was misread.

Two counts, one algorithm, and no contradiction

At n = 1024, merge sort does 10 240 units of work and at most 9 217 comparisons; quicksort's worst case is 523 776 comparisons; binary search is 11; Karatsuba is 59 049 multiplications. All five numbers describe work on the same size of input.

Condition at risk: the instinct that two different numbers for "the same algorithm" means one is wrong. They are different quantities, and the question's wording is what selects between them.

Five wrong beliefs, each with the smallest example that kills it

Each card gives the belief as a learner states it, why it tempts, why it is wrong, the minimal counterexample, and the correct rule.

1. "n log n comparisons"

Why it tempts: the complexity class of merge sort is n log n and the two words get merged in memory. Why it is wrong: n log n counts units of work — element placements — not comparisons.

Minimal counterexample: n = 8, where the work is 24 and the worst-case comparison count is 17. Correct rule: comparisons at most n·ceil(lg n) − 2ceil(lg n) + 1.

Verified fact The formula and the enumeration agree at every n from 1 to 8 on this page.

2. "The root is level 1, so there are log n + 1 levels"

Why it tempts: numbering from one is natural when counting things. Why it is wrong: the level count multiplies the per-level work, so an off-by-one becomes an error of one whole level.

Minimal counterexample: merge sort at n = 8 has three levels below the root, not four; 8 × 4 = 32 is not the work. Correct rule: count the levels below the root, which is log2 8 = 3.

Mathematical derivation The tree is built in code: 1 + 2 + 4 + 8 nodes with the last level holding the leaves, so the depth is 3 and the node count is 15 = 2·8 − 1.

3. "Binary search takes log n comparisons"

Why it tempts: log n is the class, and the halving is visible. Why it is wrong: the halvings reach a single element, and that element still has to be tested.

Minimal counterexample: n = 1024, where 10 halvings and 11 comparisons differ. Correct rule: floor(lg n) + 1, verified for every n to 64 and every target.

Verified fact A doubling loop shows the same count: GATE CSE 2007 Q15's answer is floor(lg n) + 1.

4. "The miss penalty multiplies the number of misses"

Why it tempts: the total time "should" grow with the number of misses, and it does — but the formula uses a rate. Why it is wrong: average access time is per access, so the penalty is multiplied by the miss rate, not the miss count.

Minimal counterexample: the row-major walk has 4 misses out of 16 accesses. Multiplying by 4 gives 160 cycles; the formula gives 1 + 0.25 × 40 = 11. Correct rule: hit time + miss rate × miss penalty.

Mathematical derivation 16 accesses at 11 cycles each is 176 cycles, which is 16 hits at 1 plus 4 misses at 40 — the two routes agree, which is how the rate form is justified.

5. "alpha is the expected number of probes"

Why it tempts: alpha is the mean chain length, and a successful search in a chain of mean length alpha feels like alpha probes. Why it is wrong: a search must also read the slot itself and, when it fails, the null.

Minimal counterexample: this lesson's table: alpha = 1.43, successful search 1.4 probes, unsuccessful 2.43 probes. Correct rule: under chaining, about 1 + alpha/2 successful and alpha unsuccessful — and simulate a stated table.

Community observation GATE DS&AI 2024 Q11 turns on exactly this distinction: it gives the unsuccessful-search estimate and asks for the insertion cost, which is the same figure.

How this topic is examined

The categories that genuinely apply are C (calculation), D (construction of a count from a structure), E (counterexample reasoning against a wrong formula), F (multiple conditions) and G (misconception trap). A (direct definition) applies only to the definitions of the units, and H (multi-step reasoning) appears whenever a count has to be turned into a time.

C — Calculation

Reasoning path: identify the unit, count one level or partition, apply the identity, then check the arithmetic against a second route.

Common wrong approach: quoting n log n and substituting. It gives a plausible number that is the wrong quantity.

D — Construction from a structure

Reasoning path: read the count off the object — the tree's levels and leaves, the table's cells and transitions, the cache's blocks, the chain's positions.

Common wrong approach: counting a table's cells and calling them transitions, or counting a tree's nodes and calling them leaves.

E — Counterexample against a formula

Reasoning path: find the size at which two candidate formulas disagree. For floor against ceil it is any n that is not a power of two; n = 15 separates them.

Common wrong approach: testing at n = 16, where both formulas give 5, and concluding they are the same.

F — Multiple conditions in one item

Reasoning path: a hashing item can fix the table, the hash function, the insertion order and the collision scheme at once. Every one of those is part of the count.

Common wrong approach: using the estimate after the question has stated the table, or applying a chaining formula to open addressing.

G — Misconception trap

Reasoning path: decide what is being counted before choosing any formula. The wording "comparisons", "probes", "transfers" and "multiplications" are four different questions.

Common wrong approach: answering 24 when the paper asked for comparisons, because 24 is the number the course spent the most time deriving.

The solving procedure, in five steps

  1. Underline the unit in the question. If none is named, the unit is "operations" and you must say which.
  2. Underline the input. A stated array, table or sequence means simulate; a symbolic n means use an identity.
  3. Count one unit of structure — one level, one partition, one access, one cell.
  4. Multiply with the structure's identity and write the arithmetic out, so an off-by-one is visible.
  5. Check with a second route — a closed form, an enumeration, or a small case you can draw.

MCQGATE CSE 2007 Q15

Consider the following segment of C code:

int j, n; j = 1; while (j <= n) j = j * 2;

The number of comparisons made in the execution of the loop for any n > 0 is:

  1. ceil(log2 n) + 1
  2. n
  3. ceil(log2 n)
  4. floor(log2 n) + 1

Answer: D — floor(log2 n) + 1

j takes the values 1, 2, 4, … up to the largest power of two not exceeding n, and each of those is one comparison made while the loop runs. That is floor(log2 n) + 1 comparisons. This page executes the loop for every n from 1 to 64 and the count matches the formula at every size.

Why A fails. At n = 15 the loop compares four times but ceil(log2 15) + 1 = 5. Why B fails. n comparisons is a linear scan. Why C fails. At n = 8 the loop compares four times, not three.

The trap. The exit comparison. Counted, the answer would be floor(log2 n) + 2, which is not offered — so the paper is counting only the comparisons made while the body executes, and the answer is D. A and D agree at every power of two, so a power-of-two test case cannot choose between them.

MCQGATE CSE 2014 Set 1

Let P be a quicksort program to sort numbers in ascending order using the first element as pivot. Let t1 and t2 be the number of comparisons made by P for the inputs {1, 2, 3, 4, 5} and {4, 1, 5, 3, 2} respectively. Which one of the following holds?

  1. t1 = 5
  2. t1 < t2
  3. t1 > t2
  4. t1 = t2

Answer: C — t1 > t2, with t1 = 10 and t2 = 6

On {1,2,3,4,5} each partition peels one element: 4 + 3 + 2 + 1 = 10. On {4,1,5,3,2} the first partition costs 4 and the left part {1,3,2} costs 2, after which both sides are singletons, giving 6. This page runs both inputs through one partition function and gets 10 and 6.

Why A fails. 5 is the number of elements, not the comparisons. Why B fails. It reverses the comparison: the sorted input is the worst case for a first-element pivot. Why D fails. Both inputs cost 4 in the first partition, which is exactly why the totals look equal if you stop there.

The trap. Counting one partition. The difference of 3 is entirely in the recursion, so only a total count sees it.

MCQGATE DS&AI 2024 Q11

Consider performing uniform hashing on an open address hash table with load factor alpha = n/m < 1, where n elements are stored in the table with m slots. The expected number of probes in an unsuccessful search is at most 1/(1 − alpha). Inserting an element in this hash table requires at most ______ probes, on average.

  1. ln(1/(1 − alpha))
  2. 1/(1 − alpha)
  3. 1 + alpha/2
  4. 1/(1 + alpha)

Answer: B — 1/(1 − alpha)

An insertion probes until it finds an empty slot, which is the same walk as an unsuccessful search for the key being inserted: it never stops at the key, because the key is not there yet. So the expected count is the figure the question gives, 1/(1 − alpha). This page computes it as 2 at alpha = 0.5 and 10 at alpha = 0.9.

Why A fails. It is the expected probes for a successful search under uniform hashing, a smaller quantity. Why C fails. That is the chaining estimate for a successful search. Why D fails. It decreases as the table fills, which reverses the behaviour.

Note on provenance. This item is from the GATE Data Science and Artificial Intelligence 2024 paper, not the CS paper. The hashing syllabus item is common to both, so the reasoning transfers; the year and paper are named so you can check it.

NATOriginal practice question

Written for this lesson. Merge sort with the halving split is run on a worst-case input of 16 distinct elements. What is the exact number of element comparisons in the worst case?

Answer: 49

n·ceil(lg n) − 2ceil(lg n) + 1 = 16 × 4 − 16 + 1 = 49. The other route: 64 units of work (16 elements at each of 4 levels) minus 15 merges, since each merge saves at least one comparison and a worst-case merge saves exactly one: 64 − 15 = 49.

Why 64 appears. That is the unit-of-work count, not comparisons. Why 48 appears. Subtracting 16 merges instead of 15 — there are 15 internal nodes in a tree with 16 leaves.

The trap. The gap between work and comparisons is the number of merges, which is n − 1.

NATOriginal practice question

Written for this lesson. Binary search is run on a sorted array of 1000 distinct elements, and the target is present. What is the worst-case number of element comparisons?

Answer: 10

floor(lg 1000) + 1 = 9 + 1 = 10, since 29 = 512 < 1000 < 1024 = 210. The model's staircase for every size to 64 confirms the formula, and the same formula gives 11 at n = 1024.

Why 9 appears. That is floor(lg n), the number of halvings, without the final test. Why 11 appears. That is the answer for 1024, where ten halvings are needed.

The trap. Treating 1000 as "about 1024". The floor is on 1000, not on the next power of two.

NATOriginal practice question

Written for this lesson. A 64 × 64 array of 4-byte integers is scanned in row-major order. The cache block is 16 bytes and nothing is in the cache at the start. How many block transfers does the scan cause?

Answer: 1024

A 16-byte block holds four integers, and the array holds 4096 integers, so the scan touches 4096 / 4 = 1024 distinct blocks. Row-major order uses every word of a block before moving on, so each block is fetched exactly once: 1024 transfers for 4096 accesses.

Why 4096 appears. That is the number of accesses, not transfers. Why 2048 appears. That is the block count for an 8-byte block, or for a 16-byte block holding two integers.

The trap. Dividing by the block size in bytes instead of in words, or forgetting that a block transfer moves the whole block.

NATOriginal practice question

Written for this lesson. Matrix-chain multiplication is solved by dynamic programming for a product of 6 matrices. How many subproblems (cells of the form i..j with i < j) does the table hold?

Answer: 15

The subproblems are the ranges i..j with i < j, and choosing two boundaries out of six gives 6 × 5 / 2 = 15. The model checks n(n−1)/2 at every n from 2 to 10: 1, 3, 6, 10, 15, 21, 28, 36, 45.

Why 36 appears. That is n² = 36 cells including the diagonal, which are not subproblems of length two or more. Why 35 appears. That is the number of split points, n(n²−1)/6 — a different count.

The trap. The cells and the transitions are two numbers, and a question that names one is not asking for the other.

MSQOriginal practice question

Written for this lesson. Merge sort with the halving split is run on eight distinct elements. Which of the following statements are true?

  1. The total number of element placements is 24.
  2. The worst-case comparison count is 17.
  3. On already-sorted input the comparison count is 17.
  4. The number of internal merges is 7.

Answer: A, B and D

A: eight elements at each of three levels is 24 placements. B: the closed form gives 24 − 8 + 1 = 17, and the enumeration over all 40,320 orderings attains 17. D: a tree with eight leaves has seven internal nodes, one per merge.

Why C fails. On sorted input the count is 12, the minimum — each merge of two sorted halves compares only the smaller elements and then copies the rest. 17 is the maximum, reached on interleaved inputs.

The trap. C reads as true because 17 is the number the lesson quotes most. A maximum and a value on one particular input are different claims.

Definitions, one line each

  • Comparison — one predicate evaluated on two keys.
  • Probe — one hash-table slot examined.
  • Block transfer — one block moved between memory and cache.
  • Multiplication — one scalar product.
  • Work — element placements; for merge sort, n per level.
  • alpha — keys divided by slots.
  • AMAT — hit time plus miss rate times miss penalty.

Formulas, with the condition each needs

  • Merge sort comparisons, worst: n·ceil(lg n) − 2ceil(lg n) + 1 — halving split, comparison stops when one list empties.
  • Merge work: n per level, log2 n levels.
  • Quicksort: n − 1 per partition; worst n(n−1)/2; average 2(n+1)Hn − 4n.
  • Binary search: floor(lg n) + 1, for successful and unsuccessful alike.
  • Chaining: about 1 + alpha/2 successful, alpha unsuccessful — random hash functions only.
  • Open addressing: 1/(1 − alpha) for an unsuccessful search and for an insertion.
  • Matrix chain: n(n−1)/2 cells, n(n²−1)/6 transitions.
  • Karatsuba: 3k multiplications, exponent log2 3 = 1.585.

Decision procedure

  1. What unit does the question name?
  2. Is an input stated? If yes, simulate; if not, use an identity.
  3. Count one level, partition, access or cell.
  4. Multiply by the identity and write the arithmetic.
  5. Check with a second route — closed form, enumeration, or a tiny case.
  6. Does the answer need the class as well? Say both, separately.

Traps, with the number that defuses each

  • Work for comparisons → 24 against 17.
  • Root counted as a level → 4 against 3.
  • lg n without the plus one → 10 against 11 at 1024.
  • Miss count for miss rate → 160 against 11.
  • Estimate for a stated table → 1.43 against 2.43.
  • Cells for transitions → 10 against 20 at n = 5.
  • floor against ceil → n = 15 separates them.

What is computed rather than cited

The page sorts all 40,320 orderings of eight elements by merge sort and by quicksort, recording min, max and average comparisons at every n from 1 to 8, and compares the extremes with n·ceil(lg n) − 2ceil(lg n) + 1, n(n−1)/2 and 2(n+1)Hn − 4n.
