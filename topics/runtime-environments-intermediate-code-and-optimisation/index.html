Topic and objective

TOPIC: The compiler back end — runtime environments, intermediate code generation, local optimisation and the data-flow analyses (constant propagation, liveness, common subexpression elimination). Section 7 of the GATE 2027 CS syllabus, Compiler Design.

LEARNING OBJECTIVE: Name every field of an activation record, size it and offset it, and tell the control link from the access link. Read a call sequence as a preorder and a return sequence as a postorder traversal of the activation tree. Resolve a free name by static or dynamic scoping and get both printed values right. Simulate call by value, by reference and by value-result, and say which one lets a swap work. Write an expression as three-address code, then as quadruples and as triples. Apply the three leader rules to a sequence of statements and partition it into basic blocks. Build the DAG of a basic block by value numbering and count its nodes as leaves plus distinct operators. Write use and def sets, iterate the two liveness equations backwards to a fixed point, and read the register count off the largest live set. Contrast liveness with available expressions on direction, meet operator, boundary and kill.

I read this syllabus clause as four procedures and one idea. The procedures are: size the record, count the leaders, count the nodes, iterate the equations. The idea is that every fact a back end uses is computed from the program's own structure — and the page computes all four rather than quoting them.

The five ideas, in one line each

  • A frame is per call, not per procedure. Its size is the sum of its fields, and its two links point at two different things.
  • Calls are preorder, returns are postorder. That single sentence answers the activation-tree questions.
  • Three leader rules give the blocks. First statement, every jump target, every statement after a jump.
  • A DAG node is a value, not a statement. Count leaves plus distinct operators, and a second definition becomes a label.
  • Liveness is backwards and unions; availability is forwards and intersects. Get the direction and the meet right and the equations write themselves.

Level 1 — Intuition, before any notation

A compiler is a translator with a memory problem. The front end reads your program and writes down what it means; the back end has to run it, and running it means keeping track of which call is in progress, which value lives where, and which of the many possible rewrites of the program are actually safe. This topic is that second half.

Three pictures carry the whole lesson. A stack of trays: every call puts a tray on top and every return takes one off, so the last call is the first to finish. A shopping list: the intermediate code is a list of very small steps, one operation per line, which is what makes the program easy to rewrite. And a spreadsheet of facts: for every point in the program, the compiler writes down what is true there — which variables still matter, which expressions are already computed — and those facts are what license the rewrites.

Level 2 — The formal definitions

Activation record. The block of storage holding one activation of a procedure: actual parameters, the return address, the control link, the access link, the return value, the locals and the temporaries.

Control link. A pointer to the record of the caller. The chain of control links is the dynamic chain.

Access link. A pointer to the record of the lexically enclosing procedure. The chain of access links is the static chain.

Three-address code. A statement form in which the right-hand side has at most one operator, so each statement is a single step.

Basic block. A maximal straight-line sequence: control enters only at the first statement and leaves only after the last.

DAG of a block. A directed acyclic graph with one leaf per distinct initial value or constant and one interior node per distinct operator applied to two nodes.

Live variable. A variable is live at a point when some path from that point reaches a use of it with no redefinition of it in between.

Level 3 — What each analysis actually assumes

Liveness. A may analysis: one path to a use is enough, so the meet at a join is union, the direction is backwards, and the boundary is the empty set at the exit.

Available expressions. A must analysis: every path must compute the expression and leave its operands alone, so the meet is intersection, the direction is forwards, and the boundary at the exit is the set of all expressions.

Value numbering. Assumes the expression's operands have the values their current names denote; a redefinition makes a different expression, which is exactly what the numbering must respect.

Strength reduction. Assumes the arithmetic does not overflow, or that the target's shift and multiply agree on overflow. Without that assumption the rewrite can change the answer.

Level 4 — Four worked examples, one line each

Record. Eleven four-byte slots — three parameters, return address, two links, return value, two locals, two temporaries — make a 44-byte frame with eleven distinct offsets.

Recursion. fact of three leaves five frames on the stack at the deepest point, and the values come back 1, 1, 2, 6.

Blocks. Seventeen statements with three jump targets and two statements after a jump give six leaders and six blocks of sizes 1, 1, 7, 2, 1, 5.

DAG. Five statements, three leaves (b, c and the constant 1) and three operator nodes, so six nodes, and two statements become labels.

Level 5 — Boundaries and constraints

Every mechanism here has a condition, and the paper builds questions by stepping just outside it. The stack discipline for activation records assumes calls nest properly, which is why a language that lets a function return a function cannot use a pure stack: the returned function outlives the frame that created it, so its environment must be heap-allocated. A DAG assumes the block has no control flow inside it, which is why it is a local analysis and why global common subexpression elimination needs available expressions instead. Value numbering assumes the operators are the ones the machine will actually compute, so a DAG drawn with algebraic identities applied can differ from one drawn without them. Liveness assumes the flow graph is the whole program region under analysis, so a variable read by a callee is live unless the analysis models calls.

A useful habit: before using any analysis, say its direction, its meet operator and its boundary out loud. Three sentences, and most of the marks in this topic are decided by them.

Level 6 — The counterexample to carry into the exam

Take the flow graph a = 0; b = a + 1; c = c + b; a = b * 2; if a < N goto the second statement; return c. The first block computes nothing that involves the loop, so it is tempting to think a single backward pass settles it. It does not: after one pass the sets at the header are still empty, and the analysis reports that nothing is live there, which is false.

Mathematical derivation The page checks this directly — it re-runs the equations on the result of the first round and shows that they move. A solution that is not a fixed point is not a solution, and that is the single most common way a hand-computed liveness answer goes wrong.

Levels 7 and 8 — How it is tested, and where to practise

The count. A numerical answer: the number of basic blocks, the number of DAG nodes, the number of registers, the number of live variables.

The trace. A short program and a scoping or parameter rule, asking for the printed values.

The statement set. A multiple-select item on what static allocation permits, or on which analysis drives which optimisation.

The table. A flow graph with a figure, asking for the live sets at the exit of each block. Practice is the Practice tab: twelve items, answers hidden until you ask, each with the reason the wrong options are wrong.

Level 9 — Consolidation

Four procedures cover this topic. Size the record by adding its fields, and follow the access link for meaning and the control link for history. Count the leaders — first, target, after a jump — and the block count follows. Count the nodes as leaves plus distinct operators, and a repeated definition becomes a label rather than a node. Iterate the equations from the boundary until a round changes nothing, then read the answer off the sets. None of these requires memorising a number, and every one of them is checked on this page.

The activation tree read two ways — GATE CSE 2021, Set 1 (1-mark MCQ)

PYQ Consider the statements. S1: the sequence of procedure calls corresponds to a preorder traversal of the activation tree. S2: the sequence of procedure returns corresponds to a postorder traversal of the activation tree. Which option is correct?

Step 1. An activation tree has one node per activation, and a caller is the parent of its callee. A node is visited when its procedure is entered.

Step 2. A parent is entered before any child, and every node in the left subtree is entered before the right subtree is reached, so the entry order is exactly a preorder walk. S1 is true.

Step 3. A procedure returns only after every call it made has returned, so a node is visited at return after all of its descendants. That is a postorder walk. S2 is true.

Answer: both S1 and S2. The page builds the tree for fact of three and checks both claims against the tree it actually built: the entry order is main, fact(3), fact(2), fact(1), fact(0), and the return order is exactly its reverse.

Reference parameters under dynamic scoping — GATE CSE 2016, Set 1 (2-mark MCQ)

PYQ What is printed when parameters are passed by reference and dynamic scoping is assumed? a = 3;
void n(x) { x = x * a; print(x); }
void m(y) { a = 1; a = y - a; n(a); print(a); }
void main() { m(a); }

Step 1. main passes the global a, which is 3, so y aliases it. Inside m, a = 1 declares a local a and sets it to 1.

Step 2. a = y - a is 3 − 1 = 2, in m's local a. Then n(a) passes that local a by reference, so x and m's a are one cell.

Step 3. Under dynamic scoping, n's free a resolves in the newest active frame that has one, which is m, where a is 2. So x = 2 × 2 = 4, printed, and m's a becomes 4, printed. Answer: 4, 4. The page runs the same program under both scoping rules: static gives 6, 6 and dynamic gives 4, 4.

What static allocation forbids — GATE CSE 2002 (1 mark)

PYQ In the C language, which of these is true? (1) at most one activation record exists between the current one and main; (2) the number of activation records between the current one and main depends on the calling sequence; (3) the visibility of global variables depends on the calling sequence; (4) recursion requires the recursive function's record to be saved on a different stack.

(1) False. Every call adds a record, and C allows nested calls, so many records can sit between the current one and main.

(2) True. The number of live records is exactly the depth of the current call chain.

(3) False — C is statically scoped, so a global is visible wherever it is not shadowed, whatever the call order. (4) False — a recursive call and an ordinary call are identical to the compiler; both use the same stack. Answer: statement 2 only.

Which statement about optimisation is false — GATE CSE 2014, Set 1 (1-mark MCQ)

PYQ Which one is FALSE? (A) a basic block is a sequence of instructions where control enters at the beginning and exits at the end; (B) available expression analysis can be used for common subexpression elimination; (C) live variable analysis can be used for dead code elimination; (D) x = 4 * 5 becoming x = 20 is an example of common subexpression elimination.

(A) is the definition of a basic block. (B) is the standard use of available expressions: if the expression is available, reuse it. (C) is the standard use of liveness: an assignment to a variable not live afterwards is dead.

(D) is false. Evaluating arithmetic on constants at compile time is constant folding. Common subexpression elimination reuses an expression that was already computed elsewhere in the program. Answer: D.

Counting the nodes of a DAG — GATE CSE 2021, Set 1 (2-mark NAT)

PYQ The segment a = b + c; e = a + 1; d = b + c; f = d + 1; g = e + f; is represented internally as a directed acyclic graph. The number of nodes in the DAG is ______.

Step 1. Leaves are the distinct initial values and constants: b, c and the constant 1. That is three.

Step 2. Interior nodes are the distinct operators. b + c is one. (b + c) + 1 is two. The last statement adds the second node to itself, which is three.

Step 3. Statements three and four recompute expressions that already exist, so d and f join the labels of nodes one and two instead of creating nodes. Answer: 6. The page builds this DAG by value numbering, checks the count is three leaves plus three operators, and checks the DAG computes the same g as the five statements on four inputs.

Two statements in a block — GATE CSE 2021, Set 2 (2-mark MCQ)

PYQ For a statement S, USE(S) is the set of variables used in S, IN(S) the set live at its entry and OUT(S) the set live at its exit. A basic block consists of S1 followed by S2. Which is correct?

Step 1. S2 is the only successor of S1 inside the block, so everything live at the exit of S1 is exactly what is live at the entry of S2.

Step 2. That is the definition of OUT at a block boundary: the union of the successors' IN, and here there is one successor.

Answer: OUT(S1) = IN(S2). The other options mix a variable's own use into its exit set, which is the IN equation, not the OUT one. Confusing the two is what the question is for.

Counting basic blocks — GATE CSE 2025, Set 1 (2-mark NAT)

PYQ The sequence runs from address 1001 to 1017: initialisations, a loop from 1003 to 1009 jumping back to 1003, an increment and a loop from 1002 jumping back to 1002, then a second loop from 1013 to 1017 jumping back to 1013. The number of basic blocks is ______.

Step 1. Leaders: 1001 is the first statement. Jump targets are 1003, 1002 and 1013.

Step 2. Statements after a jump are 1010 (after the jump at 1009) and 1012 (after the jump at 1011).

Step 3. Six leaders, and no two are adjacent, so six blocks, holding 1, 1, 7, 2, 1 and 5 statements, which add to 17. Answer: 6. The page computes the leaders from the jump structure and then checks that the partition covers every statement exactly once and that no block is entered in the middle.

Why intermediate code exists at all — GATE CSE 2014, Set 3 (1-mark MCQ)

PYQ One purpose of using intermediate code in compilers is to: (A) make parsing and semantic analysis simpler; (B) improve error recovery and reporting; (C) increase the chances of reusing the machine-independent code optimiser in other compilers; (D) improve register allocation.

(A) and (B) are wrong because parsing, semantic analysis and error reporting all happen before intermediate code exists.

(D) is wrong because register allocation is machine-dependent: registers belong to the target, and the intermediate code knows nothing about them. Answer: C. Write the optimiser once against the intermediate code and only the back end changes when you retarget.

One program, four answers — the same 2016 question under the other rules

The 2016 program is worth more than one mark, because changing the scoping rule and the parameter mechanism gives four different pairs, and only two of them are answers to questions the paper has asked.

Static scoping, by reference. n's a is the global 3, so x = 2 × 3 = 6, and because x aliases m's local a, m prints 6. Pair: 6, 6.

Dynamic scoping, by reference. n's a is m's 2, so x = 2 × 2 = 4, and m prints 4. Pair: 4, 4. This is the paper's answer.

Static scoping, by value. x = 6 is printed, but the write never reaches m, so m prints 2. Pair: 6, 2.

Dynamic scoping, by value. x = 4 is printed, m prints 2. Pair: 4, 2. Mathematical derivation The two by-value pairs follow from the definitions and are not the paper's question, but they are why 6, 2 and 4, 2 appear as distractors. The page's model runs all four combinations and confirms the two it quotes.

What these eight items have in common

Seven of the eight are decided before any arithmetic happens: name the two traversals, decide which link the scoping rule follows, apply the three leader rules, count leaves plus operators, notice that one successor means OUT equals the next IN. Only the liveness table needs iteration, and even that needs two rounds and a confirmation. Educational interpretation That is the shape of this section in the paper: the marks are for the decision, and the computation is short once the decision is made.

An original question in the 2014 shape

Original practice Which of these is NOT a local optimisation of a basic block? (A) constant folding; (B) dead code elimination; (C) loop-invariant code motion; (D) strength reduction.

Answer: C. Loop-invariant code motion moves a computation out of a loop, which crosses basic-block boundaries and therefore needs a global analysis. The other three are local: they rewrite one block using only what is inside it. This question was written for this lesson, not taken from a paper; it exists because the local-against-global distinction is what the syllabus's word "local" is testing.

Records: the four boundary cases

A record with no parameters. The size is the sum of what remains; a parameter count of zero is not an error and changes nothing else.

A nested procedure. Now the access link is needed, and it may point several frames back, not to the caller. That is why a display exists: an array of pointers, one per nesting level, so a reference at depth k is one lookup instead of k.

A function returned as a value. Its frame must outlive the call that created it, so the environment moves to the heap and the pure stack discipline fails.

A variable-length local. A C array whose size is a run-time value makes the frame size dynamic, so the compiler reserves a pointer and adjusts the stack at entry.

Blocks: the cases that change the count

A jump target immediately after a jump. One statement is both "after a jump" and "a target". It is one leader, so one block, not two.

A conditional jump. Two successors, and both the target and the following statement are leaders.

A label with no jump to it. Not a leader. Only the three rules create leaders; a label by itself does not.

The last statement. Ends its block whether or not it jumps; there is no statement after it to lead.

The analysis that fails when you stop too early

The flow graph a = 0; b = a + 1; c = c + b; a = b * 2; if a < N goto the second statement; return c. One backward pass from the exit gives, at the header, an empty IN set.

That answer is wrong: a is used at the test and c is used at the return, and the back edge is how both reach the header. Mathematical derivation The page re-runs the equations on the first round's result and shows that they change, so the first round is not a solution at all. Iterate until a round changes nothing; here that is two rounds, confirmed by a third.

The optimisation that is wrong outside its assumption

Replacing 2 * i by i + i, or by a left shift, is safe only while the arithmetic is exact. For a signed integer that overflows, a shift and a multiply are not required to agree, and a compiler that assumes they do is entitled to produce a different answer.

Verified fact In C, signed overflow is undefined behaviour, so a compiler may assume it does not happen — which is exactly why the transformation is licensed there and not in a language that specifies wraparound.

DAG: three counting traps

The constant written twice. The constant 1 appears in two statements and is one leaf. Counting it twice gives seven instead of six.

The commutative swap. Whether a + b and b + a share a node depends on whether the analysis normalises operand order. Questions state it when it matters.

The redefinition. After a = 5, a later a + b is a different expression, because a means something else. Reusing the old node is the classic wrong answer.

The assignment chain. d = a + b after a = b + c where d was a label on that node adds a label; it does not add a node.

Two pairs that are constantly confused

Local against global. A local optimisation rewrites one basic block using only what is inside it: folding, local CSE, local dead-code elimination. A global one crosses blocks and needs data-flow facts: global CSE, loop-invariant motion, register allocation. The syllabus's word "local" is doing real work.

Analysis against optimisation. Liveness is an analysis; register allocation is an optimisation that consumes it. A question asking "which of these uses live variable analysis" wants the consumer, and the answer is register allocation and dead-code elimination, not "liveness".

“One activation record per procedure”

Why it feels right. We talk about "the activation record of f" as though f owned one, and in a program without recursion that is almost true.

What is actually true. There is one record per activation. fact of three and fact of two are two different records with two different values of n, and both are live at the same time.

The correction. Count activations, not procedures. The 2021 question is about a tree with one node per call, and reading it as one node per procedure destroys the answer.

“Recursion needs the heap”

Why it feels right. The word "dynamic" suggests the heap, and recursion is the dynamic case.

What is actually true. Recursion needs dynamic allocation of activation records, which a stack supplies exactly, because records are freed in the reverse of the order they were created. A heap is not required; garbage collection is not required.

The correction. A heap is needed when a frame must outlive its caller — a returned closure, for instance. That is a different requirement.

“Static and dynamic scoping differ only in the lookup”

Why it feels right. The definitions really are only about where a free name is found.

What is actually true. The lookup decides which cell is written, and with a reference parameter that cell is shared with the caller. So changing the rule changes both printed values, not one: 6, 6 against 4, 4.

The correction. Trace the cells, not the names. Write down which frame each write lands in before computing anything.

“Constant folding is common subexpression elimination”

Why it feels right. Both replace an expression by something simpler, and both are called optimisation.

What is actually true. Folding evaluates arithmetic on constants. CSE reuses an expression that was computed elsewhere. 4 * 5 becoming 20 is folding, and GATE 2014 Set 1 offers it as the false statement for exactly this reason.

The correction. Ask what the replacement depends on: only constants means folding; a previous computation means CSE.

“One backward pass gives the live sets”

Why it feels right. For straight-line code it does, and most textbook examples start that way.

What is actually true. With a back edge, information must travel round the loop, which takes another round. A one-pass answer satisfies no equation at the header.

The correction. Iterate until a round changes nothing, and then verify by substituting the result back into the equations. The page does both.

“Union at a join is always safe”

Why it feels right. Being conservative sounds safe: claim more is live, or more is available.

What is actually true. Union is safe for liveness and unsafe for availability. Claiming an expression is available when one path never computed it, or killed it, licenses a reuse that computes the wrong value.

The correction. Match the meet to the question: "some path" means union, "every path" means intersection. Never pick the meet by habit.

The five question shapes in this section

1. The count. Blocks, DAG nodes, registers, live variables. A numerical answer, and the mark turns on one rule applied correctly.

2. The trace. A short program with a scoping or parameter rule, asking for printed values. Two or three writes and one shared cell.

3. The statement set. Several claims about what an analysis or an allocation scheme permits; find the false one or the true ones.

4. The table from a figure. A flow graph drawn in the paper, asking for IN or OUT at each block. The figure is the whole question.

5. The traversal. Activation tree against preorder and postorder, or an access-link chain for a given call sequence.

What each shape demands

For a count, write the rule down before counting: leaders, or leaves plus operators, or the largest live set.

For a trace, draw the frames and mark which cell each write lands in. Then read the printed values off the drawing.

For a statement set, test each claim against one small counterexample rather than against intuition.

For a table, write use and def for every block first, then iterate in reverse order and check the fixed point.

The four wrong approaches that cost marks

Counting statements instead of nodes. Five statements, six nodes, and the numbers coincide only by accident.

Merging adjacent leaders. A jump target straight after a jump is one block of one statement, not two.

Stopping after one liveness pass. Gives an answer that is not a fixed point, which the paper's options usually include.

Reading "local" as "simple". Loop-invariant code motion is simple to state and is not local: it needs a global analysis.

The procedure, in five lines

1. Read the question's noun: record, block, node, live set, register. That names the procedure.

2. Write the rule for that noun in one line.

3. Apply it mechanically to the given code, without skipping a line.

4. Check the answer against an identity: blocks tile the code, nodes equal leaves plus operators, the sets are a fixed point.

5. Only then read the options. Reading them first is how a plausible wrong number becomes an answer.

MCQMediumPYQ: GATE CSE 2016 Set 1

With parameters passed by reference and dynamic scoping, what is printed by a=3;
void n(x){x=x*a; print(x);}
void m(y){a=1; a=y-a; n(a); print(a);}
void main(){m(a);}

  1. 6, 2
  2. 6, 6
  3. 4, 2
  4. 4, 4

Answer: D — 4, 4

m's local a becomes 3 − 1 = 2 and is passed by reference, so x is that cell. Dynamically, n's free a is m's 2, so x = 2 × 2 = 4, and m then holds 4 as well.

MCQEasyPYQ: GATE CSE 2021 Set 2

In a basic block with S1 followed by S2, which relation holds?

  1. OUT(S1) = IN(S2)
  2. OUT(S1) = IN(S1) ∪ USE(S1)
  3. OUT(S1) = IN(S2) ∪ OUT(S2)
  4. OUT(S1) = USE(S1) ∪ IN(S2)

Answer: A

Inside a block, the only successor of S1 is S2, so what is live at the exit of S1 is exactly what is live at the entry of S2.

B and D add a variable's own use to its exit set, which belongs to the IN equation. C unions two different points.

MCQMediumPYQ: GATE CSE 2002

In C, which statement is true?

  1. At most one activation record exists between the current one and main
  2. The number of records between the current one and main depends on the calling sequence
  3. The visibility of global variables depends on the calling sequence
  4. Recursion needs the record saved on a different stack

Answer: B

The number of live records is the depth of the call chain, which is exactly the calling sequence.

A is false because nested calls stack records. C is false because C is statically scoped. D is false because a recursive call uses the same stack as any other call.

NATMediumOriginal practice

For the block t1 = a + b; t2 = a + b; t3 = t1 * t2; t4 = t3 + t1; t5 = t4 - t2; the number of nodes in the DAG is ______.

Answer: 5

Leaves: a and b, so two. Operators: a+b (labelled t1 and t2), then times, then plus t1, then minus t2 — four. Five nodes in total, and one statement becomes a label.

This is an original question written for this lesson, not a previous-year item. It is the 2021 shape with one extra layer, and it tests whether you attach the second label rather than creating a second node.

MSQMediumOriginal practice

Which of these are local optimisations of a single basic block? I. constant folding II. loop-invariant code motion III. local common subexpression elimination IV. strength reduction

  1. I and III only
  2. I, III and IV only
  3. I and II only
  4. all four

Answer: B — I, III and IV

Folding, local CSE and strength reduction all rewrite one block using only what is inside it. Loop-invariant code motion moves a computation across block boundaries, so it needs a global analysis.

Option A drops strength reduction, which needs no analysis at all. Option D is the "local means simple" trap. Original question written for this lesson.

NATHardOriginal practice

For the flow graph 1: a = 0; 2: b = a + 1; 3: c = c + b; 4: a = b * 2; 5: if a < N goto 2; 6: return c, the largest number of simultaneously live variables is ______.

Answer: 2

The live sets are {c}, {a,c}, {b,c}, {b,c}, {a,c}, {c} across the six points, so the largest has two members: b and c, or a and c.

So two registers suffice, and the interference graph has the edges a–c and b–c, which two colours can colour. Note that a and b are never live together. Original question; the page computes these sets and checks them against a path search.

MCQHardOriginal practice

Blocks: B1 computes d = a + b; B2 branches on d and has successors B4 and B3; B3 executes a = 5 then goes to B4; B4 executes e = a + b. Is a + b available at the entry of B4?

  1. Yes, because both paths computed it at B1
  2. No, because one path redefines a before B4
  3. Yes, because availability is computed by union
  4. No, because B4 defines e

Answer: B

Availability is a must analysis: every path must compute the expression and leave its operands alone. The path through B3 reassigns a, which kills a + b.

A ignores the kill; C is the union error, which the page computes and reports as the trap case; D confuses the expression being killed with the block's own definition. Original question, built on the syllabus's own example of the analysis.

MCQMediumOriginal practice

A language has no global variables, no nested procedures and no recursion, and every variable is local to its procedure. Which allocation scheme is sufficient?

  1. Static allocation, one area per procedure
  2. Stack allocation of activation records
  3. Heap allocation with garbage collection
  4. No allocation at all is possible

Answer: A

Without recursion, at most one activation of each procedure is live at a time, so one fixed area per procedure is enough. That is the classic static-allocation case.

B is what you need as soon as recursion is allowed. C is never required for this program shape. D is absurd. Original question; it is the positive half of the 2002 and 2008 statement sets, and it is why "static allocation makes recursion impossible" is true.

The six statements to know word for word

frame = params + return address + control link + access link + return value + locals + temporariesThe size is the sum of the fields; here eleven four-byte slots, 44 bytes.

control link → caller; access link → enclosing scopeDynamic chain against static chain. C needs no access link.

calls = preorder, returns = postorderOne node per activation, not per procedure.

leaders = {first} ∪ {targets} ∪ {after a jump}Each leader starts a block; no two adjacent leaders means blocks = leaders.

DAG nodes = leaves + distinct operatorsA repeated definition is a second label, not a second node.

IN = use ∪ (OUT − def), OUT = ∪ IN(successors)Backward, union, boundary empty at the exit. Iterate to a fixed point.

The four analyses, side by side

Liveness. Backward, union, empty at the exit. Drives dead-code elimination and register allocation.

Available expressions. Forward, intersection, all expressions at the exit. Drives global common subexpression elimination.

Reaching definitions. Forward, union, empty at the entry. Drives constant propagation and def-use chains.

Constant propagation. Forward, and the meet is "agree, else unknown". The only one of the four whose meet is neither union nor intersection.

The counting rules, which is most of the marks

  1. Frame size: add the fields. Offsets: place the frame pointer and step.
  2. Blocks: three leader rules, then group. Check the sizes add up.
  3. DAG nodes: leaves for distinct initial values and constants, plus one node per distinct operator.
  4. Registers: the largest live set, which equals the colours of the interference graph when the graph is a clique.
  5. Statements eliminated by CSE: one per statement that recomputes an existing expression.

Every one of these five is computed on the Animation tab, and the pass count is printed under the canvas.

Numbers worth remembering

Frame: 11 slots, 44 bytes. fact(3): 5 frames, values 1, 1, 2, 6.

2016 question: static 6, 6; dynamic 4, 4; the distractor 6, 2 belongs to no rule.

2025 blocks: 6 leaders, sizes 1, 1, 7, 2, 1, 5, total 17. 2021 DAG: 6 nodes, 3 leaves and 3 operators, 2 statements eliminated.

Liveness example: 2 rounds to a fixed point, largest live set 2, so 2 registers, with edges a–c and b–c.

The four-step procedure

1. Name the noun. Record, block, node, live set, register — that chooses the procedure.

2. Write the rule in one line before computing anything.

3. Apply it mechanically, and iterate if the graph has a back edge.

4. Check an identity. Blocks tile the code, nodes equal leaves plus operators, the sets are a fixed point, the colouring respects its edges.

The two counterexamples to keep

One backward pass is not a solution. On the six-node loop graph, the first round leaves the header empty; re-running the equations moves the sets, so the first round fails its own definition.

Union is not always safe. In the four-block graph, union says a + b is available at the join although one path reassigned a, and that would license a reuse that computes the wrong value.
